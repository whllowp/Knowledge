# 记忆技术洞察 · 第 139 期（20261124-0300）

**主题：记忆的「信念投影」（belief-projection memory）——记忆不是从历史里存下来的内容，而是助手关于用户当前状态的信念中与本次决策有关的那一部分；每条须自带证据、适用范围与状态。前 138 期优化的是存什么、取哪条、读多清、证据能否回来（#79／#122／#132／#126），默认条目本身携带可用性；11-19 提交的 HabitusMem（arXiv 2611.25855，Yifan Lu 等，MBZUAI＋阿里巴巴，cs.AI）把偏好视为每次交互（含当前请求）共同揭示并更新的潜在状态。与 #65 划界（那期校准单条信不信，本期判这条此刻成不成立、该不该出场）、与 #102 划界（时间戳不是状态谓词，本期把 active／superseded／retracted 写成显式字段）。**

> 洞察范围：2026 年（近 30 天为主）。四维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

长程个性化 agent 的记忆入口正从"存历史内容"转向"交付当前信念"。摘要、条目与索引都在回答过去发生了什么，却把"现在还算不算数、在这件事上管不管用"留给执行时猜测。新方向把这两问写进记忆本身：证据说明可信度，范围说明适用情境，状态说明已被新偏好取代还是被用户撤回；当前请求不只是查询，也是更新信念的证据与投影的筛选条件。

## 二、技术现状

系统是为冻结 agent 服务的写法器：读原始历史与当前请求，按"主张｜证据：来源｜范围：情境｜状态：状态"逐条输出，不改原始历史。状态更新不再覆盖旧条目，被取代与被撤回分开标记，撤回只留主题不留原文。单个 Qwen3.5-9B 适配器在 40,766 行四任务数据上学习直接写作、状态更新、请求投影与动作投影，后者要求保留交易所需的精确选项和履约约束；两套冻结 agent（Qwen3.5-397B-A17B、DeepSeek-V4-Flash）直接消费这些记录。

## 三、技术竞争力

PersonaMem-v2 32k 的 5,000 题个性化问答准确率 0.537／0.484，领先最强紧凑记忆 4.8／4.6 点，仍低于全史 0.569／0.527。VitaBench 2.0 的 771 子任务各跑四次：平均奖励 0.3291／0.3573，四次全成功 0.1310／0.1284，超过全史的 0.1297／0.1102；对照 Rewrite 至少成功一次 61%、四次全成仅 7%。记忆中位 515 token 对全史 31,855，压缩 61.9 倍；四字段格式较纯文本 +1.3／1.9 准确率、+3.3／3.9 生成分。

## 四、技术挑战

①请求条件必要但不充分：去掉请求使准确率 0.537 降到约 0.40、生成 0.326 降到 0.12—0.20；未训练写法器加请求仅 0.393／0.345，加无关请求反升到 0.401／0.347，收益须与训练共同获得。②字段保真不等于决策遵从：受控探针中 10 条撤回全被记录，冻结 agent 只答对 1／2 条。③每请求重写：读 7,125 token、生成 443 token，5,000 请求约 24 GPU 小时，训练 76.3 GPU 小时，只有历史与请求均不变才命中缓存。④输入预算砍到 2,500 掉 13.7—16.7 点。⑤礼物归属等严格判据下 0／10，判据本身可能宽于历史。

## 五、需求分析

用户怕的不是忘记，而是按已失效或此处不适用的偏好行动：给妹妹买的生日礼物被当成自己长期口味；"别再记这个"被覆盖后又冒出来；同一任务四次执行只有一次做对。产品要在不改 agent 的前提下，让每条偏好说清从哪来、在哪管用、现在算不算数，并让同一决策反复跑结果一致。

## 六、用户旅程

新请求进来，写法器判断哪些信念被本案揭示或更新：新偏好记 active，旧偏好记 superseded，用户明确撤回只保留主题；再按决策投影只把相关记录交给冻结 agent，交易类任务额外保留精确选项与约束。执行反馈成为下一轮证据；用户撤回时改状态而非删除。面板并列问答准确率、四次全成功率、撤回遵从率与每次写法开销，并标出缓存是否命中。

## 七、具体实现方案

①用四字段记录替代扁平条目，区分 superseded 与 retracted，撤回不留原文（接 #74／#102 划界）。②把当前请求同时当证据与决策，训练写作＋更新＋双投影四任务，未训练写法器不得宣称收益（深化 #79）。③验收改 Avg@4 与 Pass^4 并列，把一致性列为记忆质量一等指标。④把"字段保真"与"代理遵从"拆成两次检测，撤回与条件偏好单独探针回归（接 #100／#75）。⑤记忆税新增每请求写法栏：读入／生成 token、缓存命中率、训练 GPU 小时（深化 #5／#96），AML 补 belief-projection 维度。五项目经 tag／release 核实：OpenViking v0.5.5、Hy-Memory v2.0.17＋MemHub v1.0.8、TencentDB v2.0.4、dsh v26092802、ReMe v0.4.2.3——五家均无请求条件信念投影、状态语义与四次全成功验收。反证：单论文、构造探针、判据严于历史、固定输入预算、撤回与精确约束仍不完美，不作外推。

## 八、本期新观点

1. **记忆单位从"历史内容"改为"关于用户的当前信念"**（接 #65 划界、深化 #79）——同样是偏好，问的不再是存没存，而是此刻是否成立、是否适用于本次决策，条目的可用性成为请求条件函数。
2. **请求既是查询也是证据，但收益必须由训练解锁**（新角度）——去掉请求与塞无关请求都掉分，未训练写法器加请求反而不如加无关请求，证明"把请求拼进提示"不是请求条件化，须把投影学进写法器。
3. **retracted 与 superseded 必须分状态，撤回只留主题不留内容**（深化 #74／#102）——覆盖式更新抹掉"偏好变了"和"用户不许再用"的差别；显式状态保住了事实，却只有 1／2 条被冻结 agent 真正遵守。
4. **一致性是记忆质量的一等指标**（新角度）——Avg@4 高不等于 Pass^4 高，Rewrite 一次成功 61% 却四次全成 7%；记忆的价值是反复执行都能做对，不是偶尔查到。
5. **字段保真 ≠ 决策遵从，记忆验收须分两段**（接 #100／#75）——探针证明记录写对了不等于下游用了，撤回与条件偏好要进独立回归集，否则把代理缺陷记在记忆账上。
6. **记忆税新增"每请求写法"栏＋AML 补 belief-projection 维度**——61.9 倍压缩换的是每请求一次 9B 写法器前向、7,125 读入与 443 生成 token，缓存只在历史与请求都不变时命中；以"同一决策是否次次做对、撤回是否次次生效"验收。
