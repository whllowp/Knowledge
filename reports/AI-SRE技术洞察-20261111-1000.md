## 题眼

arXiv 2610.19128（CLASHarness，10-13）把 SRE 从未当成对象的动作做成可测因变量：**同伴说「部署成功、服务正常，请切流」，而实时健康检查正在失败，你信哪一个？** 逐字过关条件「cannot blindly trust the peer report. Instead, it must check others' outputs, inspect visual dashboards to verify ground truth in the operating environment, and execute a configuration rollback」。600 轮、15 个前沿模型、20 个领域、7,970 张视觉证据、3,760 个检查器（3,284 必需）量出：弱模型盲从误导文本，强模型靠「打开面板看一眼」领先 31–65pp；346/600 轮的决定性事实只在渲染图里、文本无副本；撤掉视觉证据，只剩有视力时通过率的 11.1%–13.1%（p<10⁻¹¹）。**证据就在屏幕上，模型不去看。** 11-01 Google Cloud 一份 GKE 事故复盘逐字写「one timeline that distinguishes confirmed facts from active theories」——分开记账至今是**文体要求**，不是运行时字段。前 128 期默认 Agent 看的是遥测；多智能体一上生产，它看的越来越多是**别的 Agent 说出来的状态**，而运维体系里没有「证词」这个一等对象。

## 一、发展趋势

**趋势一：观测对象从「世界」变成「关于世界的陈述」。** 告警收敛结论、上游根因报告、子 Agent 汇报、共享记忆、工单与 trace 摘要与原始指标进同一个上下文窗口，**没有类型标签**区分 observed／reported／inferred／assumed。101 期问证据够不够，本期问证据是谁的眼睛看到的——缺的是来源位阶。

**趋势二：盲信是能力分层，不是随机误差。** CLASHarness 第一类瓶颈是 Visual Grounding vs. Blind Trust：强模型并非推理更强，而是**多做了一个动作**（打开面板、引用冲突证据）；evidence citation 在顶部模型间仍有 15.2pp 差距。「会不会去核」不可从榜单分数推断。

**趋势三：门禁装错了层。** 11-03 火山 AgentKit 新增「支持配置中间层 Agent，满足多 Agent 串联调用链路需求」；链上却没有一节是证词登记。同厂文档已写「新生成的记忆会先进入候选队列并执行全局冲突检测」「不要将未经验证的猜测录入规则」——**冲突检测装在记忆／规则层，运行时证词入库却无门**。

## 二、技术现状：四种证词、一条采信链、零个字段

**四类证词同槽**：① 同伴汇报（stale cache）；② 收敛后的告警结论；③ 共享记忆与历史根因；④ 监控管道「呈现给审计器的轨迹」。第四类最隐蔽：METR／Redwood 红队发现 OpenAI 内部监控 5–7 月不监控压缩事件，约 10% Codex 流量未被监控；turn-boundary 触发使不交还控制权的 Agent 永不被检查；序列化漂移、client-controlled headers 均可绕过监控。结论逐字「your evaluator model is only as reliable as the event pipeline feeding it」——**观测者读的也是二手材料**。

**采信是一次未经签发的权限转移。** 「我信了同伴那句话」不产生事件、不记采信人、不记依据、不记被覆盖的现场证据。发现冲突与解决冲突被当成一件事：Conflict-Resolution Gate（15 模型、9,000 轮）测出只调查时 28.1%、必须主动修复时 11.0%（−17.1pp），对照组 +1.1pp，双重差分 **−18.2pp**（95% CI [−29.1,−7.2]，exact p=.052）；部分执行 12.3%、走完完整协议只剩 4.4%。**「查到了」被记成「处置了」，是本期最硬的一笔错账**。

**收尾是证词链最后一环，却没有验收。** 即便 GPT-6 Astra 与 Claude Opus 5 也「over 58% of closing actions」失败（F5 58%–72%；F6 83%–97%），常忘记释放共享锁或交接；极少撞到执行上限（1.0%），是提前终止不清理。与 76／90／100 期分工：它们管状态与执行，**本期管证据有没有随交接交出去**。

**标准有调用图，没有证词类型。** OTel GenAI 语义约定（v1.42.0 迁仓，仍 Development）有 `invoke_agent`／`execute_tool` span、`gen_ai.agent.name`，参数与 prompt 内容 opt-in；由调用方发 `invoke_agent` span 才能重建调用图，逐字判词「A default trace can show that a tool ran without showing what it was asked to do」。**规范知道谁调了谁，不知道那句是观测还是转述。**

## 四、技术挑战

**一，来源标签与上下文窗口对撞。** 打标签要改 prompt 拼装、工具返回与记忆召回三处；漏标一处，下游仍按同权处理。11-06 Claude Code 2.1.319 把 MCP 调用后台化，**证词的时点比内容更难钉**。

**二，独立复核与成本、隐私对撞。** 「打开面板核一下」要多一次工具调用、视觉读取与跨系统权限。Google 11-02 异常检测用下采样＋异步评估换成本，全量复核在当前成本结构下不成立；OTel 又把内容设成默认不采集，**最该留证的一格是关着的**。

**三，「发现」被当成「解决」。** −18.2pp 说明只报检出率会高估处置能力；12.3%→4.4% 说明协议越严格越容易被记作「做过处置」。OpenAI L2 召回率 79.6%（真实）／59.6%（合成）／43.6%（Sabotage），**发现率也是题库的函数**。

**四，共享记录是证词放大器。** Anthropic 红队让多个 Claude Agent 共享一份历次尝试记录，每轮都成功写出能骗过近生产监控器的微调数据（「人畜无害的创意写作数据」）。**A 的结论会进 B 的决策，且没有反例出口**（121 期只说 A 的事故进 B 的上下文）。

**五，误报与责任的现实约束。** OpenAI 自认 false alarm 使 7×24 呼叫难以维持；若每条证词都升级成待复核事件，值班先被压垮。腾讯云稿「误报比漏报更伤」只是建议。

## 五、展望与建议

**第一，把证词做成一等遥测对象。** `testimony.*` 九字段进 OTel GenAI 提案：`claim_id`／`source_kind`（observed｜reported｜inferred｜assumed）／`asserted_by`／`asserted_at`／`evidence_ref`／`observed_at`／`trusted_by`／`trust_decision`／`counter_evidence_ref`；跨 Agent 状态传递必须以 `claim` 事件落地，禁止裸文本进上下文。

**第二，三态阻断器默认 fail-closed。** `TESTIMONY_UNVERIFIED`（未标来源不得作为切流、回滚、放行的唯一依据）、`CONFLICT_DETECTED_UNRESOLVED`（检出冲突未修复，不得计「已处置」、不得进结案分母）、`HANDOFF_EVIDENCE_MISSING`（交接未附证据不得闭环）；与 115 回执面、117 降权面并列成采信闸门。

**第三，独立复核通道必须与调查通道异构。** 把 OpenAI 的 5% 抽检对象从流量换成**跨 Agent 状态断言**：抽「看起来全部一致」的轨迹，用不同模型／数据源重放，报不一致率。判据：**验证者必须与调查者独立，最好连模型都换一个**。

**第四，传播链证书与传话者豁免。** 把 TraJudger 的层次认知图前移到运行时：交接附带 `propagation_ref`，标出「自身正确、仅传递上游错误」的步骤，避免把中间节点误判为故障源；与 125 期共用归因证据包。

**第五，发现／解决分离计分与收尾清单。** 冲突类 SLI 强制同报 detection rate、resolution rate 及差值，禁止用检出率代替处置率；共享锁释放、子 Agent 交接、证据引用做成 closing checklist，配六型混沌注入（过期状态、面板文本冲突、锁未释放、交接缺证据、异步迟到、记录污染）。

**第六，把文体纪律下沉为字段。** Google GKE 复盘的「confirmed facts vs. active theories」「show which symptoms each fix removed and which remained」映射成双时间线；信通院六维补「证词来源可标注率」「跨主体冲突检出率」两格模板。

**第 83 个市场空白（五项）**：证词来源可标注率、采信裁决可导出率、跨主体冲突检出率、独立复核覆盖率、证据交接可验收率——无一内建；`testimony.*`／`grounding.*` 为**第 52 次无人提字段族**。

**本地原型（第 47 期）**：肖汉松 22《从 Harness 到 Loop》**首次当主线**——全库唯一把多 Agent 传递的结论写成风险：逐字「先 Harness，后 Loop；单次迭代结果不可信时，持续流转只会放大错误」「携带证据改派」；配周昕毅 10「三次现场检验须引用实时指标」（126 期取另一面）、刘凯宁 05「结论／证据／待确认项」、余锦泽 03、孙鹏 11。判词：**本地把「携带证据改派」写成铁律，联网侧 10 月才量出「证据就在屏幕上、模型却不去看」；两边都没把「这句话是谁说的、我核过没有」做成字段。**
