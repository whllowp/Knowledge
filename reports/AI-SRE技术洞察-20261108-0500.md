## 归因面／推断边面（Causal Attribution / Inferred Edge）

> **题眼**：同一周，一家把「从真实云 API 长出来、无需前置治理」的全景图谱交给 Agent 当事实底座，同一生态的工程稿却写「静态依赖图在滚动更新中迅速过时、会把根因误判给症状最明显的服务」；另一家把事件风暴折叠成带「可能根因」的单一事件，官方自认根因仍需人判。**买的是根因分析，交付的是搜索空间压缩与降噪率；图上的边是测出来的还是猜出来的，没有一层回答。**

## 一、发展趋势：一周之内，「图」从底座降格为待举证的假设

**10-29～11-03**，腾讯云把 CloudQ 升级为多云 AIOps 智能体：全景图谱把资源、**资源之间的关系、运行状态与可采取的处置动作**放进同一张图，表述是「从真实云 API 的数据里长出来，无需前置治理」，一条路给人、一条路给 Agent；同期信通院六维与五项要求发布。**11-03** 阿里云 AgentCore／STAROps：UModel 发布后刷新成「活地图」，STAROps 根因推导「**沿拓扑依赖关系反向定位**」，AgentCore 关系由运行状态驱动、只读 SQL 生成，**保留版本、运行代次和观察时间**。

**11 月初**，NVIDIA Minerva 的动态知识图谱由 auto-discovery「补齐原始遥测所缺的关系」并随环境更新，拓扑感知关联把事件风暴折叠成带「可能根因」的单一 incident；开发者博客在「40 万接口定位一条 NVLink 降速」后自认**运维仍需自行判定根因，折叠只是缩小搜索空间**。**11-04** 其 Operations Agent 亦不公布 RCA 准确率数字。Perform 2026 的 Dynatrace Intelligence／Smartscape 合作稿亦写「**相关性不证明因果**」。

结论侧反而谨慎：**11-03** Honeycomb Team Agents 每条 finding 链回 query／trace／deploy／ticket、每条记忆标 **confirmed 或 hypothesis**；**10-14** NeuBird ARC 把调查、结论与工程师更正带署名写进版本化记忆，自报 94% 根因准确率。

**11-02 修订的 arXiv 2601.07342v2**（9 场景／360 次运行／4 模型）指出数字孪生不可能以合理成本建模一切，「区分性证据往往就在挂在图上的非结构化文本里」——两个事件**结构不可区分、描述却一个例行一个因果**；端到端 96.7%／86.7%，**证据需跨资源组合时每个模型都掉分**。**11-02／11-03 的 arXiv 2611.02416** 实测「最终决策偏爱大的异常分数，**尽管模型自己的传播分析指向别处**」，4B 模型 48.7% 对 OpsAgent 18.5%。规范侧有词汇却不成产品：OTel 实体数据模型要求「关系自带证据与有效期」、区分 **Observed／Configured／Authoritative** 三态，却自认「不是知识图谱产品」；**11-02** GenAI 约定仍 Development。

**主线划界**：47 期世界模型面问「有没有一份世界」，本期问「哪一笔是猜的」；83 采样面管「没被抽中」、98 计分面管「没被测量却被记零」，**本期是负事件家族里唯一「被合并掉而非被丢掉」的成员**；87 候选面管调查中的竞争假设，本期管**调查开始前平台已替你做掉的归因**；84 时间基准面管事件时间戳，本期管关系有效期。

## 二、技术现状：边有四种来源，图上只有一种

**来源断点**。观测、自动发现、推断、人工录入四类边共用一种「关系」类型，无 provenance、无置信度、无 as_of；CloudQ 甚至把处置动作挂进同一张图，事实、推断、动作不可分辨。OTel 三态尚未容纳「推断边」。唯一把观察时间写进关系的是阿里 AgentCore，但那是**实体—资源映射的时态**，不是因果边的时态。

**折叠断点**。告警风暴被聚合成单一事件，被折叠的症状仍在，只是归属被改写到别人的条目下；折叠依据（共享依赖路径）本身又是推断结果，因而**折叠不可反演**——无法回答「若不折叠会看到几个故障」。腾讯云社区稿把「降噪 90%」与「根因分析：基于拓扑与相关性」并列；NVIDIA 自认只交付更小的搜索空间。**降噪率由此被当作根因准确率验收**。

**口径断点**。NeuBird 报 94% 根因准确率、Forrester Wave Q4 2026 给 Dynatrace「因果 RCA」最高分、NVIDIA 报通知事件与工单显著减少；同一批官方材料却写「不证明因果」「根因仍需运维自行判定」。这是 97 期同名不同口径在归因层的复现：**连通性被当因果性交付，压缩率被当定位精度**。

**传播断点**。三源互证同一机制：论文实测决策偏爱大异常分数而压过自身传播分析；腾讯云工程稿写「固定因果图会把根因误判给下游症状最明显的服务」，并以 TopoEvo／StaR 主张「拓扑是流动的、故障是有记忆的」；2601.07342 证明决定性证据常在结构属性之外。**图负责连通性，证据负责因果性**。93 期 RCAtlas「固定 SOP 跳过决定性证据」与此同构：都是先定路径再看证据。

**时态断点**。动态图随环境更新，但「这条边在故障发生时是否成立」不进 trace；滚动更新与金丝雀发布恰是边变化最快、故障高发的窗口，于是用此刻的图解释三小时前的事故。本期换的是图，不是规则。

**本地 173 库连续第二十期成组启用，作「推断边治理原型」**。余锦泽 03 记录同一问题四种算法「都没算错」却得 1.15%／1.23%／1.25%／1.29%，解法是**表间关系写入本体并附数据／代码／文档证据，LLM 只提候选、程序核对给出「已验证／候选」，人可否决、否决作下一轮反例**——等于给每条关系打了来源、二态证据等级与回流通道。刘凯宁 05 的蚂蚁实践沿业务路径取证、诊断报告三分（结论／证据／**待确认项**），与「沿拓扑反向遍历」划清界限。周昕毅 10 要求影响面引用实时指标／日志／拓扑，吴垚 09 沉淀「真实根因分布」。判词：**联网侧 11 月才把「关系要分来源与有效期」写成方法论稿，本地讲义早把它做成流程**；仍是项目内约定，不可采购。

## 四、技术挑战：第五十三个市场空白

`topology.*`／`attribution.*` 是**第 22 次无人提出的字段族**。五项空白：① 边级 provenance 与四态（observed／configured／inferred／asserted）及置信度；② 折叠账本——被折叠事件清单、折叠依据、可反演重放；③ 因果边双时态（valid_from／valid_to／as_of）与「故障时刻的图」快照；④ 降噪率、聚类纯度、经验证根因率三条 SLO 分栏；⑤ 图外证据（变更单、故障描述、工程师笔记）作为一等检索对象。

更硬的反证在标准里：信通院《运维智能体（SRE AGENT）能力要求》把故障定位分成**现象定位／对象定位／原因定位**三级，1 级写「通过现象关联分析实现初步定位」、2 级才要求「结合多源数据进行多维度根因分析」——**标准自己已承认关联不等于原因，分级条款却无一要求边的来源、置信度、有效期或折叠可回放**；六维与五项要求同样无「图可信」维度。而《可信 Agentic Cloud 流量负载均衡能力要求》已列出「**路由决策可追溯率**」——可追溯率并非没人会写，只是用在流量路由而非归因折叠。延续 94／98 期方法：**标准文本的书面指标清单，恰是空白的最佳证据**。

## 五、展望与建议

**字段与默认态**：`topology.*` 九字段（edge_id／source_type／provenance_ref／confidence／valid_from／valid_to／as_of／inference_method／fold_group_id）与 `attribution.*`（collapse_ratio／unfoldable／candidate_root_cause／confirmed_root_cause／decision_trace）进 OTel 实体／genai 提案；默认 `EDGE_UNVERIFIED`，未声明来源的边不得作为根因唯一依据（承接 91 期工具注册期声明、97 期 `EPISODE_UNVERIFIED`）。

**最小实现**：边来源标注器把 auto-discovery 与静态 CMDB 分开落库；折叠账本与反演重放器按 `fold_group_id` 还原原始事件；故障时刻图快照与发布／扩缩容事件绑定；独立见证走 96 期带外只读，读变更单与工程师笔记而非被测平台自己的拓扑。

**计分与治理**：三轨 SLO 沿用 98 期双轨计分与配对 placebo，凡「沿拓扑反向定位」须附至少一条图外独立证据，**「候选根因」不得折叠成「根因」**（衔接 81 弃权面、87 候选面）；图与折叠策略变更进 CAB 并发布 re-grade diff（93 期「加固是变更」在图层复现）；混沌注入新增六类（边过期、误加边、共因拆分、多因折叠、大异常分数压过传播分析、图外证据不可达）。

**标准与采购**：SRE AGENT 能力要求 2 级补格——须声明边来源、报折叠可回放率、区分现象关联与原因定位；六维「数据可信」「结果可评价」补「图可信」子项。采购五问：这张图的边从哪来？折叠掉了什么？故障时用的是哪一版图？相关性与根因是不是两个数？错了能不能回放？

**口径与边界**：40 万接口案例、94% 根因准确率、90% 降噪率、六维首批认证、Forrester 评分均为厂商自述或供稿；ProdAgent／Sevbot 经二手编译仅取机制；腾讯云社区稿为作者授权发表，非产品承诺；两篇 arXiv 为预印本／修订版，数字仅取机制不外推；OTel 实体模型为设计指引、GenAI 约定仍 Development；本地 173 为讲义转写稿；未采信 SEO 农场数字。
