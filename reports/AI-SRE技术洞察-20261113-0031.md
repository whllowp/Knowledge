# AI-SRE 技术洞察（第 165 期）

**生成时间**：2026-11-13 00:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：资源账本面（Resource Ledger）——Agent 花的不只是 token：算力、工具配额、人的注意力，四本账要一起算；只算一本，就会在另一本上超支

---

## 题眼

143 期量过「一次循环能在账单来之前烧掉三天」，147 期量过「告警少了人却更累」，53 期早就写过「读完是运维里最稀缺的资源」。把三件事放在一起，会发现**大多数团队只在算一本账：token**。可 Agent 真正消耗的是四种资源：**算力（GPU 分钟/推理时长）、token（输入输出）、工具配额（API 调用/检索次数/沙箱时长）、人的注意力（审阅、审批、复盘）**。它们之间还有**兑换率**：**省 token 的压缩会让审阅变难；换便宜模型会多出返工；多开 Agent 会多出审批**。**只优化一本账，等于把成本搬到另一本账上——而另一本账往往没有仪表盘。** **四本账之间还有汇率：token 便宜了，人的分钟数可能贵了。** 本期把四本账合成一张表，并给出「按解决任务计费」的统一口径（113 期的分母，在这里变成四个分母）。

## 一、发展趋势

**趋势一：从「单资源优化」转向「组合预算」。** 省钱、提速、降人工，三个目标互相挤；**没有统一账本，就会各自最优、整体最差**。**FinOps 管的是云账单，管不到「人的分钟」。**

**趋势二：人的注意力开始被计入成本。** 147 期的疲劳、53 期的「读完」，都在说**审阅不是免费的**；**Agent 越自动，审阅越像瓶颈**（155 期）。

**趋势三：承诺容量变成第四本账。** 161 期说「2027 算力已卖完」；**预留是预付成本，闲置也是成本**。

## 二、技术现状：四本账，三本没有仪表盘

**算力账：有，但和 token 混在一起。** GPU 分钟、冷启动、预热池；**136 期的预热成本常被算进「基础设施」而不是「Agent 成本」**。

**token 账：最成熟。** 输入/输出/缓存命中；**但它只回答「模型花了多少」，不回答「任务花了多少」**（113 期分母）。

**工具账：几乎没有。** API 配额、检索次数、沙箱时长、MCP 调用；**超限时才发现，而不是提前预算**。

**注意力账：完全没有。** 审阅分钟、审批次数、复盘工时；**53 期说它最稀缺，却最少被计量**。

**四账的三种错配，一种比一种常见。** 只算 token（把审阅当免费）、只算钱（把返工当免费）、只算人（把机器当免费）；**三种错配都会在季度末以「怎么又超了」的形式出现**。

**判读与本期反转。** 把 token 成本做成看板的是 143 期，把注意力写成稀缺资源的是 53 期，把「按任务计费」的分母讲清的是 113 期；**六家云厂商 Agent 平台「工具账／注意力账／统一分母」三列全空**。与 143 的分工：143 管「花超了」，本期管**四本账之间的搬运**；与 147 的分工：147 管人的疲劳，本期管**人的分钟数**；与 161 的分工：161 管容量合约，本期管**合约成本怎么摊到任务**。判词：**「成本看板」「配额」「工时」「预留」全部可采购，「举证这个任务的四本账加起来是多少」不可采购。**

## 四、技术挑战

**一，兑换率未知。** 省 1 万 token 换来 10 分钟审阅，值不值？**没有兑换率，就无法做取舍**。

**二，工具账分散。** 每个工具一个配额；**没有统一视图，超限是突然的**。

**三，注意力不可自动采集。** 审阅时长靠自报；**自报就会低报**。

**四，成本归属跨团队。** 模型费、工具费、人力费在三张预算表；**没人对合计负责**（146 期）。

**五，优化会转移成本。** 压缩上下文省 token、但让判断变难；**账要一起看才不亏**（151 期）。

**六，分母不统一。** 每任务、每解决、每租户；**四个分母混用，报表永远对不上**（113 期）。

**七，预留成本不会自己摊销。** 承诺买的是容量，**闲置也要摊到任务上**（161 期）。

**八，多租户分摊会打架。** 共享池谁用得多？**没有计量，就按人头平摊——用得少的补贴用得多的**（121 期）。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `ledger.*` 字段**：`task_id`、`gpu_ms`、`tokens_in`、`tokens_out`、`tool_calls`、`human_minutes`、`outcome`。
- **R2 四账合一**：按任务汇总四本账；**统一分母（每解决任务）**。
- **R3 兑换率**：定义 token↔分钟↔配额的换算；**每季度复核**。
- **R4 预算与断路**：按 tier（153）设四账预算；超支走分档断路。
- **R5 归属**：四账各有 owner；**合计有人负责**（146 期）。
- **R6 指标**：每解决任务成本（四账）、注意力占比、工具超限率、成本转移量。

### 5.2 用户旅程

- **平台工程师**：看板显示某任务 token 降 40%、审阅分钟涨 3 倍 → 合计更贵 → 回滚压缩策略 → 记入兑换率。
- **SRE**：审批队列积压 → 查注意力账 → 加自助审批 → 释放人力。
- **财务**：把预留、token、工具、人力合成一张表 → 按任务分摊。
- **审计**：抽查一个任务 → 核对四账 → 确认没有「只报 token」。

### 5.3 实现方案（90 天）

- **0–30 天：埋点。** 四账字段；先覆盖 top 20 任务。
- **30–60 天：合表。** 统一分母；兑换率；预算与断路。
- **60–90 天：归属。** 四账 owner；季度复核；成本转移看板；预留摊销规则。

**第 113 个市场空白（五项）**：四账覆盖率、统一分母可算率、兑换率可复算率、注意力采集率、成本转移可测率——无一内建；`ledger.*`／`cost.*` 为**第 82 次无人提字段族**。本地 173／173-kb 连续第 73 期成组启用：肖汉松 22「全局调度器：分派、等待」＝全库唯一把「资源分派」写成组件的实践，本期首次当主线；配 143 期成本、147 期疲劳。判词：**本地把分派写进调度器，联网侧 2026 年才承认「注意力也是最稀缺资源」；两边都没把「四本账合计」做成任务级字段。**
