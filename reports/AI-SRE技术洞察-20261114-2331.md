# AI-SRE 技术洞察（第 195 期）

**生成时间**：2026-11-14 23:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：缓存面／提示缓存（Prompt Caching）——同一段系统提示被反复计费；缓存省了钱，也可能缓存了旧世界

---

## 题眼

143 期说成本失控，165 期说四本账，96 期说合式错值。三件事在**缓存**上会合成一个新问题：**Agent 每次调用都带着同一段系统提示、同一批工具描述、同一份检索结果**——**缓存能把这块成本砍掉一大截、把首 token 延迟降下来**；但缓存也会**把旧世界留下来**：索引更新了、文档改了、模型换了，**缓存还命中**，于是 Agent 拿着旧上下文给出「看起来对」的答案。**缓存不是优化项，是正确性项**：**省下来的钱好算，缓存错的代价不好算。** **而大多数 Agent 栈的账本里，既没有「省了多少」，也没有「旧了多久」。** **命中率是运营指标，旧缓存率才是正确性指标。**

## 一、发展趋势

**趋势一：提示缓存从「供应商特性」变成「架构默认」。** 前缀缓存、KV 缓存；**不设计缓存，成本就按全量算**。

**趋势二：缓存开始带版本键。** 索引版本、prompt 版本进 key；**版本变了，缓存自动失效**。**没有版本键的缓存，是「永远正确」的假设。**

**趋势三：缓存进入成本账本。** 命中率、节省 token、旧缓存比例；**不记，就不知道省没省**（165 期）。

## 二、技术现状：三种缓存，通常只管一种

**提示前缀缓存：最成熟。** 同一段系统提示复用；**省钱最多，也最容易缓存旧 prompt**（151 期）。

**检索结果缓存：最危险。** 同一 query 复用 hits；**索引更新后仍命中旧结果**（168 期）。

**工具响应缓存：最隐蔽。** 同一参数复用响应；**资源已变，响应没变**（96 期）。

**现状：只关心命中率。** 命中率越高越好；**没人问「命中的是不是当前的」**。

**三种旧，一种比一种难发现。** 旧 prompt（行为变了）、旧索引（证据变了）、旧工具响应（资源变了）；**三种都返回 200，都看起来对**。

## 四、技术挑战

**一，缓存键不含版本。** 索引更新、prompt 改了；**key 没变，命中照旧**。

**二，TTL 与一致性打架。** TTL 短，命中率低；TTL 长，旧数据多。

**三，跨租户串缓存。** A 租户结果被 B 命中；**隔离与命中率冲突**（121 期）。

**四，工具响应缓存最难失效。** 资源变了，缓存不知道；**要按资源版本失效**（96 期）。

**五，节省不可见。** 命中率有，节省 token/钱没有；**账本里看不出缓存贡献**（165 期）。

**六，旧缓存比例不可测。** 命中的有多少是旧的；**没有版本比对，测不出来**。

**七，缓存可能被污染。** 错误结果被缓存；**后续所有命中都错**（96 期）。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `cache.*` 字段**：`key`、`kind`（prompt/retrieval/tool）、`version`、`hit`、`age_s`、`stale`、`saved_tokens`。
- **R2 版本键**：prompt/索引/资源版本进 key；**版本变即失效**。
- **R3 TTL 分级**：按数据类型定 TTL；**短 TTL 保正确，长 TTL 保成本**。
- **R4 失效联动**：索引重建、prompt 发布、资源变更触发失效（173 期）。
- **R5 节省入账**：命中节省的 token/钱记进账本（165 期）。
- **R6 指标**：命中率、旧缓存率、节省额、失效时延。

### 5.2 用户旅程

- **平台工程师**：上线提示缓存 → 命中率 70% → 加版本键 → 旧缓存率降到 0.5% → 节省入账。
- **SRE**：答案变旧 → 查缓存 → 发现索引已更新但 key 没变 → 修失效。
- **财务**：看账本 → 缓存节省 18% → 确认口径。
- **审计**：抽查一次命中 → 核对版本与时效 → 确认不是旧世界。

### 5.3 实现方案（90 天）

- **0–30 天：埋点。** 三类缓存命中；版本；年龄。
- **30–60 天：版本键。** 三类 key 加版本；TTL 分级。
- **60–90 天：失效与账本。** 变更联动失效；节省入账；季度审计；污染清理。

**第 136 个市场空白（五项）**：缓存版本键覆盖率、旧缓存率可测率、失效时延达标率、节省入账率、跨租户隔离率——无一内建；`cache.*`／`hit.*` 为**第 105 次无人提字段族**。本地 173／173-kb 连续第 95 期成组启用：余锦泽 03「上下文装配、工具调用、结果校验」＝全库唯一把「装配」写成流水线环节的实践，本期首次当主线；配 143 期成本、165 期账本。判词：**本地把装配写进流水线，联网侧 2026 年才把提示缓存做成默认；两边都没把「这次命中是不是当前版本」做成缓存字段。**
