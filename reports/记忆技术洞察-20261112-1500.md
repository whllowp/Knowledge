# 记忆技术洞察 第64期：前瞻性记忆——被遗忘的"另一半"

> 生成时间：2026-11-12 15:00 ｜ 固定四维：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战
> 覆盖来源：arXiv（Pro-Memory 2611.05731、Task-Conditioned Utility 2611.03930、EvoMemState 2611.03743、MemRole 2611.01778）；OpenViking v0.5.4.1、Hy-Memory 2.0.14、TencentDB-Agent-Memory v2.0.3、dsh-memory-evolve v26092802、ReMe（含 proactive discovery）

## 主线与新观点

前 63 期把记忆的"回顾性"象限（Retrospective：发生了什么、如何召回、如何修正状态、如何防投毒与回滚）近乎做透，却始终绕开"前瞻性记忆"（Prospective）：记住一个面向未来的意图，并在恰当时机、不被催促地自行实现，同时抑制不该触发的干预。Pro-Memory（arXiv:2611.05731，11-03）首次把"维持未来意图"与"决定何时实现"拆成两个正交子问题。本期权的新观点：**前瞻性意图应成为与 Chat / Working / Coding 并列的第四类一等记忆资产；且它与"任务条件效用"（2611.03930）是同一枚硬币的两面——一条记忆的价值，只在它服务于某个未来任务、并在对的时机被激活时才成立。**

## 发展趋势

记忆建模正从"事实堆叠 / 状态修正"转向"意图就绪 / 任务效用"。EvoMemState（2611.03743）用 RL 学习"推理态"决定事实如何应用于当前请求；MemRole（2611.01778）把"记忆→决策"显式化为 LHMT 推理模式；Pro-Memory 把"未来意图 + 激活条件 + 解决证据回流"做成闭环。评测也从"能不能找到"升级为"是否在对的时机被想起、是否被无用触发污染"。

## 技术现状

六家产品仍以回顾性为主。OpenViking v0.5.4.1（~42k★，AGPL-3.0）的 viking:// 与 Agent Evolution 仍是"沉淀经验"；Hy-Memory 2.0.14 的 L4–L6"Mind & Intent / 前瞻意图"把意图存成静态事实，而非"带激活条件的意图"；TencentDB v2.0.3 的 Skill 是可复用未来动作但被动（仅被检索）；dsh-memory-evolve v26092802 五轨记忆无意图激活层；ReMe 的 proactive discovery 仅做"主动补记忆"，不触发自主动作。无一实现"条件满足时自行行动、否则静默"。

## 技术竞争力

倒挂延续：前瞻性最完整在论文（Pro-Memory 在延迟意图与开放协助两基准上跨多骨干稳定优于代表性记忆法，且抑制多余干预），产品零披露。但 Pro-Memory 仅框架、无持久化与公开基准；任务条件效用（2611.03930）公开了带版本的 Conditional Memory Utility Dataset，给出"同一记忆对含答案任务对的增益比匹配控制对高 +0.33（95% CI +0.21~+0.46）"——首次把"该不该留这条记忆"变成可测变量，却未被任何产品采用。

## 技术挑战

①意图—动作耦合：记住意图易，判断"现在该不该做"难，过早过晚皆错；②激活条件表达：用自然语言还是结构化谓词描述触发时机？③抑制与频次：如何避免每次相关观察都触发、又不漏关键时机；④与回顾性记忆冲突：前瞻意图与已存事实矛盾时谁优先？⑤效用闭环：如何用任务条件效用反推写入与保留（2611.03930 的 cost ledger 思路）；⑥产品落地：单库架构加"意图态 + 激活态 + 解决回流"等于新增一类生命周期。

## 需求分析

真实场景里用户常说"下次 X 出现时提醒我做 Y"，而非"记住 X"。需求本质是：**以未来任务为锚，存储带激活条件的意图，并在运行时持续比对观察、恰当触发、执行后回流证据**。这要求记忆系统从"问答检索"升级为"意图调度"。

## 用户旅程

投研用户说"等这家公司发布年报就提醒我重估仓位"：系统把该意图存为 prospective 条目（目标=年报发布事件、动作=重估提醒、抑制=未发布前不骚扰）；随后每次会话自动比对公开信息流，年报一发布即在恰当轮次主动提示并附证据，用户确认后标记 resolved，经验回流为未来同类意图的触发策略。

## 具体实现方案

1. **第四类资产 Intent Memory**：在 Chat/Working/Coding 外新增 prospective 轨道，条目含 goal / trigger_condition / action / suppression_rule / state（pending/active/resolved）。
2. **意图—激活分离**：参考 Pro-Memory，写时只存"意图+支撑证据"，运行时由独立"激活判定器"比对观察与 trigger，避免把"记得"误当"该做"。
3. **解决证据回流**：动作发出或外部确认后更新 intention state，并沉淀进 experience memory 指导未来触发（Pro-Memory 闭环）。
4. **效用导向剪枝**：用任务条件效用数据集思路，对每条意图/事实记 cost ledger，低效用且长期未触发的意图降级或归档（深化第 53 期退化率）。
