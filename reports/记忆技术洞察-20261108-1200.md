# AgentMemory 技术洞察（第 30 期）：记忆的利用率——价值不在条目，在"送达形态"

- 期次：2026-11-08 12:00（第 30 期）
- 覆盖范围：2026 年全年，重点为 2026-10-09 至 2026-11-08 的公开材料
- 主线：**全行业都在优化"送得对不对"，没人量"送了有没有用"；而数据说，有用的比例是个位数，且集中在极少数送达形态上**

---

## 一、发展趋势

前二十九期沿着生命周期逐段追问，从写到删、从指认到对账，共享一个从未被检验的默认值：**送出去的记忆，等于被用上的记忆**。

本周两条独立证据线同时把这个默认值打掉。MemUse（2611.01718，11-01）把评测挪到"使用点"，在 8,000 集 SWE-bench 轨迹里逐条回看每次送达的去向；GroupAssistBench（2611.04867，11-03）用 50 个真实群聊、80,299 条消息、逾 5.3 万美元构建成本，把"召回"（L1）与"使用"（L2）拆成两级打分。两边结论同向：**能召回不等于会用，而"会不会用"才是任务成败的预测变量**——GroupAssistBench 里"召回却未用"的比例与 L2 排名的相关性是 ρ=0.89，召回本身只有 0.56。

趋势由此换轴：从"记得住"、"删得掉"、"敢不敢信"，推进到"**值不值**"。而这一问目前没有一家产品能回答——它们连"这条送出去几次、被用上几次"都不记。

## 二、技术现状

### 2.1 六个指定项目的本周状态

**OpenViking** 主仓停在 v0.5.3（11-02），DSH 插件却连发 0.5.31/0.5.32/0.5.33（11-02 至 11-06），重心从存储层转向接入层。L0/L1/L2 分级读法未变，无"被读取"计数出口。

**TencentDB-Agent-Memory** v2.0.3 维持 L0–L3 四层与团队记忆资产，本周值得注意的是它成了 MemUse 的被测系统之一，并被测出两个数字：复述率 88.4%，以及那个"每次都出现的角色说明块"单独贡献 18 个百分点的虚假相关性。**它 99.8% 的单集都交付过相关条目，剔除固定重复项后只剩 14.3%**——常驻块撑起了几乎全部表面相关性。

**Hy-Memory / MemHub** v1.0.6（底层 2.0.14）：30B-A3B 专业写入器、chat/working/coding 三类记忆、diff chain 保留"为什么改"，lite/pro/ultra 三档。它把"变更理由"做成了结构，却没把"使用证据"做成结构。

**ReMe** 本周最实的一步是 DSH 插件 0.1.2 的投递语义：私有 outbox、receipt 幂等重放、按端点独立排水、413 只暂停受影响会话、owner 锁与重启恢复。**投递可靠性到了队列级，投递效果仍零观测**。

**dsh-memory-evolve** 五轨（用户档案/全局事实/项目记忆/项目日志/技能待办）不变，`reviewEnabled` 每 10 个用户回合审查一次、默认关闭；最后 push 仍为 10-29，37 个 open issue。星数口径本周出现三个数（插件站 446、第三方核验 645、台账 665），只能记相对位置：DSH 记忆插件第一梯队。

**dsh-memory-tide** 是本周唯一在机制上回应本期主题的产品：热/冷两层，`promoteHits=3` 才钉住、冷层被查 5 次浮回热层、钉住 90 天未查自动解除、冷层超 120 个文件按日期删除。**它是全行业第一个把"访问次数"写成调度参数的记忆系统**。但 `usage.json` 按自然日去重（同日多次记一次），"高频"这一维在数据生成端就被抹平了。

**AML 二期**：11-04 关闭评测，官方口径 11 月中旬出榜，至 11-08 仍未发布。三个赛道、两个榜单，仍无"使用"维度。

### 2.2 五级漏斗：只有前两级有仪表

把一次记忆的生命拆开，是一个五级漏斗：**写入 → 送达 → 相关 → 采信 → 生效**。工程侧普遍埋了前两级（`memory_written_total`、`memory_recalled_count`，DeerFlow 一类实践再加平均相似度与 trace span），后两级是空白。MemUse 恰好把中间三级的留存率一次量了出来：

- **相关率**：每个送达片段中，71.5%–98.6% 的条目与任务无关。按系统看，MemGovern 15.08%、Mem0 约 1.42%、TencentDB 28.48%（含常驻块虚高）。
- **采信率**：所有系统里，51.3%–79.7% 的相关条目被晾在一边，既未据此行动也未引用。
- **生效率**：真正被采纳的 714 条中，421 条有益、16 条有害、64 条无可观察效果，另有 213 条（29.8%）无法判定。**有益条目只出现在 3.65%–7.05% 的单集里**。

两级失效通道由 GroupAssistBench 拆开：未采信的条目里 36% 根本没进 L2 输入（检索失败，且强烈依赖提示词是否点名——L1 直接点名时六套系统有四套能取回 84%–100%；词面重叠度上升，输入覆盖率从 62% 升到 83%），剩下 64% 进了输入仍未被用。**记忆系统会失败两次：一次找不到，一次找到了不用。**

### 2.3 形态集中律：价值挂在"怎么送"，不挂在"送哪条"

本期最重要读数：MemUse 按送达形态统计有益条目分布：

| 系统 | 受益形态 | 占有益条目 | 占送达词元 |
|---|---|---|---|
| MemGovern | 完整经验卡片 | 96.4% | 12.5% |
| TencentDB | 完整技能 | 86.0% | 2.0% |
| Mem0 | 任务开场召回 | 75.8% | 13.0% |

三种形态各自只占一成上下的词元，却承接了八成以上的收益。由此可以下一个强命题：**记忆的收益是形态的函数，不是条目的函数**。同一批条目，装进完整卡片和塞进常驻角色说明，产出差一个量级——词元效率上，MemGovern 每百万送达词元换 50.50 条有益条目，其余配置只有 3.08–4.92 条，**10–16 倍差距，靠的不是检索更准，是形态不同**。

这解释了为什么榜单分数与体感长期不符：榜单在给"形态配置"打分，却报告成"系统能力"分。也解释了"常驻即税"——固定注入块的边际相关性趋零，token 恒定支出，Mem0 有 68.1% 的送达词元是智能体本来就能看见的副本。

### 2.4 成本侧：盈亏平衡查询数（BEQ）

GroupAssistBench 给出了比 NPV 更可采购的一个数：LightMem 构建成本 69.6 美元，EverMemOS 814.9 美元，后者需要 **11,138 次查询**才追平。MemUse 侧同构：单集成本从 0.0045 美元（MemGovern，+8.8%）到 0.0178 美元（TencentDB，+293.2%），而解决率四套配置全部落在 72.65%–73.35%，与无记忆基线 72.95% 的差距不超过 0.40 个百分点，置信区间全部含零。

**同样的结果，账单差近四倍。** BEQ 把"该不该上记忆"变成可算的题：日均查询量低于 BEQ，这套记忆在财务上就是负的，与它多先进无关。

### 2.5 调度侧的新解：把"何时送"从主智能体剥离

MemSidecar（2611.00779）把记忆调度与任务执行解耦：Hooks 在执行事件命中条件时直接投递绑定记忆，Foresight 用独立智能体预测查询、并行取回并缓存，MCP-Persona 上得 41.23% 与 44.34%。**送达不再由主智能体临时发起**——与第 11 期"读同步写异步"互补：读仍同步，发起点换了人。

## 三、技术竞争力

| 方案 | 使用计数 | 计数去向 | 成本-收益证据 | 形态可配 | 常驻块控制 | 相关未用披露 |
|---|---|---|---|---|---|---|
| OpenViking v0.5.3 | 无 | — | 仅 token 降幅 | L0/L1/L2 | 摘要先行 | 无 |
| TencentDB v2.0.3 | 无 | — | 单集 +293% | 技能/条目 | 弱（18pp 虚高） | 无 |
| Hy-Memory 2.0.14 | 无 | — | 无 | 三类记忆 | 中 | 无 |
| ReMe 0.4.2.2 | 无 | — | 无 | 日记/知识页 | 中 | 无 |
| dsh-memory-evolve | 无 | — | 无 | 五轨 | 中 | 无 |
| dsh-memory-tide | **有** | **仅晋升** | 无 | 热/冷索引 | **强** | 无 |
| Mem0 | 无 | — | +8.8% | 开场召回 | **差（68.1% 复述）** | 无 |
| Zep / Graphiti | 无 | — | 无 | 事件/边 | 中 | 无 |
| EverMemOS | 无 | — | **BEQ 11,138** | 有 | 中 | 无（仅论文） |
| MemGovern | 无 | — | 50.50/百万 token | **卡片制** | 强 | **有** |

十行里"使用计数"只有一格（dsh-memory-tide），"相关未用披露"只有一格（MemGovern，且是论文而非产品），"成本-收益证据"两格。**这一栏的空洞程度超过此前任何一期**：第 12 期的 owner 字段至少还有一张表，这里连表都不存在。

分层很清楚。**第一档"有形态无计量"**：MemGovern 与 MemSidecar 证明形态决定收益，但都停在论文。**第二档"有计量无闭环"**：dsh-memory-tide 记了访问次数，只用于升降层，不回流到写入与形态选择。**第三档"两样都没有"**：全部商业产品，包括装机量最大的几家——它们能说出库里有几条，说不出有几条被用过。

不太乐观的判读：**利用率是唯一一个"厂商越强越不愿公开"的指标**。库容、时延、召回率都能做成宣传材料，利用率不能——它一旦公开，等于承认大部分记忆是死重。这与此前二十期的"倒挂"不同：不是能人没做，是能做的人没有动机做。

## 四、技术挑战

**归因不可分。** 一次任务里多条记忆共同作用，收益无法按条分摊，成本也无法按条拆分（MemUse 自认只能按插入位置估算体积）。29.8% 的"效果无法确定"就是这条限制的直接读数。这与第 22 期的信用分配同构，但对象不同：那是训练侧给"件"分配梯度，这是运营侧给"条"分配功劳。

**利用率陷阱。** 用"从未命中"做淘汰判据会自我实现：不读→删→更不会读。而低频但必需的记忆（一年一次的合规条款、一次性的部署拓扑）恰好全在这一格。dsh-memory-tide 的处理是对的——**使用只用于晋升，不用于淘汰**（单向棘轮），淘汰仍按日期与容量。这条原则目前只有一家社区插件无意中实现。

**计数口径本身失真。** 同日去重抹掉频次；复述计入送达（Mem0 78.2%）；固定块计入相关（TencentDB 18pp）；L1 命名式提问抬高召回（84%–100% 对 62%）。四个口径偏差叠加，足以让同一系统的利用率相差数倍。

**评测的选择偏差。** 所有记忆基准的题目都从"库里有答案"反向构造，天然过滤掉零命中的记忆——**benchmark 测的是条件分布，不是联合分布**。GroupAssistBench 用开放请求（L2 无固定答案）缓解了一半，但仍要求"请求确实需要群历史"。

**行为数据的隐私。** 使用统计本质是注意力画像：哪条被读、何时被读、读了几次。第 26 期的元信号泄漏在此复现——**为了优化记忆而采集的遥测，本身就是一份用户档案**。

**盲信期。** BEQ 之前没有使用数据，而采购决策必须发生在使用之前。冷启动（第 16 期）与利用率存在天然时间错配，唯一解是先用形态与领域先验代替证据。

## 五、展望与建议

**换三个指标。** 用 **NRR**（零命中率，从未被任何查询触达的条目占比）替代"记忆条数"，用 **HCR**（命中集中度，前 1% 条目承载的命中份额）替代"平均召回率"，用 **CPB**（每条有益记忆的成本）替代"每千 token 成本"。三者都能从现有日志算出，不需新架构。

**把形态当第一优化变量。** 在"写什么"上继续投入的边际收益已经很低（29 期的对账、24 期的规模律都指向同一结论）；而"以完整卡片还是以常驻块送"这一个开关，在本周数据里值 10–16 倍。先砍常驻块与复述，比换模型更直接。

**单向棘轮写进设计。** 使用计数只能提升优先级、延长保留、触发晋升，不得作为删除依据。删除仍由时间、容量、显式指令决定——三条都可审计，唯独"没被用过"不可。

**采购条款加两问。** 一问"上线后能否导出每条记忆的送达次数与采信次数"，二问"这套配置在我们的日均查询量下，BEQ 是多少"。答不出第一问，等于买了一个不可验收的系统；答不出第二问，性价比无从判断。

**一个预测。** 12 个月内会出现第一份"记忆使用报告"（Memory Usage Report）作为产品功能——最可能出自本地优先阵营（OpenViking、MemHub、ReMe），因为它们的数据本来就在用户机器上，公开利用率不构成商业自杀。云端厂商会晚 1–2 个季度，且大概率以"节省了多少 token"的形态出现，而非"有多少条被用过"。

**最后一个提醒。** MemUse 里最冷的一刀：260/383 的有益使用发生在基线四次都解出来的任务上，而基线四次都解不出的 79 个任务里，73 个仍然没解出来。**记忆改变的是顺风局的成本，不是逆风局的上限。** 若这一点成立，下一期该追的就是定价：按"节省"卖，而非按"增强"卖。
