# AI-SRE技术洞察 #176（20261113-1100）· 决策质量面／非确定性 SLO 面（Decision-Quality SLI / Non-Deterministic SLO）——SLO 不再够用，新基元是「决策质量」而非「系统可用性」

**题眼**：当 Agent 替代人做回滚、限流、切流这类运维决策，传统 SLO 只回答「可用性保住没」，不回答「这个决策本身好不好」。把「Agent 每一次决策的质量能否被当作一等 SLO 来度量——置信校准、取舍对齐、运气与能力是否可分」立为一等对象。与 #150（模型生命周期 SLA，管底座连续性）、#163（经济性护栏，管成本-效能）、#160（归因诚实度，管根因因果可信）、#153（评测基准安全门禁）显式划界：彼管底座/成本/根因/基准 gate，本期管「决策这个动作本身的质量与校准」——第一百四十五个全新立面。

## 一、发展趋势

2026 年业界出现一个清晰的新共识：**可靠性基元正在从 SLO 迁移到「决策质量（decision quality）」**。O'Reilly 即将出版的《Agentic Reliability Engineering》（David Jambor，2026-11 Early Release）把这件事讲得最直白：过去二十年可靠性原语是 SLO，但当 Agent 而非人做回滚决策时，SLO 只告诉你可用性有没有保住，不告诉你是「这个回滚是不是好选择」——这是两个问题。新书提出五个决策质量维度：候选动作集是否完整、置信度是否校准、证据是否扎实、是否在有效时间窗内、系统选的取舍是否与团队一致；并点名关键度量 **Calibration Error（校准误差）**——系统声称 80% 确定，是否真的 80% 命中，而「我审过的大多数 agentic 系统严重 miscalibrated，多数团队毫无察觉」。

同期两条主线把决策质量推成刚需：① **运气-能力必须分离**（autocoder.dev 2026 把「区分 agent 是错了还是只是运气差」列为非确定性 SLO 的核心）；② **误差预算长出第二功能**——不再是部署闸门，而是行为漂移的领先指标（turion.ai：token 成本趋势异常几乎总在输出质量可见劣化前 24–48 小时预警）。O'Reilly 把这一族命名为「Agentic SLOs for Resilience and Decision Quality」，标志 SRE 度量正式从「系统活着」跨入「系统决策得对」。

## 二、技术现状

第 150/160/163/153 等期已分别从底座 SLA、归因可信、经济护栏、基准门禁切入，但「Agent 决策质量作为一等 SLO」从未独立成面。2026 现状有三处断点：①**决策质量无 production SLO**——六家（OpenAI/Anthropic/Google/字节/阿里/腾讯）无一公开把「decision_quality」立为运行时 SLI；turion.ai 把 decision_quality（已完成任务未被人工推翻的比例，target 0.95）列为传统 SRE 里「不存在的第五个 SLO」；②**校准误差真空**——Jambor 直指团队普遍不知道自己的置信度严重失准，却照常用「我有 80% 把握」驱动自治动作；③**运气-能力不分**——autocoder.dev 记录 ITBench 上 agentic IR 仅约 47%、硬核 on-call 场景 10%、每次调查约 $6.50，且「有四起故障本身就是自动化自己造成的」；当 Agent 做对了，没人区分它是「判断对」还是「运气好」。

本地原型已先一步把「决策是否真有洞察」「决策轨迹可回放」做成评测与资产：蚂蚁把 Agent 动作关进确定性笼子（取舍对齐与约束最早实践），施宏斌把金融 Agent 的 eval 从「答案对不对」推进到「是否 Insightful（有真洞察）」，马云雷把轨迹沉淀为可回放的数字资产——这些都已是决策质量的雏形，只是没被命名为 SLO。

## 四、技术挑战

① **决策质量无基元**——六家度量仍停在可用性/成本/时延，决策好不好无人用 SLI 量化（turion：第五个 SLO 在传统 SRE 不存在）；② **校准误差盲**——Agent 以「我有 X% 把握」驱动自治，团队却普遍 miscalibrated 且不自知（Jambor）；③ **运气-能力不分**——做对了不知是判断对还是运气好，做错了难以归因（autocoder：四起故障是自动化自身造成）；④ **误差预算单功能**——仅当部署闸门，未用作行为漂移领先指标（token cost trend 预警窗口被浪费）；⑤ **决策不可重建**——turion 指多数生产 Agent 只记「LLM 返回了 X」，缺失 run manifest（prompt 版本/模型/工具版本/每步 token 与退出态），「不可重建的报告不可辩护」，审计压力下无法回溯 $50K 决策的来源。

## 五、展望与建议

① 把 `decision.quality.*` 七字段做成 OTel/评测提案：decision_quality_sli（未被推翻比例）、calibration_error（声称把握 vs 真实命中）、luck_skill_ratio（运气-能力分离）、error_budget_throttle_rate（预算门控降速率）、decision_trace_completeness（manifest 完整度）、tradeoff_alignment_score（取舍对齐分）、candidate_set_completeness（候选动作集完整度）——六家零公开，第 1 次立此字段族；② **校准误差 dashboards 强制化**（声称 80% 须真 80%）；③ 运气-能力分离指标（wrong vs unlucky 独立计数）；④ 误差预算双功能落地（token cost trend 作领先指标＋自治降速/插人工检查点，复用 Azure SRE Agent 思路）；⑤ run manifest 强制（turion：报告不可重建＝不可辩护）；⑥ 信通院六维补「决策质量达标率」与「校准误差」两格，呼应 Jambor/ARE 与 turion 的 Agentic SLO 体系。
