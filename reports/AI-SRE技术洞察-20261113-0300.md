# AI-SRE 领域技术洞察报告 · 第 164 期

> **题眼｜知识复利闭环面（Knowledge Compounding Loop / 经验资产化与防退化）**
> 首次把"组织的运维知识能否随每次事故**复利增长而非复利错误**"立为一等运维对象；与 159(确定性策略执行点·过不过闸门)/160(输出因果可信度·根因对不对)/161(人机信任校准·人信的分量)/162(Agent 自身可观测·能不能看见动作)/163(经济性护栏·账算在谁头上)显式划界：彼管"动作/诊断/信任/可见性/成本"，本期管"**经验资产化是否真的让下次更准，还是把错误也一起存了下来**"——最隐蔽的元风险，因为污染的知识比缺失的知识更危险。

---

## 一、发展趋势

1. **从"会行动的 Agent"到"会成长的 Agent"。** 2026 下半年行业共识从"分级自治 + 护栏"进一步推进到第三标志：知识复利闭环。Agent 不再只是执行一次诊断，而是把每次事故转成可复用、可验证、可版本化的资产。
2. **三股力量汇流。** ① 复盘自动化（postmortem auto-gen，Google SRE Extension、腾讯故障复盘智能体、PagerDuty 5 步法）；② 轨迹资产化（Trajectory-as-Asset，阿里云 AgentLoop）；③ 在线 RL 闭环（AReaL 2.0 把已部署流量转成 Online RL，无需重写 Agent）。
3. **知识从"RAG 检索"升级为"被治理的生命周期对象"。** 重点不再是"能否查到历史事故"，而是"结论是否附证据、是否带版本、是否被回写、是否被防退化"——skill.re 为此在 Agent 事故复盘模板中新增 **Version drift（版本漂移）** 与 **Eval gap（评测缺口）** 两个字段。
4. **左移成为闭环终点。** 腾讯"一次复盘、全域预防"、Google"设计期风险发现"表明，知识复利的检验标准是"下次事故是否被提前拦下"，而非"报告写得多漂亮"。

## 二、技术现状

- **国际厂商**：Google 以 **AI Insights** 持续复盘历史事故、构建"operational memory"并结合风险标注层给 Agent 带上"谨慎权重"，SRE Extension 可自动生成结构化复盘与指标图；OpenAI **SevBot** 挂载按服务命名的只读 runbook、关联相似历史事故，但知识回写为静态挂载；Anthropic **Claude on call（Claude Tag）** 把 standing instructions 写成提交进 GitHub 的 markdown skill，并维护 `lessons.md` "self-improvement loop"，将团队事故史转成 triage playbook；PagerDuty 五步法"操作记忆→自治执行→左移预防"；Komodor 强调"会学习的 Agent = 记忆 + 反馈 + eval 闸门"，并警告 stale memory 与 version drift。
- **国内厂商**：阿里云 **AgentLoop**（马云雷）提出"让轨迹成为数字资产"四阶段闭环（资产基础→质量数据/Badcase→Benchmark→优化产物→价值验证），经验注入使 StarOps 指标查询 **7.1%→36.1%**、整题通过率 **79%→88%**；腾讯**故障复盘智能体**将报告"认知结晶"为案例/知识点/因果子图/整改规则入库，并向巡检、变更、混沌、容量平台自动左移；快手智能运维助手（吴垚）走"评测→迭代 SOP→录入知识库"进化闭环；百度 SRE Agent 探索自主进化；**AReaL 2.0** 在线 RL 闭环由清华、蚂蚁、华为、字节、小米、腾讯共同维护。
- **本地讲义原型（173/173-kb）**：温睦宁（自进化智能体 = 基座 + 可更新组件 + 反馈信号 + 更新规则，**"只要反馈不回写，再会行动也不叫自进化"**）；马云雷（四阶段轨迹资产闭环）；余锦泽（本体记忆：错误关系留在记忆里会反复出错——**记忆污染**）；吴垚（快手助手自进化，从不准到准）。

## 三、技术竞争力（主要厂商/方案对比表）

| 厂商/方案 | 知识留存机制 | 自动复盘/抽取 | 经验回写/自进化 | 防退化/评测闭环 | 知识左移/预防 | 可治理/开放 |
|---|---|---|---|---|---|---|
| **Google** | AI Insights operational memory + 风险标注层 | SRE Extension 自动复盘+指标图 | 持续 review/改进 runbook、事后起草 playbook | 分级自治 L0-L4 + 持续评估原则 | 设计期风险发现、异常告警 | 红钮全局暂停 + MCP（强） |
| **OpenAI** | 挂载只读 runbook + 历史事故记录 | SevBot 关联相似事故 | 无显式自进化，依赖 eval | Agents SDK tracing + 人工审批 | 弱（未提左移） | 沙箱隔离 + human approval（强） |
| **Anthropic** | Claude Tag 跨渠道记忆 + 版本化 skill | Claude on call 自动首报/复盘 | `lessons.md` 自改进循环（保守） | "auditable loop，非魔法学自主" | 弱 | 托管运行时 + vault + memory dreaming |
| **字节跳动** | AReaL 数据代理捕获交互 | 中 | AReaL 2.0 在线 RL 闭环（基础设施级） | 轨迹可回放可治理 | 弱 | 开源社区供应商中立（强） |
| **阿里巴巴** | 轨迹数字资产 AgentLoop | Badcase→Benchmark | 经验注入 StarOps +29pp（**最强实证**） | 受控发布 + 回归集更新 | 中 | 阿里云原生可观测 |
| **腾讯** | 故障知识图谱 | 结构化复盘报告自动生成 | 认知结晶入库 | 置信度卡点 + 反馈闭环 | 自动左移全域预防（**最强**） | MCP + A2A 开放协议 |

**判读（反转）**：最强知识复利来自"运维现场 + 实证"侧——阿里经验注入有硬数据、腾讯左移全域预防、Google operational memory ——而六家 SRE Agent 平台在"**经验注入增益 / 知识污染召回率 / 版本漂移率**"等可计量列几乎全空；纯通用 Agent 厂商（OpenAI/Anthropic）把知识当作"挂载 runbook / 版本化 skill"，缺乏回写实证。即："分级自治、护栏、记忆"可采购，"**举证知识在每次事故后真的更准、且没存错**"不可采购。

## 四、技术挑战

1. **记忆污染 / 知识复利反噬**：余锦泽实测"错误关系留在记忆里，后续查询反复出错"；Komodor 与 skill.re 点名 stale memory 与 version drift——这是比"不会学"更隐蔽的风险。
2. **经验不回写 = 不会成长**：温睦宁断言"反馈不回写，再会行动也不是自进化"；若 Badcase 未进数据集，同类缺陷反复出现。
3. **质量随业务漂移**：马云雷指出"离线通过 ≠ 长期稳定"，需持续在线评估、聚类、归因、回归集更新。
4. **Eval gap 沉默**：每个事故若未转化为 eval 用例，便失去永久改进机会，组织重复为"换了衣服的同一事故"买单。
5. **知识左移的组织阻力**：prevention 永非最紧急项，复盘入库后常无人消费，闭环在终点断裂。
6. **隐私与权限**：Agent 轨迹与知识库比基础设施含更多 PII（与 162 自身可观测同源），需 pipeline 脱敏。

## 五、展望与建议

- **把"知识复利闭环"立为一等运维对象**，定义 `kb.*` 字段族（**第 114 个市场空白**，`kb.*` **第 81 次无人提字段族**）：
  `kb.drift_rate`(知识版本漂移率) / `kb.contamination_recall_rate`(污染知识召回率) / `kb.write_path_human_rate`(人审写路径覆盖率) / `kb.evidence_attached_rate`(结论附证据率) / `kb.experience_injection_lift`(经验注入增益) / `kb.left_shift_action_rate`(左移执行率) / `kb.eval_gap_coverage`(评测缺口覆盖)。
- **落地建议**：① 复盘模板必含 **Version drift + Eval gap** 两字段；② 记忆带证据 + aging，近因确认记忆优先；③ 经验以"轨迹→Benchmark→可执行能力"回写（阿里 AgentLoop 范式）；④ 知识自动左移至巡检/变更/混沌/容量（腾讯范式）；⑤ 接本地三原型（温睦宁自进化公式 / 马云雷四阶段 / 余锦泽本体校验防污染）；⑥ 评测增 `kb.*` 七字段，并建议信通院补"知识复利达标率"格。
