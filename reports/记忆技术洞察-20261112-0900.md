# 记忆技术洞察 第59期：记忆的可携带性与互操作性——当"离开"成为一种能力

> 生成时间：2026-11-12 09:00 ｜ 固定四维：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战
> 覆盖来源：arXiv 记忆论文、OpenViking、TencentDB-Agent-Memory、Hy-Memory、dsh-memory-evolve、ReMe（含 ReMe2Ops）、W3C/SAIHM/OAMP 标准动态

## 主线与新观点

前 58 期把"记忆主权"陆续拆成了写入权（第1期）、删除权（第2期）、可寻址权（第3期）、内省权（第52期）。本期补齐最后一块，也是被行业刻意回避的一块——**携带权（portability）**。核心反共识观点：**记忆主权的最终形态是"携带权"而非"删除权"**：若你无法带着记忆离开一个平台，删除只是房东的恩赐。更尖锐的是——记忆越深，平台切换成本越高（被指"远超社交媒体时代"），因此可携带性不会由厂商自发提供，只能被 GDPR 第20条（数据可携带权）与 AML C2（11-19 预期出榜，用"可比性"倒逼互操作）从外部强行挤出。

## 发展趋势

互操作正从"nice-to-have"升格为"宪章级标准"。W3C「AI Agent Memory Interoperability」社区组 2026-07-16 通过 v1.0 宪章（便携记忆单元格式、后量子身份 ML-DSA-65、能力范围共享+撤销、防篡改审计、对齐 GDPR 第17条）；其规范锚定 SAIHM（IETF 独立提交草案，钱包派生密钥客户端加密、毁钥即擦除）；OAMP 已发 v1.2、v1.3 草案新增 granted-scope 治理内存。国内不写协议、改做"搬家工具"——MemOS-MindDock、ContextDrop 一键抓取豆包/Kimi/ChatGPT 记忆注入任意 AI，在豆包 7 月下线自定义智能体时直接接住了失忆用户。

## 技术现状

六家产品**无一"真便携"**。OpenViking v0.5.4（11-09，41.9k★）以 `viking://` 文件系统统一寻址、只读/写分道，但 AGPL-3.0 + 实例孤岛仍是事实锁定；TencentDB Agent Memory 借 Memory Proxy 接 9–10 客户端却用私有协议、MongoDB 后端；Hy-Memory 绑 SDK；dsh-memory-evolve 用本地文件+git 分支标签（最廉价可迁移历史）；ReMe 以 `.reme/` Markdown 文件即真相（Apache-2.0，最开放格式）；Hindsight 走"服务端而非格式"路线，transfer ZIP 跨实例重嵌、自称零 token 零新事实。

## 技术竞争力

分两派——**格式派**（OAMP/SAIHM，赌规范胜出）与**服务端派**（Hindsight/MCP，用 bank id 做实时寻址）。胜负将由 adoption 而非规范质量决定。值得注意的倒挂：论文与 W3C 谈互操作，产品却集体用私有协议筑墙；AML C2 作为**基准**而非标准，反而可能因"可比性"比宪章更快逼出互操作——这是本期对第56期"评测契约危机"的深化。

## 技术挑战

①"标准的标准"缺失——OAMP/Akashik/WAMP/LedgerSync/TradeMemory 并存未归一；②隐私保护共享（不暴露全量即共享上下文）；③跨代理层查询频率远高于单代理，规模化性能；④治理归属（谁拥有你的记忆、移动时如何审计）仍是最大未解之谜。

## 需求分析

企业 Agent 接入核心业务的最大卡点不是模型能力，而是"上周记住了客户什么、依据哪条对话、谁批准"的黑箱。合规（EU AI Act 高风险条款、GDPR 第17/20条）把"可治理白箱"变成硬门槛；同时用户在被停服时要求带走记忆。两股力共同定义需求：**可导出、可审计、可撤销授权**。

## 用户旅程

开发者在 Claude Code 沉淀项目上下文 → 切到 OpenClaw 重做同一任务 → 现因各自私有库从零开始；改用单一 MCP 记忆服务端后，所有客户端读写同一 bank，零同步零重述；当用户要求删除，服务端按 granted-scope 逐记录撤权并留防篡改审计；换厂商时执行 transfer export，目标实例重嵌重解析，不丢上下文也不造新事实。

## 具体实现方案

1. **服务端而非格式**：起一个 MCP 记忆服务，所有客户端（Claude Code/Codex/OpenClaw/Hermes）指向同一 `bank_id`，用 hook 在 SessionStart 注入项目画像。
2. **四元数据**：每条记忆携 `source + date + principal + granted_scope`，默认最小授权、显式授予视图。
3. **可携带导出**：用 OAMP 1.3 的 governed 结构 + transfer archive（去 embedding，导入时重嵌），定期演练 import 验证"搬家"成立。
4. **双轨擦除**：逻辑删（tombstone + 毁密钥）对应 GDPR 第17条，导出权对应第20条。
