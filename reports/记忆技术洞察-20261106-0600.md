## 一、发展趋势：十天内，"事件"顶替"事实"成为记忆的基本单位

**第一条证据来自厂商自己的发布说明。** 腾讯混元 Hy-Memory 2.0 讲聊天记忆的这一版改动，用词是"从零散事实升级成完整的事件脉络"——按事件梳理时间、地点、人物，遇多线索问题先合并重复、剔除冲突。这不是内部重构，是把"单位换了"写在对外文案里。

**第二条来自一次失败被讲清楚。** 11 月 3—4 日，华为 openJiuwen 的 AgentMemory 0.2.0 上线 OmniMem-Lens，正面反对"按分钟盲切"。例子极准：一段 14:20—16:50 的情节被 60 秒窗口连切两刀，成了"女生离开""男生目送""蝴蝶飞走"三段互不相干的记录；问"男生在想象什么"时，"蝴蝶只是幻想"这个限定语落在被切走的那一半，模型把幻想当事实。改为视觉切变与 ASR 话题转向双流交叉定界后，EgoLife-QA 召回 +45.7%，LVBench 时延 34.5s→1.72s——**增益最大的数据集，正是固定窗口必然失败的"一整天连续生活流"。**

**第三条来自一个反常的设计选择。** Hindsight 把会话切成事件粒度，并且**把"一次失败重试"单独算作一个事件**。事实抽取式流水线绝不会产出这种东西——重试没有新语义，只是重复。它被单独成条，说明该系统的单位不是"信息量"，而是"发生"。

两处旁证同样锋利：OpenViking 的会话归档已从"抽取结构化条目"演化为六字段事件模板——**时间、主体、诉求、承诺、分歧、未决问题**，其中承诺与分歧天生带有效期和对端，不可能是无时态的事实；QwenPaw 把记忆写入从"会话结束"改成"每轮经中间件写入"，等于承认"会话会结束"这个前提本身不成立了。

把十天的行业动作摆在一起：10-20 Databricks（MemCurrent）与 Autopoetic，11-02 阿里云，11-03 Hindsight，11-04 Redis、MongoDB+Google、PhoenixAI，**十六天七家**。形态分三派——存储派（记忆当数据库里的表）、管道派（强调后台巩固）、判断派（Hindsight 用专用小模型判"是否新/是否矛盾/哪条相关"，单次 167ms，通用 LLM 需 1—7 秒）。三派互不兼容，却共享同一句判断：**原始记录不是记忆，是证据；把证据变成记忆的那一刀，才是产品本体**。

## 二、技术现状：为什么"原子事实"这个单位撑不住了

**缺陷一：事实没有时态，冲突就只能靠"消解"，而消解无解。** 2026 上半年主流是 atomic fact（Mem0 抽取、Graphiti 关系边、TencentDB L1、Hy-Memory 8 层），它解决了"从长对话里捞出可检索的短句"，但三个缺陷在 11 月同时到期：无时态、必须去重、合并即断边。事实是断言（"用户偏好 Python"），断言之间非真即假，于是必须裁决谁对；可 15 项记忆校验中，矛盾检测、置信校准、教条度等 7 项主流方案均未实现。事件不是断言，而是"某时某处发生了某事"——两条矛盾的事实可以合法共存为两个不同时刻的事件，谁生效由时序决定，**不需要裁决**。第 2 期说"仅 Zep 把 `valid_to` 当一等公民"，本期补一句：一旦单位是事件，`valid_to` 不再可选，它就是单位的定义。

**缺陷二：事实必须去重，而 WASP-Mem 实证"人工规定的组织方式反而有害"。** 11 月 2 日的 WASP-Mem（arXiv:2611.04003）做了一项罕见的老实实验：预置人工 schema、显式去重规则这些"看起来更规范"的做法，**降低了** TheAgentCompany 的 checkpoint 通过率；而让 agent 自己把轨迹蒸馏成互链 wiki 页，通过率高 4.6—6.1pp，存储还少 57—61%。更反直觉的是分工：**一轮人工诊断胜过四轮自我判断 7.0—10.9pp**。反面读法很清楚——"去重"本身在消灭信号：同一故障发生三次，在事实库里是一条，在事件流里是三条，而"第三次"才是要报警的那条。

**合并会断边，所以本期最重要的一条工程结论是：正确分层不是"精度分层"，而是"可变性分层"。** ReMe 的插件文档里有一句被埋没的原则：**"从源文件重建派生索引；永远不要为了迁就索引而改写源记忆"**。它把记忆系统劈成两半——**不可变的事件源**，与**可重建的派生索引**（关键词、向量、摘要、图式、Skill）。判据很干脆：删掉它能否从源重建？能，是派生；不能，是源。

按这把尺子量一遍，多数系统量错了。OpenViking 的 L1 是"L2 的摘要"，重生成即覆盖——派生却承担了源的角色；Hy-Memory 的 `evolve()` 把个案蒸成图式，图式是派生却被当作可检索条目；TencentDB 的 L2 是路径可读写的 Markdown、L1 是原子事实，**两层之间没有说明谁可重建**。反过来，Autopoetic 用哈希链把实体、关系、事件串成追加日志，是唯一把"源不可变"写进数据结构的方案。

## 三、技术竞争力：加入"记忆单位"与"切分依据"两列

| 方案 | 记忆单位 | 切分依据 | 源/派生分层 | 合并与去重 | 时态内建 | 最强项 / 主要短板 |
|---|---|---|---|---|---|---|
| **Hy-Memory 2.0** | 事件脉络 + 8 层（含前瞻意图） | 未公开（宣称按事件梳理时/地/人） | 弱（图式覆盖个案） | 先合并重复再交模型 | 部分 | 单位最先进、写入由归因 RL 训练（30B-A3B）。短板：切分策略不披露 |
| **TencentDB** | L1 原子事实 / L2 场景块 | 异步管道逐层蒸馏 | 弱（层间无边） | 允许改写 | 无 | 治理最强（四类资产 + ACL + 按条计费）。短板：删 L0 不传播至 L1 |
| **OpenViking** | 六字段事件（时/主体/诉求/承诺/分歧/未决） | 会话 commit 后抽取 | 中（宣称保留来源链接） | LLM 合并去重 | 是（承诺/分歧自带期限） | 单位结构最完整、目录级 ACL fail-closed、token −34~91%。短板：摘要重生成覆盖旧版 |
| **openJiuwen OmniMem-Lens** | 事件（视听双流定界） | **内容边界**（视觉切变 × ASR 话题转向） | 强（L0 原始视频永不改写） | 不合并 | 是 | 唯一公开"切分算法"并给出切分失败案例。短板：仅多模态视频 |
| **Hindsight** | 事件（含失败重试） | 事件类型四分（对话/工具/重试/反馈） | 中 | 约束优化器裁决留/并/汰 | 是（写时/验时/状态三字段） | 判断外置为小模型，167ms/次。短板：未见开源实现 |
| **Redis Agent Memory** | 层级记录（MemoryETL 摄入） | 文档与用户行为双源 | 中（audit + provenance） | 可主动遗忘 PII | 部分 | 配 Lens 做结果回溯。短板：切分仍以文档/动作为界 |
| **Zep Agent Skills** | Skill（Trace 编译） | 一次 run 为界 | 强（claim 引事件、删源级联） | 准入由代码校验 | — | 唯一字段级引用完整性。短板：只覆盖过程性记忆 |
| **ReMe** | Markdown 条目 | 人 + `auto_dream` 巩固 | **最强**（明示"源不改写、索引可重建"） | 按 provenance 元数据去重 | 弱 | 分层哲学最正确、diff 即证据。短板：无自动派生关系 |
| **dsh-memory-evolve** | 文件（五轨） | 人写 + 分支 | 中（归档可逆） | 交人裁决 | 无 | 作用域最细（分支级）。短板：切分完全靠人 |

**表外三条结论。**

第一，**"事件"已是共识，"切分算法"还不是。** 九家有六家宣称事件级单位，却只有 openJiuwen 公开了切分判据并给出反例。其余五家要么藏在 `Add` 接口里（AML 正是如此——参与者控制"如何压缩、索引、重排"，评测方只看下游），要么藏在提示词里。**切分是唯一既决定全部下游、又完全不被审计的环节。**

第二，Redis Lens 表面上补上了第 3 期判定的"C 级可归因无人"。它声称"每个结果可回溯到服务它的 skill、route 或 FAQ、它学到的记忆，以及源 session"。但要辨析：这是**事件级重放**，不是因果归因——重放回答"当时用了什么"，归因回答"去掉它结果会不会变"。**C 级仍无人，但 B 级的门槛已从"字段"拉到"链路"，这是对上一期判断的修正。**

第三，**计费单位开始与记忆单位错配。** TencentDB 按"条·小时"计价（0.02 元/万条·小时），而条数由切分粒度直接决定：切成事实是一万条，切成事件是两千条，账单差五倍，能力未必差。**当计价单位本身是架构选择而非物理量时，采购比价就失去了可比性**——这是本期新发现的商业问题。

## 四、技术挑战

**挑战一：切分没有 ground truth。** "这件事从哪开始"是解释性的，不是事实性的。EgoLife-QA 的 +45.7% 只验证了"事件切分优于固定窗口"，不是"某种切分是对的"。没有金标准就没有可优化的损失函数，切分只能靠下游效果间接调，而下游效果混着检索、排序、模型能力三种噪声。

**挑战二：切分不稳定，幂等就是空话。** MongoDB 的幂等摄入解决的是"同一 session 重放两次"；但若切分由模型判定，模型版本一换边界就漂移，重放产生的是**新事件**而非重复事件——幂等的前提在切分层不成立。Hy-Memory 的 MemHub 给写入加了自动重试与暂停，保的是"写成功"，不是"切一致"。

**挑战三：长驻 agent 抽掉了锚点。** 按会话切的前提是会话会结束；QwenPaw 改为每轮写入，等于承认锚点消失。可每轮切会把"一次三小时、跨十七轮的故障排查"切成十七段，正好复现 openJiuwen 批判的断章取义。**没有会话边界的地方，事件边界必须由内容自己长出来**——多模态刚有解，纯文本长会话还没有公开方法。

**挑战四：切分粒度就是隐私粒度。** 切得越细，单条越难独立解释，越必须靠标识符串联，而第 3 期已论证稳定标识符是最强的关联键。**为了"记得准"而切细，同时是在制造画像入口**——粒度可调，标识符不能不发。

## 五、展望与建议

**给建设者：把表拆成两张，按"能否重建"划线。** 事件源表只追加、不 UPDATE、不改写，字段取 OpenViking 那六个（时间、主体、诉求、承诺、分歧、未决）+ 三个时态（`valid_from`/`valid_until`/`superseded_by`）；派生表存摘要、向量、图式、Skill，带 `rebuilt_at` 与 `src_event_ids`，随时可 DROP 重建。它把"删不干净"和"改了就丢血统"两个老问题一次消掉。

**给平台方：把切分策略当 schema 发布。** 至少公开切分依据（时间窗/内容边界/模型判定）、最小单位定义、边界漂移时的处理。客户迁移记忆时第一个撞上的不是格式，是"你的一条和我的一条不一样长"。

**给评测方：AML 增设"切分稳定性"探针。** 同一段输入摄入两次比边界一致率，再换一次模型版本看漂移率。WASP-Mem 已证明"人工规定组织方式有害"，那么"切分是否可复现"比"切分是否最优"更值得先测。

**用一条理论收口。** 11 月初的《Do agents need to sleep?》（arXiv:2611.02216，Haber 与 Tononi）把睡眠的"振铃—共振—重整"映射到数字记忆，并给出可证伪预测：**记忆库越大，选择式巩固越会胜过指令式巩固**。WASP-Mem 的"schema 有害、agent 自组织更优"正是其小规模实证。若成立，未来一年的分水岭不是谁压缩得更狠，而是谁把"选择"做成系统能力——**事件单位是选择式巩固的前提，事实单位是指令式巩固的产物**。

**30/60/90 天判断**：30 天内 AML 二期出榜，预计 Coding 轨在噪声条件下普遍下探，且不出现切分或可追溯维度；60 天内会有一家厂商公开切分判据（openJiuwen 已开先例，OpenViking 六字段最接近可发布形态）；90 天内"事件源 + 派生索引"会成为新项目默认骨架，"记忆条数"作为计价单位被"事件数 + 派生重建次数"取代。
