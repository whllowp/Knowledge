# AI-SRE 技术洞察（第 173 期）

**生成时间**：2026-11-13 08:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：影响面／变更影响面（Blast Radius）——改一句 prompt，哪些 Agent 会变？没人算得出来；没有反向依赖图，变更就是盲改

---

## 题眼

127 期说「代码有流水线，行为只有热更新」：prompt、skill、model 的改动常常直接生效，没有发布评审。但缺的不只是流水线，还有**影响图**：**一句共享 prompt 被 20 个 Agent 引用，改一个标点，哪 20 个？** 137 期说工具会在 pin 下漂移、134 期说文档会过期、144 期说编队里 A 的错误会成为 B 的前提、111 期说假设会继承。把这些串起来：**Agent 的依赖是「行为级」的，不是「包级」的**——包依赖有 lockfile，**prompt/工具/知识之间的引用却没有反向图**。于是变更评审只能问「你觉得会影响谁」，**答案通常是「应该不会吧」**。**包依赖有 lockfile，行为依赖只有记忆。**

## 一、发展趋势

**趋势一：变更对象从「代码」扩到「行为」。** prompt、skill、工具描述、模型版本；**它们共享、复用、隐式引用**。

**趋势二：评审从「看 diff」转向「看影响」。** diff 只显示改了什么；**影响图才显示会动到谁**。**没有影响图的评审，是在猜。**

**趋势三：回滚从「回代码」变成「回一整套」。** prompt 回了、工具没回；**行为还是不回**（164 期）。

## 二、技术现状：三种共享，三种盲区

**共享 prompt：一对多。** 一个模板被多 Agent 引用；**改一处，影响面等于引用数**，但**引用关系没人记**。

**共享工具：多对一。** 多个 Agent 用同一个 MCP server；**工具升级，全体受影响**（137 期）。

**共享知识：隐式引用。** 文档/索引被检索；**改了文档，所有检索到它的 Agent 都变**（134／168 期）。

**现状：影响分析靠「问人」。** 谁写的谁猜；**新人猜不出来，老人猜不全**。

**影响三问，一问都答不上。** 谁在用（消费者）、影响到什么程度（行为差异）、怎么验证（回归抽样）；**答不上三问，变更就只能盲发**。

## 四、技术挑战

**一，引用是隐式的。** prompt 通过字符串拼接、工具通过名字、文档通过检索；**没有显式 import**。

**二，影响是行为级的。** 同一个工具，对不同 Agent 影响不同；**不能按「用了就影响」一刀切**。

**三，图会过期。** 新 Agent 上线、旧 Agent 下线；**图不更新，影响分析就错**（146 期）。

**四，影响不可验证。** 说「影响 20 个」，**怎么证明这 20 个真的变了**（123 期）。

**五，回滚范围不清。** 改了 prompt 和工具；**回滚只回了一个**（164 期）。

**六，跨团队共享。** A 团队的 prompt 被 B 团队引用；**变更通知发不到**（146 期）。

**七，图的质量决定结论。** 采集不到隐式引用（字符串拼接、检索命中）；**图不全，影响分析就是假精确**。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `impact.*` 字段**：`change_id`、`shared_asset`、`consumers[]`、`affected_agents[]`、`verified_count`、`rollback_scope`。
- **R2 反依赖图**：prompt/工具/文档 → Agent；**自动采集，不靠登记**。
- **R3 影响报告**：变更前生成「谁用、影响多大、怎么验」。
- **R4 验证抽样**：抽 10% 受影响 Agent 跑回归；**用差异证明影响**。
- **R5 回滚范围**：变更与回滚绑定；**回滚覆盖同一批资产**。
- **R6 指标**：反依赖覆盖率、影响报告产出率、验证抽样率、回滚完整率。

### 5.2 用户旅程

- **平台工程师**：改共享 prompt → 生成影响报告（20 个 Agent）→ 抽 2 个回归 → 发布 → 记录验证数。
- **SRE**：发布后某 Agent 异常 → 查影响图 → 确认同一 prompt → 回滚整批。
- **安全**：工具升级 → 查消费者 → 通知 → 灰度。
- **审计**：抽查一次变更 → 核对影响报告与验证记录 → 确认可举证。

### 5.3 实现方案（90 天）

- **0–30 天：建图。** 采集 prompt/工具/文档引用；覆盖 top 资产。
- **30–60 天：报告。** 变更前影响报告；抽样验证。
- **60–90 天：回滚。** 变更-回滚绑定；季度图更新；图覆盖率看板。

**第 121 个市场空白（五项）**：反依赖覆盖率、影响报告产出率、验证抽样率、回滚完整率、跨团队通知率——无一内建；`impact.*`／`dependency.*` 为**第 90 次无人提字段族**。本地 173／173-kb 连续第 81 期成组启用：朱革 15「统一权限、审批、回滚」＝全库唯一把「回滚」写进治理闭环的实践，本期首次当主线；配 127 期发布、144 期编队。判词：**本地把回滚写进治理，联网侧 2026 年才承认「行为只有热更新」；两边都没把「这次变更会影响哪些 Agent」做成变更单字段。**
