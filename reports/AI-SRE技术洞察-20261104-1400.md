# AI-SRE 技术洞察 · 第 69 期（2026-11-04 14:00）

## 串扰面（共租面）运维——"你的 P99 是陌生人流量的函数"

> 本期主线（第六十条）：前 68 期都在管"我们的系统"，本期拿掉这个前提——推理时代，执行单元是批次，而批次里坐着看不见的陌生人。与 67 期依赖面分界：那期问"供应商在不在线"，本期问"同一个分片上谁在挤我"；与 33 期配给分界：那期管"我还剩多少口粮"，本期管"别人的口粮怎么改写我的延迟分布"；与 27 期缓存分界：那期把缓存当成本科目，本期把它当跨租户信道；与 49 期对抗面分界：那期管投毒输入，本期管硬件与缓存的旁路泄漏。本期论证：隔离不是配置项而是逐跳不变量，串扰不是容量问题而是记账问题。

### 一、发展趋势

三条本周内可核实的事实，指向同一个尚未被命名的空缺。

第一条，Anthropic 的 Priority Tier 承诺"已不再可购买"，标准档被官方描述为"尽力而为的可用性"；同一份实测里，Sonnet 5.5 低推理档的中位首字延迟为 1.17 秒，P95 却是 10.64 秒——九倍。第二条，OpenAI 的 Fast 模式卖"最高 2.5 倍速度"，但条款写明"流量骤增时可能被降回标准速度"。第三条，火山方舟 11-02 上线的在线推理（低优）档，价格约为常规档 50%，文档里一句"不承诺 TTFT / TPOT / 成功率"，把"被邻居挤掉"直接写成了合同语言。

把三条并排看，趋势不是"隔离变好了"，而是**延迟已经被单独定价，隔离却没有被单独承诺**。速度已独立成 SKU：GPT-6.1 Sol 的 Ultrafast 档单价是标准档 6 倍，Opus 5.5 的 Fast 模式约 2.5 倍速、2 倍价，小米 MiMo 的 UltraSpeed 档以约 3 倍价换 10 倍速。厂商把"更快"做成了商品，于是"更慢"就成了没有 SKU、没有条款、也没有赔付的品质缺陷。

第二个趋势是**隔离的档位化与高档位收缩**。火山把在线推理拆成低优（flex）/ 常规 / 低延迟 / TPM 保障包四档；阿里云百炼把部署拆成 DTU 独占吞吐（物理隔离）、PTU 预置吞吐（逻辑隔离）、按量付费（共享公池）、PAI 灵骏（物理隔离）；而海外两家恰在此时收窄了最高档——一家停售优先档，一家给加速档加了降级条款。隔离从工程属性变成了商务属性，且越往上越难买。

第三个趋势来自合规侧。阿里云安全支柱文档 BP-SEC-05 明确要求"对安全要求高的租户提供独占推理实例（非共享 GPU），避免通过侧信道攻击获取同一物理设备上其他租户的推理信息"。侧信道第一次被写进云厂商的安全基线条目，而不是安全公告。这条要求与性能优化正面相撞：前缀缓存、连续批处理、跨请求 KV 复用，每一项省下来的钱都来自"共享"。

最后是负载结构。增长最快的三类负载——编码智能体、长文档 RAG、多轮语音——恰好都是长上下文、高预填、吞吐贪婪型，也就是最吵的那类邻居。串扰不是稳态问题，它在随负载结构恶化。

### 二、技术现状

**共享发生在三个地方，而且是乘性的。** 第一处是连续批处理：vLLM、TGI 与前沿 API 背后的服务栈都按解码步滚动装箱，你的解码步和陌生人的解码步落在同一次 kernel launch 上——transformer block 内部没有公平份额调度器，只有被装进同一批的其它东西。第二处是 KV 缓存争用：每个在飞请求占用的 KV 与其上下文长度成正比，池满时必须驱逐、抢占或拒绝，长上下文租户不只是在多占内存，它在重塑整条队列。第三处是 GPU 之下的 PCIe 与 HBM 带宽：即便用 MIG 切卡，权重加载、KV 传输、集合通信仍共享主机通道。三者是乘法关系，不是加法关系；一个长上下文、高预填、贪婪生成的邻居会同时触发三项。这解释了两个看似矛盾的数字：公有托管 API 的 p95/p50 比值约 1.8 倍，而共享型 serverless GPU 平台在高峰可达 4–5 倍；仅做 PCIe 感知放置就能把 TTFT p99 改善 10–15%，说明原基线里有一到一成半的尾部延迟纯粹烧在总线争用上。

**KV 缓存事实上已经是一个数据库，但很少有人按数据库的方式运维它。** 驱逐策略从 LRU 走到 LFU、前缀感知（SGLang 基数树天然叶先驱逐，根与内节点受保护）、TTL 分层（Anthropic 的 5 分钟与 1 小时两档）、显式 pin；多租户部分则复刻了 1980 年代 RDBMS 的缓冲池分区问题——硬配额保证隔离但搁浅容量，软配额加水位数驱逐优先保住利用率但要求策略真的尊重优先级，此外还有每租户块预算、VTC 虚拟令牌计数器公平份额、迭代级抢占（重算 vs 换出）。判读一句：**大多数团队在第一次吵邻居事故之前，都不会在这块投入。**

**跨租户隔离的实现谱系已经很清楚，但默认值仍然是不隔离。** 全局共享 → `cache_salt` 命名空间 → 每主体 HMAC 盐（KVGov 用 σ_p = HMAC_K(secret, principal_id) 给块哈希链播种）→ 物理分区。8 月的一篇论文在 A100 + vLLM 0.26 上测到冷/热 TTFT 比 0.22，在 llama.cpp/Metal 上复现为 0.093——这个比值就是信道的信噪比。同一篇论文给出本期最值得记住的结论：识别性信息只存在于提示词分歧的地方，**把盐注入分歧边界而不是链根，可保留约 93% 的前缀缓存收益，且不留跨主体信号**（估算值，基于实测校准的模拟）。

**隔离会随控制流失效。** CVE-2026-105752（GHSA-935w-9g4m-p28p）指出 vLLM 0.30.0 之前，多轮 Responses API 的 Harmony 路径在工具调用续轮时没有传递 `cache_salt`，于是工具执行后的提示词前缀落进了全局无盐缓存。这条 CVE 值得单独记一笔，因为它的失效点不在配置里，在**控制流的分支上**：一次工具调用就足以让隔离失效，而智能体恰恰是工具调用最多的负载。隔离不是配置项，是必须逐跳携带的不变量。

**可观测性这一侧的缺口是字段级的。** vLLM 已经用 `vllm:request_queue_time_seconds` 把排队与预填分开记录；但 OTel 的 GenAI 约定仍停在 Development，只有客户端侧的 `gen_ai.client.inference.time_to_first_chunk`，没有任何字段描述"我和谁同批"。你拿到的遥测能证明自己慢，不能证明慢从哪来。

本地素材可作互证：陶炳哲《智能路由》记录同一权重、同一挂牌价下供应商 P50 吞吐相差 23 倍（OpenRouter，2026-09-06 采样）。这句话换个读法就是本期命题——**你买的不是模型，是某个切片；切片之间的差，比你以为的模型间差异还大。**

判读三条。其一，**海外卖档位与合同，国内卖物理隔离**：前者把问题交给条款，后者把问题转成容量采购，两条路都不解决"共享池里的那一档"。其二，**赔付结构系统性错配**——SLA 赔的是错误，串扰只产生缓慢；Azure 甚至把 429 计为可用，等于把"被限流"从事故里摘了出去。其三，真正的空白是**邻接证据**：没有任何一家 provider 在响应或遥测里告诉你 shard_id、batch 组成、队列深度、预填份额、驱逐原因。这使得"该不该为隔离付钱"永远只能拍脑袋——这是本系列第二十五个市场空白，也是第一个纯粹由"共租"产生的空白。

### 四、技术挑战

**归因不可能。** 自家服务退化时有日志、有 trace、有部署标记可以二分；共享基础设施退化时，本地什么都没有，provider 状态页要么全绿，要么只有一句"聊天补全延迟升高"。这是"昨天还好好的"成为推理运维里最贵一句话的原因——它没有主语。

**退化没有 owner。** 串扰不产生 error，只抬高 p99；不越告警阈值，只越用户耐心。它进不了事故流程（本期之前 45、63、65 期都隐含"有一个事件"），只能进"性能抱怨"流程，而抱怨没有 SLO、没有复盘、没有行动项。第三种状态"绿而慢"（green-and-slow）至今没有对应的运维对象。

**乘性使容量规划失效。** 加法假设下加 30% 算力应降尾部；乘性结构下，新增容量可能只是把更吵的邻居吸引到同一分片。容量模型必须引入"邻接密度"这个变量，而它恰好不可观测。

**隔离与保密是同一个旋钮的两端。** 前缀缓存带来 2–5 倍吞吐，也带来可探测的命中信号；时序归一化（人为加最小 TTFT、注入抖动）能压掉信道，却等于**为了保密而主动变慢**。"故意劣化"是一个全新的运维动作类别：它需要登记、需要预算、需要和性能事故区分开，目前一条都没有。

**重算的账没人记。** 显存压力下引擎可选换出或重算；重算省了 PCIe，却把成本转成被抢占者的算力时间。这些 token 记在谁的账单上？第 58 期建立的成本归因体系里，没有"被邻居挤掉的重算"这一科目。

### 五、展望与建议

1. **邻接证据字段族**：把 `co_tenant_class`、`batch_id`、`queue_depth`、`prefill_share`、`eviction_reason` 作为提案推进 OTel GenAI 约定——先在应用层属性落地，等约定转 Stable 再映射（第 62 期"schema 无法 pin"的变通解法）。
2. **隔离不变量测试进 CI**：以 CVE-2026-105752 为样板，构造"多轮工具续轮后盐是否仍在"的回归用例；凡跨进程、跨网关、跨子智能体的边界都要带一次。身份要逐跳携带，隔离也要。
3. **把 SLO 从绝对值改为比值**：`p99/p50 ≤ 3` 加"队列暴露度"（排队时间占总时延比例），比单看 p99 更能识别串扰，也不受机型换代影响。
4. **故意劣化登记簿**：安全控制清单新增"最小 TTFT 钳制 / 抖动注入"条目，记录开启范围、性能代价、审批人；把这笔开销从"性能回归"里摘出来单列。
5. **串扰注入进第 56 期注入目录**：新增两个故障类——长上下文邻接（同池投放 128K 预填）、跨租户缓存探测（以 TTFT 为 oracle 反推命中），验收判据是"能否在 10 分钟内自证或自证不能"。
6. **采购条款两句话**：尾部延迟条款（p99 相对基线的退化上限）+ 邻接举证义务（事故窗口内 batch 组成可举证）。同时把 flex 类"不承诺成功率"档位限定在可重试链路，不进同步交互路径。
7. **重算 token 归因**：抢占与重算产生的 token 单独记账，作为"共享成本"分摊，与第 58 期账面合流。

一句话收束本期：**共享是设计出来的，隔离是证明出来的。** 当延迟成为可售商品，而隔离只剩"尽力而为"，运维要补的不是更多容量，是那份能证明"慢不是我造成的"的证据。
