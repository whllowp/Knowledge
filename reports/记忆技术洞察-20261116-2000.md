# 记忆技术洞察 · 第 101 期（20261116-2000）

**主题：记忆的「受众分配」——从"共享/隔离"开关到逐条经验的受益∩可披露授权**

> 洞察范围：2026 年（近 30 天为主）。四维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

前 100 期把共享记忆当作"存得对不对"（#99 信道性、#67 投毒）或"用得对不对"（#100 群体兑现），默认可见性是账号/团队级粗粒度 ACL。MixUA（arXiv 2611.10439，11-07）把自进化 agent 的跨用户、跨 agent 经验共享重定义为"每条经验给谁看"：同一条教训对一方是收益、对另一方可能是隐私泄漏，须逐条决定受众。这是价值判据从"对谁有用"（#91 主体间异质性）扩展到"对谁可披露"的一步——共享不再是一个开关，而是二维受众格上的路由。

## 二、技术现状

MixUA 把轨迹蒸馏成带 situation／lesson／scope／provenance 的经验条目，按用户×agent 二维分配到 Pair（同人对同 agent）、User（同人跨 agent）、Agent（同 agent 跨人）、Global（所有人）四档；授权读者严格取受益面 G(e) 与可披露面 D(e) 的交集。写入走 reusable／protected 双流且相互隔离——不依赖 writer 自标隐私，而由来源流约束范围：protected 条目只能进 User／Pair，永不进跨用户可读的 Agent／Global。配套 CrossLearnBench 用 5 用户×7 agent（35 对）、178 任务、7 套基准，注入用户偏好与隐私事实，同时记任务成功率、偏好保留、隐私泄漏三本账。

## 三、技术竞争力

MixUA 较无记忆 +16.3 点、较单一 Global 记忆约 +5 点，偏好保留 90%（Global-only 仅 11%），隐私事实泄漏≤0.02%（约 1.8 万探针中 4 例，store review 后清零）。消融揭示四档不可互替：去掉 Global 使跨用户/跨 agent 迁移增益从 13.0 跌到 4.6（迁移几乎全靠 Global）；去掉 Pair 使工作上下文泄漏从 22% 飙到 95%；去掉 Agent 使 crowd-pass 从 89% 降到 40%、误用从 0% 升到 14%。五项目（OpenViking v0.5.5、Hy-Memory 2.0.16＋MemHub、TencentDB v2.0.3、dsh v26092802、ReMe v0.4.2.2）仅主体级 ACL、零逐条受众分配、零隐私探针量化，倒挂延续。

## 四、技术挑战

①受益面与可披露面须分别判定，且只有打开"用户轴"才需隐私门控（Pair→User 不新增用户，Pair→Agent／User→Global 才需），判定被压缩到一条轴；②单 writer 只见单条轨迹，易把 scope 放太宽或太窄，须周期性 store review 重判并 promote／demote／merge，review 同时改善三项指标；③全局库效用高却毁个性化（偏好保留 11%），完全隔离保隐私却失迁移，四档是中间解；④偏好泄漏（MixUA 0.9–4.8%）与隐私事实泄漏（≤0.02%）是两个不同指标，不可混报。

## 五、需求分析

多用户共用一组 agent 的平台要回答："这条从别人经验里学来的教训，能不能给他看？"用户既想跨人、跨 agent 借力（别人踩过的坑别再踩），又要求自己的偏好、工作代号、隐私事实不被串进别人的记忆。运维需把"可见范围"做成可审计的一等字段，而非藏在账号 ACL 里；合规侧要能证明某条隐私事实从未进入禁区。

## 六、用户旅程

用户 A 用 agent X 完成任务，写下"项目代号 Phoenix、签字日期用 2026-01-01"；splitter 拆流——代号属 protected，只能进 A 的 Pair，通用 bug 修复进 Global。用户 B 用 agent Y 遇到同一 bug，从 Global 读到修复（跨人跨 agent 受益），却看不到 A 的代号与签字偏好。若错放 Global，B 的助手会吐出 A 的代号（泄漏）；若全放 Pair，B 无从借力（失去迁移收益）。受众分配正是这两种失败之间的阀门。

## 七、具体实现方案

写侧先由 splitter 分 reusable／protected 两流、隔离 writer；每条 lesson 附 situation／lesson／scope／provenance，按 G(e)∩D(e) 算授权读者，protected 强制收敛到 User／Pair。检索按 scope 分桶、各桶独立字符预算，situation 文本用 embedding 匹配当前任务。周期 review 重判 scope 并去重（promote／demote／merge）。评测同报任务通过率、偏好保留、隐私事实泄漏率与 scope 消融，并把 scope 决策及来源做成可回放审计字段。

## 八、本期新观点

1. **共享从二值开关升级为二维受众格**：受益面∩可披露面决定逐条可见范围，把 #99 "共享即信道（漏但不可控）"推进为写入期可控路由。
2. **两处"作用域"须分列**：#9 作用域流失管内容适用范围，本期管受众可见范围，同名不同物，混用会让评测看不见受众风险。
3. **收益与隐私可协同而非取舍**：+16.3 点、90% 偏好保留、≤0.02% 泄漏同时成立，反驳"共享越多越不安全"的默认假设（对照 #74 删除不可能三角）。
4. **四作用域不可互替**：去 Global 迁移崩、去 Pair 泄漏飙、去 Agent 误用起，反驳"一个全局库够用"，接 #91 共性底座但上升到受众维度。
5. **AML 应补 audience-allocation 维度**：受益/披露判定覆盖率、隐私事实泄漏率、偏好保留率、scope 消融稳健性，接 #56/#69；五项目零披露，倒挂延续。
