# AI-SRE 技术洞察（2026-11-02 16:00 期 · 第 32 期）

**本期主线：轨迹面运维——当"智能体干过什么"成为一等运维资产（第二十三条主线）**

前 31 期已从治理、根因、演练、组织、记忆、路由、供应链、承诺、时间、缓存、协同、进化、知识供给、接口等二十余个平面审视 AI-SRE。本期换到最底层却最容易被当成"日志"忽视的一层：**轨迹（Trajectory）**。它不是排障的副产品，而是唯一不可伪造的评测集、训练集与审计底座；而轨迹本身的完整性、口径、加工经济学与合规，正在成为运维必须回答的新问题。此前第 22 期讲"智能体记什么"，本期讲"组织如何留存并榨取智能体做过的事"。

## 一、发展趋势

**趋势一：轨迹从"排障线索"升格为"生产资产"。** 本地一手显示该判断已成行业共识：蚂蚁可观测团队（刘杨）明确"有了日志、指标和完整 Trace，仍判断不了 Agent 是否做对了任务"，将实时评估链路直接架在 Trace 上；阿里云（马云雷）把轨迹拆为五类衍生资产——质量验证（Evaluator/Benchmark/回归集）、Agent 优化（Prompt/Skill/SOP）、训练数据（SFT 样本/偏好对/奖励模型）、成本效率（路由/缓存/预算策略）、产品组织洞察（失败分类/能力缺口），并要求"来源可追溯、版本可管理、收益可验证"。W&B 也以同样的逻辑重构 Weave：线上信号捕捉未知失败模式，再抽取为离线评测集，形成"轨迹→评测→回归"飞轮。

**趋势二：判定（judge）正从生成调用中剥离，成为独立的调用类别。** 蚂蚁用 fastText+正则对全量轨迹粗筛、仅留不到 1% 进大模型精判，token 成本下降 99%；并探索置信度路由、三分类概率、规则拆解三条通用路径。OpenAI 在 10 月 22 日将 Decisions API 转 GA——不生成完整回复、只做分类与判定，宣称比经 Responses API 走 GPT-6 Luna 快 10 倍，第三方转述定价 0.10 美元/百万输入 token。"便宜模型先判、不确定再升级"从工程技巧变成了一等 API 品类，判定市场正在与生成市场分离定价。

**趋势三：评测基础设施自身进入生命周期管理。** Langfuse 宣布 v4 断代：trace 级 LLM-as-judge 评估器 11 月 16 日起在云端停止产出结果，必须迁移到 observation 级；OpenAI Evals 平台 10 月 31 日转只读、11 月 30 日关停。轨迹资产的加工层本身也会"腐烂与迁移"，这要求把评测平台当作有版本的运维对象。

## 二、技术现状

**口径已成三级，但各平台并不一致。** 业界普遍形成 Span（单次调用）—Trace（一次交互）—Session（多轮对话）的层级，蚂蚁进一步把 Trajectory 定义为"状态—动作—结果"的 MDP 序列，用奖励函数按状态约束定位首个非法转换，把"失败结果"归因到具体步骤——这是轨迹语义最深的一版。但 Session 边界判定是公认难点：蚂蚁的流水线以 trace_ready/session_sealed 触发增量处理，需综合显式信号、空闲窗口、迟到事件与业务主键，并保留修正与补跑能力；Langfuse 则承认"平台天然不知道会话何时结束"，LLM 评估器无法直接挂在 Session 上，只能挂到承载完整历史的 observation。

**统一语义靠门禁而非自觉。** 蚂蚁基于 OTel GenAI 约定扩展 L1（gen_ai.*）/L2（agentic.*）/L3（业务）三层、9 类 Span，并用**属性前缀白名单门禁**拒绝不合规范前缀的上报，使 100+ 种异构 Agent 的轨迹可横向比较；新 Agent 接入周期从周级降到天级。评估器与埋点解耦用 DSL 表达式实现：换一个 Agent 只改两行取值表达式，评估器不动，埋点不规范也能低成本接入。

**归因进入日志主键。** Google 的 Gemini Enterprise Agent Platform 引入**双重归因日志**：智能体代表用户操作时，审计日志同时记录基于 SPIFFE 的智能体身份与发起人身份，审计员用 is_agentic=true 过滤即可隔离全部智能体事件；OpenAI Agents API 公测同样把 sessions/turns/traces/subagents 作为可检视产物。火山引擎 10 月在全栈可观测平台上线"Agent 轨迹"功能，ArkClaw 企业版提供事件级 token 消耗与缓存命中率明细——国内云厂商已在把轨迹做成控制台一级入口。

**判读：** 三个分歧点值得记录。其一，判定经济学上 OpenAI 把"判定"产品化收租，蚂蚁把"判定流水线"自建内化——前者赢在标准计价，后者赢在可与业务维度同链计算。其二，审计归因上只有 Google 正面回答"这条轨迹是谁以什么身份写下的"；Futurum 直接指出 Anthropic 的托管智能体轨迹"不能单独充当审计记录"——span 里不含思考内容，"做了什么"有、"为什么"没有，缺口必须由建设者补齐。其三，资产化路线上国内强在"轨迹→可复用资产"的工程纵深（版本化 Dataset、回归门禁），海外强在"轨迹→评测"的工具闭环与生态伙伴密度。

## 四、技术挑战

**轨迹完整性是缺失的 SLI。** 迟到、乱序、Session 边界误判、字段不合规范，都会让"完整任务轨迹"悄悄残缺；而 Managed Agents 连思考内容都不落 span——不完整的轨迹进入训练集，等于把幻觉蒸馏回模型。目前没有任何厂商公布轨迹完整性指标。

**人审吞吐与流量规模差四个数量级。** 行业口径人类评审能力约 50-100 条轨迹/小时，线上评估典型只能采样 10-20%；Futurum 调研显示 45% 的企业记录智能体行为、仅 12% 在晋级前评估，四分之三的企业过去一年发生过 AI 参与的生产事故。轨迹在采集端接近全量，在判定端必然欠采样，欠采样的那部分正是资产缺口。

**轨迹自身的合规与成本。** Full content 模式把提示词与回复（含 PII）复制进可观测体系，Anthropic 对 HIPAA 组织强制仅元数据；高频 Agent 单日轨迹可达 GB 级，保留策略、访问控制、加密成为 OpenAI 责任表里明确留给买方的义务。此外评估器自己也要被观测（蚂蚁连"评估器的 trace"都可查看），judge 漂移缺乏行业标准校准方法。

## 五、展望与建议

1. **把轨迹完整性做成 SLI**：建议四指标——Span 到齐率、迟到/乱序率、Session 边界判定准确率、字段规范合规率（以前缀白名单为准），并纳入值班看板。
2. **建立判定预算**：粗筛全量、精判按需；对照 OpenAI Decisions 类定价与自建小模型两条路线做单位成本核算，评估成本纳入智能体总账。
3. **轨迹治理三权分立**：写入权（埋点门禁）、读取权（PII 分级与 full-content 白名单）、保留权（快照冻结与合规退役）分开授予。
4. **让"轨迹→回归集"成为发版门禁**：参照 Dataset Item 的 Candidate→Reviewed→Golden 三态，未经回归的 Prompt/Skill/模型变更不得上线。
5. **给评测基础设施做版本 pin**：Langfuse 断代与 OpenAI Evals 关停证明评估层会迁移，评测器与平台版本应进入第 25 期所述的变更账本。
