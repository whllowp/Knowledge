# AI-SRE 技术洞察 · 第 56 期（2026-11-03 22:00）

## 本期主线：混沌面（扰动面）运维——注入目录是一等运维资产

第 20 期问过"练不练"（演练赤字），第 52 期问过"敢不敢切"（授权），本期回答剩下的半个问题：**注入什么、注在哪一层、注入后用什么判据判、注入器自己算不算一次生产变更**。第 38 期把智能体的写当变更，本期是它的镜像——故障注入器本身就是系统的写入者，注入目录因此成为与 runbook、轨迹同级的一等运维资产。

### 一、发展趋势

10 月下旬两篇顶会论文把"给智能体注入故障"从博客实践抬成学术范式。MCP-Injector（arXiv 2610.32555，10-23 提交，NeurIPS 2026 poster）在 MCP 工具调用路径上做协议感知的注入中间件，故障模型不是拍脑袋定的——它从 1,774 个开源 MCP 仓库的 57,240 条 issue/PR 里挖掘真实事故分布（故障模式 × 持续性）来校准注入谱；AgentChaos（arXiv 2608.06790，ASE 2026）则在 HTTP 层不侵入源码地拦截改写模型返回，65 种配置、五个系统、四个骨干模型全测。两家共同方法论是"注入后核验触发"：故障没真正打中的任务从分母里剔除，避免假实验稀释结论。

行业侧，AWS 把结构化混沌演练与 GameDay 写进 Unified Operations 企业支持合同，混沌从自选动作变成合同条款；腾讯内部"AI Native 混沌工程"实践（8 月公开）反过来让智能体自己跑混沌实验——哨兵 Agent 触发、指挥 Agent 编排、四阶段状态机、三道安全闸门。一句话概括趋势：**评测在测智能，注入在测幸存**，两者开始被承认为两个不同的问题。

### 二、技术现状

本期最有分量的结论是一条"守恒律"：**换模型不换韧性**。AgentChaos 用 Claude Sonnet 4.5、GPT-5.2、DeepSeek-V3.2、Seed-1.8 四个骨干轮换，系统鲁棒性排名几乎不变；MCP-Injector 的标题就是"规模买不来容错"——120B 与 20B 骨干在故障下的韧性比无统计差异（p=0.96），完成率 91.1% 反而低于 20B 的 95.6%。两个独立工作指向同一处：韧性是框架层错误处理的属性，能力基准分数会掩盖运营脆性。

第二个反直觉发现是"静默失败不比崩溃便宜"。AgentChaos 的三族故障里，遗漏族（截断、空内容，HTTP 200 正常返回）在 MAD 系统上造成 38.46% 的 pass@1 下降，与显式报错的 37.5% 相当，远超超时的 22.33%——**绿灯监控下出错才是大头**。opennash 的注入矩阵补了最险的一格：长任务中途凭证过期（第 N 次成功调用后返回 401），智能体对后续写操作全部 no-op 却持续"报告成功"。这是第 45 期沉默面在依赖层的再现：不只是"该来的没来"，还有"来了 200 但没干活"。

第三，经典混沌的两大支柱对智能体失效。其一，幂等重试假设崩塌——LLM 调用失败后重试会生成不同的思维链，重试逻辑本身变成不确定性来源；其二，断路器保护错了对象——传统断路器让调用方停下来，而失去数据源的智能体不会停，它会即兴：幻觉补数、换工具、跳步骤不标记。ReliabilityBench 的数据支持这一点：任务扰动一项就把成功率从 96.9% 压到 88.1%，限流（一个无聊的 429）是单一伤害最大的故障，简单架构（ReAct，恢复率 80.9%）比复杂架构（Reflexion，67.3%）更抗造。稳态定义因此要从"系统保持运行"改写为"系统保持正确"——语义断言（是否承认故障/是否编造填补/是否静默跳步）取代状态码检查。

### 三、技术竞争力

| 方案 | 注入层 | 故障分类 | 触发核验 | 判定方式 | 安全闸门 |
|---|---|---|---|---|---|
| AgentChaos（ASE'26） | HTTP 中间件，免改源码 | crash/omission/value 三族 | 有（未触发任务剔除） | pass@1 下降幅度 | 测试环境隔离 |
| MCP-Injector（NeurIPS'26） | MCP 协议路径 | 永久/瞬时/间歇 × 模式 | 种子化调度可复现 | 韧性比（故障下/无故障分） | 中间件级 |
| ReliabilityBench | 任务扰动+API 故障 | 一致性/鲁棒性/容错性三维 | 无 | 三维指标面 | 无 |
| agentic-chaos（开源） | LLM 层+工作流层 | 超时/静默降级/记忆污染 | 报告含恢复契约检查 | 重试/回退/恢复契约 | 会话级声明 |
| Cordum 治理剧本 | 策略路径（控制面） | 策略点不可达/队列重放/锁竞争 | 稳态假设+abort 守卫 | fail-closed 验证+审计 | 显式中止条件+爆炸半径单租户 |
| 腾讯 Agent 军团实践 | 全流程 Agent 自驱 | 预检→注入→恢复→报告 | 基线对比恢复判定 | 根因分析+自动工单 | 三道闸门（白名单硬规则不可被 LLM 绕过/双签/基线判定） |
| AWS Unified Operations | 基础设施+工作负载 | 结构化演练目录 | 专家带队 | GameDay 复盘 | 合同化服务边界 |

判读有三条。其一，注入层位置成为流派分野：HTTP 中间件最快接入但看不见工具内部；协议感知（MCP-Injector）精度最高但绑定协议版本；平台内建（Gravity/AWS）最省事但把弹性逻辑锁进供应商。其二，故障目录的校准数据源是稀缺资产——用 1,774 个仓库的事故分布反推注入谱，本质是"注入目录=生态事故的镜像"，这比任何自拟清单都硬。其三，**注入目录覆盖率与演练通过率没有任何一家做成常驻 SLI**——这是继前十三期之后的第十四个市场空白，且它是唯一"演练本身也需要被演练"的空白。

### 四、技术挑战

1. **注入目录腐烂**：MCP 生态月月在变，57,240 条 issue 校准出的分布会过期——30 期知识债在注入层复现，目录需要版本化与退役机制。
2. **provenance 缺口**：污染上下文演练几乎总能暴露同一件事——污染源删得掉，但"过去 4,000 条响应里哪些被它影响过"没人答得上来（47 期断言账本的演练侧验证）。
3. **判据自指**：故障下判定"回答对不对"依赖 LLM-as-judge，而 judge 自己在故障下的表现无人验证——46 期尺子问题在混沌层镜像。
4. **重试风暴**：多个智能体同时按指数退避重试，聚合起来把下游压垮十倍负载——38 期写入面的乘法效应。
5. **生产注入的授权链**：腾讯"环境白名单硬规则不受 LLM 判断绕过"是正确方向，但注入即写入，按 38 期双证制（幂等键+回滚键）与 42 期自治等级，探索性注入的准入仍是裸奔。

### 五、展望与建议

三条最小落地路径：**模型降级演练**（中途静默切备模，可怕的不是质量下降，而是仪表盘毫无变化）；**污染传播演练**（测检测时延、触达范围、清除时延三指标）；**策略路径故障演练**（safety kernel 不可达 5 分钟，验证 fail-closed 而非 fail-open——Cordum 已证明这类实验可以 YAML 化）。中期建议：把"每类注入配可接受/不可接受行为双清单"写进 CI；韧性分数进采购合同，要求框架层注入成绩而非仅能力基准；OTel 方向可提 fault_injection.* span 家族（注入 ID、触发核验、abort 原因），让第 32 期轨迹面与本期混沌面在同一张遥测里合流。混沌工程不会让智能体更聪明，但它让一个不够聪明的智能体在最坏时刻不至于把业务拖下水。
