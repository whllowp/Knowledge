# AI-SRE 技术洞察（2026-11-03 01:00 期 · 第 39 期）

**本期主线：复现面（回放可证性）运维——"断网重放"是轨迹的验收标准**

往期已埋下多枚回放碎片：第 32 期提出"轨迹→回归集"发版门禁，第 34 期借刘凯宁提出"回放投产门禁"，第 37 期留下"恢复点分裂"三时间戳。本期把它们收敛为一条第一性判据：**一段轨迹是否可用，取决于它能否在阻断出口的前提下重演故障**——需要联网才能"复现"的回放不是回放，是一次重新掷骰子的运行。这是第三十条主线，管的是证据的可复用性证明，而非证据的留存（32 期）或进程的恢复（37 期）。

## 一、发展趋势

**回放从"评测偏好"变成"工程门禁"。** 10 月 30 日 Dekita 在 DEV Community 点破行业默认假设的裂缝：多数 harness 的回放模式是**自我报告的承诺**——缓存键命中则用录制响应，未命中则静默落回真实函数与网络；回放跑完、输出合理，你却无法分辨刚才是在放录像还是在新世界重跑。而 OS 层阻断出口（`unshare -rn` 一条命令）是从进程外部执行的**测量**。"当承诺与测量不一致时，相信测量。"

同周之内四个独立方向合流：Kruglov 在工具边界加 record/replay 装饰器并默认严格模式；apprs 主张比较两条 trace 前先对齐环境清单；codehub 把会话打包成可重执行的"回放包"；abd_alrahmanqaroot 用 **10,851 条历史 shell 命令**回放重写后的守卫规则，恰好拦截应拦的 **15 条**、零多余拦截——这正是第 32 期"轨迹→回归集"的量化实例。

载体侧同步演进：10 月 14 日 Anthropic 将 Claude Platform 的 OTel trace 导出送入公测（覆盖 Managed Agents、Messages API、SDK），但 Managed Agents 路径**不包含模型推理内容**，且文档明示 GA 前 span 名与属性可能变更——trace 是读证据的地方，不是存证据的地方。开源侧 AiSOC（6,106 星）把"决策账本"做成可回放的合规证据：每步 prompt、工具调用、状态迁移、人工审批时间戳全部入账，六个月后仍能回答"当时为什么封这个 IP"。

## 二、技术现状

**四种回放载体并存且互不替代**：进程快照（Google ACE、腾讯 Agent Runtime，恢复的是机器）、事件日志（Anthropic "session = durable event log"，恢复的是会话）、span/trace（OTel，恢复的是观察）、决策账本（AiSOC，恢复的是问责）。工程界默认用快照做容灾、账本做审计、trace 做排障——最接近回放所需的事件日志反而少有人专管。

**回放五字段**（Dekita）：① 原始响应体——parser 处理之前的字节，大量工具 bug 恰在 parser；② 调用时刻的工具 schema 哈希——回放参数对当前 schema 校验失败是真实发现而非噪音；③ 实际应答的模型标识——从响应元数据读取而非配置，**配置是愿望，元数据才是记录**；④ 注入式固定时钟——读时钟的工具与按窗口计数的限流器在回放日行为必然不同，否则对比是表演；⑤ 失败签名——步骤索引、工具名、错误类、退出码的哈希。字段①③最常被省略，而它们恰好决定回放是不是回放。

阻断运行有**三种结局，不可合并为通过/失败**：同一故障复现=轨迹对该 bug 充分（但只证明证据完整，不证明推理正确）；无故障或异故障=轨迹不完整（常见原因：工具响应仅部分持久化、时钟读取、未包装路径上的取数）；harness 拒绝启动=最健康——严格模式下未录制调用是硬错误而非静默活取。本地印证高度一致：刘凯宁（蚂蚁）"写出 Skill 离稳定投产还有多远——真实案例与回放检验，『能跑』≠『可信』"；马云雷（阿里云）"完整 Trajectory+稳定 Harness+多次复现；离线通过≠长期稳定（工具契约/环境快照/漂移监控）"。

## 三、技术竞争力

| 方案 | 回放载体 | 隔离手段 | 时钟 | 模型身份记录 | 断网可复现 |
|---|---|---|---|---|---|
| Anthropic（event log + OTel 公测） | 事件日志+span | 无内建 | 未提供 | 响应元数据 | 部分（不含推理内容，属性预 GA 可变） |
| OpenAI（Responses/Agents SDK tracing） | trace | 无内建 | 未提供 | 依赖后端 | 弱 |
| Google ACE（37 期） | microVM 快照 | 硬件级（进程） | 无 | 无 | 恢复≠回放 |
| 腾讯 Agent Runtime（37 期） | 沙箱快照/克隆 | 沙箱级（进程） | 无 | 无 | 恢复≠回放 |
| AiSOC（开源） | 决策账本 | 自托管 | 每步时间戳 | 每步记录 | 审计级（不可重算） |
| Kruglov 严格模式 + unshare | harness+OS | OS 级出口阻断 | 需注入 | 需自记 | 可达（当前唯一完整路径） |

**判读**：进程级恢复与证据级回放被普遍混为一谈——ACE 能把机器拉回 t₁，却不能重演模型当时"想了什么"；OTel 全家桶给了观察的统一格式，却没人保证被观察的字节还在。**无一家厂商把"断网重放通过率"做成内建指标**，这是继第 38 期幂等并发防护之后的第二个市场空白。

## 四、技术挑战

**1. 确定性合取律。** 严格可复现率是执行轨迹各轴的合取，最不受约束的轴决定总分。Dhage（2026）实测：第一版确定性 harness 在四个模型×任务格中反而有两格更差（legal_clause 复现率 0.79→0.68，p=0.038）——因为自由文本的 plan 成为唯一自由变量；为 plan 补上 schema（JSON 数组逐态校验）后四格全部达到 0.98–1.00，且 token 成本**反降 14.8%–16.7%**。这修正了第 34 期"确定性=成本"的直觉：补齐最后一轴，确定性不仅免费还省钱。

**2. schema 全覆盖的反噬。** Li 等（2026）复现了开源模型在 JSON Schema 约束下"保持高合规却停止调用工具"——schema 被编译为语法掩码后工具调用 token 在解码期不可达；弱模型在标准 token 预算下掉 36.2pp。Fan（2026）的"先思考后格式化"是反向排序的补救。

**3. 复现≠正确。** 被忠实回放的错误答案仍是错误；回放充分性只回答"证据够不够"，不回答"当初做得对不对"——后者仍需第 35 期判据面与行为 SLO（Grafana 10 月：pass^k 衡量生产可靠性的"始终成功"，优于 pass@k 的"至少成功一次"；系统可以在线但越来越不可信）。

**4. 回放语料即高危资产。** 原始响应体是生产数据的完整拷贝，PII 与凭据问题（36 期污染债）在回放语料上重现且更严重；有意截断必须显式记录截断行为，否则又是一次静默损失。录制完备性与数据最小化天然对冲，需要分级录制策略。

**5. 检查手段自身的盲区。** HTTP client 包装挡不住子进程、原生扩展与自开 socket 的工具二进制；namespace 方案下 loopback 接口若被拉起，本地 daemon 会静默应答造成假回放；真实时钟的退避 sleep 会让 CI 空等分钟级延迟。wrapper 日志干净是较弱证据而非证明。

## 五、展望与建议

- **复现充分性 SLI**：以"断网重放通过率"为核心指标，按失败签名对三态结局分别统计，并入第 32 期轨迹完整性四指标；每季度用当日轨迹抽样回放，作为证据管道自身的健康检查。
- **承诺与测量分离**：harness 自报的 replay mode 只作参考；CI 中以 namespace 级出口阻断为验收。通过的阻断回放直接登记为免费回归测试——任何给 agent 路径新增出站依赖的改动都会提前失败。
- **五字段录制清单进 harness 评审**：字段①③设为红线；模型标识一律取响应元数据，语义版本与 digest 分层 pin 衔接第 37 期版本六维。
- **"轨迹→门禁回归集"标准化**：把 10,851 条历史命令回放守卫的做法模板化——变更守卫、判据（35 期）或 schema（31 期接口面）时，先对全量历史轨迹回放，报告应拦/误拦/漏拦三数。
- **载体分工声明**：组织层面明确快照管恢复、事件日志管回放、trace 管观察、账本管问责，并在回放语料的保留期限与 PII 分级上与合规共建——回放语料按生产数据同等对待。
