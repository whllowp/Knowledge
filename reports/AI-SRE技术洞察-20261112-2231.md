**生成时间**：2026-11-12 22:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：凭据面／密钥生命周期（Secrets）——轮换救不了信任策略；密钥换了，后门还在

---

## 题眼

11-12 Help Net Security 报道的 **wfx-loot** 把「轮换即修复」这句话打穿了：攻击者用 **4,837 个被盗 GitHub 账号**，在 **61,764 个仓库**开探测 PR；其中 **10,431 个 PR 进了账号并不拥有的仓库**——因为协作/组织权限，**一个被盗 token 就能暴露它的主人能写的所有项目**。**超过 1,800 个仓库真的执行了恶意脚本**，把 GitHub Actions secrets、云与 SSH 凭据、shell 历史，以及 **OpenAI／Anthropic／Cursor／Copilot 的 token** 发去攻击者服务器。最狠的是持久化：它**改写 AWS 角色的信任策略为「接受任意账号」、给 Azure 应用加联邦身份凭据**——**这两样在密钥轮换之后仍然有效**；它还**伪造通过的状态检查**绕过分支保护，**一分钟内 revert、删掉 workflow run 与日志**，常常只留下运行历史里一个跳号。**密钥轮换只能让旧钥匙失效，不能把攻击者装的那扇门拆掉。** **更麻烦的是：这扇门写在云账号的信任策略里，不在你的密钥清单里。**

## 一、发展趋势

**趋势一：CI 成为新的边界。** workflow 里握着云账号与包仓库的钥匙；**Agent 的 token 也在同一批 secrets 里**（OpenAI/Anthropic/Cursor/Copilot）。**谁能在 PR 里改 workflow，谁就能借 CI 的手拿云权限。**

**趋势二：持久化从「密钥」转向「信任关系」。** 信任策略、联邦凭据、OIDC subject 都可以绕过密钥轮换；**轮换是清理的一部分，不是清理本身**。

**趋势三：检测从「找文件」转向「找痕迹」。** 攻击者删日志、删 run，**只剩分支名、PR 标题、commit message、跳号**；**「没找到证据」不等于没发生**。

## 二、技术现状：四层凭据，四层风险

**长期密钥：最常见。** 154 期说 **19% 的 Agent 用永不过期、写在配置里的 key**；**这类 key 一旦泄露，轮换前一直是活的**。

**CI secrets：最值钱。** workflow 能拿云角色；**一个 PR 就能触发**（pull_request_target 类配置尤其危险）。

**Agent 工具 token：最容易被忽略。** 模型 API key 能直接换成调用与数据；**泄露后账单与数据一起走**（143 期）。

**信任关系：最持久。** AWS trust policy、Azure federated credential、OIDC 条件；**它们不随密钥轮换失效**。

**凭据有三种寿命，管控方式完全不同。** 长期 key（靠轮换与到期）、短时 token（靠签发与 scope）、联邦信任（靠条件与撤销）；**只做第一种，等于只关了前门**。

## 四、技术挑战

**一，轮换清单不全。** 密钥在配置、CI、第三方平台、shell 历史；**漏一个就等于没换**。

**二，持久化不在密钥清单里。** 信任策略、联邦凭据、OIDC subject；**没人列，就没人删**。

**三，一个 token 的爆炸半径。** 10,431 个非自有仓库；**组织权限让「最小权限」变成一句口号**。

**四，日志被删。** 一分钟内 revert＋删 run；**只剩跳号，检测窗口极短**。

**五，包发布带毒。** Packagist/Go 包被推毒；**下游安装即中招**（110 期供应链）。

**六，Agent token 无人管。** 模型 API key 不在传统 PAM 里；**账单与数据双风险**。

**七，OIDC 条件也能被放宽。** 把 subject 改成通配、把 audience 放松；**轮换不会碰它，扫描也常漏**。

**八，轮换窗口本身是风险。** 轮换期间新旧并存；**旧 key 未失效的那几分钟，就是攻击窗口**。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `cred.*` 字段**：`cred_id`、`type`（key/token/federated）、`owner`、`issued_at`、`expires_at`、`scope`、`last_used`、`rotated_at`。
- **R2 短时凭据**：CI 用 OIDC 换短时角色；Agent 用按任务签发的 token；**长期 key 例外要审批**。
- **R3 轮换清单**：配置、CI、第三方、shell 历史、Agent 工具；**清单驱动，不靠记忆**。
- **R4 持久化清扫**：轮换后必须查信任策略/联邦凭据/OIDC 条件；**清扫未完不算修复**。
- **R5 检测剧本**：分支名、PR 标题、commit message、跳号；**缺失痕迹不作为清白证据**。
- **R6 指标**：长期 key 占比、轮换覆盖率、清扫完成率、爆炸半径（可写仓库数）。
- **R7 轮换演练**：季度模拟一次 token 泄露，按清单走完轮换＋清扫＋验证。

### 5.2 用户旅程

- **安全**：发现 wfx 痕迹 → 隔离账号 → 轮换 → **跑持久化清扫** → 确认信任策略已复原 → 查包发布链。
- **平台工程师**：CI 改 OIDC 短时角色 → 删长期 key → 记录例外。
- **SRE**：Agent token 泄露 → 吊销 → 查账单异常 → 换按任务 token。
- **审计**：抽查 20 个凭据 → 核对到期、轮换、清扫 → 确认没有「换了但没清」。

### 5.3 实现方案（90 天）

- **0–30 天：盘凭据。** 列长期 key、CI secrets、Agent token；标爆炸半径。
- **30–60 天：短时化。** CI OIDC、按任务 token；长期 key 加到期与审批。
- **60–90 天：清扫。** 轮换后持久化清扫；检测剧本；季度演练；轮换窗口缩短。

**第 111 个市场空白（五项）**：长期 key 占比、轮换覆盖率、持久化清扫完成率、爆炸半径可报率、痕迹检测覆盖率——无一内建；`cred.*`／`secret.*` 为**第 80 次无人提字段族**。本地 173／173-kb 连续第 71 期成组启用：朱革 15「统一权限、审批、回滚」＝全库唯一把「权限与回滚」写成治理闭环的实践，本期首次当主线；配 154 期退役、140 期代理注入。判词：**本地把权限回滚写进治理，联网侧 2026 年才证明「轮换救不了信任策略」；两边都没把「轮换后持久化是否清干净」做成验收项。**
