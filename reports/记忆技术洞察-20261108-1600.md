# 记忆技术洞察 · 第 34 期

> 覆盖维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战｜范围：2026 年（重点 2026-10-09 至 11-08）
> 生成时间：2026-11-08 16:00（UTC+8）

## 一、发展趋势

过去一年，"记忆写入"被讨论成两个问题：抽取什么、怎么去重。两者都发生在用户说话的那一轮。2026 年下半年真正的结构变化在另一条路上——**调度器成为第二个写者**。

四个产品证据指向同一方向：Letta 以 `enable_sleeptime` 起一个后台 agent，默认每 5 轮重写共享记忆块，并建议用便宜的 Haiku 承担；ReMe 在 `reme start` 后默认每天 23:00 跑 `dream_cron`，把日笔记提炼成 digest；OpenViking 在 `session.commit()` 后异步抽取，接口 0.2—0.3 秒返回而抽取仍在后台排队；Hy-Memory 的 ultra 档以 `evolve()` 显式触发图式归纳与跨域清扫。学界同步：Auto-Dreamer（NeurIPS 2026）把"快速在线获取"与"慢速跨会话巩固"解耦，巩固器把一片记忆区当只读证据、读取 provenance 后**整片 supersede**；LightMem（ACL 2026）严格分离在线检索与离线巩固，每 10—15 轮批量更新。

判读：第 1 期"写入侧独立化"只覆盖了一半。**真正独立出去的不是"写什么"的模型，而是"什么时候整理"的调度器**。整理从"说完之后的一次抽取"变成可按小时、按天、按阈值触发的批处理作业；而批处理意味着它不再有请求。

## 二、技术现状

### 2.1 双写入口：一个有请求，一个没有

在线写的上下文是完整的：谁在说、为了什么、属于哪个会话、有什么权限。离线写没有这些，它只知道"该整理了"。这不是疏忽，是批处理的定义——把 N 个会话的碎片合成 1 条结论，恰恰要求抹掉"这是哪次对话要的"。

结果是审计三问全部答不上：这条记忆为什么存在（触发事件）、谁要求的（主体）、能不能删（权限继承）。第 3 期把"可归因"定为 C 级空白，第 29 期把"对外对账"定为全空；本期补一个更基础的缺口——**离线产物连"写入时刻"都不唯一**：它是一次运行的产物，不是一个事件的产物。

### 2.2 巩固的四道判断，每一道都不可逆

社区讨论已把巩固拆成四问：合并什么、泛化什么、丢弃什么、重构什么。要害在第一与第二道的耦合——**合并是损失性的，且比遗忘更难撤销**：证明"这两条不同"的证据就在两条的差异里，合完差异没了。Auto-Dreamer 更彻底，直接把整个 region 替换成新的紧凑集合（ScienceWorld +7 分、活跃库小 12 倍）；效果更好，审计上则是**一次运行产生一批版本跃迁**。

墓碑（第 2 期的 valid_from / valid_until / superseded_by）在这里失效：它能记"哪条被谁替代"，记不了"两条的差异去哪了"。**差异不可恢复性**，是巩固特有的债，也是第 23 期"更新即重构"的另一半证据。

行业里唯一成文的离线约束来自 LightMem 的提示层：离线模型被明令禁止存整段对话、禁止跨用户抽象。这两条禁令恰好把上面四道判断里最危险的两道直接砍掉；换言之，有人已经把"离线可以做什么"写成了负面清单，但它只存在于一篇论文的附录里，不在任何产品文档中。

### 2.3 睡眠期复活：唯一能重建已删内容的路径

离线加工的输入是原始 episode，输出是新的摘要节点，与墓碑基本不相交：删除标记打在旧节点上，新摘要是另一个节点。三个实证形状一致——Zep 在 11 月 3 日的 changelog 修过一个正是此形的缺陷：摘要把已删除的违规文本又复制回来；一份删除工程复盘更完整：用户注销三周后，另一个客户在客服回答里听到"上个月某公司某位客户也遇到过同样的套餐冲突"，来源是当初 agent 给自己写的"相似案例"摘要，一个挂在任何删除例程之外的派生件，同案另有四处未清理副本（旧 run 的 compaction summary、语义缓存、两季前挖出的评测集、此后的每次夜间备份）；工程侧亦有记录：删除标记被后续写入覆盖、旧记忆复活，根因是"删除不单调"。

结论一致：**删除不是一次操作，是一次图遍历**。而在有离线加工的架构里，遍历必须每夜重跑，否则新派生件会把旧事实重新长出来。

### 2.4 睡眠期还是缓存杀手

Letta 的离线 agent 直接重写共享记忆块，而记忆块就在 system prompt 里。每 5 轮一次重排，等于每 5 轮把 prompt 前缀改一次——第 14 期"注入一次排序、缓存全盘作废"在这里变成周期性事件。这也给 2.5 节的模型选择提供了第二个解释：离线用便宜模型，不只是因为"记忆工作不需要贵模型"，更因为**在线侧要为每次重排重付一遍前缀缓存**。频率旋钮同时拧着三样东西：新鲜度、离线账单、在线缓存命中率。厂商只公布第一项。

### 2.5 离线该用什么模型，业内方向相反

Letta 明确建议离线用便宜模型；LightMem 反过来——在线只跑小模型保 83ms 检索、581ms 端到端，把大上下文 LLM 全部放到离线；Language Models Need Sleep 最彻底，把算力从答案路径挪到驱逐边界（GSM-Infinite 上 Ouro 1.4B 0.419→0.615）。三种选择不是精度差，是**目标函数差**：省钱、提质、保时延。行业尚未定义离线加工的验收指标，所以同一动作有三种最优解。而目标函数一旦缺席，频率就会失控——社区经验里"别过度巩固，否则丢粒度"已是被反复踩到的边界，但它是建议，不是阈值。

### 2.6 副作用：离线路径没有 golden

Zep 的社区检测用标签传播做增量扩展，论文自己写明"动态更新会使社区逐渐偏离全量运行结果，因此仍需周期性全量刷新"。这是本期最重要的工程自白：**增量结果与全量结果不是同一个函数**。加上 LLM 非确定性，同一个库跑两次夜班，产物不同。第 23 期说更新没有回归测试，本期是加强版：离线路径连"期望输出"都无法固定，canary 行为 diff 失去基准。可用的替代目前只有 OpenViking——每次 commit 在归档目录写 `memory_diff.json`，把"改了什么"本身作为一等产物。

## 三、技术竞争力

| 方案 | 离线触发 | 频率 | 离线模型 | 产物可 diff | 删除重放 |
|---|---|---|---|---|---|
| Letta | `enable_sleeptime` | 默认每 5 轮 | 建议 Haiku 档 | MemFS git 版本化 | 无 |
| Zep / Graphiti | 社区刷新 | 周期全量纠偏 | 未披露 | 边级双时间戳 | 无 |
| Mem0 | 无独立离线相 | — | — | 无（ADD-only） | 无 |
| OpenViking | commit 后异步 | 每次提交 | 未披露 | `memory_diff.json` | 仅可查 |
| ReMe | `dream_cron` | 每日 23:00 | 未披露 | daily→digest 文件 | 无 |
| Hy-Memory | `evolve()` | 手动 | 30B-A3B（ultra） | 版本链留撤回版 | 无 |
| TencentDB-Agent-Memory | 分层蒸馏 | 未披露 | 未披露 | 层级可下钻 | 无 |
| dsh-memory-evolve | 回合自审＋后台进化 | 每回合 | 宿主模型 | 五轨文件 | 无 |
| LightMem（论文） | 批量巩固 | 10—15 轮 | 大模型 | 无 | 无 |
| Auto-Dreamer（论文） | 区域触发 | 训练式策略 | GRPO 巩固器 | 替换集 | 无 |

三条判读：

1. 有明确离线调度的四家（Letta / ReMe / OpenViking / Hy-Memory ultra）全部是应用层自管，**无一家把离线写标注为独立写入口**——`write_origin` 这类字段全行业为零。
2. 删除在离线路径重放：只有 OpenViking 的 diff 日志可供人工追查，无一家自动重放。这是第 2 期"删除可举证"空位在离线维度的二次暴露。
3. 唯一把巩固做成可训练组件的是论文，产品侧仍是 prompt 加 cron——**倒挂第二十五次**。
4. 计费单位错配：记忆按条·小时计价（如 TencentDB 的 0.02 元/万条/小时），巩固按 run 计价。一次夜班可能重写上万条，算力账单不在存储账单里，采购方看到的是"每万条每小时"，付出的是"每晚若干次大模型调用"。

## 四、技术挑战

- **在线读到离线改的形状**：写者从未见过重构后的库，provenance 指向的源可能已被合并掉。
- **删除传播**：派生件无主键，第 3 期的字段级身份证在离线产物上没有落点。
- **不可复现**：无法做 golden 回归，事故后也无法重放那次夜班。
- **成本外溢**：每次 sleeptime 都是真实调用且用户看不见；频率换新鲜度，账单在别处。
- **身份与越权**：夜间任务以系统身份运行却代表所有用户，权限继承没有语义。
- **巩固债务**：Letta 社区已把"projects 块需要重构"写进 metacognition 块——债务可见，但没有到期日。

## 五、展望与建议

1. 离线写提升为一等公民：schema 增 `write_origin: online|offline`、`consolidation_run_id`、`supersedes[]`。
2. 巩固审批单四要素（源清单 / 新建文本 / 退役记录 / 变更理由）从"给人看的 GUI"下沉为"给机器读的 run manifest"。
3. 删除在离线路径重放：巩固前先取墓碑集合，命中即拒绝生成，而不是生成后再过滤。
4. 睡眠窗口预算：每次 run 定额（token / 条数 / 替换比），越阈值降级为"只报告不改"。
5. 评测补齐：AML 三期若加"离线重跑一致性"（同库两次 run 的产物差异率），本期最大空位会立刻变成可比较项。AML 二期 11 月 4 日已截止评测、官方口径 11 月中旬出榜，截至本期仍未发布；一期文本榜首 MemoraX 58.02、代码榜 62.00% 仍是唯一可引基线。
