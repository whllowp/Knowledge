# AI-SRE 技术洞察（第 293 期）

**生成时间：2026-11-20 03:00｜主题立面：语义回归面／"跑通了，但做错了"（Semantic Regression / Success-Shaped Failure）**

> **题眼**：过去我们问"Agent 有没有异常地失败"，本期问一个更少被问的问题——**Agent 规规矩矩跑通、返回格式完美的成功响应，却悄悄忘了用户的饮食禁忌、跳过了必需的座位检查，这算不算故障？** 传统 APM 监测的是"破损"（timeout、异常、500），对这种"无异常的语义错误"结构性失明。Google 于 11 月 13 日开源的 AQuA 给出的答案不只是"装个行为传感器"，而是一句可推广到整个 SREAgent 领域的判词：**洞察是它的引用，不是模型自报的置信度分数（An insight is its citations, not a self-reported confidence score）**。它把"语义正确性"从主观判断，拉回到可追溯到部署快照具体代码行的工程举证。

本期与既有立面划界：静默面（#285）问"系统安静是不是真没事"、证据通道面（#290）问"证据有没有送到决策者"、干预信用面（#292）问"动作与好转是不是因果"——三者都在系统/动作层；本期只在**结果语义层**发问：产出的"成功"是否真符合领域意图，凭什么证明，由谁判定。经查重，"语义回归／成功外观／引用可追溯／聚类验证／AQuA／肖汉松"两处索引均为 0，全新立面确认。

## 一、发展趋势

**其一，可观测性的对象从"系统是否 broke"扩展到"Agent 是否做到位"。** Google 11-13 同日放出两件事：把 Agent trace 接进 BigQuery/Looker，以及开源 AQuA（Ambient Quality Agent）。前者解决"看得见做了什么"，后者专解"看见做得对不对"。AQuA 以 sidecar 运行在请求路径之外，从 Cloud Trace / Cloud Logging / BigQuery 读遥测，每次采样至多 1000 个会话，按"取样—审阅—聚类—用完整 transcript 复核—持续跟踪"五阶段处理，目标被明确定义为**静默质量回归**：Agent 忽略用户偏好或跳过强制工具调用，却仍返回看似成功的响应——管道从头跑到尾无异常，延迟、错误率一律正常。这与 Google 对 10-20 伦敦区故障的复盘对照鲜明：那次是控制器误把双双失电的供电判为"健康"、备用发电机从未收到启动信号。一个是机器把"失电"读成"健康"，一个是 Agent 把"没做到"交付成"做到了"，本质都是**健康判据与被判对象脱钩**。

**其二，评测从"答对没有"转向"证据闭合了没有"。** 三份基准在 11 月给出一致信号：SWEOps-Bench（arXiv 2611.06099，11-04）在 16 个 Kubernetes operator 的 55 个历史故障上测得，故障检出率 72.7%–90.9%，端到端恢复却只有 14.5%–52.7%，且"报告的根因"与"最终恢复"仅部分重合——存在 RCA 错误却恢复、症状清除却过不了功能验证两类错位。Cloud-OpsBench（arXiv 2603.00468）更直接：GPT-5 联合根因准确率达 0.78，却有 33.1% 案例"找对根因但未达成证据闭合"。Grafana o11y-bench 1.1（10-28）把校验从"答案像不像"改为"引用的 trace 读得回来吗、数字与事实相符吗、dashboard 改动真的落库吗"。评测重心正从结论正确性迁移到**结论与证据间的可追溯性**——这正是本期立面的技术底座。

**其三，"成功"的判定单位从代码改没改，转成行为消没消。** AQuA 把 finding 标为 NEW / RECURRING / RESOLVED，其中 RESOLVED 是"14 天无复现后自动置位"，与是否提交修复无关：不再问"补丁合进去了吗"，而问"那个行为模式还在不在"。它与 Anthropic Claude Tag 11-12 同频——后者用语义层统一"注册数"定义，把指标下跌（周二 -12%、集中于单一区域）与当日同区域 9–11 点的支付服务事故按时间窗关联，并强调"保留查了哪些数据、还缺哪些证据"供人续查。

## 二、技术现状

语义回归检测目前落到四个可采购能力，但彼此尚未打通。

**行为聚类与复核。** AQuA 参考测试中，32 个多 Agent 旅行会话产出 42 条 finding，聚成 9 个候选簇，verifier 每簇回查至多 3 份完整 transcript，驳回 3 个支撑不足的簇，留下 6 个确认问题——两个是复现型：跳过座位可用性检查、跨 Agent 交接丢失饮食偏好。开发者改 prompt 后重放，座位绕过从 15 降到 2、饮食遗漏从 7 降到 0、全部检查通过的会话从 5 升到 13。**关键不是数字而是方法**：单条 finding 是噪声，聚类后经完整 transcript 复核才是缺陷；Google 明确其结论来自"受控重放而非真实生产流量"。

**引用锚定到部署快照。** AQuA 做根因时比对的是**出错当时拍下的不可变代码快照**，诊断 Agent 必须引用有效文件与行号，原因若在数据或外部依赖也要指明。这直指一个普遍错误：拿"现在的代码"解释"过去那次错误"，代码已改写，解释必然自洽而失真。它与记忆失活面共享"部署即时间锚"的直觉但方向相反：失活面用部署宣告教训作废，本期用快照复原出错现场。

**专用模型与证据前置。** Datadog 11-01 预览 Scout——用强化学习在仿真事故后训练的 ops 专用模型，自述以 3–8 倍低成本对标前沿模型，目前只提建议、不动手。theCUBE Research 更值得记：19 位已把 Agent 用于生产的负责人中，无人允许其无人值守执行高风险动作；25 家里只有 4 家测过"Agent 出事故"。语义保障仍停在"人工兜底＋专用模型"阶段。

**责任与身份边界。** 一份 AI SRE 评测指南强调：Agent 须有独立于操作员的身份，否则它执行的命令在日志里与人敲的无法区分；每条假设要挂证据链接，查询、动作、结论都要进可观测后端。OpenAI Control Room（11-09）给出另一条边界——急刹车做在推理层，35 秒是"收到停止指令到无法再产出 token"的上限，但不承诺撤销已发出的工具调用或已写文件；DNS 事故里监测 15 分钟触发、人 3 分钟后查看，却拖到 2.5 小时才真正停掉。**从"看见做错了"到"能证明做错了、且收住后果"，中间隔着身份、证据与执行三层。**

**读表结论**：把"行为质量诊断"做成卖点的只有 AQuA 一家；把"洞察＝引用、根因锚定出错时版本、以行为消失判修复"做成可导出字段的，**没有第二家**。多数平台停在"看得见调用链"，评测停在"判对一件事"，而"这次成功是不是真的成功、凭哪行代码哪条 trace、改完行为还在不在"三列大面积空白。新观点由此浮现：**看得见执行 ≠ 看得见正确，前者是遥测问题，后者是举证问题**——把两者混为一谈，正是"自愈率很高、同类 Badcase 却反复出现"的常见根因。

## 四、技术挑战

**挑战一：自报置信度不构成证据。** 模型会用流利英语解释它为什么"没问题"，confidence 是可被提示词操纵的自述。AQuA 把 finding 绑定到 trace 与部署快照行号，让"高置信但无引用"不计入。代价是回查 transcript、维护不可变快照、把自然语言结论映射到代码行的持续开销。

**挑战二：语义标准无法用 pass/fail 穷举。** "素食偏好""跳过座位检查"是领域目标，AQuA 用 `goal.md` 让人写自定义标准并加确定性指标。但难题转移给了人：谁保证 goal.md 覆盖了所有该守的约束？没写进标准的语义错误，AQuA 同样看不见——这与信通院"结果可评价"要求直接相关。

**挑战三：复现与真实状态的鸿沟。** Google 自列两条局限：采样 1000 会话会漏掉罕见失败；受控重放无法忠实复原外部状态（第三方系统里那个座位当时到底可不可用）。语义回归的真值常在组织外部，取证链天然不完整。

**挑战四：隐私与证据的张力。** Agent trace 会复现源系统敏感值。Google 的 managed logger 检测到行级安全、policy tag 或动态脱敏时跳过记录，而日志失败不阻断对话——可用性保住了，事故证据却可能缺失。要举证语义正确，先得保证证据没被治理策略悄悄抹掉。

**挑战五：修复权与举证权的归属。** AQuA 不自动修、不开 PR。但一旦以"行为判定修复"，新问责问题出现：14 天无复现是系统自动置位的 RESOLVED，若第 15 天缺陷以新形态重现，责任算谁的？这是干预信用面在语义域的延伸——信用口径不清，行为判定就无从追责。

## 五、展望与建议

**提出第 214 个空白字段族 `semantic.regression.*`（与静默面、证据通道面、记忆失活面、干预信用面正交）**，最小实现六字段：`finding_id + citation[]`（trace_id、deployed_snapshot_hash、file:line）／`recurring_cluster`（cluster_id、status∈NEW|RECURRING|RESOLVED、first_seen_at、resolved_at）／`verifier_result`（confirmed|rejected、transcripts_checked）／`self_reported_confidence`（与 citation 物理分离，明确不作判据）／`resolution_basis`（behavioral_cluster_absent_14d 而非 code_changed）／`quality_criteria_ref`（goal.md 版本）。缺省 `SEMANTIC_UNVERIFIED`：未声明语义标准、或未把结论锚定到部署快照的自治流程，不得进入 write≥act 阶梯，其结论不得写入语义记忆。

1. **把"洞察即引用"写进验收条款。** 采购三问：finding 能否导出到 trace 与代码行？根因比对出错时版本还是当前 HEAD？"修好了"是看补丁合入还是行为聚类消失？一问答不出，就把它定位为"可观测"而非"可举证"。
2. **让 goal.md 成为一等资产并版本化。** 领域质量标准与 runbook 同权管理、随发布评审；每次部署按标准反查"哪些约束可能漂移"，把语义回归从被动发现改为主动排查。
3. **评测增一列"证据闭合率"。** 在 Pass^3 之外单列"结论正确且证据闭合""结论错误却恢复""症状清除但未过功能验证"三类占比；用 with/without quality-criteria 双轨测出语义回归检出增益。
4. **给自动化判定配问责留痕。** RESOLVED 置位时记录依据（14 天无复现窗口与采样率），与干预信用面联动：谁改的 prompt、谁签的标准、谁确认复现消失，三者入同一份事故报告。

展望：未来 12–18 个月，"原生导出执行 trace"会成为企业 LLM API 的基线，但真正的分水岭在**举证密度**——谁能把一条"我做对了"的结论，稳定还原为出错时的代码版本、一条可回读的 trace、一份经复核的聚类和一段可追责的判定链。可观测性让团队看见 Agent，举证能力才让团队敢于把关键决策交给它。
