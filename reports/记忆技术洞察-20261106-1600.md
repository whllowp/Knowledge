# 记忆技术洞察 · 第 13 期（2026-11-06 16:00 期）

**本期主线：记忆的搬迁——锁定不在合同，在嵌入空间**

> 系列回溯：第 6 期提出"可携性梯度"——声明层可携、运行基底不可携，插座解决的是"进得来"，没解决"搬得走"。本期下钻一层，给出证据：真正的锁定点不是 API 契约、不是存储引擎，而是**嵌入空间**。换个库是搬家，换个嵌入模型是换语言。

---

## 一、发展趋势

过去两周，"记忆可搬迁性"从社区吐槽第一次变成产品议题，三条独立证据线汇聚：

1. **产品侧首个信号**：腾讯混元 MemHub v1.0.6（11-02，hy-memory==2.0.13）把"safe embedding-model switching（安全切换嵌入模型）"写进 release notes，是该能力首次被产品化命名——此前所有厂商对此沉默。
2. **大厂路线图背书**：腾讯云 TencentDB Agent Memory v2.0.3 稳定版（10-26）公开路线图，把 portable memory 与技能生成、可观测面板并列为下三件事。29.3k★ 的头部项目公开承认当前不可携，本身就是风向。
3. **格式层出现两个候选答案**：社区 CLI 工具 Vex 推出 .vmig.jsonl 交换格式（每行携带 text+vector+model+dims+namespace+metadata+时间戳，自称"向量记忆没有 JDBC"）；微软 Portable Agent Memory 协议（arXiv 2605.11032）走签名 artifact 路线——五组件记忆模型 + Merkle-DAG 血统 + 能力令牌 + 抗注入再水化，跨 GPT-4/Claude/Gemini 实测 Transfer Continuity 0.83–0.92，无记忆基线仅 0.28–0.45。

同期背景：AML Cycle 2 已于 11-04 关闭评测，结果按官方口径 11 月中公布（截稿未出），11-06 CSDN 预热文确认多模态赛道为本期新变量。

**判断**：可携性讨论正在从"接入层标准化"（第 6 期）下沉到"语义基底标准化"。这一层此前无人认领，因为它是纯成本项、无分数回报——现在它开始出现在头部产品的路线图上，说明采购侧已把它当成决策变量。

## 二、技术现状

**嵌入空间绑定律**：向量只对产出它的模型有效。换 embedder 时全库向量作废，工程上只有三条路：全量重嵌；冻结旧索引继续可查（代价是形成按年龄分层的两级记忆，检索质量静默依赖记录新旧）；迁移窗口内双索引并行（存储翻倍，且每次查询多一个融合步骤）。SciXa 成本模型给出量级：月写 8,000 万 token 的库里，重嵌全库 80 亿 token 约 $160——相当于**一次性预付 27 个月的写路径账单**。结论被明确命名为"重嵌入是资本事件，应按折旧入账，而非当事故处理"。

**不可推导性定理**（本期最重要的新判据）：文档语料换模型可以重建——源文件还在，重跑 ingest 即可；**记忆库通常不可推导**——记忆是从会话中抽取的，源会话可能已按保留策略丢弃，且抽取本身含一次不可复现的模型调用。两种工程习惯会悄悄焊死单向门：存摘要而嵌入另一个字符串；或只存指向短保留期日志的引用 ID。解药只需一行 schema：**原文与向量同存**。多数产品默认做到（文本本来要注入 prompt），但这一前提从未被写入任何导出契约。

**相似度阈值不迁移**：分数不跨嵌入模型可比，切换后所有相似度阈值需整体重标定，否则"要么全收、要么全拒"。这是比重嵌更隐蔽的坑——库搬过去了，判断标准没跟过去。

**身份税**（承接第 3 期可寻址性）：迁移脚本普遍丢 metadata、namespace、时间戳与血缘边，"拿到了向量，丢掉了意义之图"。Kunavo 对 Agent Zero 换嵌入模型给出可复核算术：3M token 重建 $0.06–0.30，30M token $0.60–3.90，且**回滚=以相同费率再重建一次**。运营侧已有成熟打法：按租户/年龄段分段迁移、高价值记录先行、切换窗口双写。

## 三、技术竞争力

| 方案 | 原文随存 | 导出形态 | 嵌入切换 | 迁移工具 | 主要锁定点 |
|---|---|---|---|---|---|
| MemHub/Hy-Memory | 是（L1 原文在库） | 本地 SQLite/Chroma | **v1.0.6 产品化支持（唯一）** | 无 | Kuzu 图、八层 schema |

| Mem0 | 开源版 ADD-only | API | 未声明 | 无 | v2 平台闭源 |
| Zep | 是（episode） | API 导出 | 未声明 | 无 | 图谱边结构 |

**判读**：①产品化嵌入切换 MemHub 独一家，且它恰好是唯一把"原文随存"做成显式分层（L1 不可删地）的方案——两个能力共享同一前提；②格式层 PAM 与 Vex 互补：PAM 解决"带血统、防篡改、跨异构模型"，Vex 解决"向量库之间怎么搬"，短期都不会分出胜负，但 PAM 的冷启动更难（协议需双方实现才有价值）；③企业侧已形成共识句式——"own the context, rent the model"：厂商记忆功能可以当缓存，不能当 system of record；④腾讯两家（数据库团队/混元团队）在可携性上出现分工：一个承诺导出，一个实现切换。

## 四、技术挑战

1. **锁定无合同化**：不做任何绑定动作，锁定随库存自动加深——"记得越多，改变记忆方式越贵"。这与传统 lock-in（靠合同、靠导出限制）不同，它由系统的成功本身制造。
2. **评测缺口（同构谱系新成员）**：AML 三赛道（文本/代码/多模态）无一考察迁移与切换能力，与弃答、冲突、时间预算、暴露-危害等缺口同构：**无分数回报的能力不会被投入**。评测若增加"迁移连续性"维度，前排将结构性重排。
3. **隐私双刃**：嵌入调用把个人文本送往模型所在处，hosted API 即第三方处理者；主权场景只剩自托管，而模型退役风险又反向惩罚自托管之外的一切选择。
4. **协议冷启动**：PAM 类签名协议的价值随采用方数量二次增长，零期无解；交换格式的竞争本质是"谁能先进一个主流产品"。

## 五、展望与建议

- **预测**：6–12 个月内"嵌入模型无关性/热切换"将进入主流记忆产品的采购条款与 RFP 模板，路径与 freshness lag（第 11 期）一致：技术指标 → 运维指标 → 合同条款。交换格式将形成 JSONL 阵营（Vex 式）与签名 artifact 阵营（PAM 式）之争，更简单的先赢。
- **采购三问**：源文是否与向量同存？嵌入模型能否声明版本并热切换？导出是否携带 ID/血缘/时间戳？
- **自查一条**：把"全库重嵌入"的预估成本写进容量规划，按折旧摊销——它不是 if 的问题，是 when 的问题。
- **下期关注**：AML Cycle 2 榜单口径（11 月中，最高优先）；MemHub "安全切换"的实现细节（是否双索引过渡）；TencentDB portable memory 是否包含血缘字段。
