# 记忆技术洞察 第62期：记忆的内部分工——当记忆系统自己变成多智能体

> 生成时间：2026-11-12 13:00 ｜ 固定四维：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战
> 覆盖来源：arXiv（MIRIX-2.0 2611.12068、AML Cycle 2 评测契约）、OpenViking、Hy-Memory、TencentDB-Agent-Memory、ReMe（含 ReMe2Ops）、dsh-memory-evolve

## 主线与新观点

前 61 期把"记忆"默认当成 agent 之外的一个单体库——第 12 期讲 N 个 agent 共享一份记忆（信任半径），第 39 期讲多机同步拓扑，第 44 期讲调度预算。本期指出三者共享一个未检验的前提：**记忆系统内部也是"一个 store"**。MIRIX-2.0（arXiv 2611.12068，11-09/10）首次把记忆系统拆成 6 个专职记忆智能体＋一个溯源超图，证明"记忆的内部也需要分工"。核心反共识观点——**episodic／semantic／procedural 三类记忆的写入与检索语义根本不同，单一 store 只能用一种索引＋一种冲突解决，必然在某一类上妥协；记忆正从"一个库"升级为"一个协调社会"**。这与第 12 期方向相反：那期是"多 agent 共用一份"，本期是"一份记忆内部由多 agent 分管"。

## 发展趋势

记忆架构从"分层"走向"分角色"。MIRIX-2.0 在 Meta Memory Manager 下让 6 个 typed memory agent 把完整记录写入"typed evidence plane"（vector DB，system of record），再用 provenance hypergraph 把实体／事件／关系／角色／时间索引成 n 元帧（n-ary frames），每条帧直接引用它来自的 records 行号。检索在确定性规划器下显式预算，证据量构造上不随历史增长（呼应第 44 期调度预算）。AutoDream 把巩固（合并重复锚点／蒸馏技能）移到写路径之外，且**永不改写证据记录**；合并只重连帧，stored memory 不被销毁。配套机制：图只是索引、DB 写入先提交、图写失败不回滚记忆、图读失败回退直接证据检索——index 与真值层解耦。

## 技术现状

六家产品仍是单体库。OpenViking v0.5.3（11-02，~41.7k★）的 L0／L1／L2 是"分层"不是"分 agent"；TencentDB v2.0.3（30.7k★）symbolic short-term＋layered long-term 仍是单 store＋MongoDB；Hy-Memory 2.0.13 覆盖 chat／working／coding 三类场景但单引擎（30B-A3B 写模型）；dsh-memory-evolve（v26092802，628★）五轨单 git 文件；ReMe（0.4.2.2）单 .reme Markdown。无一做"记忆智能体"内部分工。AML Cycle 2 仍 in progress（mid-Nov 预期），但其评测契约正在硬化——新增 user_id 严格隔离、Add 同步持久化后才返回成功、request_id 幂等、正式评测冻结版本——这是第 56 期"评测契约危机"的半步落地。

## 技术竞争力

倒挂延续：内部分工最完整的是论文（MIRIX-2.0），六家产品零"记忆智能体"披露。MIRIX-2.0 的硬指标：LoCoMo 91.4%／LongMemEval-S 72.6%（+14.3），超图单独 +2.7（85.7→88.4，多跳增益最大）＋AutoDream 再拉到 91.4；LongMemEval-S 上超图单独 +11.2。但"分 agent"带来的协调开销、agent 间冲突裁决、以及无持久化（仅 vector DB）仍是空位。AML C2 契约硬化值得肯定，但仍无 principal／source／state_role 维度（第 56 期四问未进）。

## 技术挑战

①分 agent 的协调成本：6 个 agent 各自的写入语义冲突谁裁决？MIRIX 用 Meta Memory Manager 集中，但产品化形态未知；②provenance hypergraph 的维护代价随记录数增长，十亿级条目的 n 元帧存储与查询未经实测；③AutoDream 的"合并只重连帧"假设 entity-stable 类型可靠，错误合并会污染多帧（第 3 期巩固税的代价仍在）；④index 与真值解耦使"图读失败回退直接证据"引入双路径一致性问题（第 14 期缓存稳定性孪生）。

## 需求分析

企业怕的是"一个庞大记忆库里，不同类型的事实互相拖累"——用户偏好（semantic）被任务经验（procedural）的泛化污染，或时间链（episodic）被去重合并抹平。需求本质是：**按记忆类型分工存储、按类型独立检索、按类型独立治理**，而非把所有记忆塞进同一种向量堆。

## 用户旅程

开发者的 coding agent 在多任务间切换：working memory agent 记"任务做到哪"、procedural agent 记"这条经验何时适用且带验证门禁"、semantic agent 记"用户偏好"；一次查询进 provenance hypergraph 的锚点，带回 graph fact 及其引用的原始 records 行号；AutoDream 在夜里只对新写入前沿做合并，旧 stored memory 永不被改写；审计者能顺着帧直接翻到证据行，无需信任摘要。

## 具体实现方案

1. **记忆智能体分工**：以 MIRIX-2.0 为基线，把记忆拆为 episodic／semantic／procedural 等 typed agent，各自维护写入与冲突解决语义，Meta Memory Manager 做协调。
2. **溯源超图索引**：用 n 元帧表达"结论←证据集"的支撑关系（深化第 3 期字段级血统），每条帧附引用的 records 行号，检索返回事实同时返回证据。
3. **写路径外巩固**：仿 AutoDream，合并／蒸馏只在写路径之外按"新写入前沿"触发、永不改写证据记录、合并只重连帧。
4. **真值/index 解耦**：system-of-record（vector DB）先提交，索引层失败不回滚、读取失败回退直接证据，保证证据不丢（落地第 60 期非破坏性）。
