# 记忆技术洞察 · 第 138 期（20261124-0200）

**主题：记忆的「回执兑换」（receipt-bound memory admission）——一条经历能否写进长期记忆，不取决于它读起来像不像事实，而取决于它能否当场兑换成外部进程签发的执行回执。前 137 期把可信度判在证据端、服务端与答案端（#126／#134／#136），共同预设“工具叙述≈工具结果”；11-20 提交的 Epistemic Guard（arXiv 2611.27095，Sean Maxwell，cs.SE／AI／CR）把校验前移到写库边界：先问“哪项外部副作用真发生了”，再问“它有没有资格进记忆”。与 #126 划界（那期问旧证据在新上下文可不可采信，本期问能否入库）、与 #134 划界（那期服务时反事实归因，本期写时密码学兑换）、与 #88／#105 深化（同源坍缩从引用图扩到多源佐证）。**

> 洞察范围：2026 年（近 30 天为主）。四维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

长程 agent 的记忆入口正从“文本可信”外移到“执行可证”。摘要、检索与逐出都在处理已进来的内容；一旦模型把失败、超时或根本没跑的调用叙述成既成事实，下游工作流和跨会话记忆就会把单轮幻觉固化。新趋势是把可验证执行回执做成写库凭证，并把“多源佐证”从数 URL 改为数独立来源簇。

## 二、技术现状

系统分三块。进程外 stdio MCP 代理剥离子进程的签名密钥，把每次调用分为成功执行、执行后应用失败、执行前参数拒绝、子进程崩溃四态，签发 Ed25519 回执、追加 RFC 6962 Merkle 日志并双向翻译 AER-1。符号加 INT8 混合监督器在回复交付前遮掉否定、条件、引语与代码块，识别状态变更句，再按回执的 executed／ok 与参数、目标逐项匹配。SQLite 写门在七个来源域中只放五个有签名的域通过，模型叙述和不可信工具文本没有签名构造器，审计行由触发器禁止原地改删。

## 三、技术竞争力

N=250 冻结轨迹准确率 93.2%（95%CI 89.38—95.71），比 12B／14B GPU 裁判高 6.4／6.8 点（p=0.0259／0.0095），p50 17.9 毫秒、零显存、快 4.26—4.5 倍。N=60 实时代理轨迹捕获 96.15% 危险（25／26），准确 76.67%、误报率 38.24%、p50 9.16 毫秒；回执绑定相对纯文本阶段 +18.34 点（p=0.001）。符合性上拒绝 200／200 篡改回执、通过 58／58 项 AER-1 摄入、阻断 100／100 未授权写入，135 个转载 URL 归并为 45 个单源簇。

## 四、技术挑战

①回执只证明服务端在线上回了 ok=true，恶意服务端可以造出合法签名的假回执。②镜像归并在约 15% 轻改写时仍 100%，到 30% 改写降为 40%，45% 改写与 80% 抽象重写归零，独立性存在词法悬崖。③Live-60 的 13 个误报中 6 个来自自定义工具名、7 个来自“尝试 X，但失败”的跨句否定。④仅代理 stdio，HTTP／SSE 需桥接。⑤安全硬化拒掉零参数通配后从 94.4% 落到 93.2%，硬化本身要付召回税。⑥冷启动 921.8 毫秒。

## 五、需求分析

用户怕的不是忘记，而是记住没发生的事：代理声称“已提交”，实际调用被参数校验拒掉；三家网页转载同一通稿，被当成三源佐证。产品需要在不改模型、不占 GPU 的前提下，让已执行、执行失败、未执行、已入库四态可追，把模型叙述、工具内容与用户明示分层，并让每条写入都可撤回、可审计。

## 六、用户旅程

一次请求进来，工具服务器在启动前已被剥掉签名密钥；调用返回后代理按四态签回执并链入 Merkle 日志；回复显示前先跑监督器，无副作用句直接放行，有副作用句则对目标与参数逐项核回执。核对失败时给重试提示而非静默入库；写库时按来源域放行，跨源事实先做镜像归并再数独立来源；面板按捕获率、误报率与回执开销分账。

## 七、具体实现方案

①在写库边界设兑换闸门：只有带域隔离 Ed25519 签名的五个域可写，模型叙述与不可信工具文本无签名构造器（接 #126，划界 #134）。②把“尝试≠发生≠成功”写进回执四态，非标准错误保守记为 executed=true／ok=false，目标按路径与词边界匹配、拒零参数通配。③独立来源按 k=4 shingle、Jaccard≥0.45／0.55、SimHash 汉明距≤12 折叠后计数，再按三级危险×四种证明标准的十二格策略决定能否无保留陈述。④验收：AML 增 provenance-receipt 维度（回执绑定率／未授权写阻断率／同源折叠率／误报重试成本／硬化召回税），以“没发生的进不了记忆、转载不算多源”验收。五项目经 GitHub tag／release API 核实：OpenViking v0.5.5、Hy-Memory v2.0.17＋MemHub v1.0.8、TencentDB-Agent-Memory v2.0.4、dsh-memory-evolve v26092802、ReMe v0.4.2.3（11-23 有推送但仅测试标签）——五家均无进程外回执兑换与同源折叠，倒挂延续。反证：单作者、离线语料、英文单工作站、仅 stdio、Live-60 对 GPU 裁判差距不显著。

## 八、本期新观点

1. **记忆准入单位从“语义可信”改为“可兑换的执行回执”**（接 #126、划界 #134）——未发生≠失败≠成功三态先验，叙述无法凭自身获得签名，可信度成为写库时的兑换关系而非条目形容词。
2. **独立来源数不是 URL 数，而是折叠后的簇数**（深化 #88／#105）——折叠率在 30% 改写处腰斩、45% 处归零，独立性是有边界的词法性质，必须按危险级换证明标准。
3. **验证税从显存搬到 CPU 与重试**（深化 #5／#134）——零显存、17.9 毫秒换 93.2%，但 Live-60 误报率 38.24%，每次误报付一次重试；“免费验证”只是换了一本账。
4. **安全硬化是可测的召回税**（新角度）——拒零参数通配令准确率 94.4%→93.2%，阻断率 100% 不能单独作为验收指标，须与召回、误报并列回归。
5. **写时兑换是第三道门，与运行时因果检测互补**（接 #134／#136）——写前挡住无回执叙述比事后归因省，但回执只证线上返回不证真实，二者不可互相替代。
6. **五项目倒挂＋AML 补 provenance-receipt 维度**——以“没发生的进不了记忆、转载不算多源”验收，而非以来源字段 filled 与否验收。
