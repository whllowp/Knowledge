# AI-SRE 技术洞察（第 188 期）

**生成时间**：2026-11-13 17:00（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：轨迹归属面／归因主权面（Trace Attribution）——六家把"画出 Agent 轨迹"做满，却只有三家补齐"判定轨迹是否做对、归因为哪一步"；端到端 Trace ≠ 可定位

---

## 题记

传统可观测回答"系统是否正常"，靠的是服务、接口、实例的 metrics/traces/logs。当主角变成 Agent，一次"慢回答"会穿越 7 步推理、3 次工具调用、2 个模型与一个子智能体——OTel 能画出调用树，却答不出"是哪一步、哪一个工具、哪一条策略让任务失败或变慢"。刘杨（蚂蚁）把痛点说透：**有了完整 Trace，仍判断不了 Agent 是否做对了任务**。这就是 Agent 可观测性的「轨迹归属」缺口——它正好接在 #185 度量主权（谁定义 SLI）之后：SLI 自己设了，若症状出现时定位不到具体步骤，等于测了白测。

## 一、发展趋势

**趋势一：可观测单位从"服务/接口"上移到"Agent 步骤/工具/策略"。** 2026 年六家集体把监控对象从 LLM 调用扩到 agent workflow：阿里云 ARMS 于 7-30 将"LLM 应用监控"更名"AI Agent 可观测"；腾讯云 Agent 可观测 9-21 上线；字节 Coze Loop/火山 AgentLoop 把 Trace 作为一等公民；OpenAI Traces、Anthropic 10-14 OTel 导出、Google Cloud Trace+OTel 同台。

**趋势二：语义标准化成为"入场券"。** Anthropic 2026-10-14 的 OTel 导出基于 OpenTelemetry GenAI 语义约定（convention commit e57c543b，2026-09-24），使 Claude 的 model/tool/MCP span 与各厂商在同一 dashboard 对齐；OpenAI、Google 同样走 OTel。统一语义是跨厂商轨迹归属的前提。

**趋势三：可观测与评估融合，从"画轨迹"到"判轨迹"。** 刘杨提出"以 Trace 为中心的实时评估"；Coze Loop 自动采样 Trace 做在线评测；腾讯把"任务质量"与调用链关联、支持复测。这是 2026 年最关键的跃迁：监控 → 评估。

**趋势四：归因从"人看"走向"机归因"。** 阿里 STAROps/智能告警定位根因；腾讯"AI 调用 AI"自动归因分发；字节扣子按异常特征自动归因到负责人。

## 二、技术现状

- **OTel GenAI 语义约定已成事实底座**：刘杨在蚂蚁落地 L1/L2/L3 三层、9 类 Span 的统一埋点；Anthropic/OpenAI/Google 均基于此导出。
- **但"端到端 Trace ≠ 可定位"**（刘杨）：长程几十步，错误可能出在任何一步，端到端链路齐全不等于归因自动。
- **六家落点**：Google 每 step/tool/MCP/A2A/model/memory 发 OTel span 到 Cloud Trace，ADK 内建 Agent Observability，但 Agent Simulation/Evaluation 仍 Pre-GA；Anthropic 10-14 beta 覆盖 Messages API/Managed Agents/SDKs，span 含 agent turn/model/tool/MCP，支持 metadata-only 与 full-content 两模式，W3C traceparent 传播进子进程、end-user 归因；OpenAI Agents SDK tracing 默认开、Traces dashboard 可见，Agents API（11-09）默认全追踪 beta、group_id 关联会话、可导出 OTLP JSON（ZDR 下禁用）；阿里 ARMS 全局拓扑+链路树/轨迹图+会话分析+智能告警根因，STAROps 跨层诊断，兼容 Langfuse v3/v4 与 OTel；腾讯 Agent 可观测全链路追踪+性能成本+效果评估，调用树回放、内置异常规则、AI 分析定位，蓝鲸底座+CloudQ 多云图谱；字节 Coze Loop 的 Trace 上报/自动 BadCase 识别/在线评测/迭代比对，火山 AgentLoop 运行观测/回放/离线评测/实验对比。

**判读与本期反转**：原生 OTel 语义已成"入场券"（Anthropic/Google/阿里/字节都接），真正区分度在「评估融合 × 根因归因」两列——这两列只有阿里 STAROps、腾讯 AI 调用 AI、字节 Coze Loop 填得上；OpenAI/Anthropic 停在第一段"画出轨迹"，把"评判/归因"留给外部 eval 与 backend。这是本期第一个市场空白：**「轨迹→判定→归因」三段中，六家把第一段做满，后两段仅国内三家补齐**。与 #185 度量主权的分工：#185 管"谁定义 SLI/playbook/eval"，本期管"SLI 报警后能否定位到具体 agent 步骤"；与 #187 隐私面的分工：#187 管 PII 在五处副本的脱敏/删除，本期管 full-content 导出时的归因粒度与合规冲突。

## 四、技术挑战

1. **语义孤岛仍存**：虽都标"OTel GenAI 语义"，但各厂商字段命名未完全收敛（Anthropic commit e57c543b 仍 beta），跨厂商 trace 对齐需手工映射。
2. **端到端 Trace ≠ 可定位**：长程几十步，span 齐全不等于归因自动，错误定位仍靠人肉。
3. **评估与追踪时滞**：刘杨"以 Trace 为中心实时评估"需分钟级端到端，但多数厂商评测离线/抽样，线上实时质量判定稀缺。
4. **成本归因失真**：Token 计数在 span 级易得，但"哪一步决策导致整体变慢/变贵"的多跳归因无标准指标；P95 告警到了，根因仍在黑盒。
5. **隐私与归因零和**（呼应 #187）：full-content 导出能归因但泄露 PII（Anthropic 对 HIPAA 强制 metadata-only），脱敏后又丧失归因粒度。
6. **跨厂商委托链断裂**：OpenAI group_id / Anthropic 子agent 嵌套能连，但跨厂商（A 用 Claude、B 用 GPT、C 用 Qwen）多智能体调用链无统一 traceparent 传播标准。

## 五、展望与建议

1. **把"归因命中率 / 端到端 trace 可定位率"列为 Agent 可观测一等 SLO**（第 132 个市场空白：归因命中率、端到端 trace 可定位率、agent step 级 SLO、跨厂商委托链连通率、实时评估覆盖率——无一内建）。
2. **语义收敛**：推动各厂商字段对齐 OTel GenAI semconv 稳定版；`agent.trace.*` / `agent.attribution.*` 应成标准字段族（第 100+ 次无人提字段族，延续 #187 的 `pii.*` 空白）。
3. **评估前置**：借鉴刘杨"小模型/正则全量粗筛＋大模型按需精判"（90%+ token 降本，<1% 进大模型），把在线评测接进 trace 流水线，而非离线旁路。
4. **隐私-归因双轨**：metadata-only 默认，full-content 按需审批短时保留（呼应 #187 入口脱敏），归因粒度与合规边界解耦。
5. **跨厂商委托链**：以 W3C traceparent + A2A agent card 为最小公约，让跨厂商多智能体调用链可拼接。
6. **国内基准牵引**：信通院《云上 Agent 基准度量模型》六维已立，建议补"可观测/归因"维度，把"轨迹归属力"纳入认证。

## 本期权观点（新视角）

① 可观测的下半场不是"更多仪表盘"，而是"以 Trace 为中心的实时评估 + Token 级深度分析"（刘杨命题延伸）。② 轨迹归属是度量主权（#185）的下游——SLI 自己设（#185）却定位不到步骤，等于测了白测。③ 六家把"画轨迹"做满，"判轨迹/归原因"仅国内三家（阿里 STAROps/腾讯 AI 调用 AI/字节 Coze Loop）补齐，是第一段市场空白。④ 原生 OTel 语义已成入场券，真正区分度在「评估融合 × 根因归因」二维。⑤ 隐私与归因零和（呼应 #187）：full-content 归因强但泄 PII，metadata-only 合规但归因弱，需双轨。⑥ 跨厂商委托链无统一 traceparent 传播标准，是 Agentic Ops 最大归因断点。
