# 记忆技术洞察 · 第152期（20261125-0700）

> 洞察范围：2026 年、尤其近 30 天，AgentMemory 发展趋势／技术现状／技术竞争力／技术挑战四维度。主线来源：arXiv 2611.31105（11-23 提交）。本期新观点已与本地 C/E 双版索引及知识台账比对，未重复前期。

## 一、发展趋势
记忆正从外部条目走进推理状态与权重：在线学习让 agent 在会话中途换上新版 LoRA，活跃会话却仍持有旧版 KV。11-23 LiveLoRA（arXiv 2611.31105，cs.AI，Ryquo＋App-In Club，AgenticOS workshop）把这一刻定义为"版本一致的发布"：参数、KV、下一 token logits 必须同版出现。与 #137（KV 逐出）、#141（模型内解码）、#145（编译式写权重）划界——那里是单版内的存删，本期是跨版本换脑；与 #150 缓存经济学衔接，成本从每 token 定价扩到每次发布。

## 二、技术现状
方法把 LoRA 限制在解码器最后一块，下面各块、归一化与输出头冻结；K/V 适配器的降投影 A 固定，历史只需留基础投影与低秩坐标两组不随版本变的不变量。发布时批量重算候选版 K/V，再用最新 token 重过最后一块拿到新 logits，最后把适配器、缓存、logits 原子换引用；前缀若已变化则拒绝发布。精确算术下证明与全史重预填条件分布等价；BF16 实测末块 K/V 与参考零可观测误差，而陈旧缓存 KL 达 0.0272—0.0375、百次更新压力下达 0.4864。

## 三、技术竞争力
Qwen2.5-3B-Instruct 单会话 8K 重算 150.05ms 对迁移 17.17ms（8.79×），32.7K 为 919.21 对 18.03ms（51.06×），32 个 8K 活跃会话 4,534.46 对 65.71ms（68.98×）。常规解码较原生缓存贵 4.75—4.88%，较同等守卫的直接服务只贵 0.68—0.81%。紧凑留存每会话新增 9.48MiB，较边界重放 32.41MiB 少 3.42×；但 8K 处相对全量重算的盈亏点约 600 token／次，相对边界重放只有 30 token／次。

## 四、技术挑战
迁移只覆盖末块适配且 K/V 降投影固定；若改更早层，需存边界残差并重放可写后缀。结果限于单进程、连续序列、标准 RoPE、无分页缓存与分布式发布；任务级适配质量未评，只测了高斯更新与迁移正确性。数值上精确等价不等于逐位相同，BF16 多次发布仍有非零 logits 差异。五项目今日核对版本未变，均无适配器版本的会话热迁移接口。

## 五、需求分析
运维者要的是"模型升级不停服"：新版策略上线时，正在跑的长会话不能整段重算、也不能悄悄混用旧 KV；发布失败要退回旧版；更新频繁时还要知道该选迁移还是重放，别把省下的显存赔进发布延迟。

## 六、用户旅程
训练器在冻结边界采输入→后台独立优化候选适配器→发布协调器锁住会话集与快照→锁外重算候选 K/V 与 logits→校验前缀未变后一次性换引用→下游按新版继续生成；遇到前缀已改或准备失败则整笔撤回，旧版继续服务。

## 七、具体实现方案
①把可适配层收敛到末块，K/V 降投影固定为跨版不变量；②留存基础投影＋低秩坐标，批量重算历史 K/V，不逐次累积增量；③三元组原子发布＋前缀校验＋失败回滚，进程内保证；④按更新间隔与会话数记账，600／30 token 盈亏点选迁移或重放；⑤验收七账：发布延迟、保留字节、解码附加、数值漂移、陈旧 KL、前缀拒绝率、连续发布不塌陷；⑥AML 补 live-migration 维度。

## 本期新观点
1. **记忆新增"推理状态版本一致性"对象**（接 #137／#141／#145 划界）——记忆不只是内容或权重，还包括参数、KV 与 logits 的同版绑定；旧缓存配新参数既不是丢失也不是过期，而是版本混合，须作为独立故障类验收。
2. **冻结边界把不可搬状态变成可重算坐标**（新角度，深化早期"迁移税"）——存基础投影＋rank-32 低秩坐标而非重嵌或全量缓存，换版时批量重投影；迁移税从"全量重嵌／扔掉记忆"缩成保留字节与一次矩阵乘。
3. **记忆税新增"发布税"一本账**（接 #5／#137／#150）——成本不再按每 token 或每次检索计，而是发布延迟×活跃会话数×更新频率；32 个 8K 会话全史重预填 4.53 秒、迁移 65.71ms，长会话舰队下发布延迟才主导总账。
4. **发布单位必须是三元组且失败可整笔回滚**（深化 #138 外部回执）——外部回执证明事情发生，内部发布回执证明参数、缓存、下一 token 分布同版；前缀变化即拒收，把"写后一致"从数据库事务推广到推理状态。
5. **迁移收益有双盈亏点，禁止默认热迁移**（深化 #131／#150）——相对全量重算约 600 token／次、相对边界重放仅 30 token／次；策略应随更新节奏与会话长度切换，省字节与省时间不是同一目标。
6. **产业侧无会话热迁移接口，AML 补 live-migration 维度**（新角度）——OpenViking v0.5.6／Hy-Memory v2.0.17＋MemHub v1.0.8／TencentDB v2.0.4／dsh v26092802／ReMe v0.4.2.3 均无适配器的会话级发布协议；研究已到跨版本状态迁移，产品仍停在会话确认与分层读取。
