## 一、发展趋势：等待被承认了，承认的是价格

**基础设施层第一次把「等」写成设计目标。** 10-22 Google Cloud 官方发布 Agent Compute Engine，技术深潜列三条问题之一：**"Agents spend most of their time waiting. An idle agent should cost almost nothing and wake up faster than a person notices."** 工具调用结束进入 thinking 时 microVM 发出 idle 信号，宿主快速 checkpoint 转 idle、「consuming zero active resources」；发布稿更直白——**"it can pause a running microVM while an agent waits on a human or an external system"**。20 万 agents／500 次激活每秒／恢复 <500ms（自报，preview）。判词：**承认的是成本不是责任**，算力账压到近零，「谁欠它一个决定、等了多久、等完还算不算数」一分未减——**idle cost 被消灭，idle work 没有**。

**协议层第一次给等待发了「工作收据」。** MCP Tasks 随 2026-07-28 规范成为官方扩展；10-22 AGNTCon keynote 宣布支持、10-23 进 CLI、10-26 Claude Code v2.1.304+ 列 public beta。慢调用返回 `taskId`／`ttlMs`／`pollIntervalMs`，五态 `working / input_required / completed / failed / cancelled`，用 `tasks/get` 轮询、`tasks/update` 补件、`tasks/cancel` 请求停止。AGNTCon Europe 复盘点破缺口：**"the spec deliberately leaves storage to implementers, and that's where things go wrong"**，失败模式是 orphaned tasks 与重复副作用。判词：**「能找到」不等于「能被管」**——五态无 `pending` 一等状态（"Queued" 只是自由文本），无队列长度、年龄、owner 与升级目标。

**标准侧写进了「超时与取消」，没写进「存量」。** 11-03 信通院六维建议按辅助诊断／审批执行／限定自治分阶段落地并保留人工接管；11-04《自律公约》第三条被解读为「任务状态机＋幂等键＋超时与取消」，同日横向评估标准四项书面记录（成功率、人工接管比例、单任务成本、异常响应时长）**无一是队列指标**。阿里 10-26 三级门控、腾讯 11-03「先研判再交人决策」、火山 11-03 超时自动终止——**门控成了一级语义，门控前排着的队没有**。

## 二、技术现状：一个存量，四种口径

**① 存量不产生事件，而监控是事件驱动的。** span 有起止、错误有告警、变更有审计，挂起三样全无，却是唯一单调增长的量。一份复盘：3 个并发槽被「待审批执行」永久占据，36 个任务静默延后、零错误通知，11:00 的校验任务晚 35 小时；**连「检查任务结果的监控任务」自己也被延后**。"The deferred tasks are not failures, so no failure notifications arrive."——62 元观测面复现：**监测装置与被监测对象共用同一队列时，故障在结构上不可观测**。OTel 跨 Kafka trace 能看见「几微秒进队列、模型 3 秒」，但**等人工的 45 分钟不在任何 span 里**。

**② 保质期由框架默认值给，不由业务给。** 10-23 四家官方文档横评：LangGraph 与 OpenAI Agents SDK 不设上限，Claude Agent SDK 落盘默认 30 天，Bedrock Agents 最多 90 分钟；另有 Claude Code 后台会话未附着约 1 小时停进程、RabbitMQ consumer 默认 30 分钟未 ack 关通道、MCP `ttlMs` 由 server 自定。题眼：**"No limit means the framework sets none. Your storage, and how long a person's answer stays relevant, set the real one."** 更细一层：per-message TTL 只在消息**到达队头**时清理，**积压越深，过期的工作活得越久**。

**③ 批准能力是有容量的资源，从没进 SLO。** ρ = λ·s / c：240 次/小时、每次写过门、每人 1.2 分钟、2 名审核人 → 132%，队列整班单调增长；改评分门控（8%）→ 19%。橡皮图章三信号（决策时长降而队列变长、拒绝率趋零、错误提案被批准）；10-21 核档实践更朴素：24 × 3 分钟 = 72 分钟需求 > 60 分钟工时。**"If a critical approval takes 45 minutes at the median, adding more model capacity will not improve delivery time."** 最危险的默认是「超时自动通过」＝把「没人回应」译成「同意」；反面准则是「无人回应不能被视为同意，应暂停或取消并通知具名后备」。

**④ 挂起期间世界在变，唤醒时却不重检。** 10-21 核档实践：「每次批准都应绑定到审核过的具体内容及参数，收件人、金额、记录版本变化，原审批应失效并重新提交」「执行前复查等待期间可能变化的事实」。挂起快照没有 `evidence_as_of`，恢复时被当成新鲜证据——**一次基于已经不存在的世界做出的决定**；87 期候选集与 88 期授权主体同样不重检。

**⑤ 三种静默结局，且取消也只是协商。** 过期丢弃无死亡通知；恢复后重复执行——ONES 列「重试创建第二个请求而原请求仍开放」，MCP 核心协议无幂等键、HTTP 断流换新 request ID 重发可能建出第二个任务，重提为新请求则丢掉原上下文。76 期「停是一次协商」在此更弱：**`tasks/cancel` 是协作式的，服务端确认收到意图但没有义务中途停止**；「退出 Claude Code 并不会取消远端任务」；教程里补件框被 /tasks 面板遮住——**连 UI 都能把挂起工作藏起来**。

**⑥ 有没有被记下来，取决于会话类型而非工作本身。** Claude Code 拿到 task 需版本、协议修订、功能开关、主会话且交互式等一叠条件，桌面端不支持；而 10-07 支持度盘点仍称 Claude Code／ChatGPT／Codex／Cursor 不声明该扩展——**同一时期两份材料互相矛盾，按两说并存**，82 缺省面结论在此复现。极端例是 ccdeck：Codex 的 rollout log 不记 approval request，其会话永不被标记为 waiting——**等待状态的有无取决于日志格式，不是事实**。

**判读**：**本期再修往期判词**——挂起维度最完整的答案不在六家云厂商，而在**消息队列／工作流侧**：队列系统三十年就把「没做完的东西」当一等对象（stock vs flow），有 TTL、死信、年龄、租约与 fence；云厂商把等待当成本、协议侧当句柄、标准侧当「超时与取消」，都没当**存量**。国内例外是火山：RocketMQ for AI 的 LiteTopic 生命周期与 AgentKit 按**停留时长**排序的看板——**「停留」成了看板指标，却是需求流程维度，没进 Agent 运行时 trace**，更精确于 89 期判词：强项在中间件与看板。规范层从 72 `identity` 到 89 `degraded.*` 十二族后，`pending.*` 是**第 13 次无人提的字段族**。分野三问：挂起清单能否导出及其 owner／等待是否计入 MTTR 与 SLO／唤醒是否强制重检。

## 四、技术挑战：第四十四个市场空白

**五项指标无一内建**：挂起存量、`queue_age_p95`、ρ、静默丢弃率、唤醒重检率。**挂起是负事件家族里唯一「有存量」的成员**：78 到期、81 弃权、82 缺省、83 采样都是「没有这条记录」，89 降级有代码却只在故障时才跑；挂起有库存、有作者、有占用，却因不产生事件而不进变更流、审计与 SLO。RCA「找最近变更」找不到它——**它不是变更，是一段没有结束的开放区间**。

**等待变便宜了，欠账没有。** 58 账面／79 编制／70 能耗在此合流：占并发槽、占配额（10 个后台会话约耗 10 倍额度）、占审核人力；ACE 把 idle compute 压到近零，业务成本与结论失效成本一分没少，反而因便宜鼓励更多挂起。83 期采样面交叉：挂起会话最易被丢，**分母恰少最难看的一批**。

**本地 173 / 173-kb 连续第十一期成组启用，升级为「挂起治理原型」。** casa 01「空白、等待、失败都没有设计」后紧接 **「PENDING 只恢复轮询」**——有状态却只有轮询一个动作，无账本、无归属、无到期；「预期恢复 T；任务与扣费不增加　实际观察：待填写」把「恢复后不重复扣费」留成未验收的空格。肖汉松 22 把等待定为长程执行**主要耗时**（人工衔接，均值 12.6 天）；刘宗明 06「决定等待、调整或停止」并「**绑定等待、加载中、完成等状态**」；何伟 02 未完成任务写盘可恢复、余锦泽 03 暂缓保留理由、周昕毅 10「卡住超 5 小时」、朱革 15 写操作缺统一审批与回滚、王浩男 21 调度器分发后进入等待（88 期同素材换视角）。判词：**联网侧 10 月刚发「工作收据」，本地讲义早把等待列为主要耗时、把 PENDING 写进状态机**；连续第十一期同一结论——仍是项目内约定，不可采购。

## 五、展望与建议

**立成一等存量**：六态 `QUEUED / WORKING / INPUT_REQUIRED / SUSPENDED / EXPIRED / ORPHANED`（＋三终态），每态声明 owner、deadline 及其时钟、backup、允许动作集合；`pending.*` 九字段由确定性控制器而非模型设置。**按存量告警而非按失败告警**：五项 SLI 进值班大盘，告警写「队列年龄越界」而非「错误数越界」（与 65 巡检面之别：存量本身要能触发）。**卡在派发处不是产出处**：按 Little's Law 定 WIP cap，gate 必须挡住「启动 agent 工作」，否则「开不出 PR 就留下一根没人看见的分支」；并发上限按审核容量定，不按算力定。

**唤醒重检做成门禁**：重检证据 `as_of`、被批准参数、策略版本、scope 与 87 期候选集，任一变化即作废原批准；**禁止超时自动通过**，超时转暂停/取消并通知具名后备。**租约＋fencing＋幂等**：lease 带 expiry、fence 挡旧 worker、副作用按 operation ID 幂等、DLQ 定位为「需要一次决定的任务」，trace 记 run ID／fence／worker／lease expiry／checkpoint version／external op ID／final disposition 七字段。**演练三型**：审批人离岗、恢复时证据已变、深积压过期消息被当新鲜任务消费。**采购三问与标准补格**：挂起清单及 owner 能否导出／等待是否计入 MTTR 与 SLO／唤醒是否强制重检；建议信通院六维与 11-04 四项书面指标补「队列年龄与挂起存量」，把「保留人工接管兜底」改写为「人工接管队列可观测且有 SLA」。

**结论**：79 编制、88 授权、89「少做的制度」之后，本期是——**「等着的制度」也还没上线**。平台算清了等待的电费，没算清等待欠谁一个决定。
