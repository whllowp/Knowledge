# 记忆技术洞察（2026-11-08 21:00 期）

**本期主线：记忆的环境学——记忆是唯一没有预发环境的持久状态**

> 系列第 38 期。前 37 期无论讲写入、删除、检索、成本还是合规，都共享一个未言明的预设：**记忆库只活在生产里，测试时它要么不存在、要么被理想化**。本期拿掉这个预设。记忆库是一个跨环境存续的持久资产，而行业对它的环境治理——开发/预发/生产分离、夹具化、晋升快照——几乎为零。记忆因此成为软件工程里唯一"改一版不敢测、测一次就污染生产"的状态。

---

## 一、发展趋势

本周出现一个结构性信号：记忆测试的话语权正在从**评测方**转向**工程方**。一周内集中出现多份系统性方法论文本——zorost 的记忆架构指南把"记忆如何弄坏你的评测"写成一等章节；automater 发布可在一个周二跑完的三臂记忆基准方法；n4n、QABattle 各给出确定性 harness 与隔离包清单；compelstandard 标准草案首次把"记忆版本化"列为 agent 生命周期四维（模型/提示词/工具/**记忆**）中"被遗忘的一维"。这批文本的作者全部来自测试工程与标准社区，而非记忆厂商——行业开始承认：**记忆是隐藏输入，一个记忆依赖的 agent 在记忆状态进夹具之前不可复现**（"对同一可变共享库跑两次同一任务，是两个不同实验"，zorost）。

榜单侧，AML 二期 11-04 关闭评测后，官方页 11-08 仍显示 "Cycle 2 in progress"，月中原定发榜窗口进入倒计时；一期全能力剖面（A–H 八维）已公开，MemPalace（60.4k★）以 39.48 位列文本商业榜第 9，成为榜单前十中的新面孔。

## 二、技术现状

**六项目状态（11-08 21:00）**：OpenViking v0.5.3（AGPL，41.3k–41.6k★口径不一，周 +448★，DSH 插件 0.5.33）；TencentDB-Agent-Memory 30.5k★（已迁腾讯云 org，v2.0.3 stable 10-26，路线图下一项为观测面板，MIT 许可被 GitHub 检测器标记为 NOASSERTION）；Hy-Memory 2.0（10-16 三层全开源：30B-A3B 写入模型 Apache-2.0 + Python SDK + MemHub，宏均 55.49 vs Opus 54.62 为自报未复现）；ReMe 0.4.2.x；dsh-memory-evolve 665★（末次实质提交 10-29，社区变体分裂）；ReMe2Ops 仍无独立实体。

**现状三块拼图**：

1. **不可复现二源**。记忆系统的不确定性来自两处：对 wall-clock recency 的依赖（时间越近分越高）与向量随机性。工程共识是冻结时钟 + 固定种子是最低配（n4n 给出 freezegun 方案），但六家产品无一提供"时间冻结"评测模式。
2. **夹具化三实践**（zorost，本周最完整方法）：①按用例播种并重置——否则通过可能由另一条测试写入的记录解释；②**断言写路径**——"停止持久化用户纠正"这类回归对输出评分完全不可见，必须直接检查写入了什么；③**植入陈旧记录**——种一条与工具将报告的事实相矛盾的旧记忆，验证 agent 拒用它。"会用对记忆是及格线；会拒用错记忆才配见客户。"
3. **三臂擦除式基准**（automater）：臂 A 无记忆、臂 B 候选产品（经其自身摄取路径装载夹具）、臂 C 本地 transcript 检索（产品必须击败的既有基线）；**臂间擦除库、工作树与会话态**，"记忆从臂 B 泄漏进臂 C 是基准产生假结果最常见的方式"；夹具按 1/5 植入已陈旧事实、1/10 植入跨项目相似噪声；manifest 哈希冻结后不得再改。

中文工程社区同周给出**环境分离四件套**（ainomam）：提示词、工具、评测集分环境已成实践，**记忆是最容易漏的一项**——同一个向量库同一个 collection，开发机上的测试对话污染生产检索结果，且这种污染极难发现，"检索出来的历史上下文看着像真的"。其规范基线：dev 每人独立命名空间、staging 用脱敏副本、prod 生产。配套的"治理即服务"（finexus）已能对数据库表按需生成掩码副本（"给我一张 PCI 掩码的支付表"，90 秒交付）——但等价物对记忆库不存在。

## 四、技术挑战

1. **脱敏悖论**。表数据脱敏保结构即可用；记忆的价值恰在具体性，脱敏破坏具体性。更糟的是记忆是派生物且不可从源重建（第 13 期不可推导性定理）——staging 无法像 RAG 语料那样从生产源重新生成，只能快照或合成，而合成记忆会改变检索几何（第 32 期干扰效应）。fastio 指南要求 staging 与 prod **嵌入模型对齐**，却无法回答"清洗后的记忆还代表生产分布吗"。
2. **快照与删除权对撞**。晋升点记忆快照本质是备份，第 18 期"备份-删除不可能三角"在测试场景重演：canary 期间被投毒的记忆若不快照会活过回滚（compelstandard 的原话），快照了则已删数据在 staging 复活。
3. **评测自我污染**。测试项一旦进过优化循环即成开发数据（egoistai 主张 dev/release-gate/sealed 三层分集与暴露史登记）；记忆系统自身的摄取路径会把评测内容写进生产库——**被测系统污染被测集**，canary 字符串（BIG-bench 惯例）与剥离上下文对照（删掉 supposedly 依赖的上下文分数不动＝测的是模板记忆，hackyjs）是仅有的两条检测手段。

## 五、展望与建议

**三个可证伪预测**：①夹具/种子 API（`seed()`/`reset()`/`export_state()`）将在 6–12 个月进主流记忆 SDK，首个实现者获得"可测试性"采购标签；②晋升点记忆快照将进企业采购清单，与备份条款合并审计；③`origin`（生产写入/夹具/评测）字段将进 schema——它与第 36 期 `purpose_scope` 同构：一个是"为何存"，一个是"从哪来"。

**给团队的三条建议**：把记忆状态当夹具而非环境（per-case 播种重置）；`must_not_recall` 零容忍进隔离包（QABattle：隐私失败是最贵的一类）；上线前跑一次三跑对照（无记忆/oracle/生产）——oracle 与生产之差是检索与写质量的天花板距离，生产与无记忆之差若趋近零，说明记忆在徒增成本（akkawi）。

**下期看点**：AML 二期正式榜单（11 月中，最高优先）；首个提供 seed/reset 接口的记忆产品；晋升点快照进任何产品的发布流程；`origin` 字段首例。
