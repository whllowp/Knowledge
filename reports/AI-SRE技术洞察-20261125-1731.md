# AI-SRE 技术洞察（第 355 期）

**生成时间**：2026-11-25 17:31（Asia/Shanghai）
**洞察窗口**：2026 年，重点为最近 30 天
**本期主题**：量化面／低比特与行为漂移——准确率没掉，失败方式变了

## 题眼

arXiv 2607.27275《Flat Score, Amplified Failures》（2026-07-29）在 τ²-bench 上跑了 8 个格子（两个开源模型家族、dense 与 MoE、两个领域，每格 456 个 episode，16/8/4 bit 权重）：**标准指标上没有任何一格的分数变化能通过多重比较校正**——量化看起来"免费"；但同一批数据上，失败的结构被改变了。

另一组数字更刺眼：Zenodo 23074295（2026-10-01）用五工具、25 任务的 harness 跑了 **2,400 个种子 episode**，发现在 1.5B 参数上，**8-bit 量化的任务成功率是默认 4-bit 的两倍以上**（+16 个百分点，p = 2×10⁻⁵），而且"改变的是它怎么失败，不只是失败多少次"。

准确率是一个平均值。量化改的是分布的尾部。

## 一、发展趋势

第一，低比特从"部署优化"变成"发布决策"。开源权重的默认分发正在向 4-bit 走（GGUF Q4、AWQ/GPTQ 4-bit、NVFP4），端侧与低成本 Agent 尤其如此；团队以为自己只是换了个更快的引擎，实际上换的是模型的行为边界。

第二，量化粒度从"整模型"细化到"方案"。同一模型、同一比特数，FP8_DYNAMIC 与 FP8_BLOCK 在 GSM8K 上差 1.2 个百分点（vLLM llm-compressor 的 AWQ+FP8 结果，2026-11-20）；block 方案"理论上更好"却实测更差，说明量化误差不是单调的。

第三，评测开始从"准确率"转向"失败解剖"。τ²-bench 的多轮工具调用、CoT Token Inflation Ratio、tool-call cliff 的"准确率悬崖"——这些指标都在回答同一个问题：**这个量化版本在什么条件下会坏，坏成什么样**。

## 二、技术现状

**Flat score 的幻觉**：4-bit 权重量化被广泛报告为"几乎无损"，但那是在单轮问答与困惑度上。多轮工具调用里，错误会累积、会被后续轮次放大；平均分不变，尾部失败变多，而错误预算恰好把尾部吸收掉。

**Token 膨胀抵消加速**：EMNLP 2026 主会论文《Quantization Inflates Reasoning》（ACL Anthology 2026.emnlp-main.2059）发现，INT4/INT3 可以保住准确率，却让推理模型生成更长的思维链；在数学、代码、科学问答与 Agent 工具使用上，量化后的模型"答对了，但想得更久"。CoT Token Inflation Ratio 把这件事量化：每 token 更快，但 token 更多，端到端不一定更快。

**工具调用是独立轴**：HF 上 2026-09-17 的《The Tool-Call Cliff》指出，标准评测看不见"工具调用 vs 自由文本"这条轴；在固定 thinking-off 的条件下，低比特对结构化输出的侵蚀是单独一条曲线，并且在持久上下文下与"每轮冗长税"复合（Θ(T²)）。

**小模型先崩**：1.5B 的 4-bit 默认构建在工具任务上直接掉一半成功率；同一比特数在 7B 上可能只是轻微退化。量化的安全边际与模型容量强相关，"我们测过 7B 没问题"不能外推到 1.5B。

**方案与硬件同样影响结果**：OpenRouter 2026-11-10 的 fp8/fp4 对比里，Darkbloom 在 fp4 上 40 题只对 26 题，其他五个端点 30–33 题；作者自己标注样本太小、不能断定是精度效应——但这恰好说明，"同一个模型名 + 同一个精度标签"并不等于同一个行为。

**校准集是另一个盲区**：GPTQ/AWQ 这类训练后量化需要一个校准集来估计激活分布，校准集与线上分布不一致时，误差会集中在线上真正高频的那一段。仓库里的结果通常只报校准集同分布的评测；线上流量里长尾的工具参数、异常输入、多语言混写，恰恰是最容易掉出校准范围的部分。

## 三、技术竞争力

| 方案/厂商 | 量化方式 | 工具调用证据 | 推理 token 影响 | 主要盲区 |
|---|---|---|---|---|
| vLLM / llm-compressor | FP8_DYNAMIC/BLOCK、AWQ、GPTQ | 需自测 | 未内置 | 方案间差异需逐项评测 |
| TensorRT-LLM | FP8/FP4 内核 | 需自测 | 未内置 | 内核版本与精度绑定 |
| GPTQ / AWQ 生态 | 4-bit 权重 | 弱 | 未测 | 默认"几乎无损"话术 |
| NVFP4 / MXFP4 | 4-bit 浮点 | 弱 | 未测 | 新格式基准少 |
| Ollama 默认 Q4 | GGUF 4-bit | 弱 | 未测 | 端侧默认即 4-bit |
| OpenRouter 多端点 | 供应商各自精度 | 有对比但样本小 | 未测 | 同名不同行为 |

**判读**：这张表最空的列是"工具调用证据"和"推理 token 影响"。所有方案都能给出吞吐与显存，很少有方案能给出"这个量化版本在 25 个工具任务上的失败结构"。

**本期反转**：我们一直用量化换成本，用准确率做验收。实际上量化是**行为变更**：它保住了平均分，改掉了失败分布；它省下了每 token 的时间，可能花掉更多的 token；它在一个模型规模上安全，在另一个规模上直接崩。准确率是错误预算的平均值，而错误预算会掩盖损害。

## 四、技术挑战

**挑战一：验收指标错位。** 困惑度、单轮准确率、GSM8K 都不覆盖多轮工具调用；需要任务级、结构级、失败分类级的验收。

**挑战二：失败结构不可见。** 同一个分数下，"错得少但错得深"与"错得多但错得浅"对 SRE 的含义完全不同；需要按失败类型（格式/语义/安全/循环）分开记账。

**挑战三：token 膨胀的复利。** 低比特让每 token 更快，却让推理更长；在 Agent 循环里，这个膨胀会与重试、上下文增长复合。

**挑战四：同名不同物。** 同一个模型名在不同供应商、不同内核、不同量化方案下行为不同；"我们用的是同一个模型"不成立。

**挑战五：校准与线上分布错位。** 训练后量化的误差不是均匀的，它偏向校准集覆盖不到的区域；校准数据来自旧流量、英文、短上下文时，新流量里的长参数、多语言、长上下文会先坏，而回归测试仍可能通过。

## 五、需求分解、用户旅程与实现方案

**需求分解**：①量化方案登记（模型+比特+方案+内核+硬件）；②任务级验收（工具调用/多轮/长上下文/安全四组）；③失败结构对比（不是总分，是失败类型分布）；④token 膨胀核算（端到端而非每 token）；⑤回滚到全精度或更高比特的路径。

**用户旅程**：平台团队准备把 70B 从 FP16 切到 FP8 省 40% 显存 → 评测平台按四组跑同一批 500 条任务 → 总分持平，但工具调用组的"格式错误"从 2% 升到 7%、"循环"从 1% 升到 4% → 触发阻断 → 换 FP8_DYNAMIC 方案重测 → 失败结构回到基线 → 灰度 5% 流量，观察一周 → 全量。

**90 天实现方案**：0–30 天，建立量化方案登记表与四组验收集（各 200–500 条），把"比特数"写进模型卡；31–60 天，接入失败分类与 token 膨胀核算，任何量化变更必须附"失败结构 diff"；61–90 天，把量化纳入发布门禁，保留全精度回滚镜像，季度复测一次（防止上游静默换内核）。

**第 267 个市场空白（五项）**：量化方案登记；工具调用专项验收；失败结构 diff；token 膨胀核算；量化回滚路径。

**`quantization.*`／`precision_drift.*` 第 234 次无人提字段族**：所有平台都记录"用了什么精度"，没有一个字段记录"这个精度下失败结构变了多少"。
