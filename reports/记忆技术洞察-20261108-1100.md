# AgentMemory 技术洞察（第 29 期）：记忆的对账——账实分离与负值区

- 期次：2026-11-08 11:00（第 29 期 / 累计第 28 份报告）
- 覆盖范围：2026 年全年，重点为 2026-10-09 至 2026-11-08 的公开材料
- 主线：**记忆的"更新"全部发生在账内，而真正使记忆失效的力量在账外**

---

## 一、发展趋势

前二十八期把"更新"当作记忆治理的终点：覆盖、墓碑、双时态、失效归因，都在回答"同一键上出现两条值，留哪条"。本期指出这一整套机制的共同前提——**失效必定由一次写入宣告**。现实中大量失效没有任何写入：用户的航班改签、客户的套餐变更、API 下线、同事离职，事件发生在记忆系统视野之外。第 1 期提出的"记忆即账本而非数据库"在此显出它真正的缺口：**账本的核心动作是对账，而 28 期下来，没有一家做过对账**。

三条动向同时出现。论文侧的重心从"召回率"移到"失效判定"，且结论比预期严厉：过期记忆不是零收益，是**负收益**，甚至低于"什么都不记"。产品侧则把失效降级成读时排序（Mem0 4 月算法 ADD-only，"nothing is overwritten"）或写入期标记（Graphiti `invalid_at`），两者都只处理账内对冲。工程侧开始借用数据库的陈旧性原语——水位线、变更订阅、读时再验证、按可变性分级 TTL，但这些讨论至今停留在博客与社区 playbook，未进入任何记忆产品的 API。

一句话概括趋势：竞争轴从"记得住"转向"**敢不敢信**"，而"敢不敢信"需要一个当前尚不存在的动作——核验。

## 二、技术现状

### 2.1 六个指定项目的本周状态

**OpenViking** v0.5.3（11-02，98 个提交）带来 Rules（Beta）与其 `openviking_rule_search` 工具、SQLite 事务锁与 Redis 租约、ACL 空授权显式哨兵、查询驱动的 CacheFS 与 storage/vectordb 运维指标。41,337★、周增 448★，仍为 AGPL-3.0。其"内容层 L2 与索引分离"使库可重建，但重建只保证"结构一致"，不保证"事实仍为真"。

**TencentDB-Agent-Memory** 本周重点是 Memory Proxy 的接入面扩张：新增 Codex CLI、WorkBuddy 与 DeepSeek Harness 接入，并对 compaction / title-gen 这类辅助请求做短路，避免记忆注入污染摘要请求；导入历史会话"保留原始时间，时间线不再错乱"，另有对话记忆批量清空。时间保真做了，时间核验没做。

**Hy-Memory / MemHub** v1.0.6（底层 hy-memory 2.0.14）：lite / pro / ultra 三档，ultra 每晚自动整理；支持安全切换嵌入模型、写重试与模型服务异常时暂停队列、多用户 CLI/API、11 种语言界面。整理仍是夜间批量，作用域限于库内。

**ReMe** v0.4.2.2（11-05）：文档化日期区间召回、修正 frontmatter 读取、修复 float16 余弦零分。值得记一笔的是第三方校验站给出的状态：3,748★、验证等级 L3，标注"**安装规格过期**"——声明兼容 dsh 0.1.x，实际运行环境 0.2.2-rc.1 被安装门直接拒绝。**一个记忆工具的元数据比它管理的内容先过期**，这是本期主题的绝佳注脚。

**dsh-memory-evolve**（社区 chenzheshushi 变体 v0.4.2）：剪枝改成 preview→execute 两段式，预览时给每个目标记下 ETag，执行时若目标已被改动则该目标跳过而整单不失败；`forgottenAt` 墓碑软删可恢复；热度用 `accessedAt || createdAt` 而非 `updatedAt`。这是目前产品层面**最接近对账的原语**——它承认"我读到的版本可能已经变了"。

**AML 二期**：11-04 23:59 关闭正式评测，官方口径"11 月中旬"出榜，至 11-08 仍未发布。一期文本榜 MemoraX 58.02 / MemOS 45.89 / NTES 44.21，代码轨 62.00 / 52.00 ×3。三道赛道、两个榜单，仍无"失效"维度。

### 2.2 负值区：过期记忆比没有记忆更差

**STALE**（2605.06527）用 400 个专家校验场景、1,200 条查询、104 个日常属性、平均 15.2 万 token 上下文，把"隐式冲突"（后一次观察未显式否定前一条）拆成三个探针：状态识别 92%、前提抵抗 4%、策略适配 42%（最佳模型 55.2%）。**检测几乎满分，抗预设几乎为零**——模型看得出旧值已废，但只要用户提问里预设了旧状态，它照样顺着答。

**When Memory Lies**（2608.04574）给出更硬的数字：1,800 次检测 + 12,000 个导航回合，**信任原始记忆的 agent 死亡率是无记忆 agent 的两倍以上**；文本上能判过期的模型，在图像上 F1 从 0.887 掉到 0.067；即使给出 oracle 陈旧标签也不再有显著增益。载体一换，核验能力掉两个数量级（承接第 17 期"像素不是符号"）。

**TEPA**（2608.07429）做了一次干净的对照：完全反转场景、50 个随机种子下，append-only 0.210、LWW 0.210、**无记忆 0.309**、TEPA 0.950；换成真实文件执行漂移仍是 0.203 / 0.298 / 0.950。**行业最普及的两种写策略，都跑不过"什么都不记"**。它把失效提升为记忆的显式状态（revoked），并保留撤销档供审计——这是"撤销留档"第一次成为机制而非日志。

**The Trust Gap**（2609.01852，PayPal AI）则拆开了能力变量：Benefit 套件里各尺度模型用陈旧值作答的比例都是 0.92–1.00；Safety 套件里净伤害**随能力出现**，模型越大越容易崩，因为强模型能把错误前提执行得更像对的；"陈旧但日期更新"这一特征对大模型伤害更重，来源权威信号则弱且不随尺度变化；缓解手段也反转——元数据只救得动大模型，小模型必须先把冲突预解掉。**能力的诅咒**：换更强的模型不但救不了记忆，还会放大它的危害（与 Supersede 的"更强模型不救"互相印证）。

### 2.3 三种"伪对账"

产品侧存在三类看起来像对账、实际都不是的动作。**无账型**：Mem0 把覆盖删掉，失效变成读时排序决策，历史全留但无撤销标记，事后无法指认哪条被推翻。**账内失效型**：Graphiti 用 `invalid_at` 关闭旧边，可回答"6 月时是哪位"，但这个关闭动作只由**到达的**证据触发，世界自己变了它不知道。**幂等重跑型**：Agent-Memory-OS 的导入器给每条记录算内容哈希，重跑跳过未变、刷新已变，并保留来源系统与 source key。三类里只有第三类具备"重新向外部取一次"的语义——**冷启动用的导入器，无意中成了唯一的对账通道**（第 16 期"导入是第二次写入"的意外延伸）。

## 三、技术竞争力

| 方案 | 失效一等状态 | 源侧水位 | 读时核验 | 陈旧可见 | 撤销留档 | 对外对账 |
|---|---|---|---|---|---|---|
| Mem0（4 月算法） | 无（ADD-only） | 无 | 排序代偿 | 无 | 全留不标 | 无 |
| Zep / Graphiti | 有（invalid_at） | 事件级 | 无 | 有效期窗口 | 双时态 | 无 |
| TencentDB-Agent-Mem | 覆盖 / 清空 | 无 | 无 | 原始时间戳 | 版本链 | 无 |
| OpenViking v0.5.3 | 覆盖 / 重建 | 无 | 无 | L0/L1 滞后 | 源层可重建 | 无 |
| Hy-Memory 2.0.14 | 版本链 | 无 | 无 | 版本号 | 被撤回版 | 无 |
| ReMe 0.4.2.2 | 编辑 / 区间 | 文件 mtime | 无 | frontmatter | git 历史 | 弱 |
| dsh-memory-evolve | 软删墓碑 | ETag | 剪枝时校验 | forgottenAt | 可恢复 | 弱 |
| TEPA（论文） | revoked 档 | 键级 | 冲突键检查 | 撤销档 | 保留供审 | 无 |
| Agent-Memory-OS | 重跑导入 | 内容哈希 | 哈希比对 | 跳过/刷新 | provenance | 有 |

账内完备度最高可到五分之四（Graphiti、dsh-memory-evolve、TEPA），**对外对账一列几乎全空**。这构成本期的核心竞争判读：记忆产品的护城河不在"记得多准"，而在"是否承认自己可能过期，并给出成本可承受的核实路径"。承认过期需要三样东西同时到位——失效状态位、源侧水位、返回体的陈旧标注——目前没有一家三样齐全。倒挂第二次出现于同一议题（第 20 期查询治理、本期对账），累计第二十次：**最完整的对账实现出现在导入器、社区剪枝插件与论文里，不在记忆产品里**。

第二层竞争力变化是治理件效果与模型能力反相关：同一件元数据提示，对大模型是净收益，对小模型无效；同一份 oracle 标签，在文本模式有用，在视觉模式无用。**治理件不是普适资产，而是随部署档位失效的局部资产**，这直接否掉了"买治理能力"这类采购论证的普适性。

## 四、技术挑战

**其一，没有对手方。** 数据库对账成立是因为有一个权威库可对。记忆分三类：可对（文件哈希、API 版本、DB 行）、可问（偏好、计划——主体是人）、无对（推断、传闻、情绪）。消费级记忆大半落在后两类，对账成本约等于一次人工确认，这才是它缺席的真实原因——不是做不到，是算不过账。

**其二，可变性不可知。** 按可变性分级 TTL 是对的方向，但分级靠人猜；真实世界会突然改变（用户换工作），统一 TTL 同时造成"过度刷新稳定项、欠刷新易变项"。

**其三，嵌入即不可对账。** 向量把多维状态压成一团，无法定位到"套餐"那一维去单独刷新，只能整体重生成——与第 13 期"换嵌入模型是单向门"同源。

**其四，归因缺失使核验无法定点。** 没有字段级记忆身份证（第 3 期），就无法从一次错误回答反推到"是哪条记忆害的"，只能全库重核，成本爆炸。

**其五，评测无位。** AML 八维不含失效，`Δ_mem`（记忆相对无记忆的净变化）不作为指标。负值区不可见，就没有人投入（口径缺口第二十次）。

## 五、展望与建议

未来 12 个月可见三件事：返回体里出现 `as_of` 与 `may_be_stale`；失效类型字段化（写触发 / 时间触发 / 世界触发）；评测引入 A/B 双跑，把 `Δ_mem` 作为独立指标而非总分的一个维度。

给工程侧三条可执行建议：一是**当核验成本高于重取成本时，默认动作是"丢"而不是"修"**——删除是最廉价的核验；二是把可变性分级做成写时标注而非读时猜测，宁可粗；三是给"过期"一个一等状态位，而不是继续加置信度分数——置信度回答"我有多确定我记得"，不回答"这条现在还成立吗"。

给采购侧三条条款：可导出失效清单、可按源侧水位重核、可关闭夜间自动整理并索取 diff。

最后一个反向建议：不要指望换更强的模型来兜底。Trust Gap 与 Supersede 从两个方向证明，能力提升会放大而非消除这一类错误。**记忆的可信度只能由核验动作产生，不能由模型规模产生。**
