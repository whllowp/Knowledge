## 一、发展趋势

过去一个月，可观测性领域出现了一个此前从未被正面提出的品类：**遥测质量**。Juraci Paixão Kröhling（Jaeger 创始成员、OpenTelemetry 治理委员会成员）创办的 OllyGarden 于 10 月底宣布 400 万美元种子轮（Next Frontier Capital 领投），其种子前轮的投资方是 Datadog、Grafana Labs 与 Dash0。三家互相竞争的后端厂商同时押注一家"阻止坏遥测进入后端"的公司，这个资本结构本身就是判读：**后端已经卷不动了，瓶颈移到了数据生成的那一端。**

位移有三层。第一层是角色变了。同一次访谈里有一句话值得所有 SRE 抄下来：*"遥测已经悄悄变成你的 AI 所操作的数据。如果这些数据嘈杂、重复、缺少上下文，智能体会自信地去修错的问题。"* 这是 Agent 时代的新失效模式——不是拒绝执行，不是报错退出，而是**在错误的证据上高置信度地正确执行**。SRE 能力的上限因此不再由模型决定，而由插桩的可见度决定。

第二层是成本位置变了。传统降本手段是采样与丢弃，但那发生在管道里：数据已经生成、已序列化、已传输，钱已经花掉。OllyGarden 的判断很硬——*"在管道里采样只是治症状，你仍然要为生成、序列化和传输付费"*，正确的位置是代码。这意味着**降本的第一现场从"平台配置页"回到了"提交记录"**。

第三层是插桩的作者变了。编码智能体正在大量代写埋点，而模型会把一年前已废弃的语义约定当成本能复现。于是 OpenTelemetry 的使用知识被外置成智能体技能（Apache 2.0 开源、定期对照上游规范刷新），因为"不能依赖模型训练时记住的东西"。插桩从人的手艺，变成了需要供应链管理的知识资产。

中国侧的信号来自标准而非产品。11 月 2 日腾讯全球数字生态大会上，中国信通院发布《云上 Agent 基准度量模型》，从功能、安全、可靠、体验、性能效率、成本效益六个维度立标，并提出数据可信、流程贯通、权限可控、过程可审计、结果可评价五项要求，建议按辅助诊断、审批执行、限定自治三阶段落地；CloudQ、AndonQ、MigraQ、WorkBuddy 首批通过认证。"结果可评价"与"成本效益"两项，本质上是把**遥测从运维工具升格为验收证据**——评价一个智能体是否合格，要先能读出它做了什么、花了多少、对不对，而这三件事全部由遥测质量决定。

## 二、技术现状

### 1. 遥测四病灶：一次审计的四类固定发现

OllyGarden 对客户遥测做审计后给出的四类高频问题，几乎可以直接当检查表用：大量重复日志；占比较高但**不回答任何问题**的 trace 数据；从没有人查询过的 metric；以及最刺眼的一条——**六分之五的企业存在凭据或个人数据泄露进遥测**。前三类是浪费，第四类是事故。而四类的共同点是：写入时没人负责，读取时才发现。

### 2. 最小可行插桩（MVI）：把"加 span"当成一种预算支出

对应的工程纪律被命名为 Minimum Viable Instrumentation：只插服务的边界，在关键业务路径上加一到两个 span，然后停手。配套三条实践：每个变更走 PR 由人评审，让团队拥有决策权；智能体必须从问题出发（"这个服务会怎么坏，现有遥测能不能告诉我们"）而不是从缺口出发（"哪里还没有 span"）；**删除一个噪声信号与新增一个信号是同等有效的产出**。反面案例的说法很传神：给每个函数都加 span 不是帮忙，是**把问题从代码库搬到了账单上**。

### 3. 成本搬运的两端：写入侧止损，代码侧治本

国内厂商把工程重心放在写入侧。观测云 GuanceDB 3.1 的路线是"存算分离→查询加速"：以 Partition By/Cluster By 减少扫描范围、倒排索引先定位候选记录、流式聚合复用高频查询的计算、在 Pipeline 的写入阶段就把数据整理成可查询形态。这是把成本从"每次查询"搬到"一次写入"，对固定看板有效，对探索式查询更有效。

但它和 MVI 不是同一件事。写入侧优化降低的是**单位数据的持有与访问成本**，代码侧删除降低的是**数据总量**。前者让账单斜率变缓，后者让账单变矮。多数团队只做前者，于是每年优化、每年更贵——因为智能体还在源源不断地新增埋点。

### 4. 计量粒度下沉：从月结到步结

三件事在同一周发生。OpenAI Agents SDK 把用量写进追踪元数据（`model_usage_to_span_usage`、含 `cached_input_tokens` 的聚合计数），token 消耗第一次成为 span 的一等字段；腾讯云 AgentObs 兼容 OpenTelemetry，按会话、轮次、步骤还原推理/检索/工具调用并记录每步耗时与 token；火山方舟则把"输入 token×系数＋输出 token×系数÷10000"归一为统一燃料单位 AFP，连视频、图片、语音、数据集都折算进同一账本（文档更新于 11 月 2 日）。

方向一致：**计费单位正在从"账单科目"下沉到"执行步骤"**。好处是成本可以被归因到某一次工具调用；代价是成本变成了智能体每一步都要感知的约束，而这恰恰是第 27 期缓存面与第 33 期配额面都没有覆盖的第三本账。

### 5. 查询形态错配：平台为人的"窄而深"设计，agent 做的是"宽而浅"

人类值班查问题时看的是少数几个固定看板、少量高价值查询，平台据此优化缓存命中与预聚合。智能体相反：它从告警出发做探索式扫描，反复跨信号 join，每次 RCA 从零开始，几乎不复用上一次的查询计划。当平台按扫描量或数据点计费时，**agent 的排查风格天然比人贵一个量级**，而账单上只显示"查询费上涨"。Google Cloud 的做法是把这个决策显式外包给租户——请求/响应日志的采样率是可填的配置项（填 0.1 即记录 10%），并可选择落 BigQuery 或开启 OTel 日志。配置权交出去了，配错的责任也就交出去了。

判读分三层：**后端平台在搬运成本**（写入侧预处理、冷热分层、自适应聚合），**新品类在减少生成**（质量审计 + MVI + 删除建议），**标准社区在提供判据**。国内赢在"统一底座 + 统一计量单位"，把成本、轨迹、配额收敛到一本账；海外赢在"质量治理 + 插桩知识供给"，把埋点当成需要评审和版本管理的代码。差距最明显的一格是"信号退役"：九家里没有一家提供"这条 span 还有人读吗"的产品能力，而它恰恰是唯一能真正降低数据总量的动作。

## 四、技术挑战

**观测税的双重计征。** 同一份遥测被写一次（按摄入计费）、被 agent 读 N 次（按扫描计费）。人读得少，agent 读得多，于是可观测性账单第一次与"智能体的勤奋程度"正相关。

**故障期成本与故障规模正相关。** P0 期间 agent 反复宽扫、跨信号 join、上下文越滚越大，观测开销随火势上涨。最需要观测的时刻，恰好是预算最紧张、最容易被限流的时刻——这与第 33 期的"告警旁路额度"是同一类设计缺位，只是对象从模型配额换成了遥测查询。

**查询预算缺位。** RCA 模板普遍给时间预算（15 分钟、30 分钟），不给扫描预算（可扫多少 GB、多少 span、多少次工具调用）。没有上限，探索式排障的成本不可预测。

**遥测债没有 owner。** 写插桩的人在开发期，消费插桩的人在凌晨三点，计费的人在财务。三方都不对"这条 span 是否回答任何问题"负责。这比第 30 期的知识债更难治：文档至少有作者，代码至少有 CI。

**删除的证据悖论。** 要合法删除一个信号，得证明"没人读"；而"不读"这件事本身不产生任何记录。于是退役决策永远缺证据，只能靠猜——猜错的代价是下次故障时缺一条关键证据。可行的折中是长期保留读取日志并接受其成本，但读取日志本身又是遥测。

**污染债就是合规债。** 六分之五企业把凭据或个人信息写进遥测，意味着遥测库必须按敏感数据系统治理：分级、脱敏、保留期、访问审计。第 32 期讲的是轨迹三权，这里的问题是**插桩侧根本没有权限概念**——一行 `log.info(request.headers)` 就够了。

**质量向判据传导。** 第 35 期说"判据没变，判据的输入变了"（语义约定升级）；本期是同一失效的另一半：输入从来没对过。数据生来不回答任何问题，判据再准确也只是在噪声上做精确判断。

## 五、展望与建议

1. **把遥测效率做成 SLI。** 定义 TE＝被查询过的数据量÷采集的数据量，按服务统计、按季度评审。它比"成本下降 X%"更能说明问题，因为它同时约束产量与消费。
2. **把查询预算写进 RCA 模板。** 每次诊断给扫描上限与工具调用上限，超限需申请，并将超限次数作为"证据不足"的显式信号，而不是让 agent 无界翻找。
3. **信号退役三问。** 谁问过它、删了谁会瞎、怎么证明——以读取日志为依据，以"下一次演练能否复现"为验收，把删除纳入变更管理而非清理动作。
4. **插桩 PR 门禁。** 每个新增 span 必须回答"它对应哪一条 on-call 会问的问题"，答不出就打回；把 MVI 清单写进模板，让删除与新增同等计功。
5. **故障期遥测旁路。** 与第 33 期的告警旁路额度合流：P0 期间放开查询配额、锁定采样率，避免"最需要看见时被迫降采样"。

一个判断留作后续跟踪：**2027 年可观测性的采购问题会从"能存多少"变成"多少被读过"。** "看得见"正在变成免费能力，"值得看"才是收费项。当智能体成为遥测的主要消费者，衡量一套可观测体系的标尺，不再是它覆盖了多少信号，而是它能否让一个 agent 在三十秒内拿到足以做出正确决定的证据。
