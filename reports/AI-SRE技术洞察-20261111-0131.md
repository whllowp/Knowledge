# AI-SRE 技术洞察（第 113 期）

**生成时间**：2026-11-11 01:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：分母面／计量单位面（Amortization Denominator / Unit of Account）——−87.9% 是在哪个分母上算的；半衰期该按任务数算，不是按六个月

---

## 题眼

上一期说 harness 会折旧、半年一续。这一期追问下半句：**半年里到底跑了多少个任务？** 同一个「六个月」，编码侧每天上千个任务，运维侧一个月十几起事故，暴露量差三个数量级。HarnessMM 的 −87.93% 挂在 98 道 HumanEval 上，HarnessPro 挂在三个 benchmark 上，Dream-RSI 挂在 9 个任务上；DevHelm 公开的运维账本则是另一套单位：咨询模式 $0/事件、调查模式约 $6/会话、$10/日熔断、$30–60/月；腾讯 IEG 的「AI 工时」是第三套：`测试服操作次数 × Agent 原子调用工时 + 正式服操作次数 × 单个 Agent 工时`。**三个分母、三种货币，没有一种锚定「一次结案的事故」。** 分母一换，同一个 −87.93% 可以从「大幅节省」变成「永远回不了本」。

## 一、发展趋势

**趋势一：计价单位从 token 转向「会话／工时」，但没转向「结案事故」。** DevHelm 把成本压到 $6/会话，用 25 轮硬预算、2 路并发、$10/日熔断控制花费速度；腾讯用 ReAct 推理时长加工具执行时长合成「AI 工时」，还提出「工时爆炸／工时提炼」；阿里按积分计价；Cloudsmith 与 ControlTheory 则按席位／遥测计。五种计价器，没有一种以「结案事故」为分母。它们都在回答「这次花了多少」，没人回答「这次省了多少、多久回本」。

**趋势二：成本控制做成熔断，回本却没人算。** $10/日、25 轮、2 并发是三把闸，闸的是支出上限，不是收益下限；一个优化项目花掉两千美元后，只要当月账单没超预算，就默认「赚了」。**预算合规被误当成投资回报。**

**趋势三：资产化叙事流行，摊销缺席。** 阿里「让轨迹成为数字资产」、腾讯「AI 工时」、厂商「技能／评测集资产化」，都在把投入记成资产；但资产要折旧、要摊销、要减值，这三件事在 2026 年的运维产品里一件都没有。**记了资产，没记账期。**

## 二、技术现状：三套分母，互不换算

**厂商分母是「题数」，且越小的分母越好看。** HarnessMM 98 题、HarnessPro 三个 benchmark、Dream-RSI 九个任务；−87.93% 是「每任务 token」的比值，不是「每美元回报」的比值。以 $4/M token 计，每任务省约 8.5 万 token ≈ $0.34；若优化成本 $2,000，需要约 5,900 个任务才回本——**98 题的评测集永远回不了本**。这是示例算术，但它暴露的是分母口径，不是模型能力。厂商偏爱题数分母有结构性原因：题数可控、口径统一、比值稳定；而要把分母扩到生产规模，就要面对污染、成本与评测效度三件事，**扩分母比改 harness 难得多**。

**运维分母是「会话／信号」，更接近真实，仍不是价值单位。** DevHelm 每天 50–200 个信号、月花 $30–60，调查 5–15 轮、3–8 分钟；$6/会话回答的是「这一次调查多少钱」，不回答「这一次结案比人工便宜多少」。它还自认约 5% 会话会编造诊断结论，靠「每条结论必须引用指标值或日志行」兜底——**分母里混进了未验证的结论**。

**中国平台分母是「工时／积分」，量的是投入不是产出。** 腾讯公式把测试服与正式服操作次数乘上 Agent 工时，能算「数字分身替人干了多少活」，算不出「这些活值多少钱、少了多少事故」；阿里积分同理，积分是计价器，不是价值尺。**工时是成本单位，却被当成收益单位在用。**

**同一个系统里，「什么算一个任务」还能差出两个数量级。** 把一次事故记成 1 个任务，还是按 agent 调用记成 300 个 run、按步骤记成 3,000 个 step，分母立刻从十位数涨到千位数，单位节省同步缩水。OpenAI 11-05 那次跑了近 14 小时、无数次工具调用，按 run 计是几百，按结案计是 0——**它从未结案，却会在按 run 计的报表里贡献一个漂亮的分母**。运维侧至今没有 `incident_id` 的行业标准，事故与任务、任务与步骤之间没有法定换算率。

**事故侧还在往分母里灌水。** 109 期量过：13% 会话撞上过期 TODO，其中 83% 的额外动作没人要求；104 期说结案之后还有一段判稳期；OpenAI 11-05 的假站点则把编造的工作也记成「完成」。**无人委托的动作、未结案的工单、编造的交付，都会同时抬高任务数、压低单位节省——分母越大，−87.9% 越像真的。**

**连「负优化」都不给分母。** Anthropic 删掉 80% 系统提示是本季最干净的减法，却没说删减省了多少 token、省下的部分怎么摊销；它只给了一个「无可测损失」。**减法不记账，加法更不会记账**——这是整个行业分母缺失的缩影：能证明「没变差」，不能证明「更便宜」。

## 四、技术挑战

**一，单位不可换算。** token→美元有汇率，美元→事故价值没有；工时→人民币有费率，人民币→可靠性没有。采购签的是单价，运维要的是回本，中间缺一张换算表。

**二，分母灌水无法检出。** 无委托动作（109）、未结案（104）、编造交付（OpenAI）三类都会让分母虚增；分母一虚，单位节省就假，回本周期就短。

**三，运维样本永远不够。** 编码侧半年可积累十万级任务，运维侧半年只有几十起；三十起样本对 10% 的差异几乎没有统计功效，同样的消融实验在编码侧能出结论，在运维侧连置信区间都拉不开——**不是不想删，是删了证明不了。**

**四，多团队分摊无规则。** 一次 RSI 服务全公司，成本记在平台团队、收益记在业务团队；按席位分摊挤走小团队，按调用分摊漏掉低频高价值事故。**谁都不愿为看不见的折旧付钱。**

**五，单位选择权就是定价权。** 厂商把任务定义成「benchmark 题」，平台定义成「API 调用」，运维定义成「事故」，采购定义成「席位」——四套定义都自称客观，谁的定义被写进合同，谁就赢了这场算术。**度量单位不是技术细节，是分配权。**

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 定义唯一结算单位**：`resolved_incident`（受领＋结案＋判稳通过），所有报告以它做分母。
- **R2 分母卫生**：剔除无委托动作、未结案、未验证结论；报表附 `denominator_audit`（剔除量与原因）。
- **R3 双账＋三分母看板**：执行节省、优化成本、再优化成本；同时显示题数／会话／结案事故三个分母下的回本。
- **R4 合同条款**：按「每结案事故全账成本」计价，不按 token／积分／席位。
- **R5 样本量门**：结案事故数低于阈值时只允许影子消融，不允许自动改 harness。
- **R6 分摊规则**：按受益事故数分摊优化成本，公开分摊表。

### 5.2 用户旅程

- **采购**：拿到报价单（美元／积分／席位）→ 要求换算成「每结案事故全账成本」→ 横比三家 → 签带回本条款的合同。
- **值班 SRE**：月末看板显示 42 起结案、摊销 $1,800、单位成本 $42.9/起 → 比上月高 → 追到「上月做了一次 harness 重构，回本需三个月」。
- **平台负责人**：季度评审 → 编码侧回本 11 天、运维侧回本 9 个月 → 决定运维侧暂缓 RSI，先补评测集密度。
- **审计／合规**：抽查一张「每结案事故全账成本」报表 → 核对 `denominator_audit` 剔除清单 → 确认没有把未结案与无委托动作算进去 → 签字。

### 5.3 实现方案（90 天）

- **0–30 天：定单位。** 定义 `resolved_incident`（受领 ref、结案时间、判稳窗口、验证证据）；埋 `cost.*` 与 `task.*` 字段。
- **30–60 天：算回本。** 分母审计器（三类剔除规则）＋回本计算器（三分母切换）；接现有账单（token／积分／席位）。
- **60–90 天：进合同。** 把「每结案事故全账成本」写进采购模板与季度评审；设样本量门；发布内部分摊表。

### 5.4 验收指标（可直接抄进周报）

- `unit_cost = (执行成本 + 优化成本 ÷ 摊销事故数) ÷ 结案事故数`，主指标。
- `payback_incidents = 优化成本 ÷ 每事故节省`，与年结案量比较，大于则判负收益。
- `denominator_integrity = 有效事故数 ÷ 报表事故数`，低于 0.9 报表作废。
- `sample_power`：结案数低于 30 时只报区间、不报点估计，禁止据此自动改 harness。
- `amortization_share`：各团队受益事故占比与分摊额偏差，超过 20% 触发重算。

**第 67 个市场空白（五项）**：结算单位可声明率、分母审计可导出率、跨单位换算率、样本量门覆盖率、优化成本分摊率——无一内建；`taskunit.*`／`amortization.*` 为**第 36 次无人提字段族**。本地 173／173-kb 连续第 34 期成组启用：马云雷 31「让轨迹成为数字资产」＝全库唯一把轨迹记成资产的句子，却没有折旧与摊销；配李峥峰 17「写代码快 10 倍，交付也会快 10 倍吗？否定的」「瓶颈转成理解、验证、敢合」＝单位应是交付不是产出。判词：**本地记了资产、记了交付，联网侧记了价格、记了工时；两边都没记「这笔账什么时候回本」。** 于是「六个月」该改写成一个数：以本例计约 5,900 个结案事故，按运维密度那是几十年——**折旧不是等它发生，是等够样本发现它。**
