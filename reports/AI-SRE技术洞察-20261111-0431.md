# AI-SRE 技术洞察（第 118 期）

**生成时间**：2026-11-11 04:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：可退出面／接口可迁移面（Exit Readiness / Harness Portability）——换一个运行时，7.13 个点的差异盖过训练增益；你能导出数据，导不出行为

---

## 题眼

09-03 提交、10-09 修订的 arXiv 2609.04518 做了一个很朴素的对照：同一份 SFT 检查点、同一批回放数据，训两个 Qwen3-8B 变体，只在奖励归一化上不同（按 harness 内归一 vs 跨 harness 归一），然后在四个训练 harness 与一个**没见过的 harness** 上测 SWE-bench Verified。结果是三句话：多 harness RL 相对 SFT 只涨 **+0.48／+0.77 个点**；跨 harness 归一化在未见 harness 上没有稳定优势；而**不同执行接口之间的成绩差 7.13 个点，远大于训练带来的增益**。换句话说：**你辛苦训出来的那点提升，还不到换一个外壳造成的波动的一个零头。** 锁定不在模型，在接口。四训练 harness 用的是同一批任务、同一套评分，唯一变的是「模型看到什么、能调什么、失败怎么返回」——**行为参数全在接口里**。

## 一、发展趋势

**趋势一：多模型已是常态，锁定转移到外壳。** 2026 年多供应商策略的文章都在说「不要把鸡蛋放在一个模型里」，模型层确实可换；但换模型时真正决定成败的是 harness、评测集、技能包、回执与策略——TechTarget 今年的标题就是「AI 供应商锁定已越过模型」。**模型可换，行为不可换；模型是这轮锁定里最小的一把锁。**

**趋势二：可迁移性被误当成数据导出。** 欧盟合规讨论聚焦数据驻留与可携带，厂商也提供 trace／记忆导出；但 77 期已经量过「export≠migration」，本期再往前一步：**导出的数据在新运行时里能不能复现旧行为，没有任何一家给数**。合规能要求你带走数据，不能要求你带走判断。

**趋势三：迁移演练开始出现在工程实践里，但不在产品里。** 社区出现「model and harness swap 专用评测套件」「runtime parity」这类模式文档，说明一线已经意识到要成对跑；产品侧仍只有「导入向导」，没有「行为等价报告」。**演练成本其实很低——一个 agent、五十道题、两周；不做的人没有数字，做了的人拿到议价权。**

## 二、技术现状：四类迁移物，没有一类有标准出口

**行为等价没有度量，只有声明。** 2609.04518 给的是目前最干净的一组数：训练增益 0.48–0.77pp，接口差异 7.13pp，且未见 harness 上训练没有显著迁移。15 期 Coinbase 换模型后金额加权召回率 −21.8pp、105 期同快照重放 24/24 一致却与真实续跑在 9/24 分叉，都在说同一件事：**「同一个模型」不等于「同一个行为」。**

**四类迁移物各自为政。** 轨迹（数据格式各家不同）、评测集（题目与标签住在谁的账户里）、技能（SKILL.md＋hooks＋运行时依赖）、回执与计量（114 期的 `meter_receipt` 没有跨平台格式）。Cloudsmith 11-09 把 skill 做成可钉版、可禁、可审计的包，是四类里最接近「可迁移」的一类；但它管的是供应链，不是行为等价。

**厂商侧的「可迁移」都停在导入。** Google Agent Substrate 的快照能在任意 Worker 恢复，却不出 Google；Anthropic 删 80% 系统提示让外壳变薄、迁移成本下降，但没有迁移报告；HarnessMM 同时支持 Codex 与 DeepSeek Harness，是少见的跨运行时实现，仍只报 token 与成功率，不报「换壳后同一任务的行为差」。

**协议层只统一了「说什么」，没统一「怎么默认」。** MCP 统一工具描述与调用，A2A 统一消息与交接；但超时、重试、审批、错误映射这些真正决定行为的默认值，仍在各家运行时里。**协议让工具可插拔，没让行为可迁移。**

**学术侧已经把「训练增益 vs 接口差异」摆在同一张表上。** 这是本期最硬的方法论：**任何「我们提升了 X 点」的声明，都必须同时报「换一个接口会差多少点」**；否则你不知道自己买的是能力，还是接口。

**接口差为什么这么大：它改的是行为参数。** 工具 schema 的宽窄、上下文注入的顺序、重试与超时的默认、错误如何映射成模型看得懂的话、审批闸门在不在——115 期的返回语义、110 期的护栏存量、108 期的规则位阶，全都长在接口里。**换壳不是换皮肤，是换一套行为规则。**

**最贵的锁定是评测集。** 15 期引过一句：「评测套件不应住在它要审判的公司的账户里。」评测集编码的是你这一行的故障分布；没有它，新运行时「能跑」也无法「可验」。迁移顺序因此是反直觉的：**先迁评测集，再迁 agent**——否则你连比对的能力都没有。

**一份合格的迁移报告该长什么样：** 同一批任务在源／目标运行时各跑一遍，报逐题 delta、失败类型迁移矩阵、技能可运行率、回执连续率、成本比，并声明两次运行的时间窗与模型指纹。现在没有一家产品出这份报告，**它只能由买方自己造**。

## 四、技术挑战

**一，行为等价不可声明。** 没有跨运行时的成对评测，就没有迁移前后可比的行为差；厂商只报「导入成功」，不报「行为一致」。

**二，接口差异大于训练增益。** 7.13pp vs 0.48–0.77pp 意味着：选型时纠结模型，可能不如纠结 harness；而 harness 的选择又最难迁移。

**三，四类迁移物没有统一格式。** 轨迹、评测、技能、回执各自为政，任何一类缺失都会让新运行时「能跑但不可验」。

**四，退出成本无法预算。** 没有演练就没有 T 天、多少人力、多少行为损失的数字；采购只能拍脑袋，锁定因此自我实现。

**五，双运行时本身有成本。** 常年跑两套运行时意味着两套技能、两套回执、两套告警路由，漂移会在两边同时发生；**降低锁定风险的方案，自己会制造新的运维面。**

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `portability.*` 清单**：五类迁移物（轨迹／评测集／技能／策略／回执）各带格式、版本、属主、导出方式。
- **R2 行为等价门**：同一批任务在源与目标运行时成对跑，报逐题 delta 与分布，不只报均值。
- **R3 迁移演练**：季度一次，选一个 agent 迁到第二运行时，限 T 天，验收＝行为差 ≤2pp、技能 100% 可跑、回执连续、成本 ≤1.2 倍。
- **R4 双运行时常态**：5% 影子流量常年跑在第二运行时，早发现锁定与漂移。
- **R5 合同条款**：导出格式、90 天迁移协助、删除证明、行为等价报告义务。
- **R6 报表**：`portability_score` 进季度评审，与 116 的 `record_fidelity` 并列。
- **R7 迁移期双回执**：迁移窗口内新旧运行时同时产出回执，按 `task_id` 对齐，缺一侧即视为迁移未完成。

### 5.2 用户旅程

- **平台负责人**：决定换 harness → 打开可迁移清单 → 发现评测集在供应商账户 → 先迁评测集，再迁 agent。
- **SRE**：迁移后第一周 → 双运行时对比同一批事故 → 行为差 1.4pp、技能 100% 可跑 → 逐步切流。
- **采购**：签约前要求「迁移演练条款」→ 供应商拒绝 → 改签带退出条款的第二家。
- **审计**：查退出演练记录 → 核对逐题 delta 与回执连续性 → 签字。
- **供应商**：客户要求迁移演练 → 主动出行为等价报告 → 用「可退出」当差异化卖点，而不是把导出藏进工单。

### 5.3 实现方案（90 天）

- **0–30 天：盘物。** 列五类迁移物清单；把评测集与技能包移出供应商账户；统一导出格式。
- **30–60 天：对跑。** 建跨运行时成对评测台；先跑 50 题小样本，报逐题 delta 与失败类型。
- **60–90 天：演练。** 完成一次真实迁移演练；把行为差、成本差、耗时写进季度评审与合同模板。
- **90 天后：评分。** 把「迁移演练通过率 × 行为差」纳入供应商季度评分；连续两次不达标的运行时降级为备选。

**第 72 个市场空白（五项）**：迁移物清单可导出率、跨运行时行为差可报率、技能可迁移率、回执连续性、退出演练覆盖率——无一内建；`portability.*`／`exit.*` 为**第 41 次无人提字段族**。本地 173／173-kb 连续第 38 期成组启用：朱革 15「Agent、Skill、Prompt、工具和知识缺少统一版本边界」＝全库唯一把「搬不走」写成版本问题的句子，本期首次当主线；配刘宗明 06 SIS（Skill Interface Standard）＝本地版可迁移接口、马云雷 31「离线通过≠长期稳定（工具契约／环境快照／漂移监控）」。判词：**本地把迁移写成版本边界，联网侧 9 月才量出「接口差 7.13 点盖过训练增益」；两边都没把「换壳后的行为差」做成可签字的数。**
