# 记忆技术洞察 · 第 99 期（20261116-1700）

**主题：记忆的「信道性」——共享状态即通信，无人宣告的协作**

> 洞察范围：2026 年（近 30 天为主）。四维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

前 98 期把共享记忆当"存储问题"（#67 投毒半径、#75 并发写、#62/#86 内部分工），默认 agent 只有被告知彼此存在才会协作。2026-11 两篇工作换了视角：共享记忆本身就是信道。2611.12412（11-09，双实现锁定复现）让四个 agent 各领算术题、共用一个被描述为"自己的草稿"的 KV 存储，提示词从不提及其他 agent；持互补半题的两方仍靠读写共享 store 交换中间值、双双答对。评价轴从"存得对不对"扩到"在 agent 之间传了什么"——共享即通信。

## 二、技术现状

该研究最硬的证据是反事实：1,214 个未发生跨 agent 读取的 world，联合成功为 0；把 store 改成私有 namespace（写入行为不变），gpt-6-astra 从 49/50 跌到 0/50——共享性单独贡献 +98 点。反直觉的是，是否协作不按模型档位排序：低档 gpt-5-nano 达 45/49，Pro 档 gemini-3.1-pro 为 0/50；机制只取决于"写中间结果＋写后再看一次"。而一句普通指令"提交前再看一眼工作区"，把 gpt-6-astra 的跨读从 50/50 拉到 1/50。另一侧，MemLeak（2610.04195，NeurIPS-PALM 2026）量化同一共享向量库的暗面：同队池化检索下非恶意跨用户泄漏 70–100%，对抗构造 top-k 命中 90–100%，下游回答污染 5/5；唯一有效缓解是检索后硬所有权闸门（回落 1/5，约 1.4ms/查询）。但它同时给出负面结果——共享嵌入不支持可靠顺序隐蔽传输，故这是"漏但不可控"，而非成功暗信道。

## 三、技术竞争力

竞争焦点从"谁的库更大、召回更高"转向"谁把共享状态当信道治理"。五项目（OpenViking v0.5.5、Hy-Memory v1.0.6＋MemHub、TencentDB v2.0.3、dsh v26092802、ReMe v0.4.2.2）都把共享当存储＋访问控制：OpenViking 有多租户 ACL 但默认 opt-in，TencentDB 有团队 ACL；均无 KV 级作者标记、无"跨 agent 读取"可观测、无所有权硬闸。研究侧已证明"一句话即开关、无标记则把碰撞当协作"，产品侧信道语义仍是空白，倒挂延续。

## 四、技术挑战

①无作者标记就无法区分"读同伴的值"与"读自己被覆盖的旧 key"：gpt-5-nano 用严格口径从 17/50 降到 2/50，信度先失守（接 #95/#94）；②协作率对提示词脆弱，一次措辞改动抹掉 98 点，系统性质却被当作模型能力；③共用缓存/草稿/记忆库默认就是 tuple space，归属须显式声明；④"漏但不可控"意味着既堵不住泄漏、也不能借此可靠协同；⑤解析规则、endpoint、key 命名等实现细节本身就能翻转结论，跨实现可比性待立契约。

## 五、需求分析

共享缓存、记忆服务与草稿目录在多 agent 部署中已成默认基础设施；用户与运维要的不是"更聪明的协作提示"，而是能回答三件事：谁写的、谁读了、这次成功是真交换还是 key 撞名。安全侧还须保证池化检索下的跨用户隔离不靠"语义距离"这类弱代理。

## 六、用户旅程

多 agent 接到互补子任务 → 各自把中间结果写入"工作空间"（KV store／记忆库）→ 其中一方受提示或习惯再看一次 → 读到同伴条目 → 双方提交正确答案；若无共享存储或改为私有 namespace，协作即消失。观测者需沿"写入—暴露—跨读—提交"四步还原链路，并剔除自写回读。

## 七、具体实现方案

给共享 store 每项加三字段：author_agent_id、namespace、timestamp，写入即登记；读取分"自写回读"与"跨 agent 首读"两类计数，只有后者计入协作；把"再看一眼"从提示词提升为显式、可审计的配置项；检索返回后加硬所有权闸门（ownership gate）再入上下文，实测约 1.4ms/查询可接受；存储层按 agent 隔离为默认、共享须显式 namespace；评测同时报 joint success、cross-agent read rate、collision-disambiguated read rate 三指标。

## 八、本期新观点

1. **共享状态即信道**：把记忆从"存储/检索"二维扩出"传输"第三维，协作可在无人宣告时涌现（stigmergy）。
2. **信道有效性不按模型档位排序**：取决于"写中间值＋回看"两动作，是配置/习惯而非能力，故可工程化。
3. **"再看一眼"一句话是系统级开关**：暴露协作率对措辞的脆弱性，须显式门控而非提示词偶然。
4. **无作者标记则协作与 key 碰撞不可分**：信度先于效度失守，接 #95 可识别性、#94 评判者偏差。
5. **泄漏是信道暗面但"漏而不可控"**：AML 应补 channel-semantics 维度（作者标记覆盖率／跨 agent 读率／碰撞消歧率／所有权闸门通过率），接 #56/#69。
