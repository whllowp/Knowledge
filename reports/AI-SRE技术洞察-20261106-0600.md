# AI-SRE 技术洞察 · 第 82 期（2026-11-06 06:00）

## 缺省面（未表态配置面）运维——没有变更事件的那一半配置

> 本期主线（第七十三条）：前 81 期把记忆、身份、计量、编制、写序、弃权逐个变成一等运维对象；本期换个角度，问**在没有任何人表态的地方，系统替你做了什么决定**。默认值是唯一不产生变更事件、不进审计链、不进 span、却每次事故都决定行为边界的"配置"。与 54 配置面（管"改了配置"）、45 发起面（该来没来）、78 到期面（负事件）、80 同时面（未记的副作用）、81 弃权面（未执行的动作）逐条划界：负事件家族在配置层的对应物，是**未发生的配置决策**。视角从 79 组织层、80 执行层、81 验收层，落到三者共用、从未被纳入资产的那半张配置表。

## 一、发展趋势：默认值从"文档角落"移到了事故主因

最近 30 天，默认值第一次以成批事故和成批版本变更的形态同时出现。

**10 月 20 日 NVD 同日公布 5 个 CVSS 9.8–9.9 的 CVE**（Letta／Langchain-Chatchat／DB-GPT／Piflow），根因同源：`compose.yaml` 默认不启用 `LETTA_SERVER_SECURE`、默认写死 `MYSQL_ROOT_PASSWORD` 并把 3306 暴露到所有网卡、`get_user_from_headers` 是给每个调用者返回 admin 的 mock、shell 工具恒定注册——**不是代码写错，是"笔记本一键启动"的默认值被搬上了公网端口**。更贴题的是 OpenSRE：`execution_allowed()` 恒返回 `True`，审批函数的默认返回值就是"允许执行"。10 月 7–8 日 PraisonAI 公告里，`CodeConfig(sandbox=True)` 从未真正沙箱化（CVE-2026-61447，CVSS 10.0），MCP HTTP-stream 仅在配了密钥时才鉴权，CLI 默认无密钥约 50 个工具裸奔。

**同一窗口，主流平台在悄悄翻转默认值而不发变更单。** Anthropic 10 月 16 日 Claude Code 2.1.302 把第三方供应商／遥测关闭／全新安装且未指定 `permissionMode` 的 `claude -p` 与 Agent SDK 起始模式从 `auto` 改回 `default`，fork subagent 在四处宿主默认全开；用户代码零改动，无人值守任务从"模型评估放行"变成"无人应答即拒绝"。当天通用权限文档仍写着旧默认值，只有带版本号的 release note 是对的，`permission_denials` 才是权威记录。10 月 27 日研究者复测 2.1.312：默认遥测把读过的文件做无盐 SHA-256 指纹连同设备／会话 ID 发回，即便指向第三方模型、无 Anthropic 账号——`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` 可关，但"默认开"从未被当作一次配置决策交付。

**能力侧默认方向同样分岔。** Google 10 月 30 日把推理元数据日志推到 GA，但只记元数据、永不记 prompt/响应，且需控制台或 REST 显式开启；中文站专门澄清"GA≠默认打开"，Data Access 日志亦默认关。阿里云 10 月 28 日更新的 CMS 2.0 文档是国内最直白的一手口径：正文默认不采集，DSH 原生 `session-telemetry-otel` 插件**默认 DISABLED**，须手改 `cordis.patch.yml` 才能外发，`FULL` 模式才带出正文。火山引擎 11 月 3 日 AgentKit 新增执行超时配置，而其「使用限制」页写着同步请求超时 30 分钟、**是否支持调整＝否**——新可配参数与硬编码默认值并存，且默认值不在产品页而在限制页；11-04 方舟公告另有"默认配置下的 GRPO"约束。

**治理侧开始收口，却仍未点名"默认值"。** 10 月 16 日信通院依 AIIA/T 0293-2026 六维（含"权限边界与关键参数配置"）发出首个 Claw 类风险管理证书；T/ISC 0123-2026 于 8 月 20 日实施、11 月进入首批评估；ISACA 2026 白皮书给出 15 项默认安全清单（默认拒出站、最小权限、缺失必需配置拒绝启动）。清单检查"有没有这项控制"，不问"上个版本的默认值是什么"。

## 二、技术现状：四个方向互相矛盾，四个结构缺口无人补

**同一件事（内容采集），四家方向相反**：OTel GenAI 把 instructions/input/output/tool 参数全定为 Opt-In（10 月核对仍全 Development、无 tagged release）；OpenAI Agents SDK 是 tracing 默认开、`trace_include_sensitive_data` 默认 True、默认导出到厂商后端，ZDR 组织反而直接不可用；Google 与阿里是"能力在、默认关、需显式开"；Anthropic 是"遥测默认开、opt-out 才停"。**权限默认也分两派**：MCP 2026-07-28 把四个 hint 全按最坏假设（readOnly=false、destructive=true、idempotent=false、openWorld=true，官方博客原话"spec assumes the worst until told otherwise"），开源框架却默认 root、无认证、全网卡。80 期用 MCP 论证"两层一个布尔没有契约"，本期换角度：**协议层是唯一把默认方向写清楚的一层，其余各层连方向都不一致**。四种方向并存于一条调用链，没有一层能回答"此刻生效的是哪一个"。

由此暴露四个结构性缺口：

**其一，默认值是版本的一部分，不是配置的一部分。** 升级即静默改行为且没有 diff：Claude Code 的一行 "Changed ... default"、Google release notes 的一行 "Change" 就是全部变更记录；AWS 收窄 Bedrock AgentCore 默认执行角色（10-08 Zenity 披露，定性有争议）亦无通知。文档与版本化 release note 还会短暂不一致——**"查文档"这个动作本身不再可靠**。

**其二，默认值有作用域，却没有作用域标记。** 同一 flag 在终端、`claude -p`、SDK、桌面、VS Code 的默认值不同；MCP 的默认值由 server 自报且规范明确要求客户端 MUST 视为不可信；`sandbox=True` 实际不生效。方法论上须区分：配置检查验证的是**意图**，行为测试验证的才是**效果**。

**其三，默认值不产生变更事件。** 54 期管"改了配置"，78 期指出 RCA"找最近变更"对负事件结构性失明；默认值两头都不占——没人改过，也不在变更流里。配置漂移检测普遍比对"声明值↔运行值"，却没人比对"上一版默认值↔本版默认值"。

**其四，默认值既不进遥测也不进账本。** span 记录执行，不记录"这次用的是哪个默认值、来自 release note 还是策略"；81 期说 span 不记录未执行，这里要补一句：**也不记录生效的默认**。复盘因此无法回答"当时那个开关是开是关"。成本侧同理：元数据日志计费、fork 默认全开、客户端 auto 分类器 token，都记在"没选过"的账上。

## 三、技术竞争力：主要厂商／方案对比

| 方案（时点） | 默认方向（采集／权限） | 默认值可否机器查询 | 默认值变更是否进变更记录 | 显式声明／缺省拒绝门禁 | 生效值是否入 span／审计 | 作用域是否分宿主标注 |
|---|---|---|---|---|---|---|
| Google Gemini Enterprise（10-30） | 元数据日志需显式开；内容永不入日志 | `observabilityConfig` REST 可查 | release notes 有 Change 行，无默认值 diff | Computer use HITL 可强制组织级策略 | 仅记元数据，不记当时开关 | us/eu/global 区域，非宿主 |
| Anthropic Claude Code 2.1.302（10-16） | headless 默认 manual；fork 默认全开；遥测默认开 | 初始化回 `claude_code_version`＋`permissionMode` | GitHub release tag 一行 Changed | 无，须自行传 `--permission-mode` | `permission_denials` 记拒绝，不记默认来源 | 终端／`claude -p`／SDK／桌面／VS Code 各异 |
| OpenAI Agents SDK | tracing 默认开、敏感数据默认 True、默认导出厂商 | env／`RunConfig` 可读 | 版本间默认变化无专门 diff | 无；ZDR 组织直接不可用 | span 记内容，不记"为何记" | 单一 SDK |
| OTel GenAI 语义约定（规范层） | 内容全 Opt-In（最悲观） | 注册表 requirement level 可查 | 全 Development、无 tagged release | Opt-In 即"不显式开就不采" | 未定义 `config.*` 字段族 | 按文档，不按宿主 |
| MCP 2026-07-28 | 四 hint 全按最坏假设 | `tools/list` 返回 annotations | 修订版固定，无运行时 diff | 客户端 MUST 视为不可信 | 不记录 | server 自报，无宿主维度 |
| 阿里云 CMS 2.0＋LoongSuite（10-28） | 正文默认不采集；DSH 插件默认 DISABLED | 须手改 `cordis.patch.yml` | 文档更新，非变更事件 | `FULL` 才带正文（显式） | 导出失败被隔离，不记默认来源 | 按 Profile／Pilot 注入 |
| 火山引擎 AgentKit（11-03） | 同步超时硬编码 30 分钟不可调＋新增可配超时 | 藏在「使用限制」页 | 新功能记录只记"新增能力" | 无 | 未公开 | 按 Region 灰度 |
| 腾讯云 CloudQ（10-29/30） | Skill 需 `requires_api_key=true`；`--dir` 缺省可能不被加载 | SKILL.md／SkillHub 元数据 | 未见机器可读默认清单 | 需人工配 Key 并重启 | 全景图谱记资源状态，不记配置来源 | Skill／IDE／控制台多宿主 |
| 开源自托管框架（10-20 CVE 群） | compose 无认证、静态口令、shell 恒注册、0.0.0.0 | 须读 compose／镜像 | 无 | 无 | 无 | 无 |
| 正面参照：OpenClaw Operator／Testkube 11 月 | 默认拒 NetworkPolicy、非 root；新会话默认私有 | CRD／管理页 | configuration-hash rollout 使配置变更产生受控滚动 | 缺失必填安全配置拒启动 | 配置哈希进 rollout | 按 Pod／组织 |

**判读**：云厂商把默认值做成"能力在、默认关、显式开"，最稳却把责任留给用户；模型厂商做成版本行为（Anthropic）或默认外发（OpenAI SDK），可达性优先；规范层方向最清楚却没有运行时；国内平台派可控性最好，但默认语义散落在「使用限制」「参数说明」「帮助中心」页，没有统一清单；开源自托管派是反例——**自托管本该更安全，恰恰因默认值面向笔记本而更脆**。最接近的是两个小体量实践：OpenClaw Operator 配置哈希滚动、Testkube「新会话默认私有」。分野不在诊断分数，而在三问：默认值能否被机器读出、变更能否被当成变更、缺省能否拒绝启动。79 期"编制制度没上线"、80 期"写序制度没上线"、81 期"不写的制度没上线"，推到配置层即：**"没选过的那个值"也还没上线**。

## 四、技术挑战：第三十六个市场空白

**默认值台账／版本默认值 diff／默认-生效偏差／隐式决策率四项，无一厂商内建**；对比表"默认值变更是否进变更记录""生效值是否入 span"两列几乎全空。OTel GenAI 至今没有 `config.effective.*`／`config.source.*` 字段族（接 72／79／80／81 期字段族提案），"当时开关是开是关"只能靠人回忆。默认值没有 owner：安全团队认为是研发默认、研发认为是平台默认、平台认为是供应商默认；10-20 五个 CVE 的共同措辞正是"没人重新检查默认值就发布了端口"。演练目录也无"默认值翻转"题型（`auto→default`／`DISABLED→FULL`／`0.0.0.0→127.0.0.1`），无一家常规化。

**反差最大的是本地 173 库**：工程实践派早于平台产品化就把默认值当一等对象。陶炳哲（智能路由）给出完整生命周期——"默认项可解释、可修改、可关闭""显式选择优先于自动推荐""决策留痕：候选曝光＋选择＋结果""默认不留敏感原文，支持删除和退出"；何伟把 `Config` 列为独立架构层，写"开关、默认值、组件注册表""统一开关、默认值与回退"，并把"配置组合、缺失值、默认值与回退""开关前后行为"列为**专项组合检查**；余锦泽标注"默认阈值 60% 取自 4 库合并数据的阈值扫描，60% 附近 F1 最高，跨行业需复核""已实现，默认关闭"——默认值有出处、有适用范围、要复核；李东东一句最锋利："'端侧优先'是方向与原则，云端仍是当前默认路径"，即**宣称方向与默认路径可以分离**。连续第三期同一判词：最接近正确答案的仍是本地工程实践派，但都是项目内约定，不是可采购的平台能力。

## 五、展望与建议

1. **默认值台账最小 schema**：`default_key / declared_value / effective_value / scope(host+sdk_version) / source(release_note|docs|env|policy) / since_version / last_diff / owner / expiry`，随升级自动重算入库。
2. **显式优先上线门禁**：无人值守任务必须显式声明 `permission_mode`、内容采集档、监听地址；缺失即拒绝启动，把"缺省"从便利变成失败。
3. **版本默认值 diff 进发布流程**：升级前抓取 release notes 中所有 "Changed ... default"／"默认配置下" 行作为变更单进 CAB；预发跑"一允许一拒绝"有界任务、核对 `permission_denials` 与端口可达性——**验证生效行为，不验证配置文件**。
4. **生效值打点**：根 span 记 `config.effective.*`＋`config.source.*`＋`config.since_version`，向 OTel GenAI 提 `config.*` 字段族提案，补上"span 也不记录生效的默认"。
5. **采购与合规条款**：供应商默认值变更视为变更事件、需提前通知；要求机器可读默认值清单与逐版本 diff；信通院 AIIA/T 0293-2026「关键参数配置」维度可增列"可查询／可追溯／可拒绝启动"三项。
6. **演练与成本**：把默认值翻转注入纳入混沌目录（接 56 期），为"默认开的能力"单列成本科目（接 58／79 期），季度核对两个 SLI。

**结论**：能力上线了，制度没跟上的清单又多一行——不是缺一个开关，是缺一张记录"谁在没人表态时替你表了态"的账。
