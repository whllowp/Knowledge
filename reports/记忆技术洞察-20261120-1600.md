# 记忆技术洞察 · 第 131 期（20261120-1600）

**主题：记忆的「剂量适配」（memory dosing）——同一套自蒸馏指南，强模型越加越好，弱模型加满反被淹没。前 130 期问"存什么／取哪条／读多少／看多清／证据能否回来"，默认记忆是越多越好的资产；11-19 提交的 How Much Should an Agent Remember?（arXiv 2611.26361，IBM Research 九人，cs.AI，IAAI 2027 Oral）用部署日志反过来证明：合适的记忆量是模型的属性，不是记忆的属性。与 #122 划界（那问一条读多少，本期问一个模型该带多少条）、与 #96 划界（那算成本兑换率，本期算剂量—响应曲线）、与 #128 划界（那问谁在记，本期问记了以后给谁、给多少）。**

> 洞察范围：2026 年（近 30 天为主）。四维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

记忆研究从"能不能涨点"移向"上线后怎么不翻车"：剂量升为一等参数，须逐模型实测，不能沿用别家配置。压缩神话退潮——读起来漂亮的精简清单恰丢掉最值钱的长尾经验。altk-evolve 已进入 IBM CUGA 与 watsonx Orchestrate，度量从榜单分数变成增量、token 与噪声地板。

## 二、技术现状

三段流水线：自轨迹每条抽 1—3 条祈使式教训，成败取评测器而非模型自报；按源任务嵌入聚类、簇内合并成指南，每条记支持数与证据极性；硬约束是合并前后支持数守恒，未覆盖者原样透传。DeepSeek 147 条轨迹得 290 条教训（失败 62、成功 228），合并为 191 条指南，其中 144 条支持数为 1。注入可全量，也可支持数≥3 的 47 条核心常驻加按源任务相似度逐题检索；阈值只在投递时生效，不删库。

## 三、技术竞争力

AppWorld test_normal 分三种曲线。强模型单调：DeepSeek 注入 0/12/19/47/191 条，任务完成 79.8→82.7→83.9→85.7→89.3，场景完成 64.3→80.4；GPT-5.5 从 92.3 涨到 95.2。弱模型倒 U：gpt-oss-120b 基线 39.9，全量 199 条仅 51.2，约 29 条精选达 55.4（56.0/54.8），token 116K 近基线 110K。压缩版 12 条仅 +2.9，全量 +9.5，差额正是 144 条一次性经验。两端亦有饱和（GLM-5 有无 72 条均 87.5）与失能（Gemma-4-31B 近无效、紧核心反伤）。产品侧 GLM-5.3-Flash 全量 TGC 87.8→93.2、SGC 84.8→88.4，token +36%；watsonx 一例跨任务迁移"先转格式再提交"，重复提交两次变一次。

## 四、技术挑战

①支持数是被反复推导的次数，不是正确性：高支持分页规则假定页长 20，而 API 默认 5，首屏 5 条即误判末页；人工改写后硬任务完成 66.7→73.0。②合并两次静默丢溯源：固定字段列表漏支持数，重复索引又重复计数。③未建噪声地板：同配置两次 56.0/54.8，168 题约 32 题翻转，受益与受损任务检索余弦 0.463 对 0.468 无法区分，五题内差按噪声。④脚手架混淆：ACE 无记忆基线低 7.8 分，表面领先实为脚手架；固定后增益相当，差别在 token（263K 对 634K、弱模型 116K 对 777K）。⑤上线事故：HTTP 400 被吞、合并输出截断、写路径未触发致库空转，均无可见报错。

## 五、需求分析

用户遭遇周期性程序失误：分页错、实体认错、没问就答。他要的不是"记住所有教训"，而是三条承诺：同一模型该给多少条才不拖累；每条指南的来路与支持数不丢；空写与吞异常能立刻看见。选型人还要把"我比对手强"拆成记忆贡献与脚手架贡献。

## 六、用户旅程

训练/开发轨迹抽教训、评测器标成败，无损合并为带支持数的指南库；部署前为该模型扫剂量曲线：强模型全量、弱模型核心加检索、饱和模型不注入。任务后核对支持数与来源守恒；某条高支持规则致回退则人工改写留痕，并补正确性或时效信号。评测固定脚手架、重复跑建噪声地板，报表并列任务完成、场景完成与每任务 token。

## 七、具体实现方案

①抽取：成败只认评测器，轨迹可插桩、可观测库同步或 MCP 交付。②合并：支持数守恒设带回归测试的不变式，未覆盖教训原样透传，下游排序字段必须上游守恒。③投递：阈值只在检索时生效，核心常驻＋源任务相似检索；全量重发多耗 78% 输入 token，支持数≥2 的 47 条仅 +27% 却拿 +5.9。④验收：固定脚手架报增量、重复跑设五题噪声地板、token 与准确率并列，补正确性/时效信号方可无人值守；AML 增 memory-dose 维度（逐剂量曲线、每任务 token、支持守恒率、回退条数）。五项目经 tag 核实：OpenViking v0.5.5、TencentDB v2.0.4、dsh v26092802、ReMe v0.4.2.3 无新版；Hy-Memory 新增 MemHub v1.0.8（11-20，冻结 Qdrant/bm25 离线资源、显式维护 CLI）并锁 hy-memory v2.0.17——维护显式化但仍无正确性信号。反证：单论文单基准、多为单次运行、产品数据描述性，不作外推。

## 八、本期新观点

1. **剂量是模型条件的一等参数**（接 #122/#96 划界）——同一记忆对不同模型符号相反，强模型单调、弱模型倒 U、饱和模型零增益、过弱模型负增益；"多记住些"不是可移植建议，逐模型扫曲线才是。
2. **长尾单次经验是主要价值源**（深化 #114/#66）——144 条支持数为 1 的指南贡献全量对压缩版 6.6 分差；摘要式压缩把"只出现一次"误判为"不重要"，与正确性无关。
3. **支持数=复现度≠正确性**（深化 #95/#94）——高支持错误规则能一路通关并造成回退；无人值守循环必须外挂正确性或时效裁判，否则popular-wrong 会沉淀成权威。
4. **下游排序字段是上游守恒不变式**（深化 #1/#105）——支持数与来源在合并时静默丢失两次，须像事务不变量一样测试，而非按约定口头保留。
5. **先建噪声地板再声称增益**（深化 #87/#113）——同配置双跑差 1.2 分、32/168 题翻转、检索相似不预测受益；小差值应改报"同精度下省 1/7 token"这类可辩护结论。
6. **五项目倒挂＋AML 补 memory-dose 维度**（接 #56/#69）——五家仍以固定注入/全量为主、零逐模型剂量曲线与回退条数披露；MemHub 1.0.8 的显式维护 CLI 只解决索引陈旧，不解决"该不该继续信这条"。
