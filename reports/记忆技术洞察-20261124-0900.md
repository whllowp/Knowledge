# 记忆技术洞察 · 第 144 期（20261124-0900）

**主题：记忆的「用法记忆」（procedural memory via memory skills）——记忆不止存"发生过什么"，还要存"该怎样用这些记录去找证据"。前 143 期把记忆当内容、证据、状态、KV 或权重（#129／#137／#141／#143），默认把检索策略写成 agent 的固定提示或工具配置；11-20 提交的 VMSA（arXiv 2611.27381，Changin Choi 等五人，cs.CV／AI）把策略本身做成可归纳、可迁移、可压缩的二阶记忆：三层视频内容记忆负责"有什么"，技能库负责"怎么搜、何时停"。与 #131 划界（那期调注入记忆的量，本期调使用记忆的程序）、与 #133 划界（那期主张零结构回看，本期加的是检索程序不是索引）、与 #140 呼应（那期成功经验会反噬，本期只从成功轨迹抽可迁移程序并定期合并）。**

> 洞察范围：2026 年（近 30 天为主）。四维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

记忆研究正从"建什么库"扩到"库该怎么用"。长视频证据跨天甚至跨周，难点不只在于有无索引，而在搜什么、查哪层、怎样连接远时段，且这些决定依赖前几步证据。VMSA 把记忆拆成两类：随视频更换的内容记忆，以及从成功轨迹抽象、可跨基准复用的程序记忆；后者不存事实，只存检索、验证与停止策略。

## 二、技术现状

三层互补内容记忆：分段字幕保留细节与时间段；实体事件用滑窗互 kNN 合并同一实体档案，再跨窗归并事件；实体感知情节把远时段同实体情节连成全局摘要。前两层作检索工具，第三层常驻上下文引导搜索。技能每条写清触发条件、检索验证步骤、跨轮保留项、解释模板、停止规则与常见错误；归纳器只吃成功轨迹，剥掉原始工具结果与视频特异细节，逐条判定覆盖，未覆盖则精炼旧技能或新增，每百条合并同一程序。推理取 top-3 技能，限十轮，按需调用字幕检索、事件检索与源视频回看。

## 三、技术竞争力

七个长视频问答基准上，三个周级第一人称基准全部第一：EgoLifeQA 66.8、Ego-R1 Bench 74.7（超 WorldMM 9.4 点）、EgoMemReason 38.6（超次优 1.2 点、超 AVP 4.6 点）；另四个 24—67 分钟基准中 LongVideoBench 74.1、HippoVlog 82.1 居首，Video-MME 76.1、LVBench 72.8 具竞争力。技能库对照尤其反转常识：15 条的紧凑库在 LongVideoBench 拿 74.1，胜过 AWM 266 条 63.1、MemP 2181 条 71.6、ReasoningBank 3325 条 71.8 与 Trace2Skill 单条 69.7；LVBench 上 72.8 同样最高。

## 四、技术挑战

消融显示三层各有用：去字幕记忆三项掉 5.5—9.2 点最大，去事件记忆一致下降，去情节记忆（失去全局引导）三项全降。技能提升的是证据定位：最佳轮 tIoG 在 LVBench 由 0.447 升到 0.522、Ego-R1 由 0.597 升到 0.641；tIoG 过 0.5 组准确率高 3.6／9.1／13.1 点。成本也是墙：16 秒粒度每条视频 286,104 输入与 60,072 输出 token、6.31 分钟，60 秒粒度降到 77,229／13,667、2.34 分钟；每题记忆 token 6,501—45,795、工具轮 2.07—4.59。周级基准复用现成字幕并关闭回看，头部成绩有此前提。

## 五、需求分析

用户问"上周二我把钥匙放在哪张桌上、当时谁在场"：答案散落数天录像，agent 要知道先查人还是查物、先粗看事件还是回看帧、证据够不够就停。产品须把"怎么搜"从内容库独立出来，可跨视频与用户迁移、可审计回滚；验收并列证据时间定位、工具轮数、记忆 token 与建库耗时，并把"库越大越好"列为待证伪假设。

## 六、用户旅程

提问后系统注入全局情节摘要和三条相关技能，面板显示触发理由。agent 按技能先查实体事件库锁定人物，再查字幕库缩小时段，必要时回看源帧；每轮展示已覆盖时间段与 tIoG，达到停止条件即作答。答对后轨迹进入归纳器判覆盖：已覆盖不动库，缺步骤则精炼旧技能，确属新程序才新增；每百条合并并记版本差异。

## 七、具体实现方案

①三层记忆用分段字幕、滑窗互 kNN 实体合并、跨时段情节归并构建，前两层以向量检索（每次 10 字幕／20 事件）暴露为工具，第三层常驻；②技能六字段模板从成功轨迹生成，逐条判覆盖后精炼或新增，每百条按触发、步骤、保留与停止规则同一性合并；③技能库用不相交的来源基准训练（15／19／26 条），推理取 top-3、限十轮；④AML 增补 procedural-memory 维度：技能条数与变更、覆盖判定、跨库迁移增益、tIoG／tIoU、轮数与 token。五项目经 tag／release 与 README 核实：OpenViking v0.5.5、Hy-Memory v2.0.17＋MemHub v1.0.8、TencentDB v2.0.4、dsh v26092802 未见技能库登记；ReMe v0.4.2.3 有动态程序性记忆与 CLI 技能入口，但无覆盖归纳、跨基准迁移与 tIoG 验收——倒挂须逐项目分列。

## 八、本期新观点

1. **记忆有第二类对象：程序而非内容**（接 #5／#143、划界 #131）——内容记忆随源更换，技能记忆跨基准迁移；VMSA 用与目标集不相交来源训出的 15／19／26 条技能库直接生效，说明"怎么搜"是独立于"存了什么"的可携带资产。
2. **技能库的质量指标是覆盖而非条数**（深化 #131 剂量、#140 经验反噬）——15 条胜 266／2181／3325 条四套对照，靠的是逐轨迹覆盖判定、抽象掉视频特异细节与定期同程序合并；把全部成功经验堆进库（AWM）反而在 LongVideoBench 掉 11 点。
3. **技能的效果先落在证据定位，再落到答案**（接 #134 轨迹审计、深化 #122）——tIoG 0.447→0.522、0.597→0.641，且 tIoG>0.5 分组高 3.6—13.1 点；不记录中间定位就只能看到最终分数，看不到策略在不在起作用。
4. **全局情节是搜索控制器，不是证据库**（新角度，划界 #133／#142）——它常驻初始上下文却也被证据归誉评为最高贡献视图，价值在于生成下一步查询；把记忆一律做成"可检索条目"会漏掉这类只负责引导的类型。
5. **粒度与时间预算须与建库成本并列披露**（深化 #5 记忆税、#132 双轴）——16 秒对 60 秒：286,104 对 77,229 输入 token、6.31 对 2.34 分钟，换的是时间分辨率；周级结果还依赖复用他人字幕并关闭回看，头部准确率不能与全套自建构直接比较。
6. **AML 补 procedural-memory 维度并拆分五项目结论**——登记技能条数与变更、覆盖判定、跨库迁移增益、tIoG／tIoU、工具轮数与记忆 token。反证：单一论文、多选一问答、技能取自他集成功轨迹（失败轨迹的策略未学）、周级集关闭回看、构建成本只在 22 分钟子集实测，不作外推。
