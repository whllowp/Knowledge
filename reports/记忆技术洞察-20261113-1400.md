# 记忆技术洞察 · 第 81 期（20261113-1400）

## 本期主题：记忆的「栖居模态路由」——从"放哪"的栖居之争，到"运行时按年龄审计"的可执行路由

> 承接第 68 期栖居之争（参数化 vs 非参数化，静态设计定位），用 2026-11 NeurIPS 实证刷新为*运行时路由协议*，并与第 80 期写入信任边界（写侧落笔）、第 79 期决策效用（取侧仲裁）、第 75 期反噬 / 第 78 期拒答（基质层新失效源）正交。

### 一、四维洞察

- **发展趋势**：2026 NeurIPS 把记忆栖居从"设计选择"推向"运行时路由"——weight memory（参数化）经 on-policy 自蒸馏（OPSD）首次在 HaluMem 上追平/反超文本基线且每查询 token 更少；研究焦点从"记不记"转向"记在参数还是上下文、何时切换"。
- **技术现状**：Route to Remember（arXiv 2611.05636，11-03/05，NeurIPS PALM）用 per-user LoRA + verify-then-regenerate 路由；Memory Atlas（11 月更新）给出保留率曲线——权重记忆随条目年龄 59.9%→32.4% 平滑衰减、检索近乎平直，二者约 20 会话处交叉（complement-by-age）；TMEM（2606.04536）/ kNN 蒸馏至 6.9B（2607.27919）同证"参数可成低成本记忆组件"。
- **技术竞争力**：五项目（Hy-Memory 2.0.16 / TencentDB v2.0.3 / OpenViking v0.5.4.1 / dsh v26092802 / ReMe v0.4.2.2）全为文本/外部基质，零参数化记忆——Hy-Memory 推 30B 写入模型仍是"文本写入专家"，OpenViking 把一切外置成 viking:// 文件以最大化可检视性，与权重记忆"以可检视性换成本"正相反；前沿在论文、产品在文本，倒挂延续（接 #56/#69/#79/#80）。AML Cycle 2 已开（11 月中发榜），七维仍无 substrate/decay 维度。
- **技术挑战**：①路由前置判据被证伪——四类查询侧信号（相似度/分类器/置信度/长度控置信）都不能在回答前预判正确性（正确性 AUC 0.516≈随机），仅能判"可否答"(0.918)；②参数化引入新失效模式：权重记忆"不知事实从未记录，于是编造而非拒答"——是 #75 反噬/#78 拒答在基质层的正交新源；③须把 #78 读取裁决升维到基质选择：VtR 在生成后拿文本库审计答案，而非生成前挑基质。

### 二、需求分析

多会话常驻 agent 的边际查询成本随历史线性增长（每查询都重捞上下文）；同时"哪些记忆该内化进参数、哪些留外部"直接牵动成本/可检视/遗忘保真三轴权衡。团队需要的不只是"存文本"，而是"按查询年龄与可信度动态决定从参数还是文本取"，且绝不可编造。

### 三、用户旅程

1. **写入**：新会话事实既写外部文本库（真相源、可审计），又按需 OPSD 蒸馏进 per-user LoRA（近期快取）。
2. **查询**：先让权重记忆无上下文作答（零边际成本），文本检索并行。
3. **裁决**：用 VtR 拿生成答案回查文本库——一致则采纳，冲突/缺失则回退文本并标"权重不确定"，绝不编造。
4. **老化治理**：监控条目年龄，逼近 ~20 会话交叉点时把权重记忆"退役"回文本权威源，避免衰减失准。

### 四、具体实现方案

- **双基质写路**：文本库为权威真相源（接 #80 文件即真相源），LoRA 为可刷新快取；蒸馏仅离线/低频触发，写入须人在环或签名（接 #80 写路完整性）。
- **路由协议**：per-user LoRA + verify-then-regenerate；前置只用"可否答"粗筛，正确性交给生成后审计（放弃前置正确性预测）。
- **抗编造兜底**：权重输出一律过文本库审计门，冲突即降级为"检索+拒答"路径（接 #78 拒答终态），记"基质不确定"标签。
- **衰减 SLA**：上报 substrate crossover point / parametric decay rate 作为新可测指标（AML 应补 substrate 维度，接 #56/#69）。

### 五、本期权观点（新视角）

①栖居之争（#68）静态定位→升维为运行时路由+生成后审计协议；②"complement-by-age"是 complement-by-kind 之外的第二分配律，交叉点（~20 会话）成新 SLA；③参数化记忆不是文本替代而是"近期快取"，权威仍在文本（与 #80 文件真相源一致）；④权重"编造而非拒答"是反噬（#75）/拒答（#78）在基质层的新源，证明 resolve-at-read 必须升维到基质选择；⑤五项目零参数化印证"前沿路由、产品文本"的结构性倒挂。
