# AI-SRE 技术洞察（第 193 期）

**生成时间**：2026-11-14 22:56（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：批处理面／离线面（Batch）——夜里跑的 Agent 没人看；白天才发现批错了；交互式的监控假设全失效

---

## 题记

96 期说「合式错值最可怕」，139 期说「告警质量」，143 期说「成本失控」，184 期说「断点续跑」。这四件事在**批处理**场景里会同时变样：**夜里跑 5,000 条工单，没人盯着；每条都成功返回，但 3% 的值是错的；早上业务发现「批出来的报告不能用」。** 交互式 Agent 的监控假设是「有人在看、错了会重试、延迟可见」；**批处理里这三条全不成立**——**没有人、没有实时反馈、只有批次结束后的一个总数**。**批处理不是「循环调用交互式接口」，它需要自己的三件套：逐条状态、死信队列、批次级验收。** **少一件，夜里跑的东西早上就不敢用。**

## 一、发展趋势

**趋势一：批处理成为 Agent 的主要成本形态。** 夜间批、离线评测、批量修复；**比交互式便宜，但错得更安静**。**便宜是用「没人看」换来的。**

**趋势二：从「批次成功/失败」转向「逐条状态」。** 5,000 条里 150 条失败；**只报总数，等于没报**。

**趋势三：死信队列进入 Agent 栈。** 失败的条目单独存、单独重试；**不阻塞整批**。

## 二、技术现状：三种批错，通常只查一种

**整批失败：最显眼。** 认证过期、配额耗尽；**一眼能看到**。

**部分失败：最常见。** 150/5,000 失败；**被「批次完成」盖住**。

**静默错值：最危险。** 全部成功、3% 值错；**只有业务能用时才发现**（96 期）。

**现状：只看批次结束时间。** 「跑完了」＝成功；**逐条状态没有，死信没有，验收没有**。

**三种批次，三种风险。** 全量批（一次 5,000 条，错了全错）、增量批（每天新增，错了慢慢积累）、重放批（历史重跑，错了覆盖正确数据）；**重放批最危险，因为它会改已经对的东西**。

## 四、技术挑战

**一，部分失败被总数盖住。** 「完成 4,850/5,000」；**剩下 150 条去哪了**。

**二，没人盯。** 夜里没有值班；**告警要能叫醒人，而不是早上看报表**（139 期）。

**三，重试放大会拖垮整批。** 失败条目重试；**整批时间翻倍**（180 期）。

**四，逐条成本难摊。** 模型调用按 token；**一条贵的拖高整批均价**（143 期）。

**五，窗口有限。** 批处理有截止时间；**跑不完就要降级/分批**。

**六，静默错值无法自动发现。** 需要抽样/规则/对账；**没有验收，就只能等业务投诉**（96 期）。

**七，批与交互共用配额。** 夜间批占满配额；**白天交互式被限流**（120 期）。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `batch.*` 字段**：`batch_id`、`total`、`succeeded`、`failed`、`dead_letter[]`、`acceptance`、`cost`。
- **R2 逐条状态**：每条成功/失败/跳过；**可查、可导出**。
- **R3 死信队列**：失败条目单独存；**整批不阻塞**。
- **R4 批次验收**：抽样对账＋规则校验；**不通过不算完成**（96 期）。
- **R5 批次告警**：失败率阈值；**夜间可叫醒**（139 期）。
- **R6 断点续跑**：按条目续；**不重跑已成功**（184 期）。

### 5.2 用户旅程

- **平台工程师**：夜间批 5,000 条 → 早上看逐条状态 → 150 条死信 → 单独重试 → 成本分摊。
- **SRE**：失败率 12% → 告警 → 查共同原因 → 修配置 → 续跑。
- **业务**：抽样验收 → 发现 3% 错值 → 打回 → 加规则。
- **审计**：抽查一批 → 逐条状态与验收记录 → 确认可追溯。

### 5.3 实现方案（90 天）

- **0–30 天：逐条。** 状态落库；死信队列；批次报表。
- **30–60 天：验收。** 抽样对账；规则校验；失败率告警。
- **60–90 天：续跑与成本。** 按条续跑；成本分摊；季度演练；配额隔离。

**第 135 个市场空白（五项）**：逐条状态覆盖率、死信队列覆盖率、批次验收覆盖率、失败率可报率、按条续跑率——无一内建；`batch.*`／`deadletter.*` 为**第 104 次无人提字段族**。本地 173／173-kb 连续第 94 期成组启用：肖汉松 22「全局调度器：分派、等待」＝全库唯一把「分派与等待」写成组件的实践，本期首次当主线；配 184 期续跑、143 期成本。判词：**本地把分派写进调度器，联网侧 2026 年才让 Agent 夜里跑批；两边都没把「这一批哪几条错了」做成批次字段。**
