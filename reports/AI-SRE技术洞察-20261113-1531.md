# AI-SRE 技术洞察（第 184 期）

**生成时间**：2026-11-13 15:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：续跑面／断点面（Resumption）——长任务跑到第 7 步断了，重跑会重复副作用；不重跑会丢进度

---

## 题眼

85 期说「同一条 run 里，第 7 步用的已经不是第 1 步的规则」；80 期说「两次都返回 200，系统却错了」；90 期说「挂起是唯一没有 SLA 的存量」；132 期说「交接要读回」。把四件事拼起来，是一个长任务 Agent 每天都会遇到的局面：**任务跑到第 7 步，进程崩了/超时了/换班了。重跑——前 6 步的副作用（发了通知、扣了款、改了配置）会再来一遍；不重跑——前 6 步的进度全丢。** 于是团队只能在「重复」和「丢失」之间二选一。**续跑不是「再跑一次」，是「从第 7 步继续，且不重复第 1–6 步的副作用」——它需要三样东西：检查点、幂等键、已完成清单。** **少一样，就只能在「重复」和「丢失」之间二选一。**

## 一、发展趋势

**趋势一：长任务从「一次跑完」变成「可中断可续」。** 任务越长，中断概率越高；**不能续跑，就只能重跑**。

**趋势二：检查点从「数据库特性」变成「Agent 一等能力」。** 每步状态、已完成动作、未决分支；**没有检查点，续跑就是重来**。**检查点是 Agent 的「存档」。**

**趋势三：幂等键从「接口可选」变成「续跑前提」。** 同一动作重复提交只生效一次；**否则续跑＝重复副作用**（80 期）。

## 二、技术现状：三种断点，三样缺一不可

**崩溃/重启：最直接。** 进程没了，内存状态没了；**检查点决定能续到哪**。

**超时/取消：最隐蔽。** 任务被取消，但副作用已经发生；**没有已完成清单，就不知道做到哪**。

**换班/交接：最组织化。** 人换了，Agent 状态没交接；**读回决定下一班能不能接**（132 期）。

**续跑三件套：检查点、幂等键、已完成清单。** 缺检查点＝重来；缺幂等＝重复；缺清单＝不知道从哪开始。

**三种续跑，成本差很多。** 断点续跑（最便宜）、补偿回滚（最贵但最干净）、整体重跑（最省事但副作用重复）；**选错策略，比不续跑更糟**。

## 四、技术挑战

**一，副作用不可撤销。** 通知发了、款扣了；**重跑就是第二次**。

**二，检查点有成本。** 每步存状态很贵；**存太稀，续跑丢步；存太密，拖慢任务**。

**三，续跑会重规划。** Agent 从第 7 步重新规划，**可能走另一条路**（171 期）。

**四，幂等键难设计。** 什么算「同一动作」；**参数、时间、来源都要进键**（178 期）。

**五，多 Agent 续跑会打架。** A 续跑时 B 也在跑；**锁没释放就双跑**（178 期）。

**六，续跑不可验证。** 说「续上了」，**怎么证明副作用只发生一次**。

**七，补偿本身有成本。** 退款、撤回、道歉；**补偿链越长，越容易二次出错**（164 期）。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `resume.*` 字段**：`task_id`、`checkpoint_id`、`completed_steps`、`idempotency_key`、`resumed_at`、`duplicate_effects`。
- **R2 检查点**：关键步骤后落检查点；**成本与粒度按任务定**。
- **R3 幂等键**：动作级键；**参数＋来源＋目标**入键。
- **R4 已完成清单**：每步记「做了什么、影响哪个资源」；**续跑先读清单**。
- **R5 续跑策略**：可续则续、不可续则补偿；**不静默重跑**。
- **R6 验证**：续跑后对账副作用次数；**重复即告警**。

### 5.2 用户旅程

- **SRE**：任务第 7 步崩 → 读清单 → 从检查点续 → 对账副作用一次 → 记录续跑。
- **平台工程师**：设计长任务 → 加检查点与幂等键 → 演练中断。
- **值班**：换班 → 交接 `checkpoint_id` 与未决步骤 → 接班人续跑。
- **审计**：抽查一次续跑 → 核对清单与副作用 → 确认没有重复。

### 5.3 实现方案（90 天）

- **0–30 天：清单。** 长任务列步骤与副作用；定检查点位置。
- **30–60 天：幂等。** 动作级幂等键；续跑策略。
- **60–90 天：验证。** 续跑对账；中断演练；指标上线；补偿链梳理。

**第 129 个市场空白（五项）**：长任务检查点覆盖率、幂等键覆盖率、已完成清单覆盖率、续跑成功率、重复副作用率——无一内建；`resume.*`／`checkpoint.*` 为**第 98 次无人提字段族**。本地 173／173-kb 连续第 88 期成组启用：肖汉松 22「全局调度器：分派、等待」＝全库唯一把「等待」写成组件的实践，本期首次当主线；配 80 期幂等、164 期恢复。判词：**本地把「等待」写进调度器，联网侧 2026 年才承认「挂起没有 SLA」；两边都没把「续跑不重复副作用」做成验收项。**
