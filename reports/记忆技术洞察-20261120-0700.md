# 记忆技术洞察 · 第 130 期（20261120-0700）

**主题：记忆的「活库兑现」（live knowledge base actualization）——前 129 期都在改记忆机制本身（存什么／取哪条／读多少／看多清／证据能否回来），11-18 KnowledgeClaw（arXiv 2611.24294，Haoran Luo 等 4 人，cs.AI）把问题推到交付端：一份个人文件库要真能当记忆用，必须同时做到全模态原生读取、编辑后闭环一致、按查询意图多粒度取用。三项缺一项，其余做得再好也不过 41.3 分；三项合取才 55.9。与 #122 划界（那管一条读多少，本期管取用的层级）、与 #129 划界（那管结论被推翻时证据回不回得来，本期管源文件变了以后整库是否仍然成立）。**

> 洞察范围：2026 年（近 30 天为主）。四维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

知识工程路线从分块 RAG、实体图、超图走到记忆 agent 与多模态 KE，却各占一角：有生命周期的不会原生读媒体，能原生读媒体的没有闭环维护，其余把库压成扁平 store。本期趋势是"建一次库"变成"库要活着"——评价对象从建库当时的问答分数，移到编辑流之后是否仍无陈旧证据、命名文件是否必然送达。记忆从算法指标变成库级不变式。

## 二、技术现状

KnowledgeClaw 三部件：C1 建全模态类型超图 K=(D,V,E,π)，边分 record／event／cross-modal，文本 PDF 走投影、图像音频视频由冻结全模态模型直读原文件，定长 schema 的目录卡经归一与别名类合并，共享实体两跳内必连。C2 以句柄管 Add／Del／Refresh，Del 不调模型，沿 π 剪掉只依附旧版本的节点，承诺"所有节点都有现存源文件"。C3 按锚点、关系／查表／综合线索路由到 file／subgraph／community 三级，社区取 64 个 Louvain 簇。

## 三、技术竞争力

OmniKE-Bench：10 个角色、五模态 3,960 个真实文件、1,829 道无模型金标题。30 基线对比，六任务十角色全部第一，OKE 55.9，超最强基线 MemPro 14.6（41.3），符号检验 p=0.002。去 C1／C2 仍得 49.1／50.4 高于所有基线，但 T1／T5 各自塌陷，说明互补而非可替代。137 项编辑前后测试：本系统 93.4→97.8，九条 70 分以上基线有八条编辑后跌破 36；2,000 次编辑流中陈旧节点恒为 0，追加式库累积 10,148 个，单次编辑只触及 0.33% 节点，Refresh 2.6 秒对全量重建 118 秒。强制单粒度 File 52.2／Walk 51.2／Flat 26.7／Community 15.8，路由 55.9；证据截到 256 token 仍得 51.2，高于全上下文的所有基线，每查询 $0.0004。

## 四、技术挑战

①五条最强基线全模态与生命周期只占其一，说明合取难做而非谁疏忽。②固定 schema、名字归一与别名键遇到歧义身份会错并或漏并；64 个社区为统一配置，没有逐角色调参却有场景边界。③2,000 次编辑是随机合成流，真实文件改动的语义冲突未测。④单一冻结骨干 Gemini 2.5 Flash Lite 与 3,072 维编码器，换模型结论未验；基准只用可再分发的公开材料，私人文件与授权边界未覆盖。

## 五、需求分析

用户手里的资料横跨 PDF、截图、录音与视频：问"某作曲家的这部作品"时，答案可能藏在音频文件名里；而文件被替换后，旧摘要若继续留在索引里，回答会自信地给出作废的值。用户要的不是"检索得更像"，而是三条硬承诺：跨模态能互相找到、编辑后不返回旧值、点名文件一定进证据。

## 六、用户旅程

系统一次性读入库内文件，为每份生成目录卡并挂上来源。用户问到点名的文件时，路由只取该文件的卡片；问"两人如何关联"时，从锚点沿超图走到共享实体连到的其他文件；问全局综述时才落社区报告。随后用户 Refresh 一份文件：系统沿来源剪掉仅依赖旧版的实体与边、加入新版，下一次问答给的是新值，而不是被新内容掩盖的旧结论。

## 七、具体实现方案

①表示层：类型超图＋π 来源映射＋别名归一，原生读取媒体，索引键只指向现存节点。②维护层：句柄化 Add／Del／Refresh，Del 纯剪枝不调模型，以"π 非空且指向现存文件"作提交后断言。③取用层：意图路由三级粒度，锚点卡必送、其余按共享实体加权的游走评分与 RRF 融合取 top-k。④验收层：编辑前后配对测陈旧率、点名文件送达率、强制粒度对照、证据长度—成本曲线；AML 补 omnimodal-live-KE 维度（编辑后陈旧率／点名送达率／路由命中／每查询证据 token）。反证：单论文、单骨干、合成编辑流、公开语料、固定 schema 与社区数，不作外推。

## 八、本期新观点

1. **记忆交付的"活库"是三项合取的新轴**（接 #122／#124／#129 划界）——全模态、闭环一致、多粒度取用必须同时成立；五强基线各占其一二、均不超 41.3，评估对象从单条记忆机制升级为库级性质。
2. **建库质量改写为编辑后不变式**（深化 #114／#106）——∀x 有 π(x) 非空且指向现存文件；2,000 次编辑陈旧节点 0 对追加式 10,148，验收从"建得准"变成"改后不陈"。
3. **三性质互补而非线性叠加**（新）——去掉 C1／C2 仍 49.1／50.4 高于全部基线，但 T1／T5 分别塌；增益来自合取，单组件分数不能外推为系统分数。
4. **命名文件必入证据是确定性契约**（深化 #109）——扁平 top-k 漏 6–77%，命题 3 保证与 k、λ、θ 及库大小无关；检索应区分"相似度不保证送达"与"句柄必定送达"。
5. **粒度是查询意图的函数，不是全局配置**（深化 #122）——四种强制粒度各在某些任务失败，路由逐题匹配最优固定粒度；把"读多少"进一步拆成"从哪一层读"。
6. **证据长度与查询成本须独立入账＋五项目倒挂**（深化 #5／#124）——256 token 仍胜全上下文基线、每查询 $0.0004，省的是证据面而非模型调用；五家零原生多模态闭环，AML 补 omnimodal-live-KE 维度。
