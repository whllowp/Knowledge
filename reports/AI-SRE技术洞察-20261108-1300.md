## 一、发展趋势：分数是模型与现场的联合函数，行业只钉了模型那一半

前 104 期的方法有一个共同底座：**出事之后重跑一遍，用重跑结果给原运行定案**。第 39 期把重放立为验收标准，第 86／98／103／104 期的独立验收、`re-grade diff`、干预重放、受保护案例重放，都默认「重放＝同一次执行」——这个默认从未被测过。

11-03 arXiv 2611.05650（NeurIPS 2026 IAB Workshop 非归档）把默认本身立为对象：任何「把失败归因于历史」的结论必须带**执行过的反事实**——冻结中轨迹状态、只改 Agent 能看到的历史、继续跑，且「恢复已被测量」「重放证书与估计量匹配」。论文点名 DoVer、REFLECT、Min 等、Who&When Pro、Causal Agent Replay 五种干预方法——**无一报告过实测重放证书**。警示测量即题眼那组——通道打开后 17/24 与 22/24 状态自相分歧，根因是工具失败抽样消耗了**进程全局随机流**，runner 启动时播种、构建缓存时又重播种，而**快照无字段记录流的位置**；补采恢复后 24/24 与 live 一致。

正面证据同周出现。11-05 Google 与滑铁卢的 ReproBridge（arXiv 2611.08452）不换更强的模型，只把「让上次成功成立的现场」打包成四件套：精炼代码库、环境配置、实验启动器、复现指南，用独立 Auditor 核验执行证据（防不跑就报数）；1,029 任务／36 篇论文、5 个人工核验参考分，全新会话不给构造对话与参考答案。结果平均复现成功率 76.4%→92.6%、API 花费降 19.7%、**跨模型差距从 21.6 点收窄到 3.9 点**，消融去代码或去环境掉得最多。两组数字合起来给出往期没写过的判断：**换现场的提升（16.2 点）大于换模型的差距**；榜单上「谁更聪明」测的有很大一块是「谁把现场带得更全」。现场不是背景条件，是能力的一个坐标。

产品侧反而在加速「无现场的经验迁移」。11-02／03 腾讯云 CloudQ 共创计划主打「一线运维经验转化为可复用的智能体技能」；11-03 Honeycomb Team Agents 的卖点是「周二一人弄明白的事，周三全队都知道」，每条 finding 链回 query／trace／deploy／ticket 并标 confirmed 或 hypothesis；同日 Grafana ObservabilityCON 2026 推出 Assistant Watchers 与带 OTel 的 Agent Observability。三者搬运的却只是结论——没有一样带「这条结论在哪个现场成立」。

## 二、技术现状：断点不在配置表，而在运行中的隐含状态

**参照物断点：一致性不等于等价性。** 2611.05650 原话最该抄进采购条款：「克隆之间共享一个种子位置的门会全票通过，却仍然是错的；只有单独执行的参照续跑（live 或前缀重建）才能发现。」论文还要求声明精确重放或分布等价并报实测一致率。11-04 AgentTrustCI（arXiv 2611.06674）虽用确定性重放做 CI 三层检查（policy／grounding／trajectory，55 合成用例全对、12 个关键用例零漏），却自认「覆盖的是自编回归集，不是生产准确率」，`MockAgent` 返回的是**存好的轨迹**。夹具重放与事故现场重放，同名不同物；且 oracle 重试下 final-grader 分歧 0/24＝结果层致盲。

**隐含状态没有字段。** 最不可导出的一格不是环境变量，而是随机流位置、runner 重播种时机、解释器版本。2611.05650 复现他人扫描时换解释器后六张表全字节一致——连「复现失败」都可能是现场伪影。11-03 Agentic Behavior Engineering（arXiv 2611.05454）把话说全：「改变 Agent 行为的多数因素——模型版本退役、策略修订、上游 schema 变更、为修一个 case 改的提示词——都源自团队之外，作为生产缺陷被发现，而不是作为回归被拦住。」

**中国侧最细的一手材料全落在「发布前」与「排查时」。** 火山引擎方舟官方文档（本期首次启用，最硬单源）把现场做成一等对象：每次改配置自动生成新版本、可对比回滚；Environment 定义运行环境模板（依赖、环境变量、产物存储），「创建 Session 时绑定 Environment，**确保代码在一致环境中执行**」，事件时间轴全程可回放。但产物不选自有 TOS 时「需在平台 TTL 到期前下载」——**现场有寿命，回放却按永久资产卖**。11-03 字节 Storage Agent Family Eval 明确「保存评测集快照、评估器版本、评分配置和运行环境」「新旧版本对比时核对双方条件」，是国内最接近现场钉版的实现，却是发布前离线回归；阿里 AgentCore 稿写「一个 Agent 在版本更新或实例重建后，可能已运行在另一个 Sandbox 中」，UModel 保留地域、版本、运行代次与观察时间——这是给排查用的身份链，不是给重放用的现场快照；阿里云栖把「被重复验证」列为 AgenticOps 三道墙之一。三家都答了「现场怎么建」，没有一家答「这次回放跑的是不是那一次的现场」。

**经验迁移不附适用条件。** 11-03 ReScopeBench（arXiv 2611.05450）在 18 个环境、20 个模型上引入**静默环境变更**，结论是「即便所需经验被正确记录，也不总能成功完成任务」。第 84 期的 as-of 是时间坐标，本期要的是**现场坐标**：结论成立的运行时条件。

**本期反转（修正第 39／86／98／103／104 期判词）**：往期把「重放」当终审法庭，本期指出法庭未经验收。最硬的否定证据（24/24 互证对 9/24、20/24 分叉，0/24 结果层致盲）与最完整的正面制品（ReproBridge 四件套＋Auditor＋参考分）同在学术侧，却属 ML 论文复现非运维事故；中国侧把现场做成一等对象最细——火山 Environment 绑定 Session、字节保存运行环境、阿里保留运行代次、云栖明写「被重复验证」——却全落在发布前评测与排查定位。**六家云厂商在「重放参照＝原续跑」「现场状态含隐含随机位」「重放证书」三列全空。判词：「回放」可采购、「记忆」可采购、「经验复用」可采购，「举证这次回放跑的是不是那一次的现场」不可采购。**

本地 173／173-kb 连续第二十六期成组启用，升级为「现场原型」：陈忻 29「源码注入评估，跨引擎一致率 100%（548/548）」是本地唯一把可复现量化到具体分母的原型（首次当主线）；刘凯宁 05 的 Skill 四步「开发调试→评测回放→部署投产→反馈迭代」要求同一套经验在自动诊断与现场排查两个现场各自回放；马云雷 31「概率性采样放大路径差异，需完整 Trajectory＋稳定 Harness＋多次复现」「离线通过≠长期稳定（工具契约／环境快照／漂移监控）」几乎是 2611.05650 的中文工程版。但须诚实说一句：本地那 100% 报的也是**跨引擎一致**，不是**与原运行一致**——本地与联网侧共享同一个盲区，这比往期「本地早写成流程」的判词更接近真相。

## 四、技术挑战

**隐含状态无处挂。** 随机流位置、runner 重播种时机、解释器版本不进任何配置表；OTel GenAI 仍 Development、`NO_CONTENT` 默认、采样可丢，`site.*` 是第 28 次无人提字段族。

**全量留现场的代价被回避。** AWS 11-06 明说「存储 prompts 与 tool calls 会带来保留、访问控制与敏感数据义务」；OpenAI 运维稿要求工具结果入库前脱敏；Anthropic 11-05 里 Cowork 本地 VM 的 EDR 传感器只检测不阻断、且不覆盖云端会话——**最需要被看见的现场，恰在组织可见性之外**。11-02 Evoke 与 CrowdStrike／Palo Alto 的 AIDR 集成，追的正是「员工合上笔记本后 Agent 仍在云端跑」这个洞。

**一致性会自证，记录本身可被改。** 克隆共享种子位置仍全票通过；Databricks 记忆文档明写 `put()` 非原子、并发写互相覆盖，后台管道还能 rewrite／merge／split／delete Agent 存的条目。

**现场与经验寿命错配。** 火山方舟产物 TTL、OpenAI Agent Builder 与托管 Evals 11-30 关停需迁到 Promptfoo 本地／CI、Agent Harness 进程重启即丢会话、ABE 点名模型退役与上游 schema 变更。经验被当永久资产，现场却是有寿命的资产。

**可复现的价格没进运维预算。** ReproBridge 需 8×H100、每论文 24 小时墙钟、独立 Auditor 与人工参考分；成本算在论文侧，没有一项出现在运维采购清单。

## 五、展望与建议

1. **`site.*` 与 `replay.*` 双字段族进 OTel GenAI 提案**：site_manifest_id／config_digest／model_tool_versions[]／env_digest／interpreter／rng_stream_position／clock_epoch／external_response_receipts[]／capture_completeness；replay_id／reference_kind（live｜prefix_rebuilt｜clone｜fixture）／agreement_rate／certificate_state，独立 `replay` span，默认 `REPLAY_UNVERIFIED`，禁由被测 Agent 写入。
2. **重放证书与一致率设为硬门槛**：声明要精确重放还是分布等价，报与「未编辑历史 live-vs-restored 对照」的实测一致率；克隆互验不得单独作通过依据；结果 grader 之外强制 realization-level 轨迹 diff，防止 0/24 式致盲。
3. **现场清单绑进经验**：Skill／记忆／finding 写入时绑定 site_manifest_id 与现场 as_of，默认 `APPLICABILITY_UNVERIFIED`；模型退役、schema 变更、依赖升级、runner 重播种触发经验复验并发布 `site diff` 进 CAB。
4. **经验迁移按 ReproBridge 四件套验收**：精炼代码库＋环境配置＋启动器＋复现指南，独立 Auditor 核验执行证据，fresh session 不给构造对话与参考答案；注入 ReScopeBench 式静默环境变更，以能报出失效经验为通过。
5. **现场寿命进保留策略**：产物 TTL、托管评测站点退役一并登记，到期前导出 site manifest；现场快照变更进 CAB，prompts／工具调用的访问控制与敏感数据义务单列科目。
6. **六类混沌注入＋补格＋采购三问**：随机流位置漏采、runner 重播种、解释器换版、环境静默变更、夹具冒充生产回放、经验跨现场复用；以能导出 `REPLAY_UNVERIFIED` 清单为验收。信通院五项要求、六维与 SRE AGENT 能力要求补「重放证书可导出率／现场一致率／经验适用条件覆盖率」；采购问三句：重放拿什么当参照、现场清单能否导出、现场变了经验会不会自动失效；KubeCon NA 11-09 为提案窗口。
