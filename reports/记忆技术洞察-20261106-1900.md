# 记忆技术洞察（第 15 期）：记忆的动作性——从"知道"到"会做"

> 期数：20261106-1900 ｜ 时间：2026-11-06 19:00 ｜ 范围：2026 年 11 月（近 30 天）动态为主
> 主线承接：第 12 期判读"程序性记忆权限是最大产品空位"，本期给出兑现证据并上钻一层。

## 一、发展趋势

前十四期讨论写、删、指、切、账、插座、空集、并发、闭环、时间、时延、信任、搬迁、缓存，全部默认一个未言明的前提：**记忆是陈述——被检索后送进上下文，回答"是什么"。** 本期拿掉这个前提。最近 30 天，"怎么做"正在从陈述性存储中被拆出来，成为独立的一等对象，且出现了此前没有的两层结构：

**第一层：经验编译成技能。** Zep Agent Skills（arXiv 2611.01386，11-01）把任务轨迹编译为版本化 Skill；腾讯 TencentDB-Agent-Memory 把 Skill 列为四类记忆资产之一（Chat Memory / Skill / Wiki / CodeGraph）；OpenViking 把 agent skills 作为三类上下文之一并在 v0.5.3（11-02）新增 Rules Beta 服务；dsh-memory-evolve 继续深化"技能自进化与技能管理器"。

**第二层：记忆操作本身编译成技能（元层）。** MemSkill（NeurIPS 2026，arXiv 2602.02474，机器之心 11-02 报道）把新增/更新/删除/跳过四个记忆操作封装为可学习、可进化的 MemorySkills，用下游任务奖励做强化学习优化技能选择，用失败案例修订技能库。产品侧普遍停在第一层，元层只有研究。

**本期核心新观点：技能是记忆中唯一自带天然反馈信号的类型。** 陈述性记忆"有没有用"需要人为构造观测（第 5 期价值可观测五级 V0—V4，主流仅 V1—V2）；而技能的每次调用直接对应任务成败，标签免费。这解释了一个此前悬置的现象——为什么治理化（验证、门禁、遥测）先发生在技能侧而不是陈述侧：不是能力差异，是**激励差异**。信号在哪里，治理就在哪里。

**框架扩展：三轨变四轨。** 第 1 期提出文件轨 / 分层轨 / 参数轨。技能轨应单列为第四轨：它是"冻结权重的参数轨"——没有梯度，但有行为改变；Zep 在 ALFWorld 上用小模型编译的技能取得与连续微调相当或更大的增益，**零训练**。技能轨与参数轨的差异不在效果，在可逆性与可审计性。

## 二、技术现状

**Zep Agent Skills 成为技能侧治理的完整样板。** 只用 verified attempts 作为证据；Skill 逐字段引用 Trace 事件（承接第 3 期血统）；Reflector/Curator 双角色编译；扫描与准入门控制激活；**verified use outcomes 反向改变技能搜索排序**——使用效果遥测进入检索排序，这是公开系统中首次。效果：教师模型轨迹编译的技能使三个更弱执行模型通过率提升 4.5–18.8 分；Agent Skills 格式由 Anthropic 捐给 Agentic AI Foundation，事实标准已成型。

**MemSkill 补上元层。** Controller 按片段选 Top-K 技能、Executor 构建、Designer 依失败案例修订库；LLaMA 学到的技能库直接迁移到 Qwen，LoCoMo 技能库迁移到 HotpotQA 均无需重训；相比 LightMem，LLM 调用量下降近七成。它证明"如何记忆"本身可以是被优化的对象——第 1 期"写入侧独立化"的最终形态可能是写入侧技能化。

**腾讯双线。** TencentDB-Agent-Memory v2.0.3（10-26）新增 Skill 导出、私有 Skill 可检索、提取捕获范围扩大，公开路线图含 skill generation，29,264★；同期腾讯数据库生态大会披露 TencentDBAgent（运维向）把十万级工单经验封装为 Skill，**四级权限：只读自动跑、变更需确认、高危直接拒绝**——第 12 期"程序性记忆权限空位"的判读已首次被产品实现，但实现位置不在记忆产品而在运维 Agent。OpenViking v0.5.3 的 Rules 服务让智能体检索"按什么规矩办事"，规则成为可检索层。

**其余项目。** 阿里云 Memory（11-02 上线）官方明确 Memory 与 Skill 的分工配对：Memory 存偏好画像，Skill 封装可复用流程，每次执行调用最新画像。ReMe 自身即以 reme_memory/SKILL.md 形式分发（会话预载 62 token、调用时 2,237 token），auto_dream 将日记巩固为长期摘要——记忆系统把自己也做成技能。Hy-Memory 2.0.13/2.0.14（11-01/02）的 working/coding 轨把工具调用轨迹转为"会话事实 + 可复用经验"，coding 版本链保留被撤回版本。dsh 生态出现同名分化：dsh-memory-evolve 持续更新技能自进化，另一插件 dsh-continual-evolve 自 2026-11 起功能冻结转低频维护；DSH 本体 v0.2.2-alpha.3（11-03）新增宿主级自动化任务与目标续跑。

**评测口径。** AML 二期评测 11-04 关闭，榜单 11 月中发布（11-06 尚未出）。Coding 轨用 CAMBench：12 仓库、150 任务、300 次计分，考的正是"历史经验复用"——评测层已把"会做"当作记忆的成绩单，但技能的权限与回滚仍无计分维度。

## 三、技术竞争力

程序性记忆能力对比（本期轴）：

| 方案 | 程序性支持 | 证据验证 | 准入门禁 | 使用效果遥测 | 执行权限 | 可回滚 |
|---|---|---|---|---|---|---|
| Zep Agent Skills | 完整（编译+版本化） | 仅 verified traces | 扫描+门禁 | 有（改排序） | 无 | 删源级联删 Skill |
| TencentDB-Agent-Memory | Skill 为四资产之一 | 强制归档（人工） | 无公开 | 无 | 无 | 可导出 |
| TencentDBAgent 运维 | 工单→Skill | 人工沉淀 | 分级确认 | 运维闭环 | 四级（只读自动/确认/拒绝） | 变更域隔离 |
| OpenViking | skills + Rules | 用户数据为主 | 无 | 无 | 无 | git 版本 |
| Hy-Memory working/coding | 轨迹→经验层 | diff 链留痕 | 无 | 无 | 无 | 版本链留被撤回版 |
| ReMe | 自身 Skill 化 | 用户授权 | 无 | 无 | 无 | 文件级 |
| MemSkill（研究） | 元层：操作即技能 | 任务奖励 RL | Designer 修订 | 任务反馈 | 无 | 技能库可修订 |
| dsh-memory-evolve | 技能自进化 | 人工闸门 | 分支作用域 | 情绪反馈入库 | 无 | git |

竞争分三档：**有验证有遥测**（仅 Zep 一家完整）；**有产物无治理**（腾讯四资产、OpenViking、dsh-memory-evolve、阿里云配对——产物都有了，验证/遥测全空）；**元层**（MemSkill 纯研究，无产品化）。技能侧是"验证-门禁-遥测-回滚"四件套首次在同一家配齐的地方，也是全行业陈述性记忆都没有配齐的地方——对"会做"严于"知道"，方向正确，但反向暴露陈述侧治理赤字。第 12 期判读的兑现方式再次印证倒挂：最好的程序性权限实现在非记忆产品里。

## 四、技术挑战

**1. 失败的不对称性。** 陈述性记忆错了，代价是答错一次；技能错了，是可重复地做错，每次执行放大一次。撤销一条事实等于改一个答案，撤销一项技能不等于撤销已形成的行为路径——程序性记忆的 unlearning 问题比第 2 期的删除问题更硬。

**2. 验证门槛与覆盖率矛盾。** Zep 只收 verified attempts，保证了质量，但所有无法自动验证的任务（开放式、跨系统、需要人判定的）被系统性排除在技能库之外。验证越严，覆盖率债越大；"verification strength"在开放任务中如何定义，目前无人回答。

**3. 元层缺位。** MemSkill 已证明记忆操作可以随任务反馈进化，但产品侧写入策略仍是硬编码四操作。写入侧技能化（把"这家公司的记忆规则"变成可迭代资产）是第 1 期主线的自然终点，尚无产品。

**4. 评测缺口。** AML Coding 轨奖励"经验复用"，不测技能权限与回滚；SkillsBench（2026-02）测技能质量，不测技能危险。一个会把生产库删掉的技能与一个平庸技能，在现有评测里同分。

**5. 分发即风险。** Agent Skills 成为基金会标准后，技能将以包形式流通——第 12 期的信任半径问题将从"共享记忆库"收缩为"共享技能包"，且技能是可执行语义，投毒面比陈述性记忆更大（FARMA 伪造推理痕迹 ASR 100% 的教训直接适用）。

## 五、展望与建议

技能轨将在 2027 年前成为采购清单的独立列项，格式层竞争已经结束（Anthropic 标准捐赠即终点），竞争焦点转向治理链四件套（验证→门禁→遥测→回滚）的完整度。给从业者的建议：选型不再问"有没有 Skill 功能"，而按四件套逐项问；有陈述性记忆写入的公司，应把 MemSkill 的元层思路落为内部写入策略的可迭代资产；采购条款中应要求技能的使用效果遥测可导出——Zep 已证明这在工程上可行。评测方面，AML 二期出榜（11 月中）重点看 Coding 轨：名次不重要，要看"经验复用"是否构成独立得分结构；若三期把技能权限纳入，程序性记忆将从加分项变成准入项。

下期候选：AML 二期榜单口径复核（11 月中，最高优先）；技能撤销后的行为残留实测；verification strength 在开放任务的定义；MemSkill 元层产品化；技能包投毒的首个实测。
