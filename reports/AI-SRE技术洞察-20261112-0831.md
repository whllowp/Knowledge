# AI-SRE 技术洞察（第 144 期）

**生成时间**：2026-11-12 08:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：编队面／多智能体协作面（Multi-Agent Coordination）——多一个 Agent 不是多一份能力，是多一份协调税；编队要先过盈亏平衡点

---

## 题眼

10-25 arXiv 2610.37700 给多智能体泼了一盆很冷的水：它把「协调税」（分解开销＋每次交接的协议成本）与「异质性红利」（把活路由给更便宜的模型）写成闭式模型，给出盈亏平衡阈值与可行性界 **α < 1/r**（α 为协调税占单调用成本的比例、r 为分工带来的相对收益放大），然后在 135 个 HumanEval/ClassEval 任务、2,430 次运行、六种架构、Claude Opus 5.5 与 Haiku 5.5 上把每一项都测了。**这个不等式很朴素：协调税一旦超过「分工带来的收益放大」的倒数，组队就是亏的。**结果：协议本身很便宜（OFP 每次交接 **7.2ms，占墙钟 0.11%**）；**贵的是分解**——planner-coder-reviewer 流水线成本是单次强模型调用的 **3.22 倍**、耗时 **3.24 倍**，**解决的题一道没多**。把 planner/reviewer 换成便宜模型，成本降到 **0.39 倍**，但 pass@1 **掉 6.7 个点**，仍然更贵、更慢、更不准；盈亏平衡预测还偏了 **−19%**，因为便宜角色把 token 量吹大了。**真正的省钱办法是按任务选模型：oracle 二选一解决了 94.3% 的运行，单题成本只有强模型调用的一半。** 换句话说：**先把「单调用＋路由」做到极致，再考虑组队；组队是最后一张牌，不是第一张。**

## 一、发展趋势

**趋势一：多智能体从「能力叙事」转向「成本核算」。** 过去说「多角色更可靠」；现在要先回答「协调税多少、异质性红利多少、盈亏平衡在哪」。**没有盈亏平衡测算的编队，是在用预算买叙事。** 框架把多 Agent 做成默认模板，**团队照着模板搭，账却没人算**。

**趋势二：协议标准化了，但协议不是瓶颈。** A2A v1.0（03-12）带来签名 Agent Card、多租户、版本协商；**协议成本只占墙钟 0.11%**——**标准化解决互操作，解决不了「该不该分解」**。

**趋势三：级联失败成为编队的主要风险。** 一个 Agent 的错误输出成为下一个的前提；**编队越深，前提继承越长**（111 期 51% 链式完成率在编队层的放大）。

## 二、技术现状：三种编队，三种账

**Supervisor 型：一个调度者分派。** 协调开销集中在一处，**调度者的判断错，整队错**；适合任务可清晰分解的场景。

**Pipeline 型：planner→coder→reviewer。** 研究里最常测的形态；**成本 3.22×、时间 3.24×、收益为零**（在可单次解决的任务上）。

**Swarm 型：多 Agent 并行试错。** 靠多样性换命中率；**成本随并行度线性涨，收益取决于「错误是否互补」**（30 期错误重叠）。

**失败分类：规格、错位、验证。** 多智能体失败多来自「任务没定义清」「Agent 之间理解不一致」「没人独立验证」；**不是模型不够强，是编队没设计好**。

**编队成本要算三块，不是一块。** 分解（planner 多写的规划）、交接（消息/序列化/重试）、返工（下游基于错前提重做）；**协议成本只是中间那块，且是最小的一块**。

**A2A 的 Agent Card 是能力声明，不是能力证明。** 签名保证「这张卡没被改」，不保证「它真的能做」；**要像 137 期验工具那样验能力**。

## 四、技术挑战

**一，协调税被低估。** 协议只占 0.11%，分解与上下文同步才是大头；**账算在协议上，钱花在分解上**。

**二，异质性红利需要真异构。** 便宜角色若只是「同样能力的小模型」，token 会膨胀、质量会掉；**红利来自「不同模型/工具/数据」的结构差，不是角色名**。

**三，级联无法回滚。** 下游基于上游输出继续做；**上游错了，下游的「成功」是错的成功**（115 期返回、116 期记录）。

**四，编队难测。** 单 Agent 可以重放；编队要重放整条交互；**没有交互级 trace，就算不出协调税**。

**五，责任分散。** 编队出错，是调度者、子 Agent、还是协议？**没有归属，复盘只能归到「模型不行」**（125 期归因）。

**六，默认组队。** 框架把「多 Agent」做成默认模板；**团队照着模板搭，没算过账**。

**七，编队缺交互级 trace。** 单 Agent 的 trace 是线性的；编队的 trace 是图——**没有图级 trace，协调税与级联都算不出来**。

**八，编队与 SLO 脱节。** SLO 按单次任务算，编队按「整条流水线」交付；**P99 被最慢的子 Agent 拖住**，却没人对它负责。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `fleet.*` 字段**：`topology`、`roles`、`handoffs`、`decomposition_cost`、`protocol_cost`、`heterogeneity`、`cascade_depth`。
- **R2 盈亏平衡测算**：上线前算「协调税 vs 异质性红利」，达不到 α<1/r 就不组队。
- **R3 编队拓扑选择**：可单次解决→单调用；真异构→pipeline；错误互补→swarm。
- **R4 委托契约**：每个子 Agent 有签名 Card、scope、budget、deadline（A2A v1.0）。
- **R5 级联控制**：最大深度、检查点、上游失败即停；下游不得把上游输出当已验证前提。
- **R6 指标**：cost per solved task（对比单调用）、重复工作率、交接丢失率、级联深度。

### 5.2 用户旅程

- **平台工程师**：想搭 planner-coder-reviewer → 先算账 → 发现 3.2× 成本零收益 → 改为单调用＋按任务选模型 → 把省下的预算投到评测。
- **SRE**：编队调查事故 → 上游 Agent 结论错 → 级联控制在第 2 层停 → 转人工。
- **架构师**：确实需要异构（代码模型＋检索模型）→ 用 A2A 签名 Card 委托 → 记录 scope/budget。
- **审计**：抽查一次编队 → 核对协调税与级联深度 → 确认没有「默认组队」。

### 5.3 实现方案（90 天）

- **0–30 天：算账。** 给现有编队算协调税与单调用基线；标出「零收益编队」。
- **30–60 天：拆队。** 零收益编队改单调用＋路由；真异构编队补签名 Card 与预算。
- **60–90 天：控级联。** 最大深度与检查点；级联失败演练；季度复算盈亏；编队变更进发布评审。

**第 96 个市场空白（五项）**：编队成本模型可报率、盈亏平衡可计算率、交接协议成本可测率、级联深度可导出率、按任务选模型覆盖率——无一内建；`fleet.*`／`coordination.*` 为**第 63 次无人提字段族**。本地 173／173-kb 连续第 57 期成组启用：陶炳哲 30「模型与 harness 必须联合评测，看错误重叠」＝全库唯一把「组合选择」写成方法的实践，本期首次当主线；配肖汉松 22「全局调度器：分派、等待」、刘凯宁 05「结论/证据/待确认」。判词：**本地把「错误重叠」写进选型，联网侧 10 月才把「协调税 vs 异质性红利」写成闭式；两边都没把「这个编队值不值」做成上线前的必算项。**
