# 记忆技术洞察 · 第 57 期（2026-11-12 06:00）

> 本期主线：**记忆的时间方向被行业默认设为"过去式"——前瞻记忆（记得去做）成为未被任何榜单覆盖的新能力边界，且它要求一套与"检索"正交的"机会探测 / 触发"子系统。**
> 覆盖维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战 + 需求分解 · 用户旅程 · 实现方案
> 与前期分界：前 56 期全部聚焦**回溯性记忆**（发生过什么、学到什么、忘掉什么、继承什么、内省什么）；本期首次切入**前瞻记忆**（未来意图与时机触发），是往期 0 覆盖的方向。沿用第 56 期"账本 + 主权"隐喻，但反转时间箭头。

## 一、发展趋势：从"记得过去"到"记得去做"

2026 下半年记忆工程把几乎所有算力砸在回溯侧——写入质量、删除举证、状态协调、压缩保真、检索解释（第 1–56 期）。但智能体要"主动"而非"应答"，缺的是**前瞻记忆（prospective memory）**：把未来意图存下来，并在恰当机会出现时自发执行。Pro-Memory（arXiv NLP，11-05）首次把"意图留存"与"时机决策"解耦，证明这是一条独立的能力轴；趋势是从"被动账本"走向"主动议程（agenda）"。

## 二、技术现状：触发是比召回更难的一件事

回溯记忆的难题是"找得准"，前瞻记忆的难题是"**认出机会**"。即便意图存对了，若没有机会探测机制，意图永远沉睡。现状两极：① 论文侧 Pro-Memory 用经验记忆蒸馏反馈、按"实际发生的动作"更新意图状态；② 产品侧 OpenViking v0.5.4（11-09）落地了最贴近的工业形态——Rule Search：执行动作前按需查"适用规则"，把"记得遵守某约束"变成一次主动查询。二者共同点：前瞻记忆 = 意图存储 ⊕ 触发器，二者必须成对存在、缺一不可。

## 三、技术竞争力：生产侧首次反超论文侧

| 实现 | 意图存储 | 机会触发 | 形态 |
|---|---|---|---|
| Pro-Memory（论文 11-05） | 意图状态 + 经验蒸馏 | 机会出现即执行 | 训练无关框架 |
| OpenViking v0.5.4（11-09） | 规则 / 约束 | Rule Search 主动查 | 文件系统式挂载 |
| 六大记忆产品 | 几乎为零 | 无 | 全为回溯 |

结论：本系列第 56 期总结的"倒挂"（论文先于产品）在此**首次反转**——OpenViking 把"执行前查规则"做成了产品能力，而论文刚给出形式化框架。但六家记忆产品（含 Hy-Memory / TencentDB / dsh / ReMe）对前瞻记忆仍零披露。

## 四、技术挑战：当记忆变成"待办"，治理与攻击面随之翻转

① **触发器的权限**：谁能往智能体里"种"一个意图？意图 = 被调度的一次动作，本质是定时任务，落入第 54 期"记忆安全"范畴却更尖锐；② **机会误判**：把无关事件当触发条件，导致过度干预或错失；③ **评测缺口**：AML Cycle 2 能力轴 A–H 覆盖事实 / 推理 / 时序 / 治理 / 个性化 / 执行 / 安全，**唯独没有"前瞻 / 意图"维度**——这是第 56 期"口径缺口"模式的延续，只是又少了一块；④ **意图可撤销性**：种下的意图能否像删除记忆一样被举证撤回（呼应第 2 期墓碑）。

## 五、需求分解 · 用户旅程 · 实现方案

**需求**：R1 记忆系统须支持"未来意图"一等类型（intent 而非 fact）；R2 须有独立的触发器子系统（事件 / 条件 / 时机三类探针），与检索解耦；R3 意图写入须带 owner 与权限（防任意主体"种"意图）；R4 意图须可列举、可撤销、可审计（复用第 2 / 45 / 52 期字段）；R5 评测须新增"前瞻执行"能力轴。

**用户旅程（D0→D3）**：团队给客服 Agent 预置"每逢大促前 3 天提醒盘点库存"→ 第 1 期式回溯记忆只存了聊天记录，大促当天 Agent 静默无动作 → 接入前瞻记忆：意图入库存为 intent 节点，触发器监听日历事件 → 到期自动提醒，且运营可 `ls` 出所有待办意图、误植的意图可被一键撤回。

**实现方案**：以 OpenViking viking:// 为蓝本，把意图建模为带 `trigger.*`（type / condition / owner）的节点，与 fact 节点同树异构；触发器走独立轻量事件总线（不进检索链路）；权限复用第 45 期 `access_version` 与第 2 期墓碑三字段实现"种 / 撤"对称；评测仿第 56 期"账本契约"提案，给 AML 补一条前瞻执行轴。
