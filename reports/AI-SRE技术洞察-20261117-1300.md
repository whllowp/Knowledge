# SRE Agent 领域技术洞察 · 第 249 期

**主题：授权面／凭证生命周期与权限膨胀（Authorization Lifecycle & Privilege Creep）——行业把"短期凭证"当成安全的答案在卖，却没人举证"这次写操作用的凭证，权限是否恰好、授权是否还有效、事后是否真的撤销干净"：token 以分钟计，授权漂移以小时计，撤销留一半**

## 题眼

过去两百多期，本系列反复拆穿各种"看起来对"的假象：#234 说"批准不等于执行"，#228 说"检出不等于拦截"，#237 说"总量不等于分组"。本期拆的是运维控制面最底层、也最被当成"已经解决"的一层——**身份与凭证**。2026 年被业界称为"Agent 身份元年"：微软 Entra Agent ID 于 4 月 GA，AWS 推 Bedrock AgentCore Identity，Google 上 Vertex AI Agent Engine，OWASP 发布 Non-Human Identities Top 10 与 Agentic Applications Top 10（ASI03 身份与权限滥用），阿里云在 8 月把 Agent Identity＋STS 临时凭证注入做进 Agent Sandbox。签发侧几乎std工业化——**短期凭证、WIF 联邦、JIT 即时授权、轮换，样样可采购**。但 §ASI03 与一线实践同时暴露另一面：Agent 会"越用越有权"（工具为试点加上、试点结束不摘）、"删了对象没删绑定"（delete without revoke）、"长任务用着几小时前已失效的授权继续走"（Workflow Authorization Drift）。一句话立题：**短期凭证是被采购的，权限边界的可举证与撤销的完整性，从来没人做。**

## 一、发展趋势

**趋势一：Agent 身份在 2026 上半年集体升格为"一等公民"，但标准只覆盖了签发。** 微软 Entra Agent ID 于 2026-04 GA，每个 Agent 身份必须有 sponsor（对用途、访问复核、留存负责）＋owner（技术侧凭据管理）；AWS Bedrock AgentCore Identity、Google Vertex AI Agent Engine、Okta Cross App Access 相继落地。协议侧，MCP 2026-07-28 修订以 Client ID Metadata Documents（CIMD）取代被弃用的动态客户端注册（DCR），引入 RFC 8707 资源指示符做受众绑定、明确禁止 token passthrough、补上 refresh token 轮换章节。这些标准的共同点是：把"第一次怎么发凭证"讲得很细。

**趋势二：签发工业化之后，泄露与膨胀同步放大。** GitGuardian 研究显示（Descope 2026-10-25 引述）泄露密钥自 2021 年增长 151%，Claude Code 参与的提交泄露密钥概率是基线两倍；一份对 40 个团队的调查中 17 个共享凭证。OWASP NHI Top 10 把"过度授权（NHI-05）""长寿命密钥（NHI-07）""不当下线（NHI-01）"列为头号风险——**问题不是没凭证，是凭证太宽、太久、没人收**。

**趋势三：短凭证被当成"最小权限"的替身，厂商自己在文档里否认这个等号。** 阿里云 Agent Sandbox 官方帮助写得极直白：**"STS 的临时性和自动刷新不会自动收窄权限"**——真实凭证不进沙箱，但沙箱内代码仍可通过网关以关联 Role 的有效权限访问已放行的服务；不配 Session Policy，权限一点不会缩小。这是本期最强的"时点反转"素材：最短的凭证配最宽的 Role，在遥测上和最小权限长得一模一样。

## 二、技术现状

把 Agent 凭证链路拆开，能力分布是"签发强、授权中、撤销弱、举证空"：

- **签发／联邦**：已较成熟。Anthropic WIF 用 RFC 7523 jwt-bearer 把 IdP JWT 换成绑定服务账号的短期 token（60～86400 秒、默认 3600、向导默认 600、无 refresh token、单次 jti 防重放）；OpenAI 接受 OIDC JWT／SPIFFE JWT-SVID／X.509；SPIFFE/SPIRE 按分钟到小时自动轮换；AWS/GCP STS 15 分钟～12 小时。
- **授权／作用域**：部分具备。MCP 支持 403 insufficient_scope 的 step-up 授权；业界建议按工具而非按 Agent 授 scope、读写分离、先只读。但 OWASP ASI03 点名"工作流授权漂移"：采购流程开头校验了审批额度，几小时后用户额度被下调，流程仍拿着旧授权 token 完成交易。
- **撤销／回收**：最薄且不均匀。Entra 按 token 撤销、Anthropic 靠过期＋jti、云 STS 靠策略变更；但 Rohit Prabhakar 调研指出"多凭证信任缺口"——没有任何单一控制台显示一个 Agent 的全部权限，撤销后 Agent 常常部分仍可用，"删除对象却留下绑定、密钥和同意授权"。JumpCloud 把这些叫"僵尸 Agent"：用途已结束，权限还在累积。
- **举证**：几乎全空。委托链（人→Agent→子 Agent→工具）在日志里普遍塌缩成"用了哪把凭证"；`acts_on_behalf_of` 按动作记录、撤销后验证（revoke→verify）都未做成可上报字段。

现状一句话：**行业在"发凭证"上做到了分钟级，在"收凭证"与"证明边界"上还停留在人工与假设。**

## 四、技术挑战

1. **短凭证≠最小权限，等号是行业自己制造的幻觉。** 阿里云白纸黑字承认临时性与自动刷新不收窄权限；一个 600 秒的 token 若挂着 AdministratorAccess，泄露窗口短了，但爆炸半径一点没小。凭证的"寿命"和"权限"是两条独立的轴，当前发布页把它们混成一个卖点。

2. **授权漂移跨不过长任务这道坎。** token 以分钟计、授权依据（额度、审批、角色）以小时甚至天计。ASI03 的"工作流授权漂移"说明：即使每步都重新验证 token，若授权依据本身中途变了、而流程拿着旧决策继续走，凭证再短也无用。这是 #232 例行承诺"缺席二义性"在授权侧的镜像。

3. **撤销的"最后一公里"没有台账。** "多凭证信任缺口"意味着一次撤销往往只覆盖一个系统；delete without revoke 留下绑定、密钥、同意授权，等待被复用。没有 revoke→verify 的回执，"已下线"只是对象被删，不是权限消失。

4. **权限膨胀是默认方向，没有自动收口。** 工具为试点接入、试点结束不摘；Agent 用途变了、scope 没跟着收回。访问复核靠人、靠表，而"僵尸 Agent"恰好在没人认领时最容易累积权限。

5. **委托链在日志里塌缩成"用了哪把钥匙"。** 只记凭证、不记人→Agent→子 Agent→工具的链路，事后无法回答审计员"谁授权的"。attribution collapse 让所有下游追责停在最后一把 token 上。

## 五、展望与建议

- **立 `authz.lifecycle.*` 五字段并进 OTel GenAI 提案**：`credential_ttl_seconds`（本次凭证有效期）、`scope_vs_action_delta`（授权 scope 与实际动作差集）、`authorization_source_at`（授权依据时间戳与版本）、`revocation_verified_at`（每系统撤销回执时间）、`delegation_chain[]`（人→Agent→子 Agent→工具，按动作记录）。缺省 `AUTHZ_UNVERIFIED`。
- **把"收凭证"做成"发凭证"的镜像流程**：suspend→revoke→verify→archive→delete 六步，每步留回执；未经 verify 的下线不算下线。下线演练常态化——在需要之前先测一次撤销。
- **强制 scope 绑定动作而非绑定 Agent**：按工具授 scope、读写分离、默认 deny；每次上下文切换/高价值动作重新授权；敏感动作单独授权决策。
- **给短凭证配双层护栏**：Session Policy／resource indicator 把权限收窄到具体资源与动作，domain 限制做辅助；明确写进规范——短期凭证不等于最小权限，两者必须同时配置。
- **建 Agent 身份台账＋责任人**：每个 Agent 有 owner＋sponsor＋deputy，无人认领超过 14 天自动失效；用途、模型、工具、自治等级变更触发复核；台账、平台目录、活动日志按月对账。
- **基准补题**：SRE-Bench／o11y-bench 增加"短凭证但权限过宽""工作流授权漂移""撤销后部分仍可用"三类题；信通院六维可增补"授权可举证率"一格。

**新观点小结（本期相较往期的角度深化）**：往期拆过"绿"的真假，拆过"批准≠执行（#234）""检出≠拦截（#228）"。本期再切一刀，落到控制面最底层：**有身份 ≠ 有边界 ≠ 边界被刷新过 ≠ 撤销被验证过**。行业已经把"签发"工业化到分钟级，却把"授权新鲜度""权限不膨胀""撤销完整性"留给了人工与假设。把这四个状态分开，才不会把"换了短期凭证"误当成"收窄了权限"。**短期凭证可以被采购，权限边界的可举证与撤销的完整性只能被举证。**
