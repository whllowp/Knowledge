# AI-SRE 技术洞察（第 150 期）

**生成时间**：2026-11-12 12:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：发现面／目录面（Discovery / Catalog）——Agent 找不到的能力，等于不存在；目录的问题不是「有没有」，是「还算不算数、允不允许我用」

---

## 题眼

138 期讨论路由时有一个默认前提：**候选集是已知的**。可真实系统里，候选集从哪来？来自目录——工具目录（MCP）、Agent 目录（A2A 的 Agent Card）、知识目录（文档与数据契约）。而 2026 年的三组数据把「目录」从清单问题变成了可靠性问题：**109 个工具描述里 33 个可被投毒**（92 期）、**11 周里 59 个工具 7 个在版本 pin 下改变行为**（137 期）、**68% 的组织说对 Agent 高度可见、82% 却发现过未知 Agent**（146 期）。**目录回答不了三件事：谁在里面、还算不算数、允不允许我用。** 于是 Agent 的「找不到」不是能力不足，是**目录在骗它**。**目录是候选集的唯一来源——候选集错了，后面选得再对也是错的。**

## 一、发展趋势

**趋势一：发现从「人工查文档」变成「运行时检索」。** Agent 在任务中按能力描述检索目录；**检索质量直接决定它能不能完成任务**——**找不到的能力，对 Agent 等于不存在**。

**趋势二：目录从「清单」变成「带状态的注册表」。** AWS Agent Registry、A2A 签名 Agent Card、MCP 注册表都在补「版本、属主、能力声明」；**但「还算不算数」需要有效性状态，而不只是登记**。

**趋势三：权限感知的发现成为刚需。** 同一个目录，A 租户能看到 20 个工具、B 租户只能看到 8 个；**目录必须按调用者过滤，否则 Agent 会去调它无权用的能力**（121 期）。**发现阶段的越权，比执行阶段的越权更难发现**——它看起来只是「检索到了一条」。**排序腐烂：目录没坏，但排在前面的都是旧的。** 排序信号如果不含「验证时间/成功率」，**老条目会靠关键词长期占位**（134 期：旧文档更具体）。

## 二、技术现状：三种目录，三种腐烂

**工具目录：同名、重复、投毒。** 多个 server 提供同名工具；描述可抄、可改；**Agent 选中的可能是「看起来一样」的另一个实现**（92／137 期）。

**Agent 目录：卡片是声明。** A2A 的 Agent Card 说明能力与端点；**签名保证没被改，不保证真的能做**（144 期）；**卡片过期后仍被检索到**，就是幽灵能力。

**知识目录：文档与契约。** 文档会腐烂（134 期）、数据契约会漂移（142 期）；**目录里的条目还在，内容已经不成立**。

**有效性：最缺的一栏。** 目录通常只有「登记时间」，没有「最近验证时间」「弃用时间」「替代项」；**Agent 无法判断一条能力是否还活着**。

## 四、技术挑战

**一，声明不可证。** 卡片与描述都是自报；**没有探针，目录就是广告牌**。

**二，有效性无状态。** 只有「登记」，没有「验证/弃用/替代」；**幽灵条目会被反复检索到**。

**三，同名与重复。** 同一能力多个实现；**没有去重与排序，Agent 随机选**。

**四，权限过滤缺失。** 目录按「有哪些」返回，不按「你能用哪些」；**Agent 会撞权限墙**（121 期）。

**五，检索质量不可测。** 命中率、首次命中时间、错选率都没有；**目录坏了没人知道**。

**六，目录会分叉。** 多租户/多区域各一份；**同一能力在不同目录里版本不同**（142 期跨库分叉）。

**七，目录与缓存不同步。** 弃用后缓存仍返回旧条目；**Agent 拿到的可能是十分钟前的目录**。

**八，目录没有「替代项」。** 弃用一个工具，Agent 不知道改用哪个；**`replaced_by` 缺失，弃用就等于断供**。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `discovery.*` 字段**：`catalog`（tool/agent/knowledge）、`entry_id`、`capability`、`validated_at`、`deprecated_at`、`replaced_by`、`allowed_for`。
- **R2 三目录统一**：工具、Agent、知识用同一套有效性字段。
- **R3 有效性状态**：登记→验证→弃用→替代；**未验证条目降权**。
- **R4 权限过滤**：按调用者返回；无权限条目不出现在候选集。
- **R5 去重与排序**：同能力合并；排序用「验证时间×成功率×成本」。
- **R6 检索指标**：命中率、首次命中时间、错选率、幽灵条目率。
- **R7 目录审计**：季度核对「登记/验证/弃用/替代」四态；幽灵条目清零，重复条目合并。

### 5.2 用户旅程

- **平台工程师**：新工具登记 → 自动探针 → 验证通过才进可检索集 → 填替代项与权限范围。
- **Agent**：检索「重启服务」→ 返回 3 条 → 按权限过滤剩 2 条 → 选验证最新的一条。
- **SRE**：事故复盘发现 Agent 调了弃用工具 → 查目录 → 补 `deprecated_at` 与替代项 → 把检索排序改为验证时间优先。
- **审计**：抽查 20 次检索 → 核对条目有效性与权限 → 确认没有幽灵能力。

### 5.3 实现方案（90 天）

- **0–30 天：统一字段。** 三目录补有效性字段；统计幽灵条目与重复率。
- **30–60 天：加验证。** 新条目自动探针；未验证降权；权限过滤上线。
- **60–90 天：排序与指标。** 去重合并；排序含验证时间；检索指标看板；季度目录审计。

**第 101 个市场空白（五项）**：有效性状态覆盖率、幽灵条目率、权限过滤覆盖率、去重率、检索命中率——无一内建；`discovery.*`／`catalog.*` 为**第 68 次无人提字段族**。本地 173／173-kb 连续第 61 期成组启用：肖汉松 22「全局调度器：创建工单、分派给对应小队、进入等待」＝全库唯一把「派给谁」写成分派组件的实践，本期首次当主线；配朱革 15「统一权限、审计、回滚」、146 期属主。判词：**本地把「派给谁」写进调度器，联网侧 2026 年才有 Agent 注册表；两边都没把「这条能力当前有效且我有权用」做成检索前置条件。**
