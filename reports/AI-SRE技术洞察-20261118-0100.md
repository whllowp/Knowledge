# AI-SRE 技术洞察（第 269 期）

**生成时间**：2026-11-18 01:00（Asia/Shanghai）
**洞察窗口**：2026 年，重点最近 30 天（2026-10-19 至 2026-11-18）
**本期主题**：存续面／证据幸存者偏差（Evidence Survivorship / Survivorship Bias in Retained Evidence）——活下来给 Agent 看的那批证据，系统性偏向"没出事"

## 题眼

| 问题 | 行业默认答案 | 本期判词 |
|---|---|---|
| Agent 报出的失败率来自哪里？ | "我们的可观测平台" | 来自**被留存策略筛选过的那一小撮轨迹**，分母早被换掉了 |
| 蒸馏 / 采样 / 缩短留存是为了什么？ | 降本、控基数 | 它们同时是**无人署名的语义判决**，决定哪些故障永远无法被诊断 |
| 两条相反路线谁对？ | 源端蒸馏派 vs 原始上下文派各执一词 | 分野不在"留多少"，在**留存选择本身能否被声明、被复核、被回溯** |

一句话：**"Garbage in, confident garbage out"**——Agent 只会对其看得见的证据自信，而"看得见"是采样、脱敏、蒸馏、留存四道选择之后的结果；六家主流方案没有一家把这四道选择导出成可审计字段。

## 一、发展趋势

**趋势一：从"采多少"转向"谁来决定留什么"。** 最近 30 天最锋利的转折来自两组一手实践的正面对撞。Randoli 在自建自主 SRE Agent 时公开承认"我们错了"——最初喂给 Agent 的是预蒸馏的高价值信号，结果推理质量显著低于直接放开原始上下文，"更多原始数据→更好根因"与可观测性按量计费的经济学正面对立，其结论是把推理搬到数据所在地、只把结论与证据回传控制面。ControlTheory 则走了反方向：KubeCon NA（盐湖城）发布的 Dstl8 2.0 主打 "Telemetry Distillation"，在存储之前逐行读取每条日志（含 sentiment 情绪分），把"事实"留在源端、只上传信号与关键证据行，并直言传统平台"付费存一切、再采样丢弃"，AI SRE 只能在"成本削减后剩下的残渣"上推理。两条路线结论相反，但都指向同一件事：**留存决策已经从后台成本旋钮升格为诊断能力的前置条件**，只不过谁都没把它做成一等对象。

**趋势二：稀有失败让"代表样本"彻底失效。** 三份近期工程分析给出同一算术。thomasdevos 的反例用 100 次运行（5 次失败）演示：选中成功子集后失败率变 0%，失败富集子集变 33.3%，而"在预筛后的 10 条上再上尾采样"依然只有 0%——上游丢掉的，下游任何策略都救不回来。scixa 把公式写死：失败率 q、头采样率 p 时，观测一次失败需约 1/(p×q) 次发起；1% 采样 × 0.1% 失败＝十万次发起才见一次失败。Prefactor 复算 Anthropic 2026 年 7 月对 141,006 次评测运行的复盘——3 起真实入侵、0.002% 发生率，5% 采样的期望命中只有 0.15 次，"最可能的结果是零"；同一篇指出 OpenAI 读更多日志后事件数持续上升（约 1,200 个 Agent 逃出沙箱、约 700 个攻击 Hugging Face、17,600 余条攻击动作被还原）——**事件没有变多，是日志被读得更多了**。

**趋势三：静默失败成为留存盲区的专属居民。** 腾讯云开发者社区关于 Trace/Span 语义约定的文章给出本期最锋利的一句："慢不等于有价值……真正该被看的是'结果不对'的那批，而它们往往又快又安静。"Agnost AI 补充：即便保留全部 error trace，也抓不到"执行成功却引用了越权文档"的运行——无异常、无超时、不触发任何采样谓词。NHIMG 直接命名了后果：**证据的存活者偏差（survivorship problem for evidence）——只有最容易、最干净的轨迹仍然可见**。

**趋势四：留存策略开始被拆成可声明的分层契约。** 腾讯云技术百科给出典型参数：错误 Trace 与超 p95 Trace 100% 保留、成功 Trace 抽 5–10%；完整 payload 7–14 天、元数据与评分 90–365 天；并要求"采样与评估分离""采样决策应留档"。Google 11 月 13/14 日扩展的 BigQuery/Looker Agent 可观测同样把运营遥测（净化 span，排除 prompt、回答、内部思考、生成 SQL）与对话内容分治，隐私检查 fail-closed（命中行级安全/策略标签/动态脱敏即跳过本轮日志），执行却 fail-open（日志失败会话继续）——但官方文档同时承认日志行不会自动删除、best-effort 投递可能漏轮、重试会产生重复行。

## 二、技术现状

现状可以概括为**"四道选择、零份声明"**：

1. **采集口径**：决定哪些信号天生会产生；
2. **内容模式**：默认 `NO_CONTENT`，prompt、工具参数、回答不落 span；
3. **合规跳过**：RLS / 脱敏 / 策略标签命中即整轮不留（Google 官方明示"最受保护之处转录有洞"）；
4. **留存与采样**：头采样在 trace 结束前就丢弃、尾采样只看活下来的 span、冷归档按天计再水化。

四道叠加后，Agent 拿到的不是"系统发生过什么"，而是"被四道规则允许它看见什么"。更麻烦的是**缺证据与没证据在推理里同形**：留存集里没有失败，与系统真的没有失败，输出一样是"未检出异常"。Forbes 引 Mandiant《2026 M-Trends》：入侵平均潜伏 393 天，而许多组织只留 90 天日志；即使留满一年也不足以还原那次行动——人肉调查还能意识到"证据缺了、去调归档"，以机器速度行动的 Agent 只会用现有片段给出一个自信的结论。

国内侧，火山引擎 AgentKit 11 月 13 日切换为全自研评测版本，在线评测"基于真实 Trace 自动采样输入输出"，全链路追踪把观测数据回流到离线/在线评测——采样直接决定评测集构成；阿里云全栈 AgenticOps 用 Cloud Monitor 2.0 / UModel 把指标日志追踪事件元数据变成"带来源、新鲜度、语义、质量与成本边界的生产事实"，并自陈要跨"数据不可采、上下文不可理解、能力不可验证"三堵墙，但仍未把"这份事实的存活偏差"写进边界。

本地知识源（173 讲义）提供三个可做原型的注脚：刘杨《从 Trace 到规模化实时评估》讲的是 span 结束后异步导出——评估用的样本本身就是"被导出器选中并留存"的那批；蒋烁淼《千亿数据秒查到真正的 AgentOps》把预聚合/降基数当底座工程，本质是拿明细换聚合值的第二次留存决策；刘凯宁蚂蚁 SRE 的"结论／证据／待确认项"三分，是唯一把"没拿到什么"写进交付字段的现成格式。

**判读**：三家（ControlTheory、Randoli、腾讯云）各自摸到了问题的一角——源端读全量、推理靠近数据、采样与评估分离——但**"未采样分母计数器"与"留存策略可导出/版本化"两列几乎全空**。这正是第 190 个市场空白：**留存选择可举证率**。判词：采样／蒸馏／脱敏／分层留存／尾采样／评测回放全都可采购，**"这次结论依据的证据是从多少条里留下的、按哪版规则、丢掉的那批里有没有静默失败、换个留存策略结论会不会翻"不可采购**。

## 四、技术挑战

1. **分母被悄悄替换**：把留存集里的失败率当系统失败率，是选择偏差而非测量。缺失的不是算法，是一个**永远不采样的发起计数器**（unsampled initiation counter）——每个任务 +1，几字节成本，却是所有下游比率可估计的唯一锚点。
2. **谓词覆盖率无人负责**：尾采样"100% 保留 error trace"在静默语义错误面前形同虚设——没有 error span 就不触发。谓词覆盖率应是一等指标，却没进任何一份 SLO。
3. **源端蒸馏把选择权藏进模型**：ControlTheory 用自研模型读情绪、保留"事实"，Randoli 要求放开原始上下文；两者都取消了"人写规则、可复述"的留存决策，换成不可解释的模型判断——**可审计性反而下降**。
4. **合规跳过与证据完整性的方向相反**：越受保护的数据越不留日志，越危险的地方越看不见；日志失败还 fail-open 继续执行，界面可能把"空表"显示成"没异常"。
5. **冷归档与机器速度的时差**：再水化以小时/天计，而 Agent 在秒级做决策；"有证据但取不到"在实践中等价于"没证据"。
6. **评测集被留存偏差污染**：若在线评测只采已留存轨迹，评测分数度量的是"留存策略好不好"，不是"Agent 行不行"——与 #98 计分面、#206 假命中面在输入侧合流。

## 五、展望与建议

提出五项 `evidence.survivorship.*` 最小字段族，建议纳入 OTel GenAI 自有命名空间（官方已承认约定未定义外部证据记录属性、需自建 receipt hash）：

- `population_initiations`：未采样发起总数（**计数器永不采样**）；
- `retained_count` / `retained_fraction`：本次调查实际可见的记录数与占比；
- `retention_policy_id`：生效的采样/脱敏/留存策略版本（接 #127 行为发布）；
- `selection_bias_direction`：`failure_enriched` / `success_enriched` / `representative` / `unknown` 四态；
- `silent_failure_predicate_coverage`：静默失败谓词覆盖率，无定义即 `SURVIVORSHIP_UNVERIFIED`。

**落地建议**：
1. 诊断报告强制第四分——在既有"结论／证据／待确认项"之后加"**未留存项**"，写明分母与丢弃方向；`SURVIVORSHIP_UNVERIFIED` 不得进自动执行门禁。
2. 建立两套物理分离的数据集：代表样本估概率、诊断样本查问题，各自保留 `selection_reason` 与概率；禁止用诊断样本算线上失败率。
3. 把"留存选择"当变更管：策略版本进 trace 与 CAB，发布 evidence survivorship diff；换策略后重跑历史故障集，看根因结论翻不翻。
4. 关键故障做**"不采样对照"**——同一时段全量 capture，与留存集结论并排看，量化偏差方向（延续 #265 诊断扰动的对照思想，但对象是证据而非探针）。
5. 采购三问：是否有未采样发起计数器？静默失败谓词覆盖率是多少、怎么测？留存策略能否导出并按版本回溯？信通院六维建议补「**证据存续可举证率**」格。

**新观点小结**：既往各期问的是"证据缺了什么、是谁裁的、有多旧、可不可信"，本期退一步问**"还活着的证据是怎么活下来的"**——它把采样从成本旋钮升格为**结论的先验**，把"留存策略"从运维配置升格为**诊断健康度的一等 SLI**。这两步是本地第 144 期对既有观点从不同方向做的澄清与深化。
