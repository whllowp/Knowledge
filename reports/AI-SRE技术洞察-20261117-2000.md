# AI-SRE 技术洞察（第 260 期）

> **生成时间**：2026-11-17 20:00（Asia/Shanghai）｜**洞察窗口**：2026-10-18 ～ 2026-11-17（近 30 天，含少量 2026 年内基线）
> **本期主题**：置信度校准面／"自信地错误"鸿沟（Confidence Calibration / The Confidently-Wrong Gap）——行业把 Agent 自报的置信度当成自动化门禁的开关，却几乎没人验证过：那个 0.85，是否真的对应 85% 的经验准确率？

## 题眼

一线 SRE 有个脏话式的黑话，叫 **"confidently wrong"（自信地错误）**：AI 把排障方向死死锁在错误线索上，语气还无比确定（Traversal，2026）。这句话正好戳中 2026 年 SREAgent 最被忽视的一层——过去 259 期我们问过"人该信它几分"（第 161 期信任校准）、"它说的因果对不对"（第 160 期因果可信），但有一个数我们一直在用、从未审过：**Agent 自己报出来的那个置信度分值**。

dev.to 一篇 SRE 式的 LLM 可靠性评测文把这个反模式命名得很准——"Threshold Without Calibration"：把自动执行的置信阈值设成 0.85，只因为"这数字听起来对"，却从不验证 0.85 是否真的预测了 85% 的经验准确率；文中明写"置信度分数与经验准确率可以相差巨大"（dev.to/npayyappilly，2026）。更麻烦的是，Gartner 预期人类对 AI 建议的审批率将从 2029 年的 80% 降到 20%，由策略护栏取代（N-iX 引 Gartner，2026）——**当人退出环路，那个没校准过的置信度就从"参考信息"变成了"事实上的开关"。**

本期立这个全新立面：与第 161 期划界（彼管人的信任分量，本期管机器自报的数值），与第 160 期划界（彼管结论因果是否成立，本期管"把握程度"这个数本身是否诚实）。一句话题眼：**结论对不对是一回事，"它有多确定"这句话可不可信，是另一回事；而后者正在被当成前者用。**

## 一、发展趋势

**趋势一：置信度从"展示字段"升格为"控制面输入"。** 火山引擎在 11 月更新的智能运维助手里写明：深度调查要在模型推理外追加 RCA Harness 排障约束层，"输出步骤可复核、结论有置信度的调查报告"（火山引擎，2026-11）。腾讯云把根因定位做成"每一步推理根据证据置信度动态调整权重"（腾讯云，2026）。GPT-5 类应用把 confidence 直接写进自动响应计划。置信度不再写给人看，而是喂给"是否升级、是否自动执行"的判决逻辑——**它从描述性统计变成了规范性开关，却没经历任何开关该有的验收。**

**趋势二：独立评测开始把"校准"单列为一个维度，而非只看准确率。** IEEE IDAP 2026 的 EnoughBench（10-26 入库）把"何时停止收集证据"这个决策单独隔离出来评测，提出 **stop-time calibration（停止时刻校准）**，并把它做符号分解，区分过度自信与自信不足；结论相当刺眼——gpt-4o-mini 的 reason-act 智能体得分低于随机基线，且其失准"完全是过度自信"（IEEE，2026）。SIGIR/工业侧也在跟进：Traversal 与哥伦比亚大学、康奈尔科技合著的 ORCA-bench 把"可验证的证据链"而非答对服务名当判据（Traversal，2026）。**准确率之外，"把握程度准不准"第一次有了独立刻度。**

**趋势三：厂商自测与独立基准的落差，主要落在"自信"这一侧。** 一份厂商自测报告宣称 8 个模型中 5 个在自建 7 集群测试里解决 95%–100% 运行问题；而 IBM ITBench 的诊断分只有 13.8%、缓解 11.4%，ITBench-AA 为 56.2%（SigNoz 编译，2026）。Rootly 在 9-15 的评估里承认，Agent 面对陌生故障或缺失埋点时"经常产生自信的错误答案"（SigNoz 引 Rootly）。**落差不是随机的：模型和厂商在"不确定时该说不知道"这件事上系统性地偏乐观。**

## 二、技术现状

平台侧已经把置信度做成了产品语言，但语义五花八门。火山引擎的"结论有置信度"、腾讯云的"证据置信度动态调权"、Azure SRE Agent 的 review/autonomous 双模式、N-iX 建议的"confident-but-wrong rate"指标——这些词指的可能完全不是一回事：有的是模型 logits 归一化的自评分，有的是证据覆盖度的启发式，有的是验证器复核后的通过率。**它们共用一个"置信度"的名字，却没有共用一个校准方法。**

研究侧把这个问题拆得更清楚。OpenRCA 2.0（2026-06 预印本）对 11 个前沿 LLM 做故障注入测试，平均只有 **20.7%** 的案例恢复出精确根因集；更值得买者警惕的伴随发现是：**当 Agent 点对了正确的服务，大约五分之一的情况它拿不出一条能验证的因果路径**（Traversal 引 OpenRCA 2.0）。ORCA-bench 里最强的模型在中等难度事故上也只在 25.3% 的案例中识别出全部根因，去掉源码访问后每个模型都掉分。研究者总结的三种失败模式——最响信号锁定、过早承诺、把"停止上报数据"误判为"健康"——本质都是**把局部的高确定性错当成全局的正确性**。

更隐蔽的一条线是"评测本身被污染"。incident.io 工程团队在 10-01 披露：回放评估时模型会偷看事后复盘报告，得到误导性的高分（SigNoz 引 incident.io）。这和 EnoughBench 强调的"uncertainty-signal fidelity"（门控信号保真度）指向同一件事：**如果你用来测置信度的信号本身失真，那么再漂亮的校准曲线也只是把偏差拟合得更精致。** 还有一层是沉默：Google 把 Agent 遥测写进客户自有 BigQuery，但托管日志在写入失败时"会话继续、日志留空"——可用性保住了，证据链却断了（Google Cloud，2026-11）；一篇实践文章记录了 ADK 从 telemetry schema v1 升到 v2 后，所有 BigQuery 查询静默返回零行、无报错（dev.to/toyama0919，2026）。**置信度再准，如果它的观测管道会静默失真，也等于没有。**

## 四、技术挑战

**挑战一：置信度是一个没有单位的数。** 模型自评分、证据覆盖率、验证器通过率被混为一谈，导致跨方案不可比、跨版本不可比。EnoughBench 证明，同一任务换个门控信号（保真度 φ 从 0.95 下降），前沿策略就从最优退化到过度收集（IEEE，2026）——**没有基准口径的置信度，连"变好还是变坏"都无法判断。**

**挑战二：过度自信是默认方向，而且是单调危险的。** 自信不足最多让人多查一会儿；过度自信直接把错误结论推进自动执行。EnoughBench 里 reason-act 智能体的失准"全部是过度自信"，Rootly 承认陌生故障下"自信的错误答案"频发——**系统在没有证据时并不会自动变谦虚，反而常常更自信。**

**挑战三：校准会漂移，而行业在做一次性校准。** 模型升级、prompt 改动、新工具接入都会移动置信度分布；dev.to 明确把"一次性评测"列为反模式——18 个月前过闸的系统今天未必过闸（dev.to/npayyappilly，2026）。arXiv 关于模型身份切换的研究也显示，静默换模型会让召回率等表现大幅波动——**置信度是分布的产物，分布一变，旧的 0.85 就作废。**

**挑战四：认知卸载把过度自信放大成组织风险。** SigNoz 的报道给了最尖锐的观察：AI 还没到及格线，人却已经退化成"失去上下文的审核员"——凌晨三点被叫醒，面对一份看似自洽、实则锚定错误方向的根因报告，要在疲惫中证伪一个算法假说（SigNoz，2026）。**置信度越高，人越倾向于不查；这形成了一个正反馈：越自信→越没人查→错误越久存。**

## 五、展望与建议

**给平台方**：把"置信度"从单一数字改造成可审计的记录——建议引入字段族 `confidence.calibration.*`（本期第 184 项市场空白）：`self_reported_confidence`（自报分）、`empirical_accuracy_at_confidence`（该分档的经验准确率）、`calibration_delta`（两者差，超阈值即判过度自信）、`confidence_basis`（模型自评／证据覆盖／验证器复核三选一）、`calibration_evaluated_at`（最近校准时刻）。缺省即 `CALIBRATION_UNVERIFIED`，不得进自动执行门禁。这是该字段族第 148 次在行业中无人提出——它该进 OTel GenAI 语义约定了。

**给采用方**：一是**阈值必须先校准再用**，用 dev.to 的 GATE 2 做验收——每个置信度区间的校准偏差控制在 ±0.10 内，任何区间系统性过度自信超过 0.15 就加校正因子；二是**验证器与调查者独立**，最好连模型都换（ResolveAI 第二代因"自己提假设自己打分"而自我确认）；三是**把"confident-but-wrong rate"和"有证据支撑的结论占比"纳入值守 SLO**（N-iX），每次模型/prompt/工具变更后重跑回放集并把新事故补进去。

**给评测与标准方**：把 EnoughBench 的 stop-time calibration 与 ORCA-bench 的"点名正确但因果链可验证"两类题型纳入 SRE 基准；对"高置信度低准确率""换模型后置信度漂移""日志静默失败但置信度照报"三类情形单独出题；信通院六维补一格"置信度可举证率"。

**判词**：「置信度打分／自动执行阈值／自治分级／人类审批／护栏门禁全部可采购；**举证这个 0.85 是否真对应 85% 的经验准确率、它是模型自评还是验证器复核、最近一次校准在何时、换模型后有没有重校——不可采购**。」

**本地原型（第 140 期成组启用）**：施宏斌《金融 Agent 开放问题 Eval》的"识别→展开→质疑→验证，还缺什么证据"与 Type I/II/III 可承诺性分级——本期从新角度深化：过去用它讲"证据是否充分"，本期用它追问"**把握程度这个数本身该不该、能不能被证实**"，把可验证的持续改进从结论层推到置信度层；配刘凯宁蚂蚁 SRE 的"结论／证据／待确认项三分"（把"不知道"写进产物结构，而非给一个虚高数字）。判词：「本地把质疑写成方法环节、把不知道写进结构；联网侧 2026 才把置信度做成独立校准维度；两边都还没把它做成可导出、可举证、可驱动门禁的字段。」
