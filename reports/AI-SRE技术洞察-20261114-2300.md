## 一、发展趋势
1. **从「仪表盘即服务」走向「数据主权即默认」**：2026-11-14 Google Cloud 将 AI agent 可观测与治理延伸到 BigQuery 与 Looker，把自有及第三方（ADK/LangGraph）agent 的 trace、成本、准确性遥测**写入客户自有 BigQuery 表**，使 Google Data Cloud 成为 agent 追踪／成本／准确性的系统归属（system-of-record）。这是行业首次把「遥测归属权」作为默认能力而非导出选项。
2. **标准层仍在 Development**：OTel GenAI 语义中 Agent/Tool/MCP 的 span 定义截至 2026-11 仍未 stable，字段名与语义可能变——你今天建在厂商库之上的看板，明天要改。
3. **评估与被观测「两套仓库」**：即便 Google 也才刚开始把 accuracy 遥测并入 BigQuery；评测/真值数据仍大多锁在厂商 eval 平台，与原始遥测割裂，无法联合审计。

## 二、技术现状
- **Google**：ADK 内置 OTel GenAI 导出 Cloud Trace；提示词/响应用 Cloud Storage 分离存储（不进 trace，合规默认）；11-14 后 telemetry 落客户 BigQuery，可 SQL 直接查。
- **OpenAI**：11-09 Agents API 默认全追踪（beta），trace 可 OTLP JSON 导出至「团队自有可观测栈」；Sessions 持久跨轮次并压缩；项目级 data residency + 零数据保留可选。
- **Anthropic**：10-14 OTel tracing 公测，GenAI semconv 覆盖 Messages API/Managed Agents/SDKs，metadata-only 默认（合规优先），不自建 SoR，纯导出。
- **阿里**：ARMS「AI Agent 可观测」推理轨迹视图、多 Agent 适配；AgentLoop 全栈观测→效果评估→持续优化→实验回测数据飞轮（Agent-as-a-Judge>90%）；数据底座为阿里云 SLS/ARMS/STAROps/UModel。
- **腾讯**：TCOP「用可观测管 AI」把模型能力/Token/工具调用/任务质量同屏；CloudQ 全景图谱（资源·关系·状态·处置动作同图）托管于腾讯云；受控执行+人工确认门控。
- **字节**：火山 AgentLoop 运行观测/离线评测/实验对比/质量分析，Coze Loop 评测引擎，数据回流入评测集与 TOS；支持 Codex/Claude/Trae 等 Coding Agent 会话与 Trace 分析。

本地原型（连续第 95 期启用 173/173-kb）：08 刘杨「以 Trace 为中心的实时评估+Token 级定位」印证——光有完整 Trace 仍判断不了 Agent 做没做对，可观测下一站是评估，而评估的事实基础正是「谁拥有那条 Trace」；23 蒋烁淼「统一目录补服务语义与知识」揭示 AgentOps 若只堆智能体而无统一语义目录仍难落地；31 马云雷「轨迹即数字资产」、03 余锦泽「Agent 记忆与本体」共同指向：轨迹/知识要可被自有体系长期沉淀、查询、复用，而非锁死在厂商闭环。

## 四、技术挑战
1. **系统归属缺位＝事故复盘权外包**：当 agent 在生产做不可逆操作，若 trace 只能在某厂商控制台回放，责任边界与合规下限被厂商可用性绑架。
2. **度量主权与数据主权割裂（深化 #185）**：eval/真值数据多在厂商 eval 平台，与原始遥测分仓，无法在同一仓库做「观测×评估」联合审计。
3. **跨厂商 AgentID/人工审批记录非一等字段**：MIT Technology Review 指出主流框架缺持久 agent id 与「谁批准了这次操作」记录，无法重建「哪个 agent、哪次人审、为何」的责任链。
4. **标准未 stable**：GenAI span 字段仍在 Development，自建 SoR 的 schema 漂移风险高。
5. **隐私-归属张力**：full-content 归因强但泄 PII；metadata-only 合规但归因弱（呼应前期）。

## 五、展望与建议
- 把「遥测归属权」列为采购一等指标：默认要求 trace/cost/accuracy 可写入客户自有数仓（BigQuery/Snowflake/自研），而非仅厂商仪表盘。
- 推动 `obs.custody.*` 字段族成为 OTel 扩展：telemetry_ownership / system_of_record_queryable / eval_accuracy_portable / agent_id_persistent / human_approval_recorded——**第 136 个市场空白**，六家仅 Google 在首两项达标。
- 评估与被观测同仓：将 #185 的度量主权与本期数据主权打通，使「谁定义尺子」与「原始事实归谁」在同一仓库可被独立审计。
- 跨厂商委托链：在 W3C traceparent 之外约定 agent.id 与 approval 记录的传播标准，否则多 agent 协作的归因断点仍在。
- 信通院六维基准补「系统归属率／可携出率」两格，倒逼厂商开放数据主权。
