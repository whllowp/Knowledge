# 第 195 期（2026-11-15 00:00）· 自治态面 / 权限动态调度面（Autonomy-State / Dynamic Authority Scaling）

> 期号说明：11-15 00:00 档生成；索引最新本方为第 194 期（11-14 23:00《可观测数据主权面》），本期顺延第 195 期；往期 194 标「第 136 个市场空白」，本期顺延为 137；主线记作**第一百七十二条全新立面**。

**题眼**：2026 年所有厂商都在讲"自主执行 / 自愈"，却把"自治等级"当成写在文档里的静态配置（L0–L4）。真正的运维风险发生在等级**迁移**的瞬间：事故升级时谁把 Agent 从"建议"提到"执行"？事故平息时谁把它降回"建议"？这条迁移链没有 SLO、没有审计、没有回退——于是"自主"要么被冻在 L0（等于没上），要么被一次误判永久推到 L4（出事后才发现没护栏）。六家厂商"自治等级迁移 / 降级触发 / 动态护栏 / 升降级 SLO"四列全空。

## 一、发展趋势

1. **从"定义等级"走向"让等级可迁移"，但只做了前半句。** 腾讯云把 AIOps 拆成三层，第三层正是"多智能体协同的自主执行"；阿里 STAROps 给"危险动作需审批"；Daimler 多智能体自愈 TTR −88% 却仍开 PR 交人批。行业共识是"该自主的自主、该拦截的拦截"，但没人定义**等级之间怎么换人**。
2. **托管与执行分离让"降级"第一次成为可能。** Anthropic 11-12 自托管 Managed Agents 把执行框架、沙箱、凭证三层分离，主机白名单只放行 git 主机与包仓库；朱革（百度）AgentOps 控制面/数据面分离。执行可分离，意味着等级可被外部收回——但收回动作本身仍是硬编码。
3. **评测与反馈正在成为"自治等级的投票权"。** 阿里 Nightly Evals 用 Golden + LLM-as-a-Judge 决定自治等级；携程用"灵魂三问"现场检验（能否引用实时指标/安全执行验证/推动成本落地）作为升级门禁；肖汉松（蚂蚁 阿福）的"先 Harness 后 Loop"本质是：**单次迭代结果不可信时，持续流转只会放大错误**——可信度没达标，自主权不该放大。
4. **跨期定位**：与 #161 人机信任校准（管"人信它的分量对不对"）分工——本期管"等级迁移这个动作本身是否可观测"；与 #95 收容 / #88 转授 / #97 组合（管静态授权范围）分工——本期管"范围之内的等级如何随态势升降"；与 #117 失效姿态（管降级时不可信）分工——本期管"降级是被设计出来的，还是崩溃逼出来的"。

## 二、技术现状

各家当前对"自治态"的处理可概括为一句话：**有等级、无迁移；有审批、无态势；有兜底、无 SLO。**

- **Google**：ADK 内置 OTel GenAI 约定、导出 Cloud Trace；11-14 再把 agent 可观测/治理扩到 BigQuery & Looker（遥测写客户自有表）。但自治等级靠应用层约定，trace 记录"做了什么"，不记录"当时是 L2 还是 L3"。
- **OpenAI**：11-09 Agents API 默认全追踪 + OTLP 导出 + Sessions 持久 + data residency；Sevbot 只建议不执行。等级由开发者写死，迁移不可观测。
- **Anthropic**：10-14 OTel tracing 公测；11-12 自托管 Managed Agents 把执行框架/沙箱/凭证分离、主机白名单、每步动作 OTel 导出。等级迁移仍由宿主应用硬编码，无 SLO。
- **字节（火山）**：AgentKit A2A 中心编排、VeOps Agent 默认启用、AI 应用监控集成 OpenCode/OpenClaw/DeepSeek。bash 60s 转后台、Session 保持 running 改写"忙碌/空闲"语义——**自治态藏在 session 状态里，无显式等级字段**。
- **阿里**：UModel 语义运行时 + STAROps 危险动作需审批 + Skills 内置 Schema 校验避免误配。审批是**动作级**，而非态势级。
- **腾讯**：CloudQ"用可观测管 AI"、Buddy AI Diagnose 给根因+建议+反馈监督学习、ADP 4.0 AgentOps + Seeker。三层 AIOps 第三层喊"自主执行"，实践仍以建议为主。

**本地原型**（第 95 期组合）：周昕毅（携程）L1–L3 演进，**L3 数字分身不可逆动作仍由人工负责**；朱革（百度）直言**生产写操作缺统一权限/审批/限流/审计/回滚是规模化最大拦路虎**；刘凯宁（蚂蚁）"确定性笼子"= 工程交给工程、大模型交给大模型、**约束只拦不改写**；肖汉松（蚂蚁 阿福）"先 Harness 后 Loop"= **不可信不放大自主权**。判词：「审批」「白名单」「沙箱」「回滚」全部可采购，**「举证这次自治等级迁移有 SLO、可回退、被审计」不可采购**。

## 四、技术挑战

1. **等级迁移无 SLO**：从"建议"到"执行"的升级延迟、回退延迟都没有目标值，故障时手忙脚乱临时拍板。
2. **迁移不可观测**：谁在什么时候把 Agent 提到 L3、基于什么信号、有没有回退，trace 里查不到（呼应 #188 轨迹归属、#183 时序保真）。
3. **降级是被崩溃逼出来的，不是设计出来的**：#117 失效姿态——系统没宕、只是慢慢不可信时，没有"自动降级到建议态"的触发（肖汉松的"不可信不放大"是人工规则）。
4. **审批是动作级，不是态势级**：阿里 STAROps / 携程白名单管"这个动作要批"，但"整体态势恶化要不要把整个 Agent 降到只读"没人管。
5. **评测与等级脱节**：阿里 Nightly Evals 定等级，但评测挂了 Agent 不会自动降级（呼应 #185 度量主权、#190 生产侧评估）。
6. **跨厂商/跨 Agent 等级不一致**：A 厂商 Agent 在 L3、B 厂商 Agent 在 L1，同一事故里协同，谁听谁的（呼应 #144 编队面）。

**第 137 个市场空白五项**：自治态迁移 SLO 覆盖率、降级自动触发率、迁移可观测率、态势级审批覆盖率、跨 Agent 等级一致率；`autonomy.state.*` / `auth.scaling.*` 为**第 106 次无人提字段族**。

## 五、展望与建议

- **把 `autonomy.state.*` 做成 OTel / 评测一等字段**：`current_tier` / `last_transition` / `transition_trigger` / `downgrade_slo` / `escalation_approval`。
- **升降级当成"动作"而非"配置"**：每次迁移生成一个 span，带触发信号与回退点（接 #183 时序保真、#184 续跑）。
- **态势级降级触发器**：基于评测分数 / 置信度 / 异常率自动降级到建议态（接 #185 / #190）。
- **评测挂 → 自动降级**：把 #185 度量主权与自治态联动，评测失准即收回自主权。
- **跨 Agent 等级仲裁**：编队里设"最高权限取最低等级"或显式等级协议（接 #144）。
- **信通院六维补"自治态迁移达标率"格**。
- **本地原型映射**：周昕毅 灵魂三问 = 升级门禁；朱革 全生命周期托管 = 等级生命周期；刘凯宁 确定性笼子 = 降级兜底；肖汉松 不可信不放大 = 评测驱动降级。
