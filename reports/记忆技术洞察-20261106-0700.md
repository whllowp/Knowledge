# 记忆技术洞察（第 5 期）· 记忆的净现值——当"记忆税"超过"记忆收益"

> 覆盖窗口：2026-10-07 — 2026-11-06（重点 10-27 — 11-06）
> 固定对象：dsh-memory-evolve、Hy-Memory、TencentDB Agent Memory、ReMe（ReMe2Ops 路径）、OpenViking
> 本期判据：前四期问"记忆能不能做对"，本期问"记忆值不值"。

## 一、发展趋势：叙事从"记得更多"翻到"记得更值"

三个信号同时出现，指向同一件事。

**产品层已经过剩。** 十六天内七家发记忆产品：Databricks MemCurrent 与 Autopoetic（10-20）、阿里云（11-02）、Hindsight（11-03）、Redis Iris、MongoDB+Google ADK、PhoenixAI Contextbase（11-04），加 Unibase Membase 的跨工具共享记忆。形态分三派且互不兼容——记忆即存储、记忆即管道、记忆即判断。当形态都统一不了，竞争就不再是"谁记得更多"，而是"谁更便宜地记得住"。Databricks 的口径已经变了：通过率 3 倍、token 少 31%，效果与成本必须成对报。

**评测层开始分叉。** AML 首期 136 队注册、69 框架完成评测：MemoraX 58.0 七维第一，MemOS 第二，网易 NTES-MEMORY-SMART 第三（个性化 57.0），腾讯云 TencentDB 41.5 第八（"规则与工作流执行"28.7 为工业榜第二），Mem0 第九；而 MemoraX 自述 Coding 轨 62 分。同一系统、两套口径、差 4 分——比价之前先要比口径。同期 AML 连发三篇方法论，主题已从"检索精度不够"转向"陈旧与冲突上下文"。

**研究层集体转向负收益。** 本月最集中的不是"更强记忆"，而是"记忆的代价"：Memory Tax（UIUC+清华）、RAW-RAG、MemoryTax、REM（Amazon）、AKV（清华）、Anti-Persistence（Indiana）。六篇独立工作指向同一结论——**加工本身有代价，且经常大于收益**。

判断：主线已从"记忆能力"切到"记忆经济学"。这不是降温，是类目成熟的必经一步。

## 二、技术现状：钱花在哪，税从哪来

### 2.1 成本不在存储，在"判断"

记忆有三处成本，行业通常只报第一处：**构建/判断**（这条要不要记、记成什么，模型调用最密集处）、**驻留**（存储 + 每次注入占用的上下文位）、**检索**（召回、重排、多跳）。

TencentDB 的公开价是 0.02 元/万条·小时（存储）+ 0.01 元/Credit·小时（模型调用），两项并列，业内仍属少数。多数方案只讲"存储便宜"，把判断成本藏进"异步管道"。

SLICE-Mem（港理工 + 华南理工）给出了判断成本的量级：把"值不值得记"从 LLM 换成轻量显著性分类器，抽取改用句法分析（谓词 + 论元），模型只留到事后清理。Memora Weekly 上 46.60 对 MemOS 46.68（打平），token 0.536M 对 7.009M（−92.4%），构建时间 2.378h→0.362h；LongMemEval-S 56.8 对 59.3（−2.5pp），token −99.5%。含义直接：**写入侧的模型调用是过度配置**——用 20 倍成本换 0.08 分，任何真实预算下都不成立。

### 2.2 记忆税：构建动作本身有损

Memory Tax（He 等，UIUC + 清华）做了本月最该读的实验：11 个开源记忆系统 × 3 基准 × 3 骨干，统一嵌入模型，并用 Retrieval Scope 把各系统暴露的 token 归一化到不低于朴素检索——先给对手松绑再开赛。

LongMemEval-s 上（Qwen3.6-27B 骨干）：两轮 RAG 81.4%，最高的 A-Mem 79.4%，MemOS 76.6%，OpenViking 58.8%。**11 个系统无一跑赢两轮 RAG**；99 组对照 90 组为负。税拆三条：

- **保真**：抽样追踪事实在记忆单元中的无损留存率，MemoryOS 98.4%，OpenViking 39.4%；38.0% 的抽样事实无对应单元——抽取器没写下，检索器就永远找不到。
- **可达**：保住了却被切碎、稀释、改写，第一轮命中率普遍低于原始 chunk。
- **脆弱**：换骨干重建或读取，波动均大于 RAG。

最硬的证据不是分数，而是**金标对照**：即便直接喂"含答案的那条记忆单元"，效果仍不如喂"含答案的原始轮次"——损耗发生在构建动作本身。修复方案轻得意外：source augmentation（记忆照常检索，同时从原始历史再捞一把合并重排）+ 递归检索。这与 Redis 2026 年的数据同向：仅提炼记忆 71.2%，原始片段 + 提炼事实 86.1%（+14.9pp）。

### 2.3 写入者设定天花板

Peng 的实验给出一个此前没人明说的约束：Zep 图由 GPT-4o-mini 写入后，读取侧从 GPT-4o-mini 换到 Claude Opus 5.5，分数只有 43%/43%/45%。**更强的读者救不回更弱的写者漏掉的东西。**

这修正了第 1 期"写入侧独立化"的乐观解读。写入独立化的真实后果不是"分工"，而是**价值上限在写入那一刻被钉死**：写入模型能力、schema 粒度、抽取取舍共同决定库的天花板，之后所有读取侧优化都是递减收益。构建成本因此不是可省的开支，而是决定上限的资本支出——但省它有明确上限（见 2.1）。Peng 另给了一个成本反例：Mem0 单独构建一次花 $25.88，同一模型跑全量上下文只要 $17.84，最终都到 95%。**构建成本可以高于"不建记忆"的总成本。**

### 2.4 缓存：记忆优化与账单的反向

The Hidden Costs of Forgetting（arXiv:2610.35496）做了 42 种删减配置、9,400 次 SWE-bench Verified 运行：延迟删除（保留最近两轮完整）在 37/42 配置保住效果，立即删除显著掉效果。掉效果的方式是**代理反扑**——工具输出被删，agent 直接重读文件，轮次暴增（Trae 删 100% 工具输出后轮次 +73%），重取率最高 10.6 倍。

账单更反直觉：平价格下 26/42 省钱；**缓存感知定价下 0/42 省钱**。因为改动旧轮次会让其后所有 token 的前缀缓存失效，丢掉 90% 折扣，压缩后的请求反而贵 5—10 倍（缓存读按基础价 10% 计、写按 125—200% 计）。一次会话中途的技能安装就足以击穿全体活跃会话的前缀。Manus 把 KV-cache 命中率称为生产级 agent"最重要的单一指标"，不是夸张。

第 2 期问"有没有权删"，本期补第三问：**删了划不划算**。

> NPV(forget) = 省下的前缀 token − 重取成本 − 缓存重建惩罚 − 精度损失

这个式子经常为负。合理的结论不是"不要删"，而是"**在会话边界删，不在会话中途删**"——把删除放到缓存本就要失效的时刻，是唯一不需要额外付费的窗口。

### 2.5 正确的压缩层位在 KV，不在文本

Cache Engineering for Agents（清华，arXiv:2610.28577）绕开了这个矛盾：让 agent 直接改 KV cache——drop 把条目排除出后续注意力，repos 调整保留键的位置编码。因相同 token 可映射到不同 cache 状态，前缀匹配不再充分，于是配一套无状态 API + 有状态复用的引擎 AKV。结果：滚动丢弃旧工具输出，比阈值触发摘要平均高 1.7 分、成本低 27.7%，吞吐 1.2×。

这是本期最值得记住的架构判断：**记忆压缩的正确层位可能不在文本层**。两年来的记忆系统都在文本上压缩（摘要、抽取、分层），每压一次断一条源边（第 3 期的巩固税），还要付缓存惩罚（本期）。而在注意力层丢弃，既保住原文这条"源"，又不破坏前缀。

### 2.6 固化会繁殖错误

Anti-Persistence（Indiana，arXiv:2610.27406）指出一个失败环：错误抽象被检索到 → 塑造下一次执行 → 该轨迹又被抽象成同一个错误，作者称"错误再生产"。修法是保留原始轨迹与结果、按需重建指引、用完即弃；在多个基准上，这个"存得更少、想得更少"的设计拿到最高成功率与最低调用成本。与 2.2 合看结论不太好接受：**抽象的价值随时间衰减，错误却随抽象增殖**。写得越"聪明"，错得越系统——这直接质疑 L2/L3 蒸馏层的存在理由：它省读取 token，付的是错误固化。

## 四、技术挑战

**1. 价值不可观测，因而无法定价。** 可分五级：V0 无 / V1 使用计数 / V2 使用痕迹（REM 的 substring probe 只证明"出现过"，不证明"起作用"）/ V3 消融增益（Scalaris 内部 A/B：有记忆 91.9% 偏好、4.33 对 3.18）/ V4 反事实。主流停在 V1—V2。没有 V3，淘汰只能按新近度与相关性，而相关性无法区分"高相关且有害"——MemHarmBench 留存样本改写决策 59.38%—76.39%，其中 55.71% 任务完成干净无异常。

**2. 基准 headroom 不足。** 多数基准"检索友好"，关键词可解 70%，记忆能证明的空间很小，税反而显眼；反过来基准越难（PersonaMem-v2 / MINT-Eval），Mem-T 才有 +3.9。**考题难度决定了你看到的记忆系统是赚是赔。**

**3. 计费单位与价值单位脱钩。** 条·小时无法解释"这条值不值"，"每次正确答案成本"又会诱导刷分母。缺的是"复用次数"这一维。

**4. 缓存与记忆的激励冲突。** 记忆厂商的 KPI 是省 token，推理厂商的收入来自缓存折扣失效后的全价重算，两者最优解在结构上对立。

**5. 决策小模型不一定省钱。** Good Judgment, Bad Advice（2610.24649）在 Terminal-Bench 2.1 上做了 315 次试验：专用决策模型 Jev 把每次尝试成本抬高 19%，通过率不变（73.0%），比 placebo 还贵 22%，校准也很差（通过率 87% 的运行上平均完成概率只报 0.50）。这对"用 167ms 小模型替代 1—7s 大模型判断"是直接反证——快不等于便宜，排序准不等于校准对。

## 五、展望与建议

**对厂商**：把"每次正确答案成本"做成一等指标，与精度同表发布。这是比价要求而非道德要求——采购方一旦用这个指标，只报分的方案立刻失位。同时把构建成本从 LLM 调用降级（分类器/句法/小模型），把压缩下沉到 KV 或会话边界：SLICE-Mem 与 AKV 给出 −92% 与 −27.7% 两条路径，都不牺牲分数。

**对采购**：先跑两个零成本基线——no-memory 与两轮 RAG。Memory Tax 的结论是 11 个系统在 LongMemEval-s 上全输给两轮 RAG，而后者可能不到一天工程。若基线已够，买记忆层的理由只剩三条：跨会话、可治理、可追溯——都不是分数能证明的。若确实要买，按**复用频次**分层而非按数据类型分层：高频复用的团队规范、踩坑、接口约定值钱，一次性排障不值钱（NPV 里复用次数是唯一乘数）。

**对研究**：三个空位——①税的可复现基准（Retrieval Scope 归一化的开源实现）；②价值可观测 V3 的最小字段；③会话边界删除的最优调度。

一句话收尾：记忆系统这两年一直在证明"我能记住"，从 2026 年 11 月起要证明的是"记住我划算"。
