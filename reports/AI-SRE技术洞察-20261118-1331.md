# AI-SRE 技术洞察（第 282 期）

**生成时间**：2026-11-18 13:31（Asia/Shanghai）
**观察窗口**：2026-01 至 2026-11-18
**本期主题**：探针面／合成监控与真实用户——探针全绿，是因为它只走过自己那条路

## 题眼

2026-07-28，Downdetector 上关于 Reddit 的报障在一天内两次冲高、峰值超过 30,000 条，用户描述是信息流不加载、登录循环、App 卡死；同一时间，Reddit 官方状态页显示所有系统正常。第三方追踪器成了唯一可信的“到底挂没挂”来源，而这是五天内的第三次中断。2026-11-03 一篇托管应用监控的对比文章把同一件事说成通则：应用返回 HTTP 200，客户仍可能登不进去、下不了单；合成监控只测团队预先设置的那几条路径。2026-11-13 一份基础设施客户端的契约审计更直白：空数组是**合法**响应，缺失键、Redis 读错、JSON 非法才返回 503——于是“200 + 空结果”会被客户端当作有效数据缓存并替换旧值。2026-10-24 的一篇设计文把这类失败归成四类：客户端失败、多步失败、依赖失败、数据相关失败，健康端点对它们全部无感。

探针不是观测，探针是一份**带身份的采样**——固定区域、固定账号、固定套餐、固定数据集。它绿，只证明“它那条路今天通”。

## 一、发展趋势

1. **探针从“端口存活”走向“用户旅程”**。HTTP 检查只能抓 DNS、TLS、进程、源站错误；现代故障更多发生在 HTML 到达之后：第三方脚本、坏 bundle、错误开关让页面变成死按钮（appscale，2026-10-24）。浏览器脚本能登录、搜索、开仪表板，但**只覆盖被枚举的路径**。

2. **多区域与仲裁成为默认**。单点探针的失败无法区分“服务坏了”还是“探针到服务的那条路坏了”，甚至可能是监控厂商自己在该区域的基础设施故障（webpixie，2026-08-30）；多区域仲裁要求跨洲确认后才告警（FourSight、kloudfox，2026）。

3. **探针开始被要求“自证”**。2026 年一份计费分类器的 canary 工作流写明：借用凭据需要续期时任务**不发探针**，这一次运行对分类器“什么都没说明”；连续阻塞要升级——“一直阻塞的 canary 就是盲 canary”。

4. **合成数据与真实用户数据必须对账**。实验室与现场本就不是同一总体：同一页面实验室 LCP 8.2 秒、现场 75 分位 1.9 秒，原因是实验室模拟了更慢的移动网络（coralogix，2026-10-13）；CLS 在 RUM 与合成工具里连“页面生命周期”定义都不同（SpeedCurve）。

## 二、技术现状

**第一层：探针的“世界”与用户的世界不同。** 探针在一个区域、用一个测试账号、看一份固定数据；用户在全球、用真实账号、看个性化结果。Reddit 那次，状态页的探针世界是通的，三万个用户的世界不是。

**第二层：200 不是结果。** 搜索页加载成功但索引重建失败、返回零结果；DDoS/流量异常 RPC 返回 200 和空数组，客户端把它当有效数据覆盖缓存（koala73，2026-11-13）。断言必须落在“用户看到的业务事实”上，不是状态码。

**第三层：探针会静默停跑。** 凭据过期、令牌轮换、WAF 拦截、探针厂商区域故障、脚本元素定位失效，都会让检查“没有失败”，只是“没有发生”。多数平台把“未运行”记成灰色或跳过，而仪表盘的默认读法是绿色。

**第四层：状态页是叙事，不是遥测。** GitHub 报错数分钟后状态页仍绿，直到用户报告累积到阈值才创建事件（hotmolts，2026-09-20）；Fastly 自己的支持系统故障持续六天，状态页组件本身也在受影响列表里。状态页有**发布延迟**与**措辞选择**，它回答“官方承不承认”，不回答“现在通不通”。

**第五层：Agent 让探针更脆。** MCP 服务的健康检查不是一次 GET，而是 initialize、initialized、ping、tools/list、tools/call 五次往返，还要携带 session id、同时接受 JSON 与 SSE（voxgig，2026-10-18）。固定 prompt 的合成检查会因模型版本、采样参数、工具描述变化而漂移——探针自己变成了一个需要被监控的系统。

## 三、技术竞争力

| 方案／机制 | 探针位置 | 身份与凭据 | 检查深度 | 数据正确性 | 探针自证 | 与 RUM 对账 |
|---|---|---|---|---|---|---|
| Pingdom 类 HTTP 检查 | 多区域 | 无/基本认证 | 状态码、关键字 | 弱 | 运行历史 | 无 |
| Datadog Synthetics | 多区域 | 保管库+测试账号 | API/浏览器/多步 | 中（断言） | 有运行结果 | 可与 RUM 并列 |
| Grafana Synthetic | 多区域公共探针 | 机密管理 | HTTP/浏览器 | 中 | 有 | 弱 |
| Checkly | 多区域 | 环境变量/保管库 | 浏览器+API | 中 | 有 | 弱 |
| Cloudflare Health Checks | 边缘 | 无 | HTTP/TCP | 弱 | 有 | 无 |
| 自建 curl+cron | 单点 | 脚本内 | 状态码 | 无 | 无 | 无 |
| MCP canary | 单点/CI | 借用令牌 | 五步协议 | 中 | 阻塞可升级 | 无 |
| 状态页 | 无探针 | 无 | 人工叙事 | 无 | 无 | 无 |

**判读**：每家都能回答“探针最近一次返回什么”，没有一家能回答“**用户旅程里有多大比例有探针覆盖、探针今天是否真的跑了、跑的时候用的是谁的身份、看到的数据与用户看到的是否同一份**”。而事故里要的正是后者。

**本期反转**：我们一直把合成监控当“外部视角”，以为站在系统外面看就更客观。实际上探针只是换了一个**更窄的视角**：一个区域、一个账号、一份数据。它比内部指标更接近用户，但仍是一个样本；把样本的绿色当成总体的绿色，是把“没看见”当成“没发生”。**探针的价值不在它报了什么，而在它没覆盖什么。**

**判词**：「合成监控平台／浏览器探针／多区域仲裁／状态页／RUM SDK／SLO 引擎」全部可采购，「这条用户旅程有没有探针、探针今天跑没跑、用谁的身份跑、看到的是不是同一份数据、探针绿而用户红时谁先发现」不可采购。

## 四、技术挑战

1. **覆盖不可枚举**：用户旅程是组合爆炸，探针只能覆盖被写下来的路径。
2. **身份漂移**：测试账号的权限、套餐、数据随时间变化，探针测的已不是当初那条路。
3. **静默停跑**：令牌过期与元素定位失效都表现为“没有失败”。
4. **断言层次浅**：多数检查止于状态码与关键字，不校验业务结果。
5. **双总体混算**：合成 SLO 与 RUM SLO 样本不同，混在一起会互相掩护。
6. **Agent 探针漂移**：模型与工具描述变化让固定脚本变成 flaky。

## 五、需求分解、用户旅程与实现方案

**需求分解（D1–D6）**

- D1 旅程清单：列出收入/登录/支付/权限等关键旅程，每条标注是否有探针、探针版本、覆盖区域。
- D2 身份台账：探针使用的账号、角色、套餐、数据快照，变更时同步更新探针。
- D3 探针自证：每次运行写“跑了/没跑/被阻塞”，阻塞超过 N 次升级为事件，而不是灰色。
- D4 业务断言：登录后能取到个人数据、搜索有非空结果、下单后订单可查，而不只是 200。
- D5 双总体对账：合成与 RUM 分别算 SLO，差距超过阈值时告警“探针与用户不一致”。
- D6 状态页更正：状态页条目带“最后探测时间/最后人工确认时间”，事后补更正记录。

**用户旅程（一次“探针全绿”的登录故障）**

① 登录页改版，探针仍用旧选择器，脚本“成功”但只断言了标题（D1/D4 缺失）；② 测试账号的套餐被降级，探针拿不到个性化数据，返回空列表仍被判通过（D2 缺失）；③ 令牌过期，探针连续三天未运行，平台显示灰色，值班按绿色读（D3 缺失）；④ 用户大规模登录失败，RUM 错误率上升，但合成 SLO 仍是 100%，两个数字各自成立（D5 缺失）；⑤ 状态页在用户报障 40 分钟后才更新，且只写“部分用户受影响”（D6 缺失）；⑥ 复盘结论是“监控没覆盖”，但没人能说出覆盖矩阵缺了哪一格。

**90 天实现方案**

- **第 1–30 天**：盘点关键旅程与现有探针，产出覆盖矩阵（D1）；建立探针身份台账与到期提醒（D2）。
- **第 31–60 天**：探针自证与阻塞升级（D3）；把三条收入旅程的断言从状态码改为业务结果（D4）。
- **第 61–90 天**：合成/RUM 双总体对账与差分告警（D5）；状态页加探测时间戳与更正记录（D6）；用一次真实故障回放验证“探针没跑时谁会发现”。

**第 203 个市场空白（五项）**：① 用户旅程探针覆盖矩阵标准；② 探针自证与阻塞升级协议；③ 200-空结果的业务断言模型；④ 合成与 RUM 双总体 SLO 对账；⑤ 状态页探测时间戳与更正记录规范。

**`probe.*`／`synthetic.*` 第 170 次无人提字段族**：平台文档谈“如何配置检查”，不谈“检查覆盖了哪条旅程、今天是否真的运行、断言是否落在业务事实上”。

**本地 173／173-kb 连续第 158 期成组启用（陶炳哲 30：探针要能说“我今天没跑”）**：本地原型为每次探针运行写 `probe_run{journey, region, identity, status=ran|blocked|skipped, assertion}`，覆盖矩阵按旅程聚合；合成与 RUM 分别计 SLO，差距超阈值触发“探针-用户不一致”事件；状态页条目带 `last_probe_at` 与 `last_human_ack_at`。
