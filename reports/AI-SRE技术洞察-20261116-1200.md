# AI-SRE 技术洞察（第 213 期）

**生成时间**：2026-11-16 12:00（北京时间，档位 1200）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：因果闭合面／诊断可证面（Causal Closure / Grounded Diagnosis）——「答对根因」不等于「查对因果」；当 top-1 准确率把一场诊断塌缩成一个服务标签，蒙对和查对同分

---

## 题眼

过去十年，自动根因分析（RCA）被一个指标牵着走：**top-k 定位准确率**——Agent 有没有把"哪个服务坏了"说中。2026 年 10 月至 11 月，三份独立论文几乎同时指出这把尺子量错了东西。香港中文大学（深圳）团队的轨迹级研究分析了 RCABench 上 5000 条轨迹，一句话刺穿行业泡沫：**"正确的定位可能掩盖因果重建的缺陷"（correct localization can hide deficiencies in causal reconstruction）**。Cloud-OpsBench 补上数字：即便 GPT-5，**在 33.1% 与 29.4% 的案例中识别对了根因，却没有实现"证据闭合"**。RCAtlas 则给出最反直觉的一击：在 8 个公开数据集、90 起验证事故上，**最简单的 harness（单次 LLM 调用或开放查询的 SQL agent）PR@1 达 65–77%，而精心编排、硬编码 SOP 的已发表 RCA agent 只有 16–53%**。

三句话指向同一个被忽略的事实：**我们评判"诊断好不好"的整个度量体系，和"诊断可靠不可靠"的真实目标，是两套东西；这个错配已经大到让整条技术路线的投入方向都可能是反的。** 本期首次把"因果链是否闭合、命中是否靠蒙、过程是否可证"立为一等对象——与 #160 归因诚实度（管"说的因果对不对"）、#188 轨迹归属（管"轨迹能否定位到步骤"）、#93 脚手架面（管"编排层是不是故障源"）显式划界：本期只问一件事，**评测口径把"答对"误当成"查对"，这个错配如何被度量、被证伪、被采购。**

## 一、发展趋势

**趋势一：RCA 评测从"答案对不对"转向"过程对不对"。** 轨迹级研究、Cloud-OpsBench、CloudIR-Bench（APSEC 2026）在 10 月 21 日至 11 月间接连公开，**共同把"证据闭合／因果重建／过程级质量"推成一等评测维度**；RCA 正从"给标签"走向"给可审计的推理过程"。

**趋势二：简单基线正在推翻"编排越复杂越好"。** RCAtlas 的 Pareto 前沿上，**每一个成本或时间最优配置都是简单 harness**；硬编码 SOP 在事故揭示什么重要之前就决定了去哪找证据，系统性跳过决定性证据。**"多 Agent 编队＋固定调查阶段"这条主流路线，第一次在公开基准上被单次调用打败。**

**趋势三：产品页开始把"证据"写进交付物。** PagerDuty 11 月 3 日发布的 Paige 以并行假设检验为卖点，输出"假设 A 因查询时间一致被否、假设 B 因 AZ-1 与 AZ-2 间 15% 丢包被确认、置信度 94%"的叙事链；Honeycomb 同日发布的 Team Agents 让每个发现链回查询／trace／deploy，并标注"confirmed 还是 hypothesis"。**"给结论"已不够，"给带证据链的结论"成为新品共同话术。**

## 二、技术现状：四种塌缩，把"蒙对"伪装成"查对"

**其一，标签塌缩。** Acc@1/MRR 把一场包含几十次查询、跨服务证据拼合的诊断，压缩成一个服务名。**命中与因果闭合被记成同一个分数**——GPT-5 那 33.1% 的"答对但未闭合"在榜上和真正查对的案例完全同形。

**其二，过程漂移不可见。** 轨迹级研究归纳出失败调查的三种可枚举模式：**遗漏证据（omitted）、误解证据（misinterpreted）、无支撑推理（unsupported）**。失败轨迹会漂向无关服务或反复做浅层查询；而**只看最终标签，这些漂移全部隐身**。同一研究用轻量防御原型针对这三族做拦截，Acc@1 在全部配置上提升 3.5–35.1 个百分点——说明这不是随机噪声，是可定向修复的系统缺陷。

**其三，推理预算的负收益。** RCAtlas 的消融显示：**调高 reasoning effort，准确率最多抬几个点，运行时间却最多翻 7 倍**；模型档位主要买到"稳定性"，多轮 harness 主要抬高"能力上限"，二者与"砸思考时间"买到的东西并不相同。**"想得更久"被误当成"查得更对"。**

**其四，闭合率无人上报。** 六家云厂商的 Agent 运维平台——Google Data Cloud、阿里云 STAROps／Cloud Monitor 2.0、腾讯 CloudQ、火山 AgentKit、以及 Anthropic、OpenAI 的 Agent 栈——**没有一家把"证据闭合率／因果路径完整度／命中-闭合差"做成可导出字段**。Google 11 月 13 日把 Prism 评测跑分写进客户自有 BigQuery 表、与生产 agent_events 并列，是离闭合最近的一步，但其公开的 execution／outcome／goal 三层里，**goal 层（到底解没解对题）仍被明确留空**。

**判读与本期反转。** 把"答对≠查对"证到极致的是学术侧三份基准，把"证据链"做进产品话术的是 PagerDuty 与 Honeycomb，**而六家云厂商 Agent 平台「证据闭合率／因果路径完整度／命中-闭合差」三列全空**。最锋利的反讽来自 RCAtlas：**不是编排无用，是尺子量错了地方**——基准只奖励"定位"，恰好是简单系统最擅长、对生产 SRE 最没用的那一维；编排的价值本在"闭合"，基准却量不到。判词：**「top-1 准确率」「RCA 报告」「置信度分数」「根因标签」「SOTA 榜单」全部可采购、可引用，举证这次诊断的因果链是闭合的、关键证据不是被跳过的、命中不是蒙对的——不可采购。**

## 四、技术挑战

**一，"结论正确"是天然遮蔽物。** 一旦答对，没人追问过程；错误答案才触发复盘——**因此对"蒙对"的系统性检验在组织里没有入口**。

**二，闭合没有公认定义。** 什么算证据足够？GPT-5 那 33.1% 是"没查全"还是"标准过严"？**没有基线就没有验收条款**。

**三，因果重建需要反事实。** 证明"A 导致 B"要能回答"若非 A 是否仍 B"；现有 Trace 是观察性证据，**缺少故障传播路径这一因果参照**。

**四，失败三族对抗性强。** 遗漏证据可被"看起来很忙的浅查询"伪装；无支撑推理在流畅自然语言里难以一眼识破。

**五，简单 harness 的诱惑。** RCAtlas 说单次调用更准更省，但生产场景需要可复用、可维护的诊断资产——**"基准最优"与"工程可运维"发生冲突**。

**六，置信度不等于闭合度。** Paige 的"94% confidence"是模型自信，不是"每一步都有证据"；**把自信当闭合，是本期要拆穿的核心混淆**。

**七，合规开始要"可举证的诊断过程"。** 审计要的是"你凭什么定位到这里"，没有逐证据记录，就答不上。

## 五、展望与建议

**把闭合做成一等 SLI。** 建议最小字段集 `rca.closure.*`（第 151 个市场空白、第 119 次无人提字段族）：`evidence_closure_rate`（证据闭合率）／`causal_path_complete`（因果路径完整度）／`unsupported_inference_count`（无支撑推理数）／`omitted_evidence_count`（遗漏关键证据数）／`hit_vs_grounded_gap`（命中-闭合差 = Acc@1 − 闭合率，直接暴露蒙对）。这五项在主流 OTel GenAI 约定与六家产品文档中**均无对应字段**。

**三步落地。** 第一步，零改造：**在诊断报告末尾加"证据闭合清单"**——列出每一步用了哪条证据、排除了哪个假设；这是 #208"未见证据清单"的深化版，从"没看见什么"进到"用了什么支撑"。第二步，把 `hit_vs_grounded_gap` 纳入变更门禁与回归集：**命中率上升而闭合率不动，判为疑似过拟合或蒙对**。第三步，采纳 RCAtlas 的工程建议——**先把单次调用／SQL agent 作为默认基线跑一遍自己的事故集**，再决定是否上编队；并把 reasoning effort 当作延迟预算而非质量旋钮。

**本地知识积累（第 106 期成组启用）。** 蚂蚁 05 刘凯宁的诊断报告固定为"结论／证据／待确认项"三段，是闭合形态的本地先声——其"工程的交给工程、大模型的交给大模型"恰是闭合的确定性骨架；08 刘杨以 Trace 为中心的实时评估提供过程级数据底座；31 马云雷把轨迹沉淀为回归集，为闭合率提供可回放的判据。**本地把"待确认项"当成交付格式，联网侧 10—11 月三份论文才把它升级为可度量的闭合率；两边都没把闭合率做成可导出字段**——这正是本期新增的、可继续深挖的知识增量。
