# AI-SRE 技术洞察 · 第 100 期

## 交接面／状态托管面（Handoff / Continuity of Custody）

> **题眼**：同一家公司 **11-03** 发布稿写「检测、调查、修复作为一条工作流运行，而不是三次 handoffs」，自家工程博客却要求智能体持续适应作战室讨论、共享笔记与新上传产物。**交接没有被消灭，只是从一次可导出的动作，压进了不可导出的上下文。**11-05 论文让六个配置接手 44 个在途项目：能构建 58.56%，完整交付 4.95%；把正确目标状态直接喂过去，构建升到 96.40%，完整交付仍只有 8.11%。**「能跑」与「接得住」是两个数。**

## 一、发展趋势：从「谁来做」转向「谁现在接得住」

**11-03** PagerDuty 更名 PD Reliability Platform 并 GA 了 Paige，底下挂 Scribe（记录）、**Shift（排班与交接路由）**、Insights 三个具名子智能体；PD Labs 同日放出 **SRE Workbench**：「人和 Paige 从同一份证据、同一张图、同一条时间线并排调查」，复盘自带 owner 与 due date。这是行业第一次把交接做成具名角色与共享界面。但发布材料同时宣称三个 handoffs 已并成一条工作流，工程博客又要求持续刷新上下文——**界面越顺滑，那次易手越不像一次可举证的变更**。

**11-05 arXiv 2611.07307《Take It From Here》**（44 个在途项目／7,983 条消息／6 种配置）给出首个可复核基线：完整交付率 4.95%，构建通过 58.56%、所选变更真正生效 6.31%；历史裁成「相关消息」反跌到 2.70%；**给出正确起始状态几乎无改善（4.50%），给出正确目标状态也只有 8.11%**，312 次诊断无一配置能重建「当前适用需求」。结论不是上下文不够，而是**接手方缺一个叫「当前适用需求」的状态对象**。

**11-01 arXiv 2611.02300** 把多智能体交接写成 *an architectural extension*，留下两条硬判例：**作业已完成但因任务过期仍须重新准入**；反例暴露「被丢弃的否定事实」，并区分**历史生命周期状态与当前适用性**。**11-02 arXiv 2611.03178 CoworkOS** 把跨智能体、跨会话连续性列为设计目标；**11-02 arXiv 2611.03092** 提出 AOI＝U−λP，首次把监督负担写进公式，但 P 不含交接损失。

**主线划界**：88 转授面管授权传了几跳，本期管「易手那一刻谁现在能批、谁欠一个签收」；95 收容面管停止后还剩多少权限，本期管**旧主体没停、新主体已动的重叠窗口**；90 挂起面管没开始的存量，本期管**做了一半、必须被别人继续的存量**；97 组合面是「每步都批过、整件事没被批过」，本期是「每刻都有 owner、整段没人拥有」。前 99 期都在补「还缺哪层制度」，而所有制度（回归集、SOP、花名册、评分器、拓扑图）都默认**责任主体连续**；交接正是这个默认失效的时刻。

## 二、技术现状：交接是动作，不是对象

**状态断点**。可用交接包至少五格：原本要完成什么、改了哪些业务对象、哪些步骤已有确认、哪些仍在等待、哪些结果与预期不符；另加已排除假设、待批准动作与**已发给客户的说法**。焦点实验室方法论稿更直白：从 A 到 B 的交接「不只是工作项交接，也是**谁能采取行动、谁能批准行动**的交接」。**11-04 阿里云开发者社区 A2B 稿**给出中文版题眼——「**谁负责把整件事接住？**」「各团队都能证明自己的系统正常，并不自动意味着有人负责协调」「**未完成的部分如何重新交回组织**」，并建议演练「只完成了一半」时接手人能否据此继续——仍停在组织建议。

**权限断点**。OpenAI Agents SDK 的 handoff 是模型可自行调用的 `transfer_to_*` 工具，`on_handoff` 是 opt-in 扩展点，示例多用于日志；Anthropic 的 coordinator/subagent 各跑独立会话线程，官方文档明确「**子智能体咨询失败或中断不会使协调者回合失败**」。协议侧自认「交接瞬间的授权收窄最多只是可行，而非默认强制」。**交接失败不向上传导，父 episode 便可在没人接住时自动结案**。

**口径断点**。11-03 信通院五项要求含「流程贯通」、六维含「过程可审计」，并保留人工接管兜底；《运维智能体（SRE AGENT）能力要求》把「多智能体协同」定义为**集群任务分配与联动作业**、「人机协同」列为一种行动能力。于是「协同」是动作、「接管」是兜底，**没有一级按交接完整度分级**。腾讯 11-03 提「清晰的责任边界」与按可回退性划分人机职责，11-05 社区稿直接问「**停下之后业务怎么接**」——落点仍是值班手册。

**可观测断点**。OTel GenAI 的 span 只有 `invoke_agent`／`invoke_workflow`／`execute_tool`／`plan`／`retrieval`，`gen_ai.conversation.id` 把多次 run 绑到同一会话，却绑不住谁在何时把什么交给了谁、对方签收没有；有工程稿把「子 Agent 交接」塞进 `invoke_agent`，第三方 Handoff span 也仅是建议。11-02 GenAI 约定仍 Development，A2A 亦不保证分布式 span 同 trace。**协议级互操作与状态可导出是两件事。**

**本地 173 库连续第二十一期成组启用，作「交接契约原型」**。王浩男 21 把「上下文共享」列为飞猪交付大脑第一支柱：同一需求共享项目背景、仓库代码、工程规范、PRD／验收标准与过程澄清成果，三 Agent 各取所需、结果交回供人审阅；踩坑栏点明「人整理后传给各自 Agent 易形成信息孤岛」。肖汉松 22 给出最小契约「单 Agent 无法解决时须**携带证据改派**，Loop 承接每一次交接」。刘凯宁 05 诊断报告三分（结论／证据／**待确认项**）即未决项字段，casa 01「交回可查证据」补全。判词：**联网侧 11 月才测出「接不住」，本地讲义早把三者串成流程**；仍不可采购。

## 四、技术挑战：第五十四个市场空白

`handoff.*`／`custody.*` 是**第 23 次无人提出的字段族**（自 72 identity 至 99 `topology.*` 之后）。五项空白：① 五格状态与已排除假设、已对外说法的可导出率；② 可行动权与批准权的强制转移校验率（而非 opt-in 回调）；③ 交接失败向上传导率——子会话中断时父 episode 是否仍自动结案；④ 接手方「当前适用需求」重建率与签收回执覆盖率；⑤ 重叠窗口时长与并发写检出率。

反证仍在标准文本：五项要求有「**流程贯通**」、能力要求有「**协同能力层：集群任务分配与联动作业**」、六维有「过程可审计」、分级按人审批与否分 1／2／3 级——**可追溯率并非不会写**（《可信 Agentic Cloud》已列「路由决策可追溯率」），只是「贯通」指系统对接、「协同」指任务分配、「接管」指兜底，都不问易手那一刻状态与未竟事项是否守恒。延续 94／98／99 期方法：标准清单恰是空白的最佳证据。Gartner 预计人工批准率将从 80% 降至 2029 年的 20%；**交接对象从「人」变成「策略」，记录反而更没有落点**。

## 五、展望与建议

**字段与默认态**：向 OTel GenAI 提 `handoff` 独立 span 与九字段（handoff_id／episode_id／from_actor／to_actor／transferred_scope／authority_epoch／unresolved[]／evidence_as_of／accept_receipt），默认 `ACCEPTANCE_UNVERIFIED`，**未签收不得视为已交接**；补 `handoff.chain_id` 让跨会话、跨厂商的易手串成一条链（承接 88 委托链、95 epoch-bound）。

**最小实现**：交接包由代码确定性生成五格清单＋已排除假设＋已对外说法，不用模型总结；签收门禁要求接手方复述「当前适用需求」并绑定参数、策略版本与 as_of，按 2611.07307 的 delivery test 验收，**不看能否构建**；过期任务按 2611.02300 重新准入，子会话中断即标 `HANDOFF_INCOMPLETE` 禁自动结案。

**重叠窗口与计分**：旧主体 `STOP_REQUESTED` 与新主体 `ACCEPTED` 之间不得同时持有写权限，握手期内动作双记；三轨 SLO——交接完整率、接手重建率、重叠窗口时长；AOI 的 P 补一项 handoff loss。演练三型：只完成了一半、恢复时证据已变、签退后定时任务续开会话。

**标准与采购**：五项要求「流程贯通」补「交接状态可导出」；SRE AGENT 能力要求「协同能力层」增设交接契约子项并在 2 级要求签收回执；六维补交接完整率与重建率。采购三问：交接那一刻能导出什么？权限是否真正收窄？没接住会不会自动结案？

**口径与边界**：四篇 arXiv 为预印本与仿真，数字仅取机制不外推；11-04 阿里与 11-05 腾讯社区稿系作者授权发表，非产品承诺；PagerDuty GA 与 PD Labs 三项为 preview，规模与效果为厂商自述；信通院与 11-04 公约属标准／自律文本；11-03 腾讯与阿里已在往期作过钩子，本期改取「责任边界／接得住」侧面＝同素材不同面；焦点实验室稿为较早方法论稿；OTel GenAI 仍 Development；本地 173 为讲义转写稿；未采信 SEO 农场数字。
