# 记忆技术洞察 第63期：记忆的"陈述者×镜头"维度——谁说的、从哪个视角说的，正成为第六个一等元数据

> 生成时间：2026-11-12 14:00 ｜ 固定四维：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战
> 覆盖来源：arXiv（TrackMem 2611.02001 / FinLoCoMo）、OpenViking、Hy-Memory、TencentDB-Agent-Memory、ReMe（含 ReMe2Ops）、dsh-memory-evolve

## 主线与新观点

前 62 期把记忆的"账本属性"拆成 principal（谁有权）、source（来自哪）、state_role（此刻是否有效）三轴（第 3/55/56 期）。本期指出三者共享一个未检验前提：记忆是"单一陈述者、单一视角"的断言。TrackMem（arXiv 2611.02001，11-01）用金融长程对话证明该前提在多数真实场景不成立——同一家公司会被"估值 / 监管风险 / 仓位 sizing"多个分析镜头分别讨论，数字会被修订、立场会跨会话说变。核心反共识观点：**"谁说的、从哪个镜头说的"不是检索的副产品，而是与 principal/source/state_role 正交的第六个一等元数据（speaker_id + lens）；把陈述者维度压平进单一 user_id 或 flat 向量，等于主动丢弃区分"被取代的数值"与"应保留的规则"的能力。**

## 发展趋势

记忆建模从"事实堆叠"走向"视角分面"。TrackMem 把四类失效模式显式化：Revision（数值被取代而非累加）、Stance（立场沿时间序列演化）、Constraint（一次陈述的规则管辖后续问题）、Aspect（同一实体多镜头必须分离）。FinLoCoMo（15 段长程投资对话 / 765 问）证明 Aspect 是现有系统唯一集体失守的维度——其 Table 1 中仅 TrackMem 标 G（部分覆盖），其余系统对"镜头分离"全是 #（未覆盖）。评测正从"能不能找到"升级为"找的是哪个镜头下、哪个人说的"。

## 技术现状

六家产品仍把陈述者维度压平。OpenViking v0.5.4（11-09，~42k★，但 releasealert 标记 6 个 CVE）的 viking:// 是单命名空间，peer=git identity 只管写者身份、不区分内容陈述者；Hy-Memory v1.0.6 / 2.0.14（11-06）新增 lite/pro/ultra 三档（lite 不用 LLM、保留原文直搜），仍是单 user_id；TencentDB v2.0.3（30.6k★，11-10 仅 README 更新，feat/server_team 团队服务端在研）四类资产单库；dsh-memory-evolve v26092802（~628★）五轨单 git 文件；ReMe 0.4.x（11-06 新增 application-owned chat #714）单 .reme。无一建模 speaker×lens。

## 技术竞争力

倒挂延续：视角分面最完整在论文（TrackMem），产品零披露。TrackMem 在 failure-mode split 达 73.9% macro 准确率 vs 最强基线 69.4%，其中修订数值题 86.5% vs 73.4%——最大增益恰在"谁在何时改了哪个数"。但 TrackMem 仅开源实现、无持久化层、金融场景外泛化未证；AML C2（11-19 预期）契约仍无 speaker/lens 维度（第 56 期四问未进，本期加一问：which-speaker-under-which-lens）。

## 技术挑战

①lens 枚举爆炸：估值 / 监管 / 仓位之外还有多少镜头？未声明镜头如何兜底？②speaker 解析成本：对话中"引用他人观点"vs"自己主张"需判别，误归责会污染分面；③多镜头冲突裁决：同一实体不同镜头结论相反时谁优先？TrackMem 按图保留但未给裁决语义；④与 state_role（第 55 期）耦合：被取代的数值（revised）与被取代的立场（stance）是两层，需双时间戳；⑤产品落地：单 user_id 架构要拆 speaker×lens 等于重写写入主键（第 3 期字段级血统的代价复现）。

## 需求分析

企业真实场景（投研、法务、医疗会诊）里，记忆不是"一条事实"，而是"某人在某时点以某视角提出的断言"；用户要"把 A 分析师的估值观点与 B 合规官的提醒分开召回"，而非把所有人所有视角混进同一向量堆后被相似度平均掉。需求本质是：**按陈述者与会话镜头分面存储、独立召回、独立治理**。

## 用户旅程

投研助手用户问"这家公司还值得买吗"：system 沿 per-speaker graph 拉出 A 分析师的 valuation 镜头结论（带修订时间线）、B 合规官的 regulatory-risk 镜头提醒、C 交易员的 position-sizing 约束；每条都标 speaker_id + lens + 时间戳；回答显式区分"这是谁的视角、是否已被新版修订"，审计者能翻到原始对话轮次与发言者。

## 具体实现方案

1. **陈述者×镜头主键**：在写入边（第 3 期字段级血统）上追加 speaker_id 与 lens 两字段，检索返回事实同时返回"谁、何时、哪个镜头"。
2. **分面图记忆**：仿 TrackMem，用 per-speaker 图保存数值修订史 + 按 entity×lens 隔离，Constraint 类规则单独建边不被语义检索淹没。
3. **修订/立场双时间戳**：Revision 与 Stance 分别挂失效时间（深化第 55 期 state_role），避免把"数变了"和"立场变了"混为一事。
4. **评测加一问**：推动 AML C2 增 speaker/lens 维度（延续第 56 期评测契约），把"镜头分离准确率"设为可比指标。
