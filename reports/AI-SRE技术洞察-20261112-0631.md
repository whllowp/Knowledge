# AI-SRE 技术洞察（第 140 期）

**生成时间**：2026-11-12 06:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：主权面／跨境面（Sovereignty）——数据驻留管「存在哪」，管不了「Agent 把什么发到哪、在哪执行」

---

## 题眼

11-07 Blaxel 的主权指南把三个常被混用的词拆开了：**数据驻留**回答「数据存在哪」；**数据主权**回答「谁的法律、谁的操作员能碰到它」；**网络主权**回答「流量能走哪条路、谁能到达运行时」。它给了一个很锋利的例子：**一家美国公司运营的欧盟区域，满足驻留，却仍暴露在 CLOUD Act 之下**——**存在欧洲，不等于归欧洲管**。更麻烦的是 Agent：它在一个任务里可能同时调用模型、MCP server、包仓库，还会跟随文档里读到的 URL；**这些调用常常绕过 API 网关，看起来就是普通的外发 HTTP**。指南引 NIST 2025 年 1 月的测试：对 Claude 3.5 Sonnet 的 Agent 劫持，五个注入任务平均成功率 **57%**——**这种量级下，靠模型拒答挡不住外泄**。**驻留是「东西放在哪」，主权是「谁的手能伸进去」，网络是「东西走出去时经过谁」。**

## 一、发展趋势

**趋势一：从「数据驻留」升级到「三层主权」。** 驻留只钉存储位置；主权还要看所有权、员工访问地、子处理者；网络主权还要看出口路径与执行位置。**只做区域 pin，等于只答了三分之一。**

**趋势二：Agent 把「跨境」从静态变成运行时。** 人访问数据是「打开哪个库」；Agent 访问数据是「运行时决定发给谁」——**模型端点、工具、检索、包仓库都可能是跨境点**（Amazon Bedrock 跨区推理会明说 prompt/输出可能离开源区域）。**你 pin 了入口区域，不等于 pin 了处理区域。**

**趋势三：控制点从代码移到基础设施。** 默认拒绝出口、静态出口 IP、组织级区域策略、代理注入凭据、私有端点——**这些必须在 Agent 代码之外执行**，因为 Agent 生成的代码能读环境里的一切。

## 二、技术现状：驻留做了，主权与网络没做

**驻留层：区域 pin 最常见。** 把沙箱、日志、备份钉在某个区域；**但区域策略常只覆盖新资源**，存量与副本仍有盲区。

**主权层：所有权与操作员访问最少被问。** 谁控股、支持人员从哪国访问、子处理者是谁；**SOC 2／ISO 27001 证明不了驻留，也证明不了司法管辖**。

**网络层：出口几乎全开。** Agent 默认能访问任意域名；**一个被注入的 URL 就能把读到的数据发走**；允许清单若在 Agent 进程内，代码能改。

**保留层：ZDR 有例外。** 零保留能挡住持久化，但**厂商仍可能保留被标记的会话**（如最长两年）；**例外不写进数据地图，就等于没有 ZDR**。

**六件套控制，缺一件就有缺口。** 默认拒绝出口＋允许清单（代理侧）、静态出口 IP、组织级区域策略、ZDR 例外表、代理注入凭据、私有端点；**任何一件放在 Agent 代码里，都等于没有**。

## 四、技术挑战

**一，驻留不等于合规。** GDPR 第五章把「远程访问」也算传输；**Agent 每次带个人数据的调用都要有传输工具**（充分性决定或 SCC＋TIA）。

**二，Agent 会自己选目的地。** 运行时决定调用谁；**出口不在代码里管，就等于没管**。

**三，跨区推理是隐藏的传输。** 模型端点可能把 prompt 送到别的区域；**你以为钉了区域，实际只钉了入口**。

**四，ZDR 有例外。** 被标记会话、滥用审查、计费日志；**例外不映射，数据地图就是假的**。

**五，凭据在沙箱里等于裸奔。** Agent 生成的代码能读环境变量；**密钥必须在代理侧注入**（OpenAI 也警告注入环境仍会暴露）。

**六，审计靠自证。** SOC 2／ISO 不证明驻留；**要自己从沙箱里调一个未列名域名，确认它失败**。

**七，数据地图会过期。** 新工具、新模型端点、新区域上线；**地图不随发布更新，合规就停在上一版**。

**八，多司法团队各说各话。** EU 要 SCC、美国要 DPF、金融要 DORA、医疗要 BAA；**同一份数据流，四个团队四个结论**——没有统一字段，就无法对齐。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `sovereignty.*` 字段**：`data_class`、`residency`、`jurisdiction`、`egress_dest`、`execution_region`、`transfer_tool`、`retention`。
- **R2 数据流地图**：列出每次运行时调用的目的地、司法辖区、传输工具；**没有地图就没有合规**。
- **R3 默认拒绝出口**：允许清单在代理/防火墙，不在 Agent 进程；**未列名域名必须失败**。
- **R4 执行区域 pin**：沙箱、日志、备份、推理都钉；跨区故障转移要单独评估。
- **R5 ZDR 例外表**：把厂商保留例外写进地图；**例外不写＝没有 ZDR**。
- **R6 审计清单**：所有权链、支持访问地、子处理者、出口 IP、密钥托管、退出条款。

### 5.2 用户旅程

- **平台架构师**：新 Agent 上线 → 画数据流 → 发现会调美国模型 → 换 EU 端点或加 SCC → 记录 `transfer_tool`。
- **安全**：从沙箱调未列名域名 → 确认失败；调允许域名 → 确认成功 → 把结果存档。
- **SRE**：跨境告警（出口到未授权辖区）→ 熔断该域名 → 复盘是配置还是注入 → 把域名加入拒绝清单并重跑出口测试。
- **合规**：季度审计 → 核对子处理者与保留例外 → 更新数据地图与合同。

### 5.3 实现方案（90 天）

- **0–30 天：画图。** 列运行时调用与目的地；标司法辖区与传输工具。
- **30–60 天：收口。** 默认拒绝出口；允许清单外置；区域策略；凭据移到代理。
- **60–90 天：验证。** 沙箱出口测试；ZDR 例外核对；季度主权审计；数据地图随发布更新。

**第 92 个市场空白（五项）**：运行时数据流可导出率、司法辖区可声明率、出口默认拒绝覆盖率、执行区域可验证率、ZDR 例外可报率——无一内建；`sovereignty.*`／`jurisdiction.*` 为**第 61 次无人提字段族**。本地 173／173-kb 连续第 55 期成组启用：赵恒 25「语义层不是 Agent 的另一个 prompt，而是每一条都用同一份定义」＝全库唯一把「定义权」写成基础设施的实践，本期首次当主线；配朱革 15「统一权限、审计、回滚」、余锦泽 03「本体约束校验」。判词：**本地把定义权写进语义层，联网侧 11 月才把「驻留≠主权≠网络」拆开；两边都没把「这次调用的司法辖区」做成运行时字段。**
