# AgentMemory 技术洞察 · 第 22 期

**时间**：2026-11-08 02:00（GMT+8）｜**范围**：2026 年，重点为近 30 天｜**覆盖**：dsh-memory-evolve、Hy-Memory、TencentDB-Agent-Memory、ReMe2Ops、OpenViking

> **本期主线：记忆的信用分配——"写对哪一条"从未可问，现在可算，代价是记忆不再可读。**
> 前二十一期轮流拿掉了"记忆存在""记忆可删""记忆可指认""记忆是符号""记忆必需"等预设，但它们共享一个更隐蔽的前提：**一条记忆对最终成败的贡献是可以不谈的**。本期把这个前提拿掉。当写入开始被训练、经验开始被物化成件、榜单开始计算增量，信用分配（credit assignment）就从学术细节变成了工程主轴；而它一旦变细，记忆就从"可读的句子"退化为"可加载的件"。

---

## 一、发展趋势

三条信号在 11 月第一周同时到位，指向同一处。

**其一，写入被当成训练任务。** 腾讯混元 10 月中开源的 Hy-Memory-30B-A3B（arXiv:2610.22196，30B 总参／3B 激活）不是"会记忆的模型"，而是只做写入的专用件：跨 Mem0、MemOS、Hy-Memory 三个框架训练同一套写协议，六项指标宏平均 55.49，略高于 Claude Opus 5 的 54.62；在从未参与训练的留出框架 EverMemOS 上领先 2.86 分。作者承认 0.01–0.02 分的差距"不构成统计上可分辨的差异"，真正的证据是跨框架一致的名次与留出集上的领先。

**其二，经验被物化成件。** Meta FAIR 与普林斯顿的 Self-Direction（arXiv:2610.31846）给每条失败经验训练一个独立 LoRA，每件约为基座参数的 0.02%，基座与既有件全部冻结；GAIA 上三件合计约 256 MB，成功率 36.4%→52.7%，整体提升 8.9–17.0 个百分点，纠错可靠性近乎翻倍，少量件还能迁移到数十个更难的新任务（+10.47pp）。

**其三，评测开始算增量，而不是算存量。** Letta FrontierMemory 把"从既往经验中学习"的增益作主指标：Dream 73.3%（$2.80/任务）、Prime 60.0%（$3.74）、OpenAI Agents SDK 40.0%（$0.82）、Claude Managed 33.3%（$3.21）、Hermes 26.7%（$2.79）。总分第一与每美元第一仍是两个系统。

三条合起来是一句话：**写入侧的竞争单位，正从"文本有多好"换成"信用有多细"**——提示词无法把一个端到端的成败信号，拆成"第几个块写坏了"。

## 二、技术现状

### 2.1 信用粒度三级

**会话级**是文本轨的默认。一整轮任务结束，成败作为单一标量回到"这批记忆"，无法定位具体条目。第 9 期（闭环）与第 19 期（代谢）都卡在这里：没有条目级信用，"改进"只能靠事后巩固与压缩，而压缩会丢掉范围。

**块级**是第一次下移。Hy-Memory 把每个会话独立切成约十轮一块（块不跨会话边界，保证语义完整），对每块单独做失败面探针，再把"最终答案错了"归因成"第几个块写得不好"；奖励合并过程项与结果项（s = PRM + 2·ORM − 0.3·惩罚），GRPO 归一化也下沉到块。最值得记的是那个 0.3 惩罚项：记忆写入有一条显然的作弊路径——**全存下来，问什么都能检索到**，"可回答性"随即失效。过存惩罚不是修辞，是让"多存"不划算的唯一机制。

**件级**是第二次下移，也是最激进的一次。Self-Direction 把"一次失败"与"一个适配器"做成 1:1：信用分配问题不是被算出来的，而是结构上就不需要算。代价是每条经验都要一次训练，且经验从此不可读。

### 2.2 结构级信用：沿血统而非按时序

MemQ（上海交大 + MemTensor，2026-05）提供第三条路：用 provenance DAG 记录"这条记忆是检索了哪些记忆之后才产生的"，再用 TD(λ) 资格迹把信用沿 DAG 深度回传，权重按 (γλ)^d 衰减。多步任务 +5.7pp，单步仅 +0.77pp——**信用传播只在依赖链足够深时才有价值**，浅链任务的信用本就不稀缺。

第 3 期曾判"字段级血统 + 团队级治理从未同体"，并把血统归为纯成本项。MemQ 说明血统同时是信用分配的必需输入——本系列对血统价值判断的一次上修。

### 2.3 件的两条工程事实

**检索退化为路由。** 件库不提供 top-k，只提供"按任务描述相似度挑一个件加载"。于是第 3 期的可寻址性在参数轨彻底归零：无字段、无引用、无命中位次。更麻烦的是失败形态——加载错件不报错，只是行为偏移，属静默失败。

**卸载不等于释放。** 工程侧的经验很硬：把 LoRA 的 scale 归零只是撤回效果，件仍在进程内存里；要验收"完全不加载"，必须重启进程、比对基座 SHA-256、并分别记录无件／加载未启用／启用三态的内存占用。多数记忆产品文档里没有这一步。

### 2.4 删除只到行为层

VGUA（arXiv:2605.02206v3）给出最锋利的一份卸载审计：先验证遗忘集确实被记住过、评分器确实在评正确性、代码确实实现了声称的过程，再测 234 个卸载模型。结果：78% 的健康模型在输出层更接近"从头重训"的参考点，94% 却在激活空间里离得更远；成员推断优势不跟踪重训对齐度；打乱选项顺序后，卸载模型仍答对 25% 的"已遗忘"题目，而只保留数据的参考模型仅 6%。

翻成记忆的语言：**删除能改行为，改不了表征**。第 2 期判"参数轨注销全失能"，第 18 期判"备份是删除权的敌人"，本期把结论再收一格——参数轨现在可卸载（件可枚举、可移除），但卸载结果不可证（内部残留无指标）。

### 2.5 件其实可审，只是不能引

两条 11 月的新证据反向修正了"件是黑箱"的直觉。其一（arXiv:2611.07610）只用件本身就能反推它的训练数据域：在 Qwen3.5-0.8B 上做 36 个微调、18 个数据集、5 个域，灰盒激活 61%、黑盒输出 64%、白盒权重统计 42%，随机基线 20%；黑盒结论在只给生成文本、不给 token 概率时不变，也不随 rank（8–64）变化。其二（TopKLoRA）说明稀疏化能把后门电路压到同 rank 稠密 LoRA 的十分之一，并用"消融后攻击成功率必须为 0"作必要性检验。

于是归因出现了中间态：**条目级归因（引用哪一条）在参数轨不存在，域级归因（这件属于哪类数据）可测且不弱**。合规举证从"我删了第 1234 条"退化为"这批件覆盖的域已被移除"——是降级，但不是零。

### 2.6 文本轨的反击与其余项目状态

文本轨没有坐等。Hy-Memory 把写入器做成可插拔件直接塞进 Mem0／MemOS 的写路径——保留可读性，换掉写入质量。agentmemory v0.9.32（11-04）给 lesson 增加 sourceIds，并给每个 MCP 工具打 read-only／destructive／open-world 标注，让客户端可在执行前询问；ReMe 0.1.2 插件把召回内容包裹并标记为"不可信历史数据"，auto_dream 每天 23:00 整理——"ReMe2Ops"仍无独立产品实体，本期按其运维面处理。dsh-memory-evolve 维持 645★／71 fork／MIT／37 open issues，最后 push 停在 10-29；它写进 README 的第一条原则是"AI 只提议，你确认"，所有会改变行为的写入先进待确认队列。TencentDB Agent Memory 仍是 30.3k★（NOASSERTION）、四资产 + 三级角色；OpenViking v0.5.2.1（41.6k★，1,204 issues）继续以文件系统形态提供"可打开、可编辑"的审计面。

三家在不同位置补同一课：**写入与召回都需要一个能被外部裁决的凭据**。

另一组不利数据：MemUse（11-01）在 8,000 集 SWE-bench 轨迹上逐条回看送达，四套配置与无记忆基线的解决率差距不超过 0.40pp，单集成本却从 $0.0045 涨到 $0.0178（+293.2%），71.5%–98.6% 的条目与任务无关。粒度再细也救不回"送错了"。

## 三、技术竞争力

| 方案 | 信用粒度 | 单件可删 | 可读可引 | 换基座 | 增量证据 |
|---|---|---|---|---|---|
| Self-Direction | 件（1:1） | 是（卸载） | 否 | 全废 | +8.9–17pp |
| Hy-Memory 2.0 | 块（10 轮） | 条级 | 是 | 可（换写入器） | 宏均 55.49 |
| TencentDB AM | 会话→人设 | 资产级 | 是 | 可 | 省 61% token |
| OpenViking | 文件／会话 | 文件级 | 是（可编辑） | 可 | 无 |
| Mem0 | 会话（增改删） | 条级 | 是 | 可 | 省 90% token |
| Zep | 事实（失效） | 事实级 | 是 | 可 | p95<200ms |
| Letta | 会话 | 块级 | 是 | 可 | Δ 榜第一 |
| ReMe／agentmemory | 会话 | 条级 | 是 | 可 | 无 |

第一，**能力错位而非能力高低**。唯一测增量的是 Letta，唯一做到件级信用的是 Self-Direction，唯一把"过存"写进训练奖励的是 Hy-Memory；三者互不重叠，说明这不是一条成熟赛道的分层，而是三条互不通信的路线。

第二，**治理与信用粒度反向**。件级最细但零治理（无 owner、无可见性、无审计面）；资产级治理最全（四资产 + 三级角色 + 四档可见性）但信用最粗。这是第 12 期"信任半径"结构的复现，只是反向轴换成了信用。

第三，**"换基座"是硬分水岭**。文本轨全部"可"，编译轨"全废"：第 13 期的嵌入锁定律在件上加重一级——嵌入可重算，件不可重算，因为它的训练数据是失败轨迹，通常根本没存。

第四，**没有一家公布"删一件后行为回退"的数据**，也没有一家把"信用粒度"写进文档。采购侧目前能问的只有总分，而总分与信用粒度几乎不相关。

## 四、技术挑战

**① 细化的反噬：路由歧义。** 件越多，按任务描述相似度选一个越容易错配，而错配是静默的。Self-Direction 的 GAIA 实验只装 3 件；件库到百级时，路由会退化成随机加载加轻微偏置，却依然显示"成功"。

**② 删除不可证。** VGUA 的 94% 是硬指标：件的卸载只能给行为证据，给不了表征证据，而合规要的恰是后者。第 2 期的"注销 3×3"矩阵需补一行：可卸载但不可证。

**③ 归因降级。** 域级指纹能证明"这类数据来过"，不能证明"这一条被用过"。第 3 期的 C 级可归因在件上不是"无人实现"，而是"定义要改"——从引用改为分布。

**④ 三套计价单位并行。** token/条、MB/件、训练次互不换算，采购无法横向比价；件的成本结构是"一次性训练 + 零边际"，与云按小时计费天然互斥。

**⑤ 过存与欠存对称作弊。** 0.3 的惩罚系数是补丁不是机制。任何以"可回答性"为奖励的写入训练，都会重新长回"全存"；反过来，以"简洁"为奖励的训练会退化成只记结论、丢掉范围（第 9 期"压缩放大律"）。

**⑥ 评测仍无信用位。** AML 二期 11-04 截止正式评测，榜单定于 11 月中，奖金 15 万元仅面向开源榜，本期仍未公布。其契约只有 Add／Search 两接口加平台代调，看不见"哪一条起了作用"——与弃答、冲突、时效、代谢、迁移、缓存、技能权限、载体等缺口同构。

## 五、展望与建议

**选型第一问应当换掉**：从"召回率多少"改为"信用粒度是多少"。粒度决定系统能否自我改进，召回率只决定此刻好不好用。

**采购条款加两条硬指标**：一是删除回执（件/条级，含卸载与重启验证）；二是删后行为回退测试，须含选项重排与激活空间对齐度。VGUA 的三检查可直接改成验收清单。

**文本轨短期不会被替代。** 治理、可编辑、可审计仍是刚需，件在这三项上全部缺位。分工应是：高频低价值走文本，低频高价值（工具修复、事故处置、合规流程）走件。

**若做件库，先把路由歧义当第一类故障。** 件数上限、冲突时拒绝加载、加载日志三件套缺一不可；第 7 期的"[?]"（未决）在件上同样适用——宁可返回"没有合适的件"，不要静默加载最像的那个。

**评测侧加两列**：Δ/$（增量每美元）与删后回退率。前者只有 Letta 单点，后者全球空白。

**下期观察**：AML 二期出榜口径（最高优先）；件级删除收据首例；路由歧义的生产故障报告；Hy-Memory 过存惩罚的独立消融；OpenViking 是否把"可编辑"升级为"可举证"。
