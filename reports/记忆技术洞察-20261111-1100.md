# 记忆技术洞察第 49 期（20261111-1100）：记忆的压缩层——摘要是第二次写入，不是免费的空间回收

> 覆盖维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。范围：2026 年（重点最近 30 天）。本期为系列第 49 期。

## 一、发展趋势

**压缩正在从"成本优化"被重新定价为"第二次写入"。** 触发是 11 月第一周三件材料的会师：SUMONE（arXiv 2611.06445，11-04）给出第一个任务无关的压缩内在指标——冻结重构器从摘要恢复被随机遮蔽的轨迹段，重构质量替代下游分数成为训练信号（GRPO），压缩成本降 78%（DeepSearchQA）/75%（SWE-bench Verified）而绝对分数只掉 0.04，且同一 checkpoint 跨下游模型与 harness 迁移零微调；Memento（2611.00244，10-30）发现最强模型根本不会主动记笔记——GPT-5.5 在 337 条测试集零笔记，GLM-5.3 1.2 万条 rollout 零有效笔记，无 SFT 预热的 RL 在 20 步内把压缩频率坍缩到零。三者的共同指向：压缩不是空间回收，是一次继承全部账目的写决策。这与第 42 期"给库打分不给答案打分"同构——压缩评测第一次有了内在指标（可重构性），而非只看下游分数。

## 二、技术现状

行业存在三条训练信号谱系：**无训练**（Codex/Claude Code 的 prompt 摘要）、**任务奖励**（HiAgent/FoldGRPO，与任务耦合不可迁移）、**自监督重构**（SUMONE，任务无关可插拔）。产品侧分裂为两条路线：**可逆压缩**——TencentDB Agent Memory 把"每条摘要保留确定性 node_id 回溯原始日志"写进设计（Mermaid 画布 + refs/*.md 卸载），token 节省 61% 同时 SWE-bench 提升，本周第三方独立分析确认"下钻链是品类里对黑盒记忆批评最直接的回答"，但同时指出全部基准为厂商自跑、prompt cache 失效问题（issue #120）未解决；**不可逆压缩**——SUMONE 只保留轻量摘要器，原文轨迹被丢弃，第 47 期"备份单位＝不可再生物"在此提前生效：不可逆压缩把原件变成不可再生物。ReMe 的"可恢复压缩提案"（决策模型返回压缩建议而非直接执行）是产品侧第二个可逆回应，本周仍未见其他产品吸收。

本周最大产品动态是 **Hy-Memory 2.0**：腾讯混元开源 Hy-Memory-30B-A3B 专用写入模型（~3B 激活参数、Apache-2.0、arXiv 2610.22196 "Attributed RL for Long-Term Memory Writing"）+ SDK + MemHub v1.0.5（本地统一 Claude Code/Cursor/Codex/OpenCode/Qwen Code 四类工具历史）。自称宏平均 55.49% 对 Claude Opus 5 的 54.62%——但为固定 20% 子样本自测口径，未经独立复现。这是第 46 期"抽取器≠判别器"的产业级回应：写入值得一个专门的模型。但 MemHub 把多家工具的敏感编码历史聚合到一个目录，其权限模型（第 45 期）从可选项变成了关键依赖。

AML 二期：评估 11-04 截止，官方口径更新奖金为 US$22,000，榜单 11-11 仍未发布；CSDN 11-06 预热文章聚焦 MemoraX（58.02）与 MemOS（45.89）的 12.13 分差距及代码榜三个 52.00 同分系统的分化悬念。

最锋利的对照来自 CMU 的 CompressionBench：**模型权重压缩已有独立验证门**（独立容器复核，生成准确率须保留 BF16 的 80%，且完整模型反馈推翻了 79 个局部排名中的 17 个），而**记忆压缩连"摘要保留 80% 信息"这样的验收门都不存在**——同一周的两篇论文，一个建立了验证文化，一个证明其缺席。

## 四、技术挑战

三个结构性缺口：

1. **压缩账是第五笔账。** AML 的 Add/Search 合同完全不区分系统内部压缩策略：参与者可以在 Search 前把记忆压到面目全非，榜单分无法区分能力与压缩损失。继第 42 期三重账、第 48 期版本账之后，榜单混入的是第五笔账——压缩账。倒挂第 40 次：压缩语义最完整的三个实现（确定性回溯、重构指标、行为训练）全在论文与工程侧，产品只报 token 节省。口径缺口第 41 次。
2. **不可逆压缩是授权与灾备的偷渡口。** 摘要里嵌着授权记忆化产物（第 45 期）时，原件删除后摘要照常流通；原文被压掉即失去第 2 期的删除举证能力。主张三字段：`compression.mode`（lossless/lossy/reversible）、`compression.reconstructable`、`summarizer_version`——最后一个是第 48 期 writer_model 的压缩器版：摘要器也是写入者，其 checkpoint 跨 harness 迁移（SUMONE 已证明可行）反而让它成为第一个应当被 pin 的资产。
3. **行为先于策略。** Memento 的教训对第 46 期入库门是釜底抽薪式的：门的策略写进 prompt 没有用，因为模型没有写路径习惯——RL 无法从零探索出该行为，必须先 SFT 演示再强化。记忆行为不是能力，是习惯；而行业目前全部的写入策略都押在 prompt 上。

## 五、需求、用户旅程与实现方案

**需求分解**：① 长任务 agent 必须压缩上下文（成本与窗口双重约束）；② 采购方需要"省了多少、丢了什么、能不能找回"三问的答案；③ 压缩产物需继承原记忆的全部治理属性（授权/删除/同步）。

**用户旅程**：开发者接入 → agent 长任务中上下文到期 → 触发 compaction，摘要替换原文 → 后续任务需要细节 →（可逆路线）凭 node_id 读回原文继续；（不可逆路线）只能拿摘要再答，细节永久丢失 → 排障时无法归因：分不清是记忆没记住、检索没取到、还是压缩压掉了。

**实现方案**（三步，按成熟度排序）：① 短期——压缩门两态强制：可逆压缩须带回溯指针，不可逆压缩必须标记 `compression.mode` 并把原件纳入备份单位；② 中期——借 SUMONE 的 masked reconstruction 做发布前 swap test：摘要冻结后由重构器盲测，重构得分低于阈值即回滚（CompressionBench 独立验证思想移植到记忆层）；③ 长期——写入行为训练化：像 Hy-Memory 2.0 与 Memento 那样，把"记什么、压什么"从 prompt 迁入专门模型，SFT 演示打底、RL 收口，并以自监督重构替代下游分数作为奖励，避免任务耦合。
