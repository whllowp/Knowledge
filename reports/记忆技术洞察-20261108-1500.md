# 记忆技术洞察 第33期：记忆的积累曲线——收益全在前 25%，且只买时间

**时间**：2026-11-08 15:00（GMT+8）
**覆盖窗口**：2026 年 10 月中旬—11 月 8 日（重点为最近 30 天）
**本期主线**：第 16 期问过"记忆从哪来"（来源三径与出生证明），答案是导入绕过治理。本期换一根轴，问"记忆从第几天开始值钱、值多少、值在哪一栏"，答案是——它只值时间，不值分数，而且只在开头值。

---

## 一、发展趋势

第 16 期记录过 11 月第一周"四家同做导入"的竞争潮，那是从供给侧看的。本期从收益侧看，三个信号说明衡量口径正在换。

其一，产品首次把建库成本交到用户手上。腾讯混元 MemHub v1.0.6（2026-11-06）把记忆强度做成 onboarding 首屏选项：lite 不调大模型、直接存原文检索；pro 走大模型抽取；ultra 再加知识图谱与每晚整理。这是目前唯一把"要不要付建库成本"显式前置的产品。

其二，论文首次把起点写成方法的一部分。EvoGroup（arXiv 2611.03868，11-02）自述从"minimal six-tool cold start"起手，靠自演化把 EverMemBench 留出集 pass@1 从 71.07% 提到 89.58%，超过人工设计的 Claude Code harness（85.83%），并在未见的 GroupMemBench 上冻结迁移仍有增益。

其三，商业产品把冷启动当作卖点。TencentDB Agent Memory 的第三方评述直接写"通过把历史工作轨迹转成可复用、可治理的资产来解决 Agent 的冷启动问题"，路径是 Chat/Skill/Wiki/CodeGraph 四类资产批导。

更值得注意的是 OpenViking 的目录分家：`viking://resources` 可由 `ov add-resource` 从外部仓库整段导入，`viking://user/{id}/memories` 只能由会话结束后蒸馏生成。这一分为二等于承认：**知识可以导入，记忆不能**。第 1 期说"写入侧独立化"，本期补一句——写入侧里只有蒸馏这一环不可外包。

竞争轴因此从"库容"移到"库龄"。第 24 期问"库大了会不会变笨"，本期问"库小的时候值不值"。

## 二、技术现状

### 1. 收益三分账：只有"收敛"一项全为正

Continual AutoResearch（arXiv 2611.05108）用 5 个前沿 Agent（Sonnet 4.6 / Opus 5 / GPT-5.4 / GPT-5.6-Sol / Kimi K3）、4 个域 9 个任务族、每模型 32 个迁移任务、30 分钟预算，把"有状态 vs 重置"拆成三笔账：起跑线（首个有效解得分）、收敛（固定预算内 best-so-far 曲线面积）、终点（最终提交得分）。

终点增益：Opus 5 −0.9、GPT-5.6-Sol −0.8、GPT-5.4 +0.2、Kimi K3 +0.4、Sonnet 4.6 +7.6。收敛增益五家全正（+3.0 至 +21.3）。起跑线增益 −1.0 至 +7.0。

一句话：**记忆几乎不提上限，只提前起跑，并把搜索过程压得更早。** 行业所有榜单都在终点那一栏打分，而记忆真正兑现的是中间那一栏。这给"口径缺口"第一次提供了方向性解释——不是少了一个维度，而是打错了那一栏。

### 2. 早期集中律：收益在 25% 预算处见顶，到截止基本归零

同一份实验的时间切片最能说明问题。预算 25% 处，有状态相对重置的平均领先 +24.0 个归一化奖励点；50% 处 +15.7；75% 处 +6.5；100% 处 +1.2。衰减近 20 倍。原因是重置版能靠任务内探索追平——时间越充裕，"更早起跑"越不值钱。

这解释了一件长期矛盾的事：用户体感记忆很有用（他们看的是前十分钟），榜单测不出差距（它看最终分）。也修正第 21 期的"记忆-上下文等成本曲线"：记忆应按"被节省的墙钟时间"计价，而不是按"被提升的准确率"计价。

### 3. 只买时间：首解提前 3.4—8.6 分钟，其余增益归负

首有效解时间（有状态/重置）：Opus 5 7.7/11.1 分钟、Kimi K3 9.5/18.7、Sonnet 4.6 7.7/16.3、GPT-5.4 8.4/9.2。把首解奖励从总增益里扣掉后，五个模型的收敛增益全部转负，只有 Sonnet 4.6 在"同等候选数"与"去除首解延迟"两重对照下仍为正（+6.5 / +6.6）。

即：**记忆的全部价值集中在"第一次能动手"那一刻**，之后的优化它不但不帮，还略微拖累。第 32 期的"干扰"在这里有了经济学形态——旧经验收窄了搜索。

### 4. 负迁移率 33%—66%，越强的模型越容易中

负迁移率（有状态反而更差的任务占比）：Opus 5 65.7%、GPT-5.4 48.1%、GPT-5.6-Sol 40.7%、Kimi K3 38.0%、Sonnet 4.6 33.3%。最强的 Opus 最容易被旧经验带偏。论文给的案例很具体：高度特定的卡片把 Sonnet 锚定到更弱的模型族；Agent 把上一任务的运维经验套得过猛，用"过拟合候选"替掉了稳健候选。

这是第 29 期"能力的诅咒"的第二次独立验证，但机制更锐：不是危害随能力上升，而是**能力越强，越有能力把一条不适用的经验执行到底**。

### 5. 冷启动期"相关性"不兑现，只有"卡的存在"兑现

记忆消融（Energy-systems 流，每任务全新会话，仅通过 Agent 自撰 insight cards 传递信息）：matched（同流卡片）对 no-memory 的最终增益，Sonnet +14.7、GPT-5.4 +5.0；shuffled（无关流等量卡片）对 no-memory 是 +14.9、+4.8。**两组几乎相同。** matched 减 shuffled：Sonnet −0.2、Opus +1.0、GPT-5.4 +0.2、GPT-5.6-Sol −3.2。

含义很硬：在小库/冷启动期，起作用的不是"记住了什么"，而是"有没有一张结构化卡片"（六字段：主张、证据、置信度、适用范围、推荐行动、失败条件）。第 30 期讲"形态集中律"——同一条记忆换送达形态，效果差 10—16 倍；本期推到极端：**冷启动期形态就是全部，内容还没到起作用的时候。**

这同时修正第 16 期对导入风险的定级。第 16 期判"无出生证明的导入条目"是最大隐患，理由是治理绕过。从收益侧看，导进来的内容在冷启动期本来就不承担"正确性"职责，承担的是"给一个可引用的骨架"；真正该担心的不是它不干净，而是它把骨架定死了（见第 8 条的"起点是约束"）。

### 6. 库越长，初始化越好，收敛越差

流长度 3→5→7 个任务：初始化增益 +3.56→+5.53→+5.34（上升后走平），收敛增益 −1.75→−3.61→**−31.44**（急剧恶化）。操作失败率则有分化：Sonnet 30.7%→7.7%、Kimi 11.4%→1.8%，但 GPT-5.6-Sol 反向 1.7%→8.3%。

积累不是单调的。前 2—3 个任务在攒"能用的东西"，第 6 个之后开始攒"该扔但没扔的东西"。第 19 期说"死的判据不可计算"，本条给了它一条可测的下降沿。

### 7. 真正的瓶颈在写手，不在数据

Memento（2611.00244）的对照组：GPT-5.5 在 337 条测试上一条压缩笔记都没写；GLM-5.3 跑 1.2 万条 rollout，零条有效笔记；Qwen3-8B 约 6% 轨迹有效；不做 SFT 预热，RL 20 步内把记笔记频率降到零。对照 Hy-Memory-30B-A3B（2610.22196）：专门用归因 RL 训练的写入模型，宏均 55.49 对 Opus 5 的 54.62。

同一件事——通用前沿模型不会写条目，专用小模型会。这推翻冷启动的默认叙事：行业把它当"时间问题"（等库长起来），实际是"能力问题"（第一天就写不出好条目）。时间解决不了，换写手才解决。

### 8. 起点越小，演化空间越大

EvoGroup 从六个工具起手，自演化到 89.58%，压过人工精心设计的 harness；MemSkill（NeurIPS 2026，2602.02474）从四个原语（add/update/delete/skip）起手，靠 Designer 分析失败案例扩技能库，跨模型零样本迁移仍有增益。共同方法论是：**起点是约束，不是资产**——预置越多，可演化方向越少。

反面是 DAEDALUS（2610.08048）的警告：只靠探索攒记忆、不做"连续成功三次"的验证，Agent 比完全没有记忆**更差**；加上验证关卡后成功率跳升 4.5 个百分点（这是消融口径；第 16 期记的 +15.9pp 是对基线口径，两组数字不冲突但含义不同——前者说"验证是命门"，后者说"自生成整体有效"）。自生成种子是唯一不依赖人工的冷启动路径，但它必须自带验收器。

## 三、技术竞争力

冷启动的竞争不在"能不能记"，在"第一个小时里能不能用"。按种子类型分四类：结构种子（空内容、有骨架）、内容种子（导入/继承）、自生成种子（自己练）、无种子（纯累积），也有一类干脆取消积累期。

| 方案 | 冷启动起点 | 种子类型 | 首个可用 | 写手 |
|---|---|---|---|---|
| OpenViking | 空目录 + 三层目录树 | 结构 + 资源导入 | 首次会话后 | 宿主模型 |
| TencentDB-Agent-Memory | 历史轨迹批导 | 内容（四类资产） | 导入完成时 | 抽取管线 |
| Hy-Memory / MemHub | lite 档直存原文 | 结构 + 跨应用历史 | 第一轮对话 | 30B-A3B 专用 |
| ReMe | runbook 模板 | 结构 | 首次运行 | 宿主模型 |
| dsh-memory-evolve | 空库 + 合并阈值 | 无 | 数轮之后 | 宿主模型 |
| Mem0 | add() 即写 | 无（可导入） | 第一轮对话 | 抽取 LLM |
| Letta | 预置空 memory block | 结构（仅骨架） | 首轮 | Agent 自编辑 |
| Memorilla | 16 token 固定槽 | 取消积累期 | 即刻 | 学习式放置 |
| EvoGroup（论文） | 六工具 | 自生成 | 自演化中 | 自演化 |
| DAEDALUS（论文） | 自出题练习 | 自生成 + 验收 | 建库后 | 提取器 |

判读三条。第一，唯一把建库成本做成**可选项**的是 Hy-Memory（lite 档零 LLM，第一天即可用）；唯一把冷启动写成**方法**的是 EvoGroup；唯一把知识导入与记忆蒸馏**分开**的是 OpenViking。三者各占一角，没有一家同时做到。

第二，头部商业产品仍以"纯累积 + 内容导入"为主，没有一家披露"第 N 天可用率"。TencentDB 按 Credit 计费，但预抽取一次要多少 Credit 无公开数据；MemHub 的 lite/pro/ultra 是档位不是账单。

第三，卖种子的社区项目反而提供了最完整的结构种子：gentle-ai 8.4K★ 主打 curated skill library + 教学型 persona，obsidian-mind 5.5K★ 干脆就是一个 vault 模板，dsh-memory 606★ 走非 LLM 白盒管道。倒挂第二十四次——最会做冷启动的仍是没利益在"多记"上的一方。

## 四、技术挑战

1. **冷启动不可评测。** EverMemBench、GroupMemBench、LoCoMo、LongMemEval 都把历史当给定输入，AML 的 Add/Search 契约也假定库已存在。唯一把"任务位置"当自变量的是 2611.05108，而它是 harness 论文，不是记忆榜单。口径缺口第二十五次。
2. **结构种子的收益被误记为内容收益。** matched≈shuffled 意味着采购方无法用 A/B 判断"买的到底是骨架还是知识"。
3. **负迁移无闸门。** 33%—66% 的任务上记忆有害，而没有产品在写入时判断"这条经验会不会被误用"。
4. **建库成本不透明。** 档位制掩盖了"预抽取一次要多少钱、要多少条才回本"。
5. **自生成种子的验收器成了新单点。** DAEDALUS 的"连续成功三次"由 Solver 自身判定，Judge 可靠性即上限；一旦判定宽松，库会在第一天就被污染。

## 五、展望与建议

**三条判断。** 其一，半年内会出现"库龄曲线"作为一等指标——第 N 天可用率、拐点任务数；谁先公布，谁拿到采购不对称。其二，记忆的定价会从"增强"转向"节省的墙钟时间"，因为终点增益不成立而收敛增益成立。其三，结构种子会先标准化（承第 28 期"schema 即世界观"），内容种子仍无法跨组织迁移。

**三条建议。** 采购侧：要求供应商给出空库第 1/3/10 次任务的三点测量，而不是单一总分；单看终点分会系统性高估记忆价值。自建侧：第一天就落结构种子（六字段卡片），不要等库长起来；同时把"连续成功 N 次"作为入库闸门，宁可空库也不要脏库。写手侧：优先用专用写入模型或 SFT 预热，不要指望前沿模型自己会记笔记——它真的不会。
