# 记忆技术洞察 · 第 97 期（20261116-1500）

**主题：记忆的「引擎层栖居」——留存 ≠ 可检索（residency ≠ retrievability）**

> 洞察范围：2026 年（近 30 天为主）。四维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

前 96 期讨论记忆"存什么、删什么、读什么、值多少、花多少"，默认其栖居在文本、向量或权重三层（#68/#81）。2026-11 的 PACE（arXiv 2611.10240，11-06，AWS）把记忆再下沉一层——到推理引擎运行时的 KV cache 状态，揭示一个被忽视的瓶颈：记忆即便被正确选中、物理上驻留缓存（residency 99.6%），只要它与 query 的 RoPE 位置距离过远，模型仍"看得见却用不了"，通过率随距离 2K→90K 从 93% 跌到 64%。价值兑现链在"选中→装入"后新增一环"位置可达"，栖居基质由二选一变为三选一。

## 二、技术现状

PACE 把长时程 KV 管理拆成正交双因子：①plan-aware retention——用 planner 已产出的依赖图 blueprint 给未来会被引用的 token 加 foresight bonus（σ=10⁵、下限 50K、λ=0.35），确保不被驱逐；②bounded positions——resident token 物理位置逼近上限时重新编号并对缓存 key 精确 re-rotate，把到 query 的旋转距离恒压在 2–7K。再叠加 persistent sessions（每步只发新增消息、决策跨步累积）与 tiered rehydration（被驱逐行卸载到主机内存→本地盘→远端 Valkey，按需从最近层恢复，主机 2.3ms / 远端约 2.7s）。100K token、2048 预算下 hidden checks 达 97%（H2O 42%、SnapKV 3%），300K/1M/2M 分别 100%/99%/100%，全程 KV 状态 <0.7GB（2M 全量缓存需 295GB）。

## 三、技术竞争力

竞争焦点从"召回率更高"转向"引擎层可用性 SLO"：只做留存 63%、只做位置 63%、两者合一 97%（L=40K 时交互增益 +27.6 点，p=0.0014）——两个 63% 不相加而是相乘，记忆质量是双因子而非单轴。五个开源项目（OpenViking v0.5.4、Hy-Memory 2.0.13＋MemHub v1.0.6、TencentDB-Agent-Memory v2.0.3、dsh-memory-evolve v26092802、ReMe v0.4.2.2）全部工作在文本/向量层，零 KV 运行时介入、零位置几何披露，倒挂延续：前沿在引擎层论文，产品缺席。

## 四、技术挑战

①bf16 key 反复 re-rotation 会数值漂移（60 次重旋相对误差 0.031），须用 fp32 reference store 压到 0.003；②交互增益在推荐 L=8K 下不显著（+8.3 点，p=0.32），只敢主张"两组件都必需"；③foresight 下限约 5M token 后会被无保护注意力追平；④主机恢复 2.3ms、远端 2.7s 的 3 个数量级差使容错设计两难；⑤主结论在 Qwen3-8B 上最强，Mistral-7B 受 40% 编码上限约束。

## 五、需求分析

长时程代码/研究/助理跨会话累积历史，KV 预算是硬约束。用户要的不是"事实躺在库里"，而是"关键时刻能被用上"——正是留存与可检索之差。

## 六、用户旅程

planner 产出依赖图 blueprint → 引擎据此对将被读取的 span 加 foresight bonus 予以保留 → 位置逼近上限时重编号 + 精确 re-rotate 保持位置有界 → 被逐出行分层卸载 → 下一步 planner 报出所需 span 时从最近层恢复、splice 回并重编号 → 决策随 persistent session 跨步累积。

## 七、具体实现方案

在 SparseEngine 的 H2O cache manager 上做 subclass，配置开关启用（三组件全关时与 H2O 逐 token 一致，ablation 受控）；blueprint 作为额外 request field 传入 OpenAI-compatible server，无需改模型；bounded positions 取 L=8192、预算 B=2048、prefill chunk 4096；resident key 首次重编号时拷入 fp32 reference store（每层 4096 token、约 0.3GB），后续位置从 reference 重推，slot 复用即失效。

## 八、本期新观点

1. **第三栖居基质**：#68 是参数化 vs 非参数化静态之争，#81 是权重 vs 文本按年龄路由；本期提出运行时 KV cache 是第三基质——记忆在此的可用性由位置几何而非语义相似决定。
2. **把 #73 利用鸿沟下沉一层**：#73 管"证据拼装成多形态对象"，本期管"证据在 RoPE 位置空间里够不够近"——检索到≠用对，在此表现为 resident≠retrievable。
3. **留存与可检索正交且相乘**：记忆质量非单轴优化，须双 SLA 并置。
4. **遗忘的可用性形态**：#60/#73 的遗忘是合规不可逆擦除；PACE 的驱逐是分层卸载＋可恢复，两种"忘"方向相反，构成张力。
5. **决策持久化**：每步重发完整 transcript 会让上一步驱逐决策被静默重插回，"驱逐质量永不跨步累积"——persistent sessions 是 #71 状态化坍缩在引擎层的前提。
6. AML 应补 engine-layer retrievability 维度（留存率 / 位置可达率 / 重水化恢复率 / 决策跨步存活率），接 #56/#69。
