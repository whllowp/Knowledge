# AgentMemory 技术洞察 · 第 79 期（20261113-1200）

> 范围：2026 全年（重点近 30 天，截至 11-13）｜固定四维：发展趋势·技术现状·技术竞争力·技术挑战
> 主题：记忆的价值判据从"相关性"迁移到"决策效用"——relevance ≠ utility，记忆的终点是决策不是召回
> 新源：MemCredit（arXiv 2611.15600，11-11）、MemRole（2611.01778，11-01）、EvoMemState（2611.03743，11-02）、Memory-Aware Multi-Agent（2611.08718，11-05）

## 一、需求分析（对应·技术挑战）
企业 agent 跑长流程（网页操作、长期角色扮演、跨会话软件工程），记忆库动辄上千条，行业却默认用"语义相关性"选记忆——BM25 / 向量 / RRF 召回与当前问题最像的条目。MemCredit（arXiv 2611.15600，11-11）用受控反事实实验证明：语义最相关的记忆，对当下动作常常零贡献；记忆效用**稀疏、强状态依赖、相关性几乎抓不住**。这意味着"召回对"和"决策对"是两件事——相关性判据在长程决策任务上系统性失灵。这催生新需求：记忆选择必须按"对当前动作的边际贡献"而非"与查询的相似度"来仲裁，否则高召回只会延续 #75 反噬（用错记忆使决策更差）。

## 二、用户旅程（对应·发展趋势）
把 agent 一次"凭记忆做动作"的旅程拆开：
1. **候选生成**：仍用语义相关性做高召回粗筛——把可能相关的记忆捞出来（MemCredit 不废相关性，只把它降级为第一道网）。
2. **效用仲裁**：对每条候选做受控反事实干预——在去掉它、其余状态 / 参考上下文 / 策略不变的假设下，动作是否变坏？估计其边际贡献，蒸馏成轻量效用估计器。
3. **预算淘汰**：在固定 token 预算内，由预测效用而非相似度保留 / 淘汰。
这标志范式从"检索器"转向"决策输入仲裁者"——MemRole（11-01）的 LHMT 把"记忆→动机→策略"推理显式化、EvoMemState（11-02）引入"推理态"决定事实如何应用于当前请求，三者合流：记忆的终点是决策，不是召回。

## 三、具体实现方案（对应·技术现状 + 技术竞争力）
- **反事实边际贡献**：MemCredit 通过受控干预估计单条记忆的 state-/reference-context-/policy-conditional 边际贡献，再蒸馏为**不改动 agent 策略、不需额外环境交互**的轻量效用估计器；ALFWorld 500-token 预算下 SR@50 达 **86.57% vs BM25 65.67%**，WebShop 同样印证。
- **与 #70 条件效用分工**：#70（2611.03930）在评测层测"有无记忆的任务奖励差"，MemCredit 在运行层把效用做成"按边际贡献选记忆"的可执行检索仲裁——效用从打分变成动作。
- **五项目断层（竞争力）**：OpenViking（v0.5.4.1, 11-11）L0/L1/L2 + 语义检索、Hy-Memory（2.0.2）30B 写入模型做合并但检索仍相关度、TencentDB（v2.0.3）决策服务只管 Skill 选择 / L3 更新判定、dsh（v26092802）七标准合并但无关效用、ReMe（v0.4.2.2, 11-05）wikilink+BM25+RRF——全为相关性检索，**零决策效用评分**，倒挂延续（接 #56/#70/#73/#75）。
- **评测口径**：MemCredit 首设 decision-utility 实证（效用稀疏、状态依赖）；AML 实时榜仍按召回 / 治理 / 执行排，**缺 decision-utility 维度**（接 #56）。

## 四、四维速览
- **发展趋势**：记忆价值判据从相关性→决策效用，2026-11 三篇论文合流（MemCredit/MemRole/EvoMemState），系统定位从"检索器"升级为"决策输入仲裁者"。
- **技术现状**：MemCredit 在长程网页任务上用反事实边际贡献 + 轻量蒸馏实现 86.57% vs 65.67% 的跨越；效用稀疏、强状态依赖、相关性捕获差。
- **技术竞争力**：决策效用是比利用率更隐蔽的指标（承 #30），五项目零决策效用评分；TencentDB 决策服务为部分交集但不同轴（管 Skill 选择，不仲裁记忆→动作）。
- **技术挑战**：反事实干预成本高（需受控环境交互 / 重放）、效用估计器漂移、固定预算下的淘汰误杀、跨任务泛化（WebShop 等）、与相关性召回的融合。

## 本期新观点
① 记忆终点不是召回而是决策——相关性 ≠ 效用，效用稀疏且强状态依赖（MemCredit 反事实实证）；② 决策效用比 #70 条件效用更进一层：从评测打分变成运行层按边际贡献选记忆的可执行仲裁；③ 反事实是记忆选择新原语——受控干预估 state/ref-context/policy 条件边际贡献、蒸馏成轻量估计器，相关性只做高召回粗筛；④ 三类 Nov 论文合流印证拐点：记忆系统正从"检索器"变"决策输入仲裁者"；⑤ 五项目零决策效用评分、TencentDB 决策服务不同轴，倒挂延续，AML 应补 decision-utility 维度。
