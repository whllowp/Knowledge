# AI-SRE 技术洞察（第 325 期）

**生成时间**：2026-11-27 03:00（GMT+8）
**主题**：因果排序面／Causal-Order Integrity——「时间戳排出来的先后，不是 parent_id 写着的因果」
**时间范围**：2026 年，重点最近 30 天

> **题眼**：第 84 期问过「证据上的时间戳是谁的钟」。本期推进一层：就算所有钟都对准了，「按时间排序」依然不等于「按因果排序」。一条 trace 的因果写在 `parent_id` 树里，时间戳只负责把树画成瀑布图；当两者冲突时，Agent 若把图当数据，就会稳定地把「时钟走快的那台机器」判成瓶颈。可观测性行业卖的是「看得见先后」，而根因分析需要的是「看得见谁调用了谁」——这两件事从未被同一道门禁验收过。

---

## 一、发展趋势

**趋势一：从「时间基准」转向「因果基准」。** 11 月 1 日一篇可复现工程文章给出了一组刺眼的数字：三台机器分别偏 +180 ms、0 ms、−95 ms，200 条 trace × 2 条父子边共 400 条边，未校正时按日志时间戳排序有 **371 条颠倒（92.8%）**；按最小 RTT 估计偏移校正后降到 0/400，但作者明确提醒「0 是饱和值，说不了余量」——真正可信的是残差 +0/+1 ms 相对最小间隔 10 ms 的十倍余量。这类工作把「颠倒率」从显示瑕疵升格为可验收指标。

**趋势二：Agent 从「解释事故」走向「值班」，但解释本身还没被验收。** 11 月 22 日 AI Ops Weekly 汇总：Resolve AI 发布 270 亿参数开放权重 SRE-1（自称 80% 告警无需升级、95% 根因准确率）；groundcover 的 Agent Investigations 增设必须为每条结论签字的 Moderator；OpenAI 披露 Performance Factory 三个月跑 1700+ 次调查、定位 600+ 起、但真正合入的 Codex 作者 PR 只有约 15 个。同一周 GigaOm 对 31 款 AIOps 产品的扫描发现「回滚已执行动作」仍是稀有能力。能力在往前跑，结论的因果方向却没人签字。

**趋势三：语义层与图谱正在成为「边」的权威来源。** 腾讯云 10 月 29—30 日数字生态大会（11 月 3 日报道）把 CloudQ 的底座定为「全景图谱」——云 API 直采资源、调用、依赖、挂载关系，每次推理前先结构化查询图谱再基于「眼前的事实」推理；阿里云云监控 2.0 提出「让 Agent 看懂系统，也能看懂 Agent」，用 UModel 把事实变成 Agent 读得懂的语义，并沿链聚类做性能、成本、质量、安全四类归因。两者都在做同一件事：把「谁连谁」从时间戳里独立出来，变成可查询的事实。

**趋势四：规范层仍在发育，字段本身在变。** OpenTelemetry GenAI 语义约定 2026 年 2 月进入 `gen_ai.*` 实验命名空间、6 月拆到独立仓库，到 11 月 Agent／工具／MCP 的 span 定义仍全部是 Development，无一 Stable；`gen_ai.system` 已改名 `gen_ai.provider.name`，MCP 跨调用的 trace context 藏在 JSON-RPC 的 `params._meta` 而非 HTTP header。规范里没有「这条边的因果依据是什么」的字段。

## 二、技术现状

**现状一：单机自洽是最完美的伪装。** span 的 duration 是同一台机器上 `end - start`，共用一个时钟，偏移在减法里抵消——所以每台机器的看板全绿：耗时正常、错误率为 0、P99 平稳。只有当两台机器的数据被放进同一张图，偏移才可见。触发颠倒的条件是一条不等式：**两端偏移之差 > 这一跳的最大真实延迟**，与流量、负载、代码都无关。上述例子中第一跳真实间隔 10—60 ms、偏移差 180 ms，200 条边一条不漏全反；第二跳偏移差 95 ms 落在真实间隔 20—120 ms 区间内，171 条边变成概率性颠倒。

**现状二：排障会沿着三个方向稳定跑偏。** 按「最早开始的是入口、最晚结束的是瓶颈」的自动归因规则，检索服务被列第一嫌疑、网关排队第二；按「第一个变慢的环节」找时间轴空隙，会稳定指向时钟走快的那台机器；告警规则写「子 span 必须晚于父 span 开始」虽然没错，却会把九成以上 trace 判成异常，最后被白名单关掉。更隐蔽的是：370 多条颠倒边里**没有一条父子关系真的错了**——`parent_id` 从头到尾没被碰过，被写反的只是给人看的图。

**现状三：修完之后的判据比修本身更重要。** 该工作给出四条可配置规矩：墙钟只跨机比、单调钟只管机内；偏移只对参考点直接估、不沿调用链累加（逐跳累加会把 δ 放大）；时间戳只排序不判因果；验收要三条线同时看——残差 ≤ 最小父子间隔 ÷ 5、δ/2 ≤ 最小父子间隔、颠倒率 ≤ 1%。1% 的来由是一条 trace 平均两条边，意味着每 50 条 trace 就有一条给出反向结论。

**现状四：行业开始有「边」的意识，但没有「颠倒率」的位置。** Google 11 月 13 日为 Data Cloud 增加 Agent 可观测与评测：遥测落到客户自有 BigQuery 表、Cloud Trace 提供逐步 span、Prism 评测结果写回分区表；但隐私保护采用 fail-closed——一旦知识源用了行级安全或动态脱敏，就跳过整轮日志，恰恰在最需要取证的时刻失去证据。OTel GenAI 规范覆盖 span 树与 token 属性，却无 `clock_source`、`skew_bound`、`inversion_rate` 字段。

据此，本文提出第 246 个空白字段族 **`causal.order.*`**：`trace_id`／`edge_count`／`causal_basis∈PARENT_ID|TIMESTAMP|GRAPH|HUMAN`／`clock_source∈WALL|MONOTONIC`／`skew_estimate_ms`／`residual_ms`／`skew_bound_ms`／`min_parent_gap_ms`／`inversion_rate_pct`／`inversion_budget_pct`／`ordering_state∈ORDERED|INVERTED|BOUNDARY_UNSAFE|UNVERIFIED`／`verdict∈CAUSAL_VALIDATED|ORDER_ONLY|UNVERIFIED`，缺省 `CAUSAL_ORDER_UNVERIFIED`。

## 四、技术挑战

1. **一致比随机更危险。** 系统性偏移符号固定，会持续把同一批边推向同一侧；「稳定、比例固定的乱序」更像代码 bug 而非时钟故障，极易被当成偶发或写成白名单。
2. **图与树的降级顺序反了。** 常见实现先按时间戳排序再补父子关系；正确顺序是先按 `trace_id` 分组、`parent_id` 建树，再用时间戳校验，校验失败只降级时间线视图、不降级调用树视图。
3. **余量被 0 掩盖。** 「校正后 0 条颠倒」是饱和值；作者三条判据中两条过、一条不过（δ/2 = 12.5 ms > 最小间隔 10 ms），结论应是「这次抽到对称样本，机制上不保证」，进风险登记而非 SLA。
4. **成本花错地方。** 把残差从 1 ms 压到 0.1 ms 而最小间隔仍是 10 ms，判序能力一点没变、成本跳一个台阶；标准是间隔，不是残差。
5. **基准测不到这一维。** ORCA-bench（11 月 4 日榜单）GPT-6 Astra 50.2%、Claude Opus 5 44.3%、Kimi K3.1 Pro 32.9%；论文版本 1079 任务中最好 25.3%／困难 10%，7%—40% 报告编造不合理根因，去掉源码访问后所有模型更差。ITBench-AA 最好 56.2%，图引导方法在 23 个 ChaosMesh 耦合场景把 F1 从 0.6087 提到 0.9130。这些基准都给准确率，没有一个报「因果方向被时钟颠倒了多少」。
6. **隐私与取证同向冲突。** Google 的 fail-closed 跳过日志、脱敏跳过写轮，越是需要还原因果链的场景，机器可读的边越少。

## 五、展望与建议

**结论**：本期把「排序」与「因果」正式分家——这是第 84 期时间基准面的后继而非重复：前者管「哪一时刻为真」，本期管「哪条边为真」。建议把第 246 字段族与 `CAUSAL_ORDER_UNVERIFIED` 门禁接入既有 #310—#324 的「可举证率」叠加链：verdict ≠ `CAUSAL_VALIDATED` 的根因结论不得进入自治升档与横向排名。

**四条最小动作**：① 合并 trace 时先建 `parent_id` 树再校验时间戳，核验失败只降级时间线视图；② 任何「按时间戳推断谁调用了谁」的逻辑，颠倒率超 1% 立即关闭；③ 每次合并留档参考点、δ、残差上界与样本，把偏移当属性而不是当错误去消除；④ 把「残差 ≤ 最小间隔 ÷ 5 且 δ/2 ≤ 最小间隔」写成停手线，最小间隔 <1 ms 时改为同机产父子 span 或硬件时间戳。

**采购三问**：你们的根因结论以 parent_id 树还是时间排序为依据？偏移估计与残差上界是否随遥测一起导出？颠倒率超预算时降级的是图还是树？三问答不出，就按 `UNVERIFIED` 处理。

**评测建议**：在 ORCA／ITBench 类基准中加「时钟偏移注入配对题」——同一事故给两版 trace（对齐／±180 ms 偏移），报 `inversion_rate` 与根因方向翻转率；只报平均准确率的榜单无法区分「真懂因果」与「碰巧排序对」。信通院《云上 Agent 基准度量模型》六维之外，建议补「因果排序可举证率」一格，与 #316—#324 的审批、授权、空窗、判定、自伤、收口、归因、测量、可读性各格并列。

**本地知识积累**：本期把 173 目录中蒋烁淼《千亿数据秒查到真正的 AgentOps》重读为「图谱的边先于时间戳存在，AgentOps 的稀缺品是不随时间漂移的关系事实」，配赵恒语义层（把边写成可执行事实）、刘凯宁三分（因果结论／证据／待确认分开）、周昕毅白名单＋人工兜底，作为因果排序面的本地原型；目录按目录级引用。
