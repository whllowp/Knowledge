# AI-SRE 技术洞察（第 152 期）

**生成时间**：2026-11-12 14:00（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：韧性演练面／Agent 混沌工程面（Resilience Drilling / Agent Chaos Engineering）——生产里的 Agent 只会被真实故障打，没人主动演练它在「工具失能／模型降级／依赖 429／上下文截断／记忆污染」时的降级行为；演练不进发布门禁，等于没演练

## 题眼

The Register 2026-10-08/09 报道、Gremlin 于 10-07 发布的 **Foresight AI** 把混沌工程推到「先打后修」的 agentic 闭环：安装在客户环境的 agent 注入延迟、杀 pod、吃满内存，云侧用 **Failure Atlas**（十年、数万系统、数百万次实验）做根因推理与修复，重跑原实验验证修复，人工在关键节点把关，持 SOC 2 II 与 PrivateLink。**但它打的是 Agent 所管理的基础设施，不是 Agent 自己的依赖面。** 同期（第 9 期）开源的 **the_chaos_monkey_agent**（LangGraph 三智能体：规划-执行-分析）才把混沌对象反转到 Agent——注入 LLM 降级／工具故障／网络异常——却只是研究玩具，无故障库、无降级断言、无发布门禁。两者之间，横着一道无人填补的缝：**所有演练都打「别人的系统」，没有演练打「Agent 自己」；所有门禁都为代码设，没有为 Agent 的韧性设。** **指标全绿、Agent 在跑、发布过了，可没人验证过它在工具失能／模型降级／依赖 429／上下文截断／记忆污染时到底降级成什么样——第一次看见，是在真实故障里。**

## 一、发展趋势

**趋势一：混沌靶心从「基础设施」迁移到「Agent 依赖面」。** 工具、模型、MCP、上下文、记忆是 Agent 真正的命门；打系统保的是系统，打 Agent 依赖保的是 Agent 自己。

**趋势二：从「一次性实验」走向「发布门禁」。** 演练要像 CI——每次发布前跑一遍关键故障，且必须断言「降级符合预期」；否则演练只是团建。

**趋势三：从「人写故障剧本」走向「自动生成＋闭环修复」。** Gremlin Foresight 用 Failure Atlas 生成故障并 agentic 修复，但只覆盖基础设施；Agent 依赖面的自动生成仍是空白。

## 二、技术现状：Agent 依赖面的五类故障，通常零演练

**工具失能。** 工具超时、返回脏数据、schema 漂移（151 期说 schema 撑爆窗口，这里说它还会坏）；Agent 默认 fail-silent，错了也不说。

**模型降级。** 变慢、被限流、被静默换权重（128 期）、被退役（150 期）；根因结论可能悄悄变。

**依赖 429。** 下游 API 限流——TianPan 2026 初生产 60% LLM 错误来自限流耗尽（150 期）；多数 Agent 重试栈叠加放大中断。

**上下文截断。** 151 期预算溢出→Agent 在缺证据下通顺作答；演练里这叫「腐烂型失效」，不报错只变差。

**记忆污染。** 记忆被错写／被篡改（19 期温睦宁自进化负样本「记仇伪装」）；回放的是被污染的自己。

**现状结论：** 演练只打系统、不打 Agent；真实故障没被抽象成可重放实验；postmortem 不回灌演练。韧性是「事故发生后才知道有没有」，不是「发布前就证明过」。

## 四、技术挑战

**一，故障库缺位。** 没有标准化 Agent 依赖故障目录——工具／MCP／模型／上下文／记忆各自怎么坏，无统一定义。

**二，降级不可断言。** 「降级符合预期」没定义：是 fail-safe（安全失败）还是 fail-loud（大声失败）？多数 Agent 默认 fail-silent（151 截断不报错），演练也测不出。

**三，不进门禁。** 演练是附加项不是关卡；发布照过，韧性从未被挡下。

**四，不可重放。** 真实故障没抽象成可重放实验；postmortem 不回灌，同类故障二次打脸。

**五，爆炸半径反噬。** 对 Agent 注入故障可能触发它去改生产（145／127 自改风险）；演练本身必须 fail-closed。

**六，与评测混淆。** 演练≠评测（137 评测坍缩）；评测量能力，演练量韧性。

**七，多智能体放大。** 144 期协调税＋级联不可回滚；注入一个子 Agent 故障可能级联扩散。

**八，环境漂移。** 预发演练环境与生产依赖不一致，演练结论不保生产。

## 五、展望与建议

### 5.1 需求（按优先级）

- **R1 `chaos.*` 字段**：`fault_type`／`expected_degradation`／`actual_degradation`／`assert_pass`／`injected_at`／`replayed_from`。
- **R2 故障库**：五类 Agent 依赖故障标准目录（工具/MCP/模型/上下文/记忆）。
- **R3 降级断言**：每个关键动作定义 fail-safe vs fail-loud 预期，写入契约。
- **R4 演练门禁**：发布前必须跑 N 类故障且断言通过，不过不发布（像 CI）。
- **R5 重放对齐**：真实故障抽象成实验，回灌 postmortem 闭环。
- **R6 指标**：演练覆盖率／降级符合率／门禁拦截率／真实故障可复现率。

### 5.2 用户旅程

- **平台工程师**：接入 30 个工具 → 跑「工具失能」演练 → Agent fail-silent 漏告警 → 补 fail-loud 断言 → 门禁拦截 → 修后重跑通过。
- **Agent**：依赖 429 时显式声明「降级中」→ 不静默重试 → 上报 degraded。
- **SRE**：真实故障复盘 → 抽象成实验 → 加进门禁 → 下次发布前自动跑。
- **审计**：抽查一次发布 → 核门禁记录 → 确认跑过演练且降级符合预期。

### 5.3 实现方案（90 天）

- **0–30 天：埋点＋建库。** 记录 chaos.* 六字段；列出五类故障目录；选 3 个关键动作定义降级预期。
- **30–60 天：门禁＋断言。** 发布流水线挂演练门禁；fail-silent 一律判不通过；接 128/150 的模型/依赖故障注入。
- **60–90 天：重放＋复测。** 真实故障抽象回灌；季度复盘门禁拦截率；与 145 自改护栏共用 fail-closed。

**第 103 个市场空白（五项）**：Agent 依赖故障库覆盖率、演练进发布门禁率、降级符合预期可断言率、演练可重放率、韧性基线与真实故障对齐率——无一内建；`chaos.*`／`resilience.*` 为**第 70 次无人提字段族**。

**本地原型（第 63 期）**：**朱革 15「安全不是最后一道闸，而是从构建到执行的全程护栏」＋「场景仿真回放」＋「评估门禁、灰度和回滚约束」首次当主线**——全库唯一把「仿真回放＋评估门禁」写进 AgentOps 托管；配 **肖汉松 22（阿福 Agent 小队 Loop：回测与判定、单次迭代不可信时不流转、携带证据改派）**＋**刘凯宁 05（把大模型关进确定性笼子、强规则仍是主体）**。判词：**本地把场景仿真回放与全程护栏写进 AgentOps，联网侧 2026 才由 Gremlin Foresight AI 把混沌工程做成先打后修闭环，却只打基础设施不打 Agent 自己；两边都没把「每次发布前对 Agent 自己的依赖面跑一遍故障注入、且降级符合预期」做成门禁。**
