# AI-SRE 技术洞察（第 223 期）

**生成时间**：2026-11-16 17:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：故障域面／爆炸半径（Blast Radius）——Agent 的一个错，能传多远？

---

## 题记

116 期说「记录-现实漂移」，121 期说「隔离与池边界」，144 期说「编队」，178 期说「锁」，214 期说「Agent 间消息」。这五件事合起来，是一个很少被算的账：**Agent 的错能传多远**。传统服务有明确的故障域——进程、机器、可用区；**Agent 的故障域是「共享物」决定的**：**共享记忆**（一条坏记录污染全体）、**共享工具**（一个工具挂全队等）、**共享身份**（一个 key 泄漏全队被限）、**共享配额**（一个 Agent 刷爆全体）。**而 Agent 还会扇出**：A 调 B、B 调 C，**一个错沿着调用图扩散**。**隔离不是「多开几个容器」，是先画出共享物清单。** **画不出清单，就画不出半径。**

## 一、发展趋势

**趋势一：从「按进程隔离」转向「按共享物隔离」。** 记忆/工具/身份/配额；**共享什么，就一起坏什么**（121 期）。

**趋势二：故障传播从「同步调用」扩到「异步消息」。** A2A/队列；**错会晚到，也会重复到**（214 期）。

**趋势三：爆炸半径开始被估算。** 不是「会不会炸」，是**「炸到几个 Agent、几个租户」**（173 期）。**半径是设计出来的，不是事后数出来的。**

## 二、技术现状：四种共享，通常只隔离一种

**共享记忆：最隐蔽。** 一条错记录被检索；**十个 Agent 一起答错**（116 期）。

**共享工具：最直接。** 一个 MCP server 挂；**全队超时**（137 期）。

**共享身份：最致命。** 一个 key 泄漏；**全队被限流/封禁**（199 期）。

**共享配额：最常见。** 一个 Agent 刷爆；**全体 429**（180 期）。

**现状：只隔离进程。** 容器/命名空间有了；**共享物还在**。

**三条传播路径，一条比一条快。** 记忆（通过检索）、缓存（通过命中）、消息（通过扇出）；**三条都不报错**。

| 116 期记录漂移 | 无 | 无 | 无 | 无 | 无 |

**判读与本期反转。** 把记录漂移讲清的是 116 期，把池边界讲清的是 121 期，把委托上限讲清的是 214 期；**六家云厂商 Agent 平台「共享物清单／按 Agent 隔离／爆炸半径」三列全空**。与 121 的分工：121 管「租户之间」，本期管**「Agent 之间」**；与 116 的分工：116 管「记录错了」，本期管**「错传多远」**；与 214 的分工：214 管「消息可不可信」，本期管**「错沿消息传多远」**。判词：**「容器」「命名空间」「限流」「队列」全部可采购，「举证这个错最多影响几个 Agent」不可采购。**

## 四、技术挑战

**一，共享物不在清单里。** 记忆/工具/身份/配额；**没人列过**。

**二，传播是静默的。** 错记录被检索；**没有报错，只有错答案**（116 期）。

**三，扇出无上限。** A→B→C；**一个错变成 N 个错**（214 期）。

**四，共享缓存放大。** 错结果被缓存；**后续全命中错**（195 期）。

**五，身份无法按 Agent 限。** 共享 key；**限流只能限全体**（199 期）。

**六，爆炸半径算不出。** 没有调用图；**只能事后数**（173 期）。

**七，多租户叠加放大。** 租户隔离了；**租户内 Agent 共享**（121 期）。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `blast.*` 字段**：`fault_id`、`shared_resource`、`affected_agents[]`、`affected_tenants[]`、`fanout_depth`、`contained_at`。
- **R2 共享物清单**：记忆/工具/身份/配额；**每项标隔离级别**。
- **R3 按 Agent 隔离**：身份/配额/缓存分区（121 期）。
- **R4 扇出上限**：深度/广度；**超限拒绝**（214 期）。
- **R5 熔断**：共享物故障时快速隔离（95 期）。
- **R6 指标**：共享物隔离率、扇出深度、爆炸半径估算、隔离时延。

### 5.2 用户旅程

- **SRE**：一个 Agent 答错 → 查共享记忆 → 隔离该记录 → 评估影响面 → 记半径。
- **平台**：工具故障 → 熔断 → 只影响该工具调用方。
- **安全**：key 泄漏 → 按 Agent 轮换 → 不全队停。
- **审计**：抽查一次故障 → 影响面清单 → 确认可举证。

### 5.3 实现方案（90 天）

- **0–30 天：清单。** 四种共享物；标隔离级别。
- **30–60 天：隔离。** 身份/配额/缓存分区；扇出上限。
- **60–90 天：估算。** 调用图；爆炸半径；熔断演练；多租户叠加核对。

**第 158 个市场空白（五项）**：共享物清单覆盖率、按 Agent 隔离率、扇出上限覆盖率、爆炸半径可估率、熔断演练率——无一内建；`blast.*`／`fault.*` 为**第 124 次无人提字段族**。本地 173／173-kb 连续第 114 期成组启用：肖汉松 22「全局调度器：分派、等待」＝全库唯一把「分派与等待」写成组件的实践，本期首次当主线；配 121 期隔离、214 期消息。判词：**本地把分派写进调度器，联网侧 2026 年才承认「一个错能传多远没人算」；两边都没把「最多影响几个 Agent」做成故障字段。**
