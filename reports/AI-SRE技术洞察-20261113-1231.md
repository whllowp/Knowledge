# AI-SRE 技术洞察（第 178 期）

**生成时间**：2026-11-13 12:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：互斥面／争用面（Mutual Exclusion）——两个 Agent 同时改同一个资源，谁赢？没有锁，就没有「谁先」

---

## 题眼

80 期讲过一个经典失效：**「两次都返回 200，系统却错了」**——两个调用都成功，合起来是错的。到了 Agent 编队时代，这件事从「一个客户端的重试」变成「多个 Agent 的并发」：**A 在扩容、B 在缩容；A 在改配置、B 在读配置；A 在写记忆、B 在检索**。40 期说重试会放大冲突，144 期说编队让并发成为默认，121 期说多租户共享资源。**但大多数 Agent 栈没有锁**：它们靠「应该不会同时发生」的假设运行——**而这个假设在编队里几乎必然被打破**。**并发不是性能问题，是正确性问题：没有互斥，就没有「谁先」。** **而「谁先」错了，两个都成功也是一次事故。**

## 一、发展趋势

**趋势一：Agent 从「单线程任务」变成「并发编队」。** 多个 Agent 同时操作同一批资源；**冲突从异常变成常态**（144 期）。**编队越多，最后写入获胜越危险。**

**趋势二：乐观并发开始替代「沉默覆盖」。** 版本号/条件写；**冲突时失败而不是覆盖**。

**趋势三：租约与栅栏令牌进入 Agent 栈。** 锁有期限、有令牌、有 owner；**避免「以为自己还持有锁」**。

## 二、技术现状：三种机制，三种失效

**乐观并发：版本号/条件写。** 冲突时返回失败；**Agent 需要能处理「失败并重读」**（80 期）。

**悲观锁：租约/独占。** 有期限、要续租；**租约过期后旧持有者仍在写，就是双写**。

**串行化：队列/单写者。** 把并发变成排队；**吞吐下降，但正确性最好**（120 期）。

**现状：多数 Agent 栈只有「最后写入获胜」。** 两个 Agent 都成功，**结果是丢更新**（80 期）。

**三种并发写，三种错法。** 丢更新（后写覆盖先写）、幻读（读时没有、写时已有）、死锁（互相等锁）；**前两种静默，第三种至少会卡住**。

## 四、技术挑战

**一，租约过期双写。** 旧持有者不知道锁没了；**继续写，冲突不可见**。

**二，Agent 会重试。** 冲突失败后重试；**重试又撞上同一把锁**（40 期）。

**三，锁没有 owner。** 谁持有、何时释放；**没有 owner 的锁就是死锁**。

**四，多租户共享资源。** A 租户的锁挡住 B 租户；**隔离与吞吐冲突**（121 期）。

**五，锁的粒度。** 锁整张表还是锁一行；**粗了没吞吐，细了难维护**。

**六，冲突不可观测。** 丢更新静默发生；**没有冲突计数，就不知道有没有锁**。

**七，跨系统锁不成立。** Agent 锁了数据库，没锁配置中心；**两个系统之间没有共同锁**（173 期）。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `lock.*` 字段**：`resource`、`holder`、`lease_until`、`fencing_token`、`idempotency_key`、`conflict_count`。
- **R2 资源分级**：读多写少用乐观、强一致用悲观、批处理用队列。
- **R3 栅栏令牌**：每次加锁递增；**写入时校验令牌，旧令牌拒绝**。
- **R4 幂等键**：同一动作重复提交只生效一次（80 期）。
- **R5 冲突度量**：冲突率、锁等待、丢更新数；**进看板**。
- **R6 死锁处理**：超时释放、owner 告警、死锁检测。

### 5.2 用户旅程

- **平台工程师**：两个 Agent 改同一配置 → 版本冲突 → 一个失败重读 → 不丢更新 → 冲突计数。
- **SRE**：发现锁等待飙升 → 查粒度 → 拆细或排队。
- **安全**：旧租约仍在写 → 栅栏令牌拒绝 → 记录双写尝试。
- **审计**：抽查一次并发写 → 核对令牌与幂等键 → 确认没有丢更新。

### 5.3 实现方案（90 天）

- **0–30 天：盘点。** 列共享资源与并发路径；标「最后写入获胜」。
- **30–60 天：加锁。** 乐观/租约/队列按资源分；栅栏令牌；幂等键。
- **60–90 天：度量。** 冲突率与丢更新；死锁处理；季度压测；跨系统锁盘点。

**第 125 个市场空白（五项）**：共享资源分级覆盖率、栅栏令牌覆盖率、幂等键覆盖率、冲突率可报率、丢更新可测率——无一内建；`lock.*`／`mutex.*` 为**第 94 次无人提字段族**。本地 173／173-kb 连续第 85 期成组启用：肖汉松 22「全局调度器：分派、等待」＝全库唯一把「等待」写成组件的实践，本期首次当主线；配 80 期重复动作、144 期编队。判词：**本地把「等待」写进调度器，联网侧 2026 年才承认「编队让并发成为默认」；两边都没把「这把锁的持有者与令牌」做成运行时字段。**
