# AI-SRE 技术洞察（第 256 期）

**生成时间**：2026-11-17 18:00（Asia/Shanghai）
**洞察窗口**：2026 年，重点为最近 30 天（2026-10-18 至 2026-11-17）公开材料
**本期主题**：目标对齐面／意图-执行鸿沟（Goal Alignment / Intent–Execution Gap）——trace 全绿、答案却错：行业把"执行"做成了可观测的一等公民，却把"用户真正想要什么"留在了工单备注里

## 题眼

2026 年 11 月 13 日同一天，Google 把 Agent 的 trace、token 计数、评测分数全部塞进客户自有的 BigQuery 表，Ai2 发布 XYBench 并拿下 EMNLP 2026 最佳资源论文。前者宣布"我们填充了可观测的三层中的第一层"，后者用一个反直觉的数字戳破其余两层：**给模型看两个答案、让它挑哪个真正解决问题，五个模型有 71%–84% 挑对；让它自己写，只有 35%–41% 把答案聚焦在真正的目标上**。海峡两岸的运维现场也在复现同一道裂缝——阿里 STAROps 说"告警的地方，不是出事的地方"，火山 APMPlus 说"Agent 说完成，结果却不对"。当执行层（execution）、结果层（outcome）、目标层（goal）被拆成三件事，"这次动作做成了没有"和"这次到底解决了什么"就不再是同一个问题。生成可被观测，对齐只能被举证。

---

## 一、发展趋势

**趋势一：可观测性从"一层"裂成"三层"，而行业只交付了第一层。** Google 11-13 的 Data Cloud 更新把运行态遥测（Cloud Monitoring 指标、Cloud Trace 跨度）、对话记录（客户自有 `agent_events` 表）、成本计数、Prism 评测结果统一落进 BigQuery。媒体复述时点了关键一句：这些全部度量的是**执行**——花了多少 token、走了几步、跑分多少，唯独不回答"Agent 是不是在解决对的问题"。三层框架（execution / outcome / goal）第一次被清晰地摆到台面上：执行层已有事实标准，结果层有 Prism、XYBench 等基准在补，目标层仍是空白。

**趋势二：评测开始从"答得对不对"转向"方向对不对"。** XYBench 把"XY 问题"搬进基准：用户想达成 X，却认定方法 Y 可行、开口只问 Y。8115 条真实问题（Stack Overflow 1557、Stack Exchange 184、人工 102、WikiHow 生成 6272），要求模型识别隐含误解、把答案重心放到 X。结果显示五个前沿模型无一把目标当重心超过 41%，而人类参考答案是 55%；"把用户从错误方法引开"一项，人类 79%，模型 35%–60%。这是评测维度的一次结构性转向：从答案正确性，转向语用学层面的意图对齐。

**趋势三：从任务到目标，工程重心转向"反馈回路设计"。** LangChain 11-14 的 goal engineering 断言："prompt engineering 和 context engineering 会消失，goal engineering 会留下。"论点是长程 Agent 的瓶颈不是能力而是从反馈中学习——最难给的上下文是"从没写下来过、只存在于专家脑子里"的那部分。Actively AI 把"一个客户一个 Agent"改成跨客户共享的"motion"（一类相似任务打包），目的就是让销售一次审阅一批、一条纠正迁移到整类。这与 XYBench 的结论互为表里：模型不是识别不出意图，而是识别出来后不会据此行动；把目标写下来、做得让人能快速纠错，才可能闭环。

## 二、技术现状

目标对齐目前没有独立的技术栈，散落在三个层次里。

**执行层**已相当成熟：OTel GenAI 语义约定、会话级 trace 重建（Google SDK 的 `get_session_trace` 把多态事件重建成因果 DAG）、token/成本/延迟逐轮记录、带隐私护栏的对话日志（Google 在涉及行级安全、列级策略标签、动态脱敏的数据源上 fail-closed 跳过记录，而执行 fail-open 不打断会话）。这一层回答"发生了什么"。

**结果层**正在快速补课：Prism 把评测跑写进按天分区的 BigQuery 表，与生产 `agent_events` 并置，用来回答"哪个 prompt 版本让准确率退步、代价多少"；Cloud-OpsBench（754 个运行时验证案例、57 类故障）提出"联合根因准确率 JRA"与"证据闭合"分离——GPT-5 在 33.1%/29.4% 的案例里答对了根因却没做到证据闭合。RCAtlas（10 月底，90 个已验证事故）更把"结果"拆到反直觉的程度：一个简单 harness 的 PR@1 达 65%–77%，而五个发表的 RCA Agent 只有 16%–53%，硬编码剧本因"在事故揭示什么重要之前就决定了去哪看"而系统性跳过决定性证据。

**目标层**基本空白：没有字段、没有 SLO、没有值守。XYBench 的 oracle 实验是这一层的直接证据——把真实意图 X 明确喂给 Sonnet 4.6 后，"包含目标解法"从 59% 升到 67%，但"识别误解"反而从 47% 跌到 34%：**识别到了意图，却没有按意图行动**。这在运维里的对应物就是"告警被处理了、trace 收尾绿了、业务没恢复"。

## 三、技术竞争力：主要厂商/方案对比

| 厂商/方案 | 执行层 | 结果层 | 目标层 | 对齐证据可导出 | 主要短板 |
|---|---|---|---|---|---|
| Google BigQuery/Looker（11-13） | 强（trace/token/成本/对话分级） | 中（Prism 并置） | 无（明示 goal correctness open） | 部分（执行可查、目标不可） |只度量执行，不定义"完成"|
| Ai2 XYBench（11-13） | 无 | 强（意图/误解三维分解） | 强（唯一专测目标层） | 强（逐行为标注、判断器 97.5–100% 一致） |英文、程序性任务，非生产值守|
| LangChain goal engineering（11-14） | 无 | 中（反馈设计） | 强（motion/目标范围设计） | 弱（方法论非字段） |理念先行，无采集标准|
| Anthropic Claude（11-13 故障） | 中（状态页时间线） | 弱（无 RCA） | 无 | 弱 |定时任务晚 2h+、部分 skipped 无复盘|
| OpenAI Workspace Agent（11-11） | 中（status 页 9h42m 记录） | 弱 | 无 | 弱 |无法启动新 run，外部探针零错误——自报≠可观测|
| 火山引擎 APMPlus/智能运维助手 | 强（Agent 轨迹+RCA Harness） | 中（LLM 多维打分） | 弱（"说完成却不对"仍需人核） | 部分 |轨迹能看过程，不判方向|

## 四、技术挑战

1. **识别—行动鸿沟**：XYBench 里"选对"71%–84%、"写对"35%–41%，oracle 给出意图后识别率反跌。把"检测到意图"当作"已对齐"是最隐蔽的自欺——这与 #213 因果闭合"答对≠查对"同构，但对象是意图而非因果。
2. **表述—目标二义**：用户以 Y 提问、真正要 X；Agent 忠实复述 Y 就能让 trace 全绿。没有独立的 X 记录，事后无法区分"照做对了 Y"与"解决了 X"。
3. **完成的定义缺失**：Google 明言两份发布都没有为开放式目标定义 done。运维侧对应物是"恢复"的判据——进程起来了不等于业务恢复了（接 #234 修复采纳"执行≠留住"，但本期追问的是"留住的对不对"）。
4. **失败样本不回流**：被识破的误解、被纠正的方向若不进 golden 集，Agent 会反复在同类 XY 问题上答非所问（接 #234 未采纳样本不回流）。
5. **隐私护栏制造目标盲区**：Google fail-closed 跳记录，缺失的那一轮可能是策略结果而非 bug——目标证据天生有洞，且洞的位置由数据敏感度决定。
6. **评测—生产语言不通**：XYBench 的"语用重心"、Cloud-OpsBench 的"证据闭合"都停在基准里，没有进入 OTel GenAI 语义约定或值守门禁。

## 五、展望与建议

提出第 182 个市场空白，字段族 `goal.alignment.*`（第 146 次无人提）：`stated_request`（用户字面请求 Y）／`intended_goal`（推断目标 X 及其来源）／`goal_emphasis`（回答重心落在 X/Y/两者平衡）／`misconception_identified`（是否识别并劝离错误方法）／`goal_verified_at`（由谁、何时、凭什么判定目标达成）。建议：

1. **把 X 写下来并与 Y 分列**：工单/告警开单即记录"字面症状"与"推断目标"两栏，Agent 回答后回填重心，缺 `intended_goal` 一律 `GOAL_UNVERIFIED`。
2. **双报"选中率"与"写出率"**：对自家高频 XY 题型做 XYBench 式选择题 + 开放式对照，两个数字并列进发布门禁，防止"会判断不会做"被平均分掩盖。
3. **恢复判据绑业务而非绑动作**：把"业务指标回到基线"作为 done 的唯一凭据，进程/span 绿不作为目标达成证据；恢复失败自动转人工（接 #234 白名单执行、恢复失败转人工）。
4. **让反馈可批量迁移**：借鉴 motion——按"一类任务"而非"一个工单"组织 Agent 与审阅 UX，一条方向纠正迁移到同类；被纠正样本强制回流 golden 集。
5. **给目标证据的隐私洞打标**：因行级安全/脱敏被跳过的轮次显式编号，标注"目标证据缺失因策略"，避免误判为 Agent 失败；值守 SLO 承认这一不可消除的盲区。
6. **进标准与基准**：`goal.alignment.*` 五字段提 OTel GenAI 提案；信通院六维补"目标可举证率"格；SRE 基准新增"字面完成但目标未达成""识别意图却未行动"两类题。
