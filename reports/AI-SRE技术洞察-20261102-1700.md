# AI-SRE 技术洞察（2026-11-02 17:00 期 · 总第 33 期）

**本期主线：配给面运维——推理配额成为一等运维对象。** 前 32 期分别从治理、证据、演练、记忆、路由、承诺、缓存、协同、时间、知识、接口、轨迹等平面切入智能体运维，本期管的是此前从未被当作对象的变量：**供给端"还剩多少口粮"**。与第 25 期承诺面的分界：那期管"承诺了几个九"（SLO 与错误预算），本期管"配额还剩多少、何时重置、耗尽后怎么办"；与第 24 期路由面的分界：路由回答"选谁"，配给回答"还能用多少、什么时候恢复"。11 月 1—2 日两天内，OpenAI、Anthropic、腾讯云、阿里云四家几乎同时调整了配给规则，配给面从计费细节升格为运维议题。

## 一、发展趋势：智能体产品正在变成"资源配给操作系统"

11 月 2 日，OpenAI 帮助中心宣布 12 月起 ChatGPT 与 Codex 共享同一份按 token 计量的用量额度，Plus/Pro/Business 三档通用，界面上将展示合并后的剩余用量与重置时间，触顶后提供等待、升级、购买积分三条出路。这意味着一次大型 Codex 任务会直接挤占另一个工作流的可用额度——聊天与编码从两个产品变成同一个容量池上的两种负载。同日 The New Stack 报道，Anthropic 为已验证的 Claude Ultra 用户取消了 5 小时滚动会话上限，但保留周限额（约为 Pro 的 10 倍），并附赠与订阅价等额的月度 API 积分。

两个动作方向相反、本质相同：**配额窗口结构正在替代模型能力成为产品竞争的显性维度**。OpenAI 把碎片化的产品额度合并成统一推理预算，暴露的是机会成本；Anthropic 把"中断型约束"换成"耗尽型约束"，让长任务获得连续性、把风险后移到周末周窗耗尽。BidSense 11 月 2 日日报将其概括为"智能体产品正在从聊天界面变成调度稀缺推理资源的操作系统"。同期背景是流量侧的实锤：GitHub 9 月提交量达 74 亿次、同比 5 倍，年内为扛住智能体流量新增 400 万 CPU 核心——智能体流量作为容量问题已从推理端蔓延到代码托管端。

## 二、技术现状：配给规则的工程语义已经分化

把本周各家规则摆在一起看，配给已经出现四种可辨识的工程形态。**统一池共享**（OpenAI）：跨产品合并计量，优点是利用率高，代价是负载间没有配额隔离。**窗口换挡**（Anthropic）：滚动短窗改周窗，短时突发不再触发中断，但周总量构成新的尾部风险，且周窗配额天然不适配燃烧率工具——燃烧率假设错误均匀消耗，而智能体负载是脉冲式的。**削峰式配给**（阿里云 Tair AI Assistant）：算力包按 Credits 计量，官方文档明确"每日 Credits 消耗上限＝总额度÷当月天数"，耗尽后当日受限、次日自动恢复，当日未用不结转——这是牺牲突发性换全天可用性的确定性设计，且明示 Credits 不等价于原始 token，按任务类型、数据量、复杂度折算。**速耗式配给**（阿里云 OSS Agent）：10 月 28 日起商业化，每 UID 每月赠 1500 Credits、当月清零不予结转，用量可近实时查询。腾讯云在本周第十代云服务器 SA10 发布中推出 Agent Hosting 品牌，其中 ClawPro 把"组织权限、模型配额、Token 用量、安全审计"并列为组织级纳管四件——配额首次进入国内厂商的组织治理清单，与权限、审计同级。

另一条值得注意的支线：在配给趋紧的背景下，"互相证伪"结构开始流行。据 MarkTechPost 转述，Anthropic、OpenAI、Cloudflare、谷歌的安全智能体均采用"一方找漏洞、另一方证伪"的双智能体结构，谷歌称粗糙扫描的真实正例率不足 7%——用推理成本换人工复核成本。这提示一个反向依赖：**当配额紧张时，最容易被砍掉的恰恰是验证类调用**，配给治理与验证治理将互相牵制。

## 三、技术竞争力：配给能力成为新的对比维度

| 方案 | 计量单位 | 窗口结构 | 结转/恢复规则 | 组织级治理 |
|---|---|---|---|---|
| OpenAI（ChatGPT+Codex） | token | 月度内滚动 | 触顶可选等待/升级/购积分，重置时间可见 | 暂无隔离，负载间共享 |
| Anthropic Ultra | 周用量 | 周窗（约 10×Pro） | 周窗耗尽等重置；附月度 API 积分 | 周总量无燃烧率工具 |
| 阿里云 Tair AI Assistant | Credits（非 token） | 月包+日均削峰上限 | 次日自动恢复，当日不结转 | 算力包可叠加，并发上限 20 |
| 阿里云 OSS Agent | Credits | 月度赠送额 | 当月清零不结转 | 用量近实时查询 |
| 阿里云百炼 Token Plan | Token 套餐 | 预付资源包 | 用不完不退 | 适合稳态月百万 token 场景 |
| 腾讯云 ClawPro | Token 用量 | 组织级纳管 | 未公开 | 与权限/审计并列四大件 |
| Datadog Scout | 自研 SRE 模型 | 无用户配额 | 成本为前沿模型 3–8 倍 | AlertEval 自家基准待第三方复核 |
| Google 项目支出硬上限 | 金额 | 项目级 | 触顶暂停、一键恢复、部门摊派 | 全公司策略一次生效 |

判读有三。其一，**国际厂商在统一化（OpenAI）、窗口换挡（Anthropic），国内厂商在细分化（Credits、削峰、结转规则各不相同）**——国内把配给做成了计费产品矩阵，国际把配给做成了产品体验约束。其二，Forrester AIOps Platforms Wave（Q4 2026）同周公布 Datadog 与 Dynatrace 双 Leader，Datadog 借 Scout 自研模型把"降低单位调查成本"变成配给侧卖点（Bits AI 付费客户破 1 万），厂商自训小模型本质上是绕开推理配给约束的供给自建。其三，配给透明度正在拉开差距：OpenAI 公开重置时间、阿里 OSS Agent 给近实时用量，而多数企业级方案仍未回答"下周还能干多少活"。

## 四、技术挑战：配给面特有的四类问题

**① 两本账无法互算。** SLO 与错误预算按时间计，配额按 token/Credits 计，"这个月可靠性花了多少配额、配额透支造成多少可靠性损失"目前无统一结算口径——第 25 期的预算代数在配给面缺了供给这一项。**② 计量单位不可预测。** Credits 按"任务类型、数据量、复杂度"折算且不等价 token，用户在下单前无法估算一次诊断任务消耗多少，成本可预测性反而劣于按 token 明码计价。**③ 配额串扰与噪声邻居。** 共享池把编码、聊天、运维调查放进同一容量池，一次失控的重试风暴（第 9 期曾录得单周末 2400 美元）现在会挤干全组织额度——配额隔离与优先级抢占尚无产品化方案。**④ 脉冲负载对削峰设计的反噬。** 日均上限假设负载均匀，而故障响应天然脉冲：P0 发生在当日额度耗尽后，智能体诊断将被冻结到次日——削峰式配给与故障驱动负载存在结构性冲突，需为告警类调用保留旁路额度。

## 五、展望与建议

配给面正在重演可观测性十年前的路径：先有计量（Credits/allowance），再有透明度（重置时间/用量查询），下一步必然是治理。建议运维团队现在做三件事：**其一，建立配额台账**，为每个智能体工作负载记录"剩余额度/预估消耗/重置时刻"三项，把腾讯 ClawPro 的"配额+用量+审计"三联作为组织级最低配置；**其二，为配给定义 SLO**——重置时刻可见性、余额预测误差、串扰隔离度，像监控延迟一样监控"还能干多少"；**其三，在任务编排的准入检查中加入配额预检**，长任务启动前估算消耗并声明回退链（降档模型/排队至重置时刻/转人工），避免任务在 70% 处死于额度耗尽——这与第 28 期"检查点不证明世界仍成立"共同构成：恢复点要同时携带状态有效性与配额可行性。需要预判的分歧点：削峰式配给与脉冲式故障负载的冲突，将在 2027 年前迫使国内厂商推出"告警旁路额度"或"分级配给"，届时配给策略将进入架构评审清单，正如今天的缓存亲和性。
