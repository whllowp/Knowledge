# 记忆技术洞察 · 第 56 期（2026-11-12 05:00）

> 本期主线：**记忆工程的评测契约危机——"倒挂"与"口径缺口"的系统性根源，及"评测即契约"改革**
> 覆盖维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战 + 需求分解 · 用户旅程 · 实现方案
> 与前期分界：第 1 期把"评测失真"列为挑战之一；第 42/45/51/52/53/54/55 期各自发现一个被榜单漏掉的失败模式（内在评测/授权/来源/内省/退化/安全/状态协调）。本期不新增失败模式，而是把散落在 11 期里的"倒挂第 N 次 / 口径缺口第 N 次"做根因综合——这是往期未做的元层梳理，从"不同角度和方向"澄清本系列反复撞见的现象。

## 一、发展趋势：从"比分数"到"比契约"

2026 下半年，记忆系统的竞争叙事从"谁的榜首分高"转向"谁能在同一契约下被公平比较"。AML Cycle 2（11-19 预期出榜）把协议、数据版本、评分冻结为统一契约，方向正确；但现行契约仍只覆盖"存得下、找得回"，未覆盖"记得对、说得清、删得净、传得真、归得准"——后者恰是本系列 11 期反复撞见的盲区。趋势是评测从"排行榜"进化为"治理契约"。

## 二、技术现状：倒挂与口径缺口是同一根因的两个投影

把本系列 44–45 次"倒挂"（某能力论文/工具侧先实现、产品零披露）与 43–45 次"口径缺口"（榜单漏掉某维度）并列看，二者共享一个根因：**记忆的本质是账本+主权（append-only、可冲正、带主体 principal 与状态角色 state_role），而现行评测契约仍按"数据库"假设设计**——假设记忆是被动存储，不假设它会演变（第 55 期 Ghost Memory）、会被继承（第 51 期来源三态）、有主体（第 45 期授权）、有状态（第 2 期墓碑）、会被污染（第 54 期 provenance）、会诱发退化（第 53 期）。AML 的 Add/Search-only、单用户单库、无 principal 参数，使"账本属性"在评测中结构性不可见。

## 三、技术竞争力：谁离"契约合规"最近

| 评测/框架 | 治理维度 | 来源 | 状态角色 | 内容可见 | with/without | 备注 |
|---|---|---|---|---|---|---|
| AML Cycle 2 | 有（D+H） | 无 | 无 | 无 | 无 | 方向对、口径窄 |
| Reglos 2611.06049 | 防 gaming | 无 | 无 | 无 | 无 | 反作弊补丁 |
| CompressionBench 2611.06858 | 80% 验收门 | 无 | 无 | 无 | 无 | 唯一硬验收门 |
| 本系列"评测契约"提案 | 全 | 全 | 全 | 全 | 全 | 未被采纳 |

结论：AML C2 最接近契约合规（有 D/H），但仍是"数据库契约"；CompressionBench 是唯一带硬验收门的，证明"验证门"可工程化。真正的"账本契约"尚无人实现。

## 四、技术挑战：把散落字段收敛成一份契约

① 50+ 散落 schema 字段（state_role/origin/donor_id/access_version/deletion_residue/retrieval_explanation/provenance/with_vs_without…）须收敛为强制评测契约，否则每期仍在补同一类缺口；② "参赛资格"与"治理能力"绑定——无 provenance/无 state_role 不得在治理维度计分；③ 验收门须前置（CompressionBench 式 80% 保留）而非事后排名；④ 反 gaming 须进契约（Reglos 跨家族 critic）；⑤ 跨组织撤回/继承须进协议（第 51 期 donor tombstone）。

## 五、需求分解 · 用户旅程 · 实现方案

**需求**：R1 评测契约强制声明 principal/state_role/origin/provenance；R2 治理维度零披露即零分（GateMem MGS 乘性分，防"全拒/全收"刷分）；R3 验收门前置（重构保留≥80%、with-vs-without delta 必报）；R4 反 gaming critic 进协议；R5 撤回传播与来源维度进榜单。

**用户旅程（D0→D7）**：团队用内部榜选记忆系统，分高上线 → 真实多会话下 Ghost Memory 发作、继承 lesson 诱发退化、撤回不传播 → 回头发现内部榜无状态/来源/with-vs-without 维度、分数虚高 → 改用"评测契约"重测，三家产品因零 provenance 在治理维度直接出局。

**实现方案**：把 50+ 字段按"账本四问"（谁写 principal / 写时状态 state_role / 从哪来 origin / 为何召回 retrieval_explanation）重构为契约必填项；以 GateMem MGS 乘性分替代加和分杜绝刷分；以 CompressionBench 硬验收门 + Reglos 跨家族 critic 堵"分数虚高"；AML 类榜单增 source/state/with-vs-without 三列。
