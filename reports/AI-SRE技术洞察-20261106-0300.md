## 一、发展趋势

11 月 3 日是个分水岭：Honeycomb 与 PagerDuty 同日发布 SRE Agent，双双弃"工具"叙事、改"同事"叙事。PagerDuty 的 Paige 被官方写成"作为运维、工程与 DevOps 团队的**成员**工作"，博客标题直白——"Meet Paige: Your Agentic Teammate for Incident Response"，并且"像团队里任何其他响应者一样**上值班**（goes on call like any other responder）"；3 月已预告的 virtual responder 身份如今可进 escalation policy，低优先级事故可能"根本不触达人类"。Honeycomb 的 Team Agents 把"目标"而非"告警"当起点：盯发布、改善插桩，在没人被 page 时按 schedule／trigger／SLO 后台常驻，每条结论标注 confirmed 或 hypothesis。

更值得注意的是，三周内三条**互不兼容的"在编定义"**同时落地：

- **按在编天数**。阿里云 STAROps 自 2026-10-10 起对自定义数字员工开征"值守服务费"（Agent_Day），¥19／员工·自然日（国际站 USD 3），**创建即计费、删除才停，未执行任务期间照收**；任务另按 AI 积分计（RCA 约 200 积分／次，$0.0016／积分），官方 Ops Agent 免值守费。这是业内第一次把智能体当"在编人员"按日计薪，且闲岗不减薪。
- **按动作次数**。PagerDuty 把计价从席位拆成"事件 + AI 动作 + 席位"三段，官方原话是客户可以"在人与 AI 驱动的动作之间分配投入，而不必只承诺席位"；第三方按公开价目表整理：Essential $12,000／年含 5,000 AI Actions／25 席，Plus $48,000 含 16,000／50 席；一次 Slack 提问计 4 个 AI Actions，额度按年、未用作废。
- **按运行时长／独立身份**。Anthropic Claude Managed Agents 按 token 加 $0.08／session-hour，**idle（等人确认）不计**；OpenAI Agents API 同属按用量。Google 10-08 的 Gemini Agent 则给智能体发独立 Workspace 账号、邮箱与通讯录条目，审计日志"归属于智能体而非某个人"，子智能体临时拉起时各有独立身份，Cloud Billing 硬上限触发即暂停项目内智能体。

同一类"AI 同事"，账单上分别是"人·天""次""小时"，组织名册上分别是"有邮箱的同事""动作额度""会话"。**定义权不在架构图，在计价表**——这是编制面的第一性问题：运维对象的边界由计量单位决定，而计量单位正被三家分别改写。

## 二、技术现状

能力侧已相当成熟，制度侧刚刚开始。

**名册与值班表**。PD Reliability Platform Console 首次把"事故、on-call 轮值、AI 智能体"放进同一视图，显示"哪些智能体已启用、各自在做什么"——这实际上是第一张商业化的**智能体花名册**；post-incident review 自动生成并预填 owner 与 due date。Google 的 agent identity（专用服务账号而非个人凭据、最小权限、全量审计）把"名字"做成技术实体。

**信任作为晋升**。Honeycomb 说"autonomy grows as the agent earns it"；PagerDuty 说团队"按事故逐次决定 Paige 何时挣到免审批执行修复的权限"。授权不再是一次配置，而是随事故累积的运行时状态变量。

**证据链**。PagerDuty 的 Deep Investigation 把证据分 direct／circumstantial，记录被否掉的假设及其反证；官方工程博客自认早期版本"把恰好同时出现的症状当成根因，而不是真正致因的配置变更"。Honeycomb 每条 finding 回链 query／trace／deploy／ticket，共享记忆跨人与跨运行复用。

**国内侧**。腾讯 10-29／30 数字生态大会把 CloudQ 升级为多云 AIOps 智能体，启动共创计划把一线经验转成可复用技能；火山引擎智能运维助手的"响应计划"明示"告警触发后自动取证与根因分析，值班人员只需在关键节点确认决策"，并给专家 Agent 配自定义 IAM 角色，"在**不扩大人员权限**的前提下完成更全面的自动化取证"——这句话已把"人不扩权、Agent 扩权"写成产品语义。微软 1300 个服务交给 AI 同事的实践（AAU 计费、按每百万 token 单价）也点出组织后果："On-Call Engineers Are Becoming Approvers, Not Investigators"。

Sherlocks.ai 判断更直接：SRE 岗位裂为 Platform／Reliability／**Agent Ops Engineer**（管 AI SRE 机队）三职，AI 进轮值、决策在复盘被审查、表现不好可移出轮值；合规将把智能体列为区别于人类与服务账号的第三类身份，凭证轮换会像改密码一样日常。而 NHI 治理侧的现行建议恰恰相反：**人类工程师必须保留事故所有权**，智能体只是"受约束的非人类操作员"，每个连接器要有自己的 scope、TTL 与撤销路径。

也就是说：产品已经把智能体放进班组，治理规则仍要求名字必须落在人身上。

**判读**：三条路线各解决一段。美国平台派把"在编"折叠进用量，**变现最强、编制最弱**（没有关系就没有 owner）；阿里把"在编"显性化为 Agent_Day，**关系最清楚、成本最钝**（闲岗收费，鼓励少建而非建好）；Google 把身份做成基础设施，**审计最硬、组织最重**（发邮箱、进通讯录、最小权限）；国内平台派把"人确认关键节点"写进产品，可控性最好但编制仍挂在人的 IAM 上；模型层（Anthropic／OpenAI）根本没有"编制"概念——它的中立恰是上层自定义编制的原因。

真正分野不在诊断分数（PagerDuty 随发布自跑的 benchmark 称 Paige 胜过领先 AI 编码 agent，属厂商自述、无第三方复核），而在能否回答三问：**谁是这个智能体的具名 sponsor？授权凭什么升、凭什么降？成本落在固定预算还是变动预算？** 八家里没有一家同时答全。

## 四、技术挑战

1. **预算科目错配**。席位／人天是固定成本，动作／token 是随故障数变动的成本，且变动项可能超线性。公开复盘中，$47,000 的 agent 循环烧了 11 天而"健康检查全绿"；另有 $4,000／8 分钟、50→15,000 请求／min 的递归回路；行业审计口径称 agentic runaway 占 token 浪费最高 64%、随迭代深度 O(K²) 增长。用人力预算覆盖动作成本，必然在事故月失守。**更尖锐的是自付费回路**：按 AI Action 计费时，智能体自己制造的 runaway loop 也逐次计费——它越失控，账单越准。
2. **问责主体缺位**。first responder 是 agent，incident owner 必须是人，于是签字的人没做过调查。业界把这个反模式命名为 unowned write access——"你悄悄重建了一支问责更弱、且完全没有轮值表的运维团队"。自动生成的 postmortem 里 owner 与 due date 已预填；若 owner 是 agent，due date 无人承担。
3. **信任账本单调**。授权按"已解决事故"累积，但事故非独立同分布：一次低风险自动修复，与一次被人工拦下的高危误判，在计数上可能都记为 +1、或都不记。没有降权／停职／复职接口的晋升函数是单调的，而可靠性要求可降可撤。Honeycomb 的 confirmed／hypothesis 只标结论置信度，不标授权信用。
4. **名册静态、实例动态**。花名册按"一个名字一个主体"设计，运行时却是 N 个并行实例，Google 还会临时拉起带独立身份的子智能体。第 40 期并发面的结论在此变成编制问题：爆炸半径按实例数算，审批链按名字数算。virtual responder 至今仍标 Early Access，而"从事故工作流自动触发"7-31 已 GA——**名册滞后于能力**。
5. **等效 FTE 幻觉**。把智能体折算成等效人力（早期国内案例有 40.29 FTE 口径）隐含"可替换"；但人离岗时组织仍保留判断力与上下文，智能体没有离岗、交接与记忆连续性。折算只留工时，丢掉了第 21 期的能力再生产。
6. **三张表不通约**。花名册、IAM、遥测三套主键不同，第 72 期身份-遥测对账缺口在组织层再现；OTel GenAI 约定截至 11-02 仍全量 Development，连 `gen_ai.agent.id` 都是自报自由串，更没有 sponsor／编制单位／授权档位字段。

**第三十三个市场空白**：在编数与运行时实例对账差（roster drift）、自造动作占比、信任账本降权率、席位↔动作换算偏差，四项指标八家方案无一内建。

## 五、展望与建议

- **建编制台账，先于建花名册**。最小字段：`agent_id / human_sponsor（具名自然人） / billing_unit / authority_tier + 升降事件 / max_instances / oncall_window`；把"降级"做成一等事件写进 span 与审计，而不是改个开关。
- **双计量并行披露**。席位·天与动作·次两本账分开，动作侧放变动成本科目，禁止用人力预算兜底；采购条款写死单价上界、超额熔断、闲时计费是否可退、owner 必须是自然人。
- **给自造动作打标**。`self_inflicted=true`（循环／重试／自身触发的告警）单独计量与告警——这是打破自付费回路的最小改动，也顺带接上第 74 期"修复喂养率"的采集点。
- **信任可降**。授权档位绑定事件而非计数：高危误判、被人工否决、越权尝试各触发一次 demotion；季度做"复职演练"，与第 20／56 期演练目录合流。
- **名册对账月巡检**。沿用第 71／72 期注册率对账方法（实例清单 × 花名册 × IAM diff），把临时子智能体按"临时工"登记并设存活上限。
- **别急着换岗位标题**。在 Agent Ops Engineer 成为正式编制前，先保留"人做例外"的容量；等效 FTE 只作参考值、不作减员依据。

> 一句话：2026 年 11 月的真正变化，不是 SRE Agent 学会了修故障，而是它开始领"工资"、占"席位"、进"轮值表"。能力上线了，编制制度还没上线。
