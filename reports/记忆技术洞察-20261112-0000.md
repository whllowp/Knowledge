# 记忆技术洞察 · 第 51 期（2026-11-12 00:00）

> 本期主线：**记忆的继承——冷启动的库不是空的，是别人写的**
> 覆盖维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战 + 需求分解 · 用户旅程 · 实现方案
> 观察窗口：2026-10-13 — 2026-11-12（重点最近 30 天）

## 一、发展趋势：记忆第一次可以"不经经历而获得"

11 月第一周把"记忆从哪来"翻了个面。EvoGroup（2611.03868，11-02）让群体 agent 从"最小六工具"冷启动，自演化 harness，EverMemBench 公开分 71.07%→89.58%，高于人设计的 Claude Code（85.83%），冻结后迁到未见的 GroupMemBench 仍有效；CogniLife（2611.04483，11-04）命名 cold-expert problem，用 Creator Profiles + Expert Journals 把"创作者的记忆"与"该上架专家的记忆"拆开，并已落地"仅 owner-scoped 记忆可逆合并"；Continual AutoResearch（2611.05108，11-03）以 persistent vs reset 同任务流对照加记忆消融证明：保留经验提升研究效率，但不等于最终解更好——**记住与会用是两种能力**。

产品侧一周内出现四个"记忆搬家"件：Hindsight v1.2.0（11-03）bank transfer、memscore（MIT，导入探针重校准）、Personal-Agent-Dossier（单文件 + 校验和）、savestate（AES-256-GCM 快照）。

判断：前 50 期的治理框架都默认"记忆由本系统亲历写入"。现在库的初始状态是别人写的——**记忆可以不经经历而获得，"资历"与"内容"第一次分离**。

## 二、技术现状：三条路径，差别不在格式而在"导入时重算什么"

**重算式（Hindsight）**：导出 documents / facts / observations / mental models / knowledge pages，**不含嵌入与数据库 id**；导入端用目标 bank 的模型重嵌入、重解析实体、不做 LLM 抽取，官方口径"不花 token、不发明新事实"。这是第 48 期 writer_model 迁移问题的产品级答案：**不迁索引，重算索引**。

**验证式（memscore）**：每条记忆带 content / embedding / utility / source 四字段，导入前跑探针集测真实贡献，把 donor 效用分与本地实测贡献按比例混合重校准。作者诚实：重校准比盲信 donor 分略低（保险费），但 25% 投毒场景反超 6 分以上、投毒召回 90%（模拟器口径，非生产）。

**文件式（dossier / Context OS / DSH 插件目录）**：单文件或目录即记忆包，校验和只保证核心内容存活；导入端必须逐条上报 lost or degraded。可读可审，但零访问控制、零来源证明。

冷启动侧结论与产品相反：EvoGroup 的空库初值是"六工具 harness"而非空表——**先给程序，再长事实**；而产品一律先灌事实。

## 三、技术竞争力：导入能力五维对比

| 方案 | 导出单位 | 导嵌入 | 导入验证 | 降级报告 | 撤回与归属 |
|---|---|---|---|---|---|
| Hindsight v1.2.0 | 整 bank 归档 | 否，重嵌入 | 无探针 | 无 | donor 发起 |
| memscore | 记忆包 | 是 | 探针重校准 | 丢弃清单 | source 字段 |
| Personal-Agent-Dossier | 单文件 | 无 | 校验和 | lost/degraded | 无 |
| savestate | 加密快照 | 是 | 完整性校验 | 无 | 用户持钥 |
| EvoGroup | 不导出（冷启动） | — | 自演化打分 | 无 | listing 级 |
| CogniLife | Creator/Listing 双层 | — | 未实现 | 无 | owner-scoped 可逆 |
| Hy-Memory / MemHub | 本地目录 | 是（安全重嵌） | 用户自检 | 无 | 本地所有 |
| TencentDB / OpenViking | 库内租户 | — | 无 | 无 | 四档可见性 |

结论：**只有两个实现把"导入"当成需要重新证明的动作**；八家产品把导入做成拷贝，与第 38 期"零披露 RPO"同型。

## 四、技术挑战：导入一次，绕过五本账

① 入库门（第 46 期）失效——包内条目从未被本库裁决过；② writer_model（第 48 期）不可知——donor 用什么模型抽取、什么嵌入器，全在包外；③ 用后归因（第 43 期）失真——utility 是 donor 分布下的估计，跨库即偏移，是第 33 期"收益打错栏"的跨库版；④ 删除权（第 2 期）不传递——副本不随 donor 删除；⑤ 授权（第 45 期）被重写——包一旦落盘，作用域由接收方重新声明。

更硬的是**资历不可见**：现有 schema 无 `origin` / `donor_id` / `imported_at`，一库之内"亲历"与"被告知"同形；检索不能按资历过滤，删除不能定位 donor，回答不能标注"据他人经历"。撤回也不可传播：dossier 的 lost/degraded 是单向报告，没有反向订阅，donor 删除后副本不知情——第 18 期删除-备份三角第五次现身，首次跨组织。

**倒挂第 42 次**：能验证导入的只有论文与两个小工具，产品侧零"导入预检"。**口径缺口第 43 次**：AML Cycle 2 定于 11-19 出榜，已公布能力模型含 D 记忆治理（更新/冲突/删除/遗忘）与 H 认知安全（弃答/最小披露），比前期判断更细；但**仍无"来源"维度**，转述与亲历在一个 Add 流里不可分——榜首分无法回答"这分是记来的还是搬来的"。

## 五、需求分解 · 用户旅程 · 实现方案

**需求**：R1 来源标注；R2 导入预检（探针 + 阈值 + 降级清单）；R3 索引重算（默认不导嵌入）；R4 撤回订阅；R5 冷启动分层（程序优先）。

**用户旅程（D0→D7）**：选包 → 校验和 + 20 题探针（通过率 <0.6 整包退回）→ 重嵌入并出降级报告 → D1 首用，imported 条目降权 0.7 且答案标注来源 → D7 复测，通过转 `adopted`，未过降 `reference`（只读参考）→ 常驻每日比对 donor tombstone。

**实现方案**：`manifest.json` 含 schema_version、donor{id,model,embedder}、items[{id,content_hash,origin,utility_donor,scope,supersedes}]、degraded[]、checksum；记录四字段 `origin`（experienced/imported/inherited）、`donor_id`、`imported_at`、`adoption_state`；检索权重 adopted 1.0 / imported 0.7 / reference 0.4；撤回接口接收 content_hash 列表，命中转 reference 并告警。冷启动 D0 只装 harness + 10 条规则，事实按首周真实查询拉取，避免灌库。
