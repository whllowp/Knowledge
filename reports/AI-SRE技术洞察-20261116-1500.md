# AI-SRE 技术洞察报告（第 220 期）

**生成时间**：2026-11-16 15:00 | **时间范围**：2026 年（重点最近 30 天）| **主线立面**：告警收敛面／抑制主权面（Alert Convergence / Suppression Sovereignty）

---

## 题眼

2026 年的 AIOps 平台把「降噪 60–80%」写进产品页，把「告警收敛率 80%」写进案例。但几乎无人追问一句：**那些被收敛掉的告警，去哪了？** 嘉为蓝鲸披露的一组数字刺眼——某机构一天 4100 条告警、46% 没查就关。当 Agent 成为告警的生产者（tool_decision、idle_prompt、预算耗尽）又是告警的消费者，「收敛」就不再是一个技术动作，而是一次**判断权的行使：谁决定哪条告警不算数**。本期首次把「收敛决定本身是否留痕、是否可复盘、是否把沉默误报成健康」立为一等对象。

---

## 一、发展趋势

**趋势一：收敛从「去重」升级为「决策」，判断权开始隐形化。** 早期告警收敛只是时间窗口去重、按联系人聚合——火山引擎 2026 年上线的「按联系人聚合告警事件」仍属此类，目标是「大幅减少通知数量」。但 2026 年的收敛已进入语义层：BigPanda 用 Open Box 机器学习把告警与近期变更关联，Dynatrace Davis AI 沿 Smartscape 实时依赖图走因果链，阿里 STAROps 用 UModel 把日志/指标/链路/事件/拓扑统一建模后做全域关联。收敛从「合并相似」变成「判定因果与压掉下游症状」，这一步同时获得了**一票否决权**，却没有任何厂商把这张否决票记进账本。

**趋势二：收敛率成为 KPI，于是 Goodhart 定律进场。** 行业把「降噪率」当成绩 rewarded，等于奖励「删得多」。腾讯云开发者社区直言不讳：持续性过滤「本质是一个低通滤波器，它把模型的召回率让渡一部分给精确率，换取自愈管道不被噪声淹没」——这笔被让渡的召回率（recall tax）从未被计量。AIOps 渗透率从 2025 年 28% 飙到 2026 年 63%，但真正打通全链路自动化闭环的企业不足 15%——大量团队停在「告警在收敛、闭环没合拢」的半成品状态。

**趋势三：告警的生成方变了，收敛规则却没跟着变。** Claude Code/Cowork 通过 OpenTelemetry 导出 tool_decision、cost_usd、session.id+event.sequence 等事件，Akmatori 提出「Agent 舰队的输出就是日志，要像服务日志一样采集、索引、告警」——Agent 自己开始生产告警流。这些「Agent 原生告警」与「基础设施告警」在现有收敛管道里被同等对待、同等压掉，没人分列。

## 二、技术现状

当前收敛工程质量可归纳为三条架构路线，各带一个盲区：

**① 事件关联层**（BigPanda、PagerDuty Event Intelligence、嘉为蓝鲸）：不改监控探针，靠时间聚类、文本相似度、CMDB 富化把数百条告警并成一张工单。强在异构环境，弱在「关联质量取决于告警元数据与拓扑准确度」——元数据脏，分组规则就要持续调优；被合并的原子告警不保留可查询身份。

**② 因果拓扑层**（Dynatrace Davis AI、阿里 STAROps、腾讯 TCOP）：靠全栈插桩建实时依赖图，沿图回溯根因。STAROps 在真实大促案例中把「五个团队各自自证清白、根因藏在两方视野交界处」的困局收窄到一条链路——但静态依赖图在滚动更新与金丝雀发布中迅速过时，腾讯云指出基于固定因果图的 RCA 会把根因误判给「下游症状最明显的服务」，前沿方向是 TopoEvo、StaR 这类状态化动态因果发现。

**③ Agent 值守层**（火山引擎智能运维助手、OpenAI Control Room）：告警触发后按 Runbook 自动取证、给修复建议，人只在关键节点确认。火山 EMR Agent 为避免持续告警重复诊断，设定「同一告警每 2 小时最多分析一次」——这是**用频率降级代替收敛**的另一种抑制，重复触发的告警「仍被系统接收记录，但不调用 Agent」；OpenAI 则更激进，Control Room 直接把停权下沉到推理层，fail-closed，最长 35 秒切断。

共同现状：三家都在优化「报什么」，没有一家把「压掉什么、谁压的、压得对不对」做成可导出字段。

| BigPanda／Dynatrace（第三方） | Open Box 关联／Smartscape 确定性因果 | 行业口径降噪 60–80%（厂商自报） | ✗ | ✗ | ✗ | ✗ |

**判词**：接多少告警、并多少事件、压多少通知、走多快因果图，全部可采购；**举证「这次是哪条告警被判不算数、谁判的、留没留痕、当初它若响了会不会改变结论」不可采购**。六家云厂商在「抑制留痕／确认-处置分离／沉默验证」三列几乎全空。本期修正 #185 度量主权（谁定标尺）、#208 遥测供给面（喂给 Agent 的数据被谁裁过）、#202 记录沉默（某轮没记的三因塌缩）：标尺之下还有一道**一票否决**，供给之外还有一类**被压掉而非没采到的沉默**。

第 157 个市场空白五项 `alert.convergence.*`：`suppression_recorded_rate`（抑制是否留墓碑）／`ack_vs_action_latency`（确认到处置时差）／`recall_tax_measured`（让渡的召回是否被计量）／`agent_vs_infra_alert_separated`（Agent 自生与基础设施告警是否分列）／`silence_verified`（沉默是否经合成探针验证）。第 123 次无人提字段族。

## 四、技术挑战

**挑战一：收敛即删除，而删除没有墓碑。** 被抑制的原子告警失去可查询身份，事故复盘时「当时那条告警为什么没响」在架构上无法回答。这比 #194 数据主权更隐蔽——数据还在，但「它曾被判定为噪声」这一事实消失了。

**挑战二：确认不等于处置。** OpenAI DNS 事件把这条裂开给人看：监控器 15 分钟内发现、10:02 报 P0、10:05 人确认，但跑了 2.5 小时到 12:34 才被手动杀掉——告警系统在大部分时间里「一切正常」，只是那条告警已经成了「已确认」的摆设。更糟的是监控器「把取数失败当成访问未发生」，这正是沉默被当成健康的翻版。

**挑战三：沉默被误读为健康，且 Agent 会替它编好理由。** Mastering Observability 11-13 复盘伦敦区故障：控制器守了一夜，读的是还带电的那根线，两条真正断电的馈线没触发；OTel 项目 11-10 一句话点破「应用可能健康，而它的遥测通路不健康」。一个停了的 collector 与一个平静的周二长得一模一样——「给 Agent 一片沉默，它会用像样的英语报告一切正常」，而且不是它的错。

**挑战四：召回税无人记账。** 低通滤波把召回让渡给精确率，是理性权衡；但只公布收敛率、不公布「被压掉的真告警数」，等于用别人的漏报美化自己的 KPI。这与 #218 榜单可比性同源——奖励什么，就被什么 gaming。

**挑战五：Agent 自己生产的告警混进收敛管道。** Claude Code 的 `CLAUDE_CODE_MAX_RETRIES` 默认 10 次，`api_error` 只在重试耗尽后才发——一个安静重试了 10 次的 Agent，在舰队视图里是「健康且沉默」的。

## 五、展望与建议

1. **给抑制立墓碑**：每条被收敛的告警写 `suppression_reason`／`suppressed_by`／`parent_incident_id`，并提供 `tombstone` 查询入口。没有墓碑的收敛率不进 KPI。
2. **把「确认→处置」计时纳入值守 SLO**：区分 `acknowledged_at` 与 `acted_at`，超过阈值的「已确认未处置」自动升级，映射 OpenAI 那 2.5 小时。
3. **给召回税记账**：收敛管道必须同时上报 `input_alerts`／`suppressed`／`post_filter_true_positives`，用自家历史事故做「关掉收敛」的 A/B 对照，量化漏报代价（接 #218 同装置对照法）。
4. **Agent 告警与基础设施告警分列**：两套收敛规则、两个 SLO，禁止用同一条抑制规则压掉两者。
5. **合成探针验沉默**：定时往真实采集链路注入合成事件，做「accepted = completed + rejected + processing」三方对账；`silence_verified=false` 时 Agent 必须输出「无法判定」而非「健康」。
6. **本地原型（第 113 期）**：**吴垚 09《从接住告警到自我进化》首次当主线**——全库唯一把「接住告警」作为演进起点、把「助手给不出根因→用户打标→真实根因分布沉淀→召回进化」写成闭环的实践；配周昕毅 10「三次现场检验：告警来了能否给优先级」、刘凯宁 05「确定性笼子」。判词：本地把「接住告警」当起点、把失败打标沉淀成知识，联网侧 2026 年才把「收敛」做成聚合/降级/抑制的产品能力；**两边都没把「哪条告警被判不算数、谁判的、留没留痕」做成可导出字段**。
