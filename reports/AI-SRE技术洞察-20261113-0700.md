# AI-SRE 领域技术洞察报告 · 第 168 期（2026-11-13 07:00）

## 题眼：动作可逆性面 — 自治的真实上限不是"能不能做"，而是"做错了能不能撤"

当六家厂商都在比拼"自治等级 L0–L4""无人介入闭环率"时，一个被系统性忽视的对称性被悄悄打破：智能体**能行动**的设计远成熟于它**能撤销**的设计。重启、扩容、清缓存可一键执行，但同一次"改错了配置 / 误删数据 / 错滚发布"却往往没有undo 算子、没有补偿事务、没有经过测试的回滚路径。本期主张：在 Agentic SRE 里，**可逆性而非能力，才是自治等级的真实天花板**——一个做错了撤不回来的动作，无论多"智能"，都不该被放进 L3 自动执行。

---

## 一、发展趋势

1. **治理判据从"能否自治"倒向"撤不撤得回"。** 2026 年多份治理框架（devsecops.ae、autoheal.ai、pcnmobile）把 *reversibility* 与 *blast radius* 并列为是否允许自动执行的首要判据；autoheal 更是把"可逆性"与身份/授权/审计并列为自治分级网格的第四维（Identity / Authorization / Audit / Reversibility）。
2. **补偿事务（Saga）从数据库进入运维。** Tacnode 将 1987 年的 Saga 模式引入 Agent 动作设计：可补偿事务（语义相反的撤销算子）、pivot 不归点（过了即不可整体回退）、可重试事务。每类动作须先问"它的补偿算子是什么"。
3. **"忠实撤销（Faithful Undo）"被研究原型立为硬约束。** STRATUS（多智能体自主可靠工程）要求*每个动作必须有 undo 算子，否则拒绝执行*；不可恢复动作被改写为可恢复——例如"删除文件"被替换为"移到备份卷"，使其变得可回收。
4. **度量反转：autonomy rate 的对照指标是 human revert rate。** dev.to 明确指出，与其看"Agent 自主闭环了多少"，不如盯着"有多少 Agent 动作后来被人手动回滚"——**上升的 revert rate 是自治失诚的早期信号**，比任何能力叙事都诚实。

---

## 二、技术现状

- **现实落差：** 宣称自治的 Agent 多停在 L1（建议）/ L2（审批执行），真正 L3 自动执行的动作类是窄集合（重启、扩容、清缓存）；schema 变更、密钥轮换、数据删除被普遍列为 Human-only（devsecops.ae 风险分类表：不可逆 + 大爆炸半径 = 人审）。
- **两类撤销混淆：** ① *Agent 状态回滚*（checkpoint / time-travel）≠ *世界回滚*——回放会从 checkpoint 之后重新执行 LLM 调用与 API 请求，不撤销已经发出的退款或删除（Tacnode）；② *reconcile 重新收敛* ≠ *撤销*——K8s operator 把状态拉回期望态，但不还原"期望态被改之前"的业务副作用（rottenwifi："能改却不能恢复服务，就不算可逆工作流"）。
- **工程落地分层：** GitOps 路径（Agent 提 PR、Argo 调和）让"撤销 = revert"天然成立（dev.to）；STRATUS 用栈式回滚（窗口 K=20）做资源级细粒度 undo；Autoheal 在提案时即生成 rollback 脚本；国内六家（Google / Anthropic / OpenAI / 字节 / 阿里 / 腾讯）尚无一家把"可逆性"作为公开的一等 SLI。

---

## 四、技术挑战

1. **补偿语义的"近似撤销"难题：** Saga 补偿是语义反向、不保证回到原状态（机票例子中途被他人改过）；云原生里大量动作（外部 API、数据删除、密钥轮换）无干净补偿算子，STRATUS 也承认"perfect undo 仍是实践挑战"。
2. **状态回滚与世界回滚的认知错位：** 框架的 checkpoint / time-travel 让团队误以为"撤销 Agent 即撤销后果"，但世界副作用（退款、删除、扩缩容后的流量再平衡）不在 checkpoint 内，回放反而可能**二次发出** API 请求。
3. **可逆性与自治等级的正反馈陷阱：** 越往 L3 推进，越需要可信可逆性作前提；但当前没有"可逆性就绪度"指标，导致"先升自治、补偿后补"的逆向工程，风险只在故障日暴露。
4. **度量真空（接 #159/#163）：** 六家零公开 `rev.*` 字段；human revert rate 作为自治失诚早期信号几乎无人采集，能力叙事掩盖了可逆性断裂。

---

## 五、展望与建议

- 立 `rev.*` 为**第 118 个市场空白字段族**：`rev.action_undo_operator_present`（每动作有 undo 算子）/ `rev.compensable_ratio`（可补偿动作占比）/ `rev.destructive_confinement_rate`（破坏性动作改可恢复或拦截率）/ `rev.human_revert_rate`（人被逼回滚率）/ `rev.rollback_path_tested`（回滚路径是否经测试）/ `rev.state_world_rollback_confusion`（状态 / 世界回滚误用率）/ `rev.saga_coverage`。六家零公开。
- **治理侧：** 把"可逆性四维新"纳入采购清单（autoheal 12-cell grid）；要求厂商声明每动作类的撤销算子与补偿策略；评测增"可逆性就绪度"子项（接 #153 评测门禁）。
- **工程侧：** ① 破坏性动作默认改写为可恢复（删 → 移备份，仿 STRATUS）；② 提案即生成 rollback 脚本（仿 Autoheal）；③ 在 harness 中把"状态回滚"与"世界回滚"显式分桶；④ 采集 human revert rate 作为自治失诚早期信号。
- **接本地原型：** 刘凯宁 蚂蚁「确定性笼子」（AntOntology 只拦截不改写、覆盖率 89%）正是"破坏性动作处置"的国内最早实践；周昕毅 携程「三次现场检验」应把"可逆性"列为第四检；朱革 百度 AgentOps 缺统一回滚 / 审计，应与 Saga 补偿对齐。
