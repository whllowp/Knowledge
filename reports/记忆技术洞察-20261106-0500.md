# 记忆技术洞察 · 第 3 期（2026-11-06 05:00）

> **本期主线：记忆的可寻址性——巩固与可追溯的数学冲突**
>
> 覆盖对象：dsh-memory-evolve、Hy-Memory 2.0、TencentDB Agent Memory、ReMe（ReMe→Ops）、OpenViking，另加 Zep Agent Skills 作关键对照。
> 观察窗口：2026-10-07 至 2026-11-06（最近 30 天）。
> 第 1 期讲"写得好"（写入侧独立化），第 2 期讲"删得清"（记忆的负空间）。两期都默认了一个从未被检验的前提：**存在"一条记忆"这样可被指认的东西**。本期检验它，结论是这个前提正在被行业自己拆掉。

---

## 一、发展趋势：三条曲线在同一周内同时拐弯

**曲线一：从"记住更多"转向"能指回原文"。**

11 月 1 日，Zep 发布 Agent Skills 并同步挂出论文（arXiv:2611.01386），把 agent 执行轨迹编译成可复用的 SKILL.md 工序。两句话正好答了上期之问：

第一句——"**代码检查每一条主张都引用了来自这些 run 的已记录事件**"。主语是"代码"，不是"提示词"。Reflector 起草后，Curator 逐条比对草稿里每个 claim 与 Trace 事件，**没有事件支撑的主张直接被删除**——不是降权、不是标记，是删。

第二句——"**删除一条源 run，会移除所有引用它的 Skill**"。级联删除，引用完整性（referential integrity）第一次出现在记忆系统的公开文档里。上期我们判定"删除可举证"是竞争空位，预测 60 天内会有方案把失效字段写进 schema——实际只用了 1 天，且走的是更硬的路：不是标记失效，是维护删除传播。

**曲线二：评测开始给"过程"打分，而过程分极低。**

11 月 2 日的 DeliverBench（arXiv:2611.03412，24 位作者）用 11 个真实职业项目（财务尽调、法律合同起草、药物安全报告）串起 150 个子任务，跨 2–15 轮新素材与客户反馈，**轮次之间不注入参考答案**——agent 必须继承自己上一轮的错误。七个 model-harness 系统里，最好的最终交付分只有 65.0/100，90 分阈值下子任务通过率 50.0%。

最锋利的数字藏在审计类项目里：**七个系统全部按评审意见改对了，但只有一个保留了可追溯性**。这把"记忆"从存储问题改判成**档案学问题**：专业交付物不是结论，是结论加一条可复核的路径。

同日的 Collaborative Intelligence Benchmark（arXiv:2611.02633）从另一侧补刀：接手任务的模型面对"更弱模型作弊过"的中间状态时，通过率从 97% 掉到 81%。**六分之一的交接会沉船，因为接手方无条件信任收到的状态。**

**曲线三：记忆的"影响面"被首次量化，但只能算平均值。**

11 月 2 日的 TRACE 框架（arXiv:2611.03939）做了此前没人做的事：固定问题与搜索结果，只改用户记忆。结果——表达"偏好某出版商"的记忆，让该出版商进入回答前三引用的概率提升 **33–39 个百分点**；表达"不信任主流媒体"的记忆，让含错误信息或阴谋论来源的引用上升 **6.3 个百分点**。

意义不在数字，而在方法论局限：TRACE 只能给**群体级**效应，无法回答**个体级**归因（这一次引用这个源，是否因为那条记忆）。**记忆系统能证明存了什么，却证明不了造成了什么**——可寻址性的最高一级，目前无人抵达。

## 二、技术现状：巩固正在系统性摧毁可寻址性

**一个必须先讲清的悖论：记忆质量的提升，几乎全部来自 N→1 的压缩。**

把各家的"变好"动作排在一起，会发现是同一件事的不同说法：TencentDB 的异步 Pipeline（L0 对话 → L1 原子事实 → L2 场景块 → L3 画像）逐层多对一；Letta 的 sleeptime agent 在交互间隙重写记忆块、**合并碎片**；Hy-Memory 的 ultra 模式加"图式归纳"，由 `evolve()` 触发，图式天然丢掉个案；Zep 把 N 条成功 Trace 编译成 1 份 Skill；参数轨把全部经验压进权重，是 N→1 的极端形态。

**每做一次 N→1，源与产物之间的边就断一次。** 断边之后：授权不知道授的是哪条源、注销不知道要连带删哪些派生、举证拿不出"谁导致了谁"、计费无法按源条目归集。上期那个"参数轨写入最强、注销最弱"的结论，在此刻得到了更一般的解释——**参数轨不是特例，它是压缩谱系的端点；注销能力的强弱与压缩率单调负相关。**

于是得到一个可命名为"**巩固税**"的结论：保留血统的成本按边数计，而巩固是多层 fan-in，边数随层数**指数增长**。1 万条 L0 对话抽出 2 千条 L1 事实（每条约 5 条来源），合成 200 个 L2 场景，收敛成 3 条 L3 画像——逐层留边是万级规模，只在 L0 留原文则 L1 以上全是无源之水。**大多数系统选了后者，因为它在演示里看不出差别。**

**三种主键，三种断裂模式。** 要指认一条记忆，先要有标识，而现状三种都不稳：**路径键**（ReMe、dsh-memory-evolve、OpenViking 的 `viking://`）遇重命名、移动、目录重构即产生"新对象"，旧引用全指向空气；**序号键**（TencentDB 的 `message_ids` 与 `atomic id` 并存、L2 又退回路径）在同一系统内共存多套，跨层无映射；**内容键**（向量库默认）任何编辑即变键，而巩固产物没有稳定内容，键不可复现。

TencentDB 值得单看。它明确写了"**元数据与内容分离**"：MemoryCore 只登记"哪个知识源、什么状态、什么关系、服务地址"，解析检索交给 MemoryKnowledge。这是好的工程决策，但把可寻址性问题**上移**了——MemoryCore 知道资产存在，不知道资产内部的一条事实对应哪几句原话。L1 按 ID 批量删，L2 是按路径增删的 Markdown，L0 按 message_id，**删掉一段 L0 对话，没有文档说明 L1 里由它抽出的事实会怎样。** 不是实现缺陷，是设计里没有这条边。

**唯一把边做成一等公民的是 Zep Agent Skills，但适用范围很窄。** 它只覆盖**过程性记忆**（Skill），不覆盖事实性记忆；Zep 的另一半资产 Graphiti 时序图谱走"边失效不删除"路线，保留"曾为真"的历史，代价是永不真正移除。**同一家公司、两条产品线、两套相反的记忆哲学**——说明问题尚无统一答案。反例是 Hy-Memory 把代码 diff 链当血统（"记住那一版为什么不行"），粒度是变更意图而非事实来源：证明血统不必是重资产，但未解决跨层聚合。

## 三、技术竞争力：加入"可寻址性"维度后的对比

上期表里有"删除举证"一列。本期把它拆成更前置的问题：**能不能指认**。为此设三级阶梯——**A 可枚举**（能列出全部条目，绝大多数系统达到）、**B 可定位**（任一条目能指回它来自哪段原文/哪个事件，仅 Zep Agent Skills 达到）、**C 可归因**（能证明"这条记忆导致了那次行为"，无人达到）。

| 方案 | 主键形态 | 血统粒度 | 级联删除 | 可寻址 | 最强项 / 主要短板 |
|---|---|---|---|---|---|
| **Zep Agent Skills** | Trace ID + 不可变版本 | **字段级**（claim 引事件） | **有**（删源即删引用 Skill） | **B** | 唯一实现字段级引用完整性，准入由代码校验。短板：只覆盖过程性记忆 |
| **TencentDB** | 三套并存（message_id / atomic id / 路径） | 层间无边 | 无（各层各删） | A | 治理最强（四类资产 + ACL）。短板：蒸馏链不可回溯，删源不传播 |
| **OpenViking** | `viking://` 路径 + peer | L0/L1 为 L2 摘要，重生成即覆盖 | 无（`forget` 硬删） | A | 寻址统一、token 效率 -34%~-91%。短板：重生成抹掉旧摘要 |
| **Hy-Memory 2.0** | user_id + 三类记忆 + 代码 diff 链 | 代码轨有链，事实轨无 | 权重不可删 | A（代码轨近 B） | 写入质量、1159→703 token、Q6_K 本地 58.78%。短板：图式归纳丢个案 |
| **dsh-memory-evolve** | 文件路径 + git 分支 | 无（条目级归档） | 文件删 + git 同步删 | A | 作用域最细（分支级）、归档可逆。短板："为什么"只在对话里不在条目里 |
| **ReMe** | `.reme/` 路径 | Markdown 即真相，diff 即证据 | 文件删除 | A/B | 举证形态天然。短板：无自动派生关系，靠人维护 wikilink |
| **Mem0 / Graphiti** | 向量 ID / 图节点 ID | 双时序边（`valid_from`/`valid_to`） | 条目删除 | B（时序） | 可判"曾为真"。短板：失效边永久累积，无回收策略 |
| **Letta** | 块 ID | 无（sleeptime 合并碎片） | 块级删除 | A | 睡眠巩固完整。短板：合并即失源，最典型的"巩固摧毁可寻址" |

**表外有两条结论。第一，"有血统"与"能治理"目前互斥。** Zep 有字段级血统但只覆盖 Skill；TencentDB 有最好的治理（四类资产 + 四级可见性 + ACL）却没有层间边。**没有一家同时具备"字段级血统"与"团队级治理"**——比上期"双时序 + diff 可举证"更硬也更贵的空位。

第二，**血统是纯成本项**：不提升任何 benchmark 分数，只增加存储与写入延迟。**这解释了为什么是 Zep 而非更大的玩家先做**——它的客户是企业工作流，买方本来就要审计轨迹。血统的推动力不从评测来，从采购来。

## 四、技术挑战

**挑战一：巩固税无法规避，只能选择在哪一层交。** 全量留边不现实（指数增长），全量弃边则退回上期的合规死路。折中是**分层差异化留边**：L0→L1 留逐条边（量可控，且是事实溯源唯一入口），L1 以上只留"聚合指纹"。代价是 L2/L3 只能定位到集合、不能定位到个体——**精度换成本的显式取舍，不是能力缺失。**

**挑战二：个体级归因没有方法。** TRACE 证明了记忆能改变行为（引用偏移 33–39pp），但那是群体统计。要回答"这次错误是因为那条记忆"，需在推理时记录哪条记忆进了上下文、在哪个位置被引用、去掉它会怎样——前者是上下文日志（可做，无人做），后者是反事实推断（无可靠方法）。**没有归因，事故无法定责，也就没有运维闭环。**

**挑战三：稳定 ID 与隐私天然对立。** 可寻址要求跨时间稳定的标识，而稳定标识符本身就是最强的关联键，把分散在不同会话、不同 agent 的同一人的记忆串起来。GDPR 下假名化标识符仍属个人数据——**"为能删除而给每条记忆发身份证"，同时也在制造新的画像入口，本条最无解。**

**挑战四：多 Agent 共享记忆时，主键归属无人定义。** 两个 agent 写同一个 key，谁是 owner、谁的版本生效、冲突怎么裁决？现有答案全是"应用层自己处理"。dsh-memory-evolve 把裁决交给人（本机/远端/两者都要），诚实但不可扩展。**主键是单写者假设，多 Agent 下已失效**——这也是 CIB 97%→81% 的深层原因：接手方不仅信任状态，还无从查证来源。

## 五、展望与建议

**给建设者：把血统做成独立关系表，不要嵌进条目。** 四列即可：`(src_id, dst_id, field_path, event_ids)`。`field_path` 是关键——Zep 的价值在"字段级"：一份 Skill 里 8 个 claim 可能只有 3 个有证据，条目级血统会把 5 个无据主张一起洗白。独立存放还能按需裁剪：合规全留，消费只留 90 天。

**给平台方：把"删除传播"写进 API 契约，而不是文档。** Zep 那句"删源 run 会移除所有引用它的 Skill"应该是 `DELETE` 的返回值：`{deleted: 1, cascaded: 7, orphans_blocked: 0}`。**返回级联数量，等于每次删除都在自证引用完整性还在**——比营销话术有说服力，实现成本极低。

**给评测方：AML 下一周期增设"可追溯性"轨。** 做法极简：给定一个已交付物，要求系统回答"这份报告第 7 条结论来自哪三次交互、依据哪份材料、中间被改过几次"。DeliverBench 的 1/7 已证明这是稀缺能力，且它与检索精度**不相关**，正好补上 AML"只看下游效果"的盲区。

**30/60/90 天判断**：30 天内 AML 二期出榜，预计 Coding 轨在噪声条件下显著下探，但不会出现可追溯性维度；60 天内会有一家中国厂商把"派生/来源"字段加进公开 schema（TencentDB 因治理诉求、OpenViking 因 `viking://` 已有路径血统雏形，概率最高）；90 天内"记忆血统"会作为独立品类出现——不是新框架，而是外挂旁路服务，因为改造存量系统远比外挂贵。---
