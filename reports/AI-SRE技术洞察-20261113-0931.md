# AI-SRE 技术洞察（第 175 期）

**生成时间**：2026-11-13 09:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：传承面／接手面（Succession）——属主走了，Agent 还在；接的人要多久才能安全地改它？

---

## 题眼

154 期引过 Arrakis 的原话：**「当一个 Agent 不再被使用，没有人移除任何东西，因为在大多数公司里没有人拥有它。」** 但更常见的情形不是「没人拥有」，而是**「原来的人走了」**：创建者离职、转岗、换团队，Agent 还在跑，**新属主接手时面对的是：一份没人维护的 prompt、三个来源不明的工具、一套没有证据的权限、以及一句「这个别动」**。146 期说 Agent 有四类属主；132 期说班次之间要交接；100 期说 Agent 之间要托管状态——**但「人走了、Agent 留下」这件事，没有交接仪式**。**传承不是文档移交，是「新人能在不弄坏它的前提下改它」。** **只交接了文档，等于只交接了「它长什么样」，没交接「为什么长这样」。**

## 一、发展趋势

**趋势一：Agent 的生命周期开始长于人的任职周期。** 一个 Agent 跑三年，属主换两任；**没有传承机制，第二任只能「供着」**。**供着的系统不会进步，只会腐烂。**

**趋势二：接手从「读文档」变成「读证据」。** prompt 为什么这么写、工具为什么这么配；**答案在提交记录与实验里，不在 wiki 里**（155／157 期）。

**趋势三：交接开始有「安全改动」标准。** 不是「看懂了」，是**能独立做一次不引发事故的变更**。

## 二、技术现状：四件套，通常只给一件

**文档：最常给，最常过期。** runbook 写了三步，**第二步的界面已经改了**（134 期）。

**来源：最少给。** 模型/prompt/工具从哪来、谁批的；**没有 provenance，新人不敢动**（157 期）。

**权限：最容易漏。** 旧属主的 key 还在；**新属主不知道该撤哪些**（163 期）。

**影响图：几乎没有。** 改这个 prompt 会动到谁；**新人只能靠猜**（173 期）。

**三种接手，一种比一种难。** 冷接手（原属主已走、无文档）、温接手（有文档、能问人）、热接手（有文档、有证据、有影子期）；**多数团队在冷接手，却按热接手排期**。

## 四、技术挑战

**一，隐性知识不在文档里。** 「这个 prompt 别动第三段」；**原因没人记得**。

**二，来源链断在人身上。** 谁批的、为什么选这个模型；**人走了就断了**。

**三，旧凭据没人撤。** 旧属主的 key 还在跑；**新属主不知道存在**（163 期）。

**四，影响图缺失。** 新人改一处，动到三个团队；**没人提前告诉他**（173 期）。

**五，验收标准模糊。** 「看懂了」不算；**要能独立做一次安全变更**。

**六，传承没有时限。** 老属主「随时可以问」；**三个月后他就不在了**。

**七，离职流程不触发交接。** HR 关账号，**不关 Agent**；交接靠自觉（154 期）。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `succession.*` 字段**：`agent_id`、`from_owner`、`to_owner`、`transferred_at`、`checklist`、`first_change_id`、`shadow_until`。
- **R2 交接清单**：文档/来源/权限/影响图四件套；**缺一项不算交接完成**。
- **R3 影子期**：新属主 shadow 30 天；**期间变更双签**。
- **R4 首次改动**：新属主独立做一次低风险变更；**记录为验收**。
- **R5 权限移交**：旧凭据撤销、新凭据签发；**旧属主保留只读 30 天**。
- **R6 指标**：交接完成率、影子期事故率、首次改动通过率、旧凭据残留率。

### 5.2 用户旅程

- **离任属主**：离职流程触发 → 填交接清单 → 移交权限 → shadow 30 天 → 记录首次改动。
- **接手属主**：读四件套 → 跟一次变更 → 独立做一次低风险变更 → 验收。
- **平台**：旧 key 到期撤销；新 key 签发；记录 `transferred_at`。
- **审计**：抽查一个 Agent → 核对交接记录与首次改动 → 确认可接手。

### 5.3 实现方案（90 天）

- **0–30 天：清单。** 四件套模板；存量 Agent 补录。
- **30–60 天：流程。** 离职触发交接；影子期；双签。
- **60–90 天：验收。** 首次改动验收；旧凭据清理；指标上线；离职流程自动触发。

**第 122 个市场空白（五项）**：交接完成率、四件套覆盖率、影子期事故率、首次改动通过率、旧凭据残留率——无一内建；`succession.*`／`handover.*` 为**第 91 次无人提字段族**。本地 173／173-kb 连续第 82 期成组启用：朱革 15「统一权限、审批、回滚」＝全库唯一把「权限与回滚」写成治理闭环的实践，本期首次当主线；配 146 期属主、154 期退役。判词：**本地把权限回滚写进治理，联网侧 2026 年才量出「76% 休眠仍持活凭据」；两边都没把「新属主能否安全接手」做成交接验收。**
