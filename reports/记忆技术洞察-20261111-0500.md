# 记忆技术洞察（第 44 期）· 2026-11-11 05:00

## 记忆的调度层——"取"是一次带预算的决策，不是每次提问的默认动作

### 一、发展趋势

前 43 期拆过写（第 1 期）、删（第 2 期）、指（第 3 期）、钱（第 5 期）、空（第 7 期）、并发（第 8 期）、时效（第 10 期）、送达（第 30 期）、查（第 40 期）、测（第 42 期）、退（第 43 期），但四十三期共享一个从未写出的默认值：**每次提问都要走一遍记忆流水线**。11 月第一周（11-01 至 11-07）四篇论文同时把这个默认值拿掉——OMCE（arXiv 2611.01747，11-01）让控制器在 DIRECT/EPISODE/GUIDE/DISTILL 四种认知动作里选，其中 DIRECT 就是不取；Route to Remember（2611.05636，11-03，NeurIPS 2026 Workshop PALM）用 verify-then-regenerate 路由把问题分给"参数里的记忆"或"文本里的记忆"；MIRIX-2.0（2611.12068，11-07）写明"检索在显式预算下运行，一个问题检查的证据量不随历史增长"；SoMem（2611.11929，11-07）让 agent 在查询时自己决定搜什么、读什么。趋势判读：**记忆的成本大头不在库里，在调用次数上；而调用次数过去由框架硬编码，现在开始由调度器决定**。检索从"固定环节"变成"有预算的动作"，调度层正在成为独立工程位。

### 二、技术现状

**OMCE：把"用不用记忆"当成一个可学习的决策**。控制器是轻量 contextual bandit，输入是紧凑检索信号，输出四个动作：DIRECT（不取，直接答）、EPISODE（取具体案例）、GUIDE（取可复用原则）、DISTILL（把新经验固化成指导）。三个耦合决策被一次路由解决：是否调用经验、用哪种记忆形态、何时巩固。四个在线适应基准 × 四个骨干模型：首次尝试成功率最高 **+20.5pp**，相对 ACE（GPT-5.2）单任务 token 降 **5.7–62.5 倍**。最能说明问题的是那个定性例子：用户先说开源峰会"六月"、后更正为"七月"，固定案例记忆坚持沿用旧约束答六月；OMCE 选 GUIDE（该动作估分 0.9779，EPISODE 仅 0.6572），原则要求"丢弃已被取代的约束"，于是答七月。**同一个事实，以案例送达会答错，以原则送达会答对——形态选择直接改变正确性方向**，这不是成本问题。

**Route to Remember：记忆有了第二个物理载体**。OPSD 用"带用户记忆的教师"蒸馏出"零上下文的学生"，把用户事实烧进参数；再配一个 verify-then-regenerate 路由，让权重记忆与文本记忆各答各自擅长的题。HaluMem 上，权重记忆在召回上追平甚至超过全上下文提示与检索系统，而每次查询读的 token 更少。

**MIRIX-2.0：预算被写成硬约束**。六类记忆 agent 保留完整记录作 system of record，provenance hypergraph 用 n 元帧引用原始行；检索在显式预算下运行，**检查的证据量不随历史增长**。LoCoMo 91.4%、LongMemEval-S 72.6%（领先最强基线 14.3 点），程序性记忆在 MetaClaw-Bench 49.2% 对技能库 44.0%；AutoDream 在写路径外合并不重写任何记录。**SoMem** 走另一条：记忆是链接文档，运行时校验更新，查询时沿链接展开并回看原始证据（LoCoMo/BEAM-100K/LongMemEval-S 分别 +2.66/+3.10/+2.00），且库可跨模型复用。

**产品侧仍是硬编码调度**。OpenViking v0.5.4（11-09）的 `search` 先规划检索路径、新增 Rule Search 在执行动作前按需查规则——已经很接近调度，但规则是人写的，不学习、不估算收益；TencentDB 按 L0–L3 人工规则下钻；Mem0 固定 top-k、没有"不取"这个动作；Letta 由上下文容量触发（容量驱动而非价值驱动）。新进场的阿里云 PolarDB Agent Memory 报 LoCoMo 91.2%、检索 p50 0.51s，但调度仍是固定检索。**六项目速览**：OpenViking 41,918★/1,374 issues；TencentDB 30.6k★；Hy-Memory 10-28 后无新版；ReMe 0.1.3 无更新；dsh-memory-evolve 插件页 v26092802、GitHub push 停在 10-29。AML 二期榜单仍未发布（11-04 已关评测、月中出榜；首期文本榜 MemoraX 58.02 / MemOS 45.89 / NTES 44.21，代码榜 62.00% 对三套 52.00%）。

判读三点：①**倒挂第 35 次**——调度能力最完整的四个实现全在论文，产品侧要么固定 top-k，要么人工规则，没有一家把"不取"当一等动作；②**口径缺口第 36 次**——AML 协议只暴露 Add/Search，参赛系统被迫"每次必取"，调度策略在评测合同里根本无法表达，榜单结构性地奖励"多取"；③**恒证预算应成为记忆 SLI**：`每次回答检查的证据量`这个数（条/字节）比 top-k、比库大小都更能预测账单与正确率，MIRIX-2.0 是第一个把它写成约束的。

### 四、技术挑战

①**反馈信号既稀疏又不干净**：bandit 要结果标签，长任务成功信号晚到；且"成功"里混着模型本来就会的部分（第 42 期三重账），调度器极易把模型能力记成记忆功劳，越训越自信；②**探索税落在新用户头上**：无历史只能 DIRECT，冷启动期不得不付探索成本，与第 33 期"收益集中在前 25%"同源反向——成本也集中在最没数据的那一段；③**路由到权重＝悄悄剥夺删除权**：OPSD 学生把用户事实烧进参数，文本副本可删，权重不可删，第 2 期"注销完全失能"与第 36 期"用途分离"在路由层被绕过，而用户只看到"已删除"；④**预算化主动放弃完备性**：第 40 期的 `count(where)` 在恒证预算下不可判定，"有没有"退化为概率判断，治理脚本无法再断言空集；⑤**调度器是新单点，也是新攻击面**：MemoryDojo（2611.09721，155 条多会话轨迹 × 5 套记忆系统）显示所有记忆系统均可被投毒，而调度器一旦学会"这类题该查记忆"，污染就会被稳定放大——路由的收益与风险同源。

### 五、需求 · 用户旅程 · 实现方案

**需求**：token、延迟、正确率三本账里，唯一能同时压前两项的动作是"少取"，但开发者没有工具判断"这一问该不该取"。采购侧需要的新数字是**每次回答检查了多少证据**，而不是库有多大。

**用户旅程**：提问 → 判档（DIRECT/EPISODE/GUIDE/DISTILL）→ 预算内取证 → 载体核对（文本为权威，权重只答稳定事实）→ 结果回流更新路由 → 离线蒸馏成原则。当前断点在第二步：所有系统从第三步开始。

**实现方案**三层：①SDK 返回值加三字段 `route`（四值）、`evidence_budget`（条/字节）、`route_reason`，先做启发式（无相似 episode→DIRECT；有可复用原则→GUIDE；任务结束→DISTILL），后换 contextual bandit；②预算按"证据条数×字节"写死为常数，不随库增长，对齐 MIRIX-2.0；③反馈用三跑对照（no/oracle/prod，第 38 期）剥掉模型基线，再把差值回流；④权重路由加硬约束：仅稳定事实可进参数，且保留文本权威副本与撤销开关，否则不允许上线。

**下月对账点**：AML 二期是否披露调用策略（最高优先）；首个公布"每答证据量"的产品；OpenViking Rule Search 是否从人工规则走向学习；权重记忆产品是否提供"参数内删除"。
