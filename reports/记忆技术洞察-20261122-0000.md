# 记忆技术洞察 · 第 135 期（20261122-0000）

**主题：记忆的「按时衰减」（parametric lifecycle management）——权重里的记忆不该只追求"永不忘"，而要在到期时学会"不作答"。前 134 期的生命周期多写在文本层（#104 退役状态机、#113 陈旧、#114 删除），#80 只观察到参数化记忆随年龄衰减并做栖居路由；11-18 提交的 Some Memories Must Fade（arXiv 2611.25235，Samsung Research America，Sanidhya Vijayvargiya／Rahul Lokesh，cs.LG/cs.AI）第一次把"记不记、记多深、记多久"做成写入时的三动作策略，并让每条记忆在固定容量 LoRA 中按自己的时钟淡出。与 #80 划界（那期选择去哪存、本期让权重本身会忘）、与 #1 写入闸门和 #104 划界（那两期分守护入与退场，本期合并为一次事件决策）。**

> 洞察范围：2026 年（近 30 天为主）。四维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

参数化记忆正摆脱"持续学习＝无限期保留"的旧目标：稳定事实要留住、反复观察要加深、信念改变要覆盖、临时信息要淡出。趋势是把记忆寿命从系统常量降为逐事件可学习的变量，并把"到期后弃答"列为一等输出——不答不是检索失败，而是生命周期走到终点。

## 二、技术现状

记忆基质是固定容量 LoRA：A 矩阵正交冻结，B 的 32 个秩列作地址，每次写只路由 k=2 列（496 个 k-hot 位置），干扰随掩码重叠增长；每列带独立衰减常数 τ∈{25,100,400,1600,20000} 天，按 exp(−Δt/τ) 自然淡出并回收容量。2M 参数控制器看事件语义、GRU 轨迹史与各秩年龄／范数／前向矛盾信号，输出门控 g、写深 d 与 τ。另设秩 32 读取适配器，按写深标定弃答概率（d=20 时 0.9、d=150 时 0），空槽直接输出 Unknown；先稳定头 MSE，再 DAgger 模仿元数据预言机，PPO 可选。

## 三、技术竞争力

在 909 条多年用户轨迹（700—1500 天）、15 名留出用户、4584 个探针上，全学习策略 CB 0.56，高于同算力 RAG-MM 0.50 与 122B 管理模型 0.53，远超最佳持续学习 PCGrad 0.42；完美路由 0.60，元数据预言机 0.65，即恢复到上界的 86%。短命事实项 0.59 对无管理 ≤0.26，而稳定事实项无管理深写 0.65 反胜策略 0.39—0.40——策略用 VAL 换取高 ABS（0.78—0.81）。全局单一 τ 使 0.60 跌至 0.48；为长命事实留专用列可把 STABLE VAL 从 0.33 提到 0.70，代价是每用户 11→22MB。

## 四、技术挑战

①共享列被后写入的短 τ 覆写，长命事实会"被短命邻居带跑"；保留最大 τ 可追回约 13 点稳定事实召回，却让短命类弃答崩塌、CB 反降至 0.45。②只看事件语义推断寿命 R² 仅 0.36，必须借用户轨迹。③新输入格式要重测写深与衰减曲线。④记忆事件识别被当作已知，轨迹为合成；DAgger 状态感知监督 0.56 对固定深度监督 0.49，说明策略仍吃元数据。

## 五、需求分析

运营方要的不是"存得越多越好"，而是四类生命周期各有归宿：稳定事实留存、重复观察强化、变更信念覆盖、临时信息失效。同等重要的是失效后敢于回答 Unknown，否则陈旧的权重痕迹会被模型编成看似合理的答案。容量固定、查询不随历史增长，是参数化路线对文本记忆的核心卖点。

## 六、用户旅程

一条用户事件到达后，控制器先判是否值得写；若写入，选写深与寿命并路由到 k-hot 列，后续每一天按 τ 衰减。查询时不检索外部历史、上下文不增长：读取适配器只读基质当前状态，判断痕迹够不够支持作答，不够就弃答。上线审计须按生命周期类别分列"有效期召回率、失效后弃答率、每用户容量"，而不是只报总体准确率。

## 七、具体实现方案

①把写入闸门扩成 (g,d,τ) 三动作，路由与策略解耦以分离分配误差与管理误差。②用独立 τ 与增量写替代覆盖：五次 d=20 的累积 retention 0.93 接近单次 d=80—110，重复观察天然成强化。③以写深条件化的弃答曲线做校准，把"弱痕迹即幻觉"改为可学习映射。④长命事实走专用列，寿命隔离按 MB/用户明码标价。⑤验收：AML 增 parametric-lifecycle 维度（有效召回、失效弃答、每用户 MB、共享列干扰率），以"到期后敢不敢不答"验收。五项目经 GitHub tag/release API 核实：OpenViking v0.5.5、Hy-Memory v2.0.17＋MemHub v1.0.8、TencentDB-Agent-Memory v2.0.4、dsh-memory-evolve v26092802、ReMe v0.4.2.3——五家全在条目／向量／图谱层做管理，零逐条寿命参数、零权重级弃答校准，倒挂延续。反证：合成轨迹、模板化探针、τ 覆写未解、专用列翻倍容量，不作外推。

## 八、本期新观点

1. **写入决策从"记不记"扩为"记不记·记多深·记多久"**（接 #1 写入闸门／#104 退役门划界）——生命周期不再是事后清理，而是一次事件的三动作输出，深化 #80 的栖居路由到权重内部。
2. **弃答是记忆能力，不是检索失败**（深化 #78 拒答／#80 "权重编造而非拒答"）——用写深条件化概率把弱痕迹映射成 Unknown，权重记忆首次具备"表示缺席"的机制。
3. **寿命压缩是共享基质的新失败模式**（接 #5 记忆税）——后写短 τ 覆写先写长 τ，稳定事实被短命邻居带跑；专用列以 2× 容量换 +13 点召回，寿命隔离须明码标价。
4. **寿命是用户条件而非语义条件**（深化 #131 模型条件剂量到用户条件）——同类事实对不同用户寿命不同，语义单特征 R² 仅 0.36，必须从轨迹史与基质状态推断。
5. **强化是增量写入而非单次深写**（接 #65 信念化校准）——五次浅写累积到 0.93，提示"重复观察"应作为写策略，而非只在置信度上做加法。
6. **五项目倒挂＋AML 补 parametric-lifecycle 维度**（接 #56/#69/#87）——五家均管理文本条目，零权重级生命周期与弃答校准；补有效召回／失效弃答／MB·用户／共享列干扰率，以"到期后不答"验收。
