# AI-SRE 技术洞察（第 274 期）

**生成时间**：2026-11-18 05:31（Asia/Shanghai）
**观察窗口**：2026-09 至 2026-11-18
**本期主题**：暴露面／控制面默认值——被扫到的不是模型，是管理端口

## 题眼

arXiv 2609.07115 对暴露在互联网上的 Ollama 端点做了纵向测量，给出两个残酷的数字：**版本寿命 P50 = 114 天，IP 寿命 P50 = 5 天**；五个已披露 CVE 的**原地升级率只有 0.43%–2.90%**——补丁主要不是靠升级打的，而是靠旧 IP 消失、新 IP 带着另一个旧版本上线。与此同时，模型生态在扩张：唯一模型数 **+214%**。这意味着“曝光”不是一次性事件，而是一个稳定的存量池：机器换了一批，端口和默认值没换。

同月，SANS（2026-11-15）专门讨论“扫到暴露的 Ollama 主机”在法律上算不算未授权访问——需要讨论本身，说明暴露量已经大到成为常态。控制面更糟：Obot（CVE-2026-101065，2026-09-28）的 Docker quickstart 默认监听 `0.0.0.0:8080` 且**关闭认证**，关闭认证时每个请求被映射成合成用户 `nobody`，而它持有 Owner 与 Admin 角色；quickstart 还挂载 `/var/run/docker.sock`——任何能到端口的人都能注册并启动自己的 MCP server，再借 Docker 控制面拿到宿主机。这不是“模型说错话”，这是“控制面把钥匙插在门上”。

## 一、发展趋势

1. **攻击重心从推理面移到控制面**。推理端点泄露的是算力与数据（vLLM 的 CORS 通配默认值允许任意网页让受害者浏览器打 `localhost` 的 vLLM，消耗 GPU 并读回响应，PYSEC-2026-4348，2026-10-26）；控制面泄露的是执行权：Ray 的 dashboard、Jobs、Client 端口**按设计就能执行代码**（Ray Client 10001 是 RCE 端点），`--include-dashboard=false` 并不停掉 dashboard agent 与 runtime env agent 的四个监听器；Langflow 的公开 flow build 端点（CVE-2026-33017）被在野利用并进了 CISA KEV。

2. **“默认关闭认证”比漏洞更常见**。Obot 的 `nobody`=Owner/Admin 是最直白的例子；Clawdbot（Mallory，2026-01）被发现 **900+ 个公网实例**，默认端口 18789、Control UI 无认证，泄露第三方 token、Anthropic API key 与数月聊天记录。默认值不是配置错误，是产品决策——而运维继承了这个决策的后果。

3. **认证中间件自己会成为绕过点**。vLLM CVE-2026-48746（CVSS 9.1，0.3.0–0.21.x，0.22.0 修复）：`AuthenticationMiddleware` 用 `URL(scope=scope).path` 重建请求路径，而它信任攻击者可控的 Host 头，构造的 Host 让路径不匹配 `/v1` 前缀，认证整个被跳过。这类“认证器读错了对象”的缺陷，靠 WAF 规则很难补。

4. **生态组件的暴露面在叠加**。Langflow 1.10.3 之前的 MCP stdio 传输**不设 allowlist**，用户在 MCP server 配置里填什么命令就执行什么（GHSA-w794-rj3p-xv45，CVSS 9.9）；任何能打开 MCP 设置页的人等于拿到 RCE。Agent 平台的“配置能力”与“执行能力”没有边界。

## 二、技术现状

**第一层：资产清点仍然是端口清点。** 扫描器的指纹是 title、默认端口、`/api/tags`、`/v1/models`、`/health`；Censys/Shodan 风格的发现能给出“有多少台”，但给不出“这台代表谁、被谁批过、上面跑了哪些工具”。900+ Clawdbot 与 Ollama 的存量池都证明：发现不是难点，**归属与授权**才是。

**第二层：默认绑定与默认认证的组合决定了爆炸半径。** `0.0.0.0` + auth off = 公网可写；`0.0.0.0` + auth on 但默认口令 = 延迟爆炸；`127.0.0.1` + 反向代理 + 无认证 = 内网横向。Obot 把三种都占了：默认监听、默认无认证、默认挂 docker.sock。

**第三层：升级率低不是运维懒，是升级没有“可验证的完成”。** 0.43%–2.90% 的原地升级率说明：多数部署的升级路径要么不存在（容器镜像固定 tag），要么升级后配置回滚（compose 文件里还是 `0.0.0.0`），要么“升级了但旧进程还在”（多副本滚动）。版本寿命 114 天 vs IP 寿命 5 天，正好说明**曝光池的周转靠 IP，不靠补丁**。

**第四层：日志看不见“谁下的令”。** Obot 的无认证请求在日志里是 `nobody`；Ray 的 DELETE 请求在 dashboard 日志里是匿名；Clawdbot 的 WebSocket 会话没有用户身份。出事之后能回答“哪个 IP 打了哪个端口”，回答不了“它注册了哪个 MCP server、以什么权限运行、碰了宿主机的什么”。

## 三、技术竞争力

| 方案／组件 | 暴露类型 | 默认绑定 | 默认认证 | 最坏后果 | 修复方式 | 运维可控度 |
|---|---|---|---|---|---|---|
| Ollama | 推理端点 | `127.0.0.1:11434` | 无 | 模型窃取／算力滥用 | 绑定回环＋反代 | 高（改配置即可） |
| vLLM | 推理端点 | `0.0.0.0:8000` | 可选 | 认证绕过（Host 头）／GPU 耗尽 | 0.22.0＋CORS 收紧 | 中 |
| Ray | 编排控制面 | dashboard `0.0.0.0:8265` | 部分端点无 | RCE（Client 10001）／删任务 | 2.54.0＋网络隔离 | 低（监听器多） |

| 暴露面扫描（Censys 类） | 发现 | — | — | 只发现不归属 | 资产打标 | 中 |
| 网络策略（mTLS／零信任） | 收敛 | — | 强制 | 配置漂移 | 策略即代码 | 高（需覆盖） |

**判读**：托管推理把“默认值”问题转移给了云厂商，自建推理与 Agent 平台则把它留给了运维。控制面组件（Ray、Langflow、Obot）的共同点是**功能即执行**：它们的存在意义就是“让用户提交代码/命令/配置并运行”，所以“关掉公网”不是可选项，是前提；而它们的默认绑定又把前提破坏了。

**本期反转**：我们习惯把“模型安全”当成内容问题（越狱、注入、幻觉），把“基础设施安全”当成网络问题（防火墙、WAF）。暴露面数据说明两者在控制面交汇：一个默认无认证的 MCP 平台，让“Agent 能调什么工具”这个内容问题，直接变成“谁能拿到宿主机”这个网络问题。**先修默认值，再谈护栏**——一个开着 `0.0.0.0:8080` 无认证的 Agent 平台，护栏再厚也只是给攻击者省了一步。

**判词**：「WAF／API 网关／扫描器／mTLS／零信任网络策略／托管推理」全部可采购，「哪台实例在哪个端口上、以谁的权限暴露、升级后旧口子是否真的关掉」不可采购。

## 四、技术挑战

1. **多监听器组件**：Ray 一类组件一个进程开四个口，关掉 UI 不等于关掉 agent；资产台账按“服务”记，不按“监听器”记，必漏。
2. **默认值继承**：quickstart、Helm chart、compose 文件把 `0.0.0.0` 与 auth off 写进模板，升级镜像不会改模板。
3. **认证器缺陷**：Host 头、CORS 通配、路径重建——认证中间件读错对象时，外部扫描看不出来，只有代码审计能发现。
4. **归属缺失**：暴露实例往往没有属主、没有变更记录、没有到期时间；“影子 AI”在第 251 期讲的是清单外系统，这里讲的是清单内系统的清单外端口。
5. **验证缺口**：升级后如何证明“口子关了”？需要从外部复扫＋从内部核对监听器，两头对不上就是没关。

## 五、需求分解、用户旅程与实现方案

**需求分解（D1–D6）**

- D1 监听器级资产：资产台账记录到（主机，进程，监听地址，端口，协议），而不是“服务名”。
- D2 安全默认：自建模板一律 `127.0.0.1` 绑定＋认证必填＋无匿名管理员；`docker.sock` 默认不挂。
- D3 控制面隔离：推理面、编排面、管理面分网；管理面只允许跳板／VPN；控制面组件禁止公网入口。
- D4 认证器审计：把“认证中间件读什么”纳入代码审计清单（Host、CORS、路径规范化、代理头信任）。
- D5 升级可验证：升级后自动从外部复扫端口指纹＋内部核对监听器，双绿才算完成。
- D6 归属与到期：每个暴露实例有属主、用途、到期日；到期未续自动下线。

**用户旅程（一次 POC 变事故）**

① 团队为验证 Agent 平台起 Obot，按 README 的 quickstart 跑容器（默认 `0.0.0.0:8080`、认证关闭、挂 docker.sock）；② 为方便同事访问，安全组放开 8080；③ 扫描器发现端口，攻击者打开 Control UI，以 `nobody`（Owner/Admin）注册一个 MCP server；④ MCP server 通过挂载的 docker.sock 启动特权容器，拿到宿主机；⑤ 复盘时日志显示操作者是 `nobody`，资产台账里没有这条入口，变更记录里只有“起个 POC”。

**90 天实现方案**

- **第 1–30 天**：清点。用外部扫描（Censys/Shodan 类）＋内部 `ss -lntp` 双向对账，产出“监听器台账”；标出所有 `0.0.0.0` 且无认证的条目，按“是否挂 docker.sock／是否可执行命令”排序。
- **第 31–60 天**：收口。模板改造（绑定回环、认证必填、禁止匿名 admin、不挂 sock）；控制面组件移到管理网；为每个实例打属主与到期标签；把“暴露端口数”和“无认证控制面数”纳入 SLO 报表。
- **第 61–90 天**：验证与演练。升级 Ray／vLLM／Langflow／Obot 到修复版本，执行“外部复扫＋内部监听器核对”双绿门禁；做一次“控制面被接管”演练，验证从发现到隔离的时间；每季度重扫，防止新模板把默认值带回来。

**第 195 个市场空白（五项）**：① 监听器级资产台账标准；② 控制面安全默认的行业基线；③ 认证中间件的审计清单；④ 升级完成的可验证口径；⑤ 暴露实例的属主与到期机制。

**`exposure.*`／`control_plane.*` 第 162 次无人提字段族**：厂商文档谈“支持认证”，不谈“默认是否开启、匿名用户映射成什么角色、挂了哪些宿主资源”。

**本地 173／173-kb 连续第 150 期成组启用（闪英迪 28：入口收敛与最小暴露，与本期“控制面先关公网”同构）**：本地原型把“监听器台账”做成周更清单，凡是 `0.0.0.0`＋无认证的条目自动开单，超过 7 天未处理升级为事故——把默认值的债变成有到期日的工单。
