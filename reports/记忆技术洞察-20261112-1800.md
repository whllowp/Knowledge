# 记忆技术洞察 · 第 67 期（20261112-1800）：共享记忆的投毒爆炸半径——当"跨 agent 共享"遇上"跨会话持久"

- 期号说明：18:00 档生成；往期 #9 标「共享记忆设计」、#54 标「单 agent 主动投毒」、#59 标「可携带性」、#65 标「信念化」；本期记作**#9 与 #54 的交集专题——共享层的投毒爆炸半径**。与 #9 分工（它管"怎么让多 agent 共享一份记忆"）、#54 分工（它管"单 agent 记忆被单次交互投毒"）：本期管二者的交集——**共享层把投毒从单点慢性病升级为网络传染病，爆炸半径 = 网络规模**。往期未覆盖此轴。

## 一、固定四维

**【发展趋势】** OWASP 2026 把 Memory & Context Poisoning 单列为 ASI06（与提示注入 ASI01 分列）；InjecMEM（arXiv:2608.23471，COLM 2026，上海交大+蚂蚁）证明"单次交互即可种下跨会话后门"；多智能体共享记忆正成 2026 下半年主战场——TencentDB 20k★/90 天推 Team Memory、OpenViking peers、MemHub、dsh 会话广播、ReMe 共享 workspace。共享与投毒因此从两个独立议题合并为一个。

**【技术现状】** 六家都在做"共享/跨工具/跨会话"：TencentDB Team Memory 按 user/role/agent 配 ACL 与私有→团队 scope；Hy-Memory MemHub 10 工具共享一份记忆；OpenViking v0.5.0（10-09）peers 目录隔离；dsh v26092802 分支作用域+会话广播；ReMe v0.4.2.2（11-05）共享 workspace。但**没有一家把"共享层的写入信任边界"做成一等能力**——ACL 管"谁能读"，没人管"写入的这条是否可信"。

**【技术竞争力】** 倒挂延续：论文领先产品。InjecMEM 在 MemoryOS 联合口径 ASR 35.6%（条件 76.6%）、MemGPT 18.1%（条件 48.6%）；WildChat 健康/金融语料条件 ASR 67–71%。常用检索期过滤器（LLM-as-Judge/ProtectAI/PromptGuard）把检索成功率压到 30%+，但条件 ASR 仍 >75%；困惑度过滤要误杀 71.8% 良性记录才有效。产品的"可信"能力（#65 信念化、#46 ECA 门）均不针对共享层被攻陷的 peer。

**【技术挑战】** ① 爆炸半径失控：一条毒记经共享层一次写入、全网可读，且跨会话持久，疫情不随会话结束消退；② 碎片化投毒（五向量之最隐蔽者）跨天/跨渠道（邮件/Slack/代码注释）写入无害碎片，触发时拼成利用，单条无害、单点不可拦；③ ACL 只管读不管写，被攻陷的 peer 仍可在共享库合法写入；④ 跨开源权重族（Qwen2.5）仍可被优化指令命中。

## 二、需求分析

多 agent 协作/团队记忆用户要"经验复用、不重复解释"，但共享层每次写入都是潜在安全事件。用户与运维真正需要：写入信任边界、命名空间硬隔离、记忆使用审计（哪条被哪些 agent 读过）。

## 三、用户旅程

① 某 peer（被攻陷的工具/agent）写入一条看似无害的记忆 → ② 共享层无写入校验，记录入库 → ③ 数天后再由其他渠道补碎片，拼成完整利用 → ④ 多个 agent 在不同任务召回该记录，行为被悄然引导 → ⑤ 无审计、无隔离，只能逐 agent 清理。理想旅程：写入即打 origin_id+风险标签（#1/#46）→ 高价值命名空间硬 ACL 隔离（≠软标签）→ 行为审计追踪每条记忆的跨 agent 送达（#30/#159）→ 一键按命名空间回滚（#60）。

## 四、具体实现方案

1. **写入信任边界下沉共享层**：每条共享写入强制 origin_id+风险标签，ECA 式证据校验门（#46）对跨 peer 写入更严格，可疑进待审队列而非直接入库。
2. **命名空间硬隔离**：用户个性化记忆与团队共享知识用 ACL 物理隔离（TencentDB scope 思路），拒绝"软标签+检索信任"的脆弱组合；OpenViking peers / dsh 分支可作隔离原语。
3. **行为审计与爆炸半径追踪**：每条记忆记录"被哪些 agent、在哪些任务、以什么频次读取"（#159 记忆使用报告），中毒时一键定位并隔离受影响 agent。
4. **跨会话一致性快照+命名空间级回滚**：复用 #60 非破坏版本化，使清毒精确到命名空间而非全库。

## 五、本期新观点

共享记忆的可携性红利（#59）与投毒爆炸半径是**一对不可拆分的孪生**：能跨 agent 共享，就能跨 agent 中毒；隔离不是可选项，而是共享记忆的一等 SLA。单 agent 投毒（#54）代价是"这一个 agent 被误导"，共享层下代价是"全网被误导且疫情不消退"。防御必须从"单点过滤"升级为"写入信任边界+命名空间硬隔离+行为审计"三层——而六家产品目前只在第二层（ACL 读隔离）有雏形，第一层（写入校验）与第三层（审计）近乎空白。
