# 记忆技术洞察 #77（20261113-1000）· 记忆的"处方性整理"陷阱：程序性记忆需要涌现式组织，而非人类预设 schema

**发展趋势。** 2026 下半年，记忆研究重心从"对话事实"转向"程序性/经验性记忆"——把 agent 执行轨迹炼成可复用的动作与恢复策略。范式出现分叉：一派主张"涌现式 wiki 组织"（SoMem 链接文档、WASP-Mem wiki 页、ReMe wikilink 图、OpenViking `ov compile`→wiki），另一派仍用"固定分层 schema"（dsh 五轨、Hy-Memory 8 层、TencentDB L0–L3）。本年新证据正把天平压向前者。

**技术现状。** 程序性记忆此前无统一方法：经验被存成扁平 note 或硬编码流程。WASP-Mem（arXiv 2611.04003, 11-02）首次给出反直觉计量：在 TheAgentCompany 上把执行轨迹与反馈蒸馏成互链 wiki 页，checkpoint 通过率 +4.6–6.1%、存储 −57–61%。但它更关键的发现是——**处方性组织反而有害**：人类预定义 schema + 显式去重规则，性能不升反降；而"人类诊断"（把失败轨迹转成纠正性知识）单轮 > agent 自我判断 4 轮（7.0–10.9%）。这直接挑战"schema 应设计师冻结"（第 28 期）的隐含前提。

**需求分析。** 旧整理观遮蔽三类需求：①研发方要"整理 ROI"——先测处方性规则是否真降错，而非默认去重必有益；②agent 要"可涌现结构"——让记忆按链接自然成团，而非被五轨/八层框死（接第 71 期结构自组织权）；③人类要"诊断权而非设计权"——把稀缺人力投在失败复盘，而非画 schema。AML 七维与五产品零"整理方法 × 性能"对照口径（接第 56/69 期）。

**用户旅程。** 企业流程 agent 反复卡在同一恢复路径。预定义去重把三条等价恢复策略合并成一条，覆盖变窄、通过率下降；改用涌现 wiki：agent 自链成功/失败轨迹，人类仅对"失败→纠正"做单轮标注。下一轮同类任务命中纠正页，通过率回升且存储更省。

**具体实现方案。** ①拒绝处方：关闭硬去重与固定 schema，改用 frontmatter 标签 + wikilink 自然成团（ReMe/OpenViking `ov compile` 范式）；②人类诊断钩子：在失败轨迹落库时自动派发"诊断任务"给人类，单轮纠正优于多轮自判；③可复用经验作一等类型（接 Hy-Memory Working 双层/TencentDB 技能共享），但组织须自下而上涌现；④计量补轴：整理方法 × 通过率/存储曲线进 AML（待验证 340）；⑤深化第 28 期：schema 非"世界观冻结"而是"运行期可涌现结构"。

**技术竞争力。** 五项目分裂明显：ReMe（agentscope）wikilink 图 + `auto_dream` 涌现组织最贴 WASP-Mem；OpenViking `ov compile`→wiki/knowledge graph 次之；dsh 五轨 + 技能自演化属处方派但无去重反直觉验证；Hy-Memory 8 层固化、TencentDB L0–L3 四层均预设结构，经验以"复用经验"静态存放，缺涌现层。竞争焦点正从"记得多准"转向"整理方式对绩效的净影响"。

**技术挑战。** ①涌现失控：无 schema 时记忆可能成团过碎或过粘，需轻量结构约束（待验证 341）；②诊断规模化：人类单轮高质量但不可无限扩展，需把诊断本身做成可复用模板（待验证 342）；③对照缺失：五产品零"整理方法×性能"公开数据，AML 无此轴（待验证 340/343）；④跨工具一致性：ReMe/OpenViking 跨工具但 wikilink 语义未标准化（接第 59 期互操作）。
