# 记忆技术洞察 · 第 83 期（20261113-1700）

## 本期主题：记忆的「可用规模边界」——当无关会话累积、证据仍在却不再可用；把"可扩展记忆"从口号变为可测条件

> 承接 #53 退化（现象）/ #56 评测口径（缺口）/ #73 利用鸿沟（召回→执行）/ #75 反噬·#82 记忆悖论（"更多=更好"），用 2026 NeurIPS「规模条件化评测」(arXiv 2605.07313, camera-ready 10-29) 与 Agent Zero Memory(2608.29606, 95.60% LongMemEval, 引用锁) 刷新；与 #79 决策效用（reader-dependent）/#72 状态化坍缩（horizon）正交——本期管"无关内容累积下可靠性如何条件化衰减、边界在哪"。

### 一、四维洞察

- **发展趋势**：记忆研究从"召回/效用"进一步逼到"规模条件下的可靠性"。2026 NeurIPS 2605.07313 提出 scale-conditioned evaluation：固定任务证据、只增无关会话，记录可靠性随规模如何掉——把"记忆可扩展"从营销话术变成带四个诊断的可测协议；同期 Agent Zero Memory 用"溯源+引用锁"在 95.60% 高位上把质量归因于记忆底座而非模型，标志 scale-robust 设计开始产品化。竞争焦点从"谁记得多准"迁到"谁的可用规模边界更大"。
- **技术现状**：2605.07313 在 LongMemEval/LoCoMo 上跨 flat/planar/hierarchical 三类接口实测，给出四条诊断——预算合规可靠性、尾部记忆调用负担、失效机制分解、可用规模边界。关键发现：①可靠性损失非单一现象；②HippoRAG 守住 2-call 预算却随无关会话增加损失 16–20pp 预算合规可靠性；③LiCoMemory 失效强依赖 reader——Qwen3-8B 超预算、Qwen3-32B/235B 在测试区间仍可靠。Agent Zero Memory 三平行记忆（事件时间线+实体-事件图+引用锁 HDM）+ intent gate + 三路并发 agentic search，八 backbone 准确率仅差 3.4pp、单查询成本差 ~30×。
- **技术竞争力**：六项目（OpenViking v0.5.4.1 / Hy-Memory 2.0.16+MemHub v1.0.7 / TencentDB v2.0.3 / dsh v26092802 / ReMe v0.4.2.2）均未披露"可用规模边界"：OpenViking viking:// 靠子树限定减噪但无规模条件评测；Hy-Memory 8 层/TencentDB L0–L3/dsh 五轨/ReMe wikilink 均未测无关会话累积下的预算合规可靠性；倒挂延续（前沿在论文+Agent Zero Memory，产品缺席）。AML Cycle 2 实时榜（MemoraX ~62 resolved）仍按 A/B/G 列排、无规模条件化维度（接 #56/#69）。
- **技术挑战**：①"规模"本身是缺失变量——绝大多数系统只在固定快照上报告精度，掩盖无关累积下的塌陷；②reader/agent 比 memory system 更主导结果，纯系统横评会误导选型；③四条诊断无标准实现，跨系统可比性弱；④引用锁/溯源这类 scale-robust 设计尚未进入开源产品的默认运行期断言。

### 二、需求分析

常驻 agent 在生产中会持续累积无关会话，团队真正要的不是"召回率峰值"，而是"当历史膨胀到 N 倍时，准确率是否仍在线、是否超预算"。需要一套把可靠性表达为 agent×接口×规模×预算 四元条件的评测与上线契约——且能回答"我的可用规模边界在哪"。

### 三、用户旅程

1. **建库**：固定任务证据集，按 10×/50×/100× 梯度注入无关会话，记录每次查询的轨迹。
2. **诊断**：输出四条曲线——预算合规可靠性、尾部调用负担、失效机制占比、可用规模边界（可靠性跌破目标的规模点）。
3. **选型/上线**：给定本团队的 reader 模型与接口类型，读取对应边界，设 SLA；超界触发降级（裁剪无关、升 reader、或转引用锁只读）。
4. **观测**：把"可用规模边界"与"预算合规可靠性"列为持续监控指标，而非一次性基准。

### 四、具体实现方案

- **规模条件化评测进 harness**：复用 memory-at-scale 协议（GitHub AndyLu666/memory-at-scale），把四条诊断接入 AML 评测列（接 #56/#69），让"可扩展记忆"宣称带条件。
- **reader 作为一等变量**：横评时固定 memory system、扫 reader 模型轴，报告 Qwen3-8B vs 32B/235B 类断层（深化 #72 horizon/#79 reader-dependent），避免"换系统"误判。
- **引用锁做运行期规模护栏**：借鉴 Agent Zero Memory，答案只能引用 reader 实际打开的证据、无证据即弃答，结构上挡住无关爆炸下的编造；可插拔挂到现有 Mem0/图式架构（接 #78 读取裁决/#63 provenance）。
- **可用规模边界 SLA**：以"可靠性跌破目标"的规模点作为产品对外承诺，替代模糊的"支持长记忆"。

### 五、本期权观点（新视角）

①"更多记忆=更好"神话(#75/#82)须由定量边界收口：可靠性损失非单一现象，而是 agent×interface×scale×budget 四元条件，竞争从"谁系统最好"转为"给定 agent+接口+预算下谁可用规模边界更大"。②可用规模边界应成记忆一等 SLA——比召回率更贴生产。③reader/agent 比 memory system 更主导——LiCoMemory 在 Qwen3-8B 超预算、32B/235B 可靠，颠覆纯系统对比（深化 #72/#79）。④四条诊断应进 AML 评测列，C2 实时榜仅 A/B/G、无规模条件化（接 #56/#69）。⑤Agent Zero Memory 引用锁把 #78 读取裁决从"能否分辨"升到"无关爆炸下仍只引真正打开证据"、把 #63 provenance 从静态溯源做成运行期断言，是 scale-robust 设计产品级实例。⑥六项目零可用规模边界披露，倒挂延续（前沿在论文+Agent Zero Memory，产品缺席）；AML 应补 scale-conditioning 维度（接 #56/#69）。
