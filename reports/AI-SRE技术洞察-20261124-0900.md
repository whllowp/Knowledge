## 题眼

前面连续十四期（#294～#310，证据保真、关联键、调查污染、检测来源、事故边界、撤销生效、举证负担、入场保真、知识腐化……）共同做了一件事：把"这一次判断"拆开验真。但整个可举证体系踩在一个从未被验证的地基上——**同一 Agent、同一份证据、同一个事故，再跑一遍，结论还是不是同一个？** 如果答案是否定的，那么审计轨迹只是"一次幸运的采样"，复盘、对账、A/B 评测、根因结论全部悬空。本期把"运行间一致性"立为一等对象。

判词来自 IBM 的 Agent 一致性研究：GPT-4.1 驱动的 ReAct 智能体在 AppWorld 上 Mean@5 达 77.4%，但 Pass^5 只有 53.0%——基准里近四分之一的任务，Agent 有时能解、有时解不了，而任务本身在两次运行之间什么都没变。**第一次成功证明的是可能性，不是运营可靠性。**

---

## 一、发展趋势

**（1）评测口径正从"能力上限"补上"一致性下限"。** 主流榜单长期报 Mean@k（跑 k 次取平均通过率，k 常为 1 或 3），这是"77% 准确率"的来历。最近 30 天，Anthropic 智能体评估指南、IBM ALTK-Evolve、τ-bench 阵营同时推动另一个指标：**Pass^k**——k 次独立运行全部通过的任务占比，衡量"每次都可靠"。两者恒有 Pass^k ≤ Mean@k ≤ Pass@k。腾讯云 Agent 评估专页把这条写进方法论：单次通过率 90% 的 Agent，连跑 4/8/16 次全对的比例会快速跌到约 66%/43%/19%。一致性差距（Mean@k − Pass^k）正成为与能力正交的独立维度。

**（2）"temperature=0 即确定性"的迷思被打破。** IBM 把 Agent 的每个决策分成"尖锐分布"与"平坦分布"：前者概率压在单一 token 上，后者概率摊在几个几乎并列的选项间。即便提示词、模型、工具、解码温度全部不变，GPU 浮点运算的非结合性、请求批处理等平台侧效应带来的微小数值扰动，就足以让平坦决策重排——一个 token 的变化改变 API 选择、搜索查询、工具参数、重试决定，再沿长轨迹累积。

**（3）一致性诊断开始"去重放化"。** IBM 的 Consistency Analyzer 只需在轨迹每个决策点多一次 LLM 调用（默认 k=5 个补全），不需要真实标签，也不需要端到端重跑环境。这让它能跑在生产流量上——而 SRE 场景往往连一次完整端到端事故重放都做不到。

**（4）大厂平台把"可重试"写进架构共识。** 2026 年 3 月 AWS DevOps Agent 与 Microsoft Azure SRE Agent 相继 GA，两者都刻意选择"调查与建议"而非"自动动作"；Rootly 的目标形态是"一个 Agent 起草 PR、第二个 Agent 判断能否安全合并，有风险就叫人"。这些设计的隐含前提是动作可重复验证——恰恰是一致性课题。

## 二、技术现状

**一致性的真正代价落在 SRE 特有的长轨迹上。** 通用聊天机器人吸收措辞波动不改变语义；运维 Agent 则"根据中间选择采取行动"——每一步选择改变下一步可见的信息。一次 P1 事故调查往往有数十个决策点，其中若干处于平坦边界附近，翻转概率沿轨迹累积。结果是：同一份日志、同一次发布、同一个告警，两次 RCA 可能指向不同根因；而按错误根因做的"修复"会引入新事故。

**现有可观测栈无法回答"这两次是不是同一次"。** OpenTelemetry GenAI 语义约定截至 11 月仍是 Development 状态，2026 年 6 月已从主仓迁出到独立的 `semantic-conventions-genai` 仓且尚无发布版本，属性名持续变化（`gen_ai.system`→`gen_ai.provider.name`，`gen_ai.usage.prompt_tokens`→`input_tokens`，`gen_ai.prompt/completion` 直接删除）。当前约定有 `gen_ai.conversation.id` 关联同一会话、`gen_ai.request.model`/`gen_ai.response.model` 双列，但**没有 run_id、attempt_id、replay_seed、采样配置或决策形状字段**——即使把两次运行的 trace 放在一起，也无法判定它们是"同题重跑"还是"两次不同调查"。OTel 官方 Agent Harness 博客展示了用 Weaver 做 conformance 检查、soak test 查内存泄漏，这是 schema 层的进步，但仍不覆盖运行间一致性。

**知识层出现"隔离式记忆"雏形，但无一致性语义。** Rootly 的 Atlas、incident.io 的 Nexus、ResolveAI 的 HiveMind 都是"知识图谱＋记忆＋连接器"三件套。Rootly 实现了激活式记忆（用过才升层）和隔离式记忆（被证伪的笔记进隔离区），这是防止喂过期信息的具体机制；Uber 内部也有被几乎所有 AI 系统共用的知识图谱。但这些记忆写入缺少"该结论在几次独立运行中成立"的戳——本期第 310 期"知识腐化面"指出的"回写假成功即加速腐化"，在一致性视角下有了更精确的成因：一次运行中偶然正确的结论被写成确定知识。

**IBM 给出了可操作的收敛路径。** 在 AppWorld test_normal（168 任务）上，应用"一致性指南"后 Pass^5 从 53.0% 升至 69.0%，一致性差距从 24.4pp 缩小到 12.0pp，Mean@5 反而从 77.4% 升到 81.0%——证明修稳定性不牺牲能力。更关键的是指南可泛化：相似任务 Pass^5 提升 13.0pp，较弱的 gpt-oss-120b 上同任务提升 6.0pp（10.1%→16.1%）、相似任务反超到 8.7pp，说明捕捉到的是可迁移的失败模式而非死记轨迹。工具已随 ALTK-Evolve 开源。

## 三、技术竞争力：主要厂商/方案对比

下表考察各家是否把"运行间一致性"做成可导出的运维对象。"一致性字段"指是否有 attempt_id/采样配置/决策翻转记录；"重放诊断"指能否不做端到端重放就测一致性。

| 方案 | 主要形态 | 一致性指标 | 一致性字段 | 重放诊断 | 一致性指南/修复 | SRE 场景绑定 | 空白点 |
|---|---|---|---|---|---|---|---|
| IBM ALTK-Evolve（研究） | Consistency Analyzer＋指南生成 | Pass^k/Mean@k/差距（开源可算） | 决策点 k=5 补全、翻转定位 | 支持（每点多一次调用，无需重放） | 有，且可泛化、不降准确率 | 无（AppWorld 通用任务） | 未落生产 SRE 事故；无 OTel 出口 |
| Anthropic 评估指南 | Pass@k/Pass^k 方法论＋评估文章 | 概念与公式齐备 | 无（方法论非运行时） | 不适用 | 无自动修复 | 弱 | 无字段族、无平台实现 |
| τ-bench（Sierra 系） | 会变卦的模拟用户＋出错工具 | pass^k 已推广使用 | 任务级、无运维字段 | 需端到端重跑 | 无 | 零售客服，非运维 | 未覆盖长事故轨迹 |
| OpenTelemetry GenAI | span/metric 语义约定＋Weaver 一致性检查 | 无 | conversation.id 有；attempt/seed/决策形状无 | 不适用（schema 层） | Weaver 做 schema conformance | 中（可观测底座） | 全 Development，无 run/attempt 层 |
| ResolveAI | 三代重写（单 Agent→知识图谱→多 Agent） | 公开无 | 无 | 公开无 | 用 Verifier 对冲自我确认 | 强（RCA） | 三代重写动因含上下文腐烂/无记忆，未报一致性数值 |
| Rootly / incident.io | Atlas / Nexus 知识图谱＋激活/隔离式记忆 | 公开无 | 记忆有层无一致性戳 | 公开无 | 隔离式记忆防过期 | 强（事故响应） | 记忆写入不记"几次运行成立" |
| 阿里云 STAROps / AgentLoop | 根因评测集（3 月 58→9 月 838 条，平台 1400+，五维校验）＋反馈回写 | 评测集走 Mean 口径 | 无 attempt/seed 公开字段 | 无 | 回写知识库（可能放大偶发正确） | 强 | 回写无一致性门槛（承 #310） |
| 腾讯 CloudQ / Agent-Trace | 全景图谱＋AIOps 共创，11-03 起 | 公开无 | 无 | 公开无 | 无 | 强 | 一致性未成公开能力 |
| 字节 AgentKit | 11-13 自研评测、11-19 固定 Skill 版本、RCA Harness | 自研评测口径未公开 | Skill 版本固定（部分相关） | 无 | 版本固定≠输出一致 | 强 | 固定版本不等于固定行为 |

**对比结论：** 一致性指标、诊断器、修复指南三件事在 IBM 的研究原型里第一次凑齐，但没有任何一家 SRE 平台把"同一事故重跑 N 次的一致性"做成可导出的运维字段。**能采购到"跑通"，采购不到"次次跑通"的证明。**

## 四、技术挑战

1. **一致性差距与能力正交，升级不解决问题。** Mean@k 上升不意味着 Pass^k 上升，换更大模型通常只抬高前者。运维团队若用榜单均分做自治升级门槛，会把"偶尔正确"的 Agent 放进 write≥act 的高危档。
2. **temperature=0 不是护身符。** 平坦决策＋GPU 浮点非结合性＋批处理扰动足以翻转 token；在数十步的事故轨迹上，这类翻转沿路径累积，且不会在日志里留下"我这次和上次不一样"的痕迹。
3. **重放在 SRE 里昂贵或不可能。** 事故现场已被修复、流量已回滚、外部副作用（令牌、告警、通知）已发生，端到端重放往往不可得。生产流量上"每决策点多一次调用"的轻量诊断是目前唯一现实路径，但它本身引入成本与被观测者偏差。
4. **审计与复盘的前提被架空。** 前十四期建立的可举证字段族，全部默认"证据指向的结论是稳定的"。若结论随运行漂移，则"回滚可举证率""审批可举证率""撤销可举证率"这些治理格子的分子都在抖动——一致性是它们的前置依赖，却被排在治理链最后。
5. **知识回写把偶发正确固化为确定知识。** 单次运行中碰巧正确的根因一旦写进知识图谱或记忆层，下一次调查会把它当高置信先验（承 #310 知识腐化面），形成"不一致→错误先验→更不一致"的闭环。
6. **OTel GenAI 尚未定义一致性语义。** `conversation.id` 无法区分两次重跑；没有 attempt_id、replay_seed、采样配置字段，跨平台的"同题对照"目前只能靠自造私有属性。

## 五、展望与建议

**（1）新增第 232 字段族 `agent.consistency.*`，缺省 `CONSISTENCY_UNVERIFIED`。** 最小字段：`run_id`＋`attempt_id`＋`replay_seed`＋`sampling_config_hash`（无这四个不得声称"已复现"）；`mean_at_k`／`pass_at_k`／`pass_power_k`＋`k`＋`consistency_gap`；`decision_shape[]`（每决策点 sharp/flat）＋`flip_points[]`（跨运行翻转点）；`diagnosis_method ∈ ANALYZER|REPLAY|UNKNOWN`；`verdict ∈ STABLE|FLAKY|UNVERIFIED`。凡 verdict≠STABLE 者，不得进入 write≥act 自治档。

**（2）把一致性设为前十四期所有"可举证率"门禁的前置闸。** 审计、审批、回滚、撤销、知识回写各项治理格，分子必须先过"同题重跑一致性"检验；`consistency_gap` 超阈值时，其余可举证率按 UNVERIFIED 处理，而不是照常计分。

**（3）评测与采购同步改口径。** 内部评测集（阿里 STAROps 838 条根因集、信通院六维基准等）在 Mean@k 旁强制并列 Pass^k，k≥3；采购增加两问——"能否导出同一事故 N 次独立运行的结论分布与翻转点？""是否用不重放的轻量诊断器持续测生产流量一致性？"

**（4）知识回写加一致性门槛。** 结论写进图谱/记忆前，须有 ≥2 次独立运行一致，并带来源事故号、验证者与 `run_id`（承 #310 可回滚回写）；`flip_points` 高频的决策点自动生成"一致性指南"回流 prompt/harness（借 ALTK-Evolve 思路）。

**（5）推动 OTel GenAI 提案。** 向 `semantic-conventions-genai` 提 `gen_ai.run.attempt_id`／`replay_seed`／`sampling_config_hash`／`decision_shape` 四个属性，让"同题对照"成为跨厂商可查询的一等维度，而非各家私有字段。

**（6）本地知识原型（第 187 期新角度）：** 孙鹏《探测式评测管线》首次读作"探测管线要考 Pass^k 而不只是 Mean@k——多次独立运行的一致性才是稳定性本身"；配施宏斌《金融 Agent 开放问题 Eval》"可验证的持续改进须以可复现为前提"、何伟《Harness For Hybrid Coding》"可回退含可重放到同一状态"、刘凯宁蚂蚁 SRE"三分"扩第二十二分"这个结论换个时候、换台机器跑还成立吗"、赵恒"权威来源之外还要有可复现性戳"。
