# 记忆技术洞察 · 第 36 期（2026-11-08 19:00）

**本期主线：记忆的用途分离——一个开关装不下四种去向**

> 前 35 期都在问"记忆能不能做到"：能不能写、能不能删、能不能指认、能不能算账。本期换一个此前从未作为主线处理的前提：**同一段对话进入系统后，去向不止一个**。它可以是历史、被记住的事实、训练语料，或被人工审阅。四者各有法律基础，也各有开关。行业把它们当成一件事处理，于是出现结构性错位：用户以为在选择"记不记"，实际在选择"四件事一起要，还是一起不要"。

---

## 一、发展趋势

**监管先于产品完成了概念拆分。** 11 月初，德国巴伐利亚州数据保护监督局（BayLDA）发布面向 AI Agent 的 GDPR 指引，并把 Agent 列入 2027 年审计清单。文件里有两句此前未被任何监管文本明确写出的话：其一，"把内容存进 Agent 记忆，不等于用它训练模型；合法的记忆使用不能使训练变得合法"；其二，"Agent 记忆需要自己的合法性基础"。同时它明确"Agent 永远不是控制者"，责任落回部署者。这是记忆第一次被当作**独立的处理活动**而非"对话的副产品"来对待。

**产品侧的门是分了一半的。** 截至 11 月，ChatGPT、Claude、Gemini 均已有独立的训练开关与独立的记忆设置。但门与门并不正交：Gemini 的"记住过去对话"依赖 Keep Activity，而 Keep Activity 同时是训练开关——关掉训练，会话 72 小时后删除，长期记忆归零。11 月 4 日 Hacker News 318 票的讨论正指向这一点：付费订阅者与免费用户同条款，没有"只停训练、保留记忆"的选项。

**三类角色同时进场。** 监管在定义字段（用途、保留期、可纠正），产品在补开关，论文在做"物理隔离"（端侧占位符、可逆脱敏）。记忆的合规问题第一次从"删得掉吗"转向"**用途能不能分开**"。

## 二、技术现状

**（1）四门结构与非正交性。** 把一次输入的去向拆开，至少有四道门：历史（history）、记忆（memory）、训练（training）、人工审阅（review）。三家主流产品的现状可以概括为"四门三缺"：

- ChatGPT：训练门与记忆门独立，但《The Algorithmic Self-Portrait》（ACM Web Conf 2026，80 名用户、1,058 段对话、22,971 轮、2,050 条记忆）实测**95.9% 的记忆由系统单边写入**，用户明确要求记住的仅 4.1%。52% 含心理状态推断，28% 触及 GDPR 个人数据定义，7% 属特殊类别（其中健康占 61%）。缺的是**逐条同意**。
- Gemini：记忆门挂在训练门上（Keep Activity）。缺的是**门的独立性**。且人工审阅不受开关控制——被审阅的会话最长保留三年，用户事后删除活动记录也不影响。
- Claude：Memory 独立且 Free/Pro/Max 默认开启，incognito 不入训练。但三家共同的一处旁路是**反馈动作**：点赞或点踩可使整段会话进入训练，即使已全局 opt-out；Anthropic 对已评分会话保留五年。

于是"关掉训练"在数据流上被三处击穿：单边写入（无逐条用途声明）、反馈旁路（一次点击覆盖全局选择）、派生链（巩固与抽象不重新征询）。用户以为自己做了四个选择，实际只有两个状态。

**（2）用 途 标 签 的 缺 位。** GDPR 的用途限制（purpose limitation）要求在采集时绑定用途，之后不得静默改作他用。翻遍主流记忆 schema——TencentDB 的 L0–L3 四层与四类资产（Chat/Skill/Wiki/CodeGraph）、Hy-Memory 2.0.13 的 chat/working/coding 三型、OpenViking 的 `viking://` 三级摘要、Mem0 的 ADD-only——**没有一家有 `purpose` 字段**。这意味着巩固链每一跳（写入→合并→抽象→跨会话→跨用户）都在扩权，却全部沿用最初那一次同意。这是"同意扩张"（consent creep），而非某一次违规。

**（3）监管语言正在变成架构语言。** SciXa 11 月的《Privacy Boundaries in Agent Memory》给了一句可直接当设计原则的话："最小化决定什么东西存在，用途限制决定每条已存在记录被允许做什么。" 它把最小化重新论证为**爆炸半径与未来义务规模的控制**：每多存一条，就多一项将来要响应访问、纠正、删除的义务；过度采集会在巩固阶段成倍制造派生物。这与第 5 期 NPV 账本互补——NPV 里没有"未来义务"项，而它在合规语境下为负且不可摊销。

**（4）删除的两级语义已被量化。** 11 月被广泛引用的 DR 研究（arXiv 2610.21405，港科广与中国科大）用 456 个人工埋设的秘密、5 种记忆设计 × 4 个 LLM × 3 种删除基线做对照，提出 native / residual 双指标与 hidden-risk share：即使由 LLM 主动挑选要删的内容，仍有 **39%–76% 的残留证据可被同一读取模型拼回原貌**。这把第 29 期的"账实分离"从工程问题提升为法律问题——"assistant 答不出来"不等于"记忆已删除"。

**（5）物理隔离路线出现首个可用样本。** MemPrivacy（arXiv 2605.09530，MemTensor/荣耀/同济）在设备侧检测敏感片段，替换为**带类型的占位符**（保留"健康/邮箱/姓名"的语义类别），云端记忆系统在占位符上照常工作，回复返回前在本地回填原值，效用损失控制在 1.6% 以内。它的价值不在精度，而在把"用途限制"实现成了"数据不出设备"——用途分离的硬件化。

**（6）六个指定项目的合规位。** TencentDB-Agent-Memory（v2.0.3-beta.1）已把决策服务做成可插拔，并把 Memory Hub 的 ACL 与团队可见性做成一等能力——**有治理无用途标签**。Hy-Memory 2.0.13（Apache-2.0，1,922★，30B-A3B 约 3B 激活，宏均 55.49、LoCoMo 72.6%、每题 token 1,159→703）走"专用写入模型"路径，恰是把记忆推向参数的路线。OpenViking v0.5.3（AGPL，41.3k★）的 DSH 插件 11-08 更新至 0.5.33，仍是唯一"记忆即文件"方案，可审即可核用途。ReMe 0.4.2.x 的 `dream_cron` 与 dsh-memory-evolve（665★）的夜间自进化，把"派生用途"放到了无人值守时段。ReMe2Ops 仍无独立实体，按 ReMe 运维化路径处理。

**（7）测评市场出现激励层。** Bittensor Subnet 118 的 DittoBench（11 月 8 日快照）把 agent 记忆 harness 做成挖矿标的：综合分 = 50% 工具调用 + 50% 记忆召回，最佳 harness 0.951。这是记忆能力第一次被金融化定价。但它只奖励**可测项**——用途合规不可测，因此不会被挖。AML 二期仍处评测复核，官方口径为 11 月中旬发榜，截至 11 月 8 日未出；一期文本商业榜为 MemoraX 58.02、MemOS 45.89、NTES 44.21，代码轨 62.00 对三家 52.00。

## 三、技术竞争力

用途分离能力正在成为一条独立于"记忆质量"的竞争轴，而且它与质量轴**并不同向**：写入越主动、抽象越深、参数化越彻底，用途就越难分离。下表按五维剖面排列（"—"为未披露或不适用）。

| 方案 | 记忆门/训练门分离 | 逐条用途标签 | 反馈动作旁路 | 删除残留披露 | 参数轨可分离 |
|---|---|---|---|---|---|
| ChatGPT（个人版） | 是 | 无（95.9% 单边） | 有（点赞即入训） | 30 天，无残留指标 | 不适用 |
| Gemini Apps | **否**（挂 Keep Activity） | 无 | 有 | 72h，审阅留 3 年 | 不适用 |
| Claude | 是 | 无 | 有（已评保留 5 年） | 删除后 30 天 | 不适用 |
| TencentDB-Agent-Memory | 企业侧可约定 | 无（四资产分类非用途） | 未披露 | 未披露 | 无权重写入 |
| Hy-Memory 2.0 / MemHub | 本地优先，默认不上传训练 | 无 | 不适用 | 版本链留被撤回版 | **冲突**（写入模型） |
| OpenViking 0.5.3 | 自托管即分离 | 无（靠目录语义） | 不适用 | 文件级可 diff | 无 |
| Mem0 开源 | 自托管即分离 | 无（ADD-only） | 不适用 | delete 后 history 仍留原文 | 无 |
| MemPrivacy（论文） | 端侧闸门 | **按敏感类型** | 不适用 | 占位符可逆 | 不适用 |
| BayLDA 指引（基线） | 要求分离 | 要求具备 | 未涉及 | 要求可纠正可删 | 要求单独论证 |

三点判断：

**能力与合规反向。** 表中最右一列是分水岭。Hy-Memory 把记忆写入交给专用 30B 模型，TencentDB 走决策服务，二者都在提升写入质量；但只要写入器的输出可能回流到权重，用途分离就在物理上失败。**参数轨不是技术路线选择，是合规路线选择**——这也给第 2 期"参数轨注销全失能"补上了法律定性：不是工程缺陷，是用途越界。

**最强的用途分离实现仍然不在记忆产品里。** 这是本系列第二十七次观察到同类倒挂：端侧脱敏（MemPrivacy）、最小化论证（SciXa）、双指标删除（DR 2610.21405）三项最硬的工作全部来自论文与合规研究，产品侧只做到"补一个开关"。

**企业侧与消费侧在分道。** TencentDB 这类企业产品的合规位靠合同与 ACL 补齐（部署者即控制者，与 BayLDA 的责任归属一致）；消费侧则只能靠开关，而开关已被证明是非正交的。同一技术，两套治理，差距会随审计常态化而扩大。

## 四、技术挑战

**其一，集合级动作缺位。** 删除是条目级动作，用途限制是集合级动作——"停止一切以训练为目的的处理"要求按用途扫全库、连同派生物与副本，而当前所有实现只能按 ID 逐条删。这不是接口没写好，是数据模型里没有"用途"这个维度，扫不出来。

**其二，派生链不可回溯到用途。** 一次巩固把 20 条会话压成 1 条摘要，摘要的用途集合是 20 条用途的并集还是交集？无字段可答。第 34 期指出巩固的四道判断皆不可逆，本期补一句：它们同时也都不可**授权**。

**其三，反馈旁路无法在架构层关闭。** 点赞是产品增长指标，训练是合规约束，二者在同一个按钮上。只要反馈通道存在，全局 opt-out 就永远可被单个用户动作击穿，而这恰恰无法用权限系统解决。

**其四，用途不可测，因此不进评测。** AML 的契约只固定 Add 与 Search 两个接口，参评系统无需声明"这条记忆为什么被存、允不允许用于训练"；DittoBench 只奖励召回与工具调用。**口径缺口第二十八次**：一个维度只要不进评测合同，就不会进产品路线图。

**其五，责任与能力错配。** BayLDA 明确 Agent 不是控制者，责任归部署者；但记忆的抽取策略、巩固调度、单边写入比例全由模型厂商决定。能力方不担责、担责方无能力，这是第 8 期"裁者缺位"的法律版本。

## 五、展望与建议

**预判一：`purpose_scope` 与 `learn_eligible` 会在 6–12 个月内进入 schema。** 前者声明这条记忆为哪一用途采集，后者是布尔位，回答"是否允许进入任何形式的学习（训练、蒸馏、内化）"。二者成本极低，却能让"按用途停用"从不可实现变为一次索引扫描。第 28 期说"留白即债务"，这两个字段就是当前最大的一笔。

**预判二：审计会先于评测到达。** 2027 年审计清单已经点名 Agent，企业采购会先要求"能按用途停用 + 能给出残留率"，而不是榜单分数。这与第 6 期"采购变量从看分转向看插座"是同一条曲线的下一段：从看插座，到看门。

**预判三：本地优先会成为合规的默认形态。** 不是出于隐私偏好，而是因为"数据不出设备"是唯一不需要在服务端证明用途分离的实现方式。

**给厂商的三条建议：** ① 把"逐条用途"作为写入 schema 的必填位，而不是事后标注；② 在巩固前做用途交集检查，交集为空则禁止合并——这是唯一能阻断同意扩张的位置；③ 公开 residual 残留率，把它做成和时延一样的常规指标。

**给采购方的三条问法：** ① 关掉训练，记忆还在吗？② 点赞会让这段会话进训练吗？③ 删除后残留可还原率是多少、谁测的？
