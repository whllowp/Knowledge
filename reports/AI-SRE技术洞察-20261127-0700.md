# AI-SRE 技术洞察（第 328 期）· 决策可复演面 / Decision Replay Integrity
## 「同一份证据、同一起事故，把 Agent 重跑一遍——它还会给出同一个根因吗？」

> 期号说明：`date` 取 2026-11-27 07:03→0700 档；本实例上一期 327（05:00 升级分诊面）顺延 328；主线第 281 个全新立面；字段族 249；本地连续第 204 期。

**题眼**：行业已能把 Agent 的一次运行「录下来」——trace、span、工具调用、会话历史都在导出；但复盘里那句「Agent 判定根因为 X」，记录的只是概率采样的一次结果，不是可被复核的决策。看得见「决策被完整记录」≠看得见「把同样证据再交给它一次，它还会做同样决策」。本期首次把**决策本身的可复演性**立为一等运维对象：与 #105 现场面/重放参照面（快照与真实续跑分叉）、#176 决策质量面（决策好坏 SLO）、#286 证据托管面（记录能否被作者改写）、#296 底座漂移面（请求模型是否等于服务模型）、#298 回滚面（副作用是否撤销）、#319 判定函数面（谁定义失败）、#321 结论汇聚面（竞争结论谁收口）逐条划界：那些立面问记录、参照、裁判与执行，本期只问——**决策函数对同一份证据的输出是否稳定、这个稳定性有没有被计量、有没有被门禁**。

## 一、发展趋势

**趋势一：可观测性从「记录一次运行」升级为「重建一次运行」，但重建的是动作序列，不是决策。** Sandscale 11 月工程文章给出最清楚的分层：环境（镜像 digest）、依赖（lockfile）、仓库状态（commit SHA）、输入「能钉的都钉」，模型 ID/版本/temperature/提示词版本「部分能钉」，模型输出、工具调用序列、命令与退出码「记录但不能保证复现」。其关键方法是将每步工具调用与返回存成脚本，在全新沙箱重放：结果一致，说明差异来自模型或外部世界；结果不同，说明环境漂移了。这是重要反转——**重放不再只是「看回放」，而是充当归因实验的对照组**。火山引擎 11 月「Agent 轨迹」正式进入 AI 应用监控，记录完整执行过程；但定位仍是「记录并展示」，未把「同证据重跑一致性」列为指标。

**趋势二：非确定性第一次被主流云厂商写进 Agent 评测的一等公民。** AWS 2026-11-12 Agent DLC 官方博文把一次性测试失效归结为三个属性：非确定性（每样例跑 k 次、评分布而非单次结果）、提示词即源码（提示词版本化并附每次 eval 记录）、外部漂移（对基线定时重评）。开源侧 tau-bench 提出 `pass^k`（同一任务 k 次试验全部成功的概率）对抗 `pass@k`（k 次里至少一次成功）——前者才是无人值守生产需要的口径。常被引用的对照：`pass^1` 达 90% 的系统，五次全对只有约 59%。Google《SRE》第二版（11-15 InfoQ 访谈）把「非确定性模型输出」与 GPU/TPU 集群并列为「为 AI 做 SRE」新对象——Web 服务返回 5xx 能进错误预算，模型在服务正常时自信答错，可用性指标识别不了。

**趋势三：治理侧开始要求「可审计」，但还没有要求「可复演」。** 中国信通院在腾讯全球数字生态大会给出运维智能体五项要求——数据可信、流程贯通、权限可控、过程可审计、结果可评价——并推出六维《云上 Agent 基准度量模型》，建议分阶段落地、保留人工接管兜底。这是目前最完整的国内框架，但「同一事故重跑两次是否给出同一根因」在其六维中没有对应格。

## 二、技术现状

**已可采购的部分**：轨迹导出与集中治理（Anthropic 原生 OpenTelemetry 于 11-03 进入 Databricks MLflow Public Beta、写入 Unity Catalog；10-14 起开放更广泛原生追踪；自托管 Claude Managed Agents 于 11-12 私测，控制面与模型面拆开，PostgreSQL 保存会话、事件与 checkpoint，OTel 导出 span/agent/generation/tool/session 事件）；状态外置（OpenAI Performance Factory 用 `config.toml` 状态机与 Markdown 阶段提示词，把状态保存在任何单一 Agent 上下文之外）；对抗复核（OpenAI 另起独立 Codex 会话专门反驳初步诊断、检查反事实，据 VentureBeat 11-19 报道会打回约 25% 初步诊断）；确定性门禁（FAIL_TO_PASS 容器判分、AST 轨迹不变量、`pass^k`）；异常检测（Google AAD 于 11-17 公布在五项非 Google 编写的公开基准上捕获 87% 有害指令且不增加执行时延，方法为分析 OpenTelemetry 追踪与日志识别目标劫持和工具滥用）。

**仍空白的部分**：上述能力都在回答「记录了什么」「动作对不对」「结论好不好」，没有一个把**决策稳定性本身**做成可导出字段。OpenAI 官方承认早期 Agent 常在第一个「看起来合理」的解释处停下；100 份根因建议人工抽检准确率 70%，30% 需细化或未充分确立因果——但没有披露「同一起回归重跑十次会得到几个不同根因」。这是本期关键提问：70% 是**裁判给这一次打分**，不是**同一证据重跑的分布**。社区已有朴素解法——同一 case 连跑两次、打全程日志、diff 找出最早差异行；并把一致性治理理解为给关键路径分配「确定性预算」。但这些仍是个人经验，不是运维一等对象。

**判读**：把「记录—外置—治理—复核—判分」做满的厂商已接近全覆盖；把「同证据重跑的一致性、首次分歧点、复演者是否独立于作者」写进产出的，七家全空。这不是批评某家缺功能——它反映共同的建模缺口：**行业把决策当成一次性事件，而不是一个需要被测量方差的函数**。

## 四、技术挑战

**挑战一：快照可复演不等于决策可复演。** #105 已证明五份哈希一致的快照互相一致 24/24，却与真实续跑在 9/24、20/24 上分叉。到了决策层更尖锐：即使环境、依赖、输入全钉死，模型采样、MoE 路由浮点累积、并行工具返回顺序、记忆压缩摘要、长上下文注意力落点都会让同一次调查走向不同分支。把 `temperature=0` 当确定性保证是常见误判。

**挑战二：过度锁死与放任自流的对称陷阱。** 若用精确序列断言强制工具调用顺序，更强模型找到更短路径就会被判失败，重演 SWE-bench 验证器悲剧；若只看终态通过，则可能奖励作弊——改断言、注释边界用例、绕过前置校验。正交原则是：Outcome 判定「任务是否做成」，Transcript 审计「过程是否合规、无作弊」，后者检查不变量（未改只读目录、未越权调高危写工具、高风险操作前完成审批）而非硬编码唯一路径。

**挑战三：归因模糊与变量隔离。** 表现变化可能来自换模型、改提示词、工具 Schema 变化、知识库漂移中的任何一个；同时动几个变量，重跑差异就无法归因。严谨做法是「双跑对比 + 变量隔离」：怀疑哪个环节就锁死其他环节单独测，必要时裸调模型。

**挑战四：裁判自身的非确定性。** LLM-as-a-Judge 有位置偏置（约 14%–22%）、冗长偏置（约 18%）；带思维链的裁判提示词在五次相同评测中对边缘样本有约 6.8% 翻转率。若裁判与被测同源，「重跑一致性」只是同源偏差的自我确认——这与 #321 收口权问题是同一病灶在复演维度的投影。

**口径边界**：Google 87% 为厂商自测第三方基准口径；OpenAI 1700+/600+/70% 为内部计数与 100 份人工抽检，25% 打回为媒体转述；腾讯云「复测评估」为产品描述；`pass^8` 衰减数字来自 tau-bench 零售工作流而非 SRE 事故；厂商分母不同不可相减。上述数据用于说明机制，不作跨厂商排名。

## 五、展望与建议

**新观点**：可观测性的下一站不是「更完整地记录决策」，而是「让决策成为可复演、可计量方差、可由独立方重跑的函数」。记录的决策是证词，可复演的决策才是证据。**同证据重跑的一致性，是比「这一次答对了」更高一阶的可信度**。当模型每次都在变、工具与知识库都在漂，唯一稳住的不能是答案，必须是判据与重跑方法。

**建议一：新增第 249 字段族 `decision.replay.*`**（最小十项）：`evidence_snapshot_ref`（trace + 指标 + 日志 + 拓扑 + 变更记录哈希）、`environment_ref`（镜像 digest、lockfile 哈希、repo SHA、工具版本）、`model_pin{model_id, version, temperature, seed, prompt_version, tool_schema_version}`、`run_count n`、`decision_distribution`（n 次根因/处置分布）、`decision_agreement_rate`（众数占比）、`pass_k`、`first_divergence_step`（双跑 diff 首次分歧的工具调用）、`determinism_budget`（关键节点确定性等级）、`replay_actor ≠ decision_author`，判据 `verdict ∈ REPLAY_STABLE | REPLAY_DIVERGENT | SNAPSHOT_ONLY | UNVERIFIED`，缺省 **DECISION_REPLAY_UNVERIFIED**。与 #310–#327 门禁叠加：`verdict` 非 `REPLAY_STABLE` 时不得计入「已独立复核」合规声明、不得作为自治升档依据。

**建议二：四条最小动作**。（1）事故记录里每个关键决策附证据快照指针 + 模型钉版信息，让复演有起点；（2）高危决策强制双跑，diff 定位首次分歧行并作为治理重点，分歧未解释前标 `REPLAY_DIVERGENT`；（3）把「确定性预算」写进设计评审，明确哪些节点必须结构化输出/投票聚合/缓存、哪些保留采样空间，一致性测试纳入每次 prompt、模型、工具变更的发布门禁；（4）重跑者与决策作者至少一维异源，裁判技能包钉 SHA 入审计（承 #83/#99/#321）。

**建议三：采购三问**。「导出的轨迹能否在隔离环境按记录的命令重放，而不是只能看？」；「同一起事故重跑 n 次给出不同根因时，产品会不会报警并给出分歧步骤？」；「复演者能不能不是原决策作者？」——任一答不出，该产品只提供记录能力，不提供可复演能力。

**建议四：评测配对题**。构造同一证据包的 A/B 两版（A 钉全部可钉项、B 保留已知漂移项）各跑 n 次，报 `decision_agreement_rate`、`pass_k`、`first_divergence_step_hit_rate`；再注入温度扰动与工具返回乱序，检验 `verdict` 是否从 `REPLAY_STABLE` 正确翻转。建议信通院六维模型补「决策可复演率」格，与 #316 审批格、#317 授权格、#318 空窗格、#319 判定格、#320 自伤格、#321 收口格、#326 接管格、#327 升级格并列。

**下期候选**：`decision.replay.*` 的 OTel genai 提案与门禁最小实现／双跑 diff 首次分歧定位器／确定性预算表模板／`pass^k` 事故决策可靠性门／重跑者异源校验器／信通院补格。
