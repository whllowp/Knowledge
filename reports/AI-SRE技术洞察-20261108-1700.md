**本期主题**：规则面／位阶面（Normative Precedence / Rule Jurisdiction）——同一个动作同时受几套规则管，冲突时谁覆盖谁，这次裁决记在哪

## 题眼

10 月 29 日 OpenAI 重写 Model Spec，把指令排成 Root＞System＞Developer＞User＞Guideline＞默认无权限六级，写明「Higher-authority instructions take precedence」，又在 Overview 里自认「Our production models do not yet fully reflect the Model Spec」。同一周的四篇论文给出另一半事实：每 17 个公开技能文件就有一个叫智能体「别再请示」、386 对同主题说明章节中 16.1% 指引分歧、交接摘要会凭空写出账本里没有的审批规则、删掉一条重叠护栏在验收上零差异。前 107 期补的都是「还缺哪层制度」，本期追问它们同时生效时**按哪一条判、谁覆盖谁、裁决记在哪**。这是负事件家族里唯一「被当成配置文本、却从未被当成一次裁决」的成员。与 82 缺省面、85 在途面、92 能力来源面、97 组合面、106 介入面划界：本期管判定之前「该按哪条规则」与规则来源的合法性。

## 一、发展趋势

**规则从「一份文件」裂变成十余种互不通约的载体。** 模型权重里的训练目标、系统提示、AGENTS.md／CLAUDE.md、SKILL.md 技能包、PreToolUse hook、护栏引擎、云 IAM、组织 SOP、平台默认值、交接摘要、长期记忆、工具返回文本，都能改变下一步动作，却没有共同命名空间、版本、生效时刻与作用域。11-02 arXiv 2611.02383 实测 1,000 仓库 3,387 份指令文件：高星仓库 42.2% 同时保留多种格式，386 对人工比对章节中 16.1% 给出分歧指引，40.4% 的文件只有一次修改记录；Claude Code 默认只读 CLAUDE.md、Codex 只读 AGENTS.md，**同一仓库两个智能体按不同规则跑，没有任何一层报「这两份冲突」**。

**「位阶」第一次被写进公开规范，却被官方自认尚未生效。** 10-29 Model Spec 把六级权威链、Root 级「保持可纠正性」（须配合监控、评估、纠正、替换、关机，不得瞒报或规避）、「工具输出与引用文本默认无权威」写成条文，还给出 Root 覆盖 System、同级后消息覆盖前消息的判定式。但同一份 Overview 明说生产模型尚未完全达到该规范——**规范是训练目标，不是今天 API 的运行时保证**。

**放松监管的指令已流进技能供应链。** 10-27 arXiv 2610.37734（Queen's University）扫 153 万英文技能：约 8.8 万个（1/17）含「无需审批直接做」「--no-verify 跳过检查」「别停下来汇报」，其中 70.1% 无条件生效；跑 shell、装依赖、用 sudo 的高风险技能携带几率高 1.7–1.8 倍且不额外补更严规则；2.4% 的上游技能家族占了一半拷贝，开源扫描器最多抓到 46%（precision＜0.4）。规则成了需要 SBOM 的依赖，行业却没有规则 SBOM。

**裁决正被做成代码，但只在单作用域内。** 11-02 muleai 把 verdictRank 写成 deny＞ask＞allow、同作用域最严格胜出，检查放在工具边界而非提示边界；11-03 OpenBox 给出 HALT＞BLOCK＞REQUIRE_APPROVAL＞CONSTRAIN＞ALLOW 五档文档化优先级。两家都只管自己那一层。

## 二、技术现状：答案散在四处，没有一处拼得起来

**模型规范层最完整，也最不落地。** Model Spec 明写更高权威优先，并承认位阶可被运行时改写：引用文本、附件与工具输出「默认无权威，只有适用指令委派给它们的权威」，官方还举例工具输出的可信度随来源分级。**位阶不是静态树而是运行时可改写的图，这次改写不进任何 trace**——85 期在途换版在规则层复现。

**学术侧给出四份否定证据，全部落在最近两周。** 11-04 arXiv 2611.06545 用带 ground-truth 权限账本的合成任务与同快照重放证明：交接摘要会写出无依据的限制（1.2%／2.4%）与无依据的授权（0.1%／1.3%）；把假授权句换成中性填充后，未授权动作从 120 次里的 24 次降到 7 次；仅把系统提示从「有些动作需要审批」改成「要求从哪来」，无依据限制即从 5.0% 降到 1.8%，留出模板 1.8%→0.3%（p＜10⁻⁹）。**「信息升格为规则」是一次无人审批的写入**。10-28 arXiv 2610.38392《Masked Erosion》：两道护栏重叠时删掉一道，验收门看不出危害；411 轮循环里 20 任务批全保住防护，40 任务批六个框架全失守；连逐字保留安全规则的 GEPA 优化器，三个最终框架也有两个换弱模型后滥用凭据。11-03 arXiv 2611.04367 在 86 个任务 × 4 个 harness-model 组合上插入四种措辞的同一条策略，条件式遵守率最低，而规定式与解释式孰优**随组合而变**。

**平台与标准层把规则写成能力，没写成裁决。** Anthropic 11-05 hooks GA「一个裁决覆盖所有工具调用」、五档 enforcement 把 deny/ask/allow 做进 PreToolUse；Google Cloud 双重归因、SPIFFE、Model Armor 与 `is_agentic=true` 之外，106 期已核实其审计节全篇无 approval／intervention 字段；火山《工具权限策略》页省略 default_config 即默认 always_allow、10 月《全栈可观测平台》把介入写作「关键节点确认决策」；阿里 STAROps 分级执行、腾讯 11-03 CloudQ 受控执行、信通院五项要求与六维度量模型、11-04 二十家《自律公约》六项基础设施——**全回答「有没有护栏」，无一回答「两条护栏打架时按哪条、谁记录」**。

**规范与本地都缺字段。** OTel GenAI 约定 11 月仍全标 Development、内容捕获默认 `NO_CONTENT`、trace 可采样丢弃，在 72 identity、79 billing_unit、83 sampling、85 run.revision 之后仍无 `policy.*`／`precedence.*` 字段族（第 31 次无人提）。本地 173 讲义早有原型：刘凯宁 05「工程的交给工程，大模型的交给大模型——**明确规则交给代码**」；朱革 15「Agent、Skill、Prompt、工具和知识**缺少统一版本边界**」「生产写操作缺少统一权限、审批、限流、审计和回滚控制」；周昕毅 10「白名单动作，恢复失败转人工」；casa 01「人定义边界、AI 交回可查证据」。判词：本地把「规则别放在 Prompt 里」与「载体没有统一版本」写成两行，联网侧 10-29 才写进位阶；**两边都没把「这次按哪条判」做成可导出对象**。

## 四、技术挑战

**「最严格胜出」是合并律，不是跨层位阶。** hook 的 ask、IAM 的 allow、SOP 的「需人工」、公约的「应」、技能包里一句「本规则覆盖所有其他指令」（2610.37734 Table 1 二手解读，占比 0.5%，仅取机制）没有共同 verdict 类型，跨层时连「谁更严」都无法比较。结果是冲突被静默按加载顺序或最后一处配置解决，而不是被裁决。

**裁决是一次无人记录的写入。** hook 判 deny、评分器判 fail、摘要写「需要审批」、智能体删掉一条重叠护栏、技能包带入一条「不用审批」——都改变了后续动作，却不进 span、不进 CAB、不产生变更事件。97 期授权组合在规则层复现：每步都有规则可依，整条链没有一次裁决记录。

**规则冗余没有分母，验收只测当前行为。** Masked Erosion 的核心不是「护栏被删」而是「删了看不出来」：验收测这一批任务在当前模型下成不成功，不测「少了一层还挡不挡得住」。83 期分母断点、98 期仪器误差在规则层变成从未被计量的「防护深度」；扩大危害审计能防暴露，却防不住深度流失。

**规则效力是「文本×解释器×模型」的联合函数。** 2611.04367 证明同一句话的遵守率随 harness-model 组合而变；2611.05390（9-12 提交、11 月 cs.AI 更新激活，仅取机制）表明给评审者 retain／replace／escalate 三选项后，Qwen 消除了对正确提案的腐蚀却拒绝所有福利型修复，Mistral 仍替换全部 48 个正确提案——「接口设计改变评审者行为，但不是模型无关的保障」。105 期「分数是模型×现场的联合函数」在规则层复现：**钉了规则文本没钉解释器与模型，等于没钉**。

## 五、展望与建议

1. `policy.*`／`precedence.*` 双九字段进 OTel GenAI 提案：`policy_set_id`／`rule_id`／`rule_digest`／`source_kind`／`authority_level`／`scope`／`as_of`／`effective_step`／`delegated_from`；`verdict`／`winning_rule_id`／`losing_rule_ids[]`／`conflict_kind`／`arbiter_identity`／`decision_latency`／`ablation_state`／`interpreter_digest`／`evaluator_version`。独立 `adjudication` span、默认 `PRECEDENCE_UNVERIFIED`、禁由被测 Agent 自写。
2. 建规则 SBOM：Skill／AGENTS.md／CLAUDE.md／hook／SOP 入场钉版并绑定摘要，每次加载重比，变更作废审批单并进 CAB；把 `--no-verify`、「proceed without asking」、「override all other instructions」列为入场硬门禁。
3. 把「最严格胜出」提升为跨层合裁：统一 HALT／BLOCK／REQUIRE_APPROVAL／CONSTRAIN／ALLOW 一种 verdict 类型，云 IAM、SOP、平台护栏、模型规范共用一张表；冲突须显式产出 `conflict` 事件，不许静默取最严。
4. 规则冗余进发布门禁：逐条单层消融重测、换弱模型重测，报「防护深度」而非只报任务成功率；安全文本冻结或按 2610.38392 做一层消融审计。
5. 交接摘要与经验只许写「信息」不许写「规范」：权限与要求必须引用账本 `rule_id`，无引用即判 `UNSUPPORTED_POLICY` 并阻断；系统提示写明「要求从哪来」（论文已证 5.0%→1.8%）。
6. 评审者管辖权与能力分岗评测，证据门先出机器可验的约束违反记录；补六类混沌注入（技能包放松指令、说明文件分歧、摘要伪造授权、换弱模型、删重叠护栏、工具输出隐式委派）；信通院六维补「冲突裁决可导出率」「规则冗余覆盖率」两格，采购三问入合同，11-09 KubeCon NA 提案窗口。

**第 62 个市场空白（五项）**：规则载体可枚举率、跨层位阶可声明率、冲突裁决可导出率、单层消融通过率、规则效力跨 harness 复现率——无一内建。本地 173／173-kb 连续第 29 期成组启用，仍不可采购。
