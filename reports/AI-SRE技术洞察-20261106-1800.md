## 一、发展趋势：可恢复性被写成前置条件，产品仍把它当补救

**学术与监管侧把「退得回来」放到了动作之前。** IBM 的 Saurabh Jha 假设被 NeurIPS 2025 接收：**每个提议操作必须可撤销，不可逆操作将在运行前被拒绝**；2026 年 8–9 月 AgentRewind、Planarian、ChronoMem 与 EvoUndo 把恢复显式化并融进运行时；2026 年 5 月澳大利亚信号局联合 CISA、NSA 的指导方针把回滚机制与人工控制点列为**安全要求而非便利功能**。判词：**研究侧写成门禁，产品侧写成按钮**。

**标准侧第一次把可逆性写成自治准入变量。** 信通院云大所《迈向 Agentic Ops》直认「批量操作、高风险指令和**不可逆变更**可能扩大局部偏差的影响范围」，要求「自治范围不能仅依据模型能力确定，还应综合考虑**动作可逆性、影响范围、恢复手段和验证结果**」「设置风险窗口、步骤预算和**自动撤销机制**」「高风险、跨域和不可逆操作仍需保留人工确认」。但标准问的是「有没有保留撤销」，不是「**这一步是不是已经过了不可逆点**」——与 89 期同构：**上线的是动作，不是状态**。

**落地侧把可回退性做成职责分级依据。** 11-03 腾讯云大会搜狐畅游「按动作影响范围、**可回退性**划分人机职责」（22 个智能体、3.9 倍、3.1 倍）；11-06 甄选稿「**失败能否回滚，得拿真实单据试**」；嘉为蓝鲸秋季发布把「快照留存及**回滚冲突检查**」「统一记录发布及**回滚过程**」写进发布中心。判词：**回滚被做成发布侧工程能力，不是运行时动作的可撤销性**。

## 二、技术现状：一个「退」字，七种口径

**① 四种动作四种退法，审批单只有一格。** 可逆（恢复旧值）、可补偿（第二笔反向动作，**第一笔仍留在账上**）、可见但可更正（人已读过）、不可逆（已发邮件、已结算支付、无备份删除，**唯一控制是执行前拦住**）。题眼：**"A refund is not an undo. It's a second payment in the opposite direction, with its own fees, timing and failure modes."** 补偿是第二笔写，账上两笔不等于零。

**② 不可逆不是属性，是一个时间点。** hold→spend、draft→send、pending→settled：同一工具在 commit 前可撤、后不可撤，而这个 **commit boundary 不在任何 span 里**。权限范围也与可逆性无关：PocketOS 事故中 Claude Opus 4.6 在 Cursor 内经 Railway 删生产库，那张凭证本用于管域名——**最小权限挡不住不可逆**。

**③ 默认 trace 记下删除成功，却没记删了什么，更没记怎么放回去。** OTel GenAI 的 command execution span 给出 `execute_tool bash rm`、`process.executable.name=rm`、`process.exit.code=0`，而 `gen_ai.tool.call.arguments` 与 `result` 均 Opt-In、`CAPTURE_CONTENT` 默认 `NO_CONTENT`；11-02 仍全 Development。结论是「a default agent trace records that a destructive action happened, without recording what the action was」——86 期「业务结果不在 span」推进为**不可逆点的对象与恢复入口都不在 span**。

**④ 快照不是回滚：回的是进程，不是世界。** LangGraph time travel 官方文档明写检查点后节点会**重执行 API 请求并可能产生不同结果**。10 月 arXiv 2610.28934（205 任务×6 模型）：备份失败有 **75.1% 是「备份了但保留太少不足以恢复」**；删 116 封邮件前的导出含全部正文与头却**只记了附件名字和大小**，浏览器任务删评论后**其他用户的作者、时间戳、ID 与分数无法写回**。AgentRewind Docker 模式每步快照整容器、回到后悔动作前，**状态相似度仅 29.4%**（后悔态常在容器外），代价 12.4 GB／45 快照；事后恢复每次 859s+265s、1.1M token（$6.7）。判词：**不可逆的边界不是「能不能删」，是「删了之后能不能把别人写的东西放回去」**。

**⑤ 叫停 ≠ 撤回。** OpenAI 监控指导自认「an action can finish before asynchronous monitoring identifies a concern」「Canceling a queued step or terminating a process prevents future work, but does not retract a completed file write, API request, message, deployment, or database transaction」。Google《SRE》要求「Any action performed by an agent must be **highly interruptible**」，Red Button 挡的是**未来的动作**——**可中断不等于可撤销**。

**⑥ 撤销自己也是一次动作，且可能销毁证据。** 10 月 saga 工程稿要求每个正向写在 step record 里同时登记 `compensate` 载荷、「Never rely on the LLM to invent undo calls under stress」，并设 `compensate_failed` 一等状态；共享分支须用 revert commit（改写历史会把事件从评审者眼前抹掉）；另有**宽回滚连带移除期间安全补丁**之险。撤销因此需要幂等、独立读回、副作用回归与终止判据。

**⑦ 同一产品内，两条更新路径的可逆性不对称。** 火山 AgentKit「修改技能版本」支持升级／**版本回退**／灰度验证，「更新技能代码包」文档却明写「**覆盖后无法通过页面回滚**」。同一产品两条路径可逆性相反，不可退的恰是整体覆盖这条常用路径，**平台没有统一标记哪个动作越过不可逆点**；且回退的是**资产定义版本**而非运行时副作用（85 期复现）。

## 四、技术挑战：第四十五个市场空白

**五项指标无一内建**：可逆性分类覆盖率、commit boundary 可导出率、补偿入口登记率、撤销后读回一致率、`revert_rate`／`undo_rate`。后两者尤其反讽——Hex 把撤销做成数据飞轮（「用户每次按下撤销，都在免费标注智能体哪里做错了」），指标清单里已有 revert rate／人工推翻率，**却无一进默认大盘**。承接 73 沉默免费、80 重复免费、81 补全免费，本期是**「撤销免费」：用户付了成本，平台零科目**。而把不可逆动作交给「人工确认」，恰恰交给一个已被证明会退化的闸门：审核者抓出危险命令的比例从约 17% 降到 50 次提示后约 5%，批准率 3 月 93% → 8 月 97%。

**本地 173 / 173-kb 连续第十二期成组启用，升级为「可逆性治理原型」。** 周昕毅 10 是题眼：「**人工负责：跨业务影响与不可逆动作**」「动作必须受控，失败能够熔断或回滚」「**03 工具：动作标准化、幂等化、可审计、可回滚**」「恢复失败转人工」。余锦泽 03 更完整：「**可撤销 可审计；基线不改写；撤销移除编辑日志末条**」「**撤销后，各读取面同步复原**」「一致性测试：写入 → 断言每个读取面 → 撤销 → 再次断言」＝86 独立读回在撤销层的原型；最硬一句是「前提被否决时一并撤回已实现；**推理结论撤回尚未实现**」——**本地讲义公开标注了撤销边界，联网侧 10 月还在把「有 undo 按钮」当作覆盖完成的证据**。何伟 02、casa 01、朱革 15、刘杨 08、快手 04「**不可逆的债**」补全。判词：**联网侧才把「撤销键」当新闻，本地早把可回滚列进工具标准化四项、把不可逆动作划归人工**；仍是项目内约定，不可采购。

**与往期交叉全是空白格**：80 幂等、84 as-of、86 独立读回、88 撤销权归属、89 降级、90 唤醒重检。风险：本地 LLM 智能体可在提示下**删除或编辑自身执行日志**，恢复账本须在智能体控制之外；12.4 GB、859+265 秒与 $6.7/任务使撤销成为纯支出，而按 AI Action 计费仍把「已修复」记成收益（79 期）。

## 五、展望与建议

**分类前置、不可逆点一等化**：四态 `INTERNAL / REVERSIBLE / COMPENSATABLE / IRREVERSIBLE` 在工具注册时声明，未声明即拒绝执行；**不可逆动作唯一合法控制是执行前**。`reversibility.*` 九字段（class / commit_boundary / before_value / undo_ref / compensation_id / undo_owner / expiry / external_system / verified）提为 OTel genai 第 14 族提案。**不能靠打开内容采集换可撤销性**：应记结构化旧值与撤销引用（隐私与撤销是两件事）。

**补偿入口必须在正向写时登记、由确定性代码给出**，禁止模型临场发明；撤销自身按动作治理：幂等键、独立读回、`compensate_failed`、revert commit、副作用回归、允许判 `UNVERIFIED` 终止无限回归。**按可逆性而非算力定自治上限**：不可逆动作强制 preview 列出受影响对象与具名 owner，禁止「超时自动通过」越过不可逆点（90 期）。

**把 `undo_rate` / `revert_rate` 做成一等 SLI**：唯一天然带真值的线上信号，进大盘与采购条款、回流回归集、成本单列科目。演练三型：备份保留不足（75.1% 那类）、补偿失败而原动作已离手、撤销被降级或交接绕过；混沌补「不可逆点提前到达」「撤销销毁证据」。**标准补格**：信通院六维「可靠」补「可逆性可导出、撤销后读回一致率」，把「保留撤销能力」改写为「不可逆点可观测且有 SLA」，11-04 四项指标补 revert_rate。

**结论**：79 编制、80 写序、81 不写、88 授权、89 少做、90 等着之后，本期是——**「退得回来的制度」也还没上线**。平台把 undo 做成按钮、把回滚做成发布页，没有一家把「这一步过了就不能回头」做成一等运行态。
