# 记忆技术洞察 · 第 112 期（20261117-2100）

**主题：记忆的「可执行验证复用」（verified executable reuse）——记下的不是"他说了什么"，而是"上次跑通并已验证的那段计算"：当记忆本身是可执行、可改编的程序，准确率与成本可以同向改善**

> 洞察范围：2026 年（近 30 天为主）。四维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

前 111 期把记忆单元都当作"陈述性内容"：事实、偏好、情节、状态，检索后由模型读懂再用（#95 可识别性、#107 固化态）。11-13 MEM-SQL 把记忆单元推到另一类——**已验证且可执行的历史查询**：不是"记住他说过什么"，而是"记住上次跑通、结果已核对的计算结构"，新请求来时直接改编而非从零重建。竞争轴从"记得准、召回全"转向"复用的计算片段能否既对又省"：记忆第一次以"程序"而非"文本"进入复用链。

## 二、技术现状

MEM-SQL（arXiv 2611.18338，11-13，港大＋NUS＋港科广，cs.DB）建 HARE：从四数据集 823 条已验证查询派生 1,600 请求，逐条标注"保留哪些组件、需哪些编辑"，区分整查询改编与部分复用。系统存三层——整查询模板、可复用 SELECT 块、领域概念到 schema 元素的映射；每层设阈值，只有"该层每条要求都有超过阈值的匹配"才启用，强匹配不能掩盖未覆盖要求。另设按需 schema linking（OSL）：无层达标、或生成器判定证据不足时才回查 schema，而非默认全量载入结构。

## 三、技术竞争力

六个模型上，无历史直接生成均值 37.1%，MEM-SQL 达 50.0%，同时输入 token 少 76.6%、延迟低 68.8%——准确率与成本同向改善，因复用已验证结构省掉了从 schema 重建逻辑的开销（对照 #5 记忆税、#96 兑换率，此处记忆是净正账）。但组合是硬伤：复用单条验证查询达 56.7%，一旦拼多条（尤其塞进新结构或合并共享 join）跌到 29.7%。模板主要贡献准确率、查询块贡献组合；OSL 移植到另三种记忆设计都降成本，但准确率收益取决于能否取回完整证据。五项目（OpenViking v0.5.5／Hy-Memory 2.0.16＋MemHub v1.0.7／TencentDB v2.0.3／dsh v26092802／ReMe v0.4.2.2）全为文本/向量记忆＋相似度检索，零可执行验证查询、零覆盖门控、零按需回源，倒挂延续。

## 四、技术挑战

①组合鸿沟未解：多条各自正确的记忆拼不起来——"取到了、也对、但合不拢"，比 #73 利用鸿沟更细一层。②覆盖门控依赖逐要求标注、阈值手调，迁移新库要重标。③OSL 的"证据够不够"由生成器自判，接 #94 评判者偏差：判偏就白查或漏查。④HARE 限四数据集六模型、绝对分仅 50.0%，且"能执行"不等于"复用了预期关系"（验证兼查答案与历史关联），不作"记忆查询已解决"外推。

## 五、需求分析

数据分析用户反复查同一库：上次"华东上季度销售额"跑通了，这次问"华东上季度销量同比"。他要的不是复述答案，而是复用那段已验证的 join 与聚合、只改指标和计算。若把记忆当文本片段靠相似度捞，常对不上新结构；若每次回查 schema 重建，既贵又易错。他要的是"记住跑通的计算骨架，可靠地局部改写"。

## 六、用户旅程

用户在 BI 助手先问"各区域上季度销售额"，系统生成、对库验证后存为模板＋可复用聚合块。下一问"华东上季度销量同比"，系统判模板保留了 join 路径但计算要换，取 SELECT 块改编即可。若新问需同时复用"销售额"与"退货率"两条查询、共享同一 join，系统须把两块塞进全新结构——这正是 HARE 里从 56.7% 跌到 29.7% 的场景：两块各自都对，拼错答案就错。

## 七、具体实现方案

写侧存三层（整查询模板／可复用 SQL 块／概念→schema 映射）附验证状态与可改编位；读侧按层覆盖门控——每条要求超阈值才启用，强匹配不掩盖缺口；OSL 作权威源 fallback：无层达标或证据自判不足才查 schema。评测三本账：整查询改编准确率／部分复用成功率／多查询组合成功率（专测共享 join 与新结构）。AML 补 executable-reuse 维度，接 #61/#73/#88/#94/#95/#96/#106/#109。

## 八、本期新观点

1. **记忆单元从"陈述内容"扩到"可执行且已验证的程序"**：前 111 期记忆都是文本/向量条目，本期记忆是跑通并核对过的查询结构与组件——记忆的价值单位从"记住什么"变成"记住一段可直接改编的可靠计算"，接 #15 动作性、#107 固化态，但落点在"可执行复用"。
2. **覆盖门控优于打分排序（与 #109 划界）**：#109 把召回改为全池效用打分取 Top；MEM-SQL 反过来用 AND 门控——某层只有在它承担的**每条**要求都超阈值才启用，强匹配不能掩盖未覆盖要求。这是 #88"内容∧绑定"、#106"五维不聚合"在复用层的同一逻辑：一维高不代替其余。
3. **权威源是 fallback 而非默认（按需查证）**：OSL 让记忆优先、惰性回源，把 #61 使用闸门从"要不要用记忆"推广到"何时放弃记忆、回查外部真值"，且降成本（token −76.6%）与提准确率（+12.9）可同时成立。
4. **准确率与成本同向改善，改写记忆税方向（深化 #5/#96）**：记忆在此是净正 NPV，因其替代的是昂贵的"从 schema 重建逻辑"，说明记忆税的正负取决于被替代基线是什么——给 #5"复用次数是唯一乘数"补上"替代成本"第二乘数。
5. **组合鸿沟是独立的第三类失败（接 #73/#100）**：单条复用 56.7%→多条拼装 29.7%，不是"没取到"也不是"取到没用上"，而是"多条都对但合不拢"，尤以新结构与共享 join 为甚——评测须单列多记忆组合成功率。
6. **五项目倒挂＋AML 补维度**：五家全文本/向量记忆＋相似度检索，零可执行验证记忆、零覆盖门控、零按需回源、零组合鸿沟评测；补 executable-reuse 维度（整查询改编准确率／部分复用成功率／多查询组合成功率／OSL 回源率）。反证：四数据集六模型、绝对分 50.0%、阈值手调、生成器自判证据——不作普遍外推。
