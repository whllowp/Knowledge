# AI-SRE 技术洞察（2026-11-02 18:00 期，第 34 期）

**本期主线：确定性面（边界）运维——概率引擎的"确定性笼子"成为一等运维资产**

> 前 33 期把智能体运维拆成记忆面、路由面、配给面、轨迹面等二十余个平面。本期视角再抬一层：所有平面共享同一个母问题——大模型是概率引擎，生产运维要求确定性结论、受控动作、可验证结果，两者之间的**边界本身**正在成为最大的一块新建工程面。边界在哪里画、由谁拥有、如何验证、如何观测，本期称为"确定性面运维"（第二十五条主线）。

## 一、发展趋势

**边界显式化：从"能力即边界"到"边界即代码"。** 11 月 1 日，Anthropic 工程师 Addy Osmani 确认在 Claude Code 的 Opus 5.5 提示词里加了两句话，禁止复刻既有游戏以规避知识产权风险——策略被写进提示词而非执行层。同期 Claude Code 2.1.307–2.1.312（10.21–10.27）连续六版都在修边界：bypass 权限模式下危险 rm/rmdir 命令立即拒绝并给改写提示、PowerShell 部分 cd 命令被错误自动批准、Git Bash 缺失时 PreToolUse 钩子放行本应拦截的调用、沙箱不可用时写保护路径需先询问。OpenAI Codex CLI 0.165（10.27）则修补了一个市场 URL 校验缺口——Git 可能连到允许清单之外的主机。边界正在从隐含在模型能力里，变成显式编码在 harness 里，并以周为单位返工。

**边界可观测化，又速朽。** Claude Code 2.1.307 新增 `claude_code.safety_event` OpenTelemetry 事件：每次被规则、自动模式、钩子或沙箱拦下的工具调用都产生一条遥测。六天后，2.1.312 悄然停发该事件——给边界装了行车记录仪又拔掉电源，任何已在它之上搭建拦截率面板的团队等于被无声断供。这是本期最值得记录的信号：**边界遥测自身没有版本化契约，会随 harness 迭代随时消失。**

**确定性控制器进入行业主议程。** 11 月 2 日 SREday 阿姆斯特丹站（微软：Copilot 供给基础设施 + Azure SRE Agent 处置事故，"把组织标准编码为上下文"）与 11 月 7 日纽约站议程集中出现同一主题族：Kidar《Agent 写代码，但不写流程》主张模型只产出代码、确定性控制器拥有全部状态转移、重试预算与终止条件，"多数智能体失败源于让模型决定下一步发生什么"；Guild Systems《凌晨两点谁拦住 AI 智能体》给出注册表、身份感知策略、授权网关、kill switch 的组合，核心论断是"观察智能体不等于控制智能体"；Tiger Data《智能体可以写迁移，但不该上线迁移》把回滚标准、锁与改写检测做成数据库变更门禁。

## 二、技术现状

国内头部企业已把边界工程做成平台资产。蚂蚁（刘凯宁，QCon 上海 2026）在应急根因定位中给出**三分法**：事实还原（动线/单 Trace 过滤、关联、解析，交付可核查的时间线）、状态判定（会员积分、安心付等状态机与业务规则由代码执行）、综合归因（模型综合事实、知识与反证，输出候选原因与证据链）——"工程的交给工程，大模型的交给大模型"。配套三条现状级细节：诊断产物强制三件套（定位结论、证据、待确认项），证据不可用时保留未知并说明缺口；取数权限三要素（授权身份、范围、时长）与查询状态同样重要；工具返回的大段 JSON 若由模型转抄再落盘，是隐性不确定性注入点，蚂蚁改为脚本直接处理、模型专注综合判断。Skill 目录（SKILL.md + scripts/ + references/ 判断模式与置信度模板）被定义为"可维护、可验证、可复用的 SRE 交付物"，真实案例回放作为投产门禁，每周以诊断召回、根因准确率、端到端时效三指标运营。

携程（周昕毅）提出三问现场检验：告警来了能否给出优先级与影响面（判断必须引用实时指标、日志与拓扑）；服务异常能否安全执行并验证恢复（动作必须受控，失败能熔断回滚）；成本上涨能否找到浪费并推动落地。核心张力一句话：模型输出是概率性的，生产运维要求确定性——**会回答问题，不等于能承担 SRE 的工作**。

确定性接口也在 SDK 层标准化：Vercel AI SDK 7 把超时做成类型化一等配置（总/步/块/工具级各设 TimeoutError），错误面设计成分类学（APICallError、RetryError、ToolCallRepairError、InvalidToolApprovalSignatureError 等可精确捕获重试）——把"失败"从字符串变成可编程对象。反例则是模型供给侧：11 月 1 日开发者抓包发现 Codex 后端在 API 实返 `gpt-6.2-astra`，前端界面仍标 GPT-6 Astra，灰度模型已吃下 19.8% 真实流量（爆料口径，待官方证实）——**换芯不换名**让 pin 在模型名字上的确定性契约悄悄失效。

## 三、技术竞争力

以"确定性边界如何构造"为统一维度对比主要方案：

| 方案 | 边界构造方式 | 模型职责范围 | 边界可观测性 | 验证机制 |
|---|---|---|---|---|
| 蚂蚁 DeRiskCoWork+业务 Skill | 三分法（事实还原/状态判定代码化，归因给模型）+Ontology 取数+权限三要素 | 综合归因，输出结论+证据+待确认项 | 执行全程可追溯，阶段耗时分解到步骤 | 真实案例回放投产门禁+每周三指标评估 |
| 携程告警自愈 | 三问现场检验；动作受控、可熔断回滚 | 优先级判断与处置建议 | 引用实时指标/日志/拓扑作证据 | 现场检验三问为准入门禁 |
| Google Triage Agent/ACE | Observed/Approved/Derived 三层事实+append-only 审计；per-agent microVM 无密钥 | 调查与编排 | 拦截与事实来源分层记录 | 审计链可回放 |
| 微软 Azure SRE Agent | Review/Autonomous 双模式、agents-as-code | 诊断与响应计划 | 平台标准编码为上下文 | 人工审批节点内嵌 |
| Datadog Scout | 训练奖励"奖励证据"而非只看答案 | 仅诊断提议不执行 | 证据链随结论输出 | AlertEval 自有基准（待第三方复核） |
| 腾讯 CloudQ/ADP 4.0 | 执行计划引擎：确定性步骤+双 fallback | ReAct 限制在图引擎节点内 | 多模型评审五维实时评分 | 每日两次回归失败即阻断 |
| Anthropic Claude Code | 权限/沙箱/钩子边界周更补丁 | 编码执行（bypass 需显式） | safety_event 遥测（已速朽） | 版本级 changelog 事后追溯 |
| 独立厂商（Guild Systems/incident.io） | kill switch+授权网关+注册表 | 写与破坏性操作永不进自主调查 | 拦截事件+审批事件入遥测 | 桌面演练验证停机时效 |

判读：边界构造能力正在取代"自主度高低"成为真正的竞争分野——云厂商把边界做进平台执行计划（腾讯、微软），垂直厂商把边界做进训练目标（Datadog 用 reward 证据化把"可核查性"训进模型），企业自建派（蚂蚁、携程）把边界做成业务 Skill 资产。Anthropic 的位置最微妙：它提供最强的模型能力，但 harness 边界以周为单位返工、边界遥测六天退役，说明**边界稳定性尚未被头部厂商当成产品承诺**。

## 四、技术挑战

1. **边界遥测速朽。** safety_event 六天寿命证明：未经生命周期承诺的运维信号等于随时断供。可观测厂商不该幸灾乐祸——Tessera 对 telemetry.dev（10.31 发布）的分析指出，追踪已因 OTel GenAI 语义约定商品化，九、十家同类产品挤在同一预算科目里，速朽风险同样存在。
2. **策略执行位置漂移。** 禁复刻游戏的两句话在提示词层，而提示词层策略会被长对话冲淡、无法保证拦截率；同一策略在沙箱层、网关层语义完全不同。企业缺少"边界在第几层"的目录，安全评审时无法回答"这条规则由谁强制执行"。
3. **换芯不换名。** 模型灰度发布让按名字 pin 的契约失效；GPT-6.2 灰测若属实，前端名称与后端真身分裂将成为常态性运维事件，而多数团队的变更管理尚不覆盖供应商侧静默换芯。
4. **转抄损失未被普遍认知。** 模型转抄工具返回的 JSON 是隐性不确定性注入点，蚂蚁已用脚本替代，但业界尚未把它当成标准反模式。
5. **观察≠控制。** 遥测完备不等于能停：kill switch 必须独立于模型链路、独立于单点存储，且拦截检查放编排层而非提示词（社区工程实践给出 TTL 旗标、200ms 内响应的桌面演练标准）——这些细节仍属少数派。

## 五、展望与建议

1. **边界清单化。** 把"哪些环节由代码决定"写成版本化边界清单（状态转移、重试预算、终止条件、审批点、取数权限），纳入架构评审与回归测试——蚂蚁三分法与 Kidar 确定性控制器是两个可抄的模板。
2. **边界信号当 SLI 管。** 拦截事件流、策略版本号、执行层目录三件套需要厂商生命周期承诺；"遥测速朽条款"应进采购评估清单。
3. **名字之外的模型 pin。** 按 API 版本、行为指纹做 pin，供应商灰度公告纳入变更管理；前端名称不作为契约。
4. **三问准入门禁。** 取证、受控、验证三问作为智能体进入生产运维的最低门禁，反证与待确认项作为诊断产物强制字段——"保留未知"是确定性的组成部分。
5. **把边界本身当被测对象。** 混沌演练不仅注入故障，也应注入"边界失效"（钩子缺失、沙箱降级、策略句被冲淡），验证笼子在笼子坏掉时仍然关得住。
