# AI-SRE 技术洞察 · 第 77 期（2026-11-04 23:00）

## 本期主线：记忆的退出面（删除与迁移）——"记得住"已经卷出新高度，"删得掉、搬得走"还是集体空白

> 本期是第 22 期"记忆面运维"的定向深化。那一期回答"记得住、找得对"，指出商用产品只解决了写入与召回；本期推进到记忆生命周期的另一端——**删除语义与迁移语义**（第六十八条主线）。与 22 期划界：那期管写入裁决与召回质量，本期管退出操作——关掉开关是不是删除？删会话删不删衍生记忆？投毒之后能不能一键驱逐？换供应商时记忆跟不跟得走？与 41 期退役分界：那期管模型下线的迁移成本，本期管**记忆**作为离场成本新载体的迁移成本。

### 一、发展趋势：记忆从"资产叙事"转向"负债叙事"

30 天内最重的事件不是任何一个新功能，而是一次**大规模记忆驱逐**：10 月 15 日，字节豆包与阿里通义千问自建拟人智能体的三个月备份窗口到期，历史对话数据"彻底清除、永久不可恢复"，媒体报道约 800 万用户通宵导出自己的对话记忆。监管动因是 7 月 15 日施行的《人工智能拟人化互动服务管理暂行办法》；工程上的暴露面则是：**记忆驱逐从未被当作一个运维操作来设计**——没有导出保真标准，没有跨平台迁移通道（齐鲁晚报核实"目前所有平台均不支持完整人设、专属记忆跨平台迁移"），用户唯一的自救是手动复制 TXT。

这与行业此前的叙事构成镜像：记忆是留存引擎、付费壁垒、护城河——10 月起，同一份记忆同时是"删不掉就违法"的负债。企业侧同步发生语义下沉：Anthropic 10 月初为 Managed Agents 上线 Dreaming（异步读取记忆库与最多 100 个历史会话自动提炼洞察），OpenAI 为 Codex 推出 Chronicle（屏幕录制转本地 Markdown 记忆，明文存储、有注入风险提示）——记忆整理第一次拥有了"后台进程"形态，但两者的记忆管线均无审计日志与回滚通道。OWASP 2026 Agentic Top 10 将记忆与上下文投毒单列（22 期已述），而本期检索显示：**投毒的事后清除侧（eviction）在所有公开材料中均为空白**——检测有人研究，驱逐没人设计。

### 二、技术现状：删除是双轨的，迁移是名义的

**删除双轨不对称**是当前所有厂商的共同形态。OpenAI 官方文档明示：saved memories 与聊天记录分开存储，删除原始聊天**不会**自动删除已保存的记忆。腾讯云 Buddy 的 FAQ 写得更直白：关闭"生成会话记忆"开关后模型不再使用与更新记忆，但**既有记忆内容保留**，要彻底清除须另行点击 Clear——"关"和"删"是两个动作，界面上前者比后者显眼得多。Anthropic 的 memory imports 官方标注 experimental，且提示导入的记忆"可能不总是被成功采纳"。这构成一个用户可见性陷阱：可见的删除操作（删聊天）遮蔽了不可见的保留（衍生记忆）。

**记忆是全行业唯一没有版本控制就直达生产的共享可变状态。**模型写一条记忆，等于一次无人 review、无 diff、无回滚的发布。主流方案里只有 Google Agent Platform Memory Bank 把每次记忆变更保留为不可变修订（immutable revisions），Zep/Graphiti 用双时间轴（事实的 valid_from/invalid_at）把"曾经为真"与"现在为真"分开。反例是 Mem0：早期论文让模型自己对旧记忆做 ADD/UPDATE/DELETE/NOOP 四操作，生产环境里"不仅慢，还经常删错"，v3 干脆退成 ADD-only 只追加、放弃原地覆盖——这是生产环境对"让模型自己执行删除"投出的反对票。社区实测反馈 Mem0 覆盖式 UPDATE"越用越脏"：覆盖丢历史，相似度阈值漏判矛盾。

**检索成功即事故。**Zurb Radar 的复盘给了本期最锋利的一句话："Retrieval worked perfectly. It retrieved a fact that used to be true."——一个智能体在用户换工作数周后仍在引用旧雇主，无报错、无告警，检索链路全部健康。记忆系统没有 TTL，"曾经为真"的事实会以 100% 的检索置信度返回。同一篇复盘中，往智能体工作内容里注入损坏数据，五个合理替换中两个**从未被任何检查捕获**；某 SRE 智能体 46 小时烧掉 124 万美元的根因链条里，记忆持久化是放大器。共享记忆池的反模式同样有生产级样本：某自动修复管线中，子智能体把截断的系统提示与残缺 JSON 工具输出直接写入全局共享消息池，下游测试智能体把脏数据当作用户指令进入无限重试循环——45 分钟内 400+ 次 bash 调用、每小时烧 3,800 美元、部分未校验代码被 force-push 到三个 release 分支，回滚用了 6 小时。根因不是幻觉，是**共享可变状态没有生命周期边界**。

### 三、技术竞争力：谁把"退出"当一回事（主要方案对比表）

| 方案 | 删除语义（关=删吗） | 衍生记忆级联 | 时间语义 | 迁移/导出 | 版本留痕 |
|---|---|---|---|---|---|
| OpenAI ChatGPT/Work | 关闭≠删除；删聊天≠删 saved memory | 未提供 | 无公开 TTL | Business/Enterprise 无自助导出 | 无 |
| Anthropic Claude | 项目记忆与账户记忆边界靠配置项 | 导入 experimental、采纳不保证 | 无公开 TTL | 组织级导出仅 Primary Owner | 无 |
| Google Memory Bank | 作用域隔离清晰 | — | — | 随平台 | **不可变修订**（唯一） |
| 腾讯云 Buddy | FAQ 明示关闭≠清除，需手动 Clear | 未提供 | 无 | 未提供 | 单条可改（自然语言） |
| 豆包/通义（消费侧） | 平台侧强驱逐（10-15 全清） | — | — | TXT 导出，无跨平台迁移 | 无 |
| Mem0 v3 | ADD-only，放弃模型判删 | 判重不覆盖 | 平台有时间衰减权重 | API 导出 | 无血缘 |
| Zep/Graphiti | 不删只标 invalid_at（失效派） | 图上留痕 | **双时间轴**（最强） | Graphiti 自托管 | 失效留痕 |
| Letta | 模型自改核心块（改错即污染） | 无 | 无 | 块可导出 | 无 |

判读：商用大厂解决了"作用域与权限"（腾讯 Buddy 的账号级隔离、Google 的 per-scope collection），开源两强解决了"时间语义"（Zep 双时间轴、Mem0 衰减权重），但**没有任何一家同时回答三个退出问题**：投毒会话的一键级联驱逐（衍生记忆怎么连坐删除）、删除完成度验证、跨平台迁移保真率。记忆整理后台化（Dreaming/Anthropic、sleep-time compute/Letta、Auto Dream/CC）正在成为标配，但"后台进程写生产状态"恰恰放大了写入侧的治理债，而退出侧连审计都没有。

### 四、技术挑战

1. **级联删除无协议**。删除一个会话时，由它蒸馏出的记忆、摘要、画像属于衍生数据，目前无任何厂商声明级联语义；投毒事件的清除因此退化为逐条人肉审查。
2. **三派遗忘哲学未收敛**。衰减派（MemoryBank 艾宾浩斯曲线，遗忘即检索降权）、失效派（Zep，永不删只标失效）、显式删除派（用户主权，删得干净）各管一层，法规只认第三派，工程上最省事的是第二派——合规与架构的错位没有标准解。
3. **多写入者一致性是集体盲区**。热路径（对话中实时写）与冷路径（后台蒸馏写）同时改一条记忆、两个会话同时纠正同一事实，几乎所有方案都默认单写入者，生产级答案缺位。
4. **记忆导入的可信性**。Anthropic 自己承认导入可能不被采纳——意味着迁移不仅是"搬"，还要**验证搬过去之后行为一致**，这个验收环节无厂商提供工具。
5. **驱逐演练无先例**。22 期我们说"记错了怎么办"开始有答案；本期补充：记错之后**删错的成本如何度量**（误删合法记忆=失忆事故），同样没有 SLI。

### 五、展望与建议

**第三十一个市场空白**：记忆退出四指标——删除完成度（衍生级联覆盖率）、驱逐时延、迁移保真率、导入后行为一致率——无一厂商内建。建议：

1. **写入侧走单一写入服务**：无论模型主动写还是后台蒸馏写，过同一道闸（schema 校验、来源标记、supersedes 合法性、版本检查）；裁决用**血缘取代（SUPERSEDE）而非覆盖**——引用旧 claim 作废，历史留痕，"系统永远知道自己怎么错的"。
2. **给记忆补上运维三件套**：TTL/有效期字段（给"曾经为真"一个到期日）、provenance（谁在哪个会话写入）、级联驱逐接口（按会话/来源批量作废并出回执）。
3. **删除演练进日历**：每季度做一次"投毒会话一键驱逐"演练，验证级联删除完成度——与 20 期混沌演练同构，对象换成记忆。
4. **采购四问**（进合同）：删会话时衍生记忆的处置语义；关闭开关后的保留期限；导出格式与保真承诺；导入实验性状态下的行为一致性验收方法。
5. **把 10-15 事件当教材**：平台强驱逐 + 90 天窗口 + TXT 导出，是记忆退出操作的最坏实践样本；企业自建记忆层时应反向设计——驱逐是常态运维操作，不是合规突发事件。
