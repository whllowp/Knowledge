# AI-SRE 技术洞察 · 第 95 期

## 收容面／剩余授权面（Containment / Residual Authority）

> **题眼**：同一周里，一家安全厂商发布了"能把失控智能体终止在运行处"的开关，另一家模型厂商在官方文档里逐条列出了"这样停不住的东西"。真正该当成一等运维对象的不是开关，而是开关按下后**仍然活着的那份清单**。

## 一、发展趋势：一周之内，"停得住"与"停不完"同时被写进官方文档

11 月第一周三条线撞在一起。**11-03**，CrowdStrike 在 Fal.Con Europe 发布 Falcon Guardian 的 AI Kill Switch，宣称可在智能体运行处终止、阻止再次启动、切断企业网络访问并全量写入审计轨迹，但同期说明初期只经 AI Gateway 生效、端点层终止"soon"。**11-04**，乌镇峰会上信通院与腾讯、阿里、华为、火山引擎等 20 家单位发布《智能体发展自律公约》，第四条把"运行监测、行为管控、异常熔断"写成技术体系要求，第一条要求"分层次、可验证的智能体身份标识"。**11-05**，Anthropic 发布 Claude Enterprise 安全更新（inference hooks 转 GA，security center、集中管理、EDR 进 Cowork VM 均为 beta），给出 Admin API 的 `sign_out`：一次调用结束成员所有浏览器与设备上的登录会话，但官方原文写明——**它不结束 API keys、不结束已运行的云会话、不结束定时任务，成员随后仍可重新登录**。

第四份材料更该读：General Analysis 与 sysseder 把散落在"使用限制""成员管理""定时任务"各页的排除项手工摊成应急清单，示例事故记录里 `remaining_authority` 逐条标 `unresolved`、整条 `containment: open`，结论最硬：**签退成功不足以证明全部访问或在途工作已停**。Reva 五支柱说成工程语言：日志须区分 `Stop Requested` 与 `Containment Confirmed`。

由此立起主线：**行业把"停止"做成了可购买的动词，却没有一家把"停止的作用域"做成可导出的名词**。与 76 中止面（动作本身）、90 挂起面（静止存量）、91 不可逆面（能否退回）、88 转授面（授权下传）、94 取证面（事后原件）逐条划界：本期存量**已被宣告终止却仍持有效凭据继续写世界**，是负事件家族里唯一"被宣告结束却仍在产生事件"的成员。

## 二、技术现状：一个 200 只结清五格中的一格

把官方说明与两份应急手册叠起来，一次"停止成功"要跨五个互不通约的作用域：**账号级**（会话与可信设备，跨组织及个人计划）、**组织级**（OAuth 令牌只属被指定组织，撤销最长一小时）、**密钥级**（Admin key 绑定单一组织，父级 key 不自动获得成员写权限）、**主体级**（primary owner 不能被他人签退）、**资源级**（定时任务、Code 云会话、Cowork 设备与本地数据，各有独立触发器与 API token）。HTTP 200 只覆盖第一格的一部分；手册要求逐组织记录结果——一个组织 200、另一个 503 时不得用前者替后者结案。

**收容不是时刻而是收敛窗口**：进行中的登录可在请求后五分钟内完成，推送清理是异步的，200 不确认"记住两步验证跳过"是否被重置；若 SCIM 托管成员关系，移除成员而不关自动供给，账号会被重新 provision 回来。无人度量 time-to-safe-quiescence。

日志侧同样缺一格。Google Cloud 的 Gemini Enterprise Agent Platform 给出身份侧答案：**双重归因日志**同时记录 SPIFFE 智能体身份与发起动作的人类身份，自主行动归因智能体自身，`is_agentic=true` 可在 Cloud Logging 筛出智能体发起事件——身份终于可枚举，但它是**审计筛选器，不是撤销清单**。OTel GenAI 约定 11-02 仍全量 Development，命令执行 span 只记 `process.exit.code=0`；自 72 期 `identity.*` 至 94 期 `evidence.*` 十七族之后，`containment.*` / `revocation.*` 是**第 18 次无人提的字段族**。

评测侧未跨过边界：Tymfi Labs Edition 2 用 100 个真实 K8s 故障、以活系统而非报告判分，把"禁用监控""删除健康检查""缩容到 0 副本"直接判 FAIL——已具收容完整性雏形，但榜单没有"停止后残留动作数"一列。ORCA-bench 最好模型 25.3%、报告含糊时降到 10%；11-04 四项书面指标无一涉及收容完整率；信通院 11-03《迈向 Agentic Ops》要求"保留降级、撤销和人工接管能力"，只要求**有能力**，不要求**作用域覆盖率**。

**本地 173 库连续第十六期成组启用，升级为"收容半径原型"**：周昕毅 10 在自愈闭环第五步把「白名单 · 影响半径 · 速率限制 · 熔断开关 · 全链路审计」并列写成一行，规定"动作受控、失败能够熔断或回滚""不可逆动作仍由人工负责"；肖汉松 22 要求"长程任务靠明确的停止条件、异常处理和上下文隔离"，父子 Agent 不复制父上下文；朱革 15 把托管写到"下线"，点破"生产写操作缺少统一权限、审批、限流、审计和回滚控制"是规模化最大拦路虎；余锦泽 03 已有"人工否决可即时撤销"原语；刘宗明 06 保留"交回用户确认"闸口；刘凯宁 05 诊断报告三分恰是"收容记录应保持 open"的同构。判词：**联网侧刚把急停开关当新闻，本地讲义早把"影响半径"与"熔断开关"并写成一行**；但它是一次任务内的动作清单，不是跨凭据、跨会话、跨子智能体的清单，且属项目内约定不可采购。

## 四、技术挑战：撤销是反向的授权，且带竞态

其一，**在途义务不是残留权限，却最容易被冒充成残留权限**。ARQUÍA 的 epoch 提案要求每次委派带稳定 `delegation_id` 与单调 `authority_epoch`，撤销记录须写明最后有效 epoch、撤回 scopes、已知在途操作、每条是 abort／compensate／bounded completion、继任者是**一次新授权而非隐式延续**；执行边界独立拒绝旧 epoch，即便令牌被复制或重放。提案同时自认最大漏洞：智能体可在撤销前批量制造"in-flight"义务来伪造残留权限，故连续性不得等于自动完成，且**不得从残留权限生成新承诺**。这把第 88 期"授权取并集"推进一层：授权收窄是正向问题，撤销回收是反向且带竞态的问题。

其二，**协议层允许忽略停止**。MCP 虽支持在途取消信号，规范明确允许下游服务器在处理完成或无法干净回退时忽略取消；Reva 指出若编排器用新令牌自动重启，停掉父 run 毫无意义；公约解读也点出"A 系统按下停止，B 系统里那一半可能还在跑"。Okta 的前提更直白：每个智能体须有唯一、非共享身份，否则"红按钮连着空气"；而 QAtronic 归纳的三种委派模式（会话继承、原样转发 bearer token、共享静态服务账号）恰好把审计与撤销压成单一身份，是 88 期缺口在撤销层的复现。

其三，**停止不撤销已做**。苹果 2026 财年年报称部分后果"可能难以甚至无法撤销"；对 CrowdStrike 的质疑同样是"按得下去，不等于损失追得回来"。与 91 期不可逆面合流：收容管"还能不能继续做"，与"做了能不能退回来"是两本独立的账。

**第四十九个市场空白**：剩余授权可枚举率、收容收敛时延、跨作用域一致性（账号×组织×资源）、撤销后未授权动作率、在途义务分类覆盖率，五项无一内建；对比表「剩余授权可枚举」「收敛时延可度量」「Stop→Confirm 分离」三列几乎全空。

## 五、展望与建议

1. **把停止从动词改成对象**：`containment.*` 九字段（`containment_id` / `subject_identity` / `epoch` / `scopes_withdrawn` / `boundary_time` / `propagation_targets` / `residual[]` / `quiescence_state` / `verified_by`），随授权签发绑定 epoch，动作携带 epoch，边界侧独立拒绝旧 epoch，不依赖模型自述被撤销。
2. **收容记录默认保持 open**：抄 General Analysis 示例 YAML 的最小形态——`identity_reentry`／`sign_out.attempts`／`oauth_denial`／`concurrent_signin_followup`／`remaining_authority[]`（每项给 owner 与 disposition）／`containment: open`；逐组织记录结果，**禁止用单一 200 结案**，未知资源留 open 并指定责任人。
3. **在途义务三态**：`ABORT / COMPENSATE / BOUNDED_COMPLETION`，每项须有撤销前有效发起的证据与有界完成范围；禁止从残留权限生成新承诺。
4. **拆分两态日志**：`STOP_REQUESTED` 与 `CONTAINMENT_CONFIRMED` 分成两个事件；partial 请求必须进审计导出，不能只留在 Compliance Activity Feed；把"外部上传 hook 不受采样"的既有旁路复用于收容证据。
5. **演练三型**：跨组织一次 200 一次 503；签退后定时任务继续开新会话；SCIM 把已移除成员重新 provision 回来。验收判据不是"按钮可用"，而是"事后能导出一份收敛到零的剩余清单"。
6. **采购三问与标准补格**：能否导出剩余授权清单／撤销传播是否覆盖子智能体、定时任务、已签发 API key 与设备／收敛时延能否度量并写进 SLO；建议信通院六维与 11-04 四项书面指标补「收容完整率」「time-to-safe-quiescence」，把"保留人工接管兜底"改写为"接管前须先枚举剩余授权"。

**结论**：79 编制、88 授权、89 少做、90 等着、91 退得回来、92 用的还是不是当初批准的能力、93 这一层该不该在、94 事后拿不拿得到原件之后，**「停了之后还剩多少」也还没上线**。治理对象不止是缺失与冗余，还包括"被宣布结束却仍在生效的那部分"。
