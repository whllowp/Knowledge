# 第 191 期（2026-11-13 19:00）· 韧性归因面／架构健壮性面（Resilience Attribution / Architectural Robustness）

> **题眼**：Agent 在故障与注入下的表现，不取决于"用哪个模型"，而取决于"怎么搭系统"。AgentChaos（arXiv 2608，ASE 2026）把五套多智能体系统、四个模型后端逐一换了一遍——pass@1 在注入下最多跌 50 个百分点，而**换 GPT-5.2 还是 Claude Sonnet 4.5，系统的韧性排序几乎不变**。这是 2026 年对"选模型保稳"信仰最硬的一记耳光。
> **主线**：首次把"Agent 健壮性从何而来、能否归因到架构而非模型、能否被标准化的故障注入复现与度量"立为一等运维对象——韧性不是采购项，是设计项。

## 一、发展趋势

1. **韧性从"模型能力"被重定义为"系统架构属性"。** AgentChaos 在 HTTP 层对五套系统（AutoGen / MAD / MapCoder / EvoMAC / Mini-SE）注入崩溃、截断、腐化工具调用三类故障，跨四个后端模型实测：每套系统都退化，pass@1 最多跌 50 点；但**系统间的韧性排序与所用模型几乎无关**——健壮性是"系统如何处理响应"的属性，不是"哪个模型生成响应"的属性。换模型 alone 救不了薄弱架构。
2. **故障注入从基础设施走向 agent loop。** ReliabilityBench（arXiv 2601）建立一致性/健壮性/容错三维可靠性面，混沌式注入超时、限流、部分响应、schema 漂移；AgentChaos 用代理在 HTTP 层无侵入注入、不改源码；Imversion（2026-11-06）给出七场景清单（API 超时／畸形 JSON／陈旧检索／权限缺失／部分返回／模型失败／网络分区）。
3. **行为契约先于注入成为硬前提。** Imversion 强调：先写清 retry／validate／escalate 规则，混沌测试才不是噪声——"CRM 读超时该降级、支付授权缺元数据必须阻断"，两类故障不能用同一响应。
4. **评测基准开始纳入韧性维度。** MAESTRO（arXiv 2601）表征 12 种多智能体架构，结论"架构是资源画像与可复现性的主导变量，常压倒模型与工具差异"；ReliabilityBench 已把故障注入做成可跑基准。

## 二、技术现状

- **严重 ≠ 有害的陷阱被实锤**：AgentChaos 发现 omission fault（截断、空响应，返回 HTTP 200 绕过多数错误处理）在多数系统上与 crash 同样致命——MAD 上空内容致 pass@1 跌 38.46%，接近显式错误内容的 37.5%、远超超时的 22.33%。最吓人的故障往往最不报警。
- **单步退化会复合**：ReliabilityBench 基线 96.9% 在中度扰动下到 88.1%；每步依赖前一步的多步 Agent，若每步成功率 90%、任务 7 步，端到端仅 48%。
- **更简单反而更韧**：ReAct 在故障下恢复率 80.9%，Reflexion 仅 67.3%——本该帮 Agent 纠错的自我反思，反而放大故障影响（中度注入下 Reflexion 退化 10% vs ReAct 7.5%）。
- **多智能体特有的放大器**：重试风暴（多 Agent 协同指数退避，秒级把负载放大 10x）；不确定性被下游当作事实接力；**恢复期的提示注入**（Agent 降级时读外部源被劫持，OWASP 列 LLM01 为头号漏洞，超 73% 生产 AI 部署存在）。
- **云厂商把混沌工程卖给了基础设施，没卖给 Agent**：六家都有 VM／容器／网络级故障注入能力，但无一将"对 agent loop 做故障注入验证优雅降级与爆炸半径"做成产品（详见对比表）。

## 四、技术挑战

- **换模型救不了韧性**：AgentChaos 铁证——采购决策若只比模型安全分，等于买错维度。
- **严重 ≠ 有害**：omission fault（截断／空响应）隐蔽且致命，现有错误处理只接 crash，漏掉"看起来成功"的失败。
- **多智能体放大器**：重试风暴、不确定性下游接力、恢复期提示注入，单 Agent 测过不等于编队安全。
- **行为契约缺失**：没先定义 retry／validate／escalate，混沌测试只是噪声（Imversion）。
- **无标准化可复现注入 + 可比度量**：注入方式、故障 taxonomy、成功判据各说各话，无法横向比韧性（接 #185 度量主权、#190 在线评估）。
- **长任务退化复合**：每步 90% 经 7 步端到端仅 48%，现有评测多测单步不测端到端衰减。

## 五、展望与建议

- 立 **`resilience.*` 字段族（第 103 次无人提字段族）**：fault_injection_coverage（注入覆盖的故障类）／robustness_ranking_stable（换模型后端排序不变率）／blast_radius_bounded_rate（故障不溢出率）／escalation_under_fault_rate（故障下升级率）／false_action_under_fault_rate（故障下误动作率）——**第 134 个市场空白五项**，六家零公开。
- **行为契约先行**：以 Imversion 为标杆，先写清 retry／validate／escalate 规则，再注入。
- **HTTP 层无侵入注入**：以 AgentChaos 代理模式为原型，不改源码即可压测真实 agent。
- **韧性验证进发布门禁**（接 #152，但 #152 管演练动作、本期管韧性可归因可度量）：把 blast_radius_bounded_rate／false_action_under_fault_rate 设为上线红线。
- **爆炸半径建模 + 冷却迟滞**（接 #133 自愈遮蔽面）：注入验证"故障是否停在原地"。
- **信通院六维补「韧性可复现验证率」格**。
