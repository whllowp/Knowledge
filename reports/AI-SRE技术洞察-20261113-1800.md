# 第 190 期（2026-11-13 18:40）· 生产侧评估面 / 在线评估面（Online Evaluation & Behavioral Drift）

> **题眼**：可观测告诉你"发生了什么"，评估告诉你"做得对不对"。2026 年六家都在抢建 Agent 可观测，却只有不到四成在生产侧做持续评估——"看见"与"判断"之间，裂着一道在线评估的缺口。
> **主线**：首次把"Agent 在生产中是否被持续、在线地评估其质量与漂移"立为一等运维对象——可观测已普及，评估仍稀缺。

## 一、发展趋势

1. **评估从"离线门禁"走向"生产侧在线监控"。** Google 在 Gemini Enterprise Agent Platform 把 Agent Evaluation 做成平台一等能力：在线评估监视器（online evaluation monitors）持续监控生产中的 Agent，主动识别**性能退化与行为漂移**；更关键的是它主张"构建期迭代用的指标，就是上线后给 Agent 打分的指标"（build-grade == ship-grade metric），评估与生产首次共用同一引擎。
2. **监控 Agent 的 Agent 成为新范式。** OpenAI 10 月公开四层失配监控（激活探针 → 审查模型 → 调查 Agent → 人工），宣称复盘本可提前 30 小时发现 Hugging Face 越权事件；Anthropic 把"先看 trace、再放大权限"写进操作原则——信任来自可观测，而非默认授权。
3. **评估从"判单次对错"走向"测分布漂移"。** 关注行为是否悄悄偏移基线，而非单条结果好坏；自适应 rubric（Google 与 DeepMind 共建）让评判标准随任务演进。
4. **标准收敛但仍在抖动。** OTel GenAI 语义约定（create_agent / invoke_agent / execute_tool / plan …）已成 2026 事实标准（LangChain 调研 89% 已落地可观测），却仍标 "Development" 未稳定；内容捕获默认关闭（PII 考量）。

## 二、技术现状

- **普及率极度不对称**：可观测 89% 已落地、62% 详细追踪；但生产侧在线评估仅 **37.3%**、离线评估 52.4%（LangChain 2026）——"能看见"远多于"能判断"。
- **评测-生产裂隙真实存在**：离线 benchmark 通过 ≠ 生产长期稳定（马云雷：工具契约/环境快照会漂移，离线通过不保证长期稳定）。
- **本地最强原型在蚂蚁与阿里云**：刘杨（蚂蚁）以 Trace 为中心的**实时评估链路**，分钟级端到端、小模型+正则粗筛 99% 流量、<1% 进大模型、token 成本降 90%+；马云雷（阿里云 AgentLoop）把轨迹做成数字资产，Bad Case 必须进回归集，持续在线评估/聚类/归因。
- **厂商分野**：Google 同引擎最完整；阿里以 RCA-100 公开基准 + 生产飞轮在"轨迹→回归"最开放；Anthropic/腾讯把评估下沉到观测伙伴或可观测层；OpenAI 强在"安全监控"而非"质量评估"；字节闭源自建。

## 四、技术挑战

- **89% vs 37% 缺口**：可观测易建、在线评估难建（要真值、要判官、要口径、要成本）。
- **判官同源 / 自指**：谁评 Agent？自评虚高（度量主权 #185）。
- **漂移无基线即不可测**：行为"漂"到哪算异常，缺基线就缺告警。
- **构建-生产两套管**：训练 metric ≠ 生产 metric（评测-生产裂隙 #135）。
- **标准未稳**：OTel GenAI 仍 Development，字段会变，接入需锁版本。
- **成本与隐私**：内容捕获默认关（PII），在线评估 token 成本高，须靠粗筛降本（刘杨 90%+ 降本）。
- **离线 ≠ 长期稳定**：环境/工具契约漂移使一次通过不可代表持续正确（马云雷）。
