# AI-SRE 技术洞察 · 第 167 期（2026-11-13 06:00）

## 题眼：可观测性语义标准化面 — 让 AI 运维信号可比较、可迁移、可评测

当每个厂商都能"观测自己的 Agent"，真正的瓶颈已不再是"能不能看见"，而是"这些观测能不能对账、能不能横向评测、能不能换平台不丢信号"。语义约定层，正是那块被高歌猛进的 Agent 能力叙事长期忽视的拼图。

---

## 一、发展趋势

1. **观测对象从"服务"迁移到"Agent 行为链"。** 传统 APM 假设确定性请求-响应，而 LLM 系统是一串 LLM 调用 + 工具调用 + 子 Agent 委托的链，只有 trace 能还原"到底发生了什么"。Google Next '26 的明确信号：OTel 与分布式追踪已成为 AI 负载监控的事实底座——PayPal 的 "Agentic SRE"、Neo4j 可观测、Google Cloud Assist Investigations 自动 RCA，无一例外收敛于此。
2. **语义约定正在成为"运维世界语"。** OpenTelemetry 在 2026 年把 GenAI 约定从主仓库迁出为独立 `semantic-conventions-genai` 仓库，定义了 create_agent / invoke_agent / plan / invoke_workflow / execute_tool / chat 等统一 span 与 `gen_ai.*` 属性族，并首次为 MCP 定义 `mcp.client` / `mcp.server` span 与四类指标。行业正从"各叫各的"走向"共享词表"。
3. **评测基准与语义约定深度耦合。** SRE-Bench（2026-10 第二版）、ORCA-bench（康奈尔/哥大/Traversal，1079 任务、50GB OTel 遥测）、阿里 RCA-100（103 用例/28 类/四层标注）、OpenRCA 2.0，全部以 OTel 插桩环境为底座——基准的可比性直接依赖遥测可被对齐。
4. **巨头横向并购锁定标准。** 2026-08 Dynatrace 收购 Arize（其 OpenInference 构建于 OTel 之上），标志可观测 incumbent 把 AI tracing 收编进 OTel 谱系。

## 二、技术现状

- **约定成熟度：** 截至 2026 年，所有 GenAI Agent / MCP 约定状态均为 "Development"（非 stable）。在 OTel 成熟度模型中 Development 低于 Stable，属性名与语义仍可变、无稳定性保证。OTel 提供 `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental` 做版本钉选——"今天按约定插桩，明天可能要改"。
- **内容捕获的隐私默认：** prompt / 工具参数 / 响应默认不采集（避免 PII 与体积膨胀），改以 **span event**（非 attribute）承载，可在 Collector 层按策略丢弃。于是默认遥测是"瘦"的——只有模型名、token 数、时长。
- **厂商落地分层：**
  - **Google：** ADK 原生依赖 OTel，Cloud Trace 自动抽取 GenAI 约定 span 事件；Application Monitoring 据约定聚合出 token/调用次数等指标；最佳实践把 prompt/响应存 GCS 桶而非日志条目（绕开 256KiB 日志上限、可细粒度删除）。
  - **OpenAI Codex / Anthropic Claude Code：** 均原生导出 OTel，但默认关闭（需 `[otel]` 配置块 / `CLAUDE_CODE_ENABLE_TELEMETRY=1`），事件目录各自命名（`codex.*` / `claude_code.*`），prompt 默认脱敏。
  - **字节 VeOps：** 把服务端监控 / VMP / 云监控 / 本地日志封装成"供通用 Agent 可靠调用"的 VeOps CLI；Vigil（FSE'26，火山引擎部署 10+ 月）以 RAG 检索 + 对话内主动介入 + 从人工结案抽取知识自改进，已开源 `github.com/volcengine/veaiops`。
  - **阿里 STAROps：** ARMS 兼容 OTel 标准 + 20+ AI 框架，覆盖 Token 成本 / 模型性能 / 工具调用三场景分析与会话级回溯；UModel 统一建模（3200+ 模型定义）产出运维图谱；RCA-Bench 用 brise 评分（实体定位 40% + 故障类型 30% + 调查过程 30%，约 82% 由确定性规则完成）。
  - **腾讯 CloudQ：** 基于 OpenClaw + TSA，全景图谱把资源 / 关系 / 状态 / 动作组织成一张图，ChatOps + AIOps + CloudOps 多云纳管；2026-10 生态大会宣布从治理平台升级为多云 AIOps 智能体并启动共创计划。

## 三、技术竞争力（六厂商 + 标准对照）

| 厂商 / 方案 | GenAI 语义约定(OTel) | MCP span 可观测 | 跨厂商可比/可移植 | 自带评测基准 | 内容捕获合规默认 | Agent 遥测默认 |
|---|---|---|---|---|---|---|
| OpenTelemetry（标准） | 定义者（Development） | 是（mcp.client/server + 4 指标） | 强（运维世界语） | 否（只定义约定） | 内容 opt-in span event | 不适用 |
| Google（ADK/平台） | 强（ADK 原生遵循） | 是（经 OTel） | 强 | 有（GenAI eval service） | 内容存 GCS、默认不采 | 需配置 |
| OpenAI（Codex） | 弱（自命名 codex.*） | 否 | 弱 | 否 | prompt 默认脱敏 | 默认关 |
| Anthropic（Claude Code） | 弱（自命名 claude_code.*） | 否 | 弱 | 否 | prompt 默认关 | 默认关 |
| 字节（VeOps/Vigil） | 部分（OpenClaw 接 APMPlus Trace） | 部分 | 中 | 否（内部 RCA 框架） | 随证据链 | 视配置 |
| 阿里（STAROps/UModel） | 强（ARMS 兼容 OTel + 20 框架） | 经 UModel MCP | 强（brise 横评竞品） | 有（RCA-100） | 随证据链存 | 需接入 |
| 腾讯（CloudQ/OpenClaw） | 中（全景图谱自有） | OpenClaw 接 APMPlus | 中（多云但自有图谱） | 否（共创计划） | 待查 | 视配置 |

**判读：** 最强"语义标准化"来自 OpenTelemetry 标准本身与 Google ADK（标准驱动、跨厂商可关联）；OpenAI / Anthropic 虽原生 OTel 但事件自命名、缺 `gen_ai.*` 对齐与 MCP span；字节 / 阿里 / 腾讯在"跨厂商可比 / 自带基准"列强（自有图谱与基准），但对外不承诺 GenAI 约定合规级别；六家"Agent 遥测默认开"几乎全为关或需配置——可观测性仍非出厂默认。

## 四、技术挑战

1. **标准化未稳即被广泛依赖（churn 风险）：** 约定仍为 Development，厂商若早绑定特定属性名，升级即返工；但不绑定则各写各的，跨栈 trace 不可比。两难。
2. **命名分裂：** `codex.*` / `claude_code.*` 等非 `gen_ai.*` 命名，使同一"工具调用"在不同栈里属性名不同，后端须写多套解析器——"共享词表"并未真正共享。
3. **内容捕获的合规张力：** 调试与审计需要 prompt / 工具参数，合规却要求脱敏；默认瘦遥测让根因回溯缺上下文，开内容又踩 PII。
4. **基准的可移植假象：** 各基准虽都"基于 OTel"，但厂商 Agent 若不发 GenAI 约定 span，其 trace 无法被同一 harness 自动评分，测量变成厂商私有——"可比"只在同协议下成立。
5. **成本与噪声：** AI 负载遥测是传统服务的 10–50 倍（每次 LLM 调用产生 token 级指标 + 嵌套 span），规模化存储与抽样是工程门槛。
6. **评测盲区（接 #153/#165）：** SREGym / Incident-Arena 不测语义约定合规，投毒与命名漂移更无从度量。

## 五、展望与建议

- 把 `otel.*` 列为第 117 个市场空白字段族：`otel.genai_convention_version_pinned` / `mcp_span_coverage` / `cross_vendor_trace_correlation_rate` / `content_capture_policy_declared` / `agent_telemetry_default_on` / `semantic_convention_conformance_tested` / `benchmark_telemetry_portable`。六家零公开合规级别。
- **治理侧：** 要求厂商声明 GenAI 约定版本钉选与 MCP span 覆盖率；评测增"语义约定一致性"子项（接 #153 评测门禁）。
- **工程侧：** 统一用 `gen_ai.*` 命名、内容走 span event + Collector 层按策略剥离；prompt 默认脱敏、按需开启并留审计。
- **接本地原型：** 刘杨「Trace → 规模化实时评估」与蒋烁淼「中国式 AgentOps 可观测平台」可直接消费 GenAI 约定 span；朱革所提百度 AgentOps 缺统一审计 / 回滚，应与 OTel 审计事件对齐。
- **标准推进：** 推动信通院在 RCA / 自愈评测中补「语义约定合规达标率」格（延续此前各期建议）。
