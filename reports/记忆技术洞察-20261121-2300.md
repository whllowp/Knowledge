# 记忆技术洞察 · 第 134 期（20261121-2300）

**主题：记忆的「因果拘留」（online causal attribution）——不是问"这条记忆看起来危险吗"，而是问"把它中和掉，agent 的下一步会不会变"。前 133 期的投毒防护多在写入端（校验、来源、隔离、遗忘），共同预设"可疑内容≈有害记忆"；11-19 提交的 DriftGuard（arXiv 2611.25583，Licheng Pan／Yuzhou Chen／Zhixuan Chu 等 12 人，cs.AI）把判据移到服务时的检索端：逐条估计被检索记忆对潜在漂移的因果贡献，并让反事实重放只发生在离线，在线只做一次前向打分。与 #67 划界（那管投毒在共享层的爆炸半径，本期管一次执行里到底哪条是因）、与 #125 呼应（那让开发者看见 agent 用了哪条，本期让系统判出哪条改变了行为）、与 #126 呼应（证据可采信≠主张为真，本期中立内容≠无因果）。**

> 洞察范围：2026 年（近 30 天为主）。四维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

记忆安全的主战场正从"写入前过滤"移向"取用中归因"。因为多条相关记忆会与同一个有害动作共现，困惑度、检索相关度、注意力乃至输出有害性都是非因果特征；真正的问题变成：固定任务与上下文后，抽掉哪条会改变轨迹。趋势是把昂贵的干预留在训练侧，把因果结论蒸馏成可在线查表的风险分数——记忆税因此多出"离线因果标注"与"在线单次打分"两栏。

## 二、技术现状

DriftGuard 在每个动作节点从共享的动作前状态分叉：原始续跑与"只中和一条记忆"的续跑共享检查点、工具状态、环境快照与解码种子；中和由 LLM 去除可疑指令而保留良性事实。四条方向性事件构成记忆漂移分 MDS：动作改变、攻击消除、违规消除、任务恢复；R=3 次配对重放按分量多数投票去噪。在线风险模型用 Qwen2.5-7B 换四输出线性头、LoRA 微调，仅看动作前信息（查询、历史、其余记忆、候选、任务契约），取四个概率最大值超过阈值 γ 即中和该条再执行；每步取 top-4 记忆，γ 按基准留出集最大化 F1 后冻结。

## 三、技术竞争力

三个投毒基准、三种受害骨干上，DriftGuard 全面领先最强基线 Claude Opus 5 少样本排序。GPT-5.6 Luna 下 MINJA AUPRC 0.4993 对 0.3694、AgentPoison 0.6139 对 0.4768、MPBench 0.2415 对 0.1297（+86.2%，随机基线仅 0.0412）。在线防御中 Sleeper Memory 的 Mem2ActBench 攻击成功率 77.41%→3.25%、任务成功率 11.50%→56.13%。开销 1.52 秒/任务、986 防御 token、零额外 agent 重放，较 A-MemGuard 降延迟 75.4%、降 token 62.1%；直接反事实重放约慢 20 倍，且随候选数 K 增长差距扩大。

## 四、技术挑战

①单记忆干预不捕捉多条记忆的合谋效应，作者自陈。②中和虽保留事实，但换域与未见攻击下不保证仍安全。③在线耗时约 80% 来自命中后的重写，而非打分；γ→0 任务成功率崩塌，γ→1 攻击率回到无防御水平。④仅评工具型 agent、离线仍需 agent/工具/评估器重放，样本效率未解。

## 五、需求分析

运营方要的不是"这段记忆异常"的告警，而是可执行的定位：同一批召回里究竟哪条该隔离、哪条该保留。安全与效用必须同账——把全部记忆都改写虽降攻击率，却会摧毁正常任务；同时需要能向审计解释的依据，而不是一个黑箱风险分。

## 六、用户旅程

每步先召回候选记忆，对每条组装动作前输入并由风险模型打四个分；超阈值的条目被中和（删有害指令、留良性事实）后才交给 agent 执行。部署前用留出集标定 γ 并冻结；上线后按"攻击成功率、任务成功率、额外延迟与 token"四栏记账，并抽样保留被中和条目与反事实例证供复核。

## 七、具体实现方案

①因果监督离线化：配对分支＋四事件 MDS＋多数投票，只在训练侧付 K×R 次重放成本，在线零回滚。②四维头而非单分数：消融显示去掉 Action 掉分最大（AgentPoison AUPRC 0.6167→0.5690），去掉 Attack 最小（0.6032），近端动作差是最强监督。③上下文是有序状态而非通用 token：打乱历史（0.3851）比删掉历史（0.4746）更伤，风险判断依赖执行状态，深化 #131 的"模型条件"到"状态条件"。④验收：AML 增 online-causal-attribution 维度（逐条因果风险、ASR/TSR 双账、每任务开销、阈值审计），以"中和后行为是否改变"验收。五项目经 GitHub tag/release API 核实：OpenViking v0.5.5、Hy-Memory v2.0.17＋MemHub v1.0.8、TencentDB-Agent-Memory v2.0.4、dsh-memory-evolve v26092802、ReMe v0.4.2.3——均在写端做校验/来源/隔离，零在线逐条因果归因、零反事实派生监督，倒挂延续。反证：单记忆干预、工具型 agent、换域未验证，不作外推。

## 八、本期新观点

1. **检测单位从"内容可疑度"改为"逐条记忆的干预后行为差"**（接 #67／#54 划界）——高困惑度诱饵与看似平常的攻击端点案例证明内容特征非因果，投毒防御首次把定位做到单条记忆级。
2. **因果性可搬运：昂贵归因离线、廉价估计在线**（深化 #5 记忆税／#122 成本账）——MDS 把干预语义蒸馏进单次前向的 ORM，记忆税新增离线标注与在线打分两栏，但离线 K×R 重放仍是硬成本。
3. **方向性四维 MDS 优于标量风险，安全与效用必须同框**（深化 #94 评判偏差）——四个头缺一不可、去 Action 掉分最大；ASR 与 TSR 并列披露，避免"全量中和"式伪安全。
4. **同一条记忆的风险是执行状态的函数**（深化 #131 剂量适配到"状态条件"）——打乱历史比删掉历史更伤，说明 ORM 学的是围绕候选的结构顺序，不是把上下文当普通特征。
5. **阈值 γ 是可审计的安全—效用旋钮，须留出集校准后冻结**（呼应 #123 晋升门控）——两端各毁一侧，γ=0.033/0.081/0.093 逐基准标定，治理层应把阈值与校准集纳入变更记录。
6. **五项目倒挂＋AML 补 online-causal-attribution 维度**（接 #56/#69/#87）——五家零在线逐条因果归因、零反事实派生监督；补逐条风险、ASR/TSR 双账、每任务开销、阈值审计，以"中和后行为会不会变"验收。
