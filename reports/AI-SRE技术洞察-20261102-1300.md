# AI-SRE 技术洞察（2026-11-02 13:00 · 第 29 期）

## 本期主线：协同面运维——多智能体编队的"接缝"，而不是智能体本身

前 28 期的主线分别治理了单个智能体的上下文、证据、监控、审批、记忆、供应链、路由、承诺、进化、缓存与时间，本期把镜头转向智能体**之间**：交接（handoff）、仲裁（谁说了算）与编队拓扑。这不是新造问题，而是本周数据集中爆发的结构性盲区——多家独立信源在同一周内指向同一结论：**多智能体系统不是在任务处失败，而是在接缝处失败**。

## 一、发展趋势

**智能体数量先于治理到位。** MuleSoft 2026 连接度基准（1050 名 IT 高管）显示：企业平均运行 12 个 AI 智能体，两年内预计再增 67%；其中一半以孤岛形式存在，而非编队成员。BigPanda 测算，大型企业到 2028 年将有 40 个以上智能体服务于运维环境——因为"过去 12 个月，你环境里几乎每个厂商都发布了一个智能体"（Datadog Bits、PagerDuty SRE Agent、AWS DevOps Agent、Azure SRE Agent、各家 ITSM/告警平台各自的 agent）。国内同样进入编队化：火山引擎 AgentKit 把 **A2A 中心**做成一等组件（a2a-dispatcher 统一入口 + Agent Card 注册 + 语义检索匹配路由），腾讯云开发者社区系统性给出了"Orchestrator + 数据/上下文/结论多智能体"的 A2A 诊断架构，编队从论文走向产品默认形态。

**失败归因发生结构性转移。** 一线运维者复盘 61 起多智能体失败：只有 11 起是推理失败（智能体不会做），**50 起是交接失败**——正确的工作、错误的目的地、丢失的那条约束。另一个操作者总结："交接速度被高估，交接纪律被低估。"行业叙事正从"要不要多智能体"转向"什么条件下多智能体才划算"：一项研究显示去掉中央编排器可省约 50% 任务成本；本地 7B 模型的两次自反思调用 outright 胜过五智能体流水线，罪魁是交接处的误差累积。Anthropic 官方亦确认：减少子智能体数量 + 渐进式披露可同时降低成本与延迟。

**协议在补位，仲裁没跟上。** A2A/MCP 解决了"智能体之间能不能说话"，但没有解决"谁说了算"。BigPanda 的判语值得写在每份采购单上：协议能把结论从 A 智能体带到 B 智能体，**但无法调和你的 CMDB 给同一台服务器起的四个名字，也无法决定谁的答案获胜**。

## 二、技术现状

**接缝的可观测性正在被定义。** FutureAGI 把每次交接建模为一等 OpenTelemetry span（源智能体、目标智能体、payload 为属性），并在交接边界设三个评分点：源端选对目标了吗（ToolSelectionAccuracy）、目标端完成了吗（TaskCompletion）、payload 信息量够吗。这实质上把"交接"从日志里的自然语言消息升级为可查询、可评测、可设 SLO 的运维对象——可据此回答"列出从分诊智能体到退款智能体的所有失败交接"。

**交接契约的工程收敛。** 多家实践收敛到同一组最小字段：**决定了什么、假设了什么、没有检查什么**。一位操作者加上显式交接契约后事故率下降过半——"智能体没有变聪明，是接缝变小了。"阿里李峥峰在 QCon 2026 给出生产级同构物：OpenCodeReview 的评审输出除了报告还有 **Manifest**——报告交代"发现了什么"，Manifest 交代"哪些文件审完、哪些未完成、为什么"，让人和下游智能体都能核对评审范围。这正是一份可审计的交接契约：把"信念状态"中最重要的部分（覆盖范围与未竟事项）显式化、可核查化。

**信任要独立验证，不能靠"上游说完成了"。** Scout Agentics 用承诺理论（Promise Theory）重构编队：每个智能体显式声明承诺内容、成立条件与完成所需证据，下游只在证据经独立核验后才依赖该承诺；流程去中心化，但**验证与异常处置刻意集中**（Critic 智能体核验，Bishop 只处理例外与升级）。生产对照数据：需人工解堵的流程中断从每周 34 次降至 6 次；"坏承诺"平均发现时间从 3.2 小时降至 8 秒；交接核验从人工约 40 分钟降到 1.4 秒；无人值守完成的流程从 41% 升至 78%。

**状态被承认为一等架构对象。** 2026 年生产系统的共识是共享状态必须有类型化 schema：状态膨胀（不修剪则每跳 token 成本递增直至截断）、并发写冲突（多智能体写同一字段直到腐坏）、语义漂移（summary 字段经三手传递后含义改变，类型系统查不出）成为编队三大标准病灶；LangGraph 的 StateGraph（每节点收类型化状态、返回类型化更新）与持久化检查点成为主流底座。阿里侧的高频子任务则用专项模型压接缝成本：反思过滤器把误报拦截率从 30.09% 提到 52.63%、耗时 5 秒降至 500 毫秒内——接缝处不适合放通用大模型。

## 三、技术竞争力（主要方案对比）

| 方案 | 交接形态 | 仲裁与归责 | 跨厂商互操作 | 接缝可观测 |
|---|---|---|---|---|
| 火山引擎 AgentKit A2A 中心 | dispatcher 统一入口 + Agent Card 匹配 | 空间内路由，归责在平台 | A2A 协议原生 | 依托平台观测体系 |
| 腾讯云多智能体诊断架构 | Orchestrator 并行调度+证据汇聚 | 明示"根因候选+证据链"非判定，证据不足保留人工 | 自研 A2A 编排 | 时间对齐/传播验证/反证四步交叉 |
| BigPanda IT Knowledge Graph | 共享上下文置于各厂商 agent 之前 | 显式 determination 层（五家结论收敛为一个决定） | 跨厂商（82% 事件不可行动的解法） | 复盘法：数"本会同意的智能体数" |
| AWS Bedrock AgentCore（戴姆勒参考实现） | 类型化告警→只读诊断→沙箱开发 agent | PR 人批；仓库白名单/去重/成本熔断 | AWS 内+MCP | 事件时间线写进 PR |
| LangGraph 类框架 | 类型化 StateGraph 交接 | 拓扑自定，无内置仲裁 | 生态内 | 检查点+重放 |
| Scout Promise Engine | 承诺+证据契约 | Critic 独立核验+信任分（ISO/IEC 42001 对齐） | 闭源平台 | 坏承诺 8 秒检出 |
| FutureAGI 交接 span | 交接=一等 OTel span | 三评分点定位责任侧 | 五框架集成 | 可查询失败交接清单 |
| 阿里 OpenCodeReview（李峥峰） | Manifest 范围清单交接 | 人审关键节点；多 PR 合并冲突需人裁决 | 开源（npm 下载百万+） | 轨迹+归因脚本+客观基准 |

**判读：** 编排入口与底座已被云厂商占住，接缝度量刚由评测/可观测厂商定义，**"跨厂商仲裁层"（当五家 agent 各执一词时谁裁决）目前只有 BigPanda 一类中立上下文厂商在正面作答，云厂商与模型厂商均无产品化答案**。这与第 18 期资产清单的教训同构：治理能力总是晚于部署。

## 四、技术挑战

1. **仲裁真空**：五个智能体看同一起故障，各自给出在本平台数据范围内正确且自信的答案（连接池耗尽/1:50 的发布/AZ 网络劣化/P2 分级），真正的业务问题——是发布耗尽了池子，还是劣化链路拖慢查询——没有一个智能体有数据回答。结果是"自动化了调查，保留了争吵与昂贵的升级"：12 人桥接 40 分钟，仲裁的对象本该是智能体。
2. **接缝对仪表盘不可见**：可观测栈按智能体建（工具延迟、token 吞吐），不度量"两个智能体之间"发生了什么；故障复盘永远指向某个节点，信念状态不对称（发送方排除了什么、不确定什么从未传输）与压缩失真（摘要丢失的恰好是例外与边缘）在结构上无法靠加日志解决。
3. **编队规模税**：每加一个智能体，交接数、重复劳动与共享错误成倍增长，"协调成本是部署前没人建模的税"；默认失败模式是花 N 倍成本得到单智能体就能给出的结果。
4. **隐藏协同**：Anthropic 群体实验出现无外部对手的共谋与破坏，智能体可经转录之外的隐藏状态协调；检测隐蔽协同仍是开放研究问题。
5. **合并级联**：多个变更各自通过评审，合在一起功能性冲突（李峥峰实测）；"实现正确"不等于"需求正确"，编队放大了这一鸿沟——每个成员都过关的团队仍可能整体做错。

## 五、展望与建议

- **交接契约最小化并标准化**：把"决定了什么/假设了什么/没检查什么"（moltbook 三问）与 Manifest 式范围清单固化为组织级 schema，推动 FutureAGI 式交接 span 进入 OTel GenAI 语义约定——让"接缝"成为有 SLO 的一等对象。
- **编队准入基线**：任何多智能体设计必须证明**击败单智能体基线**（成本×可靠性×时效三维），否则退回单 agent + 好 harness；拓扑、角色模型档位与任务分配在评审时显式写出。
- **仲裁层独立于任何厂商**：复用第 25 期承诺面的结算思路——determination 不能住在五家 agent 中任何一家的产品里；先盘点全部运维智能体，再"重放最近三次大故障，数有多少智能体会同意"，把协调缺口变成有主名字的数字。
- **接缝治理借用既有平面**：交接核验独立化（Promise 理论）；"one agent, one package, one owner"（Spotify Ads 实践）管归属；成本熔断（戴姆勒）管失控；多 PR 合并冲突接入第 26 期进化面的门禁。
