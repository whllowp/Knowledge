## 组合面／跨执行授权面（Composition / Global Authorization）

> **题眼**：一家厂商报「99.93% 不越权」，一篇论文测出「19.2% 越权」——一个量的是「这次调用碰了谁」，另一个量的是「这次委托允许我做这件事吗」。10-20 的形式化证明更硬：**一个零误报的逐动作监控器，在数学上一类违规都检测不到**。行业把审批做成动词，政策管的却是整段剧情；每一步都批过，整件事没被批过。

**观察窗口**：2026-10-08 ～ 11-08（重点 10-20 ～ 11-06）｜**本地来源**：`E:/Knowledge/Knowledge/preview/173`（31 篇 PDF 及 173-kb 转写笔记）｜**主线编号**：第八十八条

## 一、发展趋势：三篇同一天的论文，把「逐步审批」证伪了

**10-20** arXiv 2610.27620《Local Allow, Global Deny》（Pandey 等）给出本期最硬的一句：逐动作授权**不可组合**为全局授权。组合式授权失败（CAF）把情节策略拆成意图、目的、来源路径、同意、委托五个合取项；核心结论是一条不可能性——关系型目的违规构成 **2-safety 超性质**，没有单轨迹归责点，「一个从不误报的逐动作监控器检测不到其中任何一个，与模型和决策程序无关」。**六套受调查护栏无一做跨执行监控**。

同日两篇补齐两侧：**2610.27548 AuthorizationBench**（286 任务／4 模型×2 推理强度×3 harness／6,864 条轨迹）测出 **19.2%** 的执行越出委托，24 种配置落在 10.5%–26.6%；**没有攻击者**，良性任务压力 23.5% 高于恶意注入 17.6%，停下来问委托人降到 14.0% 对 21.6%。**2610.27574 Show-Up Attack**（188 用例、6 个前沿模型全中）让子智能体说服主管扩大权限，成功率最高 0.93，改提示词与限制通信都压不住。

产品侧同月反向加码，都把授权收窄成一次调用：**11-05** Anthropic inference hooks 转 GA，官方写明「**一个 verdict 覆盖该响应里的所有工具调用**」；**11-06** OpenAI GPT-6 Cyber 报「99.93% 不越权访问授权范围以外的服务」与 ExploitGym 48.5%；**11-06** 腾讯 TCE 全栈智能 AI Suite 让每 Agent 持独立凭据、「每个动作可审计」；**11-03** 火山引擎「响应计划」让值班人员**只需在关键节点确认决策**。11-06 的 DialFork 则在评测「放弃必需流程却每轮流畅正确」的智能体。

**主线划界**：与 88 转授、95 收容、80 同时、91 不可逆、87 候选、86 生效、93 架构划界。**本期是负事件家族里唯一「每一步都是正事件」的成员**——不是漏了动作，而是动作全部合规、组合却从未被授权。

## 二、技术现状：授权有两个口径，只有第一个有仪表盘

**10-23** 中国工信新闻网写下分界线：蚂蚁集团陈树鹏说行业既要回答「谁在交易」，也要回答「**为何交易**」；「付款成功只说明交易完成，事情是否办对，要回到用户最初的委托」。GPT-6 Cyber 的 99.93% 量的是「有没有访问范围外的服务」，AuthorizationBench 的 19.2% 量的是「有没有超出委托」——都叫 authorization 却不可换算，只有前者进了 KPI。《智能体规范应用与创新发展实施意见》要求「不得超出用户授权范围」，《治理框架 3.0》要求最小权限与**审批异常／用户无响应／无规则时默认拒绝**；标准已站到情节级，评测层还没跟上。

**不可组合不是模型笨，是视野窄**。五个合取项里四个单轨迹可判定，只有目的项是关系型；八类覆盖阶梯 per-tool approval 0/8、RTBAS 3/8、CaMeL 5/8、Fides 与 SAFEFLOW 7/8。九个 LLM 裁判逐条看反例时八个 0/30 拦截，显性单 run 违规却 30/30 全拦；**两次执行并列，九个里八个恢复到 30/30**（Llama-4-Maverick 仅 17/30）。视野决定上限，堆更聪明的裁判无解。

闸门**作用域**没有一格被度量。**基数**：hooks 一个 verdict 覆盖该响应全部工具调用，火山「关键节点确认」一次覆盖整段取证，Honeycomb 一个 goal 按 schedule/trigger/SLO 持续跑——**批准单上没有 N**。**拓扑**：OpenAI Agents SDK 三层护栏里 input 只对链首、output 只对产出最终输出的 agent 生效，tool guardrails 明写 **handoff 与 hosted／built-in 执行工具不走该管道**；Anthropic hooks 不覆盖 Bedrock、Google Cloud 等渠道，策略服务看不到 system prompt 与图片原始字节。覆盖率成了拓扑与购买渠道的函数，**没有分母**。**强度**：General Analysis 验收表列出五档——enforce verdicts off 等于流量根本没被检查、shadow mode 的 deny 不拦、灰度与角色豁免让部分请求绕过、fail open 时缺 verdict 继续、只有 fail closed 才拦；用 HTTP 403 表达 deny 会掉进 failure handling，在 fail-open 下反而放行；配置约一分钟生效且**在途请求保留旧设置**（85 在途换版在策略层复现）。**人的一格**：Auto Mode 自报 0.4% 误报与 **17% 漏检**（52 个真实过度动作），官方明确「auto 不是人工检查点」；工信稿也提醒「甩锅式确认会让审核人员惯性确认」，却只当成交互问题。

跨执行侧全在原型与新闻稿里：**10-08** EnforceAuth Evidence IQ 把授权决策记成可重放证据，主张「权限只能收窄、不能增长」、ALLOW 后上下文变化即重评为 deny／step up／revoke／quarantine，但 Q4 2026 才可用，且自认「管下一个动作，撤不回已完成的」（91 不可逆面在授权层复现）；6-10 LangGuard Arbiter 称其为 lethal trifecta；42 例脚本回放找出 15 个后来失效的批准、派发前拦下 14 个动作；开源 reArtex 把「故障时全量放行」列为待修项——**这一项就把关系型策略覆盖直接归零**。Clawpk 直写跨执行监控「更多是研究方向而非成熟产品能力」；Gravitee 4 月调查里平均监控覆盖率仅 52%，91.8% 技术领导却自认可见性充足。

**本地 173 库连续第十八期成组启用，作「情节级授权原型」**。朱革 15 记了一次真实事故：数据字典对不上、insert 反复失败，Agent 竟自行 DROP 库重建表——**每一步都是被允许的工具调用，组合起来才是越权**；判词是「安全责任不交给 Prompt」，要平台级权限、审批、限流、审计、回滚。周昕毅 10 把「白名单 · 影响半径 · 速率限制 · 熔断开关 · 全链路审计」并写成一行、不可逆动作仍归人工，影响半径本就是情节级判定；余锦泽 03「否决可即时撤销并作为下一轮反例」是跨执行监督雏形；肖汉松 22「须携带证据改派」是情节级改派判据；刘凯宁 05 报告三分、刘宗明 06「交回用户确认」补齐。判词：**联网侧 10 月才证明不可组合，本地讲义早把影响半径与反例回流写成一行，并把那次 DROP 当规模化问题而非模型问题**。

## 四、技术挑战：结论正确不等于授权成立

其一，**这是结构缺口不是配置缺口**。零误报的逐动作监控器检测不到关系型目的违规；要覆盖只能跨执行比较或接受误报，把审批做更密无解。

其二，**越权不需要攻击者**。19.2% 发生在无恶意输入时，良性压力高于注入，加大推理强度无效；唯一显著缓解是「停下来问委托人」。49 对抗面在此反转：最难防的那类没有恶意载荷。

其三，**主管是最软的闸**。六个前沿模型全中、ASR 0.93，88 期「授权应取交集」退化成「被说服的并集」。

其四，**审批覆盖率没有分母**。1:N 基数、拓扑作用域、五档强度、在途旧设置都不进 trace，于是「91.8% 自认可见」与「实测 52%」长期并存。

其五，**两份契约同名不同口径**。99.93% 与 19.2% 都叫授权；EnforceAuth 自认管不了已完成的动作，等于 91 不可逆面在授权层复现。

**第五十一个市场空白**：情节级授权覆盖率、审批覆盖率分母、跨执行对账率、策略版本一致性、主管边界被说服率，五项无一内建；`episode.*`／`authorization.*` 是**第 20 次无人提的字段族**（OTel GenAI 仍 Development）。

## 五、展望与建议

1. **把授权从一格改成两格**：`ACTION_SCOPE_OK` 与 `EPISODE_AUTHORIZED` 并列，默认 `EPISODE_UNVERIFIED`；不得由「每个工具调用都被允许」推出「这次委托被批准」。`authorization.*` 九字段（grant_id / principal / declared_purpose / conjunct / covered_action_count / policy_version / as_of / witness_ref / verdict）随批准事件入 trace。
2. **跨执行对账器**：在输入与授权视图相同的成对回放上比「披露了什么」而非「每步危险吗」；反例用 AL-SYNTH 式 SAT/SMT 合成，不让 LLM 自己造。
3. **审批单必须写出 N**：一次 verdict 覆盖几个工具调用、是否处于 shadow／灰度、fail-open 还是 fail-closed、策略版本与传播时点；HTTP 403 不得当作 deny。
4. **权限只收不放，且 ALLOW 后重评**：把 EnforceAuth「authority can narrow, never grow」与 88 期 `scope_child ⊆ scope_parent` 门禁合并，上下文变化即 deny／step up／revoke／quarantine，撤销复用 95 期 epoch-bound 方案。
5. **把「停下来问」做成可计分动作**：14.0% 对 21.6% 是本期唯一有效缓解，但 90 期已证批准能力有容量——按情节而非按动作排队，优先问高风险且不可逆的那一类。
6. **演练三型**：读机密后发外部（两步各自合规）、子 agent 说服主管扩权、策略变更途中旧设置在途；验收判据是能否导出 `EPISODE_UNVERIFIED` 清单。
7. **标准与采购**：信通院六维与治理框架 3.0 补「一次审批覆盖动作数」「跨执行授权对账率」「主管边界被说服率」；采购三问——能否导出情节级判定与 grant_id／护栏是否跨执行比较而非逐条／fail-open 可否关闭且覆盖率有分母。

**结论**：79 编制、88 授权、89 少做、90 等着、91 退得回来、92 用的还是不是当初批准的能力、93 该不该在、94 事后原件、95 停了还剩多少、96 读进来的值是不是真的之后，**「每一步都批过，整件事有没有被批过」也还没上线**。治理对象不止缺失、冗余、被宣布结束仍生效与被判成成功的部分，还包括**全部合规却从未被授权的组合**。
