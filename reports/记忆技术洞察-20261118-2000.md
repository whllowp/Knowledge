# 记忆技术洞察 · 第 122 期（20261118-2000）

**主题：记忆的「读取粒度」（read granularity）——检索不只决定"取哪条"，还要决定"每条读多少"：段落整读还是只读一句，由"在已有锚点下还补了什么仍缺的证据"现场打分；同一来源的粗／细视图靠"补足同一缺失支持"自监督配对，把"读多少"从人工约定变成从记忆结构里学出来的决策**

> 洞察范围：2026 年（近 30 天为主）。四维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

前 121 期谈检索，默认决策轴是"取哪条、排第几、以什么形态存"——#109 找到≠排第一、#113 陈旧检索、#117 呈现位序、#121 表征升维。11-17 LMMR（arXiv 2611.22425，cs.CL）换问一层：同一来源要读多少？事实常散落在长记录里，周边文字吃掉小模型宝贵上下文。它把"读取粒度"立为与"来源选择"并列的一等检索决策：一条记录可整段读，也可只读承载关系的一句。与 #121 划界——那期管"以什么形态存"，本期管"以什么粒度读"；与 #115 划界——那期管任务内每步带什么，本期管跨记录取用时的粒度选择。趋势是记忆工程红利向端侧小模型倾斜。

## 二、技术现状

LMMR 把段落与句片段都挂回原来源，节点记来源标识、粒度、原文区间与文本，区间把粗细两视图连到同一出处。训练时：给定问题与锚点，若段落与句片段补足的是同一"缺失支持集"，就配成正例；高相关但不支撑的干扰、重复已知事实的片段作对比负例。取用时冻结相关分排初始锚点，以 Qwen3-Reranker-0.6B 加 LoRA（仅注意力 Q/V 投影，其余冻结）训出的条件重排器打"这个候选给锚点补了什么仍需的信息"，选择器在 token 预算内挑锚点加至多一节点（Ke=2），合并重叠区间、还原句序、附来源标签。

## 三、技术竞争力

22,398 条官方验证题（HotpotQA 7,405／2Wiki 12,576／MuSiQue 2,417），冻结 Qwen3.5-2B、400 token 预算：LMMR 得 61.47／43.26／30.58 F1，较查询扩展 +3.06／+2.14／+4.55，证据输入反降 23.1–26.9%。对同题训练的粗粒度检索器省 23.5–27.7% token；等输入长度下对"该检索器＋LLMLingua-2"仍领先 2.76／3.99／1.35 F1。八个 0.8B–4B 冻结答模型 F1 与 EM 全胜查询扩展与 MMR，Qwen3.5-4B 达 71.76 F1。50 段池下支持源召回 93.32%，用 185.24 token 对查询扩展的 240.95。

## 四、技术挑战

①省字与答对同向、证据完备却反向：严格支持完整度 77.87→72.99%、span-miss 升 2.57→9.59%——细视图保局部事实却不保段落全部标注支持句。②端到端延迟倒挂：Jetson Orin 上 token −21.6%、提示编码 −12%，但选择开销（A100 1081ms 对 691ms）使总延迟 2.27s 反高于 1.93s。③Ke=2 只加一节点、多跳链受限；30 段池、英文多跳 QA 非对话长记忆。④反证：单论文、LoRA 挂 0.6B 重排器、不作外推。⑤五项目倒挂：OpenViking v0.5.5／Hy-Memory 2.0.16＋MemHub v1.0.7／TencentDB v2.0.3／dsh v26092802／ReMe v0.4.2.3（11-05），零读取粒度／零边际增益打分／零同源配对监督，AML 无 multigranular-read 维度。

## 五、需求分析

端侧小模型上下文极紧，关键事实常埋在长记录的一句里，整段塞入则周边文字挤掉别的证据。用户要的不是"检索更多条"，而是"每条恰好读到够用的那段"：关系跨句时保留整段，关系在本地时只读一句。这是 #5 记忆税／#96 兑换率在"读多少"上的新缺口——既有系统把粒度写死（固定块／摘要），不随当前锚点与缺失证据动态伸缩。

## 六、用户旅程

问"Joe Buck 的父亲解说的是哪支球队？"。来源 A 说明 Jack Buck 是其父；第二事实藏在 Bob Buck（Jack 之弟）传记里一句"Jack 是圣路易斯红雀电台解说员"。查询扩展整段塞两段共 235 token，2B 模型只答出父亲名"Jack Buck"；LMMR 保留 Bob Buck 整段＋Joe Buck 一句，122 token 就答对球队。同一问题、同一模型，差别不在"取没取到"，而在"每段读多少"。

## 七、具体实现方案

三层契约：①表示层＝段落与句片段都挂回原来源（来源标识＋粒度＋原文区间），粗细视图可互指（接 #121 但落在读取侧）。②训练层＝以"补足同一缺失支持"把粗／细视图配正例、相关非支持与重复信息作负例，Qwen3-Reranker-0.6B 加 LoRA 训条件边际增益打分，监督来自记忆结构自身而非人工标粒度。③取用层＝冻结相关分选锚点、条件重排器打"补了什么"、选择器在预算内挑锚点加至多一节点并合并区间还原句序（深化 #109 从"找到"到"补了多少"）；AML 补 multigranular-read 维度（边际增益／支持完整度／span-miss／端到端 p50·p95）。反证：支持完整度反降、端到端延迟倒挂，不作外推。

## 八、本期新观点

1. **"读取粒度"是独立于"取哪条"的新一等检索轴**（接 #109／#113／#117／#121）：前 121 期默认检索决策是选记录／排序／呈现／存储形态，LMMR 把"每条读整段还是读一句"单列为并列决策——同一来源粗细两视图，粒度随问题现场决定。继 #121"以什么形态存"之后，这是"以什么粒度读"的新维度。
2. **打分从"相关度"改为"条件边际增益"**（深化 #109 找到≠排第一）：重排器不问"这条相不相关"，而问"在已有锚点下这条还补了什么仍缺的信息"；相关但重复已知事实的片段边际增益为零，即便"找到了、也相关"也不该占预算。
3. **"读多少"的监督从记忆结构自身挖，不靠人工标注**（接 #108 自监督信用）：粗段落与细句片段在补足同一缺失支持时配正例，段落—句子的天然对应即标签，相关非支持与重复信息作对比负例——把粒度选择变成自监督学习对象。
4. **省字与答对同向，但"证据完备"第三本账反向**（深化 #5／#96 记忆税、#113 指标倒挂）：F1 +3.06–4.55 且 token −23–27%，严格支持完整度却 77.87→72.99%、span-miss 2.57→9.59%——细视图保局部事实不保全部支持句，评测须并列披露三本账，只报 F1 会漏掉这笔隐蔽代价。
5. **紧预算与小模型放大粒度红利**（深化 #96 兑换率、接 #110 小模型+精确修复）：预算 400→220 增益 4.55→6.51、池 10→50 领先 2.80→3.15、八个 0.8B–4B 冻结模型全受益——记忆工程的红利恰在"读不起大上下文"的端侧最大，与大模型裸跑形成对照。
6. **省 token ≠ 省时间：记忆税要算"选择计算"这一笔**（深化 #5／#113 倒挂）：端侧提示编码 −12% 却被检索侧选择开销（A100 1081ms）吞回，总延迟 2.27s 反高于 QE 1.93s——须报端到端 p50·p95 而非只看 token；五项目全零读取粒度能力，AML 补 multigranular-read 维度（边际增益／支持完整度／span-miss／端到端延迟）。反证：单论文／Ke=2／30 段池／英文多跳 QA 非对话记忆，不作外推。
