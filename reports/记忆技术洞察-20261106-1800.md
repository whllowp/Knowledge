# 记忆技术洞察 第 14 期（2026-11-06 18:00）：记忆的缓存界面——注入一次排序，缓存全盘作废

> 系列定位：每小时一期 AgentMemory 领域技术洞察，固定五维结构（发展趋势 / 技术现状 / 技术竞争力 / 技术挑战 / 展望与建议），只覆盖 2026 年（尤其近 30 天）动态。本期为第 14 期。

## 一、发展趋势

前 13 期共享一个未言明的假设：记忆系统只要"把对的记忆送到对的会话"就算完成任务。本期补上结算层——**注入的字节稳定性决定最终账单**。核心命题：**检索排序的目标（相关性最大化）与缓存命中的目标（前缀字节稳定）方向相反**。主流前缀缓存按字节前缀匹配，注入块内一个字节变化即从该字节起全部 miss；而记忆检索天然按相关性动态排序，每次召回顺序微抖动都是对推理端 KV 缓存的一次清零。行业在 2026 年 10–11 月出现三股应对趋势：其一，**把"不破坏前缀"上升为目标函数**——TokenPilot（arXiv 2606.17016，浙大，已并入 LightMem2）首次明确"文本稀疏性收益会被前缀失配的重算惩罚吃掉"，主张在入口稳前缀、把结构变更推迟到任务相关性过期；其二，**把缓存修复下沉到服务端**——Leyline（arXiv 2606.01065）提供 KV 缓存指令原语，允许策略层主动删改一段缓存而无需全量重 prefill；其三，**把变更调度到窗口里**——Hy-Memory MemHub 的 nightly evolve 与 TokenPilot 的批次轮驱逐共同指向"日间只 append、夜里才结构化"的纪律。三股趋势汇成同一句话：记忆行业第一次认真对待"写入动作的读者成本"。

## 二、技术现状

生产侧的量级已经摸清。CorpusIQ 在生产 Hermes Agent 部署（DeepSeek V4.1 Flash/Pro）上两日窗口实测：字节稳定前缀约 45k token 时命中率 98.67%（Flash 98.70% / Pro 96.81%），miss 几乎恰好等于每会话一次冷前缀（约 47k token，仅占发送 token 的 1.33%）；DeepSeek 缓存读 0.003 美元/百万 token 对未缓存 0.15 美元，价差 50 倍，98.7% 命中下账单约为未缓存流量的 3–4%。反例同样精确：system 段插一个 `datetime.now()` 即保证永久 0% 命中。这套算术给出记忆行业的新约束——**成本主项是前缀体积×命中率的乘积，而记忆注入恰好位于前缀中段**。

研究侧三份关键结果界定了问题边界。TokenPilot 用入口压实（Ingestion-Aware Compaction）+ 生命周期感知驱逐（Lifecycle-Aware Eviction）在 PinchBench/Claw-Eval 连续模式降本 61%/87%，任务性能保持竞争力。Leyline 指出生产 harness 目前"每次编辑全量重 prefill"，其服务端拼接内核把重放命中提升 11.2 个百分点、时延最多省 241ms，十行截断规则经同一接口使 debug-gym 解题率升 14.3 个百分点。遗忘侧，Execution-State Unlearning（arXiv 2609.04875）证明：记忆删除后 KV cache 内的派生残留不除，指令式遗忘 Leak@probes=1.00，源文件涂黑仍有 80% 回合作用于已撤销偏好；精确遗忘需重算至少 T−τ+1 个转移，而溯源引导的选择性重放可达到全量重置等效、省 9 倍重算 token。

产品侧已出现首个明确承诺：OpenViking v0.5.3（11-02）的网关对注入内容**逐字节重放**，使 provider prompt 缓存与 thinking signature 保持有效；11-04 默认分支批次再加 query-driven CacheFS。Hy-Memory MemHub v1.0.6 的 lite/pro/ultra 三档加 nightly evolve，把记忆结构化演化集中到夜间窗口。TencentDB Agent Memory 则是反面镜鉴：其 issue #120 的 prompt 缓存失效问题至今未解，而其 Team Memory 的 Agent Loadout（把记忆资产绑定到不同 agent）使每个 agent 前缀互不相同——绑定集一动，注入集即变，缓存即作废。

## 三、技术竞争力

沿"缓存稳定性"轴对主要方案横向对比：

| 方案 | 注入确定性 | 变更窗口 | 缓存失效处理 | 与推理端耦合 | 证据等级 |
|---|---|---|---|---|---|
| OpenViking 网关 | 高（字节级重放） | 发布批次 | 保缓存+保 thinking signature | 协议层（base-URL） | 官方文档 |
| Hy-Memory MemHub | 中（夜间演化） | nightly evolve | 未承诺 | 本地运行时 | release notes |
| TokenPilot / LightMem2 | 高（入口压实） | 批次轮驱逐 | 目标函数级 | harness 内 | 论文+开源 |
| Leyline | 服务端接管 | 策略声明四元组 | 原语级（RoPE 修正） | serving 内核 | 论文（无产品） |
| TencentDB | 低 | 异步分层管线 | issue #120 未解 | Proxy 注入 | 公开 issue |
| ReMe | 中（文件轨） | reindex 显式重建 | 文件不重排即稳定 | 无耦合 | 文档 |
| dsh-memory-evolve | 低（回合内自审） | 会话内 | 无处理 | 插件注入 | 插件文档 |
| 通用 RAG 实践 | 视排序键而定 | 无 | doc-ID 确定性排序 | API 调用方 | 工程共识 |

三个梯队清晰：**有缓存承诺的**（OpenViking、TokenPilot/LightMem2）已把字节稳定性产品化；**有结构无承诺的**（MemHub、ReMe）依赖文件轨或夜间窗口的隐式稳定；**无处理甚至未意识到的**（TencentDB、dsh-memory-evolve）仍把注入当一次性拼接。值得注意的是能力与产品身份的关系再次倒挂（系列内第六次）：缓存原语最深的 Leyline 是纯论文，TokenPilot 是上下文管理框架而非记忆产品——记忆产品自己反而缺席。另一个结构性事实：文件轨（ReMe 的 Markdown 记忆）在缓存轴上意外占优，文件不重排则前缀天然稳定，这为第 5 期"三轨不可能三角"新增一条评分：**文件轨缓存最稳、参数轨最险**（参数轨写一次=所有会话的 system 段全变）。

## 四、技术挑战

1. **相关性-稳定性无联合目标**。"按文档 ID 等确定性键排序而非相关性分数（答案质量允许时）"已是 RAG 工程共识，但"质量允许"没有可操作判据，质量损失无基准可测——排序键选择的每一步都是盲走。
2. **遗忘的缓存债**。第 2 期的删除 3×3 矩阵没有缓存列：摘除/擦除/卸载三语义在 KV cache 里一个也没兑现。删除泄漏不降（Leak@probes=1.00）意味着第 9 期的闭环危害有了一条绕过文本层审计的隐藏通道——审计文本干净、缓存里全是旧的。
3. **TTL 与演化窗口的相位差**。主流缓存 TTL 是 5 分钟/1 小时级，记忆结构化演化是 24 小时级窗口；TTL 过期时刻与变更时刻之间的错配相位无人管理，命中损失白交。
4. **注入格式锁定**。thinking signature 依赖逐字节重放，等于把注入组装格式焊死——OpenViking 保住缓存的同时失去了重组注入的自由度。这是第 13 期嵌入空间锁定之后的第二个单向门：**换嵌入模型贵，换注入布局同样贵**。
5. **评测缺口第七次同构**。AML 三赛道无一含缓存维度：评测每次冷启动、命中为零，榜单分数不反映真实账单——同分系统在缓存轴上可以差 20 倍成本，分数结构性地看不见。

## 五、展望与建议

判读：记忆竞争正在长出第三个档位。第 6 期说采购从"看分"转向"看插座"，本期加上第三眼——**看账单**：在缓存定价下，能把注入做到字节稳定、把变更调度进窗口的方案，在真实成本上碾压榜单同分的对手；"结算层"将成为插座层之后的新战场。参数轨（Hy-Memory 30B 写入模型）在此轴上需要重新论证——写一次参数等于全员缓存作废，除非其写入频率低到可摊销。建议：①记忆系统输出确定性排序键并暴露 `injection_version` 字段，使上游能显式管理注入集变更；②变更集中夜间/批次窗口，日间只 append（MemHub 已示范，应成默认）；③删除 API 增加 cache_hint 字段，把"重算多少"变成调用方参数而非系统黑箱；④评测合同引入缓存命中维度，否则第八期以来的"口径缺口"清单上再添一项；⑤注入组装与 thinking signature 解耦，避免为保缓存而锁死布局。下期候选：AML 二期榜单口径（11 月中，最高优先）/ injection_version 首个实现 / TTL-演化相位差实测 / CacheBlend 类非前缀 KV 复用在记忆注入的适用性 / doc-ID 排序的质量损失基准。
