# 记忆技术洞察 · 第 86 期（20261114-2300）

## 本期主题：记忆的「多智能体内部分工 2.0」——MIRIX-2.0 用六类记忆智能体 + 溯源超图，把第 62 期的"预言"变成"实证"

> 承接第 62 期内部分工（记忆系统自身变多智能体，当时六项目零披露）/ 第 85 期程序进化搜索（MAPE 手设架构 vs 搜索架构），但把焦点从"是否该分"推进到"分完之后记忆的可靠性如何被架构改变"——本期管"多智能体分工带来的可归因性收益，而非仅组织风格"。

### 一、四维洞察

- **发展趋势**：记忆系统正从"单一存储/单引擎"走向"内部分工的职责分解"。第 62 期（11-12）曾预言"首个把记忆拆为内部 typed agents 的系统"（待验证 273），MIRIX-2.0（arXiv 2611.12068，11-09）成为首个落地实例：六类记忆智能体各自作为 system-of-record。这标志竞争焦点从"谁的单一库更准"迁移到"谁的职责分解让错误可被定位"。
- **技术现状**：MIRIX-2.0 给出具体实现——六类 typed memory agents 各自保有完整记录作为 system-of-record；provenance hypergraph 用 n-ary frames 索引情节/语义记录并引用其行；AutoDream 在写路径外合并重复锚点、绝不改写任何记录，并把任务会话蒸馏成技能；检索在显式预算下进行，证据量不随历史膨胀。在 LoCoMo 达 91.4%、LongMemEval-S 72.6%（领先基线 14.3pp）。五项目（OpenViking v0.5.5 / Hy-Memory 2.0.14 / TencentDB v2.0.3 / dsh v26092802 / ReMe v0.4.2.2）仍全为单 store/单引擎、零内部分工披露——倒挂延续（前沿在论文，产品缺席），但 MIRIX-2.0 是首个把第 62 期预言兑现的研究系统。
- **技术竞争力**：MIRIX-2.0 的差异化不在"更准"而在"更可归因"——当一条回忆出错，单 store 系统无法区分是写入错、合并丢信息、还是检索错；六类智能体 + 超图把故障定位到"哪个 agent 记错/哪条边引用错"。这是比召回率更贴生产的可靠性 SLA。AML C2 实时榜（11-19 开榜）仍无 principal/source/state_role 维度（接第 56/69/62 期）。
- **技术挑战**：①协调成本——六 agent 的写/读一致性协议与跨 agent 失效传播尚未被量化；②超图维护代价——n-ary frame 的写入与索引开销是否抵消可归因收益；③与第 85 期 MAPE 的边界：MIRIX-2.0 的六类分工仍是手设角色，未进入"程序进化搜索"空间，竞争轴从"手设架构"转"设计空间可搜"对它同样成立；④index/真值解耦（超图失败不回滚记忆）的边界条件未明；⑤五项目零内部分工，但 OpenViking 子树限定、ReMe wikilink 已隐含"局部性"，离 typed agents 仍有架构级差距。

### 二、需求分析

团队要的不是"再调一个更大的单库"，而是"当记忆出错时能说清错在哪一层、哪一记"。现有五项目都靠单一存储承载所有记忆类型，召回对了算功、错了无从归因，事故复盘只能靠人肉翻 .md。产品方更缺"职责分解 + 可审计血统"的方法论，导致要么精度够但黑箱，要么可解释但精度崩。

### 三、用户旅程

1. **分型**：把记忆拆为六类职责（情节/语义/程序/…），每类由一个记忆智能体作为 system-of-record。
2. **写路径外巩固**：日常写入只附加记录，合并/去重由 AutoDream 在写路径外重连超图帧，绝不改写证据。
3. **超图检索**：查询在预算内沿 n-ary frame 走引用边，定位到具体记录行而非整库。
4. **归因复盘**：出错时沿 provenance hypergraph 回溯到具体 agent 与记录，定位是写/合/检哪一步。

### 四、具体实现方案

- **职责分解**：把单 store 重构为 N 个 typed memory agents，各自持有完整记录（system-of-record），避免"全库一口锅"。
- **溯源超图**：用 n-ary frame 建 provenance hypergraph，每条记录引用其源行，检索与审计沿边进行。
- **写路径外合并**：AutoDream 式合并只在超图上重连/消歧，绝不重写原始记录（深化第 77/78 期"保真于写、裁决于读"）。
- **预算约束检索**：检索显式带 budget，证据量不随历史线性膨胀（深化第 83 期可用规模边界）。
- **AML 契约扩容**：主张评测纳 principal/source/state_role + recall-attribution 维度，否则继续漏掉分工式方案（接第 56/62/69 期）。

### 五、本期权观点（新视角）

①多智能体内部分工不是"组织风格"而是"可靠性架构"——第 62 期的待验证 273 被 MIRIX-2.0 实证兑现，记忆可靠性首次可被"归因"而非仅被"打分"；②溯源超图把"哪条记忆可信"从单点查询升维为沿引用边的可遍历断言，是比 DISCERN 双时态溯源更强的血统粒度（接第 78/80 期）；③AutoDream"合并只重连帧、永不改写证据"把第 77 期处方性整理/第 74 期遗忘保真度的"写路径保护"做成架构默认，价值在"被保护的原始"而非"被整理的副本"；④MIRIX-2.0 六类分工仍是手设角色、未进第 85 期 MAPE 的搜索空间，倒挂延续但研究已领先产品；⑤五项目零内部分工，AML 应补 recall-attribution 维度——竞争从"谁库更准"转"谁错得起、错得清"。
