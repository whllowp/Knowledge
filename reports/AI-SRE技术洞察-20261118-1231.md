# AI-SRE 技术洞察（第 281 期）

**生成时间**：2026-11-18 12:31（Asia/Shanghai）
**观察窗口**：2026-01 至 2026-11-18
**本期主题**：开关面／功能开关债务与 kill switch——最像“不用发布”的变更，最不像“有审计”的变更

## 题眼

2026-06-23 一次对公开仓库的实际扫描给出了一组不体面的数字：在 1,900+ 个引用功能开关 SDK 的 GitHub 仓库里，真正在代码里求值开关的只有 252 个（16%）；其中 25 星以上的 34 个样本里，**七个里有七个**带着至少一个陈旧开关。同一团队的年度行业报告（2026-01-07）把“陈旧开关占比”按成熟度分层：即便已有专用开关平台与清理流程的 200–600 个开关的组织，陈旧率仍高于 60%，并预测 2026 年平均陈旧率见顶于 65%–68%。开关不是没被管理，是**没人被指派去删除它**。

更严重的不是债务，是语义。2026-06-10 一份 ADR 记录了自家开关客户端“fail-open”的两种方式：一次刷新异常就把最后一份有效快照丢弃，所有检查落到空客户端、返回调用方默认值，而能力管道默认 `default=True`——**开关读不到时，功能是开的**。同月，AWS AppConfig 的 2026-09-30 审计指出一条配置投毒路径：实验定义把受众规则与对照/实验值叠加到已部署的开关上，**不创建新的 hosted configuration version**，也就没有一次“部署”留下版本记录；真正生效的是一条实验覆盖。

## 一、发展趋势

1. **开关从“发布工具”变成“生产控制面”**。AppConfig 类服务“一开始用于功能开关，一个季度后放连接串，一年后整个运行时配置都在里面，任何 profile 的变更 60 秒内进生产”——速度与灵活性同时成了威胁模型（safeguard.sh，2026-02-23）。

2. **评估侧开始产出“陈旧”信号，但语义各异**。LaunchDarkly 用 `status.lastRequested`、PostHog 用 `last_called_at`＋100% rollout、Harness 用 impressions、Flagsmith 默认关闭 flag analytics、Unleash 用 expected lifetime、ConfigCat 用“未被触碰/引用”的僵尸定义、GrowthBook 用 14 天曝光（2026-08-18 横向整理）。**“陈旧”没有统一定义**，所以清理率也不可比。

3. **实验覆盖绕过变更台账**。实验 API 把新值叠在已部署开关上而不产生新版本；这意味着“这周有没有变更”的答案取决于你查的是部署记录还是实验记录（HackTricks Cloud 审计，2026-11-08）。

4. **kill switch 的可用性没有被演练**。2026-10-02 一篇运维文把要求写得很清楚：kill switch 必须在故障中仍可用，健康检查不能只看进程存活（健康科技定价改错金额时进程是健康的）；每次求值要记录稳定 rollout 与规则修订号，**让“关掉”之后还能重建决策轨迹**。

## 二、技术现状

**第一层：开关是“不发布的发布”。** 它绕过发布流水线、绕过变更冻结、绕过代码评审——因为它“只是配置”。冻结期（本期前后文）挡得住 flag 写，挡不住实验覆盖与配置中心的其他 profile。

**第二层：关闭语义没有被证明。** fail-open 的默认值、缓存快照的 last-good、客户端本地回退，三者叠加后“开关为关”是一个推断，不是事实；ADR 里两种 fail-open 都是“读不到就当默认”，而默认恰好是开。

**第三层：求值日志与业务事件脱节。** 开关求值通常只留计数；事故里要回答“哪些用户被分到实验组、哪些账单按新规则算过”，需要把求值决策当业务事件记录（含 rollout 与规则修订号）。

**第四层：清理不是工作项。** 陈旧开关的根因不是懒，是“删除开关”从未被指派给任何人；没有 owner 与 expiry 的开关，寿命等于代码寿命。

## 三、技术竞争力

| 方案／机制 | 陈旧判定 | 关闭语义 | 实验覆盖可审计 | kill switch 路径 | 求值决策留痕 | 清理自动化 |
|---|---|---|---|---|---|---|
| LaunchDarkly | lastRequested | 客户端默认值 | 平台内可见 | 有 | 部分 | 有（code refs） |
| PostHog | last_called＋100% | 默认值 | 是 | 有 | 部分 | 弱 |
| Unleash | expected lifetime | **fail-open 风险** | 是 | 有 | 弱 | 弱 |
| Flagsmith | analytics 默认关 | 默认值 | 是 | 有 | 弱 | 弱 |
| ConfigCat | 僵尸定义 | 默认值 | 是 | 有 | 弱 | CLI refs |
| GrowthBook | 14 天曝光 | 默认值 | 是 | 有 | 部分 | 实验为中心 |
| AWS AppConfig | 无（配置版本） | 部署回滚 | **实验不产版本** | 有 | 弱 | 无 |
| 自建配置中心 | 无 | 取决于实现 | 无 | 取决于实现 | 无 | 无 |

**判读**：平台都能回答“这个开关最近有没有被求值”，没有一家能回答“**这个开关当前对谁、按哪版规则、以什么默认值生效，以及实验覆盖有没有进变更台账**”。而事故里要的正是后者。

**本期反转**：我们一直把开关当“降低发布风险”的工具——出问题关掉就行。实际开关把风险从“发布时刻”摊到了“每一次求值”：默认值错、快照旧、实验覆盖没记录、kill switch 没人演练，都会让“关掉”变成一个假设。**开关不是把变更变小，是把变更藏进求值路径。**

**判词**：「开关平台／SDK／实验 API／配置中心／清理扫描器／曝光分析」全部可采购，「这个开关此刻对谁生效、默认值是什么、实验覆盖有没有留版本、kill switch 上次演练是什么时候、关掉后哪些业务事实已经发生」不可采购。

## 四、技术挑战

1. **失效方向不统一**：fail-open 与 fail-closed 混用，默认值散落在调用方。
2. **快照与回退**：刷新失败时丢弃 last-good 是常见实现缺陷。
3. **实验覆盖无版本**：叠加值不产生 hosted configuration version，审计链断。
4. **陈旧定义不可比**：七家平台七种“陈旧”，清理率无法对标。
5. **kill switch 演练缺失**：故障中才发现控制路径依赖同一套健康检查。
6. **求值日志成本**：全量求值留痕昂贵，采样又会丢掉“谁被分到哪组”。

## 五、需求分解、用户旅程与实现方案

**需求分解（D1–D6）**

- D1 开关清单：owner、expiry、默认值、失效方向（fail-open/closed）、语义（release/experiment/ops/kill）。
- D2 关闭语义评审：每个 kill switch 明确“读不到时是什么状态”，并禁止能力管道默认 `True`。
- D3 实验覆盖入台账：实验值与受众规则写进变更记录，带 revision。
- D4 求值即业务事件：记录 flag key、rollout、规则 revision、用户/租户，按需采样。
- D5 kill switch 演练：季度演练“关掉”路径，验证不依赖被关闭组件自身。
- D6 清理进 backlog：创建开关即创建删除工单，超期自动提级。

**用户旅程（一次“关掉却没关掉”的定价事故）**

① 新定价规则在开关后上线，D1 只记录“owner=支付组”；② 刷新异常触发 fail-open，能力管道默认开，部分用户继续走新规则（D2 缺失）；③ 值班关掉开关，但实验覆盖仍在生效，账单继续按新规则算（D3 缺失）；④ 事后要回答“哪些账单算错了”，只有求值计数，没有用户级记录（D4 缺失）；⑤ 复盘发现 kill switch 与控制面共享同一健康检查，故障时打不开（D5 缺失）；⑥ 三个月后同一开关仍在，无人认领（D6 缺失）。

**90 天实现方案**

- **第 1–30 天**：开关清单与失效方向盘点（D1/D2）；把实验 API 的覆盖写进变更台账（D3）。
- **第 31–60 天**：求值即业务事件（D4），先从计费/权限/发布三类开关开始；kill switch 演练脚本（D5）。
- **第 61–90 天**：清理工单自动化（D6）；用一次真实事故回放验证“关掉后能重建事实”。

**第 202 个市场空白（五项）**：① 开关“关闭语义”标准；② 实验覆盖与部署版本的统一审计；③ 求值决策的业务事件模型；④ kill switch 可用性演练规范；⑤ 跨平台“陈旧”定义对齐。

**`flag.*`／`kill_switch.*` 第 169 次无人提字段族**：平台文档谈“如何评估开关”，不谈“默认值与实验覆盖如何进入变更台账”。

**本地 173／173-kb 连续第 157 期成组启用（余锦泽 03：开关要能回答“这一刻谁被分到哪一组”）**：本地原型把 flag 求值写入事件流（key/rollout/revision/tenant），kill switch 走独立控制面并季度演练；实验覆盖生成 change_id 与部署记录同级。
