# AI-SRE 技术洞察（2026-11-03 23:00 期 · 第 57 期）

**本期主线：指令面（说明书面）运维——AGENTS.md 是智能体读得最勤、组织审得最少的文件**

> 与前 47 条主线划界：23 期供应链管 MCP/Skill 装进前的审核，本期管随仓库分发、每次会话必装的指令文件本体；30 期知识供给管 runbook 腐烂，本期管"指令被忠实执行反而变贵"这一实证反转；27 期缓存面 tools_changed 是本期指令漂移的成本面镜像。

## 一、发展趋势

**指令文件从项目私有配置变成中立标准资产。** 10 月 22 日 AGNTCon + MCPCon 北美大会上，Linux 基金会旗下 Agentic AI Foundation（AAIF）收编四个新项目：Anthropic 的 Agent Skills、OpenAI 的 Open Responses、Hugging Face 的 OpenEnv、阿里巴巴的 OpenSandbox，一年内托管项目从 3 个增至 10 个（MCP、goose、AGENTS.md、A2A、Agent Router、agentgateway 等），成员超 300 家。其中 AGENTS.md 已被 6 万多个开源项目采用，仅 OpenAI 主仓库就有 88 个嵌套文件；Agent Skills 格式获 70+ 平台支持、发布技能超 100 万、安装近 2.8 亿次。趋势明确：**指令的治理权与指令的执行权正在分离**——格式交给中立基金会，执行解释权仍留在各厂商。

**实证出现反转。** ETH Zurich 团队 2 月发布首个指令文件严格基准（arXiv:2602.11988，AGENTbench，138 个真实 issue、4 个编码智能体）：LLM 生成的指令文件使任务成功率下降 0.5~2 个百分点、推理成本上升 20~23%；开发者手写的仅提升约 4 个百分点、成本同样 +19%。这与 Claude Code / Codex / Qwen Code 三家 `/init` 命令的默认推荐正面冲突——**厂商引导的默认实践，目前是负收益的**。

**分层装载成为共识。** Google Harness2 对编辑器的提示直白——"常驻散文是最贵的选择"，能用技能、脚本、子智能体就不要塞进 always-on 文件；Vercel 1 月评测显示未被点名的技能有 56% 从未被调用；SkillsBench（arXiv:2602.12670）测得人工策划的技能平均提升 16.2 个百分点，而模型自生成的技能平均收益为零。指令写在哪一层，比写什么更重要。

## 二、技术现状

格式割裂但语义趋同。当前指令载体超过 12 种：Codex 系用 AGENTS.md（外加 gitignore 的 AGENTS.override.md 本地覆盖），Claude Code 只读 CLAUDE.md（靠 @import 或符号链接桥接 AGENTS.md），Gemini CLI 用支持 @path 导入的 GEMINI.md，Cursor 用带 YAML frontmatter、按 glob 激活的 .cursor/rules/*.mdc，GitHub Copilot 用 copilot-instructions.md 加按路径生效的 .instructions.md，JetBrains Junie 用 .junie/guidelines.md。

三家机制细节值得运维侧记录：**其一，覆盖顺序即语义**——Codex 从仓库根向当前目录逐级拼接、最多每级一个文件、越近者胜，聊天指令永远最高；中文生态六工具（Cursor/Copilot/通义灵码/Trae/CodeBuddy/Qoder）共识也是项目规则压过全局。**其二，大小预算已硬编码**——Codex 的 project_doc_max_bytes 默认 32KiB；Anthropic 建议每份 CLAUDE.md 不超 200 行；Augment Code 的 AuggieBench 测出 100~150 行是甜点区、越线收益反转。**其三，忠实执行已被证实**——指令文件提到 uv，智能体使用率升至 1.6~2.5 倍；文件使其平均多走 2.45~3.92 步、推理 token 多耗 14~22%，但定位相关文件的速度没有任何提升。ETH 的冗余实验最具启发性：把仓库内其他文档全部移除后，同一批 LLM 生成文件反使成功率 +2.7%、反超人工文件——**指令文件的价值不取决于内容质量，取决于信息是否已可被智能体自行发现**。中文侧则演化出发布工程形态：团队在仓库外维护单一事实源目录，用同步脚本向六套规则目录分发，规则文件已经有版本一致性诉求。

## 三、技术竞争力

| 方案 | 指令载体 | 分层与覆盖机制 | 大小预算 | 治理归属 |
|---|---|---|---|---|
| OpenAI Codex | AGENTS.md + override | 根→CWD 逐级拼接，最近者胜；本地覆盖 gitignore | 32KiB 硬上限（可配） | AAIF（中立） |
| Anthropic Claude Code | CLAUDE.md | 项目/用户/子目录三级 + @import + 本地变体 | 建议 <200 行 | 厂商私有（技能格式已捐 AAIF） |
| Google Gemini CLI / Jules | GEMINI.md / JULES.md | 项目+用户+系统三级，@path 导入 | 未公布 | 厂商私有 |
| Cursor | .cursor/rules/*.mdc | glob 激活 / alwaysApply / 手动 | 目录制移除单文件 6K 字符上限 | 厂商私有 |
| GitHub Copilot | copilot-instructions.md + .instructions.md | applyTo 按路径生效 | 未公布 | 厂商私有 |
| 中文六工具（灵码→Qoder、Trae、CodeBuddy 等） | 各自 rules 目录 | 全局兜底、项目覆盖 | 全局建议 500 字内 | 厂商私有，SSOT 脚本分发 |
| AAIF / 社区 | AGENTS.md、SKILL.md | 嵌套最近者优先为跨厂商事实标准 | 无（由各 harness 自定） | 中立基金会，10 项目 |

判读：格式已收敛（纯 Markdown、无必填字段），但**装载语义、预算与三层叠加规则仍各厂一套**；跨厂商可迁移的只是文本，不是行为。Augment 的"一份好的 AGENTS.md 等于一次模型升级"与 ETH 的负收益结论同时成立，说明竞争力差异已从"是否提供指令文件"转移到"指令文件的工程化能力"。

## 四、技术挑战

**其一，忠实执行税。** 失效模式不是智能体不听话，而是太听话：多余指令转化为多余的测试、遍历与推理步。第 36 期"给每个函数加 span 是把问题搬进账单"在本期有了指令版——**给智能体每句建议都在为每次会话付费**。

**其二，指令解析链不可观测。** 没有任何一家厂商在轨迹/遥测中记录"本次会话装了哪些指令文件、多大、被谁覆盖、是否命中 32KiB 上限"。指令漂移（旧架构描述、已完成的迁移步骤滞留文件中）无检测手段，而智能体会用执行现行规则的忠实度去执行过期规则——这是 27 期 tools_changed 的指令面镜像。

**其三，自生成悖论。** SkillsBench 证明模型无法可靠撰写自己消费的程序性知识（自生成技能收益为零），ETH 证明 LLM 生成的指令文件平均为负收益，但三家 `/init` 仍在批量生产这类文件。工具默认值与实证结论的背离，本身就是运维风险。

**其四，指令是最便宜的投毒载荷。** 第 49 期已报道恶意 AGENTS.md 使 Codex 90% 以上遵循的野外案例；指令文件随仓库克隆分发、无需任何安装审批，是供应链攻击面里门槛最低的一环，而 AAIF 的 Agent Skills 安全指引 track 尚未落地。

**其五，企业级指令治理缺位。** 组织安全红线以纯文本形式散落在数百个仓库、六种格式里，无集中审计、无冲突检测（当全局与项目规则冲突时，各家裁决顺序不同）。跨仓库指令一致性与第 23 期"行为 pin"、第 30 期批准吞吐上限合流为同一缺口。这是本期判读的**第十五个市场空白：指令文件健康度（行数达标率/过期条目率/冲突率/单位指令采纳成本）无一家产品化**。

## 五、展望与建议

1. **建立指令文件健康度四 SLI**：行数预算达标率（按 100~150 行甜点区）、过期条目率（与最近一次相关重构的间隔）、三层冲突率、采纳成本（引入该指令后任务均价变化）。
2. **推动 instructions_loaded span 家族**进 OTel 语义约定：记录文件清单、字节数、版本、覆盖来源，让指令装载像工具调用一样可回放（与 39 期断网重放判据对齐）。
3. **写入规则收严**：按 ETH 的两问过滤器——只写代码不可见的歧义、或需高成本推断才能得出的信息；仓库概览类内容一律删（智能体自行发现不比读文件慢）。
4. **指令文件进 PR 评审门禁**，与 30 期 runbook 的复核四态共用机制；自生成文件须人工删减后方可合入。
5. **采购侧**：Agent Skills 已入中立基金会，技能资产可迁移性应写入合同条款；同时要求厂商公开指令装载语义（顺序、预算、冲突裁决），否则跨厂商行为一致性无从验收。
