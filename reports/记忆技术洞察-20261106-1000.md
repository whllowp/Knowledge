# 记忆技术洞察（第 7 期）｜2026-11-06 10:00

> 系列定位：AgentMemory 领域每小时技术洞察，聚焦 2026 年（尤其近 30 天）。前六期主线依次为：写入侧独立化 → 记忆的负空间（删除/注销）→ 可寻址性 → 切分单位（事件）→ 记忆净现值（经济性）→ 插座化（接入层）。六期都在讨论**存在的记忆**：怎么写、怎么删、怎么指、怎么切、多贵、怎么接。本期研究**不存在的记忆**：系统如何表达"没有"，以及它为什么表达不出来。

## 一、发展趋势：从"记住更多"到"承认没记住"

第一，评测口径的重心在偏移，但只偏移了一半。AML 二期官方博客的表述从"能存多少、召回多准"改成六条能力，其中最狠的一句是"目标不是记住一切的 agent，而是**知道什么不能再信**的 agent"；Memora（ACL Findings 2026）把惩罚"复用已失效记忆"写进指标（FAMA）；MEME 直接把"识别信息不存在"列为六项任务之一。缺席（absence）第一次成为一等对象，而非"其他"类别。

第二，工业界的痛点从"记不住"转向"记错了自己不知道"。压缩（compaction）审计显示：摘要器在追求"像人写的总结"时，系统性剥掉三类内容——精确标识符（报错串、路径、参数）、义务与疑点标记，以及**阴性知识**（已经试过并失败的修复清单）。后者一旦消失，Agent 会在同一个坑里循环重试：压缩边界后的第一个动作中，被阻塞/报错动作比压缩前高 0.108；终局正确完成率 37.3%（摘要）对 68.1%（FIFO 截断），而 Pass²（两次独立运行都成功）差距更大。

第三，工程侧开始把"缺口"当作可运维对象。Hy-Memory 的 MemHub 1.0.6 让写入**失败可重试、provider 宕机时暂停排队而非静默丢弃**；TencentDB v2.0.3-beta.1 加入可插拔决策服务与会话轨迹记录；ReMe 的 DSH 插件故障文档把"搜索无结果"拆成"源文件是否存在 → 派生索引是否健康 → 是否该重建"三步分诊，并写死一条纪律：**从源重建派生索引，永不迁就索引改写源记忆**。

第四，供给侧仍是单边的：至今没有一家把"我不知道"做成产品特性或 SLA。空位不在能力侧，在表达侧。

## 二、技术现状：空集的四种含义，接口上只有一种

**2.1 空集四义（本期框架）**

一个"没有"至少有四种语义：`∅_scope` 没观测过（不在采集范围）；`∅_store` 观测了没捕获（写入被判定为噪声、或写入失败）；`∅_recall` 存了没取到（检索失败）；`∅_world` 世界本来就没有。只有第四种能支撑否定断言——"你没提过这个偏好"是合法结论，"这个功能不存在"只有在覆盖范围被声明时才合法。而四种语义在接口层全部返回同一个空数组。于是模型面临一个无法解决的推断：拿到 `[]` 时，它必须自己猜这四种中的哪一种，而猜错的代价是幻觉。

这解释了 MEME 的结果：六个记忆系统在"缺席推理"上平均准确率 1%，"级联依赖推理"3%——不是模型不会推理"没有"，而是**输入里根本没有可用于推理"没有"的信息**。

**2.2 缺口不可分离，因此弃答无法校准**

端到端可得率 = 观测覆盖率 × 捕获率 × 召回率，三者相乘，且没有任何一项可单独测量。推论很硬：**调弃答阈值只能移动错误类型，不能提高正确率**——抬高则漏答变多，降低则编造变多；分母（"本应知道多少"）不可知，校准曲线无法闭合。这也是 LongMemEval 把 abstention 单列却始终只有个位数提升的结构原因。

**2.3 检测与修复必须分开测**

MemShift（arXiv:2611.02338，11-02）做了件此前没人做的事：把"发现输入变了"与"算出新的正确值"拆成两个可分别打分的量，用确定性打分器替代 LLM 评审，构造五种漂移分支——源修订、删除、重定义、**写入者切换**、**导出**。结论关键：检测只在修复能力允许的范围内有用，四个开源权重模型"重算"人定义派生值极少正确，而让模型写程序跑在结构化记录上能补掉大部分差距。第五种漂移值得单独看——导出即重定义：换格式那一刻，字段语义已被悄悄改写（第 6 期可携性问题的语义层回声）。

**2.4 缺口的下游表现：模糊指令与隐藏规则**

MemU-Bench（2611.00191）用 118 个"含糊任务"（用户自己忘了细节，只留残缺指令）测长程 GUI Agent：无历史时最强模型 Gemini-3.1-Pro 的 SPL 仅 16.4%，端到端 GUI Agent 低于 5%；补一个"按 App 组织的结构化历史库"后 GPT-5.5 从 15.7% 升到 66.9%。CLR-Bench（2610.40758）从另一侧印证：给定一条隐藏规则，六个自演化方法对"未见成员"的排除率只有 6-12%，而**保留原始实践日志**能到 20%，一行写明规则的提示能加 14.5-16.5 分。两篇说的是同一件事：填充缺口不靠更聪明的抽象，靠更完整的原始记录加一处显式声明。

**2.5 送达不等于使用（第 5 期"成本三段"应扩为四段）**

MemUse（2611.01718）在 8,000 条 SWE-bench Verified 轨迹上跟了三个记忆系统的每一次投递：解决率与"无记忆基线"相差不到 0.4pp，但绝大多数投递条目与任务无关，绝大多数相关条目从未被使用，两个系统里多数投递只是**复述模型仍能看见的内容**。更刺眼的是掩盖效应：23.2% 有正面记忆使用的情节仍然失败，16 个有害使用的情节里 5 个仍然成功。→ 价值链需要补第五段"采信"：判断→驻留→检索→**采信**，而采信成本为负（干扰成本），这解释了为什么"加记忆"经常不涨分。

**2.6 记录层不区分"沉默"与"被反驳"**

KLM 规范（2610.42066，11-02，v0.3）试图把"显式未知"写成一等字段（版本化认知评估 + 证据关系 + unknowns）。它自报的一个负结果极有价值：在区分"沉默"（从未有证据）与"被反驳"两类样本时，词法与作用域诊断的 AUC 都是 0.008——**远低于 0.65 的注册门槛**。也就是说，今天的记录结构里这两种状态几乎不可分——这正是 `∅_store` 与 `∅_world` 不可区分的技术证据。

**2.7 阴性知识需要独立结构，不能寄生在摘要里**

阴性知识的形态是清单而非叙事：`(动作, 前置条件, 结果, 失败原因, 作用域, 时效)`。摘要器偏好连贯、偏好"看起来重要"的近期内容，清单在它眼里就是可压缩的冗余，第一个被删。可行的工程解法只有两条：把阴性知识从摘要路径里豁免（白名单直通），或者按第 5 期结论把它挪到会话边界的结构化文件里（Anthropic 的 progress 文件即"已完成/已失败/下一步"三栏）。

## 三、技术竞争力：谁在表达"没有"

| 方案 | 空集是否分型 | 阴性知识留存 | 覆盖/范围声明 | 删除与"从未有"可辨 | 弃答接口 |
|---|---|---|---|---|---|
| KLM（规范参考） | 部分（unknowns 一等字段） | 未涉及 | 有（作用域诊断，实测 AUC 0.008） | 未涉及 | 规范级 |
| MemShift（研究原型） | 是（检测/修复分离） | 未涉及 | 分支化对照 | 删除单列为漂移 | 无 |
| ReMe 0.4.1.11 | 操作级（三步分诊文档） | 靠日志原文 | 源/派生分离 | 保留源文件 | 无 |
| dsh-memory-evolve | 否 | 项目日志可载 | 五轨作用域 | 归档可转回 | 无 |
| @guowenzhang/dsh-memory | 否 | 纯追加，不摘要 | `/memories` 目录 | **不可删（只增）** | 无 |
| Hy-Memory 2.0.14 | 否 | 代码 diff 链 | 三型记忆 | 权重覆盖，不可审计 | 无 |
| TencentDB Agent Memory | 否 | 轨迹记录（2.0.3-beta.1） | 四级可见性 + ACL | 版本覆盖，缺 valid_until | 无 |
| OpenViking v0.5.2.1 | 否 | L0 原文 | viking:// 路径 | **forget 永久删、无墓碑** | 无 |
| 阿里云 Memory | 未披露 | 未披露 | 用户/租户隔离 | 未披露 | 无 |
| Zep / Graphiti | 否 | Trace 事件 | 双时序 | 边失效不删 | 无 |
| Mem0 | 否 | 未涉及 | 三级作用域 | 未披露 | 无 |
| Redis Iris | 否 | Lens 回溯 | 租户级 | 审计可查 | 无 |

三点判读。其一，能力分布是三档而不是一条线：**有语义雏形的只有规范与研究原型**（KLM 的 unknowns、MemShift 的检测项），**有运维分诊的只有开源侧**（ReMe 的故障文档、纯追加插件的"永不删"），**托管服务几乎全部塌缩成同形空数组**——托管产品把复杂度藏起来了，也把"没有"的类型信息一起藏掉了。其二，一个反直觉的对照：@guowenzhang/dsh-memory 选择"永不摘要、永不归档、永不删除"，代价是无界膨胀，收益是不可能产生 `∅_store`（模型没写就是没写，不会被摘要吃掉一半）——**最笨的存储反而有最干净的缺口语义**。其三，删除与空集同形是共性问题：OpenViking 的 forget 是硬删且不留墓碑，删除之后系统无法回答"这条是从来没有过，还是曾经有过"——第 2 期讲的"负空间"与本期讲的"空集"在接口层撞成了同一个 `[]`。

竞争空位很清楚：**把"空集类型"做成 API 一等公民**。目前只有一份规范（KLM）和一份研究原型（MemShift），零产品实现。

## 四、技术挑战

1. **三率不可分离**，弃答因此不可校准；要修的不是模型而是覆盖面归因——必须先说清"看过哪些数据源、时段、租户"。
2. **阴性知识的作用域爆炸**：失败是条件性的（"在这个版本、这个配置下这么改没用"），条件组合会指数增长，且失败比成功更依赖上下文。
3. **压缩与清单的结构冲突**：摘要器天然反对清单；只要压缩路径不区分"叙事内容"与"约束清单"，阴性知识每次压缩都会掉一层。
4. **删除使空集与负空间同形**：无墓碑的硬删（OpenViking）与静默失效（Zep 边失效）都会把"曾有过"降解成"从未有过"，审计时无法自证。
5. **评测反向激励**：Mem0 公开 harness 把 LOCOMO 第 5 类 446 道"看着可答、实际不可答"的题（占 22.5%）整类排除在计分之外，答案提示里还写着 `NEVER say "not specified" … COMMIT AND ANSWER`；独立审计测得该 judge 对故意错答的过度接受率 62.8%。删掉题目 + 禁说不知道，等于**供应链没有动机去建否定能力**。
6. **采信不可观测**：MemUse 靠 agentic judge 逐条判影响，成本高、不可实时；线上答不了"这条记忆起了作用吗"。

## 五、展望与建议

未来 90 天，我判断"空集分型"会先在两个地方落地：一是开源侧的记忆协议（MCP 工具返回值从 `[]` 变成带 `scope_asserted` / `coverage` / `absence_type` 的对象），二是评测侧新增一列"越界断言率"（无覆盖声明却做否定断言的比例）——它比"正确弃答率"更好测，只需阴性样本，不需要分母。

给工程侧四条可立即执行的动作：

1. **接口层**：任何检索返回不得只返回数组。最小字段 `{items, scope: {sources, time_range, tenant}, coverage: {observed, captured, retrieved}, absence_type}`。
2. **存储层**：阴性库独立建表，键为 `(动作, 条件指纹, 作用域)`，压缩时进白名单；与事实库分开计费、分开过期。
3. **评测层**：在自有 fixture 上加两类样本——"从未提供过的偏好"（测编造）与"已明确删除的偏好"（测墓碑），两者的正确答案不同，混在一起测等于什么都没测。
4. **采购层**三问：空结果时你返回什么？能否给出覆盖范围与观测时段？删过的记忆会不会变成"从未有过"？三问答不上来的方案，不适合放进需要否定判断的场景（运维、医疗、法务、风控）。

最后一句判断：下一场竞争不在"记得更多"，而在"敢说没有"。这个能力没有分数回报，不会自己长出来——只能由采购条款逼出来。这与第 3 期"血统是纯成本项、推动力来自采购"是同一机制的第二次出现。
