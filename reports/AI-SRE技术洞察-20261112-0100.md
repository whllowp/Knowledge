# 第 133 期（2026-11-12 01:00）· 遮蔽面／自愈遮蔽面（Self-Healing Occlusion）——自愈把根因一起修没了；指标全绿，故障却没人见过

> 元层反转（换维度，而非补制度）：前 132 期逐层追问动作合规、审批、时序、证据、交接，本期首次把「自愈动作做完之后，根因还在不在、还有没有人能看见」立为一等运维对象。题眼「Scalence 2026：激进自动修复会在不清边界时掩盖根因、制造比原事故更难诊断的静默故障；可观测只到基础设施事件、不到决策——平台记录 CPU 飙了、Pod 重启了，却不记录为何触发修复、评估了哪些选项、套用了哪条策略」「HackerNoon 引 Dynatrace Grabner：所谓自愈是过度承诺，真实只是聪明的自动修复；无理解的恢复会掩盖根因、引入新故障模式、让工程师越来越读不懂自己救活的系统；EU AI Act 2026 年 8 月全面生效，要求持续监控输出质量而非仅可用性」。负事件家族里唯一「系统更绿了，却没人见过那次故障」的成员。

## 一、发展趋势

自愈正在从「重启 Pod」升级为横跨全栈的「自主修复」。Google Cloud Next 2026 的主题已从试点转向生产：「如何管理成千上万个 Agent」；携程披露配置自愈已累计 3,452 次。叙事主线清晰：能动手的 Agent 才是生产级。

但风险轴随之翻转：问题不再是 Agent 失败，而是它在错误的层次上成功——让症状消失，却让故障继续存活。可观测性必须从「基础设施事件可见」演进到「决策级可见」。EU AI Act（2026 年 8 月全面生效）要求持续监控输出质量，使「绿色但失明」从工程债变成合规债。评测基准也在错位：AIOps 基准量的是解决率，不是根因是否被保全。

自愈的成熟度正用「自治阶梯」衡量（Scalence 的 L1 建议、L2 低风险的自动执行、L3 策略约束下的高影响自动执行）。但当自治等级上升，治理与可观测的配套却没有同步：企业把 L2/L3 打开了，决策级审计却仍是空白。结果是「修得越快、看得越盲」——修复吞吐上升，根因的可见度反而下降。评测侧同样滞后：ITBench-AA、SREGym、SWEOps-Bench 等量的是解决率与一致度，没有一个把「根因是否被修复动作保全」作为指标，于是「靠藏根因堆出来的高解决率」在榜单上无从分辨。

## 二、技术现状

六家云厂商与 AIOps 平台都提供了 Agent 可观测（调用链、工具调用、Token、任务质量），但存在一个结构性缺口：可观测记录的是「系统做了什么」（指标/日志/链路），而不是「Agent 为何决定动手、评估了哪些选项、改了什么、留下了什么证据」。这是「无决策溯源的修复」。

自动修复还催生两种次生故障：其一是振荡（flapping）——修复触发检测、检测再触发修复，陷入反复重启；其二是「自愈进 obscure 状态」——系统被救活成一团工程师越来越读不懂的配置。更隐蔽的是：每一次自主修复动作，本质上都是一次未被治理的混沌实验，却没有混沌工程的受控条件。

更不易察觉的是取证痕迹的擦除：故障态的日志、链路、指标在被自愈动作覆盖后往往不再保留——系统记下了「已恢复」，却没记下「恢复前那一刻为什么坏」。根因分析依赖的正是故障态快照，而自愈恰好删掉了快照。再加上 Agent 给修复动作打出的置信度分数，容易让人误以为「高置信等于已根治」，而置信度只是模型自评，与「根因是否真被找到」并无关系。

## 四、技术挑战

1. 决策级可观测缺口：平台记录基础设施事件，不记录 Agent 的决策过程。
2. 振荡与 flapping：缺少冷却与迟滞，修复-检测互相触发。
3. 未受治理的混沌：每次自主动作都是一次无护栏的混沌实验。
4. 复盘错归因：根因被修复掩盖，事后复盘系统性误判（VentureBeat：静默中断企业普遍漏记）。
5. 绿但盲：可用性 100% 可伴随质量静默降级（EU AI Act 直指此点）。
6. 基准错位：评测量解决率，不量根因保全率。
7. 信任赤字：Lightrun 调研 77% 工程负责人对现有可观测支撑自主 RCA 低信心，98% 对生产 AI 信任低于编码助手。
8. 取证痕迹擦除：故障态快照被自愈覆盖，根因分析失去原料，事后复盘无从还原。

## 五、展望与建议

- 字段族 `remediation.*`／`occlusion.*`：remediation_id、trigger_signal、options_considered、action_taken、evidence_before、evidence_after、root_cause_preserved、decision_owner。
- 每条自主动作带决策级审计（关联 ID + 决策日志），把「为何触发/评估了什么/改了什么」写进链路。
- 爆炸半径感知的修复 + 冷却/迟滞，打断振荡；自愈进 obscure 状态须告警。
- 修复后强制冒烟验证 + 根因捕获，未保全根因不得标记 resolved。
- 把每次 Agent 动作当受治理的混沌事件：爆炸半径建模 + 自动中止条件。
- 评测新增「根因保全率」而非仅解决率；信通院六维补「自愈决策可溯源率」「修复后根因保全率」。
