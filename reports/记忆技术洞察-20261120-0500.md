# 记忆技术洞察 · 第 128 期（20261120-0500）

**主题：记忆的「优化器记忆」（self-improvement memory）——记住"改动的理由与预期",而不只是"改动本身"。前 127 期的记忆主体都是解题 agent(存什么/取哪条/读多少/看多清/怎么交接);11-13 SIM(arXiv 2611.18856,Xin Yu 等 10 人,cs.LG/cs.AI)把镜头上移到"改进 agent 的优化器":换基准、换模型后 harness 代码还在,但当初为什么改、预期修好什么、实测效果如何都不在代码里。SIM 按复现问题分组记录每次编辑的理由、预测与实测结果、评测上下文,让续跑知道哪些该留、改、换、删。**

> 洞察范围:2026 年(近 30 天为主)。四维度:发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

#119 问"记忆怎么改由谁设计",主体仍是解题 agent 的记忆结构。本期主体上移到元层优化器:趋势从"给 agent 记经验"到"给优化器记优化经验"。代码可跨基准迁移,理由却无法从代码反推;CRSI(持续递归自我改进)要跨兼容基准与策略模型续跑优化,记忆必须跟着改进过程走,而不只跟着任务走。

## 二、技术现状

SIM 条目 mᵢ=⟨根因假设 cᵢ,[(修改及理由 a,预测与实测结果 o,出处 p)]⟩:按反复出现的 harness 问题分组,p 记领域/基准/策略/轮次。哪几个任务会被修好的预测须在评测前登记、事后核对;提案与选择者全量读 SIM,不检索、不截断。只记录被采纳的候选,含回归或未修好者;同根因合并但不丢历史;无采纳则记忆不变。四对照:冷启动、纯 harness 迁移、只留根因、完整 SIM。

## 三、技术竞争力

四域六组跨基准:完整 SIM 全部最高,超纯 harness 2.43–4.35 点、超只留根因 0.20–6.06;只留根因有正有负(−1.82 至 +2.40)。跨模型 Opus 5.5→Gemini 3.8 Flash:继承 harness 四域全部低于种子(差 0.60–5.48),SIM 超纯续跑 3.60–11.33(工作区同起点 68.41→84.75 对 73.42)。编码十对独立续跑:共同起点 18.36,无 SIM 19.33、有 SIM 21.70,均 +2.36(95%CI[1.05,3.68],p=0.003,9/10 胜)。代际链三组中两组胜(+3.5/+1.6),4 Argon 反低 0.8。

## 四、技术挑战

①只留根因不够——诊断必要非充分,改动史与评测证据才是增量。②预测须先于评测登记,否则事后归因不可验证。③自修改 harness 可骗过 verifier 而不解题,工作区评分还带 LLM 评委偏差。④继承 harness 可能比冷启动更差(72.92 对 75.72),收益非单调、跨代会回退。⑤五项目倒挂:OpenViking v0.5.5、Hy-Memory 2.0.16＋MemHub v1.0.7、TencentDB v2.0.4、dsh v26092802、ReMe v0.4.2.3 全做解题 agent 的记忆,零优化器编辑史、零预测—实测对照、零跨模型续跑账,倒挂延续。

## 五、需求分析

harness 靠自动优化迭代。换基准或模型重跑时若只继承代码,优化器会重复已失败的尝试、删掉当初有效的功能——"需求沿用,实现要重写"。用户要的是:改动背后的理由与预期—实测落差可携带;续跑据此判保留/修订/替换/删除;且失败与回归尝试也要留,不能只留成功经验。

## 六、用户旅程

优化器在 TB2.1 上进化出"提前判定完成"门控;换到 TB4 续跑。带 SIM 的提案者读到该门的理由与源基准实测,保留完成验证、补"可行 vs 最优"检查;不带 SIM 的续跑反而收紧门控、两次修补完成死锁,还把继承的门误记为自己首轮发明。另一例:交付物与 verifier 接口不符,SIM 在第 5、6 轮同一诊断下追加修订与实测,保留源尝试与未解预测。

## 七、具体实现方案

①条目层:mᵢ=⟨根因,[(修改+理由,预测/实测,出处)]⟩,预测先于评测登记,采纳即追加(含回归),同因合并不丢历史,空采纳不更新。②使用层:提案者与选择者全量读 SIM,提案须引既有根因或命名新根因;迁移对每条继承编辑判保留/修订/替换/删除,历史不删。③评测层:四对照＋配对续跑(共同起点、同预算),报终分、Δ 与 CI,把"源提升≠目标起点提升""负迁移率""跨代单调性"入账。AML 补 optimizer-memory 维度(编辑复用增益/诊断—全记录差/跨模型 Δ/负迁移率)。反证:仅编码多次重复、余域单跑、接口须兼容、规划固定、SIM 整体不可拆继承与目标更新、verifier 可被钻空。

## 八、本期新观点

1. **记忆主体从解题 agent 上移到优化器 agent**(接 #119 划界)——前 127 期都管"解题时记什么/怎么取",本期管"改进解题器的那个 agent 记什么";这是"谁在记"这一新轴,不是又一种记忆内容。
2. **可复用的是"改动＋理由＋预测—实测",不是 harness 代码本身**(深化 #126)——#126 说技能信任要带证据,本期把同一逻辑推到"改进经验":代码迁移后理由不可反推,只留根因反而有负迁移(−1.82)。
3. **预测—实测落差是编辑级自监督信用**(深化 #108)——#108 在动作级用期望/实动作信用,本期上移到编辑级:预测先登记、评测后核对,不靠环境奖励就能判一条改进该留该换。
4. **失败与回归记录必须留,诊断不是充分条件**(深化 #114)——只采纳候选也记回归、未修好者,同因合并不丢历史;删掉"失败尝试"就丢掉优化器避免重蹈覆辙的唯一凭据,与代价敏感遗忘的非对称同构。
5. **继承需求、重写实现,且迁移非单调**(接 #104/#119/#126)——门控案例"需求沿用、实现要重写";继承 harness 可比冷启动更差(72.92 对 75.72),代际链 4 Argon 反低 0.8,"持续优化会一直变好"不成立。
6. **五项目倒挂＋AML 补 optimizer-memory 维度**——五家零优化器编辑史、零预测—实测对照、零跨模型续跑账;补编辑复用增益/诊断—全记录差/跨模型 Δ/负迁移率,以"续跑是否更好"而非"单次是否答对"验收。
