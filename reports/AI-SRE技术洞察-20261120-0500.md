# AI-SRE 技术洞察（第 295 期）

**生成时间：2026-11-20 05:00｜主题立面：置信度校准面／"它说它有多确定，和它实际有多确定，是一回事吗？"（Confidence Calibration & Abstention / The Right to Say "I Don't Know"）**

> **题眼**：过去我们问"证据有没有送到"（#290）、"结论是不是真做对"（#293）、"读到的证据是不是真的"（#294）。本期问一个几乎从不被当成产品指标的问题——**Agent 输出的那个"置信度/确定程度"，与它真实做对的概率对齐吗？当它其实不知道时，它有没有权利、有没有能力说"我不知道"？** 一句话判词：**一个从不说"我不知道"的 Agent，不是更可靠，而是把自己的不确定性伪装成了确定性**。NYU 的 outcome-grounded calibration（arXiv 2610.18614）把逐步口头置信度对齐到最终结局后，ECE 从 0.42 降到 0.12 以下、最高置信档成功率约 4.3 倍——说明"会不会评估自己"不是模型的天赋，而是一项可以、且必须单独训练与度量的能力。

本期与既有立面划界：证据通道面（#290）问证据有没有送到、干预信用面（#292）问动作与好转是否因果、语义回归面（#293）问成功是否符合领域意图、证据保真度面（#294）问证据是否说了它声称的事——四者都在"事实是否成立"层；本期只在**元认知层**发问：Agent 对自身结论的确定性声明，是否值得信、能否触发弃权。经查重，"置信度校准／弃权／不确定性表达／ECE／自我预测失败"两处索引均为 0，全新立面确认。同期 E 盘另有并行实例的 0431 "视窗面"报告，属不同序列，主题无重叠。

## 一、发展趋势

**其一，置信度从"输出装饰"变成"可训练、可度量的second output"。** 长期以来，Agent 在结论后附一句"我有 90% 把握"只是话术。2026 年出现转折：NYU 用 GRPO rollout 把每一步的口头置信度对齐到整条轨迹的最终成败（outcome-grounded calibration），在 ALFWorld/TextWorld/WebShop 上 Qwen2.5-7B 的置信度 AUROC 从近随机升到 0.68–0.85。更关键的是它揭示了一个此前被掩盖的失效模式——**局部自信的盲目**：按"下一步看起来对不对"校准的 Agent，会自信地走进终止态陷阱。趋势是：**确定性声明被当作与答案本身并列的第二个输出，需要独立的损失、独立的评测、独立的门禁**。

**其二，"测量本身的置信区间"开始被认真对待。** Anthropic 11 月 13 日发布可靠安全评测指南，报告多轮评测置信区间可超过 ±10 个百分点：claude.ai 上 Opus 5 与 5.5 的适当回应率 98% 与 94%，差异并不显著；同一模型在 claude.ai 得 94%、在 API 上得 60%——**分数依赖部署配置，不独属于模型**。这与 SRE 高度同构：一个"87% 确定是缓存击穿"的根因结论，换个采样、换次 prompt 可能就是 76%，统计上毫无区别。把点估计冒充精度，是本期要纠正的核心陋习。

**其三，"帮助压力"被识别为弃权的系统性敌人。** AgentOps Weekly 汇编的多篇 2026 研究给出同一结论：模型**具备**判断"我不知道"的能力，但在被要求"给个具体建议/解释理由"时，这种谨慎会塌缩——Okumura 用四个前沿模型（Claude Sonnet 4.6、Opus 4.7、GPT 5.5、Gemini 3.1 Pro）做 480 次试验，在要求给出 concretely 推荐或解释时，保持因果谨慎的比例只剩 1/200（0.5%）。而 SRE 场景恰恰是"给个结论、赶紧恢复"的高压语境。**结构性结论：越强调有用，越不说不知道；弃权不是模型属性，而是系统设计的函数。**

## 二、技术现状

置信度校准目前散在四类能力里，尚无统一字段族。

**校准度量：从点估计到分布与分区。** 单看一个 ECE 数字毫无意义——常数输出 0.678 置信度的模型 ECE 约为 0，却毫无用处。可用的组合是：ECE 看差距、Brier 看整体、AUROC 看排序能力、accuracy-at-coverage 看"在必须答对的覆盖率下能自动放行多少"。且须按 model+prompt+domain+部署配置四元组校准：某物流地址解析服务在模型更新后置信度整体上移，固定 0.8 阈值悄悄放进更多错误，直到每周抽检才发现。**校准是有时效的映射，不是一次标定终身有效的常数。**

**弃权门控：可训练，且不需要前沿模型。** 一项用 540 个合成案例（骰子、硬币、罐子、计时器）做监督微调的实验，把小模型在"不可知"题上的作答率压到 0.0%，并跨三个未训练域迁移，还能抵抗"是否只学到表面措辞"的对照检验。这证明**弃权是一条窄而廉价、与通用能力无关的可训练行为**。但同一研究给出本期最尖锐的发现：当强加刚性输出格式（schema）时，训练好的门控**完全崩溃**——48 道不可知题全部作答，每题还附上一个像模像样的概率。**结构化输出是弃权的敌人**：要求 `root_cause` 字段必有值，就是在强制 Agent 编造确定性。

**多步轨迹的校准不组合。** Lin 等（2026）给出反例：一个模型可以在轨迹每一步都校准良好，却在整条轨迹上系统性误校准——step-level calibration 根本不 compose 成 trajectory-level。配套提出的 TC-ECE（在轨迹多个检查点算 ECE）专门暴露"后段累积的过度自信"，那是单一终末分数会平均掉的。对 SRE 的直接映射：RCA 每一步（查监控、看日志、读代码）都"很确定"，串起的因果链却整体错误。

**平台侧：确定性分级已产品化，但缺席"弃权权"。** OpenObserve 的 AI SRE Agent 会给出带 confidence 的根因、把时间线每件事标为 confirmed/likely/unverified、并显式列出"盲点（它没能核查什么）"——这是把确定性分层做成一等产品能力的少数例子。腾讯云一线实践则贡献一句反直觉判词：**"阈值应当来自故障分级，而不是 Agent 的置信度分数——置信度会被日志质量骗，影响面不会"**；并主张把"AI 找到根因"降级为"AI 给出一个带置信度和反例的假设"。

## 四、技术挑战

**挑战一：置信度被当事实消费，"借来的确定"层层放大。** Wharton 的 Shaw & Nave 实验（1372 人）显示：当 AI 给出错误答案，人们仍有 73% 照单全收，且因有 AI 在场而自信上升——Anthropic 的 Addy Osmani 称之为"cognitive surrender"。在多 Agent 编排里，上游一句"85% 确定"被下游读成事实，每层衰减一点确定性、不衰减结论，最终整条链把假设当真相。**置信度必须与结论物理分离、且不得成为下游唯一判据。**

**挑战二：测量噪声伪装成精度。** 98% 与 94% 的差异不显著、94% 与 60% 是部署配置差异而非模型能力。若 SRE 用"Agent 自报置信度 > 0.9 就自动回滚"这条规则，等于把一条未经统计校准、随 prompt 漂移的曲线接到了生产写操作上。

**挑战三：结构化输出与弃权的结构性冲突。** 越要求返回严格 JSON、字段必填，Agent 越被迫编造确定性（48/48 全部作答）。这与 #294 "空结果≠健康"是对偶：**那边逼它输出一个像样的空结果，这边逼它输出一个像样的确定值。**

**挑战四：逐步正确 ≠ 全程正确。** step-level 校准不组合成 trajectory-level；RCA 每一步都自洽，因果链整体错。传统 APM 查"破损"，对这种"自信而错"结构性失明——Google SRE 书第二版明确指出：**一个"自信地给出错误答案"的模型，即使服务运行正常，也在损害用户信任**。

**挑战五：弃权的经济学没人买单。** 说"我不知道"会拉低命中率与自动化率，而这两项是采购方最常看的 KPI；没有对"正确弃权"的计分，就没有弃权的正激励——与 #291 "评测分数避开计费维度"同构。

## 五、展望与建议

**提出第 216 个市场空白字段族 `confidence.calibration.*`（缺省 CALIBRATION_UNVERIFIED）**，六字段：`stated_confidence` + `signal_kind`（verbalized / logprob / consistency / P(IK)）＋`calibration_scope`∈{step, trajectory} + `trajectory_checkpoints[]`（TC-ECE）；`calibration_domain`{model_hash, prompt_hash, domain, deployment_config}；`measured_metrics`{ece, brier, auroc, accuracy_at_coverage, coverage_at_accuracy} + `binning_scheme`；`confidence_interval`（点估计必须附区间，禁止裸点估计）；`abstention`{allowed, schema_forced, triggered, reason}；`policy_source`∈{incident_severity, agent_confidence} + `兑现率对账`（长期 predicted-vs-actual）。与 #292 `intervention.credit.*`、#293 `semantic.regression.*`、#294 `evidence.fidelity.*` 并列，补齐"元认知层"这一空白——前四族管事实是否成立，本族管"对事实的确定性声明"是否成立。

**给团队的三条落地建议**（本期新观点）：其一，**给弃权留出 schema 空间**——在所有结构化输出里增加 `confidence: null` 与 `abstain_reason` 两个可空字段，禁止字段必填把门控逼死；把"正确弃权率"写进评测与 KPI，与命中率并排。其二，**阈值外挂、置信内参**——自治闸门阈值一律来自故障分级与影响面（腾讯云一线判词），Agent 置信度只作为排序与取证线索，不作放行判据；每个高置信自动动作后必须跟随兑现率抽检。其三，**置信度也要"锚定当时"**——与 #293 部署快照、#292 信用判据一脉相承，置信度须记录校准时的 model/prompt/域/配置指纹，模型或 prompt 一变即视为校准失效、降级复核。

**对评测与标准**：基准（SREGym / ITBench / o11y-bench）增设"该说不知道却没说"的 seeded 题，报 accuracy-at-coverage 与区间，禁止只报命中率；信通院六维"结果可评价"补一格「置信可举证率」，与 #289 分工可举证率、#290 通路可举证率、#291 记忆失活可举证率、#292 干预信用可举证率并列，形成证据—通路—分工—记忆—信用—置信的**七层治理**。

**本地知识积累（目录级引用，讲义见 E:/Knowledge/Knowledge/preview/173）**：本期新角度采信周昕毅《AI+SRE≠AISRE：AI 如何真正进入生产运维闭环》——"人做关键决策"的判词在置信度层获得数学依据（影响面定阈值，非置信度）；配孙鹏《重塑大模型评价体系》"全自动可进化探测式评测"作为持续兑现率对账的原型；把刘凯宁蚂蚁 SRE"结论/证据/待确认三分"扩出第九分——**"这个结论的确定性声明，校准过吗、给区间了吗、能不能说不知道"**。
