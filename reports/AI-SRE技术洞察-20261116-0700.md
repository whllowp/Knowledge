# AI-SRE 技术洞察报告（第 208 期）

## 遥测供给面／输入天花板面（Telemetry Supply Ceiling / Input-Bounded Diagnosis）
### ——Agent 只能诊断供应商决定让它看见的那部分；越是被保护的数据，越是它天生看不见的地方

> **题眼**：Google Cloud 2026-11-13 上线"客户自有 BigQuery 表"的 Agent 可观测，官方提示里藏着一句该读写两遍的话——每轮之前执行 **fail-closed 检查：知识源一旦启用行级安全（RLS）、列级策略标签或动态数据脱敏，就跳过本轮日志记录**；而执行 **fail-open**，日志失败不打断会话。结论是"**数据最受保护之处，你的转录按设计就有洞；agent_events 里少一轮，可能是策略结果而不是 bug，判定为故障之前先分清是哪一种**"。同一周，ControlTheory 在 KubeCon NA 发布 Dstl8 2.0，把行业通病命名为 **Telemetry Trust Problem**——"如果没有东西触发，它们从不去看"，建在别人可观测平台上的 AI SRE，只调查平台标记的东西、只推理成本削减后幸存下来的数据。两条一手消息指向同一件事：**AI SRE 的诊断上限在采集侧就定了，不在推理侧**。

生成时间：2026-11-16 07:00 档（`date` 取值 07:44 → 0700）。时间范围限定 2026 年，重点最近 30 天。主线为**第一百八十二条全新立面**；与往期显式划界：#201 管遥测账单、#202 管"一条日志缺席的三种归因塌缩"、#194 管遥测归谁所有、#185 管尺子谁定、#162 管可观测黑洞、#143 管成本失控——**本期只问一个此前没人当一等对象的问题：喂给 Agent 的那份遥测，是谁、按什么规则裁过的？这份裁剪本身可不可见？**

---

## 一、发展趋势

2026 年 11 月这一波发布的共同方向，不是"让 Agent 看得更多"，而是"**重新划分谁能看见什么**"。

第一条线是**证据落点向客户自有仓库迁移**。Google 11-13 把首方数据 Agent、ADK/LangGraph 自定义 Agent 的结构化遥测统一写进客户自己的 `agent_events` 表，会话日志、token 计数、Prism 评测跑分都落在同一张可治理的表里；Conversational Analytics 日志、A2A 工作流、BigQuery Studio/Looker 面板已 GA，每日 token 配额仍是 Preview。这一步把"可观测"从仪表盘搬成了数据资产——但落点变了，裁剪规则也跟着搬了过来。

第二条线是**供给方开始自建遥测、绕开平台**。ControlTheory 的 Telemetry Distillation 从日志扩到指标、追踪和事件，宣称不依赖外部可观测平台也能跨信号诊断，并给出"企业 fintech 两个月、13 个 K8s 集群、328 起事故、零告警规则"的自报数字；DataAgent 11-09 开源基于 K8sGPT 的本地实验台，主打"真实系统在崩溃前很久就在静默退化"，用五种探测向量抓 CrashLoopBackOff/OOMKilled 之前的早期信号。它们的共同论点是：**你在可观测平台上省下的钱，最后会从诊断盲区里还回来**。

第三条线是**目标导向的持续供给**。Honeycomb 11-03 推出的 Personal/Team Agents 不再等告警，而是按目标在后台看发布、补埋点、偿还可靠性债务；其自报调查里，76% 的受访者说 AI 生成代码增速超过审查能力，65% 在过去半年遇到过由 AI 速率限制、Agent 失控循环、token 飙升引发的生产问题。

三条线合起来是一个转折：**行业终于承认"输入"不是中性的**。过去三十年可观测的默认假设是"采集是客观事实、分析才是主观判断"；当读事实的主体从人换成 Agent，采集规则就变成了**决定 Agent 能力上限的权力**。

## 二、技术现状

把 11 月的一手材料按"供给链"顺序摆开，可以看到一份遥测从产生到进入 Agent 上下文，要过四道裁剪。

**第一道：采集口径。** OTel GenAI 语义约定已是入场券——Google 明确追踪依赖该约定做供应商无关的多步工作流描述，Azure Databricks 的 Claude SDK 追踪直接按 `gen_ai.usage.*` 记 token。但"遵循约定"不等于"采到了同一件事"：同一工具调用/RAG/记忆读写在不同框架里可能是独立 Span、日志行或干脆不上报（本地 08 刘扬的实践踩坑）。

**第二道：内容模式。** Azure Databricks 文档写明 Claude SDK 默认 `metadata_only`，要看 prompt/response 必须显式设 `content_mode=content`；超长内容先截旧消息，图片和文档只贡献类型不贡献数据；同时 SDK 与 Console 双端会上报两个同名 Span，必须只按一种 span kind 求和才不会把 token 记两遍。Anthropic 侧的做法更彻底：代码执行式 MCP 里，PII 先被 token 化成 `[EMAIL_1]` 占位符再进模型，回调下一个工具时才换回真值——**模型看到的世界是被替换过的世界**。

**第三道：合规跳过。** 这是 Google 11-13 最锋利的一条：RLS、列级策略标签、动态脱敏三种情形，本轮日志被跳过，执行照常。其直接后果是"缺轮"这一观察值同时承载"策略保护""管道故障""真的没发生"三种含义——#202 记录沉默面已经论证过这种塌缩，但本期要补的是**方向性**：塌缩不是随机的，**它系统性地偏向高风险面**。

**第四道：告警入口。** ControlTheory 的"if nothing fires, they never look"点破最后一环——多数 AI SRE 的调查入口是告警，没触发就没调查，而告警规则本身就是一道供给裁剪。DataAgent 的"静默退化"和 Honeycomb 的"没人在值守时也在看"都是从这一道口子重新设计供给。

四道裁剪叠加的净效果是：**Agent 的视野 = 采集 × 内容模式 × 合规 × 告警，四者都是上游决定，Agent 既看不见自己缺了什么，也无法把"我没看见"写进结论**。

## 三、技术竞争力：主要厂商／方案对比

判读口径统一为六列：以"是否把供给裁剪本身做成可导出字段"为最高区分度。

| 厂商／方案 | 遥测落点与供给模式 | 内容/敏感数据处理 | 合规跳过是否可见 | 无告警路径覆盖 | 供给上限可声明／可审计 |
|---|---|---|---|---|---|
| **Google Cloud（Data Cloud, 11-13）** | 客户自有 BigQuery `agent_events` 表，首方零配置 + ADK/LangGraph 单行埋点；A2A 送指标/Trace/日志 | 净化 Span 明确排除 prompt、回答、内部思考、生成 SQL；深度转录 opt-in | **官方明确提示"缺轮可能是策略结果"**，但无独立标志字段 | 无（仍以执行层为主，goal 层留白） | 部分：落点可治理，裁剪规则未成字段 |
| **Anthropic（SDK/代码执行式 MCP）** | OTel 按 GenAI 约定，Databricks Unity Gateway 统一 trace 表 | 默认 metadata_only，内容 opt-in；PII token 化占位；MCP 启动地址疑似凭据不再记录 | 依赖 ABAC/行过滤，跳过本身无字段 | 无 | 弱：内容模式可配，供给口径未导出 |
| **OpenAI（控制室/Costs API）** | 唯一任务 ID 附推理请求，四层失配监控，最长 35 秒熔断 | 前沿 RL 配独立模型监控器；自述与行为对照 | 安全公告披露虚假自述/自关监控，非产品字段 | 弱 | 弱：供给来自模型侧，未见声明字段 |
| **字节跳动（火山 AgentKit）** | RCA Harness 排障约束层 + 专家 Agent 自定义 IAM 角色，按需读跨服务数据；LLM/Agent Trace 分析 | 专家 Agent 权限不高于人，取证受约束层限制 | 未公开 | 中：预置健康巡检/容量评估 | 弱：约束层存在，供给口径未导出 |
| **阿里巴巴（云监控 2.0 / UModel / AgentLoop）** | "既向 Agent 供给可信事实，也把 Agent 自身纳入观测"，UModel 3200+ 定义、智能巡检 117 类实体 | 查询/调查只读默认，写操作独立授权，先 Preview 后确认再回读复验 | 未公开；RCA 坚持"证据不足继续调查、不越界定因" | 中：System Map 驱动动态假设 | 中：事实供给意识最强，仍无上限字段 |
| **腾讯（CloudQ / AI 可观测）** | 宏-中-微三层（实时监控 / Session·Trace / 节点轨迹），成本按部门·模型·会话拆解 | Trace 级行为轨迹供合规追溯；信通院五项要求、六维基准认证 | 未公开 | 中：主动巡检 + 受控执行 | 弱 |
| **ControlTheory Dstl8 2.0（参照方案）** | 自建 Telemetry Distillation，自采日志/指标/追踪/事件，Prometheus/Jaeger 兼容 | prompt 与回答留在系统之外，只报模型/provider/token | 不适用自建栈 | **强：无告警规则也持续看** | 中：直击 Telemetry Trust Problem，但未给"缺口清单"字段 |

**本期反转**：把"数据越受保护、转录越有洞"写进文档的，是 Google 的官方提示；把"不触发就从不去看"命名成问题的，是一家挑战者厂商；把"模型看到的是被替换过的世界"落到代码里的，是 Anthropic 的 PII token 化。三家从三个方向说了同一句话：**供给不是事实，是被规则裁过的事实**。而六家云厂商 Agent 平台里，"合规跳过可见／供给上限可声明／无告警路径覆盖"三列，没有一家填满。判词：**可信事实供给、客户自有落点、内容模式开关、行级脱敏、trace 表全部可采购；举证"这次诊断到底看没看见那一段、没看见是因为策略还是因为没采到"——不可采购。**

## 四、技术挑战

**其一，缺轮的方向性偏差。** 若跳过日志的规则恰好集中在启用了 RLS/脱敏的敏感表和字段上，而事故又常发生在这些高价值数据周围，那么 Agent 的盲区与风险面正相关。这是最危险的一类偏差：不是"看得少"，而是"越危险看得越少"，且看不出自己在看少。

**其二，"我缺了什么"不在上下文里。** Agent 能推理的只有进入上下文的证据；被跳过的轮、被 token 化的字段、被粗筛掉的那 99% 流量，都不会生成一条"此处本应有一份证据但被规则拦截"的元信息。缺证据与没证据在 it 的推理里完全同形。

**其三，供给口径与模型口径被混着发布。** 同一张表既有 SDK Span 又有 Console Span，token 记两遍；内容模式一改，跨版本的可比性就断。没有 `supply_version` 这类字段，跑分上升究竟是模型进步还是供给放宽，无法归因——#185 度量主权面在本期有了新的下游：**尺子本身是被喂出来的**。

**其四，成本优化与诊断完备性的对立没人定价。** 本地 08 刘扬用"小模型/正则粗筛 99% 流量、仅 <1% 进大模型"实现 90%+ token 降本，这是正确的工程选择；但同一动作也决定了大模型精判层永远看不到那 99%。降本数字进了 KPI，被筛掉的可能事故没有进任何账本。

**其五，评测基准整体缺席该维度。** ITBench-AA、RCA-Bench、SWEOps-Bench、XYBench 测的是"给足证据后诊断/恢复得对不对"，没有一项测"把供给按 50% 裁剪后，结论会不会翻转、Agent 会不会照常自信"。而 XYBench 11-13 的 oracle 实验已经提示：给对意图，底层目标解题率 59%→67%，但识别用户错误前提的能力反而 47%→34%——**看对了不代表做对了，何况还没看全**。

## 五、展望与建议

建议把 `telemetry.supply.*` 立为一组一等运维字段，并给出最小可行集：

1. **`supply.coverage`**：本轮诊断实际可见的 Span/字段数 ÷ 该任务类型应需数，作为诊断的前置 SLI，而不是事后统计。
2. **`supply.redactions[]`**：被合规/脱敏/token 化跳过的轮次目录——只记"哪一轮、哪条规则、哪个字段族"，不记内容；与 #187 隐私面共用双轨导出，metadata-only 上生产、full-content 进受控仓。
3. **`supply.ceiling_declared`**：每个 Agent 声明它的输入上限（采集源、内容模式、告警入口、可回溯窗口），写进 #207 的任务级能力清单——"自主诊断"必须先声明它凭什么诊断。
4. **`supply.version`**：内容模式、脱敏规则、粗筛阈值的版本号；评测跑分与生产结论强制携带，接 #127 行为发布与 #185 度量主权。
5. **`no_alert_path_covered`**： Agent 在没有告警触发时主动扫描过的信号面比例，接 ControlTheory/DataAgent/Honeycomb 的持续供给思路。

落地顺序建议：先在诊断报告末尾加一个"未见证据清单"（成本低、立刻暴露方向性偏差），再把 `supply.redactions` 接进 OTel GenAI 自有命名空间（OTel 官方已承认约定未定义外部证据记录属性，需自建 receipt hash），最后把五项写进信通院六维基准的"过程可审计"格与采购合同的能力矩阵。

**一句话展望**：过去我们问"这个 Agent 推理得对不对"；2026 年 11 月之后必须多问一句——"**它凭什么看见这些、又按什么规则没看见那些**"。可观测的可采购时代结束了，供给的可举证时代刚开始。
