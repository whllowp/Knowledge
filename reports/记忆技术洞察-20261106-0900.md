## 一、发展趋势：插槽战争开打

近两周，记忆厂商的竞争重心出现了明显的"接口化"迁移：不卖记忆能力，卖接入形态。三个标志性事件：其一，11 月 2 日阿里云在 Model Studio 上线 Memory 服务（图表署名 Mementis），主打 MCP + CLI 一路接入 Codex、DeepSeek Harness、Claude Code、OpenClaw 等外部 Agent 工具——记忆服务第一次主动"跨自家云"去插别人的插座；其二，TencentDB Agent Memory 的 Memory Proxy 已覆盖 9-10 个客户端（Claude Code、CodeBuddy、WorkBuddy、Codex、DSH 桌面端、OpenCode、Hermes、OpenClaw、Pi），核心机制是"协议不变、改 base URL"，并在近期 release 中补齐 OpenCode 官方 adapter 配置包、DSH 桌面端适配与 Pi 客户端接入；其三，Hy-Memory 2.0 的 MemHub 以本地应用形态支持 10 种 AI 工具共享记忆。同期外部评论（Forkast、ninadpathak）将这一层命名为"状态管理层"：Agent 栈四层中，MCP 定了工具、A2A 定了通信、PAP 定了权限，唯独状态层仍是 14+ 厂商、零标准、零可携保证——**这不是空缺，是正在成型的护城河**。市场侧同步验证：爱分析测算中国智能体记忆市场规模从 2025 年 14.4 亿元增至 2030 年 642.5 亿元，五年复合增长率超 110%；Cloudflare 早在 5 月已推出 Agent Memory 托管服务，属海外先行者。趋势判读：记忆层的竞争从"谁的召回更好"转向"谁的插座更多"；捕获权（谁能看到全量对话）成为新的争夺点。

## 二、技术现状：三种插座形态与捕获盲区

本期提出长期复用框架——**插座形态学**，当前接入层收敛为三种形态：

1. **代理插座（base-URL 型）**：TencentDB Memory Proxy 为代表。代理挡在客户端与模型之间，协议原样保留，因此能**无损捕获 L0 全量对话**并在每轮注入 L2/L3 记忆、Skill 与知识。代价是需要按客户端逐一适配其系统提示词格式——Pi 使用标签行格式（Available tools:），与 Claude Code 的 Markdown 标题、CodeBuddy 的 XML 标签完全不同，Proxy 不得不为 Pi 单写一个 PiProfile 解析器。捕获完整性最高，适配成本也最高。
2. **工具总线（MCP 型）**：OpenStinger、Mem0 OpenMemory、阿里云 Memory 为代表。记忆系统暴露为 MCP 服务器，任何 MCP 兼容运行时即可挂接，OpenStinger 甚至做了 ABC 环测（OpenClaw→Qwen/Llama→DeerFlow/Grok 往返传播，身份保持）。但 MCP 模式下记忆读写依赖 Agent 主动调用工具——**捕获盲区在接口层：Agent 没调用，记忆就没发生**。MCP 标准化了传输，没标准化语义（schema 迁移仍要自己做）。
3. **文件系统挂载（FS 型）**：OpenViking 的 viking:// 虚拟文件系统（VLDB 2026 VikingMem 论文）与 Hy-Memory MemHub 为代表。记忆作为文件被渐进式加载，会话结束自动提炼。形态最中立，但捕获颗粒度取决于客户端往文件系统里写什么。

关键判读：**接口形态决定记忆完整性**。同一家厂商若同时提供三种形态，其记忆质量主张会随接入形态而变——"我们的记忆系统很强"从此必须追问一句"以哪种插座接入为前提"。第 5 期的成本结论在此接续：代理插座还承担了成本治理职能（注入裁剪、缓存友好），插槽即经济学。

## 四、技术挑战

1. **捕获-隐私悖论**：代理插座为了记忆完整必须看见全量对话，与合规最小化采集直接冲突；MCP 型天然隐私友好但记忆残缺。尚无"分级捕获"的公开实现。
2. **适配碎片化税**：Proxy 要为每个客户端的系统提示词格式写解析器（Pi 事件即证明），客户端生态越繁荣，维护面越大；DSH 社区 20+ 插件共用 sessionQuery 的共因故障（第 2 期发现）在接入层同样成立。
3. **出口缺失**：可携性的下半场是出口。Mnemoverse 把市场切成托管×跨工具等四象限，但没有一家公布标准化的记忆导出格式；AWS AgentCore 无文档化导出工具——锁入是结构性的。数据一旦在 Proxy 蒸馏成 L1-L3，导出即第 3 期"巩固税"的再现。
4. **无仲裁者**：AML 二期已于 11-01 关投稿、11-04 关正式评测，榜单 11 月中发布；但工业榜与开源榜分榜设计意味着商业产品同源评测、分板发布，插座覆盖仍不在评测范围内。

## 五、展望与建议

- **给采购方**：把"接入形态"列为第一问——要审计级完整性选代理插座，要跨云中立选 MCP 型，要本地主权选 FS 型；再要求厂商现场演示"删除是否传播到派生记忆"（第 2 期命题在采购清单上的落点）。
- **给厂商**：捕获权红利有半衰期，当 MCP 层出现"会话镜像"类标准化上报接口时，代理插座的捕获优势将被抹平；先行者的时间窗口在标准接入协议诞生之前。
- **给研究者**：值得做的空位——分级捕获协议（L0 全量驻留端侧、L1 以上上云）；接入形态作为实验变量的记忆质量对照（同库三插座 A/B/A 测试）。
- **本期新观点：插座层与蒸馏层将会解耦**。接入标准化（协议化、MCP 会话上报标准化）只会压缩插座层的差异化空间——捕获与注入终将商品化；但 L1-L3 的蒸馏质量与提取策略与插座无关，是长期壁垒。推论：未来记忆厂商的价值曲线将呈哑铃型——插座端赚部署便利、蒸馏端赚质量溢价，中间的存储层被云厂商以基础设施价格收编。腾讯"Proxy 深适配 + 四层架构蒸馏"与阿里云"MCP 广覆盖 + 自定义记忆规则"恰是哑铃两端的现成样本，11 月中 AML 二期榜单将是蒸馏端第一份同源对照数据。
- **下期候选**：AML 二期榜单发布口径（11 月中，最高优先）；阿里云 Mementis 与 TencentDB 的插座覆盖对照实测；分级捕获协议首例；导出格式标准化动向。
