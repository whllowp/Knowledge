# AI-SRE 技术洞察（第 262 期）

> **生成时间**：2026-11-17 21:00（Asia/Shanghai）｜**洞察窗口**：2026-10-18 ～ 2026-11-17（近 30 天，含少量 2026 年内基线）
> **本期主题**：数据龄期面／决策时证据有多旧（Decision-Time Data Age / Observation-to-Decision Latency）——行业把"实时可观测"写进发布页，却没人举证：Agent 在 T 时刻做自愈决策时，它翻开的那个仪表盘、那条日志、那个指标，其实是 T−Δ 秒的世界

## 题眼

Google Cloud 的 Gemini Enterprise Agent Platform 文档里藏着一张罕见的诚实表格：Cloud Monitoring 指标**每 60～120 秒采样，最多延迟 180～420 秒（3～7 分钟）才显示**；而同页另一行写着，内嵌政策违规处置是"实时内联拦截、零后处理延迟"（Google Cloud，2026）。同一块面板上，有的信号是此刻，有的是七分钟前——Agent 却把它们一视同仁当作"当前状态"推理。

这就是本期立的全新立面：**数据龄期（data age）**——信号从"事件发生"到"Agent 拿到并据此决策"之间经过的秒数。过去 261 期问过数据可信吗（第 254 期）、分组可信吗（第 237 期）、置信度诚实吗（第 260 期）、知识过期吗（第 230 期），但有一个最朴素的问题从没单列：**Agent 决策那一刻，它依据的证据是多久以前的？** 与上述各期显式划界——本期不管内容对不对，只管时间差 Δ 有没人记、有没人设预算。一句话题眼：**"实时"是采集侧的实时，不是决策侧的证据新鲜；把 T−420 秒的世界当 T 秒的世界操作，就是"看着后视镜开快车"。**

## 一、发展趋势

**趋势一：厂商第一次明码标价"延迟"，但只标采集侧。** Google 那张表逐类列出：审计/网关日志"近乎实时、几秒可搜"，执行日志"发出后几秒可见"，Cloud Trace"span 完成后几秒可搜"，指标却是"60～120 秒采样、最长 180～420 秒显示"，异常检测更诚实——"初始范围启用约需 40 分钟，每 120 秒采样，可见性延迟最长 420 秒，进 SCC 前还有额外同步延迟"（Google Cloud，2026）。同页还埋了反直觉细节：`--freshness=6h` 这类窄过滤"有时会漏掉最近编入索引的条目，验证近期事件请用 `--freshness=1d`"。**能查到不等于查到的就是最新的——连查询语法都在提醒证据有龄期。**

**趋势二："流式原生"被当成差异化卖点，本质是在打龄期战。** Edge Delta 10-08 发布 "prod immune system"，主张 Agent 直接跑在遥测管道上、"读的是正在流过的实时日志/指标/追踪，而非告警后再从别家仪表盘拉取"，以"在有人被叫醒前发现问题"为卖点；同日开源 AI SRE Arena，21 个 Kubernetes 故障自家检测 18 个、对照 12 个（Edge Delta / PR Newswire，2026-10）。火山引擎 11 月上线"Agent 轨迹"与 AI 判定触发的动态阈值（火山引擎，2026-11）。**竞争焦点正从"有没有数据"移到"数据到手有多快"——但各家比的是采集管道，不是决策时那份证据的龄期。**

**趋势三：基准开始被动撞上"龄期"，却没把它单列成变量。** SREGym 的 90 道真实题，Claude Code+Sonnet 4.6 诊断 72.6%、端到端 60.7%；注入"真实遥测噪声"后掉到 62.6% 与 53.7%（ajayk.sh 汇编，2026）。OpenRCA 2.0 三失败模式里，"把沉默读成健康"（presence bias）几乎就是龄期病：**指标还没采到 ≠ 系统没出事。** 基准已在为龄期扣分，却没人报出"这次失败是因为证据老了 7 分钟"。

## 二、技术现状

平台侧的现实是：延迟被写进文档，却没被写进遥测。OTel GenAI 语义约定规定了 `gen_ai.operation.name`、`gen_ai.usage.*` 等字段（掘金，2026），Google ADK 遥测据此落到客户自有 BigQuery，但延迟表里的 180～420 秒、40 分钟冷启动、420 秒可见上限，**没有一个成为 span 属性或 SLO 指标**。用户能查"这次调用花了多少 token"，查不到"这次决策依据的指标是哪一秒的"。

Agent 侧更微妙。一篇 SRE 现场指南拆开"时间戳悖论"：用户问时间，Agent 答 14:32，trace 却说 14:35 到达——四种解释按概率是**陈旧上下文注入**（system prompt 在 14:30 会话开始就模板化）、**副本时钟漂移**（三个 pod 三个 NTP 状态）、把模型自报时间当真、最后才是幻觉。其工程律令是"LLM 产出的时间戳是 data 不是 metadata，排序必须来自 ingress 控制的时钟"，并给出 `agent.started_at.hybrid` 作排序键（tamiz.pro，2026）。**搬到 SREAgent：RCA 那句"故障始于 14:32"也可能是陈旧注入上下文，而非被控制时钟排序的事实。**

再看自治闭环。OpenAI 失准监控是四层管道，模型审查员"前沿任务最多每 30 分钟查一次"，回放 Hugging Face 事故会在沙箱逃逸后约 30 分钟报警；Anthropic 自评估每次回答后当场判定，额外算力不到 2%（clauday / InfoRiskToday，2026-11）。**30 分钟与 0 秒，是两种完全不同的证据龄期预算**——一个适合事后归因，一个才配实时拦截。行业统称"监控"，却没为不同动作规定龄期门槛。

## 三、技术竞争力（主要厂商/方案对比）

| 厂商/方案 | 采集/可见延迟（自报） | 是否把龄期做成可查字段 | 是否有决策龄期预算 | 决策时证据来源 | 关键缺口 |
|---|---|---|---|---|---|

| Google GKE 托管 OTel | 指标导出 5s～300s 可配 | 否 | 否 | OTLP→Cloud Monitoring | 采样间隔可调但无"够不够新"判据 |
| Edge Delta prod immune system | 流式管道内实时推理 | 否 | 否；以"早于呼叫"为卖点 | 管道内实时日志/指标/追踪 | 自家 Arena 18/21 仍是自评 |
| 火山引擎 智能运维助手/Agent 轨迹 | 11 月新增完整执行轨迹、AI 动态阈值 | 有轨迹时间线，无龄期预算 | 否 | APMPlus/VMP/云监控工具集 | 轨迹记"发生了什么"非"证据多旧" |

判读：八家几乎都把"采集快、看得早"做成了能力，但**"决策时证据龄期可导出、有预算、超标即拒绝自动执行"这两列几乎全空**。最接近的是 OpenAI/Anthropic——它们事实上按频率分层（30 分钟 vs 每轮），却没把这种分层产品化为可集成的时效契约。

## 四、技术挑战

**挑战一：龄期是隐藏的第四维，三支柱模型没有它的位置。** 指标、日志、追踪都回答"发生了什么"，没有标准字段回答"距今多久"。Google 把 420 秒写进文档而非 span，等于承认这是运维常识却不是机器可读事实。跨源融合时，最陈旧那一源常决定结论——而它从不报自己的年龄。

**挑战二："没数据"与"没故障"被混为一谈。** OpenRCA 2.0 的 presence bias、指标 lookback 窗口、Google 的 `--freshness=6h` 漏索引，三者同构：**沉默可能只是证据还在管道里。** 自愈 Agent 若在 T−Δ 窗口看不到异常就判"恢复成功"，本质是拿未来的事故赌现在的清白。

**挑战三：上下文注入让"当前状态"可能是会话开始时的旧快照。** system prompt 可能在几分钟前就模板化，多副本时钟漂移又让"哪个是正确 wall time"变成选边站（tamiz.pro，2026）。RCA 时间线因此可能是"旧上下文+漂移时钟+自报时间"三者拼接，看着自洽，实则不可排序。

**挑战四：自治级别越高龄期越该收紧，行业却反着走。** 辅助诊断可容忍 7 分钟旧指标——人有时间复核；但受控自愈、自动回滚若在 420 秒证据上执行，等于用过期世界做不可逆改动。Google kill switch 的政策传播本身"最多 7 分钟、组成员更新数小时"（Google Cloud，2026）——**连"停止"都有龄期，遑论"执行"。**

## 五、展望与建议

**给平台方**：把数据龄期立为一等字段族 `decision.evidence_age.*`（本期第 185 项市场空白，第 149 次无人提的字段族）——`event_observed_at`（事件真实发生时刻）、`evidence_available_at`（证据在后端可查时刻）、`age_at_decision_seconds`（决策时刻−事件时刻）、`age_budget_seconds`（该类动作允许的最大龄期）、`age_source`（scrape/export/index/queue/ctx-injection 五选一）。缺省 `AGE_UNVERIFIED`，不得进入自动执行门禁。这是该字段族该进 OTel GenAI 语义约定的理由：**没有龄期的证据，等于没有时间戳的证据。**

**给采用方**：一是**按动作分级设龄期预算**——读型诊断可容忍分钟级，写型自愈/回滚要求新鲜证据，超预算一律转人工；二是**把"沉默"显式三态化**（真没有／尚未采到／采集中），杜绝 presence bias 借壳上市；三是**决策记录随附证据的 `age_at_decision_seconds`**，与第 260 期 `confidence.calibration.*` 并排进 SLO——一个管"有多确定"，一个管"有多旧"，两个都合格才准自治。

**给评测与标准方**：在 SREGym/AI SRE Arena 里把龄期从隐含噪声升级为显式变量——同一故障分别喂 0s/60s/420s 证据，报出龄期-成功率曲线；为"用陈旧证据自愈成功却埋下二次事故"单列题型；信通院《云上 Agent 基准度量模型》六维之外补一格"证据时效可举证率"。

**判词**：「实时采集／流式管道／秒级导出／全景图谱／异常检测／告警收敛／动态阈值全部可采购；**举证这次自愈决策依据的那条证据在决策时刻有多旧、沉默是真没有还是还没采到、Agent 手里的'当前状态'是不是会话开始时的旧快照、有没有超过该类动作的龄期预算——不可采购**。」

**本地原型（第 141 期成组启用，新角度深化）**：刘杨《从 Trace 到规模化实时评估：面向生产流量的 Agent 可观测实践》过去用于讲"OTel GenAI 三层 9 类 Span 与 token 级可观测"；本期从新方向重读——标题里那个"**实时**"评估的究竟是谁的实时：评估用的 Trace 本身是 span 完成后异步导出的，规模化评估流水线里藏着一条没人量过的证据龄期轴。配刘凯宁《蚂蚁 SRE 基于 Agent 的应急根因定位》的"结论／证据／待确认项三分"——把"此证据龄期 Δ、是否超预算"写进待确认项，与第 254 期的观测来源四分形成正交两列。**判词：「本地资料把'有完整 Trace 仍判不出做对没做对'写进标题、把不知道写进结构；联网侧 2026 才把延迟明码标进文档；两边都还没把'证据有多旧'变成可导出、可设预算、可卡门禁的字段。」**
