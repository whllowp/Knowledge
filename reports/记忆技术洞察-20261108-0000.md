# 记忆技术洞察（第 20 期）｜记忆的读法——查询即失真

> 期数：2026-11-08 00:00 期（总第 20 期）｜范围：2026 年，重点最近 30 天｜字数：约 2,750

## 本期主线

前 19 期的治理叙事几乎全部落在写侧与删侧：准入、注销、血统、并发、共享、导入、备份、代谢。读侧只在两个侧面被碰过——时延账单（第 11 期）与读到的内容是否仍为真（第 10 期）。本期拿掉最后一个未被检验的前提：**"检索会把需要的东西带回来"**。事实是，读路径的第一个动作不是检索，而是把信息需求**翻译成查询**；这个翻译由模型在无人审计的情况下完成，其失真没有名字、没有分数、没有治理位。写侧已经学会了设闸门，读侧的查询构造仍是零治理的黑箱——行业竞争的下一个不对称位。

## 一、发展趋势

**从"相关性"到"充分性"的范式迁移正在发生。** USC 团队的 QEMem（arXiv 2610.22668）把这一步说得最直白：检索到相关记忆不等于凑齐了回答所需的证据，"相关性-充分性鸿沟"（relevance–sufficiency gap）才是主失效模式——关键信息碎片化分布在多条记录里、被抽象遮蔽、与推理所需的关系脱节。QEMem 的解法是把记忆利用重构为"构造查询特定的证据集"而非"取回相关条目"：查询引导的多粒度发现、带证据角色的 ViewCards 组织、充分性引导的补捞。在共享记忆库的公平对照下，LoCoMo 上 91.43%，比最强基线 MemR3 高 7.6 个百分点，比 NEMORI 高 10.7 个点。

**查询构造本身在升维。** QUMem（2608.16168）指控行业默认的"单一 top-k 查询"只能取回"各自相关、合起来不够"的碎片，其方案是三个串行 agent：先识别任务的信息需求，再规划多查询检索，最后联合推断时序与情境有效的用户状态。CoEvo-Mem（2608.01739）则证明查询改写与记忆库必须共演化——检索决定了哪些记忆被暴露并拿到反馈，固定检索策略会锁死记忆库的进化方向，联合优化在七个基准上最多 +7.5 个百分点。

**语义距离与逻辑距离的分离被定量坐实。** CABLE（2608.17911，COLM 2026）提出"证据可达性"问题：解释后事的先因（antecedent）在语义空间里天然远离它要解释的事件，纯相似度检索系统性错过它们；ActMemEval（2603.00026）的密度分布直接画出了这条"推理鸿沟"——支持证据与查询逻辑相关但语义相似度显著偏低。三篇论文指向同一结论：**查询失真不是检索器的 bug，是信息需求到向量空间这段翻译的固有损耗。**

## 二、技术现状

**产品侧的读路径仍停在第一级。** 主流方案对外暴露的接口仍是一个 `search(query)`：Mem0 的评测协议把检索固定为"平台按题调 Search 取排序候选"；TencentDB Agent Memory 是 Embedding+关键词双路 RRF；dsh-memory-evolve 系插件是本地文件检索。查询怎么构造、要不要分解、结果够不够，全部不设防。

**少数方案已把查询当一等公民。** Hy-Memory SDK 的 `search_mode="agentic"` 是目前唯一把"查询送 LLM 改写"做成显式产品开关的方案——但只在文档里有一行，无任何改写质量、改写成本、改写失败率的披露。OpenViking 的 `search` 与 `find` 分工（前者按会话上下文规划检索计划、后者纯语义查询）+ 目录域限（TrieHI 索引先解析目录范围再向量排序）+ 11 月 4 日批次加入的 query-driven CacheFS 缓存与 `prefetch_search_topn` 预取修复，是产品侧读路径最完整的自治栈，但检索计划本身同样不可审计。

**论文侧出现"使用即归因"的读后治理。** MEMOIR（2611.07631，11-05）指出两个耦合失效：巩固可能悄悄毁掉未来查询需要的证据，而检索会持续偏向陈旧记忆——高频被检的记忆挤出低曝光的有用记忆（检索的马太效应）。其解法是查询后归因更新检索优先级 + UCB 式探索红利鼓励低曝光记忆，1,905 条去重 LoCoMo 上证据 recall@5 比裸余弦 +11.92pp。这与第 9 期的内容侧闭环互为镜像：闭环现在也在检索侧生成——检索决定信用分配，信用分配反过来重塑检索。

**六项目状态。** dsh-memory-evolve（csyangwen）665★（11-07），7 日 +198（+421%），代码最后 push 10-29——星数在涨、代码停更；生态碎片化加剧，出现第三个变体 huahua-dsh-memory-os（HOS）：五轨记忆 + git 分支感知 + Memory Sync 用 git 仓库存记忆、冲突给本地/远端/双留三选——这是第 8 期"未决返回值"的第一个民间实现。Hy-Memory 底层 2.0.14 随 MemHub v1.0.6 发布（11 语言、lite/pro/ultra 档位、30B-A3B 追加 FP8/GGUF 量化）；第三方审计揭示 SDK 仓仅 27★、PyPI 周下载 147——声量与装机量倒挂。TencentDB Agent Memory 30,584★（11-07 快照），7 日 +270；v2.0.3（10-26）稳定版；账单首次给出可复核数字：存储 0.02 元/万条/小时 + 模型 0.01 元/Credit/小时。OpenViking 11-04 批次上线检索预取与 CacheFS；933 个 open issues 的可靠性问题被媒体点名；AGPL-3.0 仍是被引用最多的合规顾虑。

判读：读路径重演了写侧的"倒挂"结构——**查询治理做得最好的全是论文，没有一个是量产记忆产品**（本系列倒挂计数第十二次）。Hy-Memory 与 OpenViking 是仅有的把查询构造产品化的两家，但都不披露改写命中率与改写失败时的降级行为；Mem0 的 add/search 固定接口在 AML 契约里是中立性保证，在真实采购里就是查询黑箱。TencentDB 的 Mermaid node_id 钻取链（persona→场景→原子→原始对话）仍是陈述性证据链最强的产品实现，但它保证的是"读到了可下钻"，不保证"查询没漏"。

## 四、技术挑战

1. **查询失真不可观测。** 写侧有准入审查、回合内确认、写入重试；读侧没有任何机制回答"这次查询漏了什么"。QEMem 的充分性校验需要额外的 LLM 调用与补捞回路，成本与第 11 期时延账单直接对撞——读侧的每一次校验都在阻塞这一轮。
2. **检索马太效应与代谢问题的合流。** MEMOIR 的低曝光挤出与第 19 期 dsh 系"读即强化"是同一枚硬币：使用统计既是代谢判据又是检索偏置，两个目标互相污染。UCB 探索红利在论文里有效，但探索的代价由谁付、付多少，无产品定价。
3. **先因证据是结构性盲区。** CABLE 证明语义图上按相似度补链只会复制宿主检索器已能取回的东西，必须显式构造"互补边"；这意味着每个记忆产品当前的图结构对"为什么"类问题系统性的低召回，且没有基准单独测这一项。
4. **查询构造与缓存稳定性的新冲突。** 多查询规划、查询改写都会放大注入内容的变动，与第 14 期的字节稳定性定理正面相撞；OpenViking 用字节级回放缓解注入端，但改写带来的"同一问题每轮检索结果不同"仍无缓存友好方案。
5. **评测缺口延续（第十三次同构）。** AML 二期 11-04 关评测、官方榜单 11 月中发布（截至 11-07 未出）；契约里检索是平台代调的固定接口——查询构造质量在评测中被平台吸收了，参赛系统的读侧智能完全不可见。首期分维数据（如 MemoraX 总分 58.02 而 G 项仅 29.99）说明能力剖面比总分重要，但剖面里依然没有查询侧维度。

## 五、展望与建议

**判读一：读路径将复制写路径的治理化时间线。** 写侧从自由写入到闸门、审查、遥测用了约一年；读侧的起点条件更好（查询是纯函数式的，可离线回放评测），预计 2027 上半年出现"查询审计"类产品：记录每次检索的原始需求、生成的查询、命中集与最终采信集，四段对账。

**判读二："少记"论得到读侧印证。** Hy-Memory 官方口径"记忆数量低 70%、每条密度高 45%"与 QUMem"同交互多条信息绑成一条会绑住不该绑的"共同说明：写侧的切分粒度直接决定读侧查询能否命中——第 4 期的切分问题与本期查询问题是同一条链的上下游，建议把"切分粒度适配查询方式"作为选型时的联合验证项，而非分别看分。

**判读三：采购条款应新增三问。** ① 查询是否经过改写/分解，失败时降级为什么；② 有没有低曝光记忆的曝光保障机制（否则库越大越只读到头部）；③ 检索计划与命中集可否导出审计。目前三家能完整回答的为零——这是谈判空间。

**建议：** 优先在评测外自建"查询-命中-采信"三段日志（成本极低，MEMOIR 证明仅归因就有 +1.5pp 可白拿）；对"为什么/依据"类问题不要信任纯向量检索，用 CABLE 式前因补链或人工缓存兜底；等待 AML 二期榜单（11 月中）时，重点看安全隐私 H 项与治理 D 项的分离度，而非总分。
