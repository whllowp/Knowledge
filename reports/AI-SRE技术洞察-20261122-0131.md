# AI-SRE 技术洞察（第 314 期）

- 生成时间：2026-11-22 01:31（Asia/Shanghai）
- 观察窗口：2026 年，重点为最近 30 天（2026-10-23 至 2026-11-22）
- 本期主题：供应商切换面／跨供应商故障转移——可用性保住了，行为保不住

## 题眼

2026-09-27，AWS Builder Center 的一篇文章把一句话放在标题里：**“fallback model 需要验收判据，而不只是一个备用端点”**。它的论证很朴素：当 Bedrock 或任何 LLM 调用失败，工程直觉是“换一个模型再调一次”；但换模型改变了用户拿到什么、账单怎么算、“成功”怎么定义——这些没定义清楚，第二个模型就只是一次“行为不同的静默重试”。

2026-06-27 的一份开发日志给出了更刺眼的例子：转录流水线的主模型故障，自动切到较弱的备用模型。备用模型不会输出乱码，它输出**看起来合理的邻词**——"low-code" 被听成 "Claude Code"，"commits" 被听成 "compactions"，"deploys" 被听成 "deep researches"，"PRs" 被听成 "peers"。乱码会让读者停下来核对；这些“合理词”直接通过评审，流进下游。

2026 年 7 月的一份多供应商路由基准（ContinuityBench）则量化了另一类损失：无状态故障转移**保住了 uptime，却静默丢弃对话历史**。它提出两个指标——连续性保持率（CPR）与连续性延迟开销（CLO），并给出有状态代理的“历史前送”方案，在异构端点间重建会话。

2026-07-29 的网关横评更冷：六个开源网关里，**只有一家默认会在 LLM 层重发失败的请求**；也只有一家能在“第一个 token 已经上线之后”做故障切换——做法是把已生成的残缺文本当作续写内容重新 prompt。其余几家在流中途死掉时，客户端看到的是一条**看起来很成功的被截断的流**。

## 一、发展趋势

**第一，路由被拆成三层。** 部署级负载均衡（同模型多实例，语义基本一致）、供应商级故障转移（模型不变、换提供方）、任务级模型路由（换模型、改变行为）——风险从左到右递增。生产系统应优先在同模型内部恢复，确认资源耗尽后再进入跨模型降级。

**第二，fallback 从“运维动作”变成“产品决策”。** 换模型要事先定义触发条件、质量下限、成本上限、哪些能力“永不静默降级”（如工具调用、结构化输出、安全拒答）。没有这些，fallback 就是把故障翻译成用户可见的行为变化。

**第三，“同模型不同供应商”不再等价。** 同一模型在不同托管方的量化、版本、工具调用可靠性、上下文窗口、缓存前缀都可能不同；OpenRouter 的 Auto Exacto 会按工具调用有效性与实时性能重排 provider，而质量重排与 prompt cache 天然冲突——把连续几轮对话搬到另一个端点，缓存前缀就断了。

**第四，连续性从“会话恢复”扩展到“证据连续”。** 历史消息、工具调用中间状态、已生成的半截文本、缓存键、请求 ID，都是切换时要“前送”的状态；只重建消息列表，不重建工具状态，Agent 会在恢复后重复调用或跳过步骤。

**第五，来源戳开始出现。** 开发日志里的做法是给每条输出盖“由哪个模型/哪个版本在何时产生”的戳，让降级可被下游识别；这与 299 期的权重同一性、276 期的回滚版本是同一条证据链。

## 二、技术现状

**可用性指标掩盖行为变化。** uptime、错误率、P99 都在绿，正确率与用户满意度却下降；因为切换后请求“成功”了，只是答案不同。

**三层风险递增。** 部署级切换风险最低；供应商级切换要验证同模型的工具调用、JSON 模式、上下文与缓存；任务级切换要重新做业务评测。

**静默截断。** 流式中途失败时，多数网关把已生成内容当成功返回；Agent 拿到半截计划继续执行，比直接报错更危险。

**能力目录缺失。** 路由若靠“模型名列表”决策，就没有硬约束（上下文长度、JSON Schema、tool calling、数据区域、版本 pin）；软评分（质量/成本/TTFT）又会掩盖硬约束不满足。

**验收缺位。** 多数团队只验证“切换后能返回 200”，不验证“切换后行为在可接受范围内”；配对回放（同一请求在主/备两端各跑一遍）很少做。

## 三、技术竞争力

| 方案 | 保可用 | 保行为 | 连续性 | 可观测 | 主要风险 |
|---|---|---|---|---|---|
| 部署级负载均衡 | 高 | 高（同模型） | 中 | 中 | 只解决实例故障 |
| 同模型换供应商 | 高 | 中（量化/版本差异） | 中 | 弱 | 工具调用与缓存漂移 |
| 跨模型降级 | 高 | 低 | 弱 | 弱 | 行为变化、成本变化 |
| 有状态代理（历史前送） | 高 | 中 | 高 | 中 | 状态重建不完整 |
| 网关默认重试 | 中 | 低（可能重复副作用） | 弱 | 弱 | 重试放大、半截流 |
| 手工切换 | 中 | 中（人判断） | 低 | 低 | 恢复慢、无记录 |

判读：买得到多端点、路由策略、重试、熔断、网关；买不到“这次切换后哪些行为变了、变了多少、是否在验收范围内、会话与工具状态是否连续、半截输出有没有被当成成功”。

本期反转：我们一直把故障转移当“可用性手段”。但转移有两个产物——**可用性**与**行为**；前者可以买到，后者只能验证。把 fallback 当运维动作，等于把“行为变化”外包给供应商的默认值。

判词：「多端点／路由策略／重试／熔断／网关／模型目录／评测平台」全部可采购，「这次切换后行为偏了多少、哪些能力被静默降级、会话与工具状态是否连续、半截流是否被当成成功、降级由谁批准」不可采购。

## 四、技术挑战

**其一，等价性无法由“同模型名”保证。** 托管方的量化、版本、推理栈不同，输出分布就不同；同名不等于同物。

**其二，工具调用是硬约束。** 备用模型可能不支持 JSON Schema、并行工具调用、特定参数；切过去不是变慢，是变错。

**其三，缓存与黏性冲突。** 为质量重排 provider 会打断 prompt cache，长会话成本上升；为缓存固定 provider 又失去故障转移。

**其四，流式半截。** 首个 token 之后失败，客户端已看到部分内容；重发可能重复副作用，不重发则用户拿到残缺答案。

**其五，连续性状态复杂。** 消息、工具调用、审批、缓存键、幂等键都要前送；少一样就在恢复后重复或跳过。

**其六，验收成本。** 配对回放要双倍调用与人工/自动判定；多数团队只在事故后才补。

## 五、需求分解、用户旅程与实现方案

**需求分解（按角色）。**

- 平台/SRE：需要切换触发条件、质量下限、切换记录与回放。
- 产品：需要定义哪些能力“永不静默降级”，以及降级时的用户提示。
- 安全：需要备用模型的安全策略、拒答行为、数据驻留一致。
- 财务：需要降级后的成本模型（备用模型单价、重试放大）。
- Agent 团队：需要工具调用兼容矩阵与会话状态前送。

**用户旅程（一次“自动降级”后的质量事故）。**

1. 主模型供应商局部降级，网关按默认策略切到备用模型。
2. 请求成功率恢复，仪表全绿；备用模型输出格式合法。
3. 备用模型对工具参数的理解偏移，调用成功但语义错；或转录出“合理但错误”的词。
4. 下游按错误结果继续执行，直到业务发现“报告不对”。
5. 复盘发现切换无记录、无验收、无来源戳；无法回答“哪些请求被降级过”。
6. 下一次故障，团队干脆关掉自动切换，回到手工——恢复更慢。

**实现方案（90 天）。**

- 第 1–2 周：定义三层路由与切换触发；同模型内恢复优先，跨模型降级需显式批准。
- 第 3–4 周：建能力目录——上下文、JSON Schema、tool calling、数据区域、版本 pin 作为硬约束；软评分只做排序。
- 第 5–6 周：验收判据——每类任务的质量下限、成本上限、延迟上限；哪些能力禁止静默降级。
- 第 7–8 周：配对回放——同一请求在主/备各跑，比较结构、工具调用、关键字段与拒答；差异超阈告警。
- 第 9–10 周：连续性——历史前送、工具状态快照、幂等键、缓存键；流式半截的取消与重放策略。
- 第 11–12 周：来源戳与审计——每条输出记录模型/版本/供应商/切换原因；提供“哪些请求被降级”的查询。
- 第 13 周：演练——主供应商故障、半截流、工具不兼容、缓存失效四种场景，验证“可用且行为可控”。

**验收标准。** 任一次切换，能回答：为什么切、切到哪、哪些能力变了、差异多大、是否在验收范围内、会话与工具状态是否连续、谁批准。

**第 226 个市场空白（五项）**：切换验收判据；工具兼容矩阵；连续性前送协议；降级来源戳；配对回放平台。

**`fallback.*`／`provider_switch.*` 第 193 次无人提字段族**：`fallback.trigger`、`fallback.capability_delta`、`fallback.continuity_state`、`fallback.source_stamp`、`fallback.approved_by` 在网关、Agent 框架与评测平台之间没有统一语义；平台只报“切换成功”。

**本地 173／173-kb 连续第 181 期成组启用**（李东东 16）：本地知识库把“可用性”与“行为”分开记账；本期把故障转移落成验收判据与来源戳。
