# AI-SRE 技术洞察 · 第 101 期

## 证据可得面／线索稀缺面（Evidence Availability / Clue Scarcity）

> **题眼**：前 100 期补的都是智能体「做完之后」的制度——生效验收、组合授权、交接托管、计分分母、图边举证。本期往前挪一步，问它开口之前：**摆在它面前的证据是谁凑的、缺了哪几样、缺的这件事记在哪里**。11-02 的论文给了 120 个真实分布式故障，其中 69% 的报告不提关键方法、63% 没有可用内部堆栈，所有榜单却仍把「没证据」与「判错了」记进同一个失败数。**买的是根因分析，交付的是「证据齐备」假设下的定位能力。**

## 一、发展趋势：证据被写进底座，却没被写进交付物

**11-02 arXiv 2611.03523《DistDebug-Bench》**（密歇根大学 OrderLab，NeurIPS 2026 Datasets & Benchmarks，41 页）第一次把「诊断」从「补丁通过测试」里拆出来：120 个真实 bug、11 个分布式系统、5 种语言、10 类故障模式，人工标注 218 个 gold 因果块，要求智能体指回修复前的代码块。摘要自述两处反复出现的缺口——**「缺显式推理结构导致的隧道视野」**与**「工具使用范围不一致导致的不确定性」**。据第三方对论文表格的解读：45% 的 bug 需多个块才能表达根因、23% 跨文件、**69% 的报告不提 gold 方法、63% 没有可用内部堆栈**；最强配置找对文件 83.9%，命名因果块仅 67.7%，各配置稳定差 15–25 点，flaky 占 12–25%，置信区间宽约 ±7–8 点。ZooKeeper-2845 案例更狠：报告里的术语（领导者选举、法定人数、同步、快照、日志重放）把调查引向一处，gold 因果路径却经过 `ZooKeeperServer.shutdown` 在重启期间保留的过时内存状态——**线索是有方向的，方向可能是反的**。

**10-26 arXiv 2610.35767（RCAtlas）**从另一侧给出机制：90 个验证案例、8 个数据集、6 模型×3 推理力度，三种不预设任何模型调用的简单 harness 拿到 PR@1 65–77%，五种已发表 RCA 智能体只有 16–53%（硬编码了十分之一到全部模型调用），非 LLM 方法 6–39%；案例研究直指预设步骤**「跳过决定性证据」**。公开案例里 SQL 智能体跑了 31 次查询、22 次模型调用，捞出 1,291 条 cart→inventory 拒绝记录、发现 inventory 请求量从每分钟约 1,450 次归零，才提交正确服务。**证据不是被给的，是被查出来的**；而产品页报的是「根因准确率」。

供给侧同一周也在动：**11-03** Honeycomb 官方稿的 forthcoming 调查称 76% 团队认为 AI 生成代码增速已超过审查监控能力、65% 过去半年遇到过由 AI 限流／失控循环／token 尖峰引起的生产问题；**11-05** Google 把 Agent Substrate 与 gVisor 捐给 CNCF（Sandbox 级），官方博客点名「SRE troubleshooter」为典型负载，同时文档列出挂起时开放的数据库与 MCP 连接被丢弃；**11-03** 腾讯 CloudQ 全景图谱主打「从真实云 API 长出来，无需前置治理」，嘉为蓝鲸秋季发布做「字段级数据血缘」；阿里 SLS 升级以 ContextModel／Context Evidence 承接工程师确认、纠正与新 Query。证据底座越修越细，**「本次调查缺什么证据」仍不是一件可交付的东西**。

**主线划界**：94 取证面问原件事后有没有被改，本期问**证据从未被采集**；99 归因面问图上的边是不是猜的，本期问**有没有可供判断的材料**；98 计分面问分母断点，本期问**输入条件有没有被标注**；87 候选面问调查中被排除的假设，本期问**调查开始前被做掉的证据**；83 采样面是抽了没中，本期是**连「没采到」都没记录**。这是负事件家族里唯一「不是丢失、而是从未产生」的成员，也不碰第 26 期已覆盖的配给面。

## 二、技术现状：四态缺口共用一格 null

**证据包是人工制品，且免费**。基准每例给定 incident report、evidence bundle（日志／堆栈）与 pre-fix 仓库快照；生产里三样都要有人现场拼，拼的动作不留痕、不进 MTTR、不进变更流（延续「XX 免费」家族）。结果是最有回报的工程路径——补齐证据——在采购清单里根本不存在。

**四态缺口**：①**没有**（无堆栈、报告不提名方法）；②**误导**（线索指向别处，大异常分数压过模型自身传播分析，99 期在证据层复现）；③**不可达**（NVIDIA DGX 运维多智能体把 kubectl 二进制钉在注册过的只读凭据上，OTel 默认 NO_CONTENT，SLS MCP 免密却仍有权限边界）；④**过期**（证据 as_of 缺位，84 时间基准面复现；挂起恢复时连接断开，使可得性成为随时间的变量）。四态在 trace 里同值 `null`，系统无法据此决定弃权、补取还是升级人。

**默认遥测里只有动作骨架**。11-03 的 OTel 工程稿逐条核出：GenAI 约定已迁至独立仓库、全部标 Development、未切 release，待办 changelog 含移除 `invoke_agent` 内部 span 的必需属性；命令执行 span 的必需属性仅 `gen_ai.operation.name` 与 `gen_ai.tool.name`，参数与结果为 **Opt-In**，`OTEL_INSTRUMENTATION_GENAI_CAPTURE_CONTENT` 默认 `NO_CONTENT`；外部内容上传「不规定 URI scheme、对象布局、序列化格式、保留策略、访问机制」；span 无签名字段、时间戳取本地时钟、可采样丢弃。**该文自己给出的补救是「约定没有为外部证据记录定义属性，须在自有命名空间补一个 receipt hash」**——94 期取证面在采集期复现：不是原件被改，是原件从未生成。

**证据等级只做进结论层**。Honeycomb 每条 finding 链回 query／trace／deploy／ticket、每条记忆标 confirmed 或 hypothesis；阿里把证据汇入 ContextModel、嘉为把血缘挂在字段上；没有一家把「本次调查有哪些证据不可用」做成可导出对象。**11-04** 信通院联合华为、阿里、腾讯、火山引擎等 20 家发布《智能体发展自律公约》，列了注册解析、能力发现、意图转换、路由连接、资源调度与计量、协议互认，**独缺证据可得性一格**。

**本地 173 库连续第二十二期成组启用**，作「证据可得性原型」：刘杨 08 直陈「有了日志、指标和完整 Trace，仍判断不了 Agent 是否做对了任务」「端到端 Trace 不等于可定位」；刘凯宁 05 写「业务语义分散导致**取证困难**」故引入 AntOntology 统一接入，沿业务路径取证，诊断报告三分「结论／证据／**待确认项**」；周昕毅 10 把「能取证、执行、验证」列为生产能力，第一问即须引用实时指标／日志／拓扑；余锦泽 03 给每条关系附数据／代码／文档证据、分「已验证／候选」并让否决作下一轮反例；蒋烁淼 23、马云雷 31 补统一采集与轨迹证据。**判词**：联网侧 11 月才用 120 个 bug 证明「给定证据后仍差 15–25 点」，本地讲义早把取证困难、待确认项、有完整 Trace 仍判断不了写成流程与交付字段；仍是项目内约定，不可采购。

## 四、技术挑战：第五十五个市场空白

五项空白：**证据齐备率**（本次调查声明了哪些证据）、**缺证据声明率**、**线索误导检出率**、**补齐动作留痕率**、**证据 as_of 覆盖率**；`evidence.*` 为**第 24 次无人提字段族**。

**本期反转（修正 89～100 期判词）**：最完整的产品答案仍来自美国创业公司（链回 query／trace／deploy、confirmed 与 hypothesis 二分），最诚实的问题定义出自学术与工程师稿（论文自报 63% 无堆栈、±7–8 点置信区间；OTel 工程稿自认「约定没有为证据记录定义属性」），中国侧粒度最细却停在底座与血缘层。三方互不相认，结果是**「建证据底座」可采购、「链回证据」可采购、「声明缺了什么证据」不可采购**。

细化挑战：线索的方向性无法证伪，报告术语与告警名会被当成证据；补齐是一次无人审批的写入，自动发现的关系若混进 bundle 会静默改结论（93 期教训在证据层复现）；默认不采集＋采样＋保留策略不规定，事后无法重建当时的证据集；挂起恢复丢弃连接，使可得性随运行态变化；容量事件会先吃掉证据（11-06 工程稿记 429 风暴与 TTFT 尖峰，65% 生产问题源自限流与失控循环）；KPI 惩罚弃权，模型于是补出一个合式错值（81／96 期在证据层复现）；120 个 bug 的样本配 ±7–8 点区间，榜单仍不带误差棒（98 期复现）。

## 五、展望与建议

1. **`evidence.*` 九字段进 OTel GenAI 提案**：`bundle_id`／`declared[]`／`missing[]`／`missing_reason`（absent｜misleading｜unreachable｜expired）／`collection_actor`／`collection_as_of`／`source_provenance[]`／`negative_evidence[]`／`completeness_state`，默认 `EVIDENCE_INCOMPLETE`；并在 `execute_tool` span 挂外部证据记录的 hash（沿用 11-03 工程稿建议）。
2. **两类失败分开计**：缺证据不计入 RCA 准确率分母；诊断报告强制第三分「待确认项」（把本地 05 原型产品化），无堆栈／不提名方法的报告自动升级人工。
3. **补齐动作进 trace 与 CAB**，发布 evidence diff，禁止把推断边与自动发现关系不经标注就补进 bundle（合并 99 期）。四态门禁分别触发：误导→重新取证、不可达→扩权申请、过期→按故障时刻重取、没有→弃权。
4. **三轨 SLO**：证据齐备率／线索误导检出率／缺证据时弃权率，与 98 期 graded fraction 并列；证据 as_of 绑定故障时刻快照，挂起恢复后强制重取。
5. **六类混沌注入**：无堆栈、报告术语误导、跨文件多块因果、只读凭据下外部证据不可达、bundle 过期、429 期间采集被削。演练验收以能否导出 `missing[]` 清单为准。
6. **标准与采购**：11-04 自律公约「资源调度与计量」与信通院六维「结果可评价」补「证据可得性声明」条款；采购三问——本次调查声明了哪些证据不可用？补齐动作谁做、记在哪？证据集能否按故障时刻重放？下周 KubeCon NA 2026（11-09 开幕，首设 AI Inference + Agentic track 与 Agentics Day）是把该提案带进标准讨论的窗口。
