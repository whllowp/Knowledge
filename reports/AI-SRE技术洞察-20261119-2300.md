# AI-SRE 技术洞察报告（第 290 期）

**生成时间**：2026-11-19 23:00（档位 2300，取自系统 `date`）
**时间范围**：2026 年，重点最近 30 天（10 月下旬—11 月中旬）
**本期主题**：证据通道面／把沉默误读为健康（Evidence-Channel Integrity / Silence-as-Health Fallacy）——第 242 条全新立面

> **题眼**：行业把"面板上没有红点、Agent 没有报事故"默认为"系统健康"。但 Google 11 月披露的伦敦区故障里，一台控制器整晚盯着错误的电缆、把断电当成供电正常，于是从头到尾没有发出启动指令——它"看见"的电源是好的，真正坏掉的是**证据本身**。人人都在给系统装传感器，几乎没有人在给"传感器到决策者之间那条路"装传感器。当凌晨四点读仪表盘的不是疲惫的工程师而是一个自信的 Agent 时，一条安静地停止导出的管道，看起来和一个平静的周二完全一样。本期首次把"证据通道是否还活着、沉默是真没事还是没送到"立为一等对象，与第 285 期"健康态误诊（假事故）"构成正反对偶：285 问"没事时会不会报出事"，290 问"出事时会不会因为没收到而报没事"。

## 一、发展趋势

**趋势一：从"给系统装传感器"转向"给证据通路装传感器"。** 2026 年 11 月 13 日 Mastering Observability 复盘 Google 伦敦区故障：供应商 A 馈线电缆在街道下故障、B 馈线因季度发电机负载测试已被断开、现场发电机Bank未启动、电池撑满设计的 5 分钟后停止——根因被 Google 归为电压检测设计缺陷加控制器误配置，控制器"读到了一条仍然带电的线"因而从未下达启动命令。文章给出一句被反复引用的判词："Everybody instruments the system. Almost nobody instruments the route the evidence travels."（人人都监控被观测系统，几乎没人监控证据传输的路线。）OpenTelemetry 项目 11 月 10 日更直白："The application may be healthy while its telemetry path is not."（应用可能健康，但它的遥测通路不健康。）两件事在同一周出现，标志着一个趋势拐点：可观测性的对象从"被测系统"扩展到"测量系统本身"。

**趋势二：Agent 作为证据消费者，把通道缺陷从"人能察觉"放大成"机器确信"。** 人类值班工程师面对空面板会本能地怀疑"是不是采集中断了"，而 Agent 不会。上述文章警告："Hand an agent silence and it will report calm, with reasons, in decent English."（给 Agent 一段沉默，它会用像样的英语、带着理由地报告一切平静。）这使通道完整性从"可观测性质量问题"升级为"自治决策安全问题"。

**趋势三：审计与治理开始区分"事前拦截"和"事后重建"，但都默认证据通路可信。** Google 11 月 12 日发布 Agent Anomaly Detection 评测（1774 段模拟会话、Gemini 2.5 Flash、报告对已执行的有害指令检出 87%、良性会话误报 2%–16%），明确其审计是"读取已有日志和 OpenTelemetry trace、位于实时请求路径之外"的异步动作；同期 Semantic Governance 则是调用前用概率模型评估提议的工具调用。二者一个重建、一个拦截，但共同前提是"记录下来的证据在场"。

## 二、技术现状

**采集标准已统一，但"统一采集"被误当成"通道可信"。** 腾讯云 11 月技术文章称截至 2026 年超过 78% 的组织在生产使用 OpenTelemetry，运维不再为每个后端维护不同采集代理；阿里云 UModel 内置 3200+ 模型定义、覆盖 10 大观测域，AgentBridge 主打"可信、可追溯、持续更新的实时上下文"。然而采集统一解决的是"有没有一种格式"，没有解决"这一刻数据到底有没有送到"。Mastering Observability 给出的廉价修法——对账计数（accepted = completed + rejected + still processing）、按已知间隔向真实路径发送合成事件、同时检查 collector 自身的 receiver/exporter 计数器——在主流平台的发布页上几乎看不到对应字段。

**"沉默"在机器侧仍是单一语义。** 空面板至少压缩了四种状态：系统真无事、采集没开启、采集开着但导出停了、导出到了但查询时间窗选错。Google 11 月的另一条线索佐证了这一塌陷：Anthropic 11 月 13 日两起事故中，官方 15:33 的更新写明"定时任务和例行程序可能延迟两小时以上、部分运行被跳过"——被跳过的调度没有错误日志，因为没有东西启动；Rush Commerce 由此给出的工程要求（自建运行记录、dead-man 缺失告警、幂等键、可补跑）本质上都是"给沉默装一个外部参照物"。

**判定与基准尚未覆盖通道断流。** Causely 在 OpenTelemetry Astronomy Shop 上的对照（有/无因果上下文：根因正确率 75%→100%、工具调用 19→4、每轮 token 308K→123K、诊断 73s→25s，健康集群假事故 4/12→1/12）附带九项"你的 Agent 能信任它读到的遥测吗"自检清单，是目前最接近"通道体检"的公开方法，如 error span 是否带 reason、`unknown_service` 占比、单 span trace 占比、log severity 与 body 是否一致。但基准侧仍是空白：SREGym-Lite 17 个故障在 2026 年 10 月已被 Cognition（Claude Opus 5.5，100%、141 秒）和 CloudThinker（GPT-6 Astra，100%）跑满饱和，ITBench-AA 上无前沿模型过半——这些题目全部预设"故障已注入且证据齐全"，没有一道考"证据没来时 Agent 会不会诚实地说不知道"。

## 四、技术挑战

1. **沉默的语义塌陷与认知卸载。** 空面板同时表示"真无事/没采到/采到没送/送了查错窗"，Agent 拿到 silence 会生成一段有理有据的"健康叙事"；人越依赖它，越不会去核对那条通路。这与第 260 期"置信度校准"同构但位置不同：260 问"把握这个数诚不诚实"，290 问"支撑判断的证据到没到场"。

2. **审计与通道共谋。** Google 的异步审计读的是已记录的日志与 OTel trace，通道断流时它输出的是"未发现异常"而不是"无法审计"；分母是"已完成的有害行为"而非全部攻击尝试， poisoned-memory 检出仅 4/18、约 6% 会话无结果——一个 cherry-pick 的记录集会让审计看起来漂亮。

3. **失败姿态不对称。** OpenAI Control Room 自挂则全拒绝（fail-closed），而观测通路自挂则全相信（fail-open）。安全控制与证据供给在"自己坏了怎么办"上采取相反默认，自治系统因此在最该谨慎的时刻最脆弱。

4. **合成探测的真实性成本。** 向真实路径发合成事件能测"安静是否被信任"，但注入流量本身有成本，且经过采样、脱敏、留存后，合成事件走的路径未必等同真实用户路径——第 269 期"证据存续面"的留存选择会二次污染通道体检。

5. **基准缺题与饱和管理。** SREGym-Lite 已饱和、ITBench-AA 无模型过半，题库全是证据齐全的干净故障；缺一类"导出器静默停止"题，无法测量 Agent 区分"静默"与"断流"的能力。

## 五、展望与建议

**提出第 211 个空白字段族 `evidence.channel.*`（缺省 SILENCE_UNVERIFIED，不进自治门禁）**：`channel_healthy_at`（通路自检时刻）、`accepted`／`completed`／`rejected`／`still_processing` 四方对账、`synthetic_probe_interval_seconds` 与 `last_probe_received_at`、`collector_receiver_exporter_counter_hash`（通路自身计数器指纹）、`silence_state ∈ {true_quiet, no_signal_unknown, path_broken}`、`posture_on_channel_failure ∈ {fail_open, fail_closed}`。命名与第 285 期 `quiescence.verification.*` 正交：后者管"该不该沉默"，本族管"这份沉默是不是真的"。

- **把"通路体检"前置为门禁**：自治等级越高，`synthetic_probe_interval_seconds` 越短；`path_broken` 或超过一个探测周期未收到合成事件，禁止进入"健康/无需动作"结论，改走人工或降级路径。
- **对账进 SLO**：accepted = completed + rejected + still_processing 对账不闭合即告警，让"安静"必须被证明而非被信任；检查 collector 自身计数器，运行中的进程不等于工作着的信号。
- **统一失败姿态评审**：把安全域 fail-closed 的原则扩展到证据通路——通道失败时默认"未知/无法判断"，而非默认"健康"；Anthropic 定时任务缺跑应在 Agent 侧产生 dead-man 信号。
- **审计输出加通道覆盖声明**：异步审计必须同时报告"本结论基于的通路在审计窗口内的完整度"，低于阈值标记 UNVERIFIABLE 而非 NO_ISSUE。
- **基准补一类断流题**：在 SREGym／ITBench 中关掉导出器或制造错配 service.name，考察 Agent 是否输出"证据不足"而非自信的健康结论；同时报召回-假事故-假健康三维。
- **信通院六维补「通路可举证率」格**，与第 285 期「健康态特异可举证率」并列成"健康—通路"双层。
- **本地知识积累角度（第 166 期）**：刘杨《从 Trace 到规模化实时评估》重读为"trace 从 span 完成到导出之间那段路，正是本期通路"；配刘凯宁蚂蚁 SRE"结论/证据/待确认项三分"新增第四分——"这份证据是何时、经由哪条通路抵达的，通路当时活着吗"。
