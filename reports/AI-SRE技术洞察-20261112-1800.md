## 一、发展趋势

**1. 推理与执行分离成为参考架构。** Google 把 AI Operator（推理）与 Actus（执行/Actuation Agent）拆成两个信任模型不同的组件：前者概率性、会出错、可被注入；后者确定性、可强制 dry-run、可按风险降级。Cloud and SRE 的评论切中要害：「把两者塌缩，你的护栏就是一句 system prompt。」这标志 Agentic Ops 从「更聪明的模型」转向「更笨但更快的闸门」。

**2. 确定性策略引擎前移到工具调用边界。** Cogent TRACE、DeepInspect 内联代理都把「能不能动手」从模型输出里抽出来，变成一次不参与思考的判定（Cogent 明确「不需要额外模型推理」，DeepInspect 默认拒绝、<50ms）。策略不再住在 prompt 里，而住在 Agent 与工具之间的那一层。

**3. 授权与认证在协议层分叉。** A2A（8-17 并入 Linux Foundation Agentic AI Foundation）与 MCP 标准化了身份认证（签名 Agent Card、OAuth/OIDC），但**授权（这个已认证 Agent 此刻能对这份数据做什么）刻意留白**——DeepInspect 称之为「被正式化在协议层、却无人回答」的委托授权缺口。

**4. 红钮从事后变前置。** OpenAI 控制中心 35 秒才阻断，说明研究基础设施可以接受；但生产 SRE Agent 的等价红钮要么没有、要么只在全局层面。趋势是把「紧急停止」从事件后处置前移到每一次动作的预检。

## 二、技术现状

- **最完整的 PEP 来自安全侧而非 SRE 侧**：Cogent TRACE（企业防御工厂）、DeepInspect（内联代理）、Google Actus（参考架构）三者共同定义了「推理-执行分离＋确定性前拦截＋独立动作血缘」的范式。
- **主流六家 SRE Agent 平台普遍描述「分级自治/边界/Harness/护栏」，但没有一家把「每个工具调用执行前的独立确定性策略执行点」做成可单独指出、可独立审计的组件**；多数把门禁逻辑埋在编排或系统提示里，与 153（基准第二道闸）、157（图谱约束层）同源但不同层。
- **本地 173 知识库早已给出生产原型**：刘凯宁 05「把大模型关进确定性笼子」（蚂蚁 SRE 应急根因，AntOntology 运维本体）；03 笔记「本体约束校验只拦截、不改写 SQL；确定性模块覆盖率 89%；审批不向智能体开放；否决后引用该关系的 SQL 在执行前被拦截」；04 笔记「AI 网关统一入口、安全护栏；Skill 门禁拦截，问题在提交前暴露；统一网关限流」。即：本地把「确定性笼子＋只拦截不改写＋审批不向智能体开放」写进了生产应急根因实践，联网侧 2026 才由 TRACE/DeepInspect/Actus 做成独立执行点。
- **标准化现状**：OTel GenAI 语义约定仍处 Development 状态（见 157 期），动作血缘尚无标准字段；A2A/MCP 解决认证不解决授权。

## 四、技术挑战

1. **策略与模型耦合**：多数平台把门禁写进 system prompt 或编排代码，模型一被注入，护栏即失效——「可被一句话说服的护栏不是护栏」。
2. **前拦截覆盖率缺口**：工具调用前的确定性检查若只覆盖部分工具（如仅 MCP、漏掉直接 API），爆破半径仍可被绕过。
3. **自主降级不可观测**：Actus 能 L3→L2 降级，但「这次为什么降级、降级覆盖率多少」无 SLI——接 117 失效姿态。
4. **动作血缘自证**：Agent 自己写日志当审计轨迹，等于「日记不是证据」（DeepInspect 判词）；独立重建需要第三方组件在每次调用前落独立记录。
5. **红钮时延**：OpenAI 35 秒说明研究侧可接受，生产侧同等时延意味着 35 秒内的破坏已发生；红钮生效时延无 SLO。
6. **授权语义空白**：A2A/MCP 认证已标准化，跨组织边界的授权仍由每家自定义，多智能体委托链无统一判定。

## 五、展望与建议

- **字段化**：`pep.*` 七字段（pep_id／policy_ref／intercept_before_tool／deterministic／downgrade_observed／lineage_independent／kill_switch_latency）。
- **常驻 SLI（第 109 个市场空白五项）**：策略执行点独立化率、工具调用前确定性拦截覆盖率、自主降级可观测率、动作血缘独立重建率、红钮生效时延 SLO 达标率；`pep.*`／`enforce.*` **第 76 次无人提字段族**。
- **推理-执行分离落到工程**：策展工具注册表＋强制 dry-run＋理由核验＋并发检查（复用 Actus 三阶段）；策略引擎与模型解耦（复用 TRACE/DeepInspect）。
- **默认拒绝＋独立授权**：Agent Gateway 在推理之外再校验一次（接 92 能力来源）；跨组织委托链按 A2A 身份＋本地授权策略双层判定。
- **评测补「策略越权拦截率/降级误判率」**（接 153 安全门禁）；信通院六维补「执行点独立性达标率」格。
