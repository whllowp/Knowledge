# AI-SRE 技术洞察 · 第 162 期（2026-11-13 01:00）· Agent 可观测性黑洞面（Agent Observability / 智能体自身遥测）

> **题眼**：我们给被运维的系统装满了指标、日志与追踪，却几乎不观测"运维它的 Agent 自己"。SRE Agent 是事故里最该被 trace 的组件，却最没有被 trace——它的规划、工具调用、子 agent 交接、token 与成本，散落在厂商私有日志里，没有一根跨厂商的标准 trace 树。OpenTelemetry 的 GenAI 语义约定（2026，仍 Development）提供了标准词汇，但六家 SRE Agent 平台几乎没有一个公开用它对"自己的事故处置动作"做语义导出。本期把"Agent 自身可观测性"立为一等运维对象：当 Agent 凌晨三点改了你的生产，你能不能在一条 trace 里复现它每一步？

## 一、发展趋势

可观测性的对象正在从"被管的系统"反转为"看系统的 Agent 自己"。三个信号值得注意：

**标准正在成型但远未稳定。** OpenTelemetry 的 GenAI SIG 在 2026 把 GenAI 语义约定移入独立仓库 `semantic-conventions-genai`，定义了 `create_agent` / `invoke_agent` / `plan` / `invoke_workflow` / `execute_tool` 等 span 以及四个 MCP 指标，但所有相关文档都被标记 `Status: Development`——可以现在就用，但是移动靶，必须 pin 住版本、预期语义会变。

**生态向 OTel 收敛。** VS Code Copilot、OpenAI Codex、Claude Code 已通过 OTel 导出 trace / metric / event；2026 年 8 月 Dynatrace 收购 Arize（其 OpenInference 追踪"基于 OpenTelemetry"），说明可观测厂商把"Agent 追踪"当成了战略要地。

**角色反转（本期核心判断）。** 可观测性过去是"看系统"，Agentic SRE 把它反转为"看那个看系统的 Agent"——讽刺的是，被看的 infra 比看它的 Agent instrumentation 更完整。看门人看不见自己，是最该被观测的组件最没有被观测。

## 二、技术现状

**编码助手侧已先行，处置 Agent 侧缺席。** Claude Code 经 OTel 导出 metric + log event（trace 在 beta）；Codex 导出结构化 log event 与 OTel metric；Copilot 每个 agent 交互都出 trace / metric / event。但这些都是"写代码的助手"，不是"处置事故的 SRE Agent"——标准词汇有了，事故处置 Agent 自己却很少用。

**四信号地基（trodo 2026）。** 每个 run 一个带 `run_id` 的根 span（成功 / 部分 / 失败）、每个工具调用一个 span（名 / 输入输出 / 时延 / 成败）、每个 LLM 调用记录 prompt + completion + token + cost、根 span 挂 user / session 上下文。

**语义成功 ≠ HTTP 成功。** 一个工具返回 200 却在 15% 情况下给出空或错误结果，传统成功率指标对此完全盲。必须捕获"语义成功"（这次调用是否真的完成了它被需要的事）。

**采样铁律。** 尾采样保留 100% 错误 run、100% 新 prompt 版本的前 N 次、健康 run 抽 5–20%；头采样随机丢长尾，会把恰好要调试的稀有失败丢掉。

**隐私反转。** agent trace 比 infra trace 含有更多 PII（prompt 里可能有用户 PII、密钥、源码），最该采集的 telemetry 恰恰最该脱敏——脱敏要在 pipeline 层做，而不是在 instrumentation 源码里做。

**判读（本期反转）：** 把"Agent 自身追踪"做成标准的是 OpenTelemetry 社区 + 编码助手三强（Copilot / Codex / Claude Code），而真正处置生产事故的六家 SRE Agent 平台，在"事故动作是否进一根 OTel GenAI trace 树、能否跨 MCP / 子 agent / 微服务关联、能否回放"三列要么缺要么未公开。能报 MTTR 下降的多，能给你一根可重放的事故处置 trace 的零——可观测性的最后一公里，倒在了 Agent 自己身上。

**本地原型（连续启用）：**
- **08 刘杨（蚂蚁可观测团队）**：统一埋点遵循 OTel GenAI 语义约定（L1 / L2 / L3 三层、9 类 Span），以 Trace 为中心的实时评估链路（分钟级端到端延迟），Token 粒度定位与概率分布评判稳定性。核心痛点："有了完整 Trace 仍判断不了 Agent 是否做对任务"——可观测的下一站是"以 Trace 为中心的实时评估 + Token 级深度分析"。
- **23 蒋烁淼（观测云）**：AgentOps 主线，DataKit 兼容 OpenTelemetry 统一全域采集，GuanceDB 统一可观测数据湖，"统一目录补上服务语义和知识"。
- **10 周昕毅（携程 AISRE）**：灵魂三问第一条"告警须引用实时指标 / 日志 / 拓扑"＝诊断取证以可观测底座为前提；与第 160 期命名根因取证、第 08 期 Trace 中心评估共组"可观测取证链"。

## 四、技术挑战

- **语义不统一**：同一次工具调用 / RAG / 记忆读写，在不同框架里是独立 Span / event 日志行 / 干脆不上报——必须先把语义统一（见 08 的踩坑）。
- **长程不可定位**：几十步任务，端到端 Trace ≠ 可定位，错误可能出在任意一步（08）。
- **标准未稳定**：GenAI 约定全部 Development，采用即承担 churn，须 pin 版本、expect 变动。
- **隐私合规**：agent trace 落入 HIPAA / SOC 2 / GDPR 范围；全量保真 trace 须短留存 + 受限访问，聚合 / 抽样长留存（belsoft 2026）。
- **成本反模式**：把 token 成本当主成功指标，会诱使少 token → 多重试 → 墙钟更长；应量"每次成功业务结果的成本"（interlock 2026）。
- **回放完整性**：事故处置 Agent 的动作若不在可重放 trace 中，postmortem 与合规取证无据——与第 159 期动作血缘、第 160 期因果取证同源但更底层：连"看见"都没有。
- **第 112 个市场空白五项**（trace 覆盖率 / 工具 span 完整率 / 跨边界关联率 / token 成本归因率 / 语义成功捕获率）；字段族 `agent.obs.*`（trace_coverage / tool_span_completeness / cross_boundary_correlation / token_cost_attribution / semantic_success_capture / replay_integrity / pii_redaction_rate）第 79 次无人提字段族。

## 五、展望与建议

1. **字段 schema**：`agent.obs.*` 七字段（trace_coverage / tool_span_completeness / cross_boundary_correlation / token_cost_attribution / semantic_success_capture / replay_integrity / pii_redaction_rate），提 OTel GenAI 约定提案，纳入 SRE Agent 处置层。
2. **一根 trace 一事故**：每起事故处置以 `run_id` 根 span 起止，`plan` / `invoke_agent` / `execute_tool` 为子 span，强制把"改了什么"写进可重放 trace（深化第 159 期动作血缘、第 160 期取证）。
3. **语义成功指标**：工具 span 带语义成败而非仅 HTTP 200；把"返回空 / 错 15%"做成告警。
4. **尾采样保错**：100% 错误 run + 新版本前 N 次全留，健康 run 抽 5–20%；头采样禁用。
5. **pipeline 脱敏**：在 Collector 层做 PII 检测脱敏（非 instrumentation 源码），保真 trace 短留存、聚合长留存，mapping 到合规边界。
6. **跨边界 W3C 传播**：MCP / 子 agent / 微服务贯通 trace context，否则树断成碎片（interlock / bixtech 2026）。
7. **接本地三原型**：08 的 OTel GenAI 三层九类 Span 埋点标准 + 23 的 DataKit 兼容采集 + 10 的"取证需可观测底座"，先把"看见 Agent"做进生产闭环。
8. **评测扩展**：Incident-Arena / SREGym 增"trace 覆盖率 / 可重放率"维度；信通院六维补"Agent 自观测达标率"格。
