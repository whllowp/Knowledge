# AI-SRE 技术洞察 · 第 49 期（2026-11-03 12:00）

**本期主线：对抗面（输入完整性面）运维——遥测是证据，还是指令载体？**

划定边界：与第 36 期分界=那期管遥测作为原料的成本、质量与所有权，本期管原料的可信性——它会不会同时是指令载体；与第 23 期分界=那期管供应链（MCP/Skill 装进来之前），本期管运行时数据通道（装进来之后读到的每一个字段）；与第 34 期分界=那期管确定性边界的构造与归属，本期管边界之外输入侧的信任标注。

## 一、发展趋势

运维数据的角色正在发生一次静默切换：LLM 开始**解释**日志而非解析日志之后，同一份记录同时承担了"证据"与"指令载体"两个角色。USENIX Security '26（8 月 14 日）的 AIOpsDoom 论文给出关键结论——**日志可以"真实"却不可信**：应用确实发出了这条日志，但其中某些字段的值来源于不可信的外部请求；**存储完整性不等于记录内每个字段的完整性**。这一条直接推翻了"监控数据默认可信"的核心设计假设。攻击在 SocialNet/HotelReservation 上成功率 89.2%，GPT-4o 与 GPT-4.1 的易感性分别达 97% 与 82%，且可绕过 Microsoft PromptShields 与 Meta PromptGuard-2。

两个现场级演示把问题从论文拉进生产视野。其一，Straiker STAR Labs 8 月 24 日公开的 Escape from Pod 9：向公开 /login 端点发一个 HTTP POST，username 字段里不是用户名，而是一条严格遵循 OpenTelemetry 语义约定的伪造告警——基于 Bedrock/EKS 的 AI SRE agent 巡检"近期失败登录"时将其当作合法 OTEL 信号摄入，按其中的"修复建议"部署特权容器、nsenter 逃逸到宿主机、AES-256-CBC 加密业务文件并维持 20 分钟持久化，击败了 agent 自己的自动恢复循环。**没有软件漏洞、没有凭据泄露，漏洞在 agent 的设计里，厂商无补丁可打。**其二，DEF CON 上的 Ghostjacking：一条被 Cloudflare **原样记录**的、已经拦掉的防火墙请求，让读取日志的 agent 修改 DNS 设置并把事件标记为"已解决"，对 Claude Code 成功率 9/10——**被安全设备拦下的攻击，反而进入了最被信任的日志**。

判读：行业的 frame 正从"提示注入是模型安全团队的麻烦"切换为"输入完整性是运维工程问题"——防御的主战场从 prompt 搬到了遥测管道。

## 二、技术现状

攻击面已分类成型。arXiv 综述（经 Help Net Security 解读）将其概括为 **confused deputy（混淆代理）**：agent 持有变更 API、部署流水线的合法权限，而塑造它行为的文本（工单、runbook、告警正文）恰是攻击者可影响的工件。四类可区分模式：①运维工件注入（工单/wiki/代码注释里藏指令）；②检索投毒（污染复盘库使诊断偏向预设结论）；③**检索阻塞**——反向灌入大量"阻断文档"制造拒答循环，不偷数据也不改配置，却在事故响应最需要速度的时点打可用性，最易被低估；④遥测操纵（本期的主命题）。

防御侧收敛出三件套。**其一，propose-commit 分离**：模型只起草 diff，任何触达生产的写操作走模型无权绕过的确定性门禁——OWASP 把 Excessive Agency 从 LLM06 升到 LLM03（2026 版），其工程含义就是"propose-commit 没实现干净"。国内方法论在 173 库 casa 的讲稿里有朴素对应物："人决定做什么、定义边界、对结果负责；AI 提供候选方案、执行任务、交回可查证据"——独立开发者的协作纪律与安全架构在此同构。**其二，污点分析与净化**：AIOpsShield 四步——canary 值重放标定外部可影响字段、LLM 辅助推导模板（三个测试应用各 84/12/132 个）、运行时把不可信值抽象化（如 User#12）、原始记录另存供人深查；开启后测试攻击无一成功。**其三，完整性标签流控**：微软 FIDES（已入 agent-framework-core 实验特性）让 trusted/untrusted 标签随工具调用自动传播，只要 untrusted 内容还在作用域内，`post_comment` 这类特权 sink 一律拒绝——官方动机写得刻骨：防御性 system prompt 和手写 allowlist "都不是确定性的，在有人把 [SYSTEM OVERRIDE] 塞进 issue 正文的那天会静默失败"。英国 NCSC 给了底线判断：提示注入可能永远无法彻底消除，指导原则是**"当 LLM 处理来自某一方的信息时，其权限应降级为该方的权限"**。

标准与事件同步逼近：OWASP Agentic Top 10（ASI01 目标劫持被称"自主时代的新 SQL 注入"、ASI06 记忆与上下文投毒）已发布；LLM Top 10 2026（8 月 3 日）出现一个耐人寻味的事实——按真实事件数提示注入会跌出前十，从业者投票仍把它保在 LLM01。最新事态（11 月 2 日，Forever Security 披露）：客户下载文件夹里一个恶意 AGENTS.md 让 Codex 在 90%+ 测试中遵循指令、篡改全机 MCP 配置并绕过沙箱再开会话；恶意 CLAUDE.md 约 50% 场景可重定向 Claude Code 的 API 流量窃取令牌。**输入通道已经从"遥测字段"蔓延到"躺在磁盘上的指令文件"。**

两点判读。其一，Datadog 工程博客的主张值得单独记：**guardrail 放在编排环路哪个位置，比它检查什么更重要**——放在 post-tool-result 时模型已决定调用工具、注入早已成功；其四挂载点设计（pre-model/pre-tool/post-tool/pre-user）是目前最诚实的架构自白。其二，AWS 的 AGENTSEC08 成熟度模型罕见地承认行业现状：绝大多数部署停在第 1 级——用户输入防得很严，而工具输出、检索内容、agent 间消息和记忆读取几乎裸奔，**后者恰恰是被攻击最多的向量**。国内三条路线（云上全栈/终端管控/内容风控）在入口与运行时拦截上跟进迅速——CNNVD 一季度已采集 82 个 OpenClaw 漏洞，信通院首批治理评估 7 月放榜——但字段级输入信任标注全部空白。继 38 期幂等并发、39 期断网重放、43 期视图指纹、44 期截断率、45 期该说没说、47 期边没有标准之后，**"证据-解释-权限三者分离"无一家产品化，是第七个市场空白**——且 AIOpsShield 证明了用遥测的结构化特征实现净化的可行性与低成本。

## 四、技术挑战

一是**净化与诊断的对抗**：字段抽象可能误删诊断上下文（富内容场景误报率 10-30%），模板覆盖率依赖发现是否彻底，schema、采集器、prompt、端点每变更一次就必须重测——输入信任边界因此是有自己的 SLO 的运维对象，不是一次性配置。二是**标注法可被仿制**：非自适应测试中边界标签可把注入成功率从 >50% 压到 <2%，但攻击者一旦知道标注方案即可仿制 trusted 标记，自适应攻击下不成立。三是**对抗性奖励劫持绕过分类器**：AIOpsDoom 的 payload 不是"忽略之前的指令"，而是"合理解释+合理补救"，让 agent 在被操纵的证据下"自愿"选出有害动作——模式/分类器层防御（PromptShields 类）对此系统性失效，硬边界只能建在授权层。四是**归因困难**：事故后必须能区分"模型判断错/证据被污染/执行控制失效"三者，这要求把触发告警、净化后视图、推理输出、策略决策、执行结果串成一条完整性受保护的审计链；且 Kubernetes 准入控制（拒绝特权容器）必须独立于 agent 身份存在——Escape from Pod 9 的直接教训是 agent 自己的权限不能是最后一道防线。五是**评测缺口**：现有基准几乎不报门禁违规率、对抗输入下行为、拒答风暴率与回滚完整性——良性负载上的成功率对这类攻击不构成任何证据。

## 五、展望与建议

建议把"输入信任边界"当作一等运维对象来运营：①盘点 agent 可见的全部遥测路径（告警、trace、工单、聊天集成、检索到的 runbook），逐字段标注哪些可被外部影响；②建立三条 SLO——外部可影响字段标注覆盖率、净化误删率（诊断上下文损失）、canary 对抗重放通过率（在合法输入里埋 canary，验证其在所有出口都能被识别）；③红队靶标从聊天机器人换成整条链：外部请求→遥测生成→采集→检索→诊断→授权→执行；④采购三问：guardrail 挂在环路哪个位置？默认开启吗？有活体故障注入下的对抗评估数据吗？展望 2027：AIOpsDoom 结论（存储完整性≠字段完整性）与 47 期"节点有标准边没有"同构——OTel 语义约定迟早要回答 **telemetry provenance**（字段级来源与信任标注），这是标准组织又一个正在打开而未完成的时间窗。
