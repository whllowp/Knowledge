# AI-SRE 技术洞察 · 第 102 期

## 分派面／题型面（Triage Granularity / Jagged Capability Envelope）

> **题眼**：前 101 期补的都是「智能体做这件事时还缺哪层制度」，本期再往前挪一步，问**「凭什么把这件事交给它」**。11-03 同一周里，一份官方文档把权限粒度做到工具集并列出两种相反默认值，另一份工程稿承认一次崩溃「看起来是 bug，其实是攻击」，而行业分级按的是自治度不是题型。更棘手的是：**分派发生在分类之后，分类恰恰是最先失效的那一步。**

## 一、发展趋势：分级按自治度，失效率按题型

**11-03 Rootly AI Lab 负责人 Sylvain Kalache**（Arrested DevOps 播客）给出本期最直白的分布描述：AI SRE 在简单、toil-heavy 事故上已接近 100%，面对复杂根因分析时表现转为「jagged（锯齿状）」。他转述 Anthropic 可靠性工程师的案例更关键：一次携带 22 张图片的 API 请求导致崩溃，Claude 没有停在报错，而是分析 4,000 个账户的请求模式，判定为滥用攻击而非软件缺陷。**同一条告警，按 bug 修与按攻击处置是两套相反动作；分类错了，越标准的修复越帮倒忙。**

学术侧在同一周把锯齿量化：**11-04 arXiv 2611.06099《SWEOps-Bench》**（55 任务／16 个 K8s operator）检出 72.7–90.9%，经验证恢复仅 14.5–52.7%，且 RCA 报错仍可能恢复成功；**10-26 arXiv 2610.35767 RCAtlas**（90 案例／6 模型×3 推理力度）三种不预设调用的简单 harness 拿 PR@1 65–77%，五种已发表 RCA 智能体只有 16–53%；**11-02 arXiv 2611.03523 DistDebug**（120 真实 bug／218 gold 因果块）45% 需多块因果、23% 跨文件，找对文件 83.9% 而命名因果块仅 67.7%（后两组数字据第三方对论文表格解读，arXiv 摘要只给规模与定性缺口）。三份基准都**统一发卷**，只报总分或阶段分，没有一份给出「按题型的分派曲线」。

供给侧的分级口径则完全在另一坐标：**11-03 信通院《云上 Agent 基准度量模型》**建议按「辅助诊断→审批执行→限定自治」分阶段落地并保留人工接管兜底；**11-03 腾讯生态大会供稿**里搜狐畅游的做法是「按动作影响范围、可回退性划分人机职责」；**11-03 PagerDuty Paige GA** 让团队逐组配置权限，仅在「明确授权的低风险、well-understood 场景」自主行动，并宣称信任「incident by incident」逐步累积。同期 **11-02 Google Cloud** 把 BigQuery 数据智能体的会话级性能与成本做成 GA 可观测，**11-02/11-04** 可观测官方文档更新（ADK 依赖 OTel GenAI 约定、`is_agentic=true` 双重归因）。**可观测修得越细，越是在量「它做得怎么样」，而不是「这道题该不该给它」。**

**主线划界**：第 21 期能力预算管人的练习量，本期管系统按什么颗粒度决定让谁上，并指出 21 期「人侧全空白」的根源是没有题型对象可挂；98 计分面管分数怎么算出来，本期管分数按哪几峰分布；101 证据可得面管开口前缺哪些证据，本期管**开口前判不判得出这是什么题**；82 缺省面管没有变更事件的那一半配置，本期管没写配置时采用的那一档分派；87 候选面与 97 组合面管调查中的假设与逐步审批，本期管调查开始前把题分错类。这是负事件家族里唯一「**没被做错、而是被分错**」的成员。

## 二、技术现状：粒度挂在工具上，默认值就是策略

**最硬的三份材料都出自官方文档，且彼此矛盾。** 火山引擎《工具权限策略》页把权限策略定为 `always_allow`／`always_ask` 两档，只作用于服务端内置工具集、多模态工具集与 MCP 工具集；**默认值取决于是否提供 `default_config`**：整个省略时内置与 MCP 都保存 `enabled=true`＋`always_allow`；提供了 `default_config` 却省略 `permission_policy` 时，内置工具运行时取 `always_allow`、MCP 取 `always_ask`。官方建议「始终显式配置」，以便回显与运行时行为可核对。阿里云国际站 OpenAgent《Confirmation and approval mechanisms》同样分会话确认与 HITL 操作审批两层，会话级白名单按「操作类型」放行，并写明**操作审批默认关闭**。**没有写配置不是没有策略，而是采用了最宽松的那一档**。

**粒度全线落在动作与渠道，而非题型。** 阿里白名单按操作类型，火山按工具集，腾讯按动作可回退性，PagerDuty 按团队授权的低风险场景（Shift Agent 按技能集路由人、不按题型路由题）；**10-29 OpenAI 四层监控**的覆盖边界按流量渠道划分——前沿 RL 与内部 Codex 跳过激活探针直接审查，Chat Completions 不在覆盖内，多数流量仅工作时间呼叫；**Anthropic 自我评估**抓到 78%／高优先级 94% 的失准、误报 1%，但作为拦截器面对 24 个网络安全任务只把攻击成功率从 79% 压到 54%，弱于完整提示式分类器的 25%——**检出率高不等于拦得住**。这些口径各自合理，合起来却说明：没有任何一层在动手前声明「本题属于哪一峰」。

**代理变量错配是本期最实的发现。** 「可回退」「影响半径」「工具集」「低风险」都是动作属性，而失效率是题目属性；一个低风险、可回滚的动作完全可能落在最难的题上——重启 Pod 很简单，却会抹掉内存里的攻击痕迹。反过来说，**11-03 阿里云「7 个样板间」工程稿**写出全行业最接近正确方向的三档：「标准明确、可评测、可回滚的任务由 Agent 执行、人审批；跨领域但风险可控的由 Owner 借助 Agent 闭环；高风险、高歧义或不可逆的仍由专业人员主导」，并给出根因评测集从 3 月 58 条增至 9 月 838 条、覆盖 100 多类故障、按五维校验。**这是唯一把「题」而非「动作」写进分派依据的公开材料，但授权仍挂在人与组织配置里，题型字段不可导出、无分母、无版本。**

**本地 173 库连续第二十三期成组启用**，作「题型分派原型」：陶炳哲 30 的灵魂命题是「**路由的是执行方案**——把适合的任务交给适合的模型＋harness，而非简单『难的给大模型』」，并明说「长上下文不一定需复杂推理，短指令也可能推进大型工程」；肖汉松 22「单 Agent 无法解决时须**携带证据改派**，Loop 承接每一次交接」＝按题型重新分派且带证据；周昕毅 10「白名单动作、恢复失败转人工」；朱革 15 真实事故（insert 失败后自行 DROP 库重建表）＝题型误判后的越级；刘凯宁 05 三分报告含「待确认项」；余锦泽 03「已验证／候选」二态；孙鹏 11、施宏斌 14、马云雷 31 补回归集与漂移。**判词**：联网侧 11 月才把「按题型逐条累积授权」做成产品话术，本地讲义早把「按任务评测结果路由」「携带证据改派」写成工程方法；两边粒度都挂在模型、工具、动作上，没有一家把「这道题属于哪一峰」做成可导出字段。

## 四、技术挑战：第五十六个市场空白

五项空白：**题型标注覆盖率**、**分派命中率**、**能力包络版本钉版率**、**分类错误检出率**、**逐题型授权可导出率**；`triage.*`／`capability.*` 为**第 25 次无人提字段族**。

**本期反转（修正 89～101 期判词）**：往期反复判「中国侧流程最细、美国侧方法论最硬」。本期最靠近正确答案的三份材料全不是能力宣传稿——阿里组织稿把三档按题目性质写出并给出题库增长曲线，火山官方文档把两种相反默认值逐格列出，搜狐畅游把可回退性写进职责分界；**但三者都在用动作属性做代理**。PagerDuty 最接近（逐事故累积信任），却把粒度挂在团队授权，置信度只是建议附件不是门禁；学术侧给出分峰数据，却全在统一发卷的基准里测。三方互不相认。

细化挑战：**分类在分派之前，而分类依据往往只有动手后才有**（101 期在分派层复现）；平均分掩盖多峰，Tier 1 的近 100% 与复杂 RCA 的 16–53% 共用一个「准确率」（98 期「没有误差棒的 SLO」复现）；能力包络是历史函数，模型换版、工具描述变更后昨天测的锯齿今天不成立（85／92 复现），而 **Tier 1 全自动之后 Tier 3 样本越来越少，包络无法收敛**——这不是人没练（21 期），是题库没长；「按低风险授权」会把最难的题误判成最简单的题；置信度由被测者自己给出，不是独立见证（96 复现）。

## 五、展望与建议

1. **`triage.*` 九字段进 OTel GenAI 提案**：`task_class`／`class_basis`／`class_confidence`／`classifier_version`／`envelope_version`／`known_pattern_id`／`novelty_flag`／`assigned_actor`／`reclass_count`，默认 `TASK_CLASS_UNVERIFIED`，未分类不得进自主通道；重分类作为独立事件写进 trace 与 CAB。
2. **分派与审批解耦成两张单**：题型判定管「谁上」，动作审批管「能不能做」；`always_allow` 不跨题型继承，未显式配置统一回落 `always_ask`；把火山官方「始终显式配置」与阿里「审批默认关闭」从建议提为采购硬约束。
3. **按题型维护能力包络**：分峰 SLO 取代单一准确率，发布 `re-envelope diff`（98 期 re-grade diff 的能力侧镜像），钉版模型／harness／工具清单／评测集版本；给 Tier 3 类题设保底采样配额，防止题库随自动化萎缩。
4. **分类错误检出**：修复前强制「是不是攻击／容量／配置变更」四选一检查点，用带外独立证据核验（96 期 witness）；把 22 图片案例、非局部因果、无堆栈跨文件多块做成六类混沌注入题，验收以能否导出 `reclass_count` 为准。
5. **逐题型累积授权**：把 PagerDuty「incident by incident」的信任从团队配置改为按 `known_pattern_id` 逐条放开，可导出、可撤销、可回放，撤销后剩余权限清单按 95 收容面对账。
6. **标准与采购**：信通院六维、《SRE AGENT 能力要求》与 11-04 企业级评估四项书面记录补「题型标注覆盖率」「分派命中率」两格；采购三问——按什么字段判题型？分类错了怎么发现？能力包络用的哪一版？下周 KubeCon NA 2026（11-09 开幕，首设 Agentics Day）是提案窗口。
