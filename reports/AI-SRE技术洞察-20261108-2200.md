# AI-SRE 技术洞察（第 111 期）

**生成时间**：2026-11-08 22:00（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：地基面／前提继承面（Assumption Inheritance / Compounding Error in Chains）——每一步都通过，整条链却塌了；单请求 95% 的智能体，把 20 个请求串成一条链只剩 51%

---

## 题眼

前 110 期我们补制度（回归集、SOP、评分器、拓扑图、委托单、规则位阶、护栏清单），又查制度之间、之前、之后；但**验收单位始终是一次动作、一次事故**。本期换成「一条链」，所有制度立刻显出同一处断点：都装在点上，链上没有接线。

11-01 arXiv 2611.02207（BOBA-Bench，Amazon，280 链×20 请求、140 仓库、10 智能体、每链跑 8 次）给出最硬的数字：单请求完成率 95%，串成链只剩 51%。**不是代码变差**——验过的 Agent 代码作地基与人类代码相差仅 −3.6～+0.8 点；病因是「自己的测试通过就宣布完成」，一次静默漏检让下一请求失败率抬 18 点，仅 14～33% 的失败测试后来被修好。同期 HORIZON 基准把复利写成算术：95% 单步×10 步约 60%，×20 步约 36%，即使优化到 99% 单步，20 步仍失败近 18%。**51% 高于 36% 的独立下界，说明回归测试在兜底；但 95% 口径对链条毫无预测力。**

## 一、发展趋势

**趋势一：行业按单步签约，生产按链条交付。** PagerDuty 11-03 称「每一次已解决事故都成为共享记忆」，Honeycomb 同日把「从每次调查建立共享记忆」写成卖点；Google 11-06 宣布 Agent Substrate 1.0 在 GKE 可用，空闲 Agent 快照 500 毫秒内恢复到任意 Worker。三家同时把「上一步产物跨时间移交给下一步」做成一等能力，却没有一家给它标注「验过没有」。

**趋势二：纠错被移到离线，自我核对被当作冗余优化掉。** 11-05 火山方舟 Seed-Evolving 官方版本记录写着「模型可自主拆解目标、持续推进并判断完成标准」，并把「冗余的自我核对减少」列为效率改进。11-06 Anthropic《The components of agent memory》把纠错交给两会话之间的「做梦」（dreaming）离线回看日志；11-05 MEMOIR 明写记忆「使用后从不修订」。**链上唯一还在跑的检查，正被同时交给模型自己、并被当作成本删减。**

**趋势三：学术侧已从「能力不足」转向「继承污染」。** 11-05 arXiv 2611.07554《The Memory Trap》发现低风险任务里「跳过确认」的记忆，会让同一模型在高风险任务里连验证一起跳过；合法清理陈旧测试的记忆会让它削弱正确测试，且**越强模型增幅越大**，作者要求「保存记忆的作用范围」。11-03 arXiv 2611.05650 更直指该标签是「读完成轨迹贴标签，从不中间态续跑」。

## 二、技术现状：三处最完整的验证能力，都不在链上

**学术侧给出因果与量级，只给机制不给字段。** BOBA 的自我复核准确率 53%，宽松评审接受 77～95% 的错误实现、严格评审反拒绝 41～58% 的正确代码——**验证器自己也不独立**。一句外部「verification failed」加一轮修复把链完成率 51%→59%（+1.1～22.1 点），点名失败断言一次约抵三轮裸拒绝；但修复使回归率 +3.2～8.9 点、每链多 47～294 次调用。**验证是稀缺且有价的资源，不是能力副产品**（与 21/26 期算力额度不同，这里是验证额度）。

**模型厂商最诚实的一句写在研究稿而非产品页。** Anthropic 11-06 原话：「写下一条已验证事实，就是预测未来会话会不加复核地依赖它」；Sonnet 5 只在 grader 检查后标 confirmed，Opus 5 首次写下「规则＋如何知道它为真」。它同时承认顶层注入的错误笔记会进入每个会话、并行 Agent 写同一文件会相互覆盖。**这已是全行业最接近「给继承知识打验证态」的实现，却落在离线笔记，而非运行时第 k 步交给第 k+1 步的状态。**

**平台侧三格齐全却错位。** Honeycomb 每条发现可回链到 query/trace/deploy/ticket 并标注「confirmed 或 hypothesis」——最完整的一格，但打在调查产物上；PagerDuty「已解决事故→共享记忆」的地基是自我声明的结案（104 期判词在继承层复现）；Google 官方博客有 identity 与凭据注入，经核**无状态验证、无完整性校验、无 audit**，即快照可迁移而前提不可举证（105 期现场证书在继承层的空白）。

**中国工程侧粒度最细，仍停在离线与调查层。** 字节 11-03 Storage Agent Family Eval 保存评测集快照、评估器版本、评分配置、运行环境四项并对齐，安全红线一票否决，评分与沙箱相互独立——**条件钉得最细，钉的是版本对比不是链上每一步**。阿里云开发者社区 11-04 一篇工程稿给出最锋利的判词：「沿 Trace 从根 Span 找第一次偏离预期的不变量，而不是先看最后错误」，并主动声明 `task_id`、业务状态快照、断言结果、授权人是「本文建议的业务扩展，**不是规范字段**」。腾讯 11-03 CloudQ 全景图谱无一步记前提验过没有；OTel GenAI 到 11-02 仍全标 Development。

**本地 173／173-kb 连续第 32 期成组启用，全库唯一把继承写成一等对象的句子首次当主线。** 周昕毅 10「发现→分析→决策→执行→验证→**反馈（结果重新成为下一次判断的上下文）**」把「上一步结果→下一步输入」写进闭环，却写成「反馈」而非「带验证状态的前提移交」。配 casa 01「已验证的重复步骤才固化成命令」、何伟 02「确认的经验回流供复用」＝继承门、余锦泽 03「程序核对给出已验证／候选，业务人员确认或否决」＝全库唯一给继承知识打验证态、李峥峰 17「瓶颈转成理解、验证、敢合」、泠乐 18「AI 写完代码，谁来验证？写—验—修」。肖汉松 22「单次迭代结果不可信时，持续流转只会放大错误」比 11-01 量化更早（109 期取「无委托产物」、本期取「验证态」侧面）。判词：**本地把闭环末环叫「反馈」，联网侧 11 月才量化成 51%；两边都没给这一步挂「验过没有」的状态位。**

## 四、技术挑战

**一，「完成」是一次未经签发的状态提升。** 单步 `done` 把候选态提升为下一步可信地基，效率更高、告警更少、成功率不变。负事件家族唯一「每步都通过」的成员，也是唯一**下游失败被记成下游的错**：第 12 步报错归因第 12 步，病因在第 3 步。责任沿时间轴错配，而归因标签本身是事后读日志。

**二，验证器不独立，且验证有价。** 53% 自我复核、宽松放行 77～95% 错实现、严格误拒 41～58% 对代码，三道口径互不校准；外部一句信号换 +8 点，同时带来回归与几十到几百次额外调用。**「每步都验」不是免费午餐，须按风险配验证额度**，而额度无字段、无 SLI。

**三，快照与共享记忆把单点错误升级为可迁移资产。** 500 毫秒恢复到任意 Worker 意味着未验证前提跨机、跨百万沙箱复制；PagerDuty 与 Honeycomb 的共享记忆让一条错前提从一次事故扩散为组织默认；Memory Trap 证明低风险 scope 会外推到高风险任务。**适用范围不随内容一起走**，而 scope 无处可写。

**四，标准层连「该记什么」都还是建议。** 阿里云社区稿自认状态快照／断言结果／授权人是业务扩展非规范字段；OTel GenAI 仍 Development、内容默认不捕获。于是「首次偏离点」只能人工沿 Trace 找，无法进入告警、门禁与合同。

## 五、展望与建议

1. **`assumption.*` 九字段进 OTel GenAI 提案**：`assumption_id`／`produced_by_step`／`artifact_digest`／`verification_state`（VERIFIED｜UNVERIFIED｜HYPOTHESIS｜CONTRADICTED）／`verifier_kind`／`verifier_identity`／`verified_at`／`scope`／`supersedes`。独立于被测 Agent 写入，默认 `INHERITANCE_UNVERIFIED`，未验前提不得进下一步自主通道。
2. **链上继承门**：每步产出不可变 `handoff_state` 绑进 span，下一步校验 `verification_state` 与 `scope`；`UNVERIFIED` 时把自治度收缩到只读／可回滚，并把「前提验证覆盖率」升为主 SLI，单步成功率降为效率指标。
3. **首个偏离点归因器**：沿用 105 期重放证书，按 2611.05650 做 executed counterfactual——冻结同一中间态、只替换第 k 步产物续跑，报 `first_deviation_step` 与归因时延；禁用「读轨迹贴标签」充当根因，采购要求报反事实续跑成功率。
4. **外部验证信号最小实现**：一条 `VERIFICATION_FAILED`＋一轮修复＋点名失败断言；验证器与产出方异源并公布联合召回率，禁用同模型自审；按风险配额度，公开回归率增量与额外调用成本，避免把修复红利记成净收益。
5. **共享记忆与快照带 scope、寿命与复验**：写入即标适用范围、签发者、验证依据、TTL；顶层注入上下文禁载 `UNVERIFIED` 条目；恢复时复验 `artifact_digest` 与 `verification_state`，失败即降为 `HYPOTHESIS` 并触发人工复核。
6. **把复利纳入评测与采购**：混沌注入六类（第 3 步静默错、低风险记忆外推高风险、恢复后未复验、严格误拒正确修复、宽松放行错误修复、共享记忆跨实例广播），报「链完成率」「首偏离定位率」「继承 diff 可复现率」；信通院六维补两格，采购三问入合同，KubeCon NA 11-09 窗口提交。

**第 65 个市场空白（五项）**：前提验证态可导出率、链上首个偏离点可定位率、跨步独立验证信号覆盖率、继承状态 diff 跨版本可复现率、错误复利归因时延——无一内建；`assumption.*`／`inheritance.*` 为**第 34 次无人提字段族**。本地 173／173-kb 连续第 32 期成组启用，仍不可采购。
