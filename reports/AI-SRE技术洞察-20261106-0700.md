## 一、发展趋势：采样从成本技巧升级为账单变量，同时被证明在 Agent 上不成立

**定价线。** 9-24 至 10-23 的 25 天内，四家可观测大厂先后为智能体遥测单独定价，却选了四种互不兼容的计数单位：Datadog 全包 per-span（10-23 加 AI Guard $0.80/百万输入 token）、Splunk $100/月/120 万 span、Grafana $1.50/千 generation 加 $2/百万 token、Dynatrace $0.10/AI unit（每次 2–30 unit）。第三方按公开价目表测算同一份流量（20 万次/月、20 步、40 GB）：五家月账单 $49–$4,002，**差 81.7 倍**；同一份流量被计成 20 万 trace 至 460 万 unit 不等，计费数量差 23 倍。10% 采样可削去最大账单 92.1%、把价差压到 6.5 倍。结论刺眼：**采样率不是可靠性参数，是财务参数**——79 期"在编的定义权落在计价表"，本期推到证据层。

**有效性线。** Galileo《The Hidden Cost of Sampling in Agent Observability》（6 月，10 月被密集重引）比"1% 太少"尖锐得多：传统 APM 采样成立的前提是请求近似可互换；Agent 每条 trace 是由随机输出、动态工具选择、多轮上下文塑形的**唯一决策树**，同一问题这一轮走 `database_query → calculator`、下一轮走 `web_search → code_interpreter`，都对但结构不可通约。原文判词："采样一条有代表性的智能体 trace 属于**范畴错误**，因为这个总体没有代表性成员"。1% 采到的不是"1% 的画面"，是没有分母的分子。其调查：仅 15% 团队测试 90–100% 行为，自报"优秀可靠性"70.3% vs 32.4%。

**厂商开始自认边界。** Anthropic 10-14 Claude Platform OTel 导出公测（Messages API／Managed Agents／七语言 SDK），默认 metadata-only；官方写明投递是 at-least-once 与 **best effort**、span 可能丢失不可重发、`traceparent` 的 sampled flag 关闭则整个请求及子 span 都不发射，完整用量核算"请走 Usage API"——**模型厂商自己把 trace 定义为抽样视图而非账本**——本期最硬一手自认。Dynatrace 10-29 扩展 ingest 并对实验性 sensor 自认属性 best-effort、**schema 可无通知变更**。Grafana 10-20 Agent Obs GA、Google 10-30 元数据日志 GA（只记元数据、需显式开启）。国内侧阿里 AgentLoop 9-24 商业化、腾讯 11-02/03 CloudQ 升级、火山 11-03 AgentKit 新增超时，三家都把"观测是评测前提"写进文档，却没有一家公开**分母口径**。

## 二、技术现状：四种"抽"法，四个结构缺口

行业已收敛到"尾采样 + 低比例头部基线"（错误／超时／高成本／评估判负／差评／护栏触发 100% 保留，常规成功流量 1–10%），统一落在 OTel Collector 的 `tail_sampling`。这套共识至少裂成四层：

**其一，抽样框不是请求全集，是"能被谓词描述的异常"。** 一份 11-01 仿真的四行账：全量 200,000 条；1% 头部采样保留 1,957 条、错误捕获 1%；尾采样（错误+慢）保留 4,940 条、错误与慢 100%、**静默失败仅 1%**；叠加 10% 在线 judge 后静默失败也只捞回 8%，且 965 误报对 415 真报。3% 的运行输出错误答案而 HTTP 200，谓词结构性看不见。腾讯云开发者社区说得更直白："慢不等于有价值……真正该被看的是'结果不对'的那批，而它们往往又快又安静"。本期补上采集层解释（承 73、81 期）：**不是模型不想说，是保留谓词里没有这一格**。

**其二，分母与分子被同一次采样一起改掉。** 国内一份报文穿透复盘记录典型错法：采样放在"事件生成"阶段，只有 10% 的 trace_id 被选中并生成完整 JSON，其余 90% 连 trace_id 都不创建；看板延迟统计系统性偏低近 70%，且被抽中的"幸运儿"恰是路径最短最不复杂的请求——**选择性偏差与分母蒸发同时发生**。两条比率即现成 SLI：`上报 trace_id 总数 / 网关请求总数 ≈ 100%`、`完整属性事件数 / trace_id 总数 ≈ 预设采样率`。

**其三，评估样本与保留样本相互污染。** 尾采样刻意富集失败，再从保留集抽样算在线质量分，必然系统性高估失败率；用评分决定是否保留则构成循环论证。纪律三条：保留按规则、评估走**独立随机样本**、比率指标从 metrics 取。即 73 期"判决器与对象分离"的采集层版：**不能用被挑过的样本证明挑选规则**。

**其四，采样决策自己不进 span。** 81 期说 span 不记录未执行，82 期说不记录生效默认值，本期补：**也不记录"我为什么被留下／被丢掉"**。OTel GenAI 约定自 6-12 v1.42.0 拆库后仍全 Development、schema URL 仍 TODO，10 月连改四次属性，无 `sampling.*` 字段族。腾讯云 AgentObs 与火山 AgentKit 官方文档同样没有"采样率／丢弃原因／分母"三项。

**留存是第二次采样。** LangSmith 14 天延到 400 天账单涨约 4.5 倍，Datadog 基础留存仅 15 天；空间维丢一批、时间维再丢一批，都不产生变更事件。留存到期是**没有主体的默认**（与 66 删除面划界）。

## 四、技术挑战：本地工程实践派在消灭采样率，联网侧还在争论采样率

这推进了 80–82 期"最接近正确答案的反而是本地工程实践派"的判词——前两期给的是流程约定，本期给的是**架构层答案**。

刘杨《从 Trace 到规模化实时评估》写死六个字："**全量不采样**"——底座是"三大引擎内直接埋点、观测开销 ‰ 级、定位效率 10x+"。埋点下沉内核、采集边际成本趋零，采样即无存在理由。另两条路径："小模型/正则**全量粗筛**、大模型按需精判"（第一阶段过滤 99% 流量，但保留全量判定结果，只有 1% 升档），**把采样从丢弃器改造成路由器**；"固定 badcase 集重跑偏差约 10%，透出评估器标签 token 概率，低置信丢弃/复核，不用多跑几次投票"，**把随机性显式化而非靠多次采样去平均**。

余锦泽《Agent 的记忆不在对话里》在语义层给出同构定理："**截断后的样本不能代表完整取值集合，包含率可能被高估；表越大，样本覆盖比例越低**"。修法即本期处方：从"只取前 8000/20000 个去重值"改为"在库内对完整取值集合聚合""大表按时间窗、小表全量""未宽窗复查标记未复检"；另有"不降低阈值换取完整"——81 期"补全免费"的本体层版本。

其余六篇佐证：马云雷"概率性采样**放大**路径差异"（采样不止丢证据，还制造虚假差异）；陶炳哲标注"设置与**错误率分母待核实**"——七个字是本期题眼；孙鹏 BoRP 把"低成本高覆盖、全量监控"列为第一原则；肖汉松"评测全量基线"与"每条样本回测 3 次"区分总体与目标样本；李峥峰"用固定样本与缺陷真值衡量结果"；陈忻"低分样本自动回流评测集"提示**采样偏差会随回流自我固化**。对照 Galileo 用专用小模型评估器把 100% 覆盖做经济可行（Luna-2 自述 $0.02/百万 token），两条路线指向一处：让采样变得不必要——Galileo 把**评估**变便宜，本地把**采集**变免费，后者连"哪些请求值得评估"都不必回答。

由此列出**第三十七个市场空白**：`分母完整性`、`样本代表性偏差`、`丢弃原因分布`、`采样率变更审计`四项无一厂商内建。Anthropic 的 sampled flag 与 Usage API 分流只是否认，不是补齐。

## 五、展望与建议

1. **先立分母，再谈采样率。** 所有请求无条件生成 trace_id 并透传全链路；基础字段 100% 上报，高成本字段才按 10% 采。把两个比率做成看板一级指标，偏离即告警——本期唯一当天可落地的 SLI。
2. **评估与保留走两条管线。** 保留按规则、评估按独立随机样本、标注样本来源；比率类指标一律取自 metrics。用同一批数据既选样本又评质量，等于让被告当法官。
3. **给"没被抽中"留一格。** 根 span 记 `sampling.policy_id/rate_effective/decision/reason`，向 OTel GenAI 提 `sampling.*` 字段族（接 72 `agent.identity.*`、79 `billing_unit`、80 `attempt`、81 `abstain.*`、82 `config.effective.*`）；规范未定前用自有前缀加 `semconv_snapshot` 锁定版本。
4. **把静默失败写进演练与验收。** 新增"答案错但 200""工具选错但空结果无报错"两类题型；验收四问追加第五问：**这次结论建立在几个样本、怎么抽的**。
5. **采购三句硬话**：提供机器可读的分母计数与采样率变更历史；采样率调整视为变更事件须进 CAB；留存期与加购口径一次性书面披露。信通院六维宜补"抽样框与分母完整性"一维。
6. **优先投资采集层而非调参层。** 引擎内埋点、分层评估器、置信度显式化比在 Collector 里调 1% 还是 5% 更有复利；采样率每下调一档省下的钱，会以 RCA 时延在下一场事故里连本带息还回来。
