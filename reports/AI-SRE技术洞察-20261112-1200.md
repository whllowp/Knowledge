# AI-SRE 技术洞察（第 150 期）

**生成时间**：2026-11-12 12:00（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：模型生命周期 SLA 面／推理底座连续性（Model Lifecycle SLA）——SRE Agent 的「脑子」是第三方模型 API，可被退役、再定价、限流、区域限制、许可切断；operator 既没有「模型生命周期 SLA」，也无法 pin 到制品、无法保证换模型后根因结论不变

---

## 题眼

同一周，OpenAI 把 GPT-4o / GPT-4.1 的 `shutdown_date` 写进每个模型的 API 字段（2027-01-14 下线、GA 模型 6 个月通知、预览模型仅 2 周）；NeuBird 把一次模型替换拆出 **9 项行为变化**（工具调用、推理行为、上下文窗口、延迟、幻觉率、输出结构、修复安全性、提示行为、成本）并断言「改模型是一行，证明 Agent 还管用不是」；TianPan 给出硬数字——**2026 年初生产环境 60% 的 LLM 调用错误来自限流耗尽而非服务故障**；upqbot 记录 Anthropic 因定价变动临时封禁 OpenClaw 创建者的 Claude 访问。**全行业在卖「模型路由」「多模型网关」「SLA 监控」，却没人给 SRE Agent 的推理底座一个生命周期 SLA**——你的 Agent 的脑子，下周可能被厂商收走、涨价、限流、或区域禁运，而没人收到预警。这是负事件家族里唯一「指标在绿、Agent 在跑，可它的推理底座明年还在不在、价格变没变、被限流能不能降级、被下线前迁没迁移、换模型后根因结论变没变，全不知道」的成员。

## 一、发展趋势

**趋势一：模型选择从「选型」变成「运行时决策」。** NeuBird、upqbot、ajayk 三篇 2026 共识一致——模型像可变云依赖而非固定库：任一模型因变贵、被限流、被区域限制，一夜之间就从「对的」变成「错的」。路由（陶炳哲#30：路由的是「模型＋harness」执行方案）正在成为基础设施，而非功能点。

**趋势二：退役与再定价进入「可程序化监控」阶段，但仅 OpenAI 做到。** OpenAI 给每个模型加 `shutdown_date` 字段（GET /v1/models 可读），把「模型还在不在」变成可被告警的遥测；其余厂商仍以博客/邮件通知为主，无结构化字段。

**趋势三：故障主因从「模型错」转向「供给断」。** TianPan 的 60% 限流错误、ajayk 的「spend-cap 429 无 retry-after、会一直失败到下月」、重试栈叠加把供应商局部中断放大成自身限流中断——SRE Agent 的可用性，越来越取决于它能否在供给侧冲击下降级，而非模型本身多强。

**趋势四：换模型的「隐性回归」成为头号未管风险。** NeuBird 的 9 项变化里，「已知好修复被标为不安全」「下游解析器被打破」「某工具收到不同参数」都是换模型后悄悄变坏的，不跑回放根本发现不了。

## 二、技术现状：路由可买，连续性不可证

**退役可预见性**：仅 OpenAI 有结构化 `shutdown_date`（GA≥6 月、变体≥3 月、预览≥2 周）；预览模型 2 周通知对生产是致命窗口。Google/Anthropic/字节/阿里/腾讯均无非结构化或字段级披露。

**fallback / 降级**：ajayk 明确要求给 fallback 路径独立的「质量 SLI」——小模型能过 schema 却答得更差，静默吃掉大量流量也是问题；LiteLLM 类网关能做路由与预算，但「限流/下线时降级到「还能用的模型」」多数团队未配。

**版本 pin 到制品**：OpenAI 可 pin 到 dated snapshot（如 `gpt-4o-2024-08-06`），强于 alias；Anthropic alias 仍不稳（#128 已证）；云厂商 Agent 平台多只暴露「选模型」开关，不暴露 snapshot 级 pin。

**换模型可复现验证**：全行业零披露。没有任何 SRE 平台声明「换模型后同一历史故障的根因结论不变」，也无人把回放历史故障当成模型变更的必跑门禁（NeuBird 只说「重放过去事故才知道」，未产品化）。

## 四、技术挑战

1. **退役预警非结构化**：除 OpenAI 外，模型下线/再定价靠博客与邮件，无 `shutdown_date` 级字段，无法进告警。
2. **供给冲击无降级**：60% 错误来自限流（TianPan）、spend-cap 429 无 retry-after（ajayk），重试栈叠加放大中断；多数 Agent 无 fallback 路径与独立质量 SLI。
3. **pin 语义太弱**：alias≠制品（#128），预览模型 2 周可消失，fine-tune 跟随 base 退役——「选了模型」不等于「锁住了脑子」。
4. **换模型回归不可见**：NeuBird 9 项隐性变化里修复安全性/解析器/工具参数悄悄变坏，无回放门禁发现不了。
5. **生命周期 SLA 缺位**：从创建到下线（朱革#15：创建→配置→部署→运行→升级→监控→故障恢复→下线）的「模型层 SLA」无人定义——可用性 SLA 管服务，不管「脑子还在不在」。

## 五、展望与建议

- **把「模型生命周期 SLA」立为一等运维对象**：新增 `model_lifecycle.*`/`substrate.*` 字段族（深化 #128 的制品可验证）。
- **deprecation 字段化**：轮询各厂商 `shutdown_date`/版本清单，纳入告警（OpenAI 已可读，其余需自建爬虫/订阅）。
- **fallback 路径独立质量 SLI**：ajayk 法则——小模型过 schema 不等于答得对，ticket 级告警 fallback 占比，限流/529 触发降级而非重试风暴。
- **pin 到 snapshot 而非 alias**，并给预览模型设「禁用生产」策略（2 周通知不可接受）。
- **换模型回放门禁**：把历史故障做成可重放基准，模型变更前必跑，断言根因结论一致（NeuBird 的「重放才知道」产品化）。
- **第 101 个市场空白五项**：模型退役可预见率／跨模型 fallback 覆盖率／换模型根因一致性可验证率／再定价冲击可预警率／版本 pin 到制品率。
- 信通院六维补「推理底座连续性」格。
