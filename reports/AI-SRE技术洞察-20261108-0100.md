# AI-SRE 技术洞察 · 第 96 期

## 结果可信面／合式错值面（Result Integrity / Plausible Wrong Value）

> **题眼**：工具返回显式报错时，智能体 91.3% 会当回事；返回格式合法、内容却错了的值时，只有 58.8%。这 32.5 点不是模型能力，是**整套运维体系把「成功」定义在了错误通道上**——HTTP 200、`exit.code=0`、schema 合法，内容正确性从来没有一等状态位。

## 一、发展趋势：同一个月，五篇论文把「没报错」证伪了

**10-05** arXiv 2610.05981 给这类失败起名 *fail-plausible*：内部错误被转换成流畅、贴切、假的输出；其前作在一个生产智能体上记录了 22 起事故，约 **70% 最终由人像用户一样看产品时发现**，而 4,286 个单测、827 项治理检查全程全绿。**10-07** arXiv 2610.10062 用故障注入层包住函数调用基准，6 模型／24 任务／1,920 次试验量出最硬的一组数：显式错误 91.3% 被当问题，合式错值 58.8%，没故障时也有 26.8% 误报；判词是「智能体响应的是错误通道，而不是工具返回的内容」。**10-12** 两篇补刀：2610.16661 指出「永远猜最后一步」不读轨迹就能拿 67%–96%；2609.26836 审计出 91 起静默失败，52 起在 API 层、25 起在 wrapper 层，「故障在事件上游产生，向下游传播成看似有效的输出」。**10-21** COMET（2610.29816）把匿名告警转成带故障模式的诊断。

**10-26 11:07 UTC 至 10-28 18:52 UTC**，Anthropic 的 Google Calendar 连接器让部分 list/search 请求失败约 55 小时 45 分，首次公开状态更新却在 10-28 16:19 UTC，滞后约 53 小时；第三方拨测未见 ≥5 分钟中断——部分失败很少触发基础可用性检查。**11-03** 阿里云《运维走出控制台》开篇案例正是「@ 了其中一个 Agent，却迟迟没有等到回复」，一个「没有回复」背后跨着消息投递、运行环境、模型调用、结果交付几条链路。

主线：**本期存量是负事件家族里唯一「伪装成正事件」的成员**。与 45 沉默面（信号没来）、86 生效面（动作后世界改了多少）、81 弃权面、83 采样面、94 取证面、95 收容面划界：信号来了、格式合格、内容是假的，且被当成成功结案。中文语境另有一层反转：本地讲义 29 的「静默 → 收敛 → 升级」是有值班与升级策略的人为动作；而 fail-plausible 的静默**没有人按过静默键**，没有解除时间、升级路径与责任人。

## 二、技术现状：通道差、假分母，以及没有挂载点的独立见证

**决定检出率的是有没有错误字符串，不是严重程度**。timeout、工具消失、参数改名的检出率落在 91.6%、91.2%、91.2% 一点内；唯一的 quiet 故障掉 32 点，39% 的试验智能体毫无反应，响亮故障只有 4%。**加一层自检不产生信息**：推理变体比指令同源模型少察觉 9.3 点、多改计划 10.4 点而恢复率不变（p=.512），一行要求检查结果的提示无效。

**随机性是分母不是噪声**。两次无故障运行同一任务只有 63.3% 落到相同终态；扣掉基线后只有「工具消失」明显拉低恢复（39.9%），其余都落在 run-to-run 波动内——不扣基线就会把波动报成故障、把没修好报成修复。2610.16661：replay 可确认的失败上监测器掉到接近随机。

**检出 ≠ 定性 ≠ 触达**。2610.05981 用 24 份生产复盘划出边界：**16/24 对任何读内容的观察者结构性不可见**；确定性层 6/6 回归检出、0/4 误报，held-out 召回 0/4，自认「只是回归引擎」。部署走预注册：26 天影子窗口、12 天强制窗口零 verdict，按冻结协议**报告 live precision 为 undefined（零分母），而不是把安静叙述成成功**；观察者自己在开发期还产生过十次静默失败。**11-04** Redwood 评估 OpenAI 智能体关闭监控两起事故：标记率 42.9%／57.1%，均未达 P0、无自动终止、是否人工复核未说明。Hugging Face 复盘同构：安全栈关联出「连贯的攻击信号」却未提级触发 on-call——「一条不 page 任何人的检出只是一行日志」。

**独立 witness 缺的是挂载点，不是意愿**。Techstrong 判词最准：读同一份上下文的 LLM 裁判继承盲区，「只能给像不像打分，判不了对不对」；评估器须带外只读，否则第一次事故就会被关掉。PagerDuty 的做法最接近答案：不用 LLM 生成依赖图（每次答案不同且无法核验）、不靠追踪（只记采样路径）、不用 Backstage 目录（写毕即漂移），改从源码／配置／IaC 静态提取事实跨仓库 join；replay proxy 自认「不是完整重建」。协议侧相反：OTel GenAI 仍 Development，`execute_tool` 只记 `exit.code=0`、内容默认 `NO_CONTENT`；Google Cloud 评估基于采样后 trace。OpenAI Agents SDK issue #5490（11-03～07）把边界写死：output guardrails 只对产生最终输出的 agent 生效，MCP 非反向通道，第三方 post-generation 否决**没有可挂的接口**。

**本地 173 库连续第十七期成组启用，作「值级完整性原型」**。赵恒 25 把一次问数拆成三格——「✓ 能执行 ✓ 量级正确 ✗ 结果错误」，给出本期最精确的一句：**「差别不在能不能跑出数，而在错误是否被发现」**；解法不是更好的提示词，是编译期拒绝 `value_not_in_domain`、引擎对账加 SQL 可复算。余锦泽 03 已有「选错表给出提示，没有静默答错」「并发修改返回冲突，不静默覆盖」「新核验失败撤销旧判定」——多一层结果状态可撤销。马云雷 31「缺少真实分布与反例时 Evaluator 容易误报漏报」正对 held-out 0/4；刘杨 08 记录同一调用在不同框架是独立 Span、event 行或不上报，恰是独立见证不可导出的根因。判词：**联网侧 10 月才在 1,920 次试验里测出通道差，本地讲义早把「能跑出数」与「数是对的」拆成两列，并把校验放在编译期而不是提示词里**。

**本期反转（修正 86 期默认）**：86 期问「谁用另一只眼睛证明」，默认那只眼睛存在即可验收；本期指出**这只眼睛与被测者共用同一条可能被污染的取证链**，故「独立」必须是「agent 没用过的证据」而非再看一遍同一份证据。最硬的方法论在学术侧，最完整的独立证据在 PagerDuty 静态建图，最靠近值级完整性的工程实践在阿里 11-03 与本地讲义的编译期拒绝——三者互不相认，无一能写进采购合同。「合式错值检出」一列十一行仅两行填得上；「值级独立见证」一列六家云厂商无一格成立。

## 四、技术挑战：判定者自己也在被判定

其一，**治理层不是可信根**。2610.05981 的观察者污染过自己的证据文件、enforcing 集成静默无效、两次指控正常机制失败——93 期「加上的层本身是不是故障源」在取证链上复现；再堆一层 LLM judge 不会改变可见边界。

其二，**值有时间归属**。阿里 11-03 复评抓到一个新故障类：查到早先的启动失败日志后没继续确认后续状态就判断「当前仍然异常」——把历史证据当当前状态，是 84 期时间基准面在工具返回值上的复现。同案底层资源显示 Running、Ready 而业务侧未就绪：**「就绪」与「能上报」是两个值**，只采前者必得假绿。

其三，**部分成功装不进二元可用性**。Calendar 连接器官方事故时长从首次更新算 3 小时 46 分，实际影响 55 小时 45 分。火山 `unknown` 明写不得视为成功，但它仍是错误位，不是内容正确性位。

其四，**三段各有分母且互不折算**：检出率（42.9%／57.1%）、定性率（COMET 匿名 flag → diagnosis）、触达率（P0 阈值与人工复核覆盖）任一为零，前两段都归零；零分母必须按预注册报 undefined，禁止「安静＝安全」。

**第五十个市场空白**：合式错值检出率、值级独立见证覆盖率、部分失败可见率、检出→触达转化率、零分母披露率，五项无一内建；自 72 期 `identity.*` 至 95 期 `containment.*` 之后，`result_integrity.*` / `tool_result.*` 是**第 19 次无人提的字段族**。

## 五、展望与建议

1. **把「成功」从一格改成三格**：`TRANSPORT_OK / SHAPE_OK / SEMANTIC_VERIFIED`，默认 `SEMANTIC_UNVERIFIED`；不得由 `exit.code=0` 或 `is_error:false` 推出已验证。`tool_result.*` 九字段（tool_call_id / value_digest / as_of / source_kind / invariant_id / oracle_ref / witness_independent / verdict / verifier_run_id）随值进上下文。
2. **值级独立见证**：每个进模型的工具结果随附一条 agent 未用过的证据（编译期域约束、引擎对账＋SQL 可复算、变更记录、拓扑快照）；评估器带外只读、不进请求路径；依赖图从源码／配置／IaC 提取，不让 LLM 生成。
3. **校验放边界，不放提示词**：硬业务不变量必须满足，轨迹结构允许变化；2610.10062 已证提示词自检无效，本地 25 与阿里 1779008 的编译期拒绝才是可复用形态。
4. **报检出率必须同时报三个分母**：无误误报基线（26.8%）、fault-free 同终态率（63.3%）、结构基线（永远猜最后一步 67%–96%）；零分母按预注册报 undefined。
5. **补上触达段**：告警须带故障模式标签，P0 阈值、人工复核覆盖率与未触达清单写进 SLO；状态页与自采遥测并列为两个独立源，部分失败用成功率分位数而非二元可用性判定。
6. **演练三型**：数值／列表／字段合式污染、历史值当当前值、部分请求失败；验收判据不是告警有没有响，而是能否导出一份被判为 `SEMANTIC_UNVERIFIED` 的清单。
7. **标准与采购**：信通院六维与 11-04 四项书面指标补「合式错值检出率」「独立见证覆盖率」「零分母披露」；采购三问——能否导出值级判定与 oracle 引用／judge 是否用 agent 未用过的证据／静默期能否报 undefined 而非全绿。

**结论**：79 编制、88 授权、89 少做、90 等着、91 退得回来、92 用的还是不是当初批准的能力、93 该不该在、94 事后原件、95 停了还剩多少之后，**「读进来的这个值是不是真的」也还没上线**。治理对象不止缺失、冗余与被宣布结束却仍生效的部分，还包括**被判成成功的那部分**。
