# AI-SRE 技术洞察（第 203 期）

**生成时间**：2026-11-16 04:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：契约面／契约测试（Contract Testing）——工具契约、数据契约、输出契约各测各的；三家一起变，就没人测

---

## 题记

137 期说「工具契约会在版本 pin 下漂移」，142 期说「列名一改，答案悄悄错」，172 期说「预发与生产四项不一致」，191 期说「输出缺字段被默认值吞」。四件事指向同一个工程缺口：**Agent 至少有三类契约——工具入参（工具侧）、数据结构（数据侧）、输出 schema（Agent 侧）**；**每一侧都有自己的测试，但没有一套测试同时验三方在一起还成立**。于是「三家各自绿、合起来红」成为常态：**工具升级了、数据列改了、输出 schema 没跟**，单测全过，**联调才炸**。**契约测试不是「多写几个单测」，是让消费者（Agent）的期望成为提供方（工具/数据）的验收条件。** **单侧绿不等于集成绿。**

## 一、发展趋势

**趋势一：从「各测各的」转向「消费者驱动」。** Agent 声明期望；**提供方按期望验**。**消费者不声明，提供方就不知道要兼容什么。**

**趋势二：契约开始版本化。** 工具/数据/输出三版；**版本矩阵取代单点兼容**（172 期）。

**趋势三：契约进 CI 闸门。** 破坏性变更阻断合并；**不靠联调发现**（170 期）。

## 二、技术现状：三类契约，通常只测一类

**工具契约：入参 schema。** 有校验；**但工具行为变化测不到**（137 期）。

**数据契约：列/类型/空值。** 有 schema；**但语义变化测不到**（142 期）。

**输出契约：Agent 产出。** 有 schema；**但下游消费期望没进来**（191 期）。

**现状：单侧测试 + 联调兜底。** 单测绿；**联调才发现字段对不上**。

**三种破坏性，一种比一种难测。** 结构（字段没了）、语义（字段还在、意思变了）、行为（结构语义都没变、结果慢了/错了）；**契约测试通常只测结构**。

## 四、技术挑战

**一，Agent 是隐式消费者。** 它不写 import；**期望藏在 prompt 与代码里**。

**二，三方版本不同步。** 工具 v2、数据 v1、输出 v1；**组合爆炸**。

**三，行为变化测不到。** schema 没变、返回语义变了；**契约测试只看结构**（137 期）。

**四，测试数据难造。** 真实数据有 PII；**脱敏后又不像**（187 期）。

**五，契约测试成本高。** 三方都要跑；**CI 时间翻倍**。

**六，破坏性变更无标记。** 哪些算 breaking；**没有规则就只能人工判断**。

**七，契约与 SLO 脱节。** 契约过了，延迟/正确性没验；**结构对、体验坏**（131 期）。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `contract.*` 字段**：`consumer`、`provider`、`version`、`expectation`、`breaking`、`test_ref`。
- **R2 消费者声明**：Agent 声明对工具/数据/输出的期望；**进仓库**。
- **R3 三方契约测试**：工具/数据/输出同跑；**失败阻断**。
- **R4 版本矩阵**：三版组合；**只测支持的组合**（172 期）。
- **R5 破坏性标记**：breaking 规则；**变更单必填**（173 期）。
- **R6 指标**：契约覆盖率、破坏性拦截率、CI 时长、联调失败率。

### 5.2 用户旅程

- **平台工程师**：工具升级 → 契约测试 → 发现 Agent 期望不满足 → 阻断合并 → 记录版本。
- **数据工程师**：列改名 → 契约测试报警 → 加兼容视图。
- **SRE**：联调失败 → 查三方契约 → 定位是哪一侧没跟。
- **审计**：抽查一次变更 → 核对契约测试记录 → 确认三方成立。

### 5.3 实现方案（90 天）

- **0–30 天：声明。** 三方期望；盘点存量契约。
- **30–60 天：测试。** 三方同跑；版本矩阵；CI 闸门。
- **60–90 天：治理。** 破坏性规则；联调失败率；季度复核；SLO 纳入契约。

**第 142 个市场空白（五项）**：三方契约覆盖率、消费者声明率、破坏性拦截率、版本矩阵覆盖率、联调失败率——无一内建；`contract.*`／`pact.*` 为**第 111 次无人提字段族**。本地 173／173-kb 连续第 101 期成组启用：余锦泽 03「上下文装配、工具调用、结果校验」＝全库唯一把「结果校验」写成流水线环节的实践，本期首次当主线；配 137 期工具契约、142 期数据契约。判词：**本地把结果校验写进流水线，联网侧 2026 年才承认「契约会漂移」；两边都没把「三方契约同时成立」做成合并闸门。**
