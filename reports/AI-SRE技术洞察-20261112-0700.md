## 一、发展趋势

SRE 的观测坐标系正在从「系统健不健康」滑向「系统值不值」。过去十年可观测性回答的是延迟、错误、饱和度（RED/USE），2026 年 agentic 运维把第三个不可见的轴推到台前：**经济轴**。三条趋势合流：

1. **单位价格下行、总消耗爆炸**。OpenAI 称 GPT-4 到 GPT-5.4 每百万 token 价格降 97%，但 agent 不是一次调用，而是循环里几百次跨工具调用——价格下降被消耗放大淹没。Gainam 测算分层路由把 blended cost 从约 $18.40/百万 token 压到 $2.31，差 8 倍，可绝大多数团队仍把全部负载丢给旗舰模型。
2. **FinOps 重写给 token**。云的 FinOps 靠标签和月账单，token 治理要进入请求热路径。Google Cloud Next '26 推 FinOps Explainability agent 与项目级 Spend Caps；FinOps 与 Linux 基金会发起跨厂商 AI 计费标准，并酝酿 Tokenomics Foundation。治理从「事后报表」变成「网关处拦截」。
3. **成本成为安全同源问题**。一个在循环里烧 token 的 agent，和一个被 prompt injection 驱动的 agent，从外部看都是「异常、升级、无人值守」。Trustgate 据此把成本控制与安全检查放进同一控制面——能看见每次调用的平面，天然也该能拦住每次超额。

## 二、技术现状

六家把成本相关能力以不同成熟度摆上货架，但**没有一家把「单次 agent loop 硬预算 + runaway 熔断 + 调用级成本归因 + 成本-结果计价」做成本地原生闭环**：

- **OpenAI**：ChatGPT Enterprise 用量分析与支出控制（按 user/product/model 拆 credit，统一 Cost API）；理念层提出「每美元有效工作」「cost per accepted outcome」，但落地仍是 Admin Console 事后报表，无单次 loop 硬预算。
- **Anthropic**：Task Budgets（beta 2026-03-13）把 token 预算注入整个 agentic loop，模型收到倒计时、临近时优雅收尾——这是最接近「运行时预算」的设计，但属「建议性」自调节，非网关硬熔断；Enterprise 还有组织/个人预算（$150–250）与 75%/90% 阈值预警。
- **Google**：Vertex Agent Engine（Gemini Enterprise Agent Platform）OTel tracing 默认开启、带 Token 成本分析仪表盘与 CoT 回放；Next '26 加项目级 Spend Caps；UiPath connector 可把每次响应的 token/unit 归因做成本分析。但预算仍在项目/平台层，无请求级熔断。
- **字节跳动/火山**：AgentKit 2026-05 商用，**按秒计费**（CPU 0.000097375 元/vCPU/秒、内存、流量 0.8 元/GB、网关请求 0.025 元/千），隐性计费项（网关请求、工具检索、公网流量）可占账单 25%；有成本预警阈值，但无 loop 熔断、无 agent 级归因。
- **阿里巴巴**：AgentCore 把「运行时权限与预算」前置到执行环节，网关做凭证转换+访问控制+**调用额度控制**，临时探索分支用完即释放、稳定任务按需编队，TCO 降 70%；Agent Context 持久记忆省 67% token——是六家中唯一明确把预算写进执行热路径的。
- **腾讯**：CloudQ 五维巡检含「成本」，AI 可观测把 Token 消耗/工具调用/任务质量关联，慢回答可下钻到调用节点；FinOps 同口径穿透到业务-系统-架构-模块-产品；信通院六维「成本效益」给验收提供标尺。

**本地主线**：陶炳哲的「智能路由不只是选模型」点破一个被忽略的事实——agent 大部分步骤是简单任务，把难度路由到便宜模型、把旗舰模型留给真正难的推理，是投入产出比最高且最被低估的杠杆；这与联网侧 2026 的 routing+caching 省 50–80% 互为印证，但本地把它做成「Harness + 任务评测 + 成本」一体的工程，而非单点优化。

## 三、技术竞争力（六方案六维对比表）

| 方案 | 运行时预算（硬约束前置） | 循环熔断（runaway 检测） | 调用级成本归因（OTel/API） | 成本-结果计价 | 成本可观测/FinOps | 经济护栏落点 |
|---|---|---|---|---|---|---|
| OpenAI（ChatGPT Enterprise） | 角色额度上限+默认限额+个人 override；无单次 loop 硬预算 | 无原生 loop 熔断，仅月度/组织上限 | Cost API 按 user/product/model 归因 | 提理念，未做原生计价 | 用量分析仪表盘 | 事后账单/Admin Console |
| Anthropic（Claude） | Task Budgets（beta）注入 loop、模型自调节；组织/个人预算 | 优雅收尾（建议性），无硬熔断 | 按 token（thinking+tool+output）计 | 提 effort 控耗，未计价 | Enterprise 分析仪表盘 | 平台月/组织层，非热路径 |
| Google（Vertex/Gemini Enterprise） | 运行时/会话/内存分项计费；项目级 Spend Caps | 无原生 loop 熔断 | OTel 默认 span+Token 成本仪表盘 | 未做原生计价 | Agent 决策可视化+成本分析 | 项目级（平台） |
| 字节跳动/火山（AgentKit） | 按秒计费+最小实例常驻；成本预警 | 无 loop 熔断 | 网关请求/工具检索计费项，无 agent 级归因 | 仅落地成本对比 | 观测中心流量统计+预警 | 控制台预警（事后） |
| 阿里巴巴（AgentCore） | **运行时预算前置执行环节+调用额度控制**；TCO↓70% | 未明确 | 网关额度+全链路审计（谁/身份/工具/资源） | 未做原生计价 | 全链路 Trace+审计+成本归属 | **网关凭证转换+额度（热路径）** |

**本期反转**：把预算写进执行热路径的是阿里（网关额度+临时分支释放），把成本做成同口径 FinOps 穿透的是腾讯，把预算做成 loop 内模型自调节的是 Anthropic——但**六家「单次 loop 硬预算 / runaway 熔断 / 调用级 token 成本归因 / 成本-结果可计价」四列均弱或缺失**。判词：**「审批/护栏/可观测/评测/调用链/图谱/身份/路由/主权/语义/数据契约 可采购，举证这条 Agent 单次 loop 的硬预算、runaway 熔断、调用级成本归因与成本-结果比 不可采购」**。

## 四、技术挑战

1. **观测≠拦截**。绝大多数工具停在 dashboard：告诉你昨晚烧了 4 万，拦不住下一个。真正治理必须坐在 agent 与模型之间的请求路径上。
2. **循环是典型故障**。一个递归 loop 一小时就能抹掉一个月优化；阈值要盯「消耗速率」而非总量，按会话/工作流 tokens-per-minute 连续超阈才跳闸。
3. **成本归因缺位**。没有把每次 tool call、retrieval、sub-agent 绑定到具体 agent/request 的语义字段，钱就藏在推理账单里，财务看到月总数却无法归到产品决策。
4. **成本-结果脱节**。一个烧钱却零产出的 agent 仍是亏损；只看 cost-per-token 几乎无法判断工作是否值得做，必须迁移到 cost-per-accepted-outcome。
5. **预算的「建议性」陷阱**。Anthropic 的 Task Budget 靠模型自觉，prompt 里写「请省着点」不是限制；硬上限必须在代码或网关，不在提示词。
6. **隐性计费项黑洞**。火山案例显示流量/网关/检索可占 25%，最小实例常驻即便零请求也计费——按资源拆分预估才能避免超支 30%。

## 五、展望与建议

- **`cost.*` 五字段**（budget_class/loop_breaker/attribution_ref/cost_per_outcome/enforced_at）纳入 OTel GenAI 提案，把预算类、熔断、归因、结果计价、拦截落点做成一等语义。
- **网关处三件套**：每 agent/tenant 硬预算 + 速率型循环熔断（指纹去重，4 次/10 调用即断）+ 调用级归因埋点，先于任何自主化扩规模。
- **路由与缓存先行**：默认小模型、保留旗舰给难任务；prompt caching + 语义缓存常态开启，把 unit cost 压下来再谈护栏。
- **结果计价 KPI**：把 blended cost/百万 token 与 cache 命中率当成运营指标周审，用 cost-per-accepted-outcome 取代 raw token 计数。
- **信通院六维补「成本效益」格**：将预算前置率、循环熔断覆盖率、调用级归因率、成本-结果可计价率写入验收条款模板。
- **本地对齐**：陶炳哲的「按难度路由」应升级为 Harness 默认策略；袁彬航在线 RL 循环、刘杨 trace-to-eval 都应把 loop 成本计入评测——本地已有成本工程雏形，联网侧 2026 才量出「六家无原生闭环」，两边都还没把单次 loop 硬预算做成运行时字段。
