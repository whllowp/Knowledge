## 计分面／测量仪器面（Scoring Instrument / Graded Fraction）

> **题眼**：榜单上那 13 分不是能力差，是有一半 episode 根本没被打分；90.9% 能发现故障的模型，端到端只有 14.5% 能修好。行业把分数当结论，却从没把「该有多少分、实际打了多少分、谁打的、用哪版打的、打的是诊断还是恢复」做成一等运维对象。

## 一、发展趋势：一周之内，「分数」从结论降格为待验收的产出

**11-03** arXiv 2611.04399《Silent Instrument Errors Reorder Agent Leaderboards》（山东大学，单作者，12 页）只用两个公开榜单自己的存档、不重跑任何 agent，就拆出四类计分管道错误：某通用 agent 结束会话的方式不触发 grader，**约一半 episode 从未被评分、却被存为失败**，与专用 scaffold 的 13 分差距在按榜单自身规则补评后闭合；成本列把嵌套模型调用重复计数且跨行不均；归档轨迹把 grader 写的动作记成 agent 动作；**一次正确且已公告的修复重排了榜单，而一个误读四个文件的 mode check 让分数塌掉 59～82 点且不打印任何错误**。HAL 维护者五周内确认其中三项。作者给出四项廉价检查：报 graded fraction、从 root spans 聚合成本、标注每个记录动作的 provenance、钉 evaluator 版本并发布 re-grade diff。

**11-04** arXiv 2611.06099 SWEOps-Bench 从另一头拆：55 个可复现事故任务、16 个 Kubernetes operator 项目、6 组配置，故障态检出 **72.7%～90.9%**，端到端经验证恢复仅 **14.5%～52.7%**；更关键的是「报告的诊断与最终恢复仅部分重合」——**RCA 报错也能修好，症状清了也可能过不了 fix-specific 功能验证**。评价四维里 stage-wise accuracy 与 verified recovery 并列，行业只买前者。

**10-29** arXiv 2610.41025 ReplayRCA 把诊断从「与标注一致」改成**因果修复**（回退到该步之前、替换动作、同一 agent 续跑，减去配对 placebo）：62 例校准失败上 13 个前沿模型最优 +51.3 点，但 **78 组配对差异无一通过多重比较校正**，5 项无任何模型能修；强制在最后一步干预损失 17.1 点；87 次运行里最好的事后诊断者恰是最弱的实时监督者（−14.5 点，p=0.002），且作者自认排名分半信度仅 **0.47**、以 80% 功效分开相差 10 分的模型需约 84 例而只有 62 例。

同一周厂商侧也在拆自己：**11-03** Google Cloud 工程师发布 skill 评测五规则（配对 WITH/WITHOUT、干净沙箱、Pass@3、**超过三分之一任务在连续相同运行中得分不同**、verifier 容器后置挂载、评分维度正交、Δ=0 先确认 skill 是否被选中）；腾讯云一篇告警研判 Skill 实录**主动拒绝给出 MTTR 与效率倍数**，写明「故障样本为单次构造，样本量撑不起统计结论」。

**主线划界**：46 期基准面管尺子的健康度、62 期元观测面把评分器列为三道门中的一格，本期把那一格展开成整条计分链；73 计量面讲三把尺不可换算，本期讲**分数算错了对象**；85 在途面是执行侧策略换版，本期是**测量侧重评换版**；86 生效面管一个动作改了多少世界，87 候选面管报告只剩第一名，96 结果可信面管值本身。**本期是负事件家族里唯一「没被测量却被记为零」的成员**。

## 二、技术现状：分数有四个断点，没有一个在仪表盘上

**分母断点**。未评分 episode 被静默记为失败，是「没有信号」被翻译成「零分」；补评后 13 分差距消失且**零次 agent 重跑**，说明变动全在测量侧。**这也是负事件家族里唯一靠加采样补不回来的成员**：提高采样率只增加已评分样本，83 期「没被抽中的连没记录都没有」在此变成「记了，却记在错误通道上」。**补评免费**——不重跑 agent、不产生推理账单、不进变更流，于是人人可做、无人留痕，一次正确修复就能静默改榜。Anthropic 提出的三个可发布指标里，coverage 是「经过监控的动作占比」，仍非「被评分的 episode 占比」；官方同时自认存在 judge-model problem 与「无共同方法论」。信通院《云上 Agent 基准度量模型》六维（功能／安全／可靠／体验／性能效率／成本效益）与「数据可信、流程贯通、权限可控、过程可审计、结果可评价」五项要求，**没有一维问分母**，全部是结果属性；腾讯云四款产品首批通过认证。

**版本断点**。「重评保存轨迹本身就是一次新测量」——evaluator 换版与 85 期在途换版同构，只是发生在测量侧；一次正确修复即可重排榜单，而 mode check 静默塌 59～82 点仍给出一个看似合理的数字。规范侧同样不稳：**11-02** OTel GenAI agent spans 与 metrics 仍标 Development，`gen_ai.system` 已改名 `gen_ai.provider.name`、per-message 事件改为 message 属性，多数库默认继续发旧名，取新约定须显式 `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental`。连属性名都不是稳定契约，**跨期分数却默认可比**。

**对象断点**。诊断准确率与恢复率既非充分也非必要：诊断错却恢复、症状清却功能验证不过、事后最准却实时最差。ReplayRCA 用配对 placebo 扣掉「本来就会成功」，并证明「永远猜最后一步」的标注捷径（96 期 67–96%）在反事实重放下要付 17.1 点代价。产品侧口径仍集中在诊断：**10-29～11-03** 腾讯 CloudQ 以全景图谱做跨产品取证、AI 工作台把 Token／工具调用／任务质量关联并「通过复测与评估验证效果」；**11-03** 阿里 AgentCore 从「@ 了 Agent 没回复」起步做复评；**11-06** OpenAI GPT-6 Cyber 报 99.93% 不越权；**11-03** 火山 AgentKit 新增执行超时自动终止。没有一家把「端到端恢复率＋功能验证」列为对外指标。

**置信度断点**。78 组差异无一显著、分半信度 0.47、样本缺口约 22 例、Google 自述三分之一任务连续重跑得分不同——**榜单是一个没有误差棒的 SLO**。评测管道自身又不进变更流（93 期「加固是变更」在测量侧复现），grader 与被测者共用同一条取证链（96 期独立 witness 在计分层复现）。

**本地 173 库连续第十九期成组启用，作「验收留痕原型」**。孙鹏 11 发现生成式 Judge 评分随模型与「先理由后分数」等输出协议漂移，故**先显式化评分标准再「读取」而非「生成」**；陶炳哲 30 主张模型与 harness 联合评测、选型看**错误重叠而非单一排名**；陈忻 29 以跨引擎一致率 100%（548/548）证明口径可稳定复现；周昕毅 10 的三次现场检验把「能回答」与「能取证、执行、验证」分开；casa 01 把验收定义为「结论可复核，留验收记录」，何伟 02 要求验收同时覆盖本次改动、真实链路与存量影响，31 马云雷要求回归集随漂移更新。判词：**联网侧 11 月才把「分数需带分母」写成论文，本地讲义早把「验收要留可复核记录、排名不如错误重叠」写成流程**；仍是项目内约定，不可采购。

## 四、技术挑战：第五十二个市场空白

`grading.*`／`eval.*` 是**第 21 次无人提出的字段族**。五项空白：① graded fraction 采集点与未评分率越界告警；② evaluator 版本钉版与公开 re-grade diff，重评当一次正式测量留痕；③ 动作 provenance 标注与 root span 成本聚合；④ 诊断／恢复双轨计分，恢复侧强制 fix-specific 功能验证与配对 placebo；⑤ 排名必须带置信区间与功效门槛。更深一层：评测管道是变更却不进变更流；grader 与被测者共用取证链，**独立见证在计分层缺席**；「样本量不够所以不给数字」在工程上正确、在招投标里等于零分。

**边界说明**：11-03 论文为单作者预印本、仅审两个榜单，11-04 与 10-29 为基准与仿真，数字仅取机制不外推；0.47、84 例、三分之一重跑差异为作者或厂商自述；GPT-6 Cyber 99.93% 与六维认证为厂商自述／供稿，待独立复现；OTel GenAI 仍 Development；本地 173 为讲义转写稿，6 篇图片型 PDF 仅据标题；未采信 SEO 农场数字。

## 五、展望与建议

短期把 graded fraction 做成一等 SLI：未评分 episode 单独成类、绝不折叠为失败；成本一律从 root span 聚合；每个归档动作打 `actor=agent|grader|harness`；任何 evaluator 升级发布 re-grade diff 并冻结旧版分数。中期把诊断与恢复拆成两条 SLO，恢复侧用反事实重放＋配对 placebo＋fix-specific 功能验证；排名强制附置信区间与功效门槛，样本不足即标 `INSUFFICIENT_POWER` 而非给名次；评测管道进 CAB、verifier 容器后置挂载、评分维度正交防作弊。长期推动信通院六维「结果可评价」补格：`grading.*` 九字段（episode_total／graded／ungraded_reason／evaluator_version／grader_id／cost_span_root／action_provenance／diagnosis_score／verified_recovery）进 OTel genai 提案，并把「该有多少分、实际打了多少分、谁打的、哪版打的、打的是哪件事」写进采购合同。混沌注入目录新增六项：grader 不触发、evaluator 悄悄换版、成本重复计数、归档动作错属、样本不足却出排名、RCA 错却恢复。

**下期候选**：`grading.*` 九字段取值表与 OTel 提案草案／graded fraction 采集器与补评重放器最小实现／evaluator 版本对账与 re-grade diff 发布格式／诊断·恢复双轨计分器（含配对 placebo）／榜单置信区间与功效门槛门禁／六维「结果可评价」补格条款模板。
