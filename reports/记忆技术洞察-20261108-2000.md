# AgentMemory 技术洞察（2026-11-08 20:00）· 第 37 期

> **本期主线：记忆的语言性——"一条记忆"的重量由词表决定。**
> 前 36 期讨论写入、删除、寻址、并发、时间、权限、成本、规模、睡眠、合规，全部默认一件事：记忆是单语言的、且"一条记忆有多少 token"是个稳定常数。今天拿掉这个默认值。同一段事实，换一个词表文件就从 0.70 变 1.44 token/字——**记忆的语义单位（条）与计费单位（token）之间没有固定汇率，汇率由分词器决定，而分词器是模型厂商的商业选择。**

---

## 一、发展趋势

**本地化从"翻提示词"进到"翻环境"。** Qwen 的 **BabelArena**（23 语言 / 15 种书写系统 / 702 任务 / 16,146 实例）把本地化做成"组件完备"：不只翻任务描述，还翻系统提示、模拟器、**工具描述、以及 Agent 运行时读到的数据库、政策文本与检索语料**；其 BabelFlow 流水线把"引用断裂"从 20.0% 压到 2.5%、行为错配 5.0% 压到 0.0%。关键设计：**评分相关的标识符（人名、账户等级、枚举值、外键后缀）在所有语言里故意保留英文**——记忆的"键"一旦被翻译，回放就对不上。

**记忆首次成为多语言榜的独立子项。** LILT 的 **AURORA** 把 Multilingual MultiChallenge 明确标注为测"上下文记忆、自我一致性、长上下文指令遵循"。结果比总分更有信息量：Command A+ 相对英文在韩语掉 18.2 分、波斯语掉 19.2 分；Gemini 3.8 Flash 在**每一个非英语语言**上第一，且单任务成本低于其他领先模型五倍；Opus 5.5 相对 Opus 5 的最大增益出现在中文与韩语，德语反而微退；其"中途换语言"倾向下降 80%。同一份榜单还否掉了一个常识：**每 token 最便宜的模型不等于每任务最便宜**——Meta 最新模型 token 单价低，但耗 token 与轮次多，单任务成本反超更贵的对手。

**记忆基准开始双语化。** NeurIPS 2026 的 **MedMemoryBench** 用 20 个纵向患者人设、约 2,020 轮问诊、1,986 条查询，把 14 种记忆方法（Mem0 / Letta / MemOS / A-MEM / MIRIX / Zep / HippoRAG-v2 等）放进同一框架，**数据中英双语，中文侧约 598MB**。**DuplexLedger** 用 1,094 个中英双语全双工会话、6,564 条同会话问答测"边听边说时哪句话该写进记忆"，按写入/更新/忽略/保留四类标注。**LongMemCode** 覆盖 16 语言、8,000 场景，**完全去掉 LLM judge**，改确定性打分。

**工程侧的信号更直接：CJK 分词从"缺省"变成"必选件"。** DSH 社区插件 **@tr1v3r/dsh-ltm（MIT，0.3.3）** 的存在理由写得很直白：同生态的 dsh-memory 用 SQLite FTS5 存扁平文本，**而 FTS5 默认分词器对中文不友好，整句常被当成一个 token，检索近乎失效**。它因此自建 CJK 感知分词、BM25 与字符 n-gram 混合重排、Jaccard 0.8 / 余弦 0.92 近重复检测、`revision` + CAS 更新、90 天未确认标 stale。

趋势判读：**记忆的国际化不是界面语言，而是分词、切分、归一化三件底层件的本地化**；前两项已被工程侧承认，第三项无人认领。

## 二、技术现状

### 2.1 计量层：token 不是单位，是汇率

2026-11-04 一份对 41 个词表文件的实测（维基中文 2,990 万码点）给出本期最硬的数：**同一个汉字、同一段文本，token 数从 0.70 到 1.44，差整整两倍**。差异不在引擎，在文件——OpenAI 自家两代编码，o200k 是 0.89、cl100k 是 1.31，相差 47%。繁体法规平行语料实测把方向也钉死了：繁中/英文 **0.66–1.53**；o200k 的英文只比繁中少 2%，cl100k 少 35%，而 DeepSeek 与 Qwen3.8 **英文反而比繁中多 24%–36%**。

于是"中文税"要改写：**它不是语言税，是词表税。** 混元宣称 1 token≈1.8 汉字，GPT-4 约 1 汉字；一万字中文文章在前者 5,500 token、后者约 1 万，同价目差近一倍。而 cl100k 上中文比英文贵 68%、o200k 只贵 11%——**换一代模型，这笔税自己缩了八成**，与用户做了什么无关。更隐蔽的是单向涨价：Claude Opus 4.7 换分词器时官方写明"同段文本可能多出 0–35% token"，单价未动，实测总耗为旧版 2–2.7 倍。**公告写能力升级，账单变化只在细则。**

### 2.2 切分层：无空格语言把检索打回整句

中文、日文没有词界，泰语、缅甸语没有空格，于是第一道工序（切）在英文里是免费的，在这里是全部成本。三层实证：

- **检索层塌陷**：FTS5 默认 `unicode61` 把一句中文当一个 token，BM25 直接失效——这是 dsh-memory 生态的**共因故障**（与第 2 期记录的 20 余个插件共用 sessionQuery 同一根因），dsh-ltm 是首个针对性修复。
- **去重层塌陷**：纯前端记忆实现 freeapp 记录了一个精确的失败——中文按标点/空格切词后，"她喜欢喝美式咖啡"与"用户喜欢美式咖啡"切成两个长整串，**交集恒为空，Jaccard 恒为 0，去重彻底失效**。解法是双轨切词：先按标点切整词，再对汉字连续段滑窗切 2-gram（上限 64 个），阈值按类别分档（0.72 / 0.78 / 0.80）。
- **归一化层塌陷**（最被忽略）：带 NFKC 归一化的词表会把全角逗号折成半角，**约 85% 的中文行被改写**；日文 Stockmark-2 的归一化改写 51.5% 的行。而**生僻字**的差距是断崖式的：字节级词表把 Unicode 扩展 B 区 4.2 万个字全部保住（约 4 token/字），BERT-Chinese 与 XLM-RoBERTa **几乎全部替换成 UNK**。

### 2.3 检索层：语码转换税

ACL 2026 的 **CSR-L** 基准（人工标注的自然混语查询）测了 BM25、多个双塔（e5 / Arctic-Embed / Qwen3-Embedding / all-MiniLM）、交叉编码器与 ColBERT v2 在"原查询"与"语码转换查询"上的差：**每一种方法都掉分，平均 −2.38 到 −12.36**。且复杂度不提供免疫——BM25 掉 6.56、ColBERT v2 掉 13.78（最差），原分最高的 Qwen3-Embedding-8B（69.88）也掉 3.86。跨到 11 任务的 CS-MTEB 最大降 27%，e5-large-v2 中文从 55.91 掉到 40.70。诊断是**语码转换查询在嵌入空间里离它的单语孪生很远**，词表扩展只补一部分；旁证是语言身份在隐层高度线性可分（PCA 第一主成分单维分类 96–100%），沿该方向投影可把码切换指数压 63–99%。**语言是嵌入空间里一个独立于语义的维度，这与第 9 期"作用域漂移"是同一个几何事实的语言版本。**

### 2.4 产品层：谁承认了这件事

六项目里只有腾讯两家留了痕：MemHub v1.0.6 界面与召回支持 11 语言，但 Hy-Memory 2.0.13 的宏均未按语种分层披露；TencentDB-Agent-Memory 的 L0–L3 与四资产结构没有 `lang` 字段，中文靠底层分词默认值。OpenViking（v0.5.3 / DSH 插件 0.5.33，11-08）以 `viking://` 路径与内容/索引分离承载多语言，无跨语言检索口径。ReMe 0.4.2.x 与 dsh-memory-evolve（665★，末次实质提交 10-29）均未处理。**唯一把 CJK 写进产品说明的，是一个社区插件。**

## 三、技术竞争力

对比维度换成本期关心的六项：是否 CJK 感知分词、是否声明跨语言检索、是否披露 token 计费口径（token/字换算）、归一化是否可逆（是否保留原文）、是否有 `lang` 字段、是否有双语评测证据。

|---|---|---|---|---|---|---|
| OpenViking | 内容/索引分离 | 无口径 | 按存储配额 | 原文随存（强） | 无 | 无 |

| ReMe | 未处理 | 无 | 未披露 | 文件轨可重建 | 无 | 无 |
| dsh-memory-evolve | 未处理 | 无 | 无 | 文件可读 | 分支级作用域 | 无 |
| **dsh-ltm 0.3.3** | **CJK 分词+n-gram 重排** | 无 | 字符上限/tokenizer.json | 原文存 SQLite | 间接（scope） | 无 |

三点判断。**其一，能力与商业化倒挂第二十八次**：唯一认真做 CJK 检索的是社区插件，唯一做跨语言对照的是基准方，两家头部商业产品在多语言上零披露。**其二，证据全在"任务成本"栏**：AURORA 的教训是 token 便宜≠任务便宜，而所有记忆产品仍按 token 或条数报价，**无一家按"每任务记忆成本"报价**。**其三，最易被误读的护城河**：国产分词器在中文上省 30%–45% token 是真实成本优势，但同时是**换模型的成本断点**——历史 token 统计不可跨模型比较。

## 四、技术挑战

**① 计量不通约。** token 不可跨语言相加，也不可跨分词器相加。后果是连锁的：预算上限（第 19 期 `maxMemories` 类参数）、缓存前缀命中（第 14 期字节稳定性）、成本 NPV（第 5 期）、利用率分母（第 30 期）全部建立在"token 可加"这个假设上。多语言部署时四本账同时失真。

**② 归一化即写入——第四个写入口。** 前 34 期认定记忆有两个写入口（在线/离线），第 36 期加了用途维度；本期发现第三个物理位置：**分词与归一化发生在存储之前，改写内容而不留记录**——NFKC 吃掉全角标点（85% 的中文行）、简繁转换吃掉字形（"蒐"→"搜"）、UNK 吃掉整个字。它比压缩（第 9 期）更彻底：**压缩还能回溯原文，归一化连原文形态都不保留**。于是与注销（第 2 期）、可携性（第 13 期）、回归（第 23 期）三处正面相撞——校验和永远对不上，去重键永远在漂，回归查不到根因。

**③ UNK 静默消失是空集的极端形态。** 第 7 期讲"四种没有塌缩成一个 `[]`"，本期补第五种：**从未被表示**。4.2 万个生僻字在人名词表里变成 `<unk>`，系统既不报错也不留缺口标记，检索时表现为"这条记忆不存在"。这比误召回更难查：无负样本。

**④ 语码转换税无产品解。** −2.4 到 −13.8 分的检索损失是结构性的（嵌入距离），词表扩展只补一部分；而真实用户（东南亚、粤港澳等）本就混语输入。产品侧的唯一可行解是**查询侧多语言改写**，但这正是第 20 期指出的"读侧零治理"位置，且与第 14 期的前缀稳定性直接冲突。

**⑤ 单语评测不可外推。** AURORA 已经证明排名会随语言翻转（同一模型韩语掉 18 分）。而 AML 二期（11-04 23:59 关评测、官方"11 月中旬"发榜，本期 20:00 仍未出）的文本轨仍以英文为主，多模态轨的 caption 声明制也不含语言变量。**这意味着中文市场的记忆能力至今没有一个可横向比较的公开分数**——MedMemoryBench 的中文侧是目前唯一的双语对照，且只覆盖医疗。

**⑥ 翻译即改写。** 跨语言共享记忆（第 12 期的必然延伸）必须翻译，而翻译比摘要更强：BabelArena 把标识符留英文即是承认——**"该不翻译的部分"必须显式标记，否则第 21 期的归约会把 key 一起归约掉**。

## 五、展望与建议

**三个字段应当尽快进 schema**：`lang`（内容语言，与查询语言分离）、`norm_form`（是否经 NFKC/简繁折叠，及原始字节的可取回地址）、`verbatim`（布尔，标记"此条禁止任何形式改写"——人名、枚举、外键、法条编号）。三者低成本高收益，且与第 28 期"留白即债务"同构：现在不写，将来要用血统（第 3 期）去补。

**分词器应进"单向门"清单。** 第 13 期已认定嵌入模型是单向门，本期补第二扇：**换分词器 = 换计量单位 = 历史账单与预算全部不可比**。采购条款应加：更换分词器须提前公告并给出语料内实测的 `tokens_per_char`。

**给采购方三个问题**（比看榜更有效）：① 你的记忆用哪个 tokenizer，中文 token/字多少，自测还是引用厂商文档？② 查询语言与记忆语言不同时召回率掉多少，有无实测？③ 归一化后原文还能取回吗，哪一版？

**给研发一条路线**：不要先在检索层解决语码转换，而要在**写入层做语言标注 + 原文保真**，读侧才有条件改写。顺序反了就是给第 20 期的黑箱再叠一层。

**下期最高优先仍是 AML 二期正式榜单**——若其文本轨开始按语种分层报告，本系列前 30 期关于"评测缺口"的判读需整体重估。
