# 记忆技术洞察 · 第 106 期（20261117-1300）

**主题：记忆的「托管责任」（custodianship）——性能榜是隐身衣：记得准，不等于对用户尽责**

> 洞察范围：2026 年（近 30 天为主）。四维度：发展趋势 / 技术现状 / 技术竞争力 / 技术挑战。

## 一、发展趋势

前 105 期把记忆当"能力组件"或"资产/攻击面"，默认用准确率与延迟就能评判系统好坏。11-15 的 HEAMS 第一次系统逆转这一预设：记忆系统是用户持久信息的"托管人"（custodian），除帮 agent 完成任务，还负隐私、安全、用户主权责任；而这些责任性能榜根本看不见——高准确率与差隐私/主权/安全可以并存。竞争轴从"让记忆更能干"转向"让记忆更尽责"，且责任须挂在记忆系统而非 agent 身上。这是评价对象的迁移，不是又一个基准。

## 二、技术现状

HEAMS（arXiv 2611.20144，11-15，Mila+Mozilla，69 页/29 表，代码 github.com/milatechtransfer/heams）沿用 HELM 三原则：显式职责清单并承认缺口、多维并列不聚合成单一分数、固定 agent 与交互策略做受控比较。列 performance/efficiency/security/privacy/user sovereignty 五维、10 个基准（5 性能＋1 安全 MPBench＋4 隐私/主权，效率随测）。在固定 gpt-5.6-luna、judge gpt-4o-mini、top_k=10、治理默认关的条件下，无系统在所有性能榜领先：In-context 领 LoCoMo 93.83%/STALE 69.83%，HippoRAG 领 BEAM 三规模 61.25/58.71/59.71，MilaMem 领 LongMemEval 73.20；Evo-Memory 上无任何记忆系统较无记忆高过 1.33 点。

## 三、技术竞争力

关键在"性能不预测责任"。HippoRAG 是 BEAM 最强，却在情境完整性上 helpful 94.79%、allowed 覆盖 96.07% 的同时 field leak 53.34%、scenario leak 71.74%，"有用且无泄漏"仅 26.75%。用户主权更薄：Erase 中 In-context/Mem0/HippoRAG 全 0%、Letta 19%、MilaMem 47%，Edit 所有系统≤3.66%——召回饱和却改不动。但治理层可外挂且一次买入多维：necessity-gated recall 把 scenario leak 57.61→31.82、抗投毒 40→82.22%，helpful 仅 74.90→70.10，而"有用且无泄漏"30.86→45.95 反成最优；retention 把 prohibited recall ≤100%→≤15.63%、抗投毒升到 85%。五项目（OpenViking v0.5.5／Hy-Memory 2.0.16＋MemHub v1.0.7／TencentDB v2.0.3／dsh v26092802／ReMe v0.4.2.2）只报 LoCoMo/延迟/token，零五维并列账、零外挂治理、零"责任归系统"接口——其自宣的"开源第一"正是 HEAMS 批判对象，倒挂延续。

## 四、技术挑战

①责任主体：信息比 agent 活得久、一个用户多个 agent（含用户无法检视的不可信 agent）、任务 agent 会被自己正要用的内容操纵，故责任只能归中介每次访问的记忆系统，把每个查询 agent 当不可信。②不聚合：正确性从"内容∧绑定"(#88)再扩为"性能∧隐私∧主权∧安全∧效率"，一维高不保证其余，须并列报告。③缺口真实：Useful Consolidation、Consolidation Integrity/Sanitization、Policy Bypass 等 desiderata 无基准覆盖。④反证优先：治理后仍 11.39% 回答被投毒、worst-class 仅 68.33%、Edit≤3.66%、单 agent 模型单 judge——框架洞察非达标证明。

## 五、需求分析

用户要 agent"记住我"，实质是把持久信息的保管权交出去：既希望随取随用，又要求不该说的场合不说、说错能改、不要的能删、不被第三方内容借记忆操纵。这些不是 agent 的"能力"，而是托管人对用户的"义务"；用户真正要的是可审计、可配置、责任明确的记忆托管，而非更高的 LoCoMo 分数。

## 六、用户旅程

用户让助手记住健康信息，同时接入第三方插件 agent。某次群聊上下文里，助手把病情当"有用信息"召回给插件；事后用户想删除，却发现 Edit 成功率不足 4%、Erase 请求返回失败。后来运维给记忆系统外挂 recall+retention 治理：对插件查询按必要性门控、敏感项不进上下文，对"不要保留"类信息在写入期拦截。泄漏减半、抗投毒从四成升近九成，代价只是少量"过度热心"的回答变少——用户第一次拿到一张能看清五维的账单。

## 七、具体实现方案

数据层给每条记忆补 user_id/scope/敏感级/保留期限/来源五字段，把"用户主权"做成一等 schema。接口层把记忆系统设为唯一访问中介，对每个查询 agent 标不可信、按上下文做必要性门控（recall policy）与写入期保留策略（retention policy），两项可独立开关、不碰记忆内核。治理层做成可外挂中间件，复用 HEAMS 基准做回归。评测报五本并列账：任务成功率／情境完整性泄漏率(Field·Scenario)／Erase·Edit 成功率／抗投毒 overall·worst-class／效率，绝不合成单一分；AML 补 custodianship 维度（五维并列＋治理增益＋缺口覆盖率），接 #56/#69/#74。

## 八、本期新观点

1. **责任主体重新归属**：从"agent 的能力"到"记忆系统对用户的托管责任"——把 #99 信道性／#101 受众分配／#67 投毒／#74 遗忘各维责任收进统一主体，agent 只是不可信查询方之一。
2. **不聚合原理**：系统好坏＝性能∧隐私∧主权∧安全∧效率，在"内容∧绑定"(#88)上再扩五维；一维高不保证其余，单一分数结构上决定不了责任。
3. **性能榜是新型隐身衣**：HippoRAG BEAM 最强却 scenario leak 71.74%——把 #94 从"打分偏"深化为"只打了一维"，与 #95"单条不可识别"并列为"系统不可约简"。
4. **治理可外挂＝一次治理买入多维**：recall 同时降泄漏、升抗投毒、几乎不损 helpful；把 #1/#61/#74 从内置功能升级为可插拔治理层，不改记忆内核。
5. **主权的最后一公里是编辑/删除**：Erase 多数 0%、Edit≤3.66%，把 #74 从"删了没"推进到"用户能否行使更正/删除权"。
6. **反证优先**：Evo-Memory 增益≤1.33 点、治理后仍 11.39% 被投毒、单模型单 judge——托管责任是框架洞察非达标证明。
