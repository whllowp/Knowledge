# AI-SRE 技术洞察（2026-11-04 02:00 期 · 总第 58 期）

## 本期主线：账面运维（成本归因面）——"谁为这次调用付钱"成为一等运维问题

前 57 期已把治理、判据、轨迹、身份、混沌等 48 个平面纳入运维视野，但"钱"始终只作为配额（第 33 期）、缓存折扣（第 27 期）与预算（第 25 期）的侧面出现。本期把账本本身当运维对象：钱花在哪、记到谁头上、异常怎么发现、账单与轨迹怎么对上。State of FinOps 2026 显示 98% 的受访组织已在管理 AI 支出（两年前仅 31%），FinOps 基金会 2026 框架为此新增"高管战略对齐"能力——成本治理从财务月度动作升级为与 SRE 同频的实时运维平面。

## 一、发展趋势

**趋势一：账单行开始"点名"。** FinOps 开放成本规范 FOCUS 1.5（2026-12-03 定案，11 月起进入知识产权审查）首次给 AI 计费统一标签：成本数据行可以记录模型及其开发商、区分输入/输出与缓存/未缓存 token，并**记下每笔费用背后的主体与凭证**（用户、服务账号或 API Key）。这与第 55 期身份面合流形成闭环：凭证面回答"谁在动手"，账面回答"谁在付钱"——当 FOCUS 1.5 落地，账单行与 OTel span 首次拥有同构的归因键。

**趋势二：价格事件日历化。** OpenAI 官方定价页确认 GPT-5.6 Sol 促销价（输入 $5→$4、输出 $30→$20）至少延续至 2026-11-21，OpenAI 帮助中心同步把该费率表扩至 ChatGPT Enterprise 点数制计价。促销到期日就是账单跳升日：单价不变预期下，输出 token 计费将上调 50%。价格政策已成为与供应商 EOL 公告（第 41 期）同级的日历事件，需进变更日历。

**趋势三：归因从"人"转向"任务"。** FinOps 基金会圆桌记录显示，按人分摊正在失真——资深工程师的大产出不该与新人配额同级，按使用量摊销反而扭曲图景；实践者转向按任务、按工具、按工作负载归集。98% 组织管 AI 支出背后，是"财务定总额与容忍度、工程把它翻译成可执行控制、FinOps 拥有翻译与证据"的三方分工。

## 二、技术现状

**归因三层栈已成型。** FinOps 基金会 token 经济工作组给出的路径：最小层是 API Key 治理（一键一团队一成本中心，具名 owner）；中间层是供应商原生归因——OpenAI 提供项目级密钥与 costs API，Anthropic 提供工作区密钥与按工作区汇报用量的 Admin API，AWS Bedrock 支持应用推理配置档把归因带进云账单；最上层是网关代理，为每次调用附加自有元数据并强制落库。国内侧，阿里云百炼支持按应用、模型、输入/缓存/输出类型及财务单元四维拆账；火山引擎提供按项目与 IAM API Key 的分账账单（AI MediaKit 文档明确专用 Key 不进分账，仅通用 IAM Key 可作分拆维度——归因粒度被凭证类型硬性约束）；百度千帆、腾讯混元支持密钥级消费统计，部分第三方聚合平台已提供密钥阈值硬拦截。

**模型调用只是账单的一半。** FinOps 基金会给出量化口径：生产 RAG 与智能体架构中，周边基础设施（向量库、嵌入、重排、编排运行时、缓存、跨区传输、可观测管道）通常占整个功能支出的 **40-60%**——这些不出现在模型供应商发票上，大部分也不经过网关。本地 173 库闪英迪（AgentENV）从训练侧互证：RL rollout 的执行环境侧开销约 35%（GPU 128 卡约 $640 加 CPU/内存）。由此得"两条账"结构：token 账（供应商发票/网关）与 harness 账（云与 SaaS 账单）必须靠共享工作负载 ID join，漏掉任何一条都会把优化引错方向。

**单位经济有了正确口径。** cost per successful outcome（每次成功产出成本）要求分子仍计入失败与被丢弃的 run——否则失败率越高、账面成本越"低"，形成统计假象。配套异常检测三层：单次执行硬上限（告警发出时钱已花掉，必须硬中断而非只告警）、小时/日趋势对比、按 Agent/任务类型分群的周期审视。

## 三、技术竞争力

| 方案/厂商 | 原生归因粒度 | AI 专用计费维度 | 实时管控 | 跨厂商聚合 |
|---|---|---|---|---|
| OpenAI | 项目级密钥 + costs API | 输入/输出/缓存分列、推理档位、促销定价日历 | 项目级配额 | 否 |
| Anthropic | 工作区密钥 + Admin API | 缓存读写分层计价（第 27 期） | 工作区限额 | 否 |
| AWS Bedrock | 应用推理配置档进云账单 | token 计量入 CUR | 云预算/异常检测 | 半（限 AWS 内） |
| FOCUS 1.5（标准层） | 成本行记主体+凭证 | 模型身份、缓存状态、供应商积分 | 无（仅数据层） | 是（12 月定案） |
| 阿里云百炼 | 应用空间/财务单元 | 应用/模型/输入缓存输出四维 | 按应用预警 | 生态内 |
| 火山引擎方舟 | 项目 + IAM API Key | 密钥粒度账单、缓存折扣 | 部分（专用 Key 不可分账） | 否 |
| 网关类（LiteLLM/Helicone 等） | 每调用自定义元数据 | 全（代理层补齐） | 严格模式拒无标签调用 | 是 |
| FinOps 平台（nOps/Vantage 类） | 账单归集+分摊 | AI 用量入总账 | 三档自主级（只读/审批/护栏内自治） | 是 |

判读：模型厂商管到"密钥与项目"为止，跨厂商归因与实时策略只有网关与 FinOps 平台两层能补；标准层（FOCUS 1.5）首次把"谁花的钱"写进开放规范，但 **provisioned throughput、reasoning tokens、上下文窗口大小三个 AI 维度明确不入 1.5**——推理 token 的归因粒度仍是标准空白。

## 四、技术挑战

**其一：成本公地。** 教学案例（skill.re，机构口径待核）描述的失败模式具有普遍性：一个服务五个业务部门的共享智能体月费 $40,000 挂在"AI 平台"成本中心九个月无人认领，扩容提案因 CFO 问"每个 BU 消耗多少"无人能答而流产，60 天内停服。无归因的共享智能体不是免费的，它是一张刷给平台团队 P&L 的信用卡。**其二：两条账缺 join key。** 供应商发票、网关日志、云账单三源各持一版"同一笔调用"，无统一工作负载 ID 时成本归因退化为手工对账。**其三：分摊模型的伦理扭曲。** 按人、按席位、按 token 三种分摊各有盲区，FinOps 圆桌给出的方向是按"已证明的生产力"分层配额，但度量本身依赖第 46 期基准面的健康度。**其四：价格条款与单价硬编码。** 业务测算中固化的"AI 单次成本"数字会在 11-21 这类到期日集体失效。

## 五、展望与建议

1. **建立单位成本 SLI 三指标**：每成功任务成本（分子含失败）、失败成本占比、归因覆盖率（有标签调用占全部调用比例）——无标签调用应默认拒绝而非兜底进"未归因"租户。
2. **账单即遥测**：FOCUS 1.5 定案后，把成本行与 OTel span 以任务 ID join，实现"每个故障附带它的账单、每笔账单可溯源到任务"（第 32 期轨迹面的财务镜像）。
3. **给价格政策设 owner**：促销到期日、计费维度变更进变更日历；State of Tokenomics 调研显示，AI 经济有具名 owner 的组织向 CFO 证明价值的概率高 3.7 倍。
4. **把 harness 账纳入评审**：向量库/沙箱/可观测开销占 40-60%，只优化 token 是在修理账单上看得见的那一半。
