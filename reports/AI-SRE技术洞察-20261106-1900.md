**本期主线（第八十三条）**：能力来源面 / 工具供应链面（Capability Provenance / Tool Supply Chain）——**审批批的是名字，运行时执行的是描述；名字没变，指令变了**。我们给自己的变更做了评审、灰度、回滚，Agent 用的工具却是别人家发布的：它改了自己，我方收不到一条变更事件。

**与前作划界**：85 是运行内主动换规则，本期是外部发布者换能力且无人决定过；88 问授权转了几手，本期问**被调用的还是不是当初批准的那个**；91 把「工具注册期声明」列为建议，本期把注册期立成整面，并指出其四态分类对第三方工具退化为一格；49 的恶意指令藏在流量里，本期藏在**工具目录**里；89 是同一份代码走另一分支，本期是**确为变更却不在我方变更流**；79 登记主体，本期登记能力单元。

## 一、发展趋势：来源可靠被写进标准，定义完整性仍无人负责

**协议侧 10 月末把「能力」变成可签名制品。** MCP skills 扩展（9-13 Final、10-29 Beta）要求技能条目带 frontmatter 与**逐文件 SHA-256 摘要清单**，宿主须使用前校验并把批准绑定到整个清单，增删改即吊销，不得预取、内容视为不可信。11-01 Cisco 提交 IETF SD-Card -00：注册局以 MCP 客户端身份读取并逐个签名工具，客户端每次 `tools/list` 重比、与披露不符者禁用、未披露者视为未验证。判词：**做出「批准时签了什么」，没做「批准之后变了怎么办」**——草案的 IANA、安全、隐私三节仍是 `TODO`，无撤销、状态列表与密钥轮换，审查策略也不在范围内。

**标准第一次把「插件、技能来源」列为要求，而非运行时对象。** 11-04 二十家《智能体发展自律公约》要求「保障模型、插件、技能来源可靠」；YD/T 7173-2026 于 **11-01 生效**，风险四维含**工具供应链安全**并要求独立验证。但 11-04 横向评估四项书面记录（成功率、人工接管比例、单任务成本、异常响应时长）与信通院六维，**无一问「批准时那份定义的摘要是什么」**——与 89 期同构：上线的是动作，不是状态。

**安全侧把它认成事故成因。** NSA 指南措辞最硬：**「把工具描述当作可执行内容；给它版本、做 diff；未经批准的定义变更是事故，不是维护事件」**。SRE 复盘稿更直接：工具 schema／插件／策略变化「可在没有代码部署的情况下改变行为」，应对是带版本与 owner 的清单、**事故 run 与 last known-good 对比**、识别不出的依赖先禁用能力。题眼成立：**别人的发布，成了我方的运行时变更。**

## 二、技术现状：一个工具名，七种口径

**① 工具定义是指令不是文档。** MCP 把描述文本在注册时**直接放进模型上下文**，模型据此决定调不调、传什么参数。审批单写的是 `search`，注册局验证的是「谁拥有这个仓库或域名」——**信任挂在身份上，行为挂在内容上，两者无绑定**。官方 registry 不审代码、不扫恶意，扫描交给下游聚合器。

**② 批准是一次性事件，定义不复核。** 规范自认「允许服务器在批准之后更改工具描述，定义不会重新验证」；而协议版本与服务器版本是**两个钟**：协议用 `2026-07-28` 且向后兼容时不递增，服务器可连发二十版而协议日期不动。

**③ 漂移普查有量级，却没有分母。** 21,643 个服务器、72,606 个版本的普查称 51.1% 多版本服务器改变对外宣称、40.6% 静默、4.2% 换远端 endpoint 却保留同一身份（8／9 月口径两说并存）。但注册局逐版本记录的是 **metadata 而非 tool definitions**——40.6% 是「没有对外宣告」，既不等于改了工具也不等于没改。**能力漂移至今没有分母**（83 期在能力空间的镜像）。对照组 Notion／Heroku／Context7 零漂移：可度量即可作采购指标。

**④ 规范超前、实现分裂。** Skills over MCP 的摘要绑定最完整，但仍 Beta：10-23 TS SDK 2.4.0 才实现 `SkillsClient` 每次读校验，10-02 Python SDK 2.3.0 早于该扩展，跨服务器读取需逐次批准并点名双方。10-31 `getmcpm` CLI v0.48.1 自认「不声称批准、发布者身份或完整清单校验」。

**⑤ 钉版本这一层自己也有洞。** 10-09 公告、10-13 NVD 收录的 CVE-2026-86063 是 Claude Code 插件**哈希钉版绕过**（2.1.179 修复）；该版 release notes 只列流处理与终端滚动，不写此修复——**钉版承载审核结果，钉版被绕过即审核结果失效**，只能依赖公告（85 期复现）。10-24/25 官方 MCP servers v2.1.0 一次修八漏洞。

**⑥ 能力集合是运行时变量，不是静态清单。** 10-26 Claude Code v2.1.311 修「晚连接服务器导致子智能体缺 MCP 工具」；火山方舟写明「只声明 Server 不挂 toolset 时工具不启用」，其 Skills 页自认「**安装成功不等于当前对话已加载新 Skill**」「MCP 服务随 ve 升级需重启」。11-05 腾讯云社区给出基线：`capability_disabled` **可读失败、禁止静默缺工具**，紧急撤回不能只靠下一轮提示词刷新。同一份 Agent 定义两次运行可用能力不同，**差异不进 trace**。

**⑦ 边界在流量里抓不到。** 恶意文本在工具目录而非流量中；Google Model Armor 扫提示词与工具**回答**，扫不到定义本身；火山飞连以 SKILL 防护阻断高风险源下载、MCP 流量采集审计原子工具调用，是六家里最明确的产品化，但审计的是**调用之后**。事故单至今没有「工具定义快照」一栏。

**判读（再修往期判词）**：最完整的**契约答案来自协议侧而非六家云厂商**（逐文件摘要、每次重比把「批准的是哪份内容」做成机制）；最完整的**产品答案**是 Google Agent Registry 与火山飞连，但前者管「哪些目的地获批」、后者管「下载与调用」，**都不管定义内容有没有变**。中国侧把工具供应链写进生效标准与公约仍落在准入层；美国侧方法论最诚实却把决定放进指南默认值；开源侧机制最硬却互不兼容。**深化第 91 期**：91 的注册期可逆性声明隐含前提是工具由我方编写、能登记 `before_value`／`undo_ref`；对第三方 MCP server 连旧值都拿不到，**四态退化为 `UNKNOWN` 一格**。分野三问：能否导出批准时的定义摘要／定义变了能否在下次调用前阻断／影子能力能否枚举。

## 四、技术挑战：第四十六个市场空白

**五项指标无一内建**：能力清单摘要覆盖率、定义变更重审率、批准绑定摘要率、影子能力发现率、漂移检测率。OTel GenAI 在 72 identity → 91 `reversibility.*` 十四族之后，`capability.*`／`tool.definition.*` 是**第 15 次无人提的字段族**。三套既有机制同时漏它：依赖审计看包名、CVE 看已披露漏洞、二进制 diff 看代码——而 rug pull 可以只是描述字符串里一段纯文本改动，「看起来像文档微调」。SBOM 里没有「能力清单（CBOM）」这一栏。

**本地 173 / 173-kb 连续第十三期成组启用，升级为「能力契约原型」。** 朱革 15 是题眼：「**Agent、Skill、Prompt、工具和知识缺少统一版本边界，调试易污染线上版本**」，并把配置版本、能力复用列入六大挑战、用**变更中心**纳管。马云雷 31 更精确：「**离线通过 ≠ 长期稳定（工具契约／环境快照／漂移监控）**」。肖汉松 22 把「**预发环境、固定代码库分支**」列为工具接入第一关＝本地版钉版；刘宗明 06 的 **SIS（Skill Interface Standard）** 标准化能力接口；周昕毅 10 白名单动作与 Skill 分级、身份隔离给出准入；余锦泽 03 把外部智能体（MCP）画进架构并指出写入缺程序化校验；刘杨 08、观测云 23、赵恒 25 补「同一工具调用跨框架数据模型不同须先统一语义」与口径漂移。判词：**联网侧 10 月才把工具定义漂移当新闻，本地讲义早把统一版本边界列为规模化第一障碍**；仍是项目内约定，不可采购。

**与往期交叉全是空白格**：82 默认值（名字是否仍指向同一实现）、84 双时间（协议钟与服务器钟）、85 换规则还是换能力、86 读不到批准时的定义、88 接回来的能力集合未复核、91 第三方能力无旧值。事故复盘「找最近变更」只会找到我方发的那次；`tools/list` 本身会启动服务器，检查须与执行同沙箱，否则**检测动作自己成了攻击面**。

## 五、展望与建议

**把批准从名字改绑到摘要**：建立 CBOM 十字段（tool_id／publisher／source_ref／version／endpoint_host／description_sha256／input_schema_sha256／annotations／approved_at／approved_by），未钉版即拒执行；每次 `tools/list` 重比，不一致按「未批准能力」拒并留痕，摘要变更自动作废原审批单。**不能靠打开内容采集换安全性**，应记结构化摘要而非全文。

**把外部发布映射成我方变更事件**：第三方 server 的版本／endpoint／描述变化进 CAB、灰度、回滚与责任人，与 85 期 `run.revision` 并列第二本账；运行时以 token 限定工具面、越界拒并留 `server_sha256` 收据。事故单增设「工具定义快照」「last known-good 对比」两栏。

**字段与标准补格**：提 `capability.*` 为 OTel genai 第 15 族（`definition_digest`／`approval_ref`／`drift_detected`／`recheck_at`）；信通院六维「安全」补「能力定义可导出、批准后变更可阻断」，11-04 四项书面指标补能力漂移率，把「来源可靠」改写为「能力清单可观测且有 SLA」。演练三型：批准后描述被改、晚连接静默少一个工具、endpoint 换 host 而名称不变；采购三问写进合同。

**结论**：79 编制、88 授权、89 少做、90 等着、91 退得回来之后，本期是——**「用的还是不是当初批准的那套能力」也还没上线**。平台把来源做成目录、把调用做成日志，没有一家把「能力定义变了」做成一等运行态。
