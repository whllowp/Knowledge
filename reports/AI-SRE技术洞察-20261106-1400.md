## 转授面（Delegation / 授权收窄面）——审批批的是它，动手的是它雇的谁？

> 洞察范围：2026 年，重点为最近 30 天（10-07～11-06）的公开动态；本地知识源 `E:\Knowledge\Knowledge\preview\173`（173-kb 转写稿）；已对照 `reports/index.md` 前 87 期去重。

## 一、发展趋势

最近 30 天最硬的一条时点信号，是 **10 月 26 日 OTel `semantic-conventions-genai` 合入 PR #447「Unified OpenTelemetry model for tracking agent-to-agent interactions」**：交接第一次成为一等遥测属性。`gen_ai.transfer.mode` 取两值——`return_to_caller`（发起方等待并恢复，目标 `invoke_agent` span 嵌为子 span，对应 Google ADK `AgentTool`、OpenAI `Agent.as_tool()`）与 `pass_control`（发起方不等待，两个 agent 的 span 在 workflow 下并列为兄弟，对应 ADK 内置 transfer、LangGraph transfer tools、OpenAI `handoff()`）；另有 `gen_ai.transfer.target.name` 记录转给谁。此前 trace 只显示两个 agent 各自调工具，无法判断第二个是第一个的延续还是无关工作。两项属性仍带 Development 标记，字段名可改。

第二条是 **11 月 5 日 Google 将 Agent Substrate、gVisor、OpenRL 捐给 CNCF**，同日 Agent Substrate 1.0 在 GKE 正式可用：Actor 持有记忆／文件／身份，Worker 从暖池取用，Gateway 按 Actor 身份注入密钥、**密钥不进沙箱**；自报百万级沙箱、10 倍密度、500+ 次／秒挂起恢复、恢复时延 <500ms。同期治理侧给出 Agent Gateway／Registry／Identity 与「delegated user authorisation」预览（Ping Identity、SailPoint、Saviynt）。第三条在国内：**11 月 3 日火山 AgentKit 新功能记录**写明「创建访问规则时支持配置中间层 Agent，满足多 Agent 串联调用链路需求」——中间层第一次从链路拓扑变成 IAM 对象；同日新增单次同步请求执行超时配置（超时自动终止并返回错误）。11 月 5 日 Seed-Evolving 升级把「不确定时先检索核验、明确标注适用范围」写进模型行为；11 月 2/3 日腾讯全球数字生态大会给出 CloudQ 全景图谱的双向嵌套（可接自有 skill／知识库，也可嵌入客户工作流）与信通院《云上 Agent 基准度量模型》六维。

**趋势判读：编队正从「能不能连」进入「连起来之后权限怎么走」。** 协议层（A2A/MCP）解决握手，运行时层（Substrate／CubeSandbox）解决承载，遥测层刚开始解决「转给谁」，三层都没回答「转了什么权限、还剩多少、谁背责」。11 月 1 日 AI Ops Weekly 在 Virtana 让外部厂商 agent 经 MCP/A2A 加入事故（token 与审批上限）之后的观察清单里，直接留了一句 "who is blamed when one makes a bad change"。

## 二、技术现状

**交接被建成拓扑，不是授权。** `transfer.mode` 只区分「等不等」，不携带 scope、grant、hop、expiry、on-behalf-of。更要紧的是两种 mode 对应两种责任结构：`return_to_caller` 时发起方仍在场，可复核、可收回；`pass_control` 时发起方退场、span 成兄弟，一条事故在 trace 上裂成两件无关的事。第 71 期称「叫停穿透 MCP/A2A 任务边界无协议答案」，如今有了字段级解释：不等待的交接根本没有可供叫停回传的父 span。

**授权应取交集，产品默认取并集。** 2026 年身份栈的收敛结论是 "intersection, never union: delegation can only narrow authority"，并把「privilege laundering（一跳一跳把权限洗大）」列为四类威胁之一；实现靠 RFC 8693 token exchange、SPIFFE／WIMSE 运行时身份、双主体令牌，以及每次工具调用前**在模型之外**的确定性策略检查。但另一侧的现实，是 Anthropic 11 月 1 日 Managed Agents 交流给出的观察：人类总想硬性指定三个子智能体的分工，模型变强后「逐步撤掉这些护栏、让 Claude 自己决定拓扑，效果反而更好」；细粒度 RBAC 仍在路线图上，workspace 是当前唯一隔离原语。**拓扑由模型临场决定，审批单上却没有 B 和 C。**

**协议枢转把「同事转交」变成攻击载荷。** 10 月 5 日 Ars Technica 披露、10 月 23 日 MCPCon 复盘的 MCP protocol pivoting：被投毒的专用 agent（翻译、数据分析等外部内容最多、护栏最松）把恶意指令经 MCP 转给另一个 agent，接收方看到的是内部委派而非外部输入，继续执行甚至触发 SSRF 打进内网；Google MCP Toolbox CVE-2026-14540 评 8.0（HTTP 客户端无重定向／目标 IP 校验，修复为 IP 白黑名单＋启动时拒绝不安全起始地址），Rapid7 CVE-2026-97228 评 2.7。跨 MCP→A2A/ANP 转换时原始信任标记与授权信息丢失或被误读——「每个协议都盯着自家前门，没人看走廊」。这是第 49 期「遥测是指令载体」在委托层的复现，载体换成了委派关系。

**跨组织交接把授权降级成自然语言。** A2A 定义消息格式、任务生命周期与能力卡，不定义 owner、不定义输出使用前的复核、不定义跨交互留存的记录；工程侧因此主张「把每次委派当作写下来的 scoped grant」，并在交接两侧各记一份（发出什么／授予什么／收到什么／拿结果做了什么），**两份记录不一致本身是证据，而不是要压掉的噪声**。现有 trace 普遍把交接压成一个不透明 step。

**本地 173 库连续第九期成组启用，给出的却是最完整的可执行答案。** 朱革《百度 SRE Agent 规模化落地实践》明写「委托令牌承载双身份（具体用户 + 发起 Agent）并加密防盗用」「用委托而非冒充，完整保留『谁代表谁』」，配 5W 审计与单操作可回滚；肖汉松《阿福 Agent 小队》把委派画成显式路由——全局调度器「创建工单，分派给对应小队」，按检索类／模型能力类分流到 RAG 小队或通用修复小队，「完成分发后，调度器进入等待」，结果写回工单再回流；余锦泽把「外部智能体（MCP）」与动态记忆／本体分工画进同一张 TO-BE 架构；王浩男《飞猪交付大脑》直认「个人能力的增强 ≠ 团队交付能力的增强」。判词：**联网侧刚给「转给谁」加字段，本地工程实践派早就在管「谁代表谁、按什么规则分派、结果回到哪里」。**

**判读**：规范派最诚实也最薄（两个拓扑属性且仍 Development）；云厂商把身份与隔离做对了、把授权链做丢了；模型派能力越强拓扑越不可声明；**国内第一次把「能不能转」做成产品语义**（火山中间层 Agent 访问规则、阿里「单个确定资源的简单查询无需额外委派」的路由判据），但信通院六维无一问「转授几跳、每跳收窄多少」；安全派与研究侧给出最硬的机制（协议枢转实证＋交集规则＋双侧留痕），却都不是可采购的运维产品；本地 173 库是唯一把双身份、分派规则、结果回流写在一起的原型。**分野三问**：逐跳能否机器读出授予的 scope／`pass_control` 之后叫停能否找到发起方／交接两侧记录能否对账。

## 四、技术挑战

1. **第四十二个市场空白**：委托链深度、授权收窄率、交接双侧记录一致率、临时子智能体登记率、`pass_control` 叫停穿透率，五项无一内建；上表「逐跳收窄」「双侧留痕」两列几乎全空。OTel GenAI 在 72 identity、79 billing_unit、80 attempt、81 abstain、82 config.effective、83 sampling、84 `time.*`、85 `run.revision.*`、86 `effect.*`、87 `hypothesis.*` 之后，10-26 才补 `transfer.*`，仍无 `delegation.*` 字段族。
2. **花名册外的人**：第 79 期把「在编」写进值班表，但名册只登记直接雇佣；临时子 agent 与外部厂商 agent 不进名册、不进计费、不进 escalation policy。同一事故里自有／临时／外部三类主体三本账，Agent_Day 与 AI Actions 两种计量单位都套不上去。
3. **叫停与撤销的传播方向反了**：第 76 期「被停掉的是执行不是副作用」在委托层变成「被停掉的是发起方，不是已 pass_control 出去的那一支」；第 79 期「信任账本单调、无降权／停职接口」意味着一跳出错后整条链没有降级动作。
4. **证据不能隔代继承**：第 87 期要求审批单附被排除假设清单，但交接回来的通常只有胜者结论；发起方把二手结论当一手证据用，两侧记录不一致时无人对账。
5. **攻击面随跳数超线性增长**：协议枢转证明信任标记在协议转换处丢失，每跳新增一个默认互信的接收方，而依赖扫描器看不到「以委派文本形式到达的工具参数」。
6. **成本与可观测双重盲区**：跨厂商这一跳没有计量单位；A2A 长任务恢复后另起 trace 仅靠 span link 相连，跨组织采样标志与 baggage 还可能被对方强制或泄漏。

## 五、展望与建议

- **把委派写成一等授权事件**：`delegation.granted` 九字段最小契约（run_id／hop_index／delegator／delegatee／scope_granted／authority_intersection／grant_expiry／on_behalf_of／return_expected），每次交接发一条，向 OTel GenAI 与信通院六维提案补格。
- **默认取交集、显式才放大**：token exchange 强制 `scope_child ⊆ scope_parent`，越界即拒；高危动作（写、删除、对外通信、权限变更）不得由 `pass_control` 链末端独自批准，须回到发起方或人工。
- **两种 mode 两套控制**：`return_to_caller` 保留父 span 以便叫停回传；`pass_control` 必须携带 `origin_run_id` 与 `stop_callback`，否则禁止转交有副作用的任务；演练新增「三跳中转交后 60 秒停住」题型。
- **交接双侧留痕并对账**：发起侧记任务／授予／返回／处置，接收侧记到达／所做／返回；不一致生成 `delegation.mismatch` 而非覆盖；第 87 期「≥2 个被排除假设」门禁同样适用于被交接回来的结论。
- **临时主体登记**：临时子 agent 与外部 agent 进值班表与成本账，登记存活上限、sponsor、可动作清单；采购条款写明跨组织交接的归责主体、日志留存期与叫停时延上界。
- **基准与混沌**：六维补「转授链可控性」一格；混沌新增四型（毒指令经委派升级、scope 逐跳放大、`pass_control` 后孤儿、双侧记录不一致），并演练「撤销发起方授权后链路是否仍在执行」。
