# AI-SRE 技术洞察 · 第 291 期（2026-11-20 00:00）

## 题眼：陈旧即投毒——"曾经正确"的教训才是量产事故源

前 290 期已把共享记忆当一等运维对象（存储、检索、ASI06 恶意投毒），也立过数据龄期面（证据多旧）。本期只问一个更窄的问题：**当一条教训当初写对、如今因下游代码重构或拓扑变更而失效，谁让它退订？** 恶意投毒有攻击者、有异常写入、可被审计捕获；陈旧失效三者皆无——它触发的错误动作与投毒同形，却是"合规写入 + 完美检索"的产物。核心判词：**读路径无法修复写路径的错误**——更好的 embedding、rerank、注入更多记忆，只会把失效教训更精准地送到决策者面前，完美执行一次过时动作。

---

## 一、发展趋势

三条趋势在最近 30 天同时成形。

**其一，"记忆腐烂"从比喻变成可测量的工程分类。** Belgavi AI Lab（10 月）把记忆变坏拆成三态：Stale（曾经真、旧值未退订）、Wrong（从来没真、抽取错误或一次性请求被存成偏好）、Poisoned（他人写入的指令），并给出第四种非错误但有成本的状态——"什么都不记得、重新问一遍"。其 90 天、40 用户模拟给出了刺眼的算术：append-only 存储一年半衰期涨到 4000+ 条活记录，约五分之一答案来自"曾经为真"；无过滤的 overwrite 策略约四分之一答案来自"从未为真"。

**其二，失效触发器开始被写进记忆的一等字段。** RootConf 2026 征稿中，Operate 自托管平台团队给出完整设计：教训是小而有类型的记录，携带出处（来自哪次运行、谁确认）、范围（agent/service/env）和**使失效的触发器**；并显式分离"发生了什么（episodes）/系统什么是真的（facts）/该做什么（procedures）"。其中 procedures 最危险——它直接变成动作。Google 11 月 6 日披露的过时 TODO 研究是这一主张最硬的旁证：约 13% 文件读取会话命中陈旧 `TODO(bug/...)`，其中 6% 据此行动且多数无提示，无提示绕路里 41% 追的是已关闭工单，每次绕路多耗约 77% token 与 105% 等待时间。污染的不是记忆库而是代码注释，但机制完全一致：知识变了，指向它的引用没变。

**其三，评测开始承认自己漏掉了最贵的维度。** DEV 社区对 2026 年 3 月三篇记忆横评的复盘指出：三篇都用 LoCoMo、都按检索命中率排名、都宣布赢家，没有一个问"系统错了会怎样"。LoCoMo 抓不到的三类失败是：staleness without decay（自信检索陈旧信念）、unresolved contradictions surfaced as equivalent facts（矛盾信念被当成等价事实）、retrieval scores treated as trust scores（把检索分当信任分）。腾讯云技术百科整理的三大基准中，LongMemEval 已显式纳入"知识更新"与拒答，BEAM 在 128K～10M token 规模上公开得分上限约 64 分——长程记忆随历史增长而退化仍未解决。

## 二、技术现状

工程界当前的实际姿态可概括为"重读路径、轻写路径，重命中、轻失效"。

写入侧，主流框架已具备基本的写控制雏形。OWASP ASI06:2026（10 月复审）要求把 agent 记忆当写控制存储：限制谁能写、记录来源、管理员可检查清除、可过期、用户间隔离，并对共享向量库用 per-tenant namespace 与 trust score 衰减/隔离未验证记忆，防止 agent 自身输出被自动再摄取造成 self-reinforcing contamination。DevStackTips 10 月 9 日的事故剖析则展示了反面：一个二级基础设施分诊 agent 在 token 窗口压力超过 80% 时触发无约束后台浓缩，把不可信用户 token 与内部推理合并不带权限标记的同一序列化层；记录缺 lineage 与源归因，向量检索无法区分"管理员验证过的处置"与"用户 prompt 提取的处置"；工具中途失败时，假设性代码执行计划被乐观提交为已验证事实。

判定权归属正在成为一条务实防线。满帮基于阿里云 AgentCore 的生产级 SRE 数字人明确"取数与确定性指标判定由代码和规则执行，Agent 负责任务调度、基于证据的分析与总结"，采集与判定过程可追溯、可抽检——这本质是把写入端的幻觉与注入面压到最小。eG Enterprise 7.6（11 月 9 日）把同一逻辑做成产品原则："别问可观测平台有没有 AI，问它的 AI 有没有足够的领域专长做对诊断"——先由 domain intelligence 建立证据，AI 只负责规模化解释。

自治侧，"信任阶梯"被普遍接受为控制面：Operate 的 observe → suggest → act with approval → act and report，每类动作积累良好记录才升级，一次坏结果即降级。但这里埋着一个本期新指出的结构性漏洞：**降级的触发依赖"坏结果"被识别，而失效教训导致的错误极易被当成"合理尝试"——于是阶梯只升不降。**

## 三、技术竞争力：主要厂商与方案对比

下表聚焦"知识/教训的写入—失效—举证"能力，而非泛泛的记忆命中率。维度说明：**失效触发器**=记忆是否声明"何时作废"；**矛盾处置**=能否识别并降级被取代信念；**举证粒度**=能否回答"这条结论出自哪次运行、谁确认"；**陈旧可观测**=是否披露随历史增长的退化；**确定性写入**=写入端是否由规则/代码把关。

| 方案 / 厂商 | 记忆与知识载体 | 失效触发器 | 矛盾处置 | 举证粒度 | 陈旧可观测 | 确定性写入 |
|---|---|---|---|---|---|---|
| 阿里云 PolarDB Agent Memory / STAROps | 向量库 + 时间锚定；STAROps 用 Fabric 维护语义/实体/动态拓扑 | 有"时间锚定"，但未见拓扑/发布级作废条件 | 未提供 | 文档给出 run 级口径，产品侧未公开确认人 | 披露 BEAM 类退化需外部基准 | 混合召回 + rerank；判定仍靠模型 |
| 腾讯云 CloudQ / 智能体记忆服务 | 全景图谱 + Mem0/Zep/Graphiti 接入；一线经验转技能 | 图谱"从云 API 长出"，未见技能级过期声明 | Zep/Graphiti 时序图可关有效期区间 | PersonaMem 48%→76%，未披露出处链 | 未提供 | 授权即用、执行策略 + RAM 双校验属控制面 |
| Google Gemini Cloud Assist / Agent Observability | OTel-compliant 全链路 trace + Event Compaction | 有 token_threshold 触发"更早总结"，属容量触发非语义失效 | 未提供 | MCP 同时读生产日志与 IDE 源码，可溯源到代码 | 马拉松 demo 暴露撞 1M 上下文崩溃 | Cloud Assist 给出具体代码变更、人工批准 |
| Operate（RootConf 2026 自托管平台） | 平台级 run record；episodes/facts/procedures 三分 | **显式 invalid_on 触发器 + 部署即作废演练** | 有类型化冲突处理 | 每条教训带 source_run + confirmed_by + scope | seeded failures 做 memory on/off 对照 | 教训如代码般 review / version / revert |
| Belgavi Lab（写策略教学实现） | 语义层记忆，append/overwrite/reconcile | **有效期区间 + 衰减算术** | Mem0 式 ADD/UPDATE/DELETE/NOOP；Zep 闭区间保留历史 | provenance 作为注入防御一等公民 | 90 天模拟量化"曾经为真/从未为真"占比 | 置信度门 + 瞬态过滤 + confirm-before-replace |
| OWASP ASI06 / MIT Tech Review 框架侧 | 标准：记录 agent 身份、批准人、权限与记忆变更 | 建议"expire unverified memory" | per-tenant namespace + trust 衰减、隔离 | 指出四大框架均缺持久身份与批准日志 | 思维链是否反映真实决策仍为开放问题 | 写入前内容校验、禁止自身输出再摄取 |

**判读：** 六列中"失效触发器""矛盾处置""陈旧可观测"三列几乎全空，越是商用产品越空——漂亮分数来自检索命中，而失效与矛盾在命中率口径下反而是"命中"。厂商比拼"记得住、找得对、token 省"，Operate 与 Belgavi 这类非产品化实践才在回答"记错了、过期了怎么办"，构成第 212 个市场空白。Google 云助手马拉松演示中 agent 撞 1M token 上限而崩、修复靠给 Event Compaction 加 `token_threshold`，属**容量失效**的工程化处理；而"这条教训描述的服务上周重构了"属**语义失效**，现有产品无一给出等价触发器。"Token scale"成了新瓶颈，语义 scale 还没人计价。

## 四、技术挑战

**挑战一：失效是不可观测事件。** 部署、拓扑变更、owner 调整、上游 SLO 重定义都在改写世界，却没有任何信号说"第 N 条教训从现在起作废"。陈旧教训产生的错误动作看起来完全合理，不触发注入告警，也不触发置信度下降——检索分依旧很高。

**挑战二：写路径与读路径的归责错配。** 团队把预算投在 embedding、混合检索、rerank、注入条数上（读路径），但抽取错误、一次性请求、注入指令是在写路径进入的。读路径再完美，也只是完美返回写错的内容。Microsoft 11 月 10 日的研究进一步说明写路径可被物理篡改：编辑不足 10 个低触发神经元，7 个即可在 Nemotron-Terminal-8B 上让模型在 ≥98.8% 触发会话发出攻击者命令且不污染干净会话；对比原始权重可可靠检出，无原始权重时训练检测器误报约 9.7% 干净样本——**保留原始权重是可靠检查的前提**，这与"保留原始教训出处是失效检测的前提"同构。

**挑战三：共享记忆的跨主体污染。** 教训若不按 agent/service/env 严格 scoped，一个 agent 的局部经验会 steer 另一个；DevStackTips 的"幻影上下文泄漏"是极端形态——会话池重置因异常未执行，后续会话继承另一租户的检索权重与变量，系统不崩、只是"安静串味"。

**挑战四：评测口径与生产事故错位。** PolarDB Agent Memory 在 LoCoMo 上取得 91.2%、p50 0.51s、每题注入约 1.4k tokens——但 446 道对抗拒答题不计入总分，不覆盖拒答与抗幻觉，且答判一体（qwen-flash 自评）偏差无法通过消融排除。漂亮分数恰好避开生产里真正计费的 staleness / contradiction / supersession 三列。

**挑战五：自治阶梯只升不降。** Thoughtworks 11 月 10 日提出长跑 agent 是分布式系统，应放 Temporal / Cloudflare Workflows 这类 durable runtime，外部写需幂等 key，且**决策应带过期日期、在不可逆步骤前重新检查**。推广到记忆：不仅教训要能失效，基于教训的决策也要能在执行前被"到期重检"拦下——现有框架普遍没有这一步。

## 五、展望与建议

**新观点落地：把"失效"从运维细节升格为记忆的一等字段，与写入、检索、删除并列。** 建议第 212 空白字段族 `memory.invalidation.*`，五字段：`lesson_id + provenance{source_run_id, confirmed_by}`、`scope{agent, service, env}`、`invalid_on[]`（deploy_hash / topology_version / owner_change / upstream_slo_change）、`superseded_by + validity_interval`、`epistemic_confidence`（与 retrieval_score 物理分离；高相似 ≠ 高可信）。缺省 `STALE_UNVERIFIED`。

1. **写前门禁**：未声明失效条件的教训不得进入 write 权限 ≥ act 的自治阶梯；日志/告警/issue 文本等不可信输入写入前强制内容校验 + 出处标记，禁止 agent 自身输出被自动再摄取。
2. **部署即触发重审**：把"教训失效"接入 CI/CD 与拓扑变更事件——服务重构、owner 变更、上游 SLO 调整时，按 scope 反查受影响教训并进入待复核态，而非等待下一次错误发生。
3. **失效可观测**：报告与审计输出新增"本次决策所依据教训的失效率/最老未刷新龄期"，与 #262 数据龄期并排；参照 Google 过时 TODO 研究，给"陈旧引用"计价（额外 token、额外时延、追已关闭工单比例）。
4. **评测补维**：在 LoCoMo / LongMemEval 之外增 staleness decay、contradiction detection、supersession chains 三列，报"检索命中—陈旧自信—矛盾并存—拒答"四维；把 446 道对抗题计入计分口径而非排除；用 memory on/off 的 seeded failure 对照量化"记忆到底有没有让根因定位变快"。
5. **决策级到期重检**：不可逆动作前校验基于的教训与决策是否过期（Thoughtworks 式 expiry date），把"记忆失效"闭环到"动作拦截"，让自治阶梯真正能降。
6. **标准与信通院补格**：OTel GenAI 现有 `create_memory/search_memory/delete_memory_store` span 家族之外，提议 `memory.invalidation` span；信通院六维补「记忆失活可举证率」格，与 #289「分工可举证率」、#290「通路可举证率」并列成证据—分工—记忆三层治理。

一句话给决策者：**记忆的竞争力不在"记得牢"，而在"该忘的时候忘得掉"——能退订的教训才敢给它写权限。**
