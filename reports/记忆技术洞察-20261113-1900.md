# 记忆技术洞察 · 第 85 期（20261113-1900）

## 本期主题：记忆的「程序进化搜索」（program-evolution memory design search / MAPE）——把"记忆系统怎么设计"本身变成可搜索的设计空间，用程序进化从最小种子自动发现整套记忆程序

> 承接 #1 写入闸门（规则）/ #71 自组织（agent 运行时自决）/ #77 处方性组织（人工预设 schema）/ #84 学习化控制（权重内化），但把视角拉到"谁/什么在搜索设计空间"——本期管"记忆行为是否可由搜索自动涌现，而非人设计、agent 自组织或策略内化"。

### 一、四维洞察

- **发展趋势**：记忆研究正从"人写架构/预设 schema"走向量化可搜索的设计空间——把"记忆系统怎样设计"本身当作 AutoML / 神经架构搜索（NAS）问题。MAPE 的发布意味着竞争焦点从"谁的架构手设得更好"迁移到"谁的设计空间更可搜、搜索目标更贴近生产"。这是继 #71 自组织、#84 policy-native 之后，对"谁决定记忆行为"的第三层回答：人设计 → agent 自组织 → 策略内化 → 搜索自动涌现。
- **技术现状**：arXiv 2611.17068（MAPE, 11-12）给出首个"记忆程序进化"框架：以标准化生命周期接口 + 诊断-提案迭代循环，从最小种子进化出整套记忆程序（读/写/合并/检索全套代码）。在 LoCoMo 与 LongMemEval 上较手工基线绝对精度 +12%、仅 35% 服务成本；设计可跨 backbone 与基准迁移。五项目（OpenViking v0.5.4.1 / Hy-Memory 2.0.16+MemHub v1.0.7 / TencentDB v2.0.3 / dsh v26092802 / ReMe v0.4.2.2）全为手工设计、零程序进化披露——倒挂延续（前沿在论文，产品缺席）。
- **技术竞争力**：两个被发现且可移植的模式直接冲击"抽取即压缩"正统：①保留原始对话作可检索证据（比纯抽取多留被丢弃的细节），重述 #19/#66 压缩风险——"压缩丢细节"不是必要代价而是设计选择；②按查询意图组合检索证据（而非倾倒检索项），重述 #73/#78 利用鸿沟。最关键：组合模块移植进五个现存系统全数提升，说明价值在"被发现的程序"而非"架构"，竞争轴变成"你的设计空间多可搜"。AML/C2 实时榜只排最终系统、对设计搜索方法论失明（接 #56/#69/#84）。
- **技术挑战**：①搜索成本与可复现性——进化整套程序需自有算力预算，规模化是否比人设计便宜仍待证；②目标错配——若搜索在 LoCoMo/LongMemEval 上优化"精度+成本"，是否过拟合这两基准（Hindsight 论文已示 schema 具领域依赖）；③可解释与可治理——进化出的程序比人写 schema 更难读懂，回滚/审计成新问题（接 #22/#60/#69）；④与 #84 policy-native、#71 自组织的边界：程序进化离线搜"程序"、policy-native 在线训"权重"、自组织运行时由 agent 驱动，三者是"谁来设计记忆行为"的三层互补，AML 缺对应分类维度；⑤原始对话保留重开规模与遗忘难题——保原始意味着遗忘请求必须同样命中原始层（接 #74/#83）。

### 二、需求分析

团队/研究者要的不是"再手调一套记忆架构"，而是"用尽量少的专家投入，搜出在该任务与预算下最优的记忆程序"。现有五项目都靠人设计整套 read/write/consolidate 流程，难以穷尽组合；产品方更缺"设计空间可搜索 + 搜索目标含成本"的方法论，导致要么追求精度压垮成本，要么省成本牺牲质量。

### 三、用户旅程

1. **定接口**：把记忆程序抽象为标准化生命周期（写入/检索/合并/裁决），定义最小种子程序与评价 harness。
2. **跑进化**：以诊断-提案迭代循环演化种群，目标函数绑定"精度 + 服务成本"，在 LoCoMo/LongMemEval 上筛优。
3. **取模式 / 移植**：把被发现的高价值子模块（如查询意图组合器）抽离，移植进现有系统验证可移植性。
4. **上线 / 控成本**：部署进化出的程序，按搜索揭示的"构建期→查询期"算力再分配压成本，保留原始证据层以保细节。

### 四、具体实现方案

- **程序即搜索空间**：把记忆系统从"固定的 SDK/管线"重构为"可变异的记忆程序"（读/写/合并/检索为可被进化操作的原语），对标 MAPE 生命周期接口。
- **双目标搜索**：目标函数同时含回答精度与服务成本，让搜索自行发现"少在写入期调 LLM、多在查询期做选择性处理"的权衡（深化 #72/#79/#83 成本轴）。
- **证据双轨**：默认保留原始对话为可检索证据（而非仅抽取摘要），以"细节保真"换"压缩省 token"，把 #19/#66 压缩风险转为可调旋钮。
- **查询意图组合器**：检索后按查询意图拼装证据子集再喂答，而非整袋倾倒，直接抬升 #73/#78 利用与分辨。
- **AML 契约扩容**：主张评测纳"设计可搜索性/搜索目标含成本"维度，否则 #56 缺口将继续漏掉搜索式方案（接 #84）。

### 五、本期权观点（新视角）

①记忆设计从"人写架构"升维为"在程序空间里搜"——MAPE 是记忆领域首个把整套记忆程序当作进化搜索对象的实证，等价于记忆的 NAS/AutoML；②搜索目标塑形算力分配这一发现最具生产价值：同时优化精度+成本会把算力从"写入期 LLM 构建"转移到"查询期选择性处理"而精度不降，揭示"构建贵↔查询期省"的可量化权衡；③两个被发现模式的可移植性（组合模块移植五系统全提升）说明——价值在"被发现的程序"而非架构，竞争轴应从"手设架构"转"设计空间可搜性"；④五项目全手工设计、零程序进化披露，倒挂延续；⑤与 #84 policy-native、#71 自组织构成"谁设计记忆行为"的三层互补，AML 应补"设计搜索方法论"分类维度（接 #56/#69/#84）。
