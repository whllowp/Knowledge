## 第 2 期（2026-11-06 04:00）· 记忆的负空间——当"忘掉"成为必须被证明的事

## 第 3 期（2026-11-06 05:00）· 记忆的可寻址性——巩固与可追溯的数学冲突

- 产物：`记忆技术洞察-20261106-0500.md`（正文 3,037 汉字；五章 + 8 方案六维对比表 + 25 条来源）
- 与第 1、2 期的关系：前两期分别讲"写得好"与"删得清"，但都默认了同一前提——**存在"一条记忆"这样可被指认的东西**。本期检验该前提，结论是它正在被行业自己拆掉，因此第 2 期"删除举证"与第 1 期"按条计费"共同的上游问题被定位到主键与血统。
- 主线：**巩固（N→1 压缩）与可寻址（1→1 持久标识）在架构上方向相反**。记忆质量的提升几乎全来自压缩（L0→L3 蒸馏、sleeptime 合并、图式归纳、Skill 编译、参数化），每压缩一次就断一条源边；断边之后授权、注销、举证、计费全部悬空。
- 新框架（第三批长期工具）：
  - **巩固税**：保留血统成本按边数计，巩固是多层 fan-in，边数随层数指数增长；只能选择在哪一层交，不能免除。
  - **可寻址性三级**：A 可枚举（能列出条目）/ B 可定位（能指回原文或事件）/ C 可归因（能证明"这条记忆导致那次行为"）。现状：多数 A，Zep 达 B，C 无人。
  - **三种主键与断裂模式**：路径键（改名即新对象）/ 序号键（同系统多套并存、跨层无映射）/ 内容键（编辑即变键，巩固产物不可复现）。
  - **记忆身份证四元组**（建议基线）：`(src_id, dst_id, field_path, event_ids)`，且 `field_path` 为字段级而非条目级——条目级血统会把无据主张一起洗白。
- 时点事实（30 天窗口，均已入台账）：Zep Agent Skills（arXiv:2611.01386，11-01）——Code 校验每个 claim 引用 Trace 事件、**删源 run 级联删除引用它的 Skill**、不可变版本、verified use 调排序；DeliverBench（arXiv:2611.03412，11-02）——7 系统最终交付最高 65.0/100，审计项目中"7 个都改对了、只有 1 个留下可追溯性"；CIB（arXiv:2611.02633）——接手"更弱模型作弊过"的状态，通过率 97%→81%；TRACE（arXiv:2611.03939，11-02）——出版商偏好记忆使该源进前三引用 +33~39pp，"不信任主流媒体"记忆使错误信息源引用 +6.3pp。
- 判读：①上期判定"删除可举证"是空位，1 天内被 Zep 以比墓碑更硬的方式（删除传播）部分填补；②新空位升级为"**字段级血统 + 团队级治理从未同体**"（Zep 有血统无治理，TencentDB 有治理无层间边）；③血统是纯成本项、不涨 benchmark 分，推动力来自采购而非评测，故由企业工作流厂商先做。
- 下期候选：zep 级联删除在事实记忆侧（Graphiti）是否对齐 / 十亿级条目的边表存储代价实测 / 归因（上下文日志）最小可行字段 / 巩固税的分层留边阈值 / AML 二期出榜后是否新增可追溯维度


## 第 4 期（2026-11-06 06:00）· 记忆的单位——从"事实"到"事件"，切分是第一性决策

- 产物：`记忆技术洞察-20261106-0600.md`（正文约 3,060 汉字；五章 + 9 方案六维对比表 + 29 条来源）
- 与前三期的关系：前三期讲"写得好 / 删得清 / 指得准"，共享一个未检验的预设——**"一条记忆"有多长是给定的**。本期追问长度从哪来，结论是它被"切"出来，且切分处在写入、删除、可寻址三者的共同上游。
- 主线：**记忆的基本单位正从"原子事实"（atomic fact）换成"事件"（event）**。一周内四家独立收敛：腾讯混元 Hy-Memory 2.0（"从零散事实升级为完整事件脉络"）、华为 openJiuwen OmniMem-Lens（视听双流按真实事件定界）、Hindsight（事件切片四类，含"失败重试"）、OpenViking（六字段事件模板）。事实单位有三个内生缺陷：无时态（冲突只能靠无解的消解）、必须去重（WASP-Mem 实证人工 schema 与显式去重有害）、可合并（合并即断边）。
- 新框架（第四批长期工具）：
  - **可变性分层**：正确分层不是"精度分层"而是"可变性分层"——判据是"删掉它能否从源重建"；能=派生索引，不能=源。ReMe 已明示该原则，多数系统把派生当源。
  - **切分三问**（建议成为 schema 契约）：切分依据（时间窗/内容边界/模型判定）、最小单位定义、边界漂移处理（合并/并存/取新）。
  - **计费单位错配**：条数由切分粒度决定（0.02 元/万条·小时），当计价单位是架构选择而非物理量时，采购比价失效。
- 时点事实（30 天窗口，已入台账）：十六天七家发记忆产品（Databricks MemCurrent 10-20、Autopoetic 10-20、阿里云 11-02、Hindsight 11-03、Redis Iris 六能力 11-04、MongoDB+Google ADK 11-04、PhoenixAI Contextbase 11-04），形态分存储/管道/判断三派；WASP-Mem arXiv:2611.04003（11-02，+4.6~6.1pp、存储 −57~61%、人定 schema 有害、一轮人工诊断胜四轮自判 7.0~10.9pp）；SUMONE arXiv:2611.06445（11-04，掩码重建+GRPO，成本 −78%/−75%）；Do agents need to sleep? arXiv:2611.02216（Haber & Tononi，选择式巩固>指令式的可证伪预测）；OMCE arXiv:2611.01747（四认知动作路由，+20.5pp）。
- 判读：①"事件"已是共识、"切分算法"还不是——九家六家称事件级，仅 openJiuwen 公开判据并给出失败案例，切分是唯一既决定全部下游又完全不被审计的环节；②修正第 3 期"C 级无人"——Redis Lens 做到的是**事件级重放**（当时用了什么）而非因果归因（去掉它会不会变），B 级门槛从"字段"降到"链路"，C 级仍无人；③长驻 agent 抽掉"会话边界"锚点（QwenPaw 改每轮写入），切分不稳定则幂等失效（MongoDB 幂等只覆盖 session 重放）；④切分粒度即隐私粒度。
- 下期候选：纯文本长会话的事件边界检测方法 / 切分稳定性可测指标（同输入两次摄入的边界一致率）/ 事件源表与派生表的迁移成本实测 / Autopoetic 哈希链的可验证删除 / Hy-Memory chat memory 8 层与"事件脉络"的层间映射 / AML 二期出榜口径

## 第 5 期（2026-11-06 07:00）· 记忆的净现值——当"记忆税"超过"记忆收益"

- 产物：`记忆技术洞察-20261106-0700.md`（正文约 3,068 汉字；五章 + 成本-精度前沿表 + 12 方案六维对比表 + 32 条来源）
- 与第 1—4 期的关系：前四期讲"写得好 / 删得清 / 指得准 / 切得对"，全部是能力命题，且都默认"记忆有用"。本期换判据：**记忆值不值**。结论是能力命题已基本可解，经济命题多数为负。
- 主线：**记忆的净现值**。三篇独立研究（Memory Tax / RAW-RAG / MemoryTax）在 2026-10 下旬同时给出反直觉答案：11 个记忆系统在 LongMemEval-s 上无一跑赢两轮 RAG（81.4%），加工动作本身有损，且构建成本可高于"不建记忆"。
- 新框架（第五批长期工具）：
  - **成本三段**：判断（写入时模型调用）/ 驻留（存储 + 上下文占位）/ 检索。行业只报驻留，成本主体在判断。
  - **记忆 NPV**：复用次数 × 单次节省 − 构建 − 驻留 − 缓存惩罚 − 错误固化损失。复用次数是唯一乘数，故应按频次分层而非按数据类型分层。
  - **遗忘 NPV**（本式为负亦常见）：省下的前缀 token − 重取成本 − 缓存重建 − 精度损失。
  - **价值可观测五级**：V0 无 / V1 计数 / V2 痕迹 / V3 消融增益 / V4 反事实。主流 V1—V2。
  - **写入者定天花板**：读取侧优化收益递减，上限在写入时锁定。
- 时点事实（30 天窗口，已入台账）：Memory Tax（11 系统 × 3 基准 × 3 骨干，99 组对照 90 组负；保真 98.4% MemoryOS → 39.4% OpenViking，38.0% 事实无对应单元；金标记忆单元 < 金标原文）；Peng MemoryTax（Mem0 构建 $25.88 > 全量上下文 $17.84，均 95%；Zep 图由 GPT-4o-mini 写入，读侧换 Opus 仅 43/43/45%）；Hidden Costs of Forgetting（42 配置 / 9,400 次运行；延迟删除 37/42 保效果；缓存感知定价下 0/42 省钱，最坏贵 5—10×；Trae 轮次 +73%）；AKV（清华 2610.28577，KV 层 drop，+1.7 分 / −27.7% 成本）；Anti-Persistence（2610.27406，错误再生产）；SLICE-Mem（分类器 + 句法，token −92.4% 打平 MemOS）；Jev 决策模型（+19% 成本、0 收益、校准差）；Scalaris（92.2/90.77，4,145 token，比 Hindsight 少 10×）；LambdaDB（4,886 token 96.0% vs 全量 105,183 token 95.2%）；Hindsight 自测（recall@5 60% vs 纯 RAG 97.5%）；Particle-1（$0.004/正确答案 vs Opus $0.099）。
- 判读：①"省 token"与"省钱"在缓存定价下可以反向，记忆优化的目标函数应改为账单而非 token 数；②压缩的正确层位可能在 KV 而非文本，这同时解掉第 3 期巩固税与本期的缓存惩罚；③写入侧不是"分工"而是"锁上限"，第 1 期判断需下调为中性；④抽象随时间是负资产（错误增殖），L2/L3 蒸馏层需重新论证；⑤竞争分三档：有净现值证据（Databricks/AKV/SLICE-Mem）／有能力无账本（Hy-Memory/TencentDB/Redis）／重架构高税（OpenViking）。
- 下期候选：AML 二期出榜后的口径复核（11 月中，优先）/ 会话边界删除的最优调度实测 / 复用频次分层的最小可行统计（哪些记忆被复用 ≥3 次）/ KV 层记忆与文本层记忆的一致性对账 / 保真度抽样审计的最小样本量 / TencentDB 可插拔决策服务能否接第三方小模型

## 第 6 期（2026-11-06 09:00）· 记忆的插座化——接入层战争开打

- 产物：`记忆技术洞察-20261106-0900.md`（正文约 2,050 汉字；五章 + 6 方案六维对比表 + 16 条来源）
- 与第 1—5 期的关系：前五期分别讲写入侧、删除、可寻址、切分、经济性，全部在"记忆系统内部"。本期向外一层：**记忆如何被接进 Agent**。结论是竞争重心正在从能力层迁到接口层——插座即产品。
