## 本期新增（第 78 期，20261113-1100）
- 主题：记忆的"写入保真·读取裁决"范式（Preserve-at-Write, Resolve-at-Read）——召回已饱和，"分辨（resolution）"才是新瓶颈；承接第 1 期写入闸门（保真是其正交轴，非内容放行）、第 71 期自组织/第 77 期处方性整理（整理移到读取侧/旁路）、第 75 期反噬（拒答是其对称安全兜底），用 2026 DISCERN/MIRIX-2.0 实证刷新。
- 新观点：①范式拐点——retention/currency 0.93–0.98 已近天花板，竞争焦点从 retrieval ranking 转向 preservation↔resolution 分工；②写入保真是独立于写入闸门的一等 SLA——严格追加双时态溯源，合并/去重一律移到读取侧或旁路（MIRIX AutoDream 写路外合并、不重写记录）；③拒答（abstain）是与 answer 对等的门控终态，是反噬的对称安全兜底；④读取裁决须零-LLM 工具面+强制歧义检查(find_similar_entities)+引用约束(citation-or-abstain)，与 #73 多形态拼装互补（彼管"检索→执行"表示，此管"多候选/时态冲突时怎么选"）；⑤AML 须补 resolution/abstention 维度（实体分辨 0.800 vs ≤0.40、拒答 F1 0.924 vs ≤0.802），否则继续误判"谁的记忆更好"（接 #56/#69）。
- 台账新增：六之四十九（写入保真·读取裁决/分辨瓶颈）+ 待验证 345–349。

## 上期新增（第 77 期，20261113-1000）
- 主题：记忆的"处方性整理"陷阱——程序性/经验记忆的习得需"涌现式wiki组织+人类诊断"，而非"人类预设schema+去重规则"；承接第71期自组织（SoMem链接文档）、第28期schema即世界观（挑战其"schema应设计师冻结"前提）、第19期代谢/整理（深化consolidation方法），用2026 WASP-Mem实证刷新。
- 新观点：①"处方性整理"反直觉失效——WASP-Mem（2611.04003, 11-02）证明人类预定义schema+显式去重规则使TheAgentCompany通过率下降，57-61%存储节省却以质量换；②人类角色应自上"设计schema"重定位为"诊断失败"——单轮人类诊断>agent自我判断4轮(7.0-10.9%)；③五项目分裂为两派：涌现式wiki组织（ReMe wikilink图、OpenViking ov compile→wiki、WASP-Mem、SoMem）vs 固定分层schema（dsh五轨、Hy-Memory 8层、TencentDB L0-L3），2026证据偏向前者用于程序性/经验记忆；④"可复用经验"应作一等记忆类型（接Hy-Memory Working双层/TencentDB技能共享），但其组织须自下而上涌现；⑤深化第28期：schema非"世界观冻结"而是"运行期可涌现结构"（接第71期结构自组织权）。
- 台账新增：六之四十八（处方性整理陷阱/人机诊断分工）+ 待验证 340–344。

## 上上期新增（第 76 期，20261113-0900）

- 新观点：①并发正确性应从"机制"升级为"可测 SLA"——把待验证29 从"零对照数据"推进为首个测量方案：固定 conflict workload，扫 git identity 漂移/账号vs实例/角色三轴，报冲突检出率与误报率，首次把第8期"身份先于锁"变成可复现实验；②"删除=依赖失效事件"模型：forget 广播 invalidation 而非点删，派生进未决态，解待验证27（接 StateGraph V2+依赖失效 / #74 复活通道）；③隔离粒度下移（浪潮 DataSpace / Maximem 四层）把并发从"条目锁"变成"scope 级不可见"，"never below/sideways"比锁更省，竞争焦点从互斥转移到身份解析与作用域边界；④五项目并发断层：OpenViking git identity 最完整但 forget 无墓碑、dsh 分支=作用域时钟最优却 unicode61 共因故障、TencentDB 角色四档+版本但跨 agent 删除权悬空、Hy-Memory 权重覆盖不可逆、ReMe2Ops wikilink 无并发语义；⑤AML 三期（待验证30）补"并发正确性"轴：冲突检出率/收敛时延/失支率。

## 上上上期新增（第 75 期，20261113-0700）
- 主题：记忆的"反噬"（memory-induced degradation）——记忆会让 agent 在"无记忆本能通过"的任务上失败，打破"召回越多越好"的正和假设；与 #73 利用鸿沟（用不对）显式划界：彼管"检索到了没用上/用对"，本期管"用了错误记忆反而更差"；与 #5 记忆税/#70 条件效用（增益侧）/#74 遗忘保真度（删除侧）正交——本期管"写入的正确记忆在运行时变成负债"。
- 新观点：①记忆价值度量应从"增益 Gain"升级为"净决策质量 = Gain − Regression"，高增益高回归=亏本，需"回归率 Regression Rate"作为与召回率对称的一等 SLA；②记忆不是事实而是"带主张、可验证、可下钻"的声明——蒸馏只给成败单标签、不含"为什么"，主张须绑定源 run 才可审计（延伸 #1 origin_id/#63 陈述者×镜头）；③双账本——MEMOIR 事后归因（2611.07631，被采用加权+UCB 欠曝奖励）记"信用账"，回归事件记"负债账"，净值为差，AML 与六产品零双账本（接 #56/#73）；④"验证优先于信任"做成可运行 harness：三层层（insight/compilation/raw trajectory）只读挂载 + 四类触发下钻（缺细节/失败来源/冲突/动作失败），WikiTrace（2611.14320, 11-10, Apache-2.0）52% 退化失败可溯源、20% 项本身错、回归 4.5%；⑤深化 #66 固化压缩/#72 状态坍缩：压缩丢"为什么"正是反噬温床，反噬是压缩风险的运行时变现。
- 台账新增：六之四十六（记忆反噬/双账本）+ 待验证 330–334。

## 第 74 期（20261113-0600）新增
- 主题：记忆的"遗忘保真度（Forgetting Fidelity）"——把"用户要求删除后信息是否真的不可恢复"立为记忆系统一等 SLA（与 #55 状态协调、#66 无丢失合并并列）；与 #19 代谢/#54 投毒/#60 回滚/#66 压缩/#67 共享投毒显式划界：彼管自然衰减/恶意注入/可回滚/整理风险/共享爆炸半径，本期管"合规遗忘——用户说删，系统是否真忘"。
- 新观点：①删除是"轨迹不变式"而非"快照断言"——当下审计量错不变量，应在每个后续时刻、每个可达状态都不可恢复（Deleted Is Not Forgotten，NeurIPS 2026）；②遗忘保真度应成记忆一等 SLA，与召回率对称；③隐私-效用-可删三角——摘要提隐私(−60% 提取)却破坏可删(衍生副本幸存)，复活机制使清掉衍生副本仍被同伴/检查点复活，可删性=min(所有表征×所有副本×所有复活通道)；④IPG 须跨 agent——单 agent 内溯源不够，需跨 agent/检查点/工具的"删除作用域图"（延伸 #1 origin_id）；⑤Bemula（arXiv 2610.18052, 10-13）实测六系统+三主干无一个端到端通过超 1.5% 遗忘请求；MemLeak（NeurIPS 2026）删文本+关联图后 VLM 凭隐式视觉线索恢复 12.0%、内容感知语义删除压到 2.0%；六家产品零 unlearning 承诺、AML 无 forget_fidelity 维度（接 #56/#69/#73）。
- 台账新增：六之四十五（遗忘保真度）+ 待验证 325–329。

## 第 73 期（20261113-0500）新增
- 主题：记忆的"利用鸿沟"——检索到了 ≠ 用上了 ≠ 用对了（多形态证据组成 + utilization delta，承接 #70 暴露瓶颈/#61 使用闸门/#20 查询失真，但聚焦"检索→执行"之间的损失）
- 新观点：①记忆的真正损失发生在"检索→执行"之间，而非召回本身——BioMem/HMRU（2611.13426）证明检索质量不变时利用方式差使答案错误差 24.9%、补齐全上下文 48% 差距；②记忆的表示应是"多形态证据对象"而非"单字符串"，HiVe-Mem（2611.12872）每条记忆保 summary/caption/视觉/原图/轨迹多形态、可训练选择器按查询拼装子集，token −90%；③定义 Utilization Delta = f(执行|记忆,拼装) − f(仅检索) 作为新计量，AML 缺"召回→执行"差列（接 #56/#70）；④六家产品全为"单一表示"检索、零多形态拼装、零利用增量口径，倒挂延续；⑤深化 #1 写入闸门：闸门应写"多表示"并挂形态标签（接 #28 schema）。
- 台账新增：六之四十四（利用鸿沟）+ 待验证 320–324。

## 第 72 期（20261113-0400）新增
- 主题：记忆的状态化坍缩——把历史递推成可决策的小状态，越过 reader-dependent horizon 后显式状态胜过长上下文（挑战"记忆=可检索上下文"前提，承接第 70 期条件效用、第 71 期自组织）
- 新观点：①存在一个 reader-dependent horizon，256 事件后长上下文把 7–32B 从 72–86% 拖到 48–55%、读状态推理模型达 96–98%（arXiv 2611.02361，11-02）；②"该记什么"应在写入时按状态依赖筛选（write-time dependency filtering），query-time 检索反不如它；③记忆系统本质受速率限制（rate-limited）的递推滤波器，遗忘是滤波器的自然行为（重写第 19 期代谢）；④深化第 1 期写入闸门：闸门判"是否属于某可递推状态的依赖集"；⑤六家仅 Hy-Memory 30B 写入模型/TencentDB 决策服务把"写"做成决策，但无状态依赖筛选，倒挂延续；⑥AML Cycle 2 开放但七维度无"状态坍缩率"计量（接第 56/69 期）。
- 台账新增：六之四十三（状态化坍缩）+ 待验证 315–319。

## 第 71 期（20261113-0300）新增
- 主题：记忆的自组织（Self-Organized Memory）——当记忆系统自己决定怎么整理自己（结构自组织权，第六项记忆主权）
- 新观点：①记忆 schema 由设计师冻结→应转为 agent 可学习的"结构自组织权"（继写入闸门/删除/可寻址/内省/携带权后第六项）；②SoMem 用链接文档+回链证据+运行时校验反范式，弃"摘要即压缩"；③自组织把 #66 整理风险升级为"结构损失"（比压缩更难审计），链回证据+运行时校验=自组织下的安全（接 #60/#19）；④深化 #59 携带权：可携带的不只是内容还有结构；⑤AML 无 schema-evolution 维度，治理缺口延续（接 #56/#69）；⑥六家产品零结构自组织披露，倒挂延续。
- 台账新增：六之四十二（自组织）+ 待验证 310–314。
