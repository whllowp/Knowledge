# 记忆技术洞察 · 第 80 期（2026-11-13 13:00）

> AgentMemory 领域 ｜ 四维度覆盖：发展趋势 · 技术现状 · 技术竞争力 · 技术挑战
> 本期新观点：记忆的「写入信任边界」——文件成真相源、向量只为派生，write-path 才是真实质量轴

**本期新观点（4 条）**：① 真实质量轴是 write-path 而非存储格式——差异在「谁决定存什么、怎么重写」；② 文件即真相源收敛造出「信任边界」，记忆库本身成写/攻击面，五项目零写授权层；③ 四层分型揭示头号选型错是「层错配」（用一层工具解另一层问题）；④ 「扔掉一部分」是四层通用修复，写入闸门应重述为「记忆质量=你拒绝留存什么」。

## 一、需求分析（发展趋势 · 技术现状）

2026-11 的选型调查揭示行业收敛：**可读文件为真相源、向量索引为派生**。Hy-Memory 上线 30B 专用写模型，ReMe/OpenViking 以 Markdown/虚拟文件系统为真相源，dsh 写入须人确认，TencentDB 决策服务分管 Skill 选择——五家不约而同把「写路」做成一等公民。记忆竞争焦点正从「存储格式（向量 vs 图）」转移到「谁决定存什么、怎么重写」。

同期 Pro-Memory(arXiv 2611.05731, 11-03) 把前瞻记忆拆成「保留未来意图 ↔ 决定何时兑现」，提示写路还要承载「未来意图」这类新对象。这与第 79 期决策效用（读侧选记忆）**正交互补**：彼管「取什么」，此管「落什么笔」。

## 二、用户旅程（技术竞争力）

以「开发者换项目三天后回会话」为典型旅程，五项目写路竞争力分层：

- **Hy-Memory**：双系统 + 30B 写模型，写路最重、质量上限最高，但强绑混元生态；
- **TencentDB**：短期卸载 + 长期四层 + 决策服务仲裁，工程化最完整；
- **dsh-memory-evolve**：写入须用户确认才生效、git 分支感知，写路治理最克制安全；
- **ReMe**：Markdown 为真相源、BM25+wikilink+向量、auto_dream 后台整合，写路最透明可审计；
- **OpenViking**：viking:// 文件系统 + L0/L1/L2，生态内最顺滑，但跨系统门槛高。

结论：写路「谁落笔」的治理粒度，正取代「用什么库存」成为选型第一问。

## 三、具体实现方案（技术挑战）

**挑战一·信任边界未设防**：文件即真相源后，记忆库本身成写/攻击面——谁可追加改写 .md 或 git 分支是安全决策。五项目零写授权/完整性层（接 #54/#67 投毒、#74 遗忘、#76 并发）。AML 应补「写路完整性」维度（写授权/人在环/编辑溯源）。

**挑战二·层错配**：四层分型（任务内上下文 / 个人长期 / 团队项目 / 程序性）揭示头号选型错是用一层工具解另一层问题，AML 应补「层适配」维度。

**落地方案**：① 写路默认「人在环 + 双时态溯源」（dsh 模式），每条记忆带 writer_id/branch/ts；② 「扔掉一部分」是四层通用修复（IBM 四失效模式皆靠丢弃），把第 1 期写入闸门重述为「记忆质量 = 你拒绝留存什么」；③ 删除 = 跨信任边界的强制文件抹除（深化 #74 遗忘保真度）；④ 评测补 layer-fit 与 write-path-integrity 两轴，补上 AML 治理缺口（接 #56/#69）。
