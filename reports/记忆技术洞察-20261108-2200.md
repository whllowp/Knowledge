# 记忆技术洞察（第 39 期）：记忆的同步拓扑——多机失忆与 Git 传输层

> 生成时间：2026-11-08 22:00 ｜ 系列：AgentMemory 每小时技术洞察 ｜ 范围：2026 年（重点近 30 天）

## 一、发展趋势

前 38 期共享一个从未检验的隐含前提：**记忆库只有一份，住在一处**。本期证据表明该前提正在被拆掉——"多机失忆"（换台机器、智能体就忘一次）已成为被命名的独立问题，且一周内至少六个项目把 Git 选为记忆的传输层。

三条趋势：其一，**同步层从功能变成品类**——hermes-mesh、ACDM、StateNest、server-noonien 全部以"多机共享记忆"为唯一卖点，而非既有记忆产品的附属功能；其二，**本地优先从理念变成默认实现**——腾讯 MemHub 桌面端本地运行时、memhub v0.2.1 每台机器全量本地召回、ai-memory 自托管服务器，离线可用成了入场券；其三，**传输介质收敛到 Git 与对象存储**——零守护进程、历史与审计随介质免费获得。

新框架（长期复用）：**传输层四形态**（共享目录整文件 / Git 仓 / 自托管服务器 / P2P CRDT 网格）；**汇合是第七个写入口**——与前六个不同，它同时改写所有机器上的副本；**同步账单**——新鲜度账户（第 11 期）的新入口。

## 二、技术现状

**1. 反面教材定形。** MCP 官方 server-memory 把整张知识图放在单个 JSONL 文件里，每次调用全文读改写：单机没问题，两台机器经同步目录共享则必丢写入。这一存储模型正是本周一批替代项目的共同出发点。

**2. 冲突裁决五档谱系。** 由弱到强：①整文件读改写（丢写）；②三方合并 + 冲突才请 LLM 仲裁（hermes-mesh：每 15 分钟拉推，每条冲突 120 秒超时串行裁决）；③永不自动合并、双版本并存（StateNest："真冲突等你"，产品级最保守——第 8 期"保留分叉"首次从论文走进插件产品）；④人工三选一（huahua-dsh-memory-os 的 Memory Sync：本地/远程/两要）；⑤CRDT 折叠（server-noonien：LWW-Element-Set + 混合逻辑时钟 HLC、墓碑删除、按节点分片单写者、S3 条件写或 nooniend P2P 网格、四条代数律性质测试）；⑥追加式事件日志 + preserve-first 解析（ACDM：月分片 JSONL、坏行容错、event_id 去重）。

**关键修正（第 8 期）**：此前判"CRDT 在生产级记忆组件缺席、记忆产品全军单主干"，server-noonien 作为 MCP 官方 memory server 的 drop-in 替换证伪了前半句——CRDT 首次进入智能体记忆生态。但 LWW 语义未变：HLC 只解决时钟可比性，"事实权威"仍等于最后写入；**收敛不等于正确**。

**3. 隔离与身份。** hermes-mesh 给事实打机器标签（硬件规格/内网地址/本地路径仅本机可见），密钥、令牌、会话日志进同步黑名单永不外传——这是第 12 期"信任半径"在同步场景的首次工程化，但标签靠提示词教智能体自觉打，不是 schema 字段；agent-memory-nest 自认"这些是协议规则，不是操作系统权限"。身份侧：StateNest 把项目身份定为 git remote 归一化哈希（同 remote 即同项目，无 remote 只得随机 id、永不合并），OpenViking 的 peer 即 git identity（第 2 期）——身份从磁盘路径迁到远端地址，是第 3 期主键断裂的新变体：**远端改名即全员失联**。

**4. 加工默认与派生性。** ai-memory 默认零 LLM 路径（捕获/检索/交接均无需 key），"做梦"式重写为 opt-in 且须先通过召回评测才能成为默认——离线加工从默认降级为可选项（承第 9、34 期）。数据库=派生索引再次确认：ai-memory 的库可从 Markdown wiki 全量重建，memhub v0.2.3 干脆把 versions.db 里的第二份向量副本删掉——第 4 期"删掉能否从源重建"判据第三次验证。跨代理历史导入长成独立品类：dsh-deja 索引 42 个编码代理的会话史，dsh-chat-import 支持 25+ 代理，memsearch-dsh 带技能候选审核面板。

**5. 六项目与大盘动态。** 腾讯 MemHub v1.0.6：11 语种界面、lite/pro/ultra 三档、CLI/API 多用户、底层 hy-memory 2.0.14；OpenViking v0.5.3 + 独立网关（端口 1935，字节级重放保缓存签名）；TencentDB Agent Memory v2.0.3 云托管、按条·小时 + Credit 计费，其"MIT + 腾讯声明"包装许可证被 GitHub 检测器拒判（首期参赛曾因此被拒后翻案）；ReMe 插件 0.1.2 进入 DSH Hub（11-06 更新、扫描通过）并同包支持 OpenClaw，recall 结果显式标注"不可信历史数据"，cron/心跳/subagent 默认不召回不捕获；DSH 生态记忆类目 11-06 集体更新。AML 二期：11-04 23:59 关评测，官方榜单 11 月中旬发布，截至 11-08 22:00 未出；一期 A–H 八维全能力剖面已在官网公开可查。

## 三、技术竞争力

市场分三档：**本地优先同步阵营**（Git 为轴，memhub/StateNest/hermes-mesh/ACDM）、**自托管服务器阵营**（ai-memory、OpenViking 网关）、**云托管阵营**（TencentDB、Mem0）。竞争变量沿第 6 期"插座覆盖"→ 第 14 期"账单"继续前移，本期新增**同步半径与冲突语义**：一台机器的写入多久到达其他机器、到达时冲突按什么规则处理。云托管把同步"做没了"（单点即真相），但付出数据出境与第 13 期嵌入锁定税；本地阵营保住数据引力，代价是必须自己回答第 8 期遗留的并发问题——本周的答案分化明显。

| 方案 | 拓扑 | 冲突策略 | 离线行为 | 隔离机制 | 身份 |
|---|---|---|---|---|---|
| hermes-mesh | Git 裸仓+15min | 三方合并+LLM仲裁 | cron拉推可用 | 机器标签+黑名单 | SSH key+协调者 |
| memhub (shibing624) | Git/网盘/服务器 | 版本链+JEV写闸 | 全量本地召回 | 版本链隔离 | 配置绑定 |
| StateNest | 私有Git+后台同步 | 永不自动合并 | 无daemon全离线 | 只同步自身记忆 | remote哈希 |
| agent-memory-nest | Git模板+协议 | 手动合并+优先级链 | 本地副本 | agent目录+git-crypt | 目录协议 |
| ACDM | Git+月分片JSONL | preserve-first去重 | 追加式只增 | SHA256追踪 | repo相对路径 |
| server-noonien | 分片+S3/P2P | CRDT LWW+HLC | 最终一致 | 单写者分片 | node id |
| ai-memory | 自托管服务器 | handoff认领一次 | 服务器随身 | 多用户鉴权+审计 | owner归属 |
| 腾讯MemHub | 本地runtime+多宿主 | 版本链+JEV | 本地离线 | 物理隔离（宣称） | 授权绑定 |
| OpenViking | 自托管+网关 | 存储层锁 | 字节级重放 | ACL哨兵 | viking://URI |
| TencentDB | 云托管单点 | 平台侧处理 | 无 | Team三级角色 | 云账号 |

判读：冲突语义五档中，最保守的（StateNest 双版本）与最强的（server-noonien CRDT）都来自社区小项目；头部商业产品对"两台机器"这个问题整体沉默——**倒挂第三十次**（有同步语义的全不是头部记忆产品）。另注意同名双包第二例：shibing624/memhub（PyPI memhub，v0.2.3）与腾讯混元 MemHub（v1.0.6）毫无关联，采购须按仓库全名区分。

## 四、技术挑战

一，**同步账单无度量**：hermes-mesh 的 15 分钟窗口内两机互盲，协调者宕机后官方文档直言"工作者会降级继续跑但记忆开始漂移"——这是第一个把漂移写进产品语言的项目，却没有任何指标去量它。二，**收敛不等于权威**：CRDT 四律保证各机折叠出同一张图，不保证图里的事实是对的；两台机器各记一个"当前架构方案"，LWW 下静默覆盖，第 8 期的"失支"型冲突在同步场景原样重现。三，**隔离靠自觉**：机器标签无 schema 字段、无写入校验，协议声明不是权限系统，黑名单遗漏即泄漏。四，**多机一致性零评测**：AML 评测契约是单机单 API 的 Add/Search，无同步维度、无冲突注入——口径缺口第三十一次，榜单分无法区分单机能力与多机可用性。五，**hub 成为新故障域**：裸仓协调者或自托管服务器同时是单点故障与单点信任，第 12 期信任半径分析在同步场景完整重现，且多了一个"降级漂移"态。

## 五、展望与建议

其一，**同步半径将成为第三个采购变量**（继插座覆盖、账单之后）：询价时应要求厂商给出"写入到可达"的分布与冲突处理语义，而非"支持多设备"一句宣称。其二，建议 schema 增设三字段：`sync_scope`（共享/机器/会话）、`machine_tags`、`last_sync_epoch`——把 hermes-mesh 的手工标签升格为机器可校验的契约。其三，CRDT 阵营需要补"语义冲突测试"：性质测试证明收敛，证明不了权威；建议对同一事实双机异写做条件召回对照。其四，选型上把 hub 当**数据**而非服务——凡派生可重建（第 4 期判据）的方案（ai-memory、memhub）可整目录备份迁移，凡把索引藏进黑盒的方案会重演第 13 期锁定。其五，本地优先不等于免治理：写入准入、注销、血统、权限在多机场景需逐条重验，尤其删除——**墓碑（tombstone）只删本机、随同步复活的概率远高于单机场景**，第 18 期备份-删除三角在同步层第三次现身。AML 二期榜单 11 月中出榜：若仍无同步/多机维度，则第 10 期（currency）、第 11 期（新鲜度）、本期（同步）三线合流指认的将是同一个缺口——评测合同里没有时间。
