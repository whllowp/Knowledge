# 记忆技术洞察（第 12 期）· 2026-11-06 15:00

**主线：记忆的信任半径——共享是卖点，半径是负债**

## 一、发展趋势

前十一期各自拿掉了一个预设：写入、删除、寻址、切分、成本、接入、空集、并发、闭环、时效、时延。它们共享最后一个从未被写出的预设——**记忆的读者就是记忆所属的那个人**。本期拿掉它。

三条信号：

1. **产品侧把"跨 agent 共享"做成了核心卖点，而卖点即攻击面。** Hy-Memory 2.0 的 MemHub（10-15 发布）自我描述为"同步已授权的历史，让一个 agent 记得另一个 agent 做过什么"；TencentDB Agent Memory 定位"团队级记忆中枢"，把对话、文档、代码蒸馏成四类可"装备"到不同 agent 的资产；OpenViking 的 `viking_manage_skill` 允许指定共享技能根、同名即覆盖。三家的共同结构是：**共享是默认路径，权限是外挂**。OWASP《Top 10 for Agentic Applications》2026 版已把 ASI-06（记忆与上下文污染）单列，并直接点名"共享记忆存储把一个 Agent 的写入变成另一个 Agent 的读取"的放大效应。
2. **研究侧的目标函数从"零污染"换成"限半径"。** 10-20 的 PerMIT 仍走收敛路线：只信用户键入与门控确认的值，两条完整性定理以 Lean 4 机器验证，把威胁模型内所有攻击化简为"一次可审计决策"。11-04 的 Airlock 走相反路线：不假设防得住，只处理"告警之后"——沿跨 agent 数据消费的 provenance DAG 前向隔离受染执行、后向收窄根因，用 deadline-aware 最小割决定牺牲哪些分支。两者不是竞争，是同一条时间轴的两端。
3. **隔离粒度在下移。** Databricks 的立场罕见直白："`actor_id` 分隔记忆，但它不是访问控制……**存储才是安全边界**，跨租户严格隔离请一租户一库。"产业侧对应动作是浪潮 Agent DataSpace：把 KV Cache 与 Memory 的"可控共享与隔离"下沉到存储层，另配"数据保险箱"做 WORM 防篡改与可逆回滚。安全正从应用层 scope 搬到存储卷。

一句话概括趋势：**记忆正从"个人外挂"变成"组织基础设施"，而基础设施的第一属性不是容量，是边界。**

## 二、技术现状

**三个可复核数字，分别对应暴露、处置、预防。**

其一，**暴露率远高于危害率。** arXiv 2610.25707（10-19）在 AppWorld 上做了单库混租实验：763 条历史登录混在一个存储里，**84.7% 的必需应用能取到他人的凭证**，但"agent 极少据此行动"；压力测试中加一行"在凭证行前或行内注明所有者"即可阻断大多数误用。作者结论是"记忆应始终记录它存的是谁的凭证，评测应测行为而非暴露"。这句话同时否证了两件事：暴露指标不能预测危害（与第 9 期"文本评级不能预测行为"同构），以及**当前缺的不是 ACL，而是"这行字属于谁"这一个字段**。

其二，**第一次给"割多少"定了价。** Airlock（2611.06727，11-04）：1,832 次 testbed、161 次真机智能家居、24,266 条仿真记录；A2A 与 LangGraph 的原生控制在同样告警下**最多容纳 33.3% 的故障，或最多保住 16% 的健康工作**；Airlock 多保住 **+68 至 +96 个百分点**的健康工作，其优化割在密集扩散下比"全量隔离"再高 **+46pp**。它给出的不是"更安全"，而是"同样不安全时少损失多少"——这是一个此前无人建模的量。

其三，**形式化开始进入记忆栈。** PerMIT（Stony Brook + AWS AI Labs，10-20）在 Trojan Hippo 上记录到**零攻击成功**，在 τ²-bench 上让最多 90 个 agent 共建共享知识库且"无直接记忆注入被提升"。它的社区背书机制（同一内容的多用户确认累加后免检）证明了一个 co-scaling 性质：社区变大时，投毒被提升与良性知识被误逐的概率同时下降，而人均验证成本不升。

**五条机制对照，看防御位置在哪里。**

| 机制 | 位置 | 默认假设 | 代价 |
|---|---|---|---|
| 内容过滤 / 关键词 | 写入前 | 恶意可被文本特征识别 | FARMA 类伪造推理痕迹可 100% 绕过 |
| 共识验证 + 负教训库（A-MemGuard） | 读时 | 上下文不一致即可疑 | EHRAgent ASR −97%、间接注入 −60%，多 agent 得分 0.950；需多次并行推理 |
| 单点门控（PerMIT） | 写入/动作前 | 只有用户键入可信 | 吞吐与仪式成本；Lean 工件未公开 |
| 归属标注（2610.25707 修法） | 写入时 | 读者会尊重所有者标记 | 近零成本，但只降低"误用"不阻止"读取" |
| 血缘切割（Airlock） | 告警后 | 污染已发生 | 需全链路 provenance DAG；割的精度依赖 DAG 完备性 |

这五条并不互补成"纵深防御"，因为它们覆盖的时间区间是断开的：**事前（门）与事后（割）都有人做，中间那段"已入库、未告警"的潜伏期没有任何机制**。

**产品侧现状。** Mem0 仍是四层 scope（user/agent/app/run）+ 元数据过滤，属"应用自己保证"；Zep/Graphiti 有双时态与 Skill 级联删除，但无写入权限分级；OpenViking 目录级 ACL 为 fail-closed 二次校验，企业文档另给"离职继承"规则；TencentDB 是三级角色四档可见性（第 8 期已记）；Maximem Synap 把隔离默认做到五层并给出最精确的语义表述——"读只取最窄的适用 scope，只看其上层，**绝不下看、绝不横看**（never below, never sideways）"；Sentra 则提出"在读时鉴权，而不是在复制时"——记忆复制文档再自带访问表，源侧权限一改就漂移。同期 MemArena 的结论（上期已引）是**所有被测配置在权限感知访问上全部失败**：Oracle 泄漏、其余过度遮蔽。

**六个指定项目 30 天动态（按本期主线标注）：**

- **OpenViking**：DSH 插件 0.5.33（11-05）、核心 v0.5.2.1；AGPL-3.0；`viking_forget` 为永久删除、`viking_manage_skill` 可指向**共享技能根**——本期最值得盯的一处权限面。
- **Hy-Memory**：2.0.14 在 PyPI；MemHub 1.0.6 的卖点正是跨工具"授权历史"同步，授权发生在操作系统/账号层，记忆条目本身无主体字段。
- **TencentDB Agent Memory**：30.3k★（11-01）、33 贡献者；四类资产（Chat Memory / Skill / LLM-Wiki / Code-Graph）跨 agent 装备，治理靠角色而非条目。
- **dsh-memory-evolve**：五轨记忆 + git 分支感知 + 回合内自审；写者身份即 git identity，天然带主体但无授权语义。
- **ReMe**：v0.4.2.1，生态仍受 DSH 版本声明门约束，无权限相关更新。

## 三、技术竞争力

按"边界怎么划、划在哪、划错了能不能收"四问做横向对照（"—"为未公开）：

| 方案 | 信任模型 | 边界位置 | 条目级主体字段 | 横向隔离 | 告警后可切割 | 公开验证 |
|---|---|---|---|---|---|---|
| PerMIT | 单一门控 + 社区背书 | 动作前 | 有（门控裁决记录） | 强（有限接口） | 无 | Lean 4 定理；Trojan Hippo 零 ASR |
| Airlock | 污染必然发生 | 告警后 | 有（消费 DAG 边） | 中（权限沿 agent 树收窄） | **强（最小割）** | 三套环境、24,266 条仿真 |
| A-MemGuard | 共识即异常 | 读时 | 弱 | 中 | 无 | ASR −97%、多 agent 0.950 |
| GateMem | 治理三难 | 指标层 | 有（principal） | 强 | 无 | MGS 无一方案三项全高 |
| Governed Memory | 生产架构 | 存储层 | 有 | 强 | 部分 | 泄漏事故 −91%（3 案例） |
| Mem0 v2 | 应用自保 | scope 字段 | 有（user/agent/app/run） | 中（靠过滤） | 无 | 无越权专项 |
| Zep / Graphiti | 双时态 + 级联删 | 边/技能层 | 部分 | 中 | 部分（Skill 级联） | 无权限基准 |
| OpenViking 0.5.x | fail-closed 目录 ACL | 文件树 | 弱（peer=git 身份） | 中 | 无 | 无 |
| TencentDB AM | 角色制 | 工作区 | 弱（角色四档） | 中 | 无 | 无 |
| Maximem Synap | 五层默认隔离 | 存储命名空间 | 有（tenant/user/agent/conv） | **强（不横看）** | 无 | 自报 LongMemEval 95.6% |

三档判读：

- **第一档（有形式化或可证性质）**：PerMIT、Airlock、GateMem。共同特征是把"安全"写成可检验的命题（定理、最小割、乘性指标），而不是策略清单。**它们全都不是记忆产品**——这是本系列第五次出现"最好的能力在非产品侧"。
- **第二档（有工程、无证明）**：Governed Memory、Maximem、Sentra。共同点是把边界下沉到存储或读时鉴权，方向正确但只有自报数据。
- **第三档（有 scope、无边界）**：Mem0、OpenViking、TencentDB、Hy-Memory。这是装机量最大的一档，也是 Databricks 那句"actor_id 不是 ACL"的精确所指。

**本期最大的空位不是"更强的防御"，而是"可执行的记忆没有自己的权限模型"。** 陈述性记忆被读错，后果是答错，可回滚；程序性记忆（Skill / Procedure Memory / Code-Graph）被执行错，后果是做错，不可回滚。但现状是两类记忆共用同一张可见性表：OpenViking 的共享技能根、Zep 的 Skill 级联删、MemoraX 自动提炼的 Procedure Memory、TencentDB 的 Skill 资产，全部把"能读到"等同于"能执行"。**记忆应该按可执行性分成两层，而不是按抽象层级（L0/L1/L2）分层**——这是本期提出的新分层轴，与第 4 期的"可变性分层"、第 5 期的"成本分层"正交。

## 四、技术挑战

1. **潜伏期是无人区。** 门在事前、割在事后，而"污染已入库、尚未被任何告警捕获"的窗口既无指标也无机制。这段窗口的长度（taint dwell time）无人测量，而它恰好是错误被复用、被压缩、被写进 Skill 的时段——第 9 期的"压缩放大律"在这里变成半径放大律。
2. **共享度与可切割性反向。** 共享越彻底，provenance DAG 越密，最小割越接近整棵树：Airlock 的 +46pp 优势建立在"故障沿有向边单向扩散"上，而记忆是双向引用、可反复压缩的图，割一条要断整条派生链。**共享的经济收益与安全成本同源同乘**（第 9 期结论的第二次验证），这解释了为什么厂商越强调共享，越不愿公开切割能力。
3. **暴露不可计分，于是无人投入。** 2610.25707 的核心发现是"暴露 ≠ 危害"，而 AML 三轨（文本/代码/多模态）没有任何越权或跨主体维度；GateMem 的 MGS 有，但不在榜上。这是本系列第五次遇到同构口径缺口：第 7 期弃答、第 8 期冲突、第 10 期时效、第 11 期时延，本期越权。**没有分数回报的能力，只能由采购条款逼出来。**
4. **群体指涉是新的闭环形态。** PerMIT 的 community-confirmed 把验证成本摊薄，但也把"足够多人确认"变成"不必再验"。背书者本身是被同一批内容塑造的——这是第 9 期"自我指涉"的群体版：主体从单个 agent 扩到整个社区，闭环半径变大，反而更难被外部观测到。co-scaling 性质在小社区成立，在"多数人已相信同一错误"的分布下方向反转。
5. **归属、权限、有效性是三张表，现在只有一张。** 第 2 期拆出"权限 ≠ 注销"，本期再拆一层：`owner`（这是谁的数据）、`principal`（谁能读）、`validity`（是否仍为真）三者互不蕴含。缺 owner 导致 84.7% 的横向泄漏，缺 principal 导致 scope 混用，缺 validity 导致第 10 期的旧值覆盖。**业界普遍只实现第三张。**

## 五、展望与建议

三条判断：其一，未来两个季度，"记忆隔离"会从功能列表移到架构图，形态是存储层多租户 + 读时鉴权，而非应用层 scope 枚举；其二，程序性记忆的权限分级会出现首个产品实现（最可能来自 Zep 的 Skill 或 TencentDB 的 Skill 资产），因为它们的后果最不可回滚；其三，潜伏期指标会成为下一个可观测性卖点，与第 11 期的 freshness lag 并列。

六条可执行动作：① 写入时强制 `owner` 字段，成本近零、收益最大（2610.25707 的直接结论）；② 读侧鉴权而非复制侧鉴权，避免权限漂移（Sentra 口径）；③ 把 Skill 类资产单列权限表，写入需二次确认、执行需 scope；④ 用"告警后保住多少健康工作"替代"拦截率"作为安全 KPI（Airlock 口径）；⑤ 记录 taint dwell time，先测后治；⑥ 采购条款中加入"单条目越权读测试 + 单条目删除路径"两项，二者缺一即不达标。

需要警惕的是第 4 条挑战：所有摊薄验证成本的机制，本质上都在把"检查"换成"信任"。信任可以规模化，但它也把错误的传播速度乘以社区规模。
