# 记忆技术洞察 第71期（20261113-0300）：记忆的自组织——当记忆系统自己决定怎么整理自己

> 生成时间：2026-11-13 03:38 (GMT+8) ｜ 领域：AgentMemory ｜ 范围：2026 全年，重点近 30 天
> **本期新观点**：记忆象限长期被"设计师定义结构"（fact/event/entity，或各产品的固定分层）垄断；本期主张"记忆结构的自组织权"是被忽略的第六项记忆主权（继写入闸门/删除/可寻址/内省/携带权之后）——谁有权决定记忆的"形状"，应成为新竞争轴。

## 四维度速览
- **发展趋势**：从"更好的写入/检索"（#1–#70 主线）转向"谁定义记忆结构"——自组织记忆（self-organized memory）把 schema 从冻结契约变为 agent 可学习行为。
- **技术现状**：arXiv 2611.11929（SoMem，11-09/10）首证 agent 能用普通文档自决摘要/分组/修订，每摘要链回原始证据；LoCoMo +2.66、BEAM-100K +3.10、LongMemEval-S +2.00，且记忆跨模型复用。
- **技术竞争力**：AML C2 实时榜 TencentDB 41.48（#7），强在 A 事实召回 50.44 / G 上下文执行 53.10，弱在 D 治理 31.54 / C 时序 21.89——"强执行弱治理"与自组织范式的风险转移呼应；六家产品零"结构自组织"披露，倒挂延续。
- **技术挑战**：自组织把 #66 的"整理=高风险"升级为"结构损失"（比压缩更难审计）；运行时校验成本、跨模型复用 vs 检索效率、AML 无 schema-evolution 维度三道坎。

## 一、需求分析
长期记忆默认由设计师定 schema：TencentDB 四层管道、Hy-Memory lite/pro/ultra、OpenViking viking:// 树、dsh 五轨、ReMe2Ops 固定式，都是"世界观冻结在结构里"。但任务与交互演化时，固定 schema 既会漏掉 designer 没预见的关系，又无法随使用积累自我修正（#28 schema 即世界观、#62 内部分工都未触"结构自决"）。SoMem 用"链接文档"反范式：agent 自己决定摘要什么、怎么分组、何时修订，每个摘要都回链原始对话作证据，运行时校验更新合法性，并自动派生时间/关系/近期三视图。需求被改写：系统要答的不是"这条记忆该存哪类"，而是"记忆的边界与分组，能否由 agent 随经验自决且可审计"。

## 二、用户旅程
一段记忆的生命周期：①原始交互沉淀为普通文档 → ②agent 自决摘要/分组/修订（链回证据）→ ③运行时校验更新合法性 → ④自动派生时间/关系/近期视图 → ⑤查询时沿文档链接走、按需查原始证据 → ⑥跨模型复用。断点在 ②：自决分组若无治理护栏，会把边缘但关键的记忆"整理"出可见区，且结构漂移比内容篡改更难审计（深化 #66 保全证明、接 #69 元进化真空）。SoMem 的"链回证据+运行时校验"是用链接而非压缩保住可逆性，与 #60 回滚、#19 代谢形成"自组织下的安全"子题。

## 三、具体实现方案
1. **链接文档基底（SoMem 式）**：用普通文档+显式回链存记忆，弃"摘要即压缩"，保原始证据可达；记忆跨模型复用，从结构层补 #59 携带权。
2. **自组织门控**：把"分组/修订"当决策（接 #61 使用闸门、#69 元政策），需运行时校验+可回滚；每次结构变更记 gate_log(structure, action, reason, rollback_point)。
3. **三视图派生层**：时间/关系/近期视图只作查询索引，绝不改写底层证据（接 #66 保全证明，检索与展示分离）。
4. **治理补丁**：自组织层补 ACL+state_role（接 #55/#69），AML 可加"schema-evolution"维度计量结构漂移与回滚率，补齐 #56 评测契约缺口。
