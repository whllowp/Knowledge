# 记忆技术洞察 · 第150期（20261125-0400）

> 洞察范围：2026 年、尤其近 30 天，AgentMemory 发展趋势／技术现状／技术竞争力／技术挑战四维度。主线来源：arXiv 2611.30412（11-23 提交）。本期新观点已与本地 C/E 双版索引及知识台账比对，未重复前期。

## 一、发展趋势
长程 agent 的记忆成本正从"少塞点 token"改成"谁付钱、按什么价付"。11-23 DMC-5（arXiv 2611.30412，cs.AI，Haochen Li 等五人）指出专用端点常无前缀缓存折扣，重复历史按全价反复计费，遂把全史整合交给有缓存的通用模型、动作生成留给专用模型。与 #137 划界（服务端 KV 逐出 vs 提示层跨轮前缀复用）、与 #147 深化（模块可组合之外新增"谁持有全史"的分工）、与 #133 呼应（原始留存的缓存经济学价值）。

## 二、技术现状
同一轨迹维护两视图：Canonical View 存原始动作／观察且永不回写摘要；Decision View 只给专用 agent 近期 K 轮原文加压缩状态。压缩复用字节不变的历史前缀、只预填新增后缀，产出五字段结构化摘要与指向原始记录的指针；YAMATO 确定性恢复工具输出、动作与工件写入序列，附 [O@i]／[D@i] 来源标记与最近 40 条失败台账。默认 K=1、压缩间隔 3、阈值 6000 token。

## 三、技术竞争力
AppWorld 77.0→78.2、OfficeBench 87.0→88.0、8-objective QA EM 39.1→44.9／F1 47.6→54.0；agent 输入降 38.46—57.02%，端到端成本降 14.48—27.97%，压缩器缓存命中 78—85%。FIFO 掉 27.7—40.7 点、ACON 掉 3.7—9.7 点且零命中；同结构下追加式命中逐轮升至 96%，未缓存压缩输入少 12.7—42.3%。

## 四、技术挑战
YAMATO 把执行关键信息损坏率 0.33%→0.01%、召回 77.7%→98.3%、准确率 69.1%→78.2%，同动作最大重复 29→6。但收益是长度与定价的条件函数：只压一次成本反涨 10.7%，两次以上才省 16.6—26.5%，第 16 步才回本；给有缓存的 agent 时命中率 70.5%→51.5%，仅在缓存价高于未缓存价 9.1% 时仍便宜。五项目版本今日未变；ReMe 有可恢复压缩提案、TencentDB 拒绝不可逆有损摘要，但均无双模型分工、缓存命中账或确定性指针恢复。

## 五、需求分析
用户要长任务不因上下文膨胀而变贵变笨，更怕压缩抹掉订单号、文件版本与失败尝试后反复做同一件错事；还要知道省下的钱来自哪次复用、什么时候不该压缩。

## 六、用户旅程
接任务→每步动作与观察追加进原始账本→达阈值触发压缩，通用模型读全史产出带指针摘要→确定性拼回关键记录与失败台账成决策视图→专用 agent 只据此出下一步→到期再压一轮，前缀持续命中；短任务不触发压缩。

## 七、具体实现方案
①双视图隔离：原始账本只追加不重写，决策视图每轮重建；②稳定前缀跨轮复用，只对新后缀计费并登记命中率；③指针恢复执行关键记录、按路径聚合工件写入顺序，不交给模型复述；④来源标记区分观察与推断，无源显式标注；⑤失败台账保留最近 40 条；⑥验收六账：输入降幅、端到端成本、命中率、关键信息召回、重复动作、回本步数。

## 本期新观点
1. **记忆税要记"谁付钱"与回本点**（接 #5、#137，深化 #147）——专用 agent 无缓存折扣时全价重付重复历史；压缩不只看比例，须记压缩器未缓存 token、命中率、每次成功成本与第 16 步回本／第 50 步净省 25%。
2. **原始轨迹只追加不是保守，而是缓存经济学**（反转"压缩即重写摘要更省"，接 #133／#146）——字节不变前缀令命中率逐轮升到 96%，递归摘要恒为零命中；留全史与低费用首次同时成立。
3. **同一轨迹两个视图、两种读者**（接 #141／#142／#147 划界）——全史整合与动作生成的上下文需求相反，新增"视图—角色"分配轴；专用模型即使不看全史仍是动作质量必要条件（67.9%→78.2%）。
4. **执行关键信息须确定性恢复，不能靠模型复述**（接 #138 回执、#140 失败反噬）——指针逐字取回工具输出，损坏率 0.33%→0.01%、重复动作 29→6，信息完整性是独立于语义保真的新验收维度。
5. **压缩收益是轨迹长度与定价的条件函数**（深化 #131／#135／#143）——压一次反贵 10.7%、压两次才省，缓存价低于未缓存价 9.1% 时优势归零，故禁止默认开启压缩。
6. **产业对照须逐家分列**：五项目无新主线版本；ReMe 已有可恢复压缩提案、TencentDB 明确拒绝不可逆有损摘要，但都无双模型分工、缓存命中账与确定性指针恢复，AML 补 cache-aware-compression 维度。
