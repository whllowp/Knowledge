# AI-SRE 技术洞察 · 第 161 期（2026-11-13 00:00）· 人机信任校准面（Human–Agent Trust Calibration）

> **题眼**：Agent 的可靠性是一个数字，人对 Agent 的信任却是一种感觉。SRE Agent 把"能不能自治"做成了 L0–L4 分级，却没人度量"人对 Agent 的信任有没有被校准过"——盲信（automation bias）让错误无人质疑地通过，盲拒则让 Agent 形同虚设。本期把"人机信任校准"立为一等运维对象：当 Agent 说"修这个"，人是不是信对了分量？

## 一、发展趋势

2026 年 SRE Agent 的竞争焦点正从"能力"转向"信任治理"。NIST AI RMF、EU AI Act、五眼（2026）已把 human–AI oversight 写成合规条款；FinSec（Dr Takyi, 2026）进一步提出"信任是必须被运营化的风险变量，而非文化属性"。研究共识高度一致：**trust must be calibrated, not maximized**（NIST 2023）——过度信任与过度不信任同样有害。

自治分级成为标配：Google Actus L0–L4、OpenAI 乐观执行+guardrails、Anthropic 权限分层。但分级是"给系统用的"，信任校准是"给人用的"，两者长期脱节。最近 30 天的关键信号：Aurora SRE 主张交接载荷必须含"what I ruled out"（被排除的假设）；IntelliSee 2026 框架把"演练驳回（drill the dismissal）"作为反自动化偏见的训练手段；Anthropic 2 月研究量化了 Agent 自己停下来的 5 类原因（50 万次中断样本），证明"会停"不等于"停在对的地方"。

## 二、技术现状

主流做法分三派。**触发式**：OpenAI 两类干预触发（失败阈值 / 高风险不可逆动作）+ 工具风险评级（low/med/high）；Anthropic Claude Code 手动模式 fail-closed、信任对话框。**状态式**：Google 基于系统状态降级——风险分或异常态强制 L3→L2，而非依赖模型自报置信度。**分层确认式**：阿里 STAROps 分级执行（低风险自动 / 关键人工确认 / 禁止强制拦）、执行前校正策略与权限；腾讯 CloudQ 人授权下执行、受控执行 + 经验复用；字节智能运维助手叠加 SOP 知识库与对话记忆，安全运营智能体把事件分为"AI 确定 / 需你认知 / 已闭环不打扰"三级。

**交接载荷缺口**是普遍软肋：Google 要求记录 chain-of-thought、信号、假设、置信度与**被排除选项**（rejected-options，全行业独有）；其余厂商多只给自然语言摘要 + 链接，置信度与 excluded hypotheses 缺失或埋在推理链里——凌晨 3 点没人读。更根本的问题是：**"置信度 < 0.7 就升级"是建在一个你无法信任的数字上的阈值**（Aurora）。Anthropic 研究发现，推理模型仅 25%–39% 提及真正驱动答案的线索，自报置信度天然不可靠。

**本地原型（第 69 期）**：周昕毅（携程 AISRE）提出"升级三条件：真实效果可评测｜执行风险可控制｜责任边界可追溯"，是全库最早把"何时信任 Agent 自治"写成生产准入闸门的实践，与第 159 期确定性笼子、第 160 期命名根因取证共组"信任三件套"。

## 四、技术挑战

- **盲信（automation bias）**：自信标签→人盲签；Aurora 指出"被交付的错误结论会锚定疲惫工程师，资历救不了它"。上升的自动确认率 + 下降的验证时长，正是盲信坐实的信号。
- **盲拒（under-trust）**：早期一次错误后全员手改流程、覆盖模型无记录→ROI 流失、知识污染。
- **置信度不可信**：自报置信度 ≠ 真实后验，阈值法失效；"升级当置信 < 0.7"是建在沙上的闸。
- **交接载荷缺失**：凌晨只看到结论，无证据、无疑被排除项→要么盲信要么盲拒。
- **信任转移（trust transfer）**：对厂商/品牌的信任错误投射到其 Agent 的每一次输出。
- **信任修复缺失**：Agent 出错后无透明故障报告 + 根因 + 改进，信任崩塌不可逆。
- **评测盲区**：Incident-Arena / SREGym 只考 Agent 不考"人对 Agent 的盲信率"；多智能体信任层级（agent 该不该信另一 agent 的指令、权威冒充）未覆盖。
- **第 111 个市场空白五项**（盲信率/盲拒率/每操作员分歧/确认-驳回比/信任校准达标率）；字段族 `trust.calib.*`（override_rate/dismissal_rate/blind_accept_rate/blind_reject_rate/per_operator_divergence/trust_calibrated_flag/review_evidence_first）**第 78 次无人提字段族**。

## 五、展望与建议

1. **字段 schema**：`trust.calib.*` 七字段（override_rate / dismissal_rate / blind_accept_rate / blind_reject_rate / per_operator_divergence / trust_calibrated_flag / review_evidence_first），纳入 OTel GenAI 约定提案。
2. **证据优先展示（evidence-first）**：交接载荷先亮标注证据框而非文字结论——人先看边界框再读标签是在验证，先读"已检测"再点确认是在橡皮图章。
3. **演练驳回而非只演练确认**：季度化用良性场景演练"高质量驳回"，校准信任双向。
4. **审计回路而非只审计模型**：confirmation/dismissal 率、override 频次、per-operator 分歧；自动确认率升 + 验证时长降 = 盲信告警。
5. **升级锚点用系统状态而非自信度**（Google 式）：风险分/异常态强制降 L2，绕开不可信的置信度。
6. **交接载荷标准化**：必含 rejected-options + CoT + signals + confidence + evidence（深化第 135/160 期）。
7. **渐进式部署（graduated deployment）**：Autonomy earned, not granted；低利害起步，表现稳再扩权；随机抽检已执行决策保持对真实错误率校准。
8. **信任修复机制**：透明故障报告 + 根因 + 改进，防信任不可逆崩塌；评测扩展（Incident-Arena/SREGym 增盲信率维度）；信通院六维补"信任校准达标率"格。
