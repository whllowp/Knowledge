# AI-SRE 技术洞察（第 294 期）

**生成时间：2026-11-20 04:00｜主题立面：证据保真度面／"读到的都是真的，结论却是错的"（Evidence Fidelity / Plausible-but-Wrong）**

> **题眼**：过去我们问"证据有没有送到"（#290）、"动作是不是真救了系统"（#292）、"跑通的成功是不是真成功"（#293）。本期问一个更靠前、更少被问的问题——**Agent 读到的每一条数据都合规、都真实、查询结果都合理，为什么结论仍然是错的？** OllyGarden 与 Causely 11 月 2 日的联合文章给出一句可推广全领域的判词：**最危险的遥测是"格式正确"的遥测（The most dangerous telemetry is well-formed telemetry）**。它能过 schema、能过异常检测、能返回像样的空结果，恰恰因此骗过了"快速而字面"的 Agent。证据保真度不是"数据好不好"，而是"这份数据是否真的说了它声称发生的事"。

本期与既有立面划界：静默面（#285）问系统安静是不是真没事、证据通道面（#290）问证据有没有送到决策者、干预信用面（#292）问动作与好转是否因果、语义回归面（#293）问产出的成功是否符合领域意图——四者分别在系统层、通路层、动作层、结果语义层；本期只在**输入证据层**发问：Agent 赖以推理的事实本身，值不值得信。经查重，"证据保真／遥测保真／因果保真／时间泄漏／独立信号／证据污染／状态污染"两处索引均为 0（"因果图"9 处、"反事实"19 处属旧期语境），全新立面确认。

## 一、发展趋势

**其一，可观测性的敌人从"坏数据"变成"好数据里的谎言"。** OllyGarden 在 2026 年 7—10 月抽样多家组织的 OpenTelemetry 数据，把失真分成三类：静默缺失、字段矛盾、词汇分裂。一个 Agent 被问"支付服务过去一小时有无问题"，按 ERROR 级别查日志得到空结果，于是报告"健康"——查询完全正确，因为 severity 只写在消息文本 `level=ERROR msg="executor failed"` 里，结构化字段为空。人翻原始日志会看到 ERROR，字面上高速执行的 Agent 没有理由再回头看。**结论**：数据质量的主战场已从"日志风暴、密码泄露"这类自曝式问题，转向"格式合规却不说真相"的隐形问题。

**其二，"因果上下文"成为可采购的独立一层。** Causely 在 OpenTelemetry Astronomy Shop 上的实验显示：同一故障，Agent 不带因果上下文时正确回答因果问题 75%、每次调查 19 次工具调用、30.8 万 token、73 秒；接上因果 MCP 后变为 100%、4 次、12.3 万 token、25 秒，健康集群误报事故从 12 次里 4 次降到 1 次。关键不是模型变聪明，而是"从告警向外搜到一个能解释的依赖重启就收手"的启发式被因果图替换。趋势是：**归因从 Agent 的推理副产品，独立为可查询、可审计的外挂事实层**。

**其三，训练侧开始堵"证据时间泄漏"。** ResolveAI 11 月 18 日发布的 SRE-1（27B、纯 RL 后训练）有一条被低估的设计：**训练时每个工具都被钉在告警触发的那一刻，模型不能读到之后提交里的修复**。这与 #293 "根因须锚定出错时的不可变快照"同源，但把防线前移到了训练数据管线——若训练证据里混入了"未来"，模型学到的是事后诸葛亮式的伪因果。领域专用模型的价值主张也由此清晰：生产知识无法从互联网抓取，必须从"当时的证据"里学。

## 二、技术现状

证据保真度目前散落在四类能力里，尚无一族统一字段。

**读前体检（数据是否说了它该说的）。** OllyGarden 九项清单的前五项可本周直接对遥测跑：错误 span 中有多少带 status message 或 exception event（抽样组织 38%–96% 带错误状态的 span 两者皆无，多数超 90%）；哪些服务上报 `unknown_service` 或无 `service.name`；单 span trace 占比（各组织 59%–100%，某服务 5 分钟内 140 万条 trace 中 99.9% 是单 span，通常指向网关/队列/线程池处上下文传播断裂）；同一概念多少种属性名（某组织 125 个服务用 `http.method`、16 个用 `http.request.method`，按新规范写查询只看得到约八分之一）；日志 severity 与 body 是否一致（多数组织约四分之一到四分之三"看起来像错误"的日志被记为 INFO/DEBUG/空）。

**因果校验（clean data 仍会骗人）。** 退款 worker 报 p99 延迟 20 秒，其实是队列 5 秒轮询间隔的等待时间；一条看似起于 ledger consumer 的 trace，根 span 仍引用 parent，因为上游 producer 从未导出 span。两者数值都准确、任何质量检查都不会报——**读懂它们需要知道系统怎么拼起来，而非字段对不对**。Causely 清单后四项问的是 Agent 的产出：最近 10 个可靠性 PR 里有几个改的是"告警的那个服务"而非"致因的那个服务"，Agent 能否说出它排除了哪些备选，证据在时间上是否对得上（一个在错误开始前就结束的重启解释不了错误），修复合入后原告警多久没清。

**平台侧事实供给。** 阿里云 AgenticOps（11-11）的 Cloud Monitor 2.0 把"标准化→组织→可信"做成流水线，声称把原始遥测转成带来源、新鲜度、语义、质量、成本边界的"生产事实"，UModel 用 EntitySet / LogSet / MetricSet / RunbookSet 围绕故障对象组织上下文；配套 BRiSE 数据集的故障诊断级 764 个 case、150+ 类故障、20+ 云产品，每个 case 记故障环境、Ground Truth、证据链、过程评分器。腾讯云 CloudQ（10-29/30）以全景图谱组织资源、关系、状态、动作，主张"用 AI 管运维、用可观测管 AI"。

**隐私护栏制造"合法空洞"。** Google 11-13 把 Agent trace/会话日志/token 计数/评测结果落进客户自有 BigQuery `agent_events` 表：RLS、policy tag、动态脱敏的数据源会触发 fail-closed 的按轮检查从而**跳过该轮日志**，而执行 fail-open、对话照常。于是表里缺一轮可能是策略结果而非 bug——这与 OllyGarden 的"静默缺失"同形，但成因是刻意设计。**当最该被审计的数据恰因受保护而不留痕，保真度与保密性正面冲突。**

**本期反转**：把"统一采集、全景图谱、因果图、OTel 全链路、引用式结论"做成发布页卖点的是七家厂商；把"空结果不许当健康、错误 span 有多少没带理由、Agent 改的是告警服务还是致因服务、受保护数据缺轮是否声明成不可审计"做成可导出字段的，几乎没有一家做全。**新观点：看得见数据 ≠ 数据说了真相——前者是采集问题，后者是保真问题；把两者混为一谈，正是"遥测覆盖率 100% 却反复误诊"的根因。**

**本地原型（第 170 期新角度）**：刘凯宁《蚂蚁 SRE 基于 Agent 的应急根因定位实践与踩坑》中"结论／证据／待确认三分"本期扩出第八分——"这条证据本身可信吗"。配蒋烁淼"千亿数据秒查到真正 AgentOps"重读为"秒查的前提是查得到的是真的"；配何伟 Harness"生成与验证分离"外延到"证据进入推理前先过验证闸门"。

## 四、技术挑战

**其一，失真不可观测。** 格式正确的遥测不会触发任何异常检测，Agent 也没有"我看到的可能不是全部"的元认知。静默缺失只有拿"应该有"去对账才能发现，而"应该有"本身需要系统知识。

**其二，证据时间对齐是硬活。** 错误 span 带 reason 的比例、重启与错误的先后、训练工具是否钉在告警时刻——都要求跨系统统一时间锚与不可变快照，工程成本高且易被"当前 HEAD"污染。

**其三，保真与保密冲突。** Google 的按轮 fail-closed 让敏感数据天然缺日志；缺轮是策略还是故障，若不在证据里声明，审计者无从分辨——"没记录"与"没发生"再度同形（呼应 #286）。

**其四，评测口径自证。** ResolveAI 全部数字来自自测；Edge Delta AI SRE Arena 既是出题人又是参赛者（21 个故障、自评 18 场景自主调查、根因 11 vs Grafana 9）；Causely 样本量小。行业缺中立、可复现的保真度基准。

**其五，责任边界未定。** Causely 场景中 PR 改错服务、评审照批、修复合入而交易继续失败——"修复已交付"在流程上被记为闭环，保真度错误却永久隐身。

## 五、展望与建议

提出第 215 个空白字段族 `evidence.fidelity.*`：`fidelity_checked_at`／`silent_absence{error_span_without_reason_ratio, missing_service_name[], single_span_ratio}`／`contradiction{severity_body_mismatch_ratio, status_field_disagree[]}`／`vocabulary{attribute_name_variants, severity_spellings}`／`causal_check{changed_service_vs_cause, alternatives_ruled_out[], evidence_time_aligned}`／`empty_result_policy=NOT_HEALTHY`；缺省 `FIDELITY_UNVERIFIED`——未声明保真度的自治流程不得进 write≥act、不得据空结果出"健康"结论。与 #289 分工、#290 通路、#291 记忆、#292 信用、#293 语义并列，构成六层治理的最前一层。

具体建议：① 把 OllyGarden 九项清单固化为每周对账任务，前五项进 Dashboard、后四项进 PR 模板；② Agent 查询层加"空结果护栏"——空结果默认返回"未知/需人工"而非"健康"，并回显查询覆盖率与词汇命中面；③ 采购三问：能否导出"错误 span 带理由比例"、能否说明改的是告警服务还是致因服务、受保护数据缺轮是否声明为不可审计；④ 评测增设"保真度"维度，用 seeded 失真（抹掉 severity 字段、断上下文传播、注入冲突属性、错序时间）测 Agent 是否仍给出自信错误，报"识破率/假健康率"；⑤ 训练侧强制"证据钉时"，禁读告警之后的提交与工单；⑥ 信通院六维"结果可评价"补「证据保真可举证率」格。
