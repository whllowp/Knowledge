# AI-SRE 技术洞察（第 296 期）

**生成时间**：2026-11-20 06:30（Asia/Shanghai）
**观察窗口**：2026 年全年，重点最近 30 天（10-21 至 11-20）
**本期主题**：底座漂移面／"你调用的模型和实际服务你的模型，是同一个吗？"（Substrate Drift / Requested-vs-Served Model Divergence）

## 题眼

2026 年 11 月 1 日，Codex 付费用户在账单里发现一行从未配置过的模型标识 `gpt-6.2-astra`，吃掉约 19.8% 调用量，而前端选择器仍显示 GPT-6 Astra；抓包显示 API 的 `model` 字段早已改名。OpenAI 直到 11 月 17 日才正式发布它——"账单比公告诚实"（Kie.ai、DoitNews，2026-11）。

同期 Google 侧：`gemini-3.7-flash` 弃用后请求不报错，被静默重定向到 `3.8-flash`；两个模型页的 token 上限、思考档位、工具支持完全相同，变的只有权重。一名跑视频转写的开发者发现约 20 条样本严重退化：22 分钟视频压成 3 条对话、30 分钟播客返回 0 输出 token（Gloss.run，2026-11）；`gemini-2.5-pro/flash` 也将在 12 月 1 日同样自动路由。Anthropic 则在 11 月 9 日被 Hacker News 公开要求停止"未公告的中途变更"，Opus 5.5 被指从 11 月 3 日起漏步、工具调用吃力，归因未定（PromptInsights，2026-11）。

三件事指向同一个被忽略的对象：**SRE Agent 的推理底座不是常量，而是供应商在网关层单方面持有的变量**。前 295 期建立的证据-通路-分工-记忆-信用-置信各层治理，都隐含假设"模型是固定的那一层"；本期把这个假设本身立为一等对象——你为 Agent 审计了代码快照、固定了提示词、记录了工具调用，却很可能没记录"此刻究竟是哪一个模型在替你思考"。

## 一、发展趋势

1. **切换决策离开用户手中**。传统下线给固定日期并报错（硬关停），新兴的"弃用即重定向"不报错、账单照走、输出变化——从"有失败可反应"变成"无失败可反应"。Google 两个入口对同一 ID 给出不同退役日期与路由策略，同一份代码在两条路径上已不是同一模型。

2. **三种静默机制被识别**：网关金丝雀灰度（同账号 1.6%～19.8% 分流）、别名自动重路由、规格隐形降级（命中蒸馏/量化/轻量池，延迟双峰化，计费按高档位）。百度开发者总结其可观测特征为"方差变大、明显变省、风格漂移、延迟双峰"（2026-11）。

3. **独立每日基准从诉求变成小产业**。is-my-model-drifting.com 用冻结的确定性评分集对 17 个线上模型定期跑分、精确匹配、拒绝 LLM-as-judge；11 月 15 日快照显示 Claude Sonnet 5 −3.4 pts、Grok 4.3 −2.9 pts 被判回归。

4. **评测界开始反思：分母在动**。Columbia 预印本（arXiv:2611.17239，11-12）证明用户观察到模型输出后会自适应调整提示难度，离线榜单与线上 A/B 测的是两个估计量，甚至排序反转。对 SRE Agent 的含义是：底座变更后，历史基线可能既非"变差"也非"变好"，而是题目分布被改写。

## 二、技术现状

**标识面**：唯一可靠信号是响应对象回显的 `model`/`modelVersion`；请求 ID 与服务 ID 不一致即一次可打时间戳的事件。Belgavi 的厂商中立包装器逐次记录 requested/served，不一致即告警，strict 模式直接让调用失败而非接受重路由响应。

**探测面**：多数评测是"冒烟测试"（能用吗），底座漂移需要"回归测试"（这个具体东西变了吗）。KubeLabs 指出三个统计陷阱：互补抵消、切片稀释（5% 切片掉 20 分总分只掉 1 分）、阈值效应。最小门槛是逐例 diff、切片报告、固定基线、CI 门禁。is-my-model-drifting 另有反向教训——"4 次告警 0 次真回归"，2 次来自失败调用，分数变化源于分母，探测器自己也需要 detection floor。

**审计面**：腾讯云给出链式字段——请求 ID→租户→路由版本→模型标识（若可获取）→提示词/RAG 版本→工具执行→结果；**版本不可得时只记录请求时间、响应头、网关配置与实验标识，不得声称识别出了隐藏模型**（2026-11-10）。这条"不得声称"是本期核心纪律：看不见就是看不见，不能拿配置里的字符串冒充事实。

**切换面**：阿里 Qwen4-Max 与腾讯 Hy4 flash 于 11 月 16 日同日上线，社区总结"换底座五闸门"：兼容契约、轨迹回放、上下文与成本预算、影子评测、灰度回退；警告是"接口兼容只保证请求发得出去，不保证行为不变"，可能让 Agent 在第 7 步才出错且"看起来很合理"。火山 AgentKit 于 11 月 13 日切换到自研新版评测并在运维助手加入 RCA Harness 约束层，但两处都没解决"被评测的模型本身是谁"。

**基准面**：SREGym 被 NeurIPS 2026 收录，11 月 5 日 Radar+Claude Code 以 95.2% E2E 登顶（Opus 5.5）；但分数全锚在具体模型上，静默变化会让历史分数变成"历史文档"。ITBench-AA 47%、OpenRCA 2.0 精确根因集 20.7%，跨期比较的效度同样依赖"模型固定"这一未声明前提。

## 三、技术竞争力（主要厂商/方案对比）

| 厂商/方案 | 请求ID vs 服务ID | 钉版本能力 | 静默更换机制 | 基线失效防护 | 对 SRE Agent 的风险 |
|---|---|---|---|---|---|
| OpenAI（Codex/GPT-6.2 Astra） | 响应 `model` 暴露真实 ID；前端仍显旧名；账单先于公告 | 具体版本可用；别名与灰度由网关决定 | 金丝雀 A/B，1.6%～19.8%，个别 100% | 无中途变更通知；需自建 golden-set | 越权边界随权重改变，自愈动作在"无变更单"下变形 |
| Google（Gemini API） | 弃用 ID 自动路由不显性通知；须主动查元数据 | 建议固定显式 ID，但 stable≠pin | 3.7→3.8、2.5pro→3.8flash 静默重定向 | 官方要求重新 baseline；Vertex 与 API 日期不同 | 同代码跨入口行为分叉；长上下文退化最难察觉 |
| Google（Vertex AI） | 固定退役日期（≥45 天通知） | 明确升级路径 | 固定日期关停，非静默 | 生命周期文档可查 | 有日期可反应，跨入口混用仍踩 API 侧路由 |
| Anthropic（Claude/Opus 5.5） | 状态页有时间线；能力变化无版本记录 | 具体版本可用，浮动别名是风险面 | 被指控 mid-cycle 变更；量化/A-B 归因未定论 | 建议 golden-set、记 model 元数据、当事故处理 | 多步 Agent 首步格式微变级联成整链失败 |
| 阿里云百炼（Qwen4-Max） | 更新日志称兼容两接口，未承诺行为一致 | 需接入点显式选版本 | 版本迭代的行为漂移（拒答/截断/解码默认值） | 五闸门为社区实践，非平台强制 | 长程任务在"合理"的第 7 步出错 |
| 腾讯云（Hy4 flash/CloudQ） | 给出"请求ID→租户→路由版本→模型标识（若可获取）"链 | 1%→10%→50% 灰度，保留回退 | 主模型超时后重试备用，或致重复副作用 | 明确"不可得时不得声称识别"；失败分三类 | 模型问题与重试问题混淆，非幂等工具重复执行 |
| 火山引擎（AgentKit/运维助手） | 全链路 Trace 覆盖输入/推理/工具/输出 | 接入点版本平滑切换与按比例回切 | 11-13 评测版本整体切换；迁移≤1 小时 | 迁移前评测提示、RCA Harness、结论有置信度 | 能证明"评测在跑"，未证明"被评测模型没换" |
| 独立探测（is-my-model-drifting） | 冻结集测线上模型，逐次记录分数与 Δ | 不控版本，只观察变化 | 专测静默更新 | 精确匹配无 LLM-as-judge；自处 detection floor | 外部哨兵，不进生产决策链，告警未联动事故 |

**本期反转**：五闸门、逐例 diff、钉版本、影子评测、灰度回退、独立跑分——各家都能找到；但"把被评测模型身份当一等证据字段、把 requested≠served 当事故记录、把评测基线绑到 served ID 而非配置字符串"三件事，没有一家做成默认。判词：**看得见调用链 ≠ 看得见是谁在推理；前者是遥测问题，后者是地基问题。** 与第 295 期划界：那期问"它说它多确定，和实际多确定是一回事吗"（元认知层），本期问"它说它是哪个模型，和实际是哪个是一回事吗"（更前置的地基层）——地基漂移会让元认知校准曲线整条作废。

## 四、技术挑战

1. **可见性不对称**。网关灰度是供应商内部实现，用户侧最多看一个字符串，有的路径不回显；当"看不见"是默认，任何基于"配置里写的是谁"的审计都是自证。
2. **验证时滞与成本**。黄金集要 20～50 条代表性提示按日/周跑，高风险任务重复看分布；但底座可随时切，探测频率永远追不上，且分流按账号而异——你的探测账号可能根本不在灰度池。
3. **告警信噪比**。"4 次告警 0 次真回归"说明失败调用、覆盖数变化都造假信号；把这些噪声接入自愈链，等于给不稳定系统再加正反馈环。
4. **责任稀释**。"静默换模型会稀释 SLA 责任"——用户、集成商、模型商都能说"我没改"；未知权重下产生重复副作用，谁签事故单无成熟契约。
5. **基准可比性危机**。模型固定是所有榜单的隐含前提，正被静默重路由打破，跨期分数不可比使平台选型失去证据基础。

## 五、展望与建议

1. **新增第 217 字段族 `substrate.provenance.*`**：`requested_model_id`／`served_model_id`（取自响应元数据）／`divergence{detected_at,mechanism∈canary|reroute|tier_downgrade|unknown}`／`benchmark_baseline{served_id,captured_at,detection_floor}`／`eval_validity∈VALID|STALE|UNKNOWN`，缺省 **SUBSTRATE_UNVERIFIED**。未声明底座身份的自治流程不得进 write≥act 档，结论不得写入语义记忆或作为干预信用结算依据。
2. **把 requested≠served 做成一等事故事件**：包装每次调用逐次记录三者，首次不一致即打时间戳、冻结当期基线、触发 golden-set 回归；高风险 strict 模式下让调用失败。沿用第 290 期纪律：**不回显就写 UNKNOWN，不写"未发现异常"。**
3. **采购第五问**（与前四问并列）：每次评测与每次自愈动作，能否导出当时实际 serving 的 model ID 及它与配置字符串的差异记录？
4. **评测升级**：所有榜单与内部基准补"serving-fingerprint"列，跨期比较先校验指纹；增 seeded 底座变更题（新旧权重双跑，报工具调用/拒答/JSON 字段差异）；把"该报底座变了却没报"计入正确弃权率（联动第 295 期）。
5. **流程前置**：把五闸门写进变更管理而非选型文档；高风险冻结候选或人工复核；1%→10%→50% 灰度不与高峰、提示词升级叠加；把替代模型自己的退役日期写进日历。
6. **标准补格**：信通院"结果可评价"补「底座可举证率」——能否说出每次结论背后实际 serving 的模型 ID，与证据保真、置信可举证并列，形成"证据-通路-分工-记忆-信用-语义-置信-底座"八层治理。

**本地沉淀（第 172 期新角度）**：陶炳哲《智能路由不只是选模型》过去多被读成成本话题，本期重读其核心命题——"路由决策本身即运行时变量"，首次作为底座漂移面主线注脚；配赵恒"字段要有权威来源"扩到"模型 ID 也要有权威来源（响应元数据而非配置）"；配刘凯宁蚂蚁 SRE"结论/证据/待确认三分"扩出第十一分"这个结论是哪个模型给出的、与请求的是否同一个"。
