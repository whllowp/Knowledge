# 记忆技术洞察 · 第 35 期（2026-11-08 17:00）

> 本期主线：**记忆的观测面——指标写在论文里，面板长在性能侧**
> 前 34 期逐层拆预设，第 27 期讲的"GUI 可视≠可治理"是**给人看的展示层**；本期换到**给 SRE 看的遥测层**，追问更基础的问题：记忆运行得好不好，究竟有没有人能量出来。结论是量不出来——**指标的定义权在论文与榜单手里，面板的实现权在 APM 社区手里，两者至今没有交集。**
> 范围：2026 年，重点为 10 月中至 11 月 8 日新增内容。

---

## 一、发展趋势

**趋势一：记忆层成了"最后一个未被观测的层"，说出这句话的是记忆厂商自己。** MemoryLake 于 11 月直言：APM 能看见模型调用，OTel 能看见工具调用，"记忆一直是黑盒"，于是把 per-retrieval 指标、OTel 兼容 trace、读写访问日志、记忆健康面板做成开箱能力。同期行业词汇成型——Inferensys 术语表已收录 "Memory Dashboard"，把延迟 p50/p95/p99、缓存命中率、空结果率、嵌入漂移、驱逐日志、schema 变更历史列为标准面板项。观测第一次从"论文里的表"变成"产品里的页"。

**趋势二：通用 Agent 观测指南已把"记忆状态监控"列为 2026 必选项。** 各类指南普遍列出四项：新鲜度、嵌入漂移、检索准确率、跨 agent 冲突。这四项与第 11 期（时效）、第 13 期（搬迁）、第 20 期（读法）、第 12 期（共享）四条主线一一对应——前 34 期从故障里推出来的缺口，正被运维社区以"最佳实践清单"独立复现，两条路径互不引用却指向同一张表。

**趋势三：失效研究从"检测"转向"传播"。** 10 月 5 日 PACMI（arXiv 2610.05732）用带类型依赖边的溯源图 + 四态有效性格（有效／继承有效／待核／作废），新证据到达时沿边**级联作废**，并保留历史证据用于"过期前提侦测"；arXiv 2608.10502 把"故障记忆已被消费之后"定义为独立问题——不是删除，而是**依赖引导的回滚修复**：删源、隔离无独立证据的下游派生状态、只重放答案相关路径。记忆研究由此开始产出**可计量的运维量**：爆炸半径、传播深度、残留复发率。

**趋势四：产品先长出"背压"，不是"仪表"。** MemHub v1.0.6 本次重点是"写入自动重试、模型异常暂停排队、可安全切换嵌入模型、lite/pro/ultra 三档（ultra 每晚自动整理）"；TencentDB 有 MemoryPanel 与 v2→v3 迁移；ReMe 有 `ReMe Status`。行业用"重试／排队／暂停"这类**控制面动作**替代"阈值／报警／看板"——因为前者不必先定义什么叫"健康"。

## 二、技术现状

### 2.1 已有面板的指标，全是数据库的形状

把 MemoryLake、Inferensys、观测指南三张清单求并集：延迟分位、吞吐、命中率、错误率、并发、增长趋势、驱逐记录、top 查询、相似度分布、空结果率、嵌入漂移。这是一张**向量数据库的 APM 面板**，几乎没有一项回答"记忆是否正确"。

原因清楚：这些量都能在 API 边界采样，不需理解语义。而第 29 期证明"账实分离"、第 33 期证明"收益只在前 25%"、第 31 期证明"干扰型丢失无写入口"——三类最致命的问题**在 API 边界上不产生异常事件**，对面板天然透明。**第一代可观测性产品复刻的是最容易采集的东西，而不是最需要知道的东西。**

### 2.2 唯一能补语义的是依赖图，它顺带解决了爆炸半径

PACMI 的关键不是又一个遗忘策略，而是把记忆从**点集**变成**图**：根状态改变即沿边级联。四态格的设计要点是"作废≠销毁"——被推翻的记忆降级为历史证据，仍可支撑"过期前提侦测"。这与第 2 期墓碑、第 29 期冲销是同一路线的第三段：**墓碑说"这条死了"，依赖边说"谁跟着死"**。

其自报数字值得单独看：移除级联后最终答案错误从 3 升到 11，但配对差异未过 0.05 显著门槛。即级联在**答案层**收益不显著，主要收益在**记忆状态正确性**。这恰好定义了观测的定位——级联先修账本，不先修回答；只看准确率会得出"级联无用"的错误结论。

### 2.3 回滚修复揭开运维最不该缺的数：复发率

2608.10502 构造 typed memory-to-action 图，从故障记忆追踪下游数据流，逐条判断"是否有独立可信证据支撑"——有则保留、无则隔离，再只重放答案相关计算。在 150 例受控用例 + 50 条 LongMemEval-V2 改编轨迹上，其**即时恢复率最高、成本低于 LLM-judge 修复**，但作者诚实披露：**残留复发率 26.6%，高于 LLM-judge 的 12.1%**。

这个自曝数比成绩更有价值：**"已修复"与"不再犯"是两个量，且可反向**——局部精准修成本低、复发高；全局重算成本高、复发低。而今天没有一块面板同时报这两个数。第 23 期说"更新是重构，只是没人写测试"；本期补一句：**连"修完多久又坏"都没有字段可落。**

### 2.4 六项目现状：观测能力分档清楚

- **OpenViking**：约 41.6k★、2000 commits／200 issues／450 PRs，可观测能力是**检索轨迹可视化**（回答"为何召回这条"），不回答"库是否健康"。
- **TencentDB-Agent-Memory**：29.9k★，已有独立 `MemoryPanel` 目录、v2→v3 迁移、MongoDB 实验后端、DeepSeek Harness 接入；面板偏"资产与权限"，与第 12 期信任半径同轴。
- **Hy-Memory / MemHub**：v1.0.6（11 月），11 语言、三档模式、底层 hy-memory 2.0.14、30B-A3B 的 FP8/GGUF 已上 HF。新增的是**韧性语义**，非健康指标。
- **ReMe**：v0.4.2.1，新增 Qoder 插件（10-29）、决策模型驱动的上下文压缩（14 查询定长摘要 Top-N 基准 + 强基线对照）、Studio 浏览器沙盒；`ReMe Status` 是最小状态出口。
- **dsh-memory-evolve**：645★／71 fork／MIT／37 open issues，末次 push 10-29；`reviewEnabled` 每 10 回合审查一次（默认关），自带记忆同步的推送与冲突三选。
- **命名风险**：`dsh-memory-evolve` 至少对应两个包（csyangwen 版与 azure5100/huahua 版，后者 README 亦自称此名）。**当观测连"装的是哪个构建"都分不清，供应链层的可观测性已经先失效。**

### 2.5 AML 二期：剖面第一次比总分有信息量

Cycle 2 已于 11 月 4 日关闭正式评测，官方榜单预计 11 月中发布。题库较一期扩大：文本轨 6,000+ 实例／32 数据源／约 3 亿 token，代码轨 300 实例／18 亿 token，多模态轨近 5,000 实例／7 数据源。七维剖面已可见：MemoraX 58.02（H 58.39，G 仅 29.99）；MemOS 45.89 而 **G 仅 9.82**；Cognee 42.61（G 27.11）；TencentDB 41.48（G 28.66／H 34.84）。**同一维极差 9.82–58.51，近 6 倍**——这是"面板该长什么样"的现成答案：不是一根总分柱，是一排剖面柱。

## 三、技术竞争力

本期不按"记忆能力"排，改按**可观测性供给**排。七列对应运维真正会问的七个问题。

| 方案 | 遥测出口 | 记忆专属指标 | 变更事件可见性 | 爆炸半径 | 复发率 | 口径披露 |
|---|---|---|---|---|---|---|
| MemoryLake | OTel 原生 + Datadog 等 APM | 有（延迟/命中/增长/驱逐/带来源访问日志） | 仅 API 读写，离线整理不可见 | 无 | 无 | 指标定义未公开 |
| APM 组合（LangSmith／Helicone／Arize Phoenix） | 原生 trace | 弱（漂移与检索评估需自建） | 无 | 无 | 无 | 工具侧，无记忆口径 |
| TencentDB MemoryPanel | 自有面板 + 资产权限视图 | 部分（资产、权限、团队） | 有资产级，无逐条 | 无 | 无 | 路线图公开，指标未定 |
| MemHub（Hy-Memory） | 桌面 GUI + CLI | 弱（档位、整理日志） | 有（夜间整理零 changelog） | 无 | 无 | 中，发布说明详细 |
| OpenViking | 检索轨迹可视化 | 有（轨迹级：为何召回） | 会话压缩可见，写入不可见 | 无 | 无 | 论文与文档齐全 |
| Hindsight Inspector（社区） | 自建 UI + 分段时延 | 有（召回→推理→留存） | 可开关记忆做对照实验 | 无 | 无 | 示例代码级 |
| ReMe | `ReMe Status` + Markdown diff | 弱（文件级可 diff） | **强**（记忆即文件，全量可审） | 人工 | 无 | 高，基准与设计公开 |
| dsh-memory-evolve | 日志 + 会话评审 + 同步冲突 | 弱（审查间隔可配） | 中（每 10 回合审查） | 无 | 无 | 中 |
| AML 榜（外部基准） | 无（离线评测） | **强**（七维剖面含治理维） | 无 | 无 | 无 | 高（数据版本锁定） |

三条判读：

**其一，观测与语义被拆给了不同的人。** MemoryLake 有出口没语义，AML 有语义没出口，ReMe 有可审计性没指标。**没有一家同时做到"有出口 + 有语义"**，而这两件事的组合恰是运维的全部内容。

**其二，爆炸半径整列空白。** 九行八"无"，只有 ReMe 靠"记忆即文件"让人工去算。PACMI 已做出依赖边，但它是论文不是产品；于是**厂商连"这次污染波及几条下游"都报不出**，事故复盘退化为"清库重来"。

**其三，复发率为零不是疏忽而是激励。** 报复发率等于承认修不干净。唯一披露者仍是论文（26.6% vs 12.1%）。这与第 24 期"精度-库容曲线零披露"、第 30 期"利用率无人记账"同构：**凡会暴露能力上限的指标，一律不进面板。**

## 四、技术挑战

**挑战一：单一健康分必然重犯第 1 期的错。** 正确性是多值的（四态格），压成"健康分 87"等于把 AML 总分那套无意义排序搬进运维。面板必须报分布：有效／待核／作废各多少、陈旧率多少、无独立证据支撑的派生条多少。

**挑战二：面板覆盖率结构性小于变更覆盖率。** 遥测挂在读写 API 上；而第 34 期证明离线整理是"唯一能改记忆却无人见证"的通道，第 20 期证明查询翻译发生在客户端，第 26 期证明元信号泄漏不产生写事件。三处盲区不是实现缺陷，是**挂载点选择**的必然后果。

**挑战三：级联的收益在答案层测不出来。** 3→11 的错误差统计不显著，按"回答准确率"验收的项目会砍掉级联，而级联真正修的是账本。**用错指标验收，会系统性淘汰正确的东西。**

**挑战四：修复的性价比可反向。** 26.6% 对 12.1%，代价是成本。没有复发率字段，运维无法回答"该精准修还是该重算"。而采集它要求记忆有稳定 ID 且在重写后仍可追溯——第 3 期证明这正是行业在拆的东西。

**挑战五：供应链可观测性先于运行时失效。** 同名不同包说明插件生态里"我观测的到底是哪个构建"都无法回答；记忆是长期资产，装错包等于资产挂错账。

## 五、展望与建议

**预判一：「面板即合同」将先于「指标进评测」发生。** 榜单半年一轮，面板每周可改。厂商会先在自家面板承诺"陈旧率 < 5%""作废传播 < 1 跳"，再倒逼评测采纳。第 28 期说 schema 即世界观，本期补：**面板是 schema 的运行时形态**——写进面板的字段，才是真被当成承诺的字段。

**预判二：依赖图会成为记忆库的标配存储结构。** 一旦有人开始报爆炸半径，没有依赖边的系统就无法参与比较。这与第 13 期"换嵌入模型是单向门"同构：**没有依赖边，等于没有可运维性。**

**预判三：第一代记忆 SRE 指标是四个，且都不在现有面板上**——陈旧率、无支撑派生占比、作废传播深度、复发间隔（MTBR）。其中 MTBR 应取代 MTTR：修得快不如不再犯。

**给使用方**：① 采购时要求演示"改一条事实后下游哪些条目变化"，演示不出即视为无依赖图；② 自建最小面板只用三个数——空结果率、作废条目占比、同一问题两周内答案变更次数，前二取自 API，第三靠回放；③ 以"记忆即可 diff 文件"（ReMe 路线）作兜底观测，成本最低、审计最真。

**给厂商**：把 `MemoryPanel` 从"资产权限视图"升级为"状态分布视图"，先做对一件事——**每条记忆带一个四态标记与一条来源边**。不需要新模型、不需要新基准，只需承认：记忆不是键值对，是图上的节点。
