# AI-SRE 技术洞察 · 2026-11-06 12:00（第 87 期）

## 候选面 / 证伪面：只报第一名的根因报告

> **本期主线（第七十八条）**：一次调查里同时成立过几个解释？被选中的那个凭什么赢？被淘汰的那些，是「被证伪」还是「压根没被想到」？前 86 期从组织层、执行层、验收层、配置表、样本框、坐标系、一次运行一路下探到「被改动的世界本身」；本期第一次上移到**动作之前的认知空间**——结论写出来之前，候选集长什么样。题眼是阿里 STAROps 评测稿那句「结论正确不等于过程可信」，以及一个更冷的推论：**人在回路里，可回路里只有一个选项。**

## 一、发展趋势

**（1）能力竞赛从「包通用模型」转向「自训专用模型 + 自建基准」。** 10-15 Datadog 发布 Scout 1.0，基于 GLM-5.3 Flash 强化学习后训练，自称在内部 AlertEval 上以 3–8 倍成本优势匹配前沿模型；11-01 Forrester AIOps Wave 中 Datadog 与 Dynatrace 各自宣布 Leader；11-03 Honeycomb Personal/Team Agents 与 PagerDuty Paige 同日落地；11-04 Fireworks 的 ORCA 榜以 13 模型给出 Hard RCA 排名（GPT-6 Astra 50.2% 居首）。10-07 ASE'26 收录的 HERO 论文则把诊断重定义为「竞争假设之间的受控判别」。

**（2）但所有度量的收敛点都是同一个数字：top-1。** ORCA 报 50.2%、Struct 10-08 生产环境基准报 Overall 68%、AlertEval 报 0–100 相对分（Datadog 自己提醒「57.5 不代表解决 57.5% 的事故」）、SREGym 报 90 个故障解出 71/79/80。**没有任何一家公开「本轮生成了几个假设、排除了几个、各自凭哪条证据排除」**。83 期问过遥测分母；本期问假设空间的分母——它连被统计的资格都还没有。

**（3）反向信号同样集中在这 30 天：证伪开始被写成流程，却仍不是契约。** 腾讯云 11 月初的 CloudQ「证据先于结论」Skill 把「④证伪」列为五步之一，要求候选不少于两个、「两个假设都无法排除时同时输出，不强行二选一」；阿里 STAROps 每轮「提假设→排除」；火山 VeOps「深度调查」把「哪些排查方向已被证伪」直接显示给值班人；Honeycomb Canvas 专设 Findings 桶让负结果跨智能体传播。四家方向一致：**过程比结论更该留痕**，但都停在自家工作流与看板里，无导出 schema、无 OTel 字段、无采购条款。

## 二、技术现状

**训练层最诚实，产品层最单薄。** Scout 技术报告披露的训练细节是本期最反直觉的一手证据：它「使用工具测试竞争性解释」，奖励函数混入 correctness、exploration 与 evidence grounding——因为早期只奖最终答案时，模型学会了「少断言、早停止」；还用 harness fuzzing 随机移除工具、缩短轮次预算，防止背下固定调查路径。可 Bits Investigation 交付给工程师的，仍是「一个诊断 + 一组建议恢复动作」。**唯一把探索写进目标函数的一家，把探索的结果压缩成一个名词交给人类。** 独立评测账号 AGTP 因此要求补一条「Scout 考虑过并拒绝了哪些证据」的审计轨迹，至今没有。

**状态被做成字段，但只有两格。** Honeycomb 11-03 官方稿写明：每个 finding 回链到 query/trace/deploy/ticket，每条 memory 标注 `confirmed` 或 `hypothesis`，四级自主度靠「持续被采纳的推荐」逐级挣得。这是全行业最接近正确答案的产品化动作。可它缺第三态 `falsified`，也缺「谁、凭哪条证据、在什么时刻」把 hypothesis 翻成 confirmed——84 期双时间戳、85 期运行修订号的缺口，在假说层原样复现。更关键的是它「show how it reached its conclusion」展示的是**胜者的路径，不是败者的路径**。

**共享记忆只复利胜者。** PagerDuty Paige「每次已解决的事故都喂给下一次」、Virtana 10-28 AOEM 让跨厂商 agent 通过 MCP/A2A「交换 findings」并最终「验证性能已恢复」、Monte Carlo Bayes 判断「是 agent 错还是喂给它的数据错」——三者都在加工**已经产生的结论**，没有一个把「被排除项」当一等对象。Honeycomb Canvas 分野最清楚：「Memory is for facts; Collaboration state is for work in progress」，其 Findings 桶要求「一个 agent 排除掉的假设应缩小其他 agent 的搜索空间」。**落选假设连传播载体都没有。**

**评测侧已经开始为「只报第一名」付账。** Struct 10-08 那张表里，Opus 5.5 High 的 Overall 68% 旁边是 55% 假阳性，GPT-6.1 Sol High 的 62% 旁边是 30% 假阳性、19%（15/80）幻觉或空输出；假阳性与幻觉是副列，整体正确率才是分数。ORCA 用 `avg@3` 记分，但 CloudsPress 点破：「Shared training patterns can produce the same wrong explanation」——同权重模型三次给出同一个错答，是同一个先验被采样了三次。这是 80 期「共识不是独立确认」在认知层的镜像。

**中国平台的反转值得单独记一笔。** 腾讯 CloudQ 的五步（分案／收敛／回溯／证伪／归因分级）把结论分三级：直接证据给置信度并「说明为什么不是更高」，间接证据标「待验证」并列出缺哪种指标，只剩假设则标「假设」、只给下一步取证方向；范围外证据一律不补全。阿里 STAROps 指出一类最难发现的错误：工具调用成功、返回真实数据、结论甚至碰巧对，**唯独时间窗查错了**——「从外面看一切正常」，必须拿真实时间窗与实际使用窗口对照（84 期时间基准面在调查层的镜像）。火山 VeOps 直陈「只有根因结论，看不清推理思路与依赖证据」。往期判词常说国内平台派「语义散在帮助页」；本期必须修正：**在证伪这一维度上，中国平台的过程定义比美国平台更细，弱点不在流程而在契约化**——信通院六维有「结果可评价」，没有一维问候选集。

**判读**：美国平台把假设做成了**字段**，中国平台把证伪做成了**流程**，学术侧把竞争假设做成了**算法**，本地工程实践派把它做成了**状态机**——四者互不换算，也都没做成可跨厂商导出的证据契约。分野不在诊断分数（Scout 的 AlertEval 为厂商自跑），而在三问：**能否导出被排除假设清单 / 假说状态变更是否可审计 / 审批界面是否呈现竞争解释**。

**本地 173/173-kb 连续第八期成组启用，且这次是「答案原型」**：余锦泽 03 给出四态（大模型只提候选 → 程序核对标「已验证」或「候选」 → 人确认或否决），评审台「必须填写评审人；否决与删除须填写理由；记录评审人、时间与理由」，否决可撤销并即时传下游、**「否决记录作为下一轮构建的反例」**，「仅有单一弱证据时保留为候选」，另设对抗基准；实测 8 题从 2/8 提升到 6/8。刘凯宁 05 把「反证」写进交付物：候选原因／证据链、「证据要求、反证与结论边界」、「证据不可用时保留未知并说明缺口」、输出「定位结论、证据与待确认项」。刘杨 08、周昕毅 10、casa 01「结论未执行：标未验证，不猜通过」、孙鹏 11、施宏斌 14 共同补全。判词：**联网侧刚开始把「假设」做成二值字段，本地工程实践派早把它做成带理由、可撤销、能反哺下一轮的四态状态机**——仍不可采购。

## 四、技术挑战

**「被证伪」与「没被想到」在 trace 里是同一个值。** 两者都表现为「没有这条记录」：span 记录执行过的查询，不记录「考虑过但没查」，也不记录「查了但排除」。这是 82 期负事件家族在认知层的对应物，且比配置默认值更难查——默认值至少还有文档。

**多采样一致不等于独立确认，判别性测量才是硬通货。** 两个假设若预测同样的观测，正确动作是声明「当前证据无法在二者间选择」并采集能区分它们的最小测量，而非用更多次采样调 top-1。HERO 在 OpenRCA 上 SR 79.77、超 ReAct 基线 23.20 分且**平均少用 1.04 个动作**、工业集 85.00，说明显式化竞争假设不是更贵而是更省；代价是把「否证结果」也当一等数据保存。

**用效果反推原因会抹平假设。** 回滚、重启、扩容都能让告警安静，多个互斥解释导向同一个修复动作。86 期说「告警安静不等于修好了」；本期补一句：**安静也不能给假设排序**。Virtana「验证性能已恢复」、Gremlin 闭环重跑都只证明世界变了，不证明解释对了。

**先验顶替第一个假设。** 中文报告提到的「Sysadmin Reflex」（零样本预训练偏差、可达 66.7% 误操作率，二手口径）与 CloudsPress「A recent change is a useful hypothesis, not proof」指向同一件事：模型把语料里最常见的动作当结论，其余假设一开始就不在集合里——「候选集」不存在，证伪无从启动。

**第四十一个市场空白**：候选集规模／证伪率（被排除 vs 被忽略之比）／判别性测量覆盖率／假说状态变更审计，四项无一内建。OTel GenAI 语义约定在 72 identity、79 billing_unit、80 attempt、81 abstain、82 config.effective、83 sampling、84 time.*、85 run.revision.*、86 effect.* 之后，仍无 `hypothesis.*` 字段族。

## 五、展望与建议

1. **把假说做成四态一等对象**：`HYPOTHESIZED / SUPPORTED / FALSIFIED / UNDECIDABLE`，七字段最小契约（id、statement、predicted_observation、discriminating_test、evidence_for、evidence_against、state_changed_by/at/reason）。`FALSIFIED` 必须携带否证结果，不得静默丢弃；`UNDECIDABLE` 与 81 期 `ABSTAINED`、86 期 `UNVERIFIED` 共用同一套「不结论也可交付」的计分位。
2. **审批门禁改写**：高危动作审批单强制附 ≥2 个被排除假设及各自否证结果；两假设预测相同时强制 `UNDECIDABLE` 并禁止自动修复。否则「human in the loop」只是让一个人在唯一选项前签字。
3. **四项 SLI 与记忆写入门槛**：`discriminating_test_coverage`、`falsification_rate`、`ignored_vs_rejected_ratio`、`hypothesis_flip_audit`；只有 `SUPPORTED` 及以上允许进共享记忆，`FALSIFIED` 单独留存作反例（余锦泽 03 已给出实现形态），避免 PagerDuty 式「只复利胜者」把一次侥幸的正确归因固化成下次先验。
4. **基准与混沌题型**：ORCA / SREGym / AlertEval 增报候选集规模与证伪率，把 Struct 表里的「假阳性」「幻觉或空输出」升为主列；注入目录新增三型——多假设同预测、修复抹平假设、锚定最近变更。STAROps「时间窗查错」列为独立题型（84 期），CloudQ「收敛可加性校验」作确定性兜底范式。
5. **标准化与采购**：向 OTel GenAI 提 `hypothesis.*` 草案；信通院六维补「候选集可导出」；采购三问写进条款（能否导出被排除假设、假说变更是否可审计、审批是否呈现竞争解释）。腾讯／阿里／火山现有流程最易改造，缺的只是一层机器可读导出。
