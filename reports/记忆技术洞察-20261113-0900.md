# 记忆技术洞察 #76（20261113-0900）· 记忆的并发正确性 2.0：多写者时代，把"冲突可见"立为一等 SLA

**发展趋势。** 2026 下半年多 agent 共线写入成默认形态，并发从边缘异常变常态负载。行业正从"条目级锁"转向"身份+作用域"原语：MongoDB+Google ADK（11-04）摄入幂等+会话乐观并发；Maximem Synap 四层隔离奉行"绝不下看、绝不横看"；浪潮 Agent DataSpace 把隔离粒度下移到 KV Cache/记忆统一承载。命题已从"会不会冲突"升级为"冲突能否被观测、裁决、复盘"。

**技术现状。** 第 8 期已立并发三形态、冲突五型（含失支型 unsupported）、一致性光谱 V0–V4。但 2026 仍三处未补：①并发删除×并发改写乘积（待验证27）——forget 与基于它的派生生成同时发生，删除传播与失支无人负责；②分支 GC 语义（待验证28）DAG frontier 膨胀、合并后墓碑无人管；③身份解析作实验变量（待验证29）零对照数据。Zep Agent Skills（11-01）做了删源 run 级联删除，仍单写者。

**需求分析。** 旧并发观遮蔽三类需求：①运营方要"冲突可计数"——上线前测冲突检出率/误报率而非只看吞吐；②多租户要"scope 级不可见"——宁可不可见也不横看他人事实（接第8期身份先于锁）；③合规要"删除即依赖失效"——forget 须广播使派生失效而非点删（接 #74 遗忘保真度复活通道）。AML 三期（待验证30）仍无并发/多写者维度。

**用户旅程。** 团队协作：agent-A 写"客户偏好=红"，agent-B 改"=蓝"并生成报价派生。无并发原语时 LWW 让 B 覆盖 A，A 的下游派生静默失支。启用作用域隔离+依赖失效后，系统保留双值标未决、对 B 派生广播 invalidation、A 的引用不崩。

**具体实现方案。** ①身份解析先行：把 git identity/账号/实例/角色四轴做成可切换变量，固定 conflict workload 扫三轴报冲突检出率（首测待验证29）；②删除=依赖失效事件：forget 广播 invalidation 而非点删，派生进未决态（解待验证27，接 StateGraph V2+依赖失效）；③scope 不可见原语：四层隔离+never-below/sideways 默认策略替代条目锁；④并发 SLA：冲突检出率/收敛时延/失支率与召回率对称，进 AML 三期补轴（待验证30）。

**技术竞争力。** 五项目断层：OpenViking peer=git identity 最完整（recallPeerScope:all）但 forget 硬删无墓碑；dsh-memory-evolve 分支=作用域时钟最优雅，却受 unicode61 中分共因故障；TencentDB 角色四档+版本追踪，跨 agent 删除权悬空（接 LangChain 11-02 peer-agent 主权否定）；Hy-Memory 权重覆盖不可逆不可审计；ReMe2Ops wikilink 图保留溯源却无并发语义。竞争已从"谁记得多"转入"谁在并发下仍正确"。

**技术挑战。** ①身份漂移：改 remote/fork/改名后记忆继承无方案（待验证5/266）；②GC 缺失：DAG frontier 膨胀、合并后墓碑无人回收（待验证28）；③测量空白：待验证29 零数据、AML 无并发轴（待验证30）；④主权边界：对等 agent 永不得使共享记忆遗忘，落地无强制。
