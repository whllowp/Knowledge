## 题眼

11-10 OpenAI「控制室」后半句才是工程决定：**「该系统还采用『故障关闭』机制。如果 Control Room 发生故障、被关闭或遭到篡改，所有相关推理请求将默认被拒绝，直至服务恢复」**——行业首次把「管不住时闸门往哪边倒」写成机制，但只覆盖内部「全部前沿模型研究任务」；**对外服务缺省姿态未提**。

11-04 arXiv 2611.06996（TRAP）把「运行时可信度 → 操作权限」这条映射本身当自变量。非对称规则（升权需连续观测、陡降即收紧）在突发退化下最好；但**把同样退化摊薄到 5–20 个区间，TRAP 只在 4 条仍保留单区间陡降的轨迹上收紧，平均 20 个区间里有 15.9–18.9 个权限高于可信度所支持的水平**（突发下仅 0.8）。作者自陈："Its restriction advantage therefore depends on degradation being abrupt."

本期判词：**「故障关闭」答的是宕机，生产里更常见的却是控制面没宕、只是慢慢不可信**（凭据临近过期、覆盖渐漏、验证器漂移、Skill 随拓扑过期）。11 月 Day 2 稿留下一句自白：评测器须放在请求路径外，**「能挡住 Agent 的评测器，会在第一次事故时被关掉」**。最该在事故时生效的闸被设计成不许挡路，漂移时也无人测。

## 一、发展趋势

**趋势一：控制面从「有没有」进入「坏时怎么倒」。** 前 116 期补的审批、护栏、急停、回执、隔离都隐含一个未声明前提：控制面可用且可信。11 月三件事拆开它：OpenAI 声明宕机即拒绝、Claude Code 2.1.317 把 `onFailure: "block"` 缺省从「回调崩溃＝放行」改成阻断、Google 11-02 上线自动纳管。**同一周三家回答同一问题，而采购清单没有一列写这一项。**

**趋势二：姿态成为可测策略。** TRAP 用 100 条轨迹对比四种策略，量「权限高于证据的区间数」；11-04 综述 2611.06764 要求评测同时看**「仍处启用状态的未授权效应」**——正是 fail-open 敞口的定义。

**趋势三：失效从「事件」变成「曲线」。** 熔断面对阶跃，退化多是斜坡。ETUDE（11-01，上海交大＋Inria）证明工具安装／审批／审计时被信任一次、实现变更永不复核，7 框架 97.6% 攻击成功率、95.9% 正常完成率。**信任无限期，实现一直在变**，闸门却只在陡降时动。

## 二、技术现状：四层控制，没有一层把姿态写成字段

**学术层首次把授权策略立为待测对象。** TRAP 价值不在算法而在报出失败模式：慢漂下 15.9–18.9/20 区间权限虚高。2611.06764 提出「授权须随工作流重评估」；ETUDE 给出供应链同构镜像——**一次授信 + 无 TTL** 让窗口内护栏结构性失效，因变更发生在窗口之外。三者同指：权限被当静态属性，不是随可信度收敛的函数。

**模型厂商层一进一退。** OpenAI 唯一把 fail-closed 写成机制，但只在内部研究设施；Claude Code `onFailure: "block"` 修的是「回调崩溃等于放行」（115 期同素材不同面）。SPILLWAY（2611.07222）提醒 fail-closed 不免费：过度拒绝会逼出旁路，**挡住三分之一合法请求的闸门自己就是新的洞**。

**云厂商层控制面最丰富，姿态最沉默。** Google 11-02 异常检测官方文档逐字写明：符合条件的 Agent 被自动认作 monitored，「the service is aware of the agent's existence, but **nothing is run on the agent's logs and no costs are incurred unless the agent is enabled**」；覆盖率指标入 Cloud Monitoring。三层检测明写 "without introducing execution latency into your live agent workflows"。**观测是旁路，授权是闸门，两者没有闭环**：异常分数升高不会让权限降档；11-02 自动纳管修的是「今天起在册即在测」，历史未启用窗口既不标 `NOT_ATTESTED` 也不回溯补测。11-05 安全峰会 Auth Manager GA、Agent Identity JWT、CodeMender 沙箱与人工 sign-off——**没有一条说明控制面不可用时默认什么**，「人工 sign-off」更把姿态托付给没有 SLA 的人。

**中国侧写得最细，却写在文档里。** 阿里 11-10 STAROps「低风险自动放行／关键变更人工确认／禁止操作拦截」是唯一按风险分档的产品策略；腾讯云社区稿「影响面说不清的处置，Skill 里固定『到此停』」「审批闸门必须存在」，几乎把边界说全——但落点是 Skill 提示词与流程文档，Skill 没加载、换框架、审批超时，约束就不存在。CloudQ 受控执行、火山 EMR 限频同理。

**标准层连这一格都没有。** 11-02 核 OTel GenAI 全部文档仍 Development、未切 release；工具参数与结果默认 `NO_CONTENT`，span 可采样丢弃。语义约定无 `posture.*`，也无「控制面不可用」状态位。**缺席在轨迹里表现为一次成功的调用**：审批超时、验证器没返回、检测未启用都不报错、不进分母（115 期返回假设在姿态层复现）。

## 四、技术挑战

**一，宕机是最好测的一种失效。** fail-closed 演练是阶跃注入；TRAP 说明慢漂 20 区间里近 16–19 个权限虚高。**斜坡不触发告警**。

**二，越不挡路越挡不住事故。** Google 明写检测异步、不加延迟、指标供人看图；Day 2 稿承认会挡路的评测器「会在第一次事故时被关掉」。可观测性允许遗忘，授权不允许，两者却共用旁路假设。

**三，缺席被计成通过。** 未启用不计费不告警、回调崩溃等于放行、审批人无 SLA，三种缺席都是一次成功调用；没有 `POSTURE_UNKNOWN`，结案分母照收。

**四，一次授信无限期有效。** 凭据、工具、Skill 无 `expires_at`；版本变更不重签，覆盖只在安装那一刻被验过。

## 五、展望与建议

**R1 `posture.*` 九字段进 OTel GenAI 提案**：`posture_id`／`gate_kind`／`dependency_ref`／`availability_state`／`on_unavailable`（FAIL_OPEN｜FAIL_CLOSED｜DEGRADED｜HANDOFF）／`authority_level`／`readiness_score`／`degradation_slope`／`last_attested_at`，缺省 `POSTURE_UNKNOWN`。**权限是静态上界，姿态是运行时函数**；除人工重签外 `authority_level` 对 `readiness_score` 单调不增。

**R2 慢漂注入台**：把 TRAP 的「摊薄到 5–20 区间」做成季度演练，主 SLI 报「权限高于证据的区间数」。六类注入：宕机、审批超时、验证器不返回、检测未启用、可信度慢漂、工具更新未重签。

**R3 不可用窗口导出器**：三闸心跳，超时即 `POSTURE_UNKNOWN` 并阻断不可逆动作；缺席时段不得进结案分母与自动化率。

**R4 在册／在测双态看板**：显式化 monitored≠enabled，历史未启用窗口标 `NOT_ATTESTED`，不回溯补测就公示。

**R5 观测→授权闭环与信任 TTL**：异常分数或覆盖率越阈值自动降一档权限（不只发告警）；凭据、工具、Skill 授信带 `expires_at`，版本变更即重签。

**R6 分档姿态与 over-refusal SLI**：同时监控「合法请求被拒率」与「绕行率」；信通院六维补「失效姿态可声明率」「慢漂降权覆盖率」两格。

**本地 173／173-kb 连续第 37 期成组启用**：**陈忻 29「门禁：严格指标 100% 通过放行——未达标不放行」首次当主线**——全库唯一把「不放行」写成硬缺省（跨境支付场景），但判据是**内容指标未达标**而非**门禁服务不可用**：指标没跑完、门禁超时，讲义无答案。配朱革 15「缺少统一权限、审批、限流、审计和回滚控制」（列五道闸，没列闸坏了怎么办）、周昕毅 10「恢复失败转人工」（无 SLA）、李东东 16「端侧优先，云端兜底」（107 期取不共域，本期取断网即切）、何伟 02。判词：**本地把「不放行」写成验收底线、把兜底写成人的分工；联网侧 11 月才把「控制室自己坏了也拒绝」写成机制，才量出「慢漂时权限虚高 15.9–18.9 个区间」。两边都没把姿态做成可导出字段。**
