# 记忆技术洞察 · 第 96 期（20261116-1400）

**主题：记忆的「成本内化与推理兑换率」（Cost-Internalized Memory）——前 95 期都在估"记忆值多少"（#22 信用分配、#79 决策效用、#94 评判者校准、#95 可识别性），默认"成本=token 数"是外生常数；本期把它提成自变量：成本不是记忆的属性，而是架构、服务层缓存与客户端策略的交易结果——"少 token"不等于"更便宜"，换一条 serving 规则就能反转 Keep/Drop 的贵贱。**

> 洞察范围：2026 年（重点最近 30 天）｜固定维度：发展趋势・技术现状・技术竞争力・技术挑战

## 一、四维度速览

**发展趋势**：价值侧趋饱和，成本侧独立成轴。Think or Remember（arXiv 2611.10982，11-07）定义成本模型：每处理 token 收 c、每注意力 pair 收 β，比值 P*=c/β 是"思考 vs 记忆"兑换率——上下文短于 P* 为 thinking regime，长于为 memory regime；Qwen3.6-27B 的 P*≈124K，全注意力同规模约 30K。CoReMem（2611.17316，11-12）把成本从检索期前移到写入期：只为"未来收益付得起写读成本"的片段建记忆。

**技术现状**：成本拆成机械项（同 continuation 重放可算）与行为项（策略改变写出不同 token，须 live rerun），计数在 648 请求上与插桩 vLLM 一致。关键反转：Qwen3-8B 丢弃推理，服务端复用生成态时成本是保留的 1.74 倍、什么都不复用时仅 0.34 倍；保留最近 5 段推理的滑窗把提示缩短 1.6%，成本却是全保留的 3.97–4.56 倍。CoReMem 只留两类锚点——仓库位置（WHERE）与可执行检查（VERIFY），推理叙述与原始 diff 是纯开销；ChainSWE 上 27B solve 率 21.0%→25.7%，步数 −17%、含记忆调用 token −11%。

**技术竞争力**：五项目（OpenViking v0.5.4／Hy-Memory 2.0.13＋MemHub v1.0.6／TencentDB v2.0.3／dsh v26092802／ReMe v0.4.2.2）只报"省了多少 token"（Hy-Memory 1159→703、TencentDB −61%），零项目披露缓存规则或兑换率——同一"节省"数在不同部署下可能反向。谁先把成本做成随服务端规则可复算的契约，谁就把自测优势变成可迁移承诺；AML C2 榜无该维度，倒挂延续。

**技术挑战**：Drop 收益符号随 serving 翻转，HotpotQA 四个模型丢弃后正确答案掉 9–23 个百分点、成本点估计却更低；gpt-oss-20b 在 ScienceWorld 反例（3/88→20/88）。跨任务携带历史成本降至 0.60 倍，新任务解决数却从 30/96 跌到 17/96——"便宜"与"有效"正交。

## 二、需求分析

采购方要的是可复算成本账：给定架构（P*）、缓存规则（ρ）、客户端策略，一段记忆写入、读取、重算各花多少，删掉省下的成本是否以正确率为代价。这些变量如今混在一个 token 总数里，"压缩=省钱""滑窗=省上下文"成了未经验证的默认，直接坑到 #93 输出预算保真的前提。

## 三、用户旅程

以"给长程编码 agent 配仓库记忆"为例：①量兑换率 P*，判断处于 thinking 还是 memory regime；②固定 serving 规则，否则成本对比无效；③写入前做有/无对照跑，只留 WHERE 与 VERIFY 锚点；④保留机械项与行为项两本账；⑤删留同时看成本与正确率，符号翻转时暂缓；⑥把缓存规则与口径写进 SLA。

## 四、具体实现方案

加"成本内化闸门"：契约增 P*／cache_rule ρ／mechanical_cost／behavioral_cost／anchor_type。写入期前瞻估值——从同一继承状态跑有/无候选片段的下一任务，差值即收益，低于写读成本者不存，只抽锚点。actor 侧用有记忆／无记忆／错放记忆三组 rollout，奖励以解决为主、成功样本罚步数；溯源门只给实际调用锚点的步骤追加信用。报价必须绑定 continuation 与 serving 规则。证伪条件：若固定 P* 与 ρ 下 token 数仍能独立预测成本与正确率、Drop 不翻转符号，本期论点被证伪。

## 五、本期新观点

1. **成本从分母提成自变量**：前 95 期估"值多少"，本期估"花多少、由谁定"——成本是 f(P*, ρ, 客户端策略)，非记忆固有属性。
2. **少 token ≠ 更便宜**：滑窗省 1.6% 提示却贵近 4 倍、Drop 两规则下贵 1.74×/便宜 0.34×，推翻 #19/#66 压缩与 #93 预算保真隐含的"越短越省"。
3. **机械/行为成本二分是新 SLA 原语**：把 #78 裁决、#95 弃权从答案侧推广到成本侧——不重放、不 live rerun 的报价不算数。
4. **两方交易无单一决策者**：客户端与服务端各控一半，任一方单独优化都可能全局反优。
5. **成本内化=证伪实验前移到写入期**：CoReMem 有/无对照延续 #89、#95 的实验设计；AML 宜补 cost-internalization 维度。
