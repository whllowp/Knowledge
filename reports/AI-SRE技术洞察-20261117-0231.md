# AI-SRE 技术洞察（第 238 期）

**生成时间**：2026-11-17 02:31（Asia/Shanghai）
**观察窗口**：2026 年内，重点 2026-10-18 至 2026-11-17（近 30 天）
**本期主题**：记忆写入门／写入策略（Memory Write Gate）——不是每段对话都值得记住

## 题眼

- **AdaMem（arXiv 2606.21144，2026-09 更新）**：长期记忆系统大多只做“抽取后存储与检索”，**“写什么”这个决定本身定义不清**（write decision under-specified）；它把写入改成“偏好条件下的写控制”，用自然语言 Memory Policy 表示用户在特定交互情境下的记忆偏好，并强调**偏好在存储之前生效，而不是在检索时修补一个不加区分的库**。
- **《Interpreting at Write Time》（arXiv 2610.02897，2026-10-30）**：写入时的压缩必然带着“这份记录是为什么用”的视角——**摘要总是从某个视角写出来的，系统命名不命名而已**；而同一份记录之后会被问完全不同的问题：LongMemEval 考五种长期记忆能力，LoCoMo 同时考问答/事件摘要/对话生成，MemoryCD 考跨十二个领域时偏好是否仍成立。
- **《The Next AI Breach Will Start in Memory》（Zenodo 22713714，2026-05）**：持久记忆正在成为企业新的安全边界；**记忆投毒与提示注入有本质差别——一条被污染的记录会越过当次交互，持续影响后续推荐、工作流与下游决策**。
- **ACM TURC 2026（3833142.3833192，2026-10-08）**：在 OpenClaw 上验证了**网页内容可以污染 Agent 的持久记忆**——“能读网页”与“能写记忆”同时成立时，不可信内容影响的不只是这次回答。
- **MemIncept（ICML 2026）**：只用看起来无害的查询、协同生成一组注入，就能在**黑盒**条件下把 Agent 的行为带偏——单条孤立记录容易被查，**一组互相配合的记录才难查**。

## 一、发展趋势

**从“记得多”转向“写得对”。** 2025 年的记忆竞赛比的是容量与召回（Mem0、Zep、MemGPT 一路把上下文扩到百万级）；2026 年的新论文开始把镜头对准**写入那一刻**：AdaMem 说写决策没被定义清楚，2610.02897 说写入时的编码就是一个视角选择，Zenodo 与 ACM TURC 说写入是新的攻击面，EverMemOS（ACL 2026）干脆把记忆做成“事件轨迹→主题场景”的生命周期，显式处理合并与冲突。四条线指向同一件事：**记忆系统的质量上限，在写入时就定了一半**——写进去的是噪声，检索再强也只能捞出噪声；写进去的是没有来源的结论，将来就无法判断它是否还成立。

## 二、技术现状

**四种写入形态并存。** ①抽取式（Mem0 一类：LLM 抽出事实，再 ADD/UPDATE/DELETE）；②摘要式（把一轮对话压成一段话）；③图谱式（Zep/Graphiti 把实体与关系写成带时效的边）；④事件式（EverMemOS 的 MemCell：情节轨迹、原子事实、带时间边界的预期）。四者共同的缺口不是存储，而是**门**：什么进来、以什么粒度进来、带不带来源、什么时候失效。

**“写什么”目前有三种实现。** 规则（关键词/长度/白名单）、偏好策略（AdaMem 的自然语言 Memory Policy，从用户反馈里改）、学习式（RL 训练写策略）。规则最省事但一刀切；偏好策略可读、可改、可审计，是目前最工程化的一条；学习式效果最好但“为什么写”说不清。

**合并与冲突开始被当成一等公民。** EverMemOS 用 MemScene 做主题合并并处理冲突；图谱写“有效期”让旧事实自动失效。反过来，只追加不合并的库，会把“用户去年说喜欢 A、今年说喜欢 B”同时留给检索，**答案取决于谁排前面**。

**投毒从论文走进产品语境。** 网页内容、工具返回、用户上传文件都可能成为写入源；单条投毒可被相似度去重挡住，**协同注入**（MemIncept）则专门绕开这一点。

**判读**：存储、向量库、摘要、图谱都已是货架商品；**“这条记忆是在什么上下文、按什么规则写进来的”没有一家把它做成可查询的字段**。本期反转：第 168 期说“检索八成不是模型问题”，本期补一句——**检索的上游是写入；写的时候没留来源，读的时候就没有证据**。判词：**「记忆存储」「向量检索」「摘要」「知识图谱」全部可采购，「举证这条记忆的写入上下文与写入规则」不可采购**。

## 四、技术挑战

1. **写多写少两难**：全写→噪声沉底、检索变贵；少写→关键偏好漏掉、下次重问。AdaMem 的价值正在于把“重要性”从全局常量改成**情境条件**。
2. **编码视角与未来问题不匹配**：写的时候按“这次任务”压缩，将来问的是另一件事；2610.02897 的三个基准正是三种问法。
3. **投毒跨会话持久**：一条污染记录可以活过无数次对话；协同注入让“看起来无害”成为武器。
4. **合并冲突无标准**：supersede、retract、merge 三种语义没有统一契约，跨系统迁移就丢。
5. **删除要能传播**：记忆被删了，摘要、向量、日志副本还在（第 187 期五处副本）。
6. **评测错位**：现有基准都在测“读得准不准”，没有测“该不该写”。

## 五、需求分解、用户旅程与实现方案

**需求分解（P0→P3）**
- P0 写入门四问：会改变下次行动吗？可验证吗？有主吗？会过期吗？——四问全过才写。
- P0 来源指针：每条记忆带 `source_ref`（会话/工具/文档 chunk/版本）与 `write_rule`（哪条规则放行）。
- P1 合并与失效：supersede/retract 语义，旧事实保留但标失效，不物理删。
- P1 TTL 与衰减：偏好类长 TTL、事实类短 TTL、事故教训带“适用版本”。
- P2 投毒检测：写入源分级（用户直述/内部文档/外部网页），外部源默认“仅当次可用、不入长期记忆”。
- P3 删除联动：删记忆→删向量→删摘要→标记日志（第 77 期退出面）。

**用户旅程（四条）**
1. 用户纠正偏好：“以后别用这种语气”——写入门判断这是长期偏好→写入→带来源与 TTL→下次生效可解释。
2. 事故复盘后写入教训——写入门要求绑定事故 ID 与适用版本，版本一变自动提示“教训可能过期”。
3. Agent 读到外部网页——默认不作为长期记忆写入；确需写入则标 `untrusted` 并隔离检索。
4. 用户要求删除——一次删除触发四处副本清理，并留下删除审计。

**90 天实现方案**
- 第 1–3 周：写入门四问做成策略层（规则＋自然语言策略双轨，参考 AdaMem），所有写入落 `write_gate` 审计。
- 第 4–6 周：来源指针与 TTL 字段进 schema；对现有库做一次回填（能补的补，补不了的标“来源缺失”）。
- 第 7–9 周：supersede/retract 与冲突检测；外部源隔离策略上线。
- 第 10–13 周：投毒红队（含协同注入）、删除联动演练、写入质量看板（写入门拒绝率、来源缺失率、冲突解决率、投毒检出率）。

**第 166 个市场空白（五项）**：`write_gate.*` 写入门决策覆盖率、`memory_write.source_ref` 来源指针覆盖率、`memory_write.ttl_hit` 过期命中率、`memory_write.conflict_resolved` 冲突解决率、`memory_poison.detected` 投毒检出率。`memory_write.*`／`write_gate.*` 为**第 132 次无人提字段族**；本地 173／173-kb 连续第 122 期成组启用（余锦泽 03「上下文装配」与周昕毅 10「恢复失败转人工」重读为：**装配之前先有筛选，转人工之前先有来源**——本地把“选什么进上下文”写成了流水线，却同样没把“为什么写进长期记忆”做成门）。
