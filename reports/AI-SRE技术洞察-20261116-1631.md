**本期主题**：运行面／推理底座可观测（Inference Runtime）——Agent 慢，可能是 GPU 排队；而你只看端到端延迟

## 题记

136 期说冷启动、161 期说容量、167 期说瓦特、201 期说遥测成本。这四件事在**推理底座**上合成一个日常误判：**用户说「Agent 变慢了」，团队看端到端 P95 涨了 300ms，然后开始查 prompt、查检索、查工具**——**但真正的瓶颈常常在 GPU：排队深度、KV cache 命中、批处理窗口**。11-09，ControlTheory 发布 Dstl8 2.0，卖点正是「**telemetry-native**，**从 Agent 跟到 GPU**」——它把这件事说破：**多数 AI SRE 只看应用层遥测，看不到模型推理底座**。**端到端延迟是结果，GPU 队列是原因；只看结果，就只能猜原因。** **而猜，通常猜错。**

## 一、发展趋势

**趋势一：可观测从「应用层」下探到「推理层」。** 从 trace 到 GPU；**中间隔着一层没人看**（162 期）。

**趋势二：TTFT 被拆成可归因的分段。** 排队、预填、解码；**不拆就只能说「模型慢」**。**「模型慢」不是结论，是三个未知数。**

**趋势三：容量规划开始看显存与队列。** 不只看 QPS；**看 KV cache 与批处理**（161 期）。

## 二、技术现状：三层延迟，通常只看一层

**应用层：最常看。** 端到端、工具耗时；**但看不到模型内部**。

**推理层：部分看。** TTFT/TPOT；**但不知道时间花在排队还是计算**。

**GPU 层：几乎不看。** 利用率、队列深度、KV 命中；**不在 APM 里**（201 期）。

**现状：端到端涨了，先怪 prompt。** 改 prompt 一周；**其实是 GPU 排队**。

**三种排队，一种比一种难看见。** 批处理排队（攒批窗口）、租户排队（共享 GPU）、预填排队（长上下文抢算力）；**三种都在 GPU 里，APM 里都没有**。

## 四、技术挑战

**一，GPU 指标不在 APM 里。** 两套系统；**trace 与 GPU 对不上**（72 期）。

**二，排队是共享的。** 多租户/多模型共用 GPU；**别人的流量让你变慢**（121 期）。

**三，KV cache 命中影响大。** 命中低 → 预填变慢；**没有指标就不知道**。

**四，批处理窗口在调。** 攒批提高吞吐、拉高延迟；**调参没有记录**（127 期）。

**五，容量与延迟非线性。** 利用率 80% 后延迟陡增；**平均值掩盖拐点**；**扩容总在拐点之后**。

**六，成本与延迟打架。** 降本用更小模型/更少卡；**延迟变差**（143 期）。

**七，TTFT 与 TPOT 分开看。** 首字慢 vs 逐字慢；**修法完全不同**。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `infer.*` 字段**：`request_id`、`queue_ms`、`prefill_ms`、`decode_ms`、`gpu_util`、`kv_hit`、`batch_size`。
- **R2 分段归因**：TTFT 拆排队/预填/解码；**进 trace**（105 期）。
- **R3 GPU 指标**：利用率、队列、显存；**与 trace 关联**。
- **R4 KV 命中**：按模型/租户统计；**低命中告警**。
- **R5 容量联动**：利用率拐点（如 80%）；**进扩容决策**（161 期）。
- **R6 指标**：分段延迟、队列深度、KV 命中率、拐点利用率。

### 5.2 用户旅程

- **SRE**：P95 涨 → 看分段 → 排队占 70% → 扩卡/限流 → 记录分段。
- **平台工程师**：KV 命中跌 → 查路由 → 修会话粘性。
- **容量**：看到 80% 拐点 → 提前扩容。
- **审计**：核对分段与容量决策 → 确认可复现。

### 5.3 实现方案（90 天）

- **0–30 天：分段。** TTFT 拆三段；进 trace。
- **30–60 天：GPU。** 利用率/队列/显存；关联。
- **60–90 天：联动。** KV 命中；拐点；扩容；TTFT/TPOT 分开看。

**第 157 个市场空白（五项）**：分段延迟覆盖率、GPU 指标关联率、KV 命中可报率、队列深度可报率、拐点利用率可算率——无一内建；`infer.*`／`gpu.*` 为**第 123 次无人提字段族**。本地 173／173-kb 连续第 113 期成组启用：余锦泽 03「上下文装配、工具调用、结果校验」＝全库唯一把「装配」写成流水线环节的实践，本期首次当主线；配 136 期冷启动、161 期容量。判词：**本地把装配写进流水线，联网侧 2026 年才把遥测跟到 GPU；两边都没把「延迟涨在哪一段」做成请求字段。**
