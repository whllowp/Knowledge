# AI-SRE 技术洞察（第 149 期）

**生成时间**：2026-11-12 11:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：红队面／对抗演练面（Adversarial Drills）——安全不是「没被攻破」，是「被攻破时多久发现、多快止住」；没演练过的 Agent，第一次实战就是事故

---

## 题眼

NIST 2025 年 1 月的那组测试，被 11 月的主权指南反复引用：对 Claude 3.5 Sonnet 的 Agent 做注入攻击，**五个任务平均成功率 57%**——**靠模型拒答挡不住**。另一边，工具侧的实证是 **109 个工具描述里有 33 个可被投毒**；供应链侧则是「同名不同实现」在 11 周里漂了 **7/59**（137 期）。三件事指向同一个结论：**Agent 的攻击面不是「它说什么」，是「它能做什么」——提示、工具、检索数据，任一处被污染，它都会照做。** 而多数团队的「安全验证」仍是一次性渗透报告：**报告说「未发现高危」，然后一年不再测**。**一次性渗透证明的是「那天没被打穿」，不是「明天打穿时能止住」。** **演练要产出三个数：注入成功率、发现时长、止住时长；缺一个，就只是演示。**

## 一、发展趋势

**趋势一：从「渗透测试」转向「持续演练」。** 一次性报告换成季度红队＋常备攻击语料；**指标从「有没有漏洞」换成「注入成功率、发现时长、止住时长」**。**语料库是资产：不积累，每次红队都从零开始。**

**趋势二：攻击面从「输入」扩到「工具与数据」。** 提示注入只是入口；**工具描述投毒、检索数据污染、MCP server 替换**才是 Agent 特有的面（92／137 期）。

**趋势三：演练开始带「行动半径」。** Agent 会执行，不只是回答；**同样的注入，只读 Agent 与可写 Agent 的后果差一个数量级**（95 期收容、121 期隔离）。

## 二、技术现状：三类注入，三种失守

**提示面：文档与用户输入。** 检索到的文档、工单、网页都可能带指令；**Agent 分不清「资料」与「命令」**（49 期：遥测是证据还是指令载体）。

**工具面：描述与实现。** 工具描述被改写，Agent 就会选错工具或传错参数；**同名 server 被替换，行为跟着换**（137 期 7/59）。

**数据面：检索与记忆。** 被污染的记录进入上下文，**后续所有推理都建立在它上面**（116 期记录污染）。

**演练现状：一次性、无基线、无复现。** 报告写「未发现」；**没有攻击语料、没有 harness、没有基线，就无法比较「这次比上次好还是坏」**。

**一次完整演练有四段，多数团队只做第二段。** 侦察（Agent 能碰什么）、注入（投什么）、行动（它真的做了什么）、止住（多久切断）；**只测「注入是否成功」，测不出「成功之后有多糟」**。

**演练环境决定结论可信度。** 真打生产会触发真实动作；纯 mock 又测不出工具真实行为；**折中是「真实工具替身＋真实权限边界」**。

## 四、技术挑战

**一，成功率太高，不能靠模型。** 57% 意味着**拒答不是控制手段**；控制必须在工具与权限层。

**二，演练不可复现。** 每次攻击不同、环境不同；**没有固定语料与 harness，结果不可比**。

**三，止住标准模糊。** 「发现」容易，「止住」难；**没有「多久内切断」的 SLO**，演练就只是演示。

**四，行动半径差异大。** 只读、可写、可转账的 Agent 不能用同一套演练；**不分级，演练结论无法复用**。

**五，红队与蓝队脱节。** 红队发现的问题进不了工程待办；**没有 owner 与期限，报告就归档了**（146 期）。

**六，演练伤害生产。** 真打可能触发真实动作；**没有沙箱与回滚，团队不敢练**。

**七，跨租户演练会越界。** 打 A 租户的注入，可能影响 B；**演练本身要先过隔离与授权**（121 期）。

**八，合规不认「演练」。** 审计要证据链；**演练记录若不进审计系统，等于没发生**（114 期）。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `drill.*` 字段**：`drill_id`、`surface`（prompt/tool/data）、`payload`、`agent`、`action_radius`、`detected_at`、`contained_at`。
- **R2 攻击语料库**：按三类面维护可复现 payload；**版本化，随新攻击更新**。
- **R3 演练 harness**：沙箱＋可回滚；**真实工具用模拟替身**。
- **R4 止住标准**：定义「发现时长」与「止住时长」目标；**未达标视为失败**。
- **R5 分级演练**：按行动半径（只读/可写/可转账）设不同通过线。
- **R6 闭环**：发现→控制项→复测；**每条 finding 有 owner 与期限**。

### 5.2 用户旅程

- **红队**：季度演练 → 用 30 条语料打 5 个 Agent → 记录成功率、发现时长、止住时长 → 语料入库。
- **平台工程师**：发现工具描述投毒成功 → 加签名校验（137）→ 复测通过。
- **SRE**：演练触发真实告警 → 验证检测链路 → 修检测规则。
- **审计**：看季度报告 → 成功率、发现时长、止住时长三条曲线 → 确认在改善。

### 5.3 实现方案（90 天）

- **0–30 天：建语料。** 收集 30 条三类 payload；搭沙箱 harness。
- **30–60 天：首轮演练。** 5 个高行动半径 Agent；记录基线；修复 top 3。
- **60–90 天：常态化。** 季度演练；finding 进待办；指标看板；语料每季扩充 10 条。

**第 100 个市场空白（五项）**：三类面语料覆盖率、演练可复现率、发现时长可报率、止住时长可报率、finding 闭环率——无一内建；`drill.*`／`redteam.*` 为**第 67 次无人提字段族**。本地 173／173-kb 连续第 60 期成组启用：周昕毅 10「白名单动作、危险动作需审批」＝全库唯一把「哪些动作必须拦」写成硬规则的实践，本期首次当主线；配 95 期收容、137 期工具身份。判词：**本地把「危险动作」写成白名单，联网侧 2025 年才量出「57% 注入成功率」；两边都没把「演练的发现时长与止住时长」做成季度指标。**
