# AI-SRE 技术洞察 · 第 93 期

**时间**：2026-11-06 20:00（GMT+8）　**观察窗口**：2026-10-07 ~ 11-06
**本期主线**：第八十四条 · 架构面／脚手架面（Scaffolding / Orchestration Debt）
**题眼**：*前 92 期一直在补「还缺哪层制度」，本期反过来问「已经加上的那些层，本身是不是故障源」*；更尖锐的是——**同一个月，同一家公司一边卖千体自动编排，一边发迁移套件劝你把子智能体并回去**。

**与往期划界**：第 29 期管「接缝怎么不漏」，本期管「要不要有接缝」这个前置决策；92 期是外部被动变更，本期是我方主动加层却同样不进变更流；与 83 证据分母、73 计量单位之别在于，这里问的是**架构复杂度的计量单位**；改的是拓扑，不是 85 的一次运行或 91 的一次写。第 29 期留下的「多智能体须击败单 agent 基线」候选，本期用一手消融正式兑现。

## 一、发展趋势：加层与减层在同一个月撞车

**加层派仍在加速**。10-09 Anthropic Dynamic Workflows 公测（Claude 自写编排程序、单工作流最多 1000 体、64 路并行）；10-22 Google Cloud 发布 ACE／Agent Substrate，11-05 捐给 CNCF；10-14 NeuBird 把 ARC 做成 access／memory／serve 三层加 Suggest／Recommend／Act 三档；11-03 同日 PagerDuty Paige GA（并行假设、Scribe／Shift／Insights 分工、750 余集成）与 Honeycomb Team Agents 早期访问；国内 10-29/30 腾讯把 CloudQ 定位为可嵌入自建体系的「AI 调用 AI」并推出 Agent Hosting 等托管矩阵，11-03 火山 AgentKit 新增「中间层 Agent 进访问规则」支持多 Agent 串联。

**减层派同月给出反证，而且来自同一批人**。10-25 前后 Anthropic 应用 AI 团队建议把成群子智能体并回单 agent：架构复刻组织图（「智能体版康威定律」）、提示词被堆成「Frankenprompt」、每次交接丢上下文、Claude Code 系统提示词已砍掉 80% 以上、单 agent 约快一倍、工具描述超过 30–50 个选择质量退化。10-26 arXiv 2610.35767 用 RCAtlas（8 个公开数据集、90 个已验证事故、6 模型×3 推理强度）给出更硬结论：不规定任何一次模型调用的简单脚手架 PR@1 达 65–77%，五种已发表 RCA 智能体仅 16–53%，非 LLM 方法 6–39%，在每个共同跑过的模型上都成立。同期 NOFire 公开删掉大部分智能体的复盘，11-05 Radar 以「单 agent + 唯一 MCP 入口」登上 SREGym 榜首。

**判断**：这不是路线之争，而是**架构第一次被当成可证伪的工程假设**；此前加层是「更生产级」的同义词，现在它必须自证。

## 二、技术现状：层的收益被记在功能页，层的成本记在别处

**预设路径会跳过决定性证据**。SOP 编码的是作者记得住的上季度故障，生产事故却活在长尾；调查路线在事故暴露前就决定了去哪看。案例里 cart 错误率飙升看似元凶，SQL 智能体查了 31 次才找到 inventory 请求量归零——硬编码阶段把这一步省掉了。五种已发表智能体把十分之一到全部模型调用写死在程序里。

**层数没有单位，也没有分母**。角色 agent、SOP 阶段、审批层、记忆层、验证器、检查点、路由层、接口层算不算一层，全行业无共识；于是既答不出有几层，也答不出「多这一层值不值」。同批 10-26 四篇论文揭开隐藏成本：2610.34491 称推理强度是「信任品」，简单任务最高档成本达最低档 42 倍，额外开销多用于反复自查；2610.34298 的 MCP／CLI 匹配实验在 2004 个 episode 中 94.3% 行为结构性不同，**接口本身就是一层**；2610.33178 的 AOS-Bench 里自管任务队列使 73% 重负载任务无人认领、CPU 中位数不足 30%，固定并发 2 却逼近最优——自管理调度层是净负价值；2610.34577 横比 17 种验证设计，独立 critic 以 1.13–1.25 倍成本换 5.9–9.5 分，completion gate 能赢更多却引爆账单。**验证也有最优点**，深化 86 期「验证是纯支出」。

**最贵的一层不在架构图上**。11-03 信通院云大所《迈向 Agentic Ops》把「流程衔接不足」写进四方面保障：结论若游离于事件、工单和变更流程之外，仍需人工转录与协调，**效率收益就会被额外成本抵消**；同文批评评价「侧重答案准确率，恢复效果、成本及人工投入评价不足」。人肉胶水是一层，却没有 owner 与 SLI。11-04 四项书面记录（成功率、人工接管比例、单任务成本、异常响应时长）无一涉及架构复杂度或基线对照，OTel GenAI 11-02 仍全量 Development——自 72 期 identity 起第 16 个待提字段族 `scaffold.*` 仍无人认领。

## 四、技术挑战：加层是变更，减层是不可逆变更

**其一，加固从不进变更流**。92 期指出外部工具定义变更不进我方 CAB；本期补上对称的一半：主动新增一层角色、一个审批档、一道验证器，同样不改版本号、不做灰度、不登记回滚点。它是「功能发布」，减层是「迁移建议」——两者都不在事故复盘的「最近变更」列表里。**其二，SOP 是制度上线得太早**：整个系列追问「制度还没上线」，这里补一句反转——**已经上线的制度若具体到写死调查步骤，反而是长尾盲区的制造者**，治理不该只问覆盖率，还要问它有没有挡住本该看到的证据。

**其三，减层本身高危且无回滚语义**。Anthropic 自己的客服智能体合并后时延降了，原本可用的流程却坏了：主 agent 握着订单查询工具，便自行作答而不再去问配送专家。因此迁移套件要求 eval 覆盖每条生产调用链、每个任务至少跑两次以捕捉间歇性失败。这与 91 期「撤销也是一次动作」、85 期「在途换版」同构：**架构简化不能靠直觉，必须按不可逆动作治理，并保留旧拓扑快照可回切**。

**其四，基准仍在自我举证**。论文原话是各家「在自己的数据上对比少数基线」，已滑向 benchmark theater；厂商侧 94%、95%、80% 多为自述自跑，11-04 四项书面指标无一要求对照简单 harness。架构收益更需剔除模型升级、数据权限与题目泄漏的贡献。

**本地 173／173-kb 连续第十四期成组启用，升级为「减层判据原型」**：蒋烁淼 23「AgentOps 不是多一个机器人，而是补上服务语义与知识的统一目录」是题眼；肖汉松 22「**单 Agent 无法解决时须携带证据改派**，Loop 承接每一次交接」直接给出加层准入条件；孙鹏 11 以 BoRP「Read, Don't Write」删掉生成式 Judge（每十万会话成本 100%→3.2%），并自述裁判随模型与协议漂移＝**层会引入方差**；刘杨 08 以小模型＋正则粗筛 99% 流量、token 降本 90%+ 实证「简单判别器替代重型评估层」，并点明跨框架语义不一致即层间税；陶炳哲 30 把「模型＋harness」当可路由方案、何伟 02 六层职责、朱革 15 五层五中心，让层数第一次可数；王浩男 21 是本地侧反方：加层确有理由，但要付上下文税。判词：**联网侧 10 月才用 90 个事故证明「剧本是 bug」，本地讲义早把「何时才该加一层」写成硬判据、把「少一层」做成降本主项**；仍是项目内约定，不可采购。

## 五、展望与建议

1. **把架构当变更治理**。新增或删除任何一层均进 CAB：层注册表登记 `scaffold.layer_id／type／version／owner／added_at／ablation_ref／marginal_cost_ms＋tokens／bypassable／rollback_ref` 九字段，每层可单独旁路，事故单增设「生效层数与最近层变更」两栏。向 OTel GenAI 提 `scaffold.*` 第 16 族草案，与 85 期 `run.revision` 并列第三本账。
2. **设立编队准入判据**：任何新层上线前，必须在同一模型、同一工具、同一权限下击败「单 loop＋证据包」简单基线；采用 held-out 事故集、按题配对、每题多次、无 best-of-N、第三方裁判，并报告时延与 token 的帕累托位置。未击败即拒，采购合同附此对照结果。
3. **给层记边际账**：逐层采集额外时延、token、工具调用、交接丢失证据数，SLO 用「层成本占比」而非总量；推理强度默认最低档、仅在验证失败后升级，验证优先独立 critic 而非 completion gate，且验证层自身也要做消融。
4. **把人肉胶水画进架构图**：结论进事件/工单/变更的转录步骤须有 owner 与耗时，按信通院条款把衔接质量而非动作列为验收项；六维「可靠／效率」补格、11-04 四项指标补「基线对照」。
5. **减层按不可逆动作做**：全量端到端 eval 覆盖每条生产调用链、每任务至少两次、保留旧拓扑快照可回切；演练三型——预设 SOP 跳过长尾决定性证据、合并后主 agent 不再转专家、某层被静默禁用却无人察觉（与 92 期能力漂移联动）。

**结论**：79 编制、88 授权、89 少做、90 等着、91 退得回来、92 用的还是不是当初批准的能力之后，**「这一层该不该在」也还没上线**。本期新增的判词是：治理的对象不只是缺失，还包括冗余；一个无法证明自身边际价值的层，与一个从未上线的制度，在事故复盘里同样不可见。
