# AI-SRE 领域技术洞察报告（第 308 期）

**生成时间**：2026-11-24 05:00（北京时间）　**主题**：举证负担面／可举证性的边际成本（Evidence Burden / Verification Overhead / The Marginal Cost of Auditability）

---

## 题眼

过去十四期（#294–#307），我们给 SRE Agent 加了一层又一层"可举证"门禁：证据要保真、置信要校准、审批要完整、复核要独立、检测要溯源、边界要可证、撤销要可验。每一条都要求它拿出证据证明自己没做错。但没人算过这笔账——**举证本身要花 token、花工具调用、花时间、还要花一个独立复核者**。Causely 的公开基准给出了一个反直觉的注脚：给 Agent 更多因果证据，工具调用从 19 降到 4、token 从 308K 降到 123K、误报从 4/12 降到 1/12；而"多查一轮"反而更贵、更容易找到看似合理的错答案。这说明举证有方向之分：给证据可以减负，逼自证却在加负。本期首次把"举证负担"立为一等治理对象，指出一个被系统性忽略的剪刀差——token 单价在跌，agentic 任务成本却在涨，而举证就藏在这个差额里。**核心新观点：可举证性不是越高越好的单调指标，而是有最优解的凸函数；当举证强度超过自治收益，治理就开始扼杀自治。**

---

## 一、发展趋势

2026 年 11 月最显眼的趋势是"降价"：11 月 9 日至 18 日十天内，Anthropic 发布 Claude Fable 5.2（输入/输出 $8/$40，降 20%）、OpenAI 发布 GPT-6.2 Astra/Sol（Astra 同价降 20%、缓存输入再降 60%）、Google 接连发布 Gemini 4 Carbon/Hydrogen/Neon（降 20–50%）。Artificial Analysis 智能指数 v5 上四款旗舰差距已收窄到 5 分以内。行业叙事是"agentic workflow 从六位数的企业预算走进 20 人公司"。

但同一批数据里藏着相反的趋势。**token 单价不是任务单价**。ProcessRaven 对 78 个常见工作流的实测中位成本是 $0.47，是单条 chat 的 20 倍；最贵的 17 步应付流程达 $3.85。Artificial Analysis 测 Fable 5.2 在最大 effort 下每任务 $26.54，几乎是上一代 $12.99 的两倍——因为"允许想更久"让它多吐出 69% 的输出 token。Accenture 对 750 名高管的调研更直白：95% 的组织表示若 token 降价 25% 会扩大用例而非省下预算，预计未来 24 个月 token 消耗涨 78%，而单价只跌 19%。这就是 Jevons 悖论在 Agent 领域的翻版：**账单不会降，只会换一个地方涨**。

对 SRE Agent 而言，这个"换地方涨"就是举证。过去一年可观测厂商把"用可观测管 AI"写进产品主线：腾讯云把 Token 消耗、工具调用与任务质量关联下钻；阿里云把 Agent 自身运行轨迹、成本与质量纳入可观测；LLM Digest 把 per-task metering 称为"你无法控制你无法计量的东西"的底座。所有这些能力的共同点，是它们都需要 Agent 额外产出可计量、可回放、可独立复核的材料——也就是本期所说的举证负担。

## 二、技术现状

当前举证能力散落在三层，且彼此没有统一账本。

**第一层是取证**：决定"这次决策该看哪些证据"。Causely 通过 MCP server 把因果图交给 Agent，让它在开查之前就知道故障如何传播；其九项自查清单中，"最近十个可靠性 PR 里有几个改的是告警的服务而非致因的服务""让 Agent 说出排除了什么"都属于把隐性推理显性化。New Relic Autopilot Kubernetes Agent（11 月 10 日 KubeCon 发布，public preview）跑 90 多个诊断探测器，基于 OTel 的 Ground Truth 上下文引擎定位根因并生成修复代码，但把执行权留给人。ScienceLogic Skylar AI 2.8 提供带引用的发现、置信分与审批门控的修复计划。

**第二层是留痕**：把决策过程写成可审计材料。ResolveAI 11 月 18 日发布的 SRE-1（27B、纯 RL 后训练）把"no peeking"写进训练——每个工具都被钉在告警触发的那一刻，模型无法从后来的提交或工单里读到答案。这是一种前置举证：训练阶段就杜绝后见之明。其 Primary On-call 自测称 80% 寻呼不升级、Salesforce 暗启动关掉 70% 寻呼。

**第三层是复核**：由第二方验证举证是否成立。Jimmy Nguyen 用同一款 Opus 5.5、同一套 prompt 和工具，对三种 Agent SDK 跑了 8 类故障共 24 次，全部成功恢复且根因正确，但单次事故成本是 Claude Agent SDK $1.44、OpenAI Agents SDK $3.73、Google ADK $4.43——2.6 到 3.1 倍的差距主要来自缓存是否默认开启：On-call 循环每轮重发对话，Claude SDK 自动加缓存断点，几乎全部输入按 $0.20/M 的缓存读计费，另两家经 LiteLLM 需手动开启。这里的关键洞察是：**举证材料（trace、decision packet）恰恰是最需要被反复重放的上下文，缓存失效会直接让举证成本翻倍**。

三层的共同缺口是：没有一层在计量"这次举证花了多少、由谁承担、值不值"。

## 三、技术竞争力

下表从"举证负担"这一新维度对主流方案做对比。"举证分级"指是否按决策风险调整举证强度；"净收益可见性"指能否导出自治收益减去举证成本后的净值。

| 方案 | 举证/证据能力 | 成本计量粒度 | 举证分级 | 缓存/复用 | 独立复核 | 净收益可见性 |
|---|---|---|---|---|---|---|
| Causely（因果 MCP） | 强：因果图+排除项+九项自查 | 中：tool call/token 基准可见 | 无 | 中：因果上下文复用 | 部分：判据可审 | 部分：仅基准口径 |
| ResolveAI SRE-1 | 强：no peeking+引用因果链 | 中：约 1/5 前沿成本自报 | 无 | 未公开 | 有：LLM judge 评分 | 弱：无成本账本 |
| New Relic Autopilot K8s | 中：90+ 探测器+OTel 上下文 | 中：平台级用量分析 | 有：HITL 保留执行权 | 弱 | 有：人审批 | 弱 |
| ScienceLogic Skylar 2.8 | 中：带引用发现+置信分 | 中：能力集而非成本集 | 有：审批门控修复 | 未公开 | 有：审批墙 | 弱 |
| ControlTheory Dstl8 2.0 | 中：自处理日志/指标/追踪 | 弱：主打省摄取成本 | 无 | 中：蒸馏复用 | 无 | 弱 |
| Claude Agent SDK | 中：原生工具追踪语义 | 强：缓存命中细到 token | 无 | 强：默认缓存断点 | 无 | 部分：需自行记账 |

判词：**per-task metering、hard caps、缓存、因果上下文、专用小模型、自研评测几乎每项已可采购或自建；但把举证本身当成有边际成本的一等对象——记清谁承担了这次取证/复核/重放的 token 与时间、举证占总成本几成、自治净收益是否仍为正、举证强度是否按可逆性与爆炸半径分级——全表几乎无人填满。**

## 四、技术挑战

**挑战一：举证与调查质量互相打架。** #304 已指出探针次数即多重比较次数，查得越多越可能拟合出错因果。而新增的举证要求（多写一份 decision packet、多跑一个独立复核 Agent）本质上都是额外查询与额外重放。Causely 判词"每一次额外查询都给 Agent 多一次找到拟合解释的机会"在此同样成立。两个治理目标——"查得充分"与"举证充分"——在成本层面是竞争关系，现有门禁却要求两者同时最大化。

**挑战二：成本单位错配与估算失准。** LLM Digest 指出，成本估算屡屡漏掉区域溢价、prompt caching 在网关后静默失效，而最强的省钱声明大多没有公开方法论。举证材料往往跨多个模型、多次重放，其真实成本比单次调用更难估算。12 月 1 日 Gemini 4 Carbon 价格翻倍这类"促销价到期"，更会让按当前单价算出的举证预算在月中失效。

**挑战三：硬上限与长任务的冲突。** 预算护栏能保护支出，但可能在一个本该完成的长任务最糟糕的时刻把它掐断。llm-digest 明确要求"优雅降级而非硬杀"。对 SRE Agent 而言，一次正在收敛的故障调查如果因举证开销触发硬上限而中断，损失远大于超支——这需要 gracefull pause 与可恢复的检查点，而非简单熔断。

**挑战四：负担最终会转移到人。** 当举证强度超过自治收益，理性选择是退回"人来做"，因为人做决策不需要向自己举证。但合规要求人做同样要被审计，于是举证负担从机器转移到人——这正是 #102 提到的值班台空转与 deskilling 的经济学根源。举证不会消失，只会换一个承担者。

## 五、展望与建议

**提出第 229 号空白字段族 `evidence.burden.*`**：

- `burden_ledger[]`：`{phase, tokens, tool_calls, latency_ms, cost_usd, borne_by ∈ agent|human|reviewer}`——按取证/留痕/复核三阶段分栏记账
- `evidence_direction ∈ INWARD|OUTWARD|PREEMPTIVE`（自证／给人看／决策前取证）
- `evidence_tier ∈ SAMPLE|STANDARD|FULL|INDEPENDENT`（抽样／标准／完整／独立复核）
- `tier_basis`：`{reversibility, blast_radius, frequency, regulatory}`——分级依据
- `marginal_cost_per_verification_usd`、`benefit_of_autonomy_usd`、`net_gain_usd = benefit − burden`
- `burden_share_of_total`（举证占总成本比例）、`provenance_cache_hit_rate`（举证材料缓存复用率）
- `verdict ∈ WORTH_IT|MARGINAL|BURDEN_EXCEEDS_BENEFIT|UNKNOWN`

配套 **BURDEN_UNVERIFIED 门禁**：无举证成本账本、`net_gain` 为负仍继续自治的，应判为"治理失败"而非"治理更强"。

**落地建议**：

1. **建举证账本**：每个自治动作在出口处落 burden_ledger，五类成本分栏、三方承担者分开记——与 #301 带外账本共用出口，但多记"举证"这一列。
2. **分层举证矩阵**：用"可逆性 × 爆炸半径 × 频率 × 监管"四维把过去十四期散落的门禁编排成四档。重启单个 pod（高可逆、低半径、高频）事后抽样举证即可；改限流阈值、删数据（低可逆、高半径、低频）走事前 FULL + INDEPENDENT。避免每层都按最高标准要求，这是把凸函数拉回最优点的关键。
3. **net_gain 触发自治降级评审**：当净值转负，正确的反应是降低举证强度或收回自治权，而不是继续加门禁。
4. **举证材料缓存复用**：decision packet 与 trace 走稳定缓存断点，监控 `provenance_cache_hit_rate`——这是把 2.6–3.1 倍 SDK 差价转化为治理收益的直接杠杆。
5. **评测增列**：在 cost-per-solved-task 旁并列 cost-per-verified-task，报告"验证一个正确答案的边际成本"，并给 with/without 因果上下文双轨。
6. **采购三问**：能否导出单次事故的完整举证总成本？能否按决策类型分级举证而非一刀切？缓存失效时举证成本会涨多少？
7. **标准补格**：建议信通院《云上 Agent 基准度量模型》在"成本效益"维度补"举证经济性"一格，成十五层治理末环。

**本地原型（第 184 期新角度）**：陶炳哲《智能路由不只是选模型：Harness、任务评测与成本优化实践》过去读作"路由决策即运行时变量"，本期首次读作"每一次路由选择也是一次成本与举证的取舍——选更贵的模型可能是为了少查几轮、少举证几次"；配刘凯宁蚂蚁 SRE"三分"扩第十九分"这次结论的举证花了多少"、蒋烁淼"秒查"改读"对可以很贵，贵在举证"、余锦泽"记忆不在对话里"改读"缓存命中就是记忆的经济学"、孙鹏探测式评测从"探测要被计分"扩到"探测要被计价"。

**差异化声明**：本期不新增一条"可举证率"门禁，而是对过去十四期的门禁做元层收敛——首次指出可举证性有边际成本、有最优强度、有承担者转移，并把举证方向（向内／向外／前置）与举证分级立为可导出字段。这是与 #294–#307 各期"逐层加门禁"相反方向的梳理澄清。
