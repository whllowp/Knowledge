# 记忆技术洞察 第70期（20261113-0200）：记忆的"条件效用"——价值取决于未来任务而非内在重要性

> 生成时间：2026-11-13 02:34 (GMT+8) ｜ 领域：AgentMemory ｜ 范围：2026 全年，重点近 30 天
> **本期新观点**：记忆的价值是"任务条件"的，不是"内在"的。行业通行的单一重要性打分（Mem0/Letta 式 importance、Hy-Memory 的 confidence）在范式上被错配——同一段记忆帮得上某个未来任务、却对另一个毫无用处。

## 四维度速览
- **发展趋势**：从"记什么"（写入侧）转向"记下的东西对谁有用"（效用侧）；任务条件效用（Task-Conditioned Utility）成为新评价单元。
- **技术现状**：arXiv 2611.03930（11-02）首次把效用从单分数改为 (记忆, 任务对) 配对收益；OpenViking v0.5.4（11-09）把工具读/写/破坏性三态隔离做成产品事实，延续第 69 期主线。
- **技术竞争力**：AML 二期实时榜已开（MemoraX 58.02 居首，TencentDB 第 7=41.48、Mem0 第 8=41.40），官方榜延至 11-19；能力剖面含事实/组合/时序/治理/个性化/安全，唯独没有"效用/压缩"维度。
- **技术挑战**：压缩与效用的张力——结构化摘要即便在同等上下文预算下也弱于原始记忆；把"将来才有用"的效用在写入时压缩掉，是行业隐性债务。

## 一、需求分析
长期记忆默认一条记忆有"内在重要性"（全局打分、阈值保留）。但 2611.03930 用 task-blind writer + frozen reader 证明：同一段记忆在"承载答案的任务对"上的配对收益增益（+0.33，95%CI +0.21~+0.46）显著高于匹配对照组，而对软件工程/科学编码基准"几乎零可测效果"。重要性不是记忆的属性，而是"记忆 × 未来任务"的关系。需求被改写：系统要答的不是"这条记忆重要吗"，而是"它对 Agent 下一个真实任务有多少条件效用"。这对第 5 期"记忆 NPV"、第 30 期"利用率/送达"是补刀——净现值乘子从"复用次数"升级为"任务条件收益"。

## 二、用户旅程
一段记忆的生命周期：①写入（task-blind，写时看不到未来任务）→ ②巩固/压缩（L0/L1/L2，行业默认此处摘要化）→ ③检索（generic retrieval 虽高于随机，却漏掉大多数"答案承载记忆"）→ ④送达（2611.08718 揭示"检索候选"与"最终展示"间存在暴露瓶颈 exposure bottleneck，+28.9pp 接受度来自编排而非重排）→ ⑤使用（效用在 Agent 真正解题时才兑现）。断点在 ②③：我们在不知未来任务时就把记忆压成结构化摘要，而 2611.03930 显示结构化摘要在固定上下文下增益反而小于 Raw——压缩在 store-time 提前支付了"任务条件效用"的税。

## 三、具体实现方案
1. **任务条件效用账本（TCU Ledger）**：在"成本三段/记忆 NPV 账本"（第 5、11 期）上新增 (memory_id, task_pair) 配对收益列，保留 Conditional Memory Utility Dataset 式标注；以条件效用而非内在重要性作保留/召回门控。
2. **压缩延后到查询时**：原始记忆与结构化视图并存，按任务动态生成摘要，避免 2611.03930 的"写入即失真"；Hy-Memory 的 lite/pro/ultra（ultra 夜间自动整理）应改为"保留 Raw、仅生成视图"。
3. **暴露瓶颈治理**：在检索与展示间引入"候选→展示"可观测层（SCS 式语义一致分），把 2611.08718 的 exposure bottleneck 变成计量指标；TencentDB 的 drill-down 链（persona→scenario→atom→raw）天然适合做证据回溯。
4. **AML 二期利用**：实时榜（11-19 前）按能力剖面排、缺效用维度；可在自有系统侧补一组 task-conditioned 评测，作厂商宣传分的对照。
