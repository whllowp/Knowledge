# AI-SRE 技术洞察（第 53 期）

## 注意力面运维：当"读完"成为运维里最稀缺的资源

**2026-11-03 18:00 · 覆盖 2026 年（重点 10-04 至 11-03）**

---

## 一、发展趋势

10 月 31 日晚，DeepSeek Harness 团队发布《Super-agent 设计探索》，其中一句被反复转引："单任务的上限取决于模型能力，多任务的上限取决于人的注意力。"他们给出的经验值是：一个人同时只能跟进 3 到 5 个活跃会话。11 月 2 日，OpenAI 宣布把关键漏洞发现赏金提高到原来的四倍以上（含奖金最高 17.2 万美元），理由是"AI 发现漏洞的能力变强，防御方要先用起来"。GitHub 的 Octoverse 数据在 10 月给出另一面：2026 年 9 月平台产生 73.8 亿次提交，是上年同期五倍多；agent 发起的 PR 占比从半年前的 17% 升到 40% 以上；10 月 7 日平台发生超过两小时的全球宕机。

三件事指向同一个转折：竞争焦点正从"agent 能做多少"移到"人能读完多少"。模型厂在架构层承认注意力是硬约束，应用厂在价格层为核验加价，平台方在容量层替全网的试错买单。前 52 期讨论的都是系统如何变坏、如何变好、如何被证明；这一期讨论一件更朴素的事——**系统说的话，组织吃不吃得下**。

## 二、技术现状

**（1）供给侧：生成成本已经坍塌，且有硬数字。** Faros AI《The Acceleration Whiplash》（2026-04，约 2.2 万名开发者、4000+ 团队、两年遥测）给本期定基准：高 AI 采用团队合并 PR 数 +98%，单 PR 评审时间 +91%，PR 体积 +154%。LinearB 对 810 万个 PR 的分析补上结果侧：AI 生成 PR 等待首次人工评审为人类的 4.6 倍，接受率 32.7%，人类 84.4%。安全侧量级更极端：Elastic 的 HackerOne 项目 2026 上半年收到 1390 多份报告，超过 2024 与 2025 两年总和（历史区间 600–850/年）。国内一手样本是阿里 Open Code Review：两年运行数百万评审任务，"总体评审建议同比翻倍"，人类转向复杂问题。

**（2）消纳侧：两种工程回应——限流与分诊。** 限流最粗暴也最有效：GitHub 7 月 27 日起把漏洞赏金改为两级制以过滤 AI 生成报告；curl、Ghostty、tldraw 直接关闭或限缩外部 PR 入口。分诊更精细：Elastic 用两个隔离的临时 VM 跑八阶段分析加独立对抗审查，单份报告成本压到约 2 美元，与人工一致率 85%（764 份已知结果验证），70% 在分析阶段即被拒，人保留最终裁决；Anthropic 的 oncall-kit 把"要不要叫醒人"写成 oncall.md 的确定性规则（"错误率>2% 持续 5 分钟且非变更窗口才 page，否则写入 lessons.md"），首份有证据的分析中位 14 分钟；Datadog Bits AI SRE 用"假设—用实时遥测验证—递归深挖"回路，单次调查 3–4 分钟；PagerDuty 用六种分组加自动暂停做到最高 91% 降噪。

**（3）第三种回应没有名字：降标消纳。** 队列不会无限增长，它会自己"解决"——通过降低门槛。四个台阶依次是：不看就合（约 31% 的 PR 零人工评审即合并；GitHub 上 agent PR 两周合并率 90%，反而高于人类的 86%，而 agent PR 有 87% 涉及多文件）；看了不验（只读摘要与自述）；验不复现（接受报告结论）；复现不追因（止于症状）。**队列不会杀死系统，降标才会**——队列长是可见的，降标是不可见的，且它以"效率提升"的面目出现。

消纳质量并非不可改善。XTransfer 的问题采纳率从 40% 升到 67% 再到 85%，说明"建议被采纳的比例"可以被反馈飞轮推高；阿里内部评审建议量翻倍的同时把人力转向复杂问题，是同一种腾挪。但两者量的都是"被采纳的比例"，不是"被误关的比例"——前者有分母，后者没有。这就是本期要补的那一格。

**（4）注意力被工程化。** DeepSeek 的设计原则写在文档第一行："尽可能少占用人的注意力，尽可能多给出价值。"实现是三件事：两级过滤（程序规则零成本筛闲聊，语义层才判是否接单）、投机执行（后台先做，有价值才提交）、只在"需要决策/结果可用/无法继续"时开口。约 300 条消息含 20 项真实请求的实验中，Super-agent 完成时间 p50 12.4 分钟、p95 15.7 分钟，对照单会话方案为 20.4/29.5 分钟；代价是缓存读取 token 2320 万 vs 610 万，关掉订阅直通后 Router 决策次数 +30%、缓存读 +37%。含义清楚：**并行不免费，它把成本从"等人的时间"换成了"上下文周转"。**

## 三、技术竞争力

两段判读。其一，海外把"分诊"做成了产品，计量单位是"每份报告/每次调查多少钱"；国内把"降噪比"做成了营销数字（99%、10000:1、10 万→100 条）。两者都不回答同一个问题：被关掉的东西里有多少是真的。其二，六列中"关闭与复发追踪""消纳/误杀度量"几乎全红。这是继幂等并发、断网重放、视图指纹、截断率、该说没说、图谱边标准、证据权限分离、时钟证据、只读三证、恢复证据之后的**第十一个市场空白**，也是唯一一个"补上就能立刻降风险"的空白——因为它量的是别人不敢量的东西。Anthropic 的形态最接近"注意力治理"，但规则住在 markdown 里，不可审计、不可回滚、无法跨团队复用，恰是 30 期"知识债"在治理层的复现。

## 四、技术挑战

**降噪率是自证指标。** 关得越多降得越多，因此它永远好看；真正要量的是误杀率——真问题被静默关闭的比例，而它只能靠抽样复核获得。抽样成本是永久的、不随规模摊薄，这意味着"消纳"这件事没有规模效应。

**CLOSED≠处理了。** 关闭是最便宜的动作，因此会被系统性滥用为消化手段。需要"关闭证据"：谁关、依据什么、谁复核、复发怎么发现、什么条件下复活。这是 52 期"COMPLETED≠恢复了"在待办侧的镜像。

**agent 互相喂养。** 生产者、分诊者、修复者、复核者全是 agent，闭环里唯一的人类环节变成限流阀。一旦限流阀失效，系统会自我确认——这是 49 期"证据—解释—权限三者分离"的直接推论：当解释者与证据生产者同源，闭环内没有任何东西能证伪它。

**注意力没有账本。** 夜间一条 page 与白天一条工单不等价，疲劳非线性，注意力不可跨团队转移、不可存储。现行 SLO 里没有任何一条覆盖"人的可分配注意力"，因此过载永远表现为"人离职"而不是"指标越线"。**中断权也缺位**：谁能叫醒人目前由各工具默认值决定，既无授权也无配额。45 期分过"发言权限 vs 动作权限"，本期要补第三条——中断权，即能不能占用人的当下。

## 五、展望与建议

1. **三个指标先落地**：消纳率（本周读完并做出判断的工作项 ÷ 本周产出）、误杀率（抽样复核中"本应处理"的已关闭项占比）、待办年龄 p90（产生到首次被人读到）。三者均可从现有工单/PR/告警系统算出，不需新采集。
2. **按核验工时计价**：给每个 agent 产出附"预计核验分钟"字段，超出团队周预算的产出不予生成。这是 33 期"配给面"的镜像——那期管 token 配额，本期管**核验配额**。
3. **中断权三级化**：立即（page）/ 本班内（队列）/ 只写日志；授予、审计、夜间配额三者齐备才允许升级。
4. **关闭证据五字段**（谁 / 依据 / 复核人 / 复发监测 / 复活条件）进工单模板与审计。
5. **给尺子配尺子**：每周固定 30 条抽样复核预算、专人轮值；它的产出不是"发现几个问题"，而是"我们的关闭动作有多可信"。

2026 年的运维风险，正在从"系统坏了没人修"变成"系统说了没人读完，而所有人都以为读完了"。
