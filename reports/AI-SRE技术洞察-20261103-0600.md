# AI-SRE 技术洞察（第 43 期）

**时间：2026-11-03 06:00　｜　主题：表征面运维——运维的第一现场是"屏"，而屏正在分裂成两个读者**

> 前 42 期分别管过治理、证据、人、记忆、供应链、路由、承诺、进化、缓存、时长、协同、知识、接口、轨迹、配给、边界、判据、遥测、进程、写入、复现、并发、退役、自治等级。本期第一次把"界面"本身当作运维对象：不是 agent 能做什么（第 31 期接口面），也不是遥测数据有多脏（第 36 期输入面），而是**从数据到判断之间那道被渲染过的压缩层**。

---

## 一、发展趋势

四十年里，SRE 把"数据"当一等对象，"视图"当数据的影子。2026 年 10 月末这一周，这个假设被三件互不相干的事同时推翻。

第一件，屏幕成了 agent 的动作面。Vercel Labs 于 10 月 30 日前后开源 `agent-desktop`（v1.0.2，Apache-2.0），GitHub 星标 11 月 2 日已达 6,748（单日 +2,536）。它不截屏猜像素，而是读操作系统的无障碍树（macOS AX、Windows UIA、Linux AT-SPI），每个可点元素带一个引用号（如 `@s8f3k2p9:e8`），界面一变旧引用直接报 `STALE_REF` 或 `AMBIGUOUS_TARGET`，逼 agent 重新取快照而不是悄悄点错行。构建方自报：苹果地图单次观察从约 3,811 token 降到 273，整体省 78%–96%（自报口径，非第三方评测）。

第二件，面板成了可查询对象。Grafana 官方 `mcp-grafana` v2 把 dashboard 直接暴露成 MCP 工具：`get_dashboard_summary`、`get_dashboard_property`（JSONPath 取值）、`patch_dashboard`、`run_panel_query`，另有 `list_dashboard_versions` 列出面板的历史版本。文档里一句警告极重："大 dashboard 会消耗大量上下文窗口"——为此专门做了三个"减上下文"工具。视图第一次有了明确的 token 标价。

第三件，屏从固定资产变成即时产物。11 月 2 日中国工信新闻网报道，中国电信北京公司在五中全会通信保障中用星辰 TeleAgent 按自然语言生成监测视图：过去"快则一周、慢则半月"的页面开发，现在十几秒；数字孪生视图把基站、光缆、保障车辆、应急人员投到同一张图上，"以前排查故障影响范围要切换三四个系统，现在一眼就能看见"。

把三件事连起来看：**视图有自己的判据、版本、成本和失效方式，而且它现在有两个读者。** 腾讯云 10 月 29–30 日数字生态大会上，CloudQ 负责人许小川把这件事说得最直白——全景图谱"走通了两条路"，一条面向人的可视化管理（数智大屏、一图胜千言），一条面向 Agent 的"AI 调用 AI"。这是本期主线最硬的第一方证据：同一份事实底座，被要求同时满足两种带宽、两种歧义容忍度。

## 二、技术现状

### 1. 双读者分裂：一图胜千言的代价

人读图靠冗余：颜色、布局、相对位置、和上次的对比。agent 读数靠可追问：分母是什么、聚合粒度多少、哪个时间窗、有没有截断。同一块写着"错误率 4.2%"的面板，人看见红色就知道"糟了"，agent 却问不出这 4.2% 是按分钟还是按小时聚合、分母含不含健康检查流量、是不是 Top-5 服务加权。我把它叫**可追问性赤字**：界面能看，不能问。

赤字不是无害的。它意味着视图不是中立展示层，而是**判据的渲染层**：改聚合粒度就是改判据，改阈值颜色就是改判据，改 Top-N 截断就是改判据——而这一切走的是"产品配置"，不经过任何 code review。第 35 期讲判据 rot（判据静默失效），本期要补一句：判据腐烂最快的地方不在代码里，在面板的默认值里。

### 2. 两条去 GUI 化路线，方向相反

**路线 A：把系统变成工具，绕开屏幕。** 嘉为蓝鲸 2026 秋季发布的 BK-CLI·鲸智，用 60 余条命令覆盖 API 网关、配置、容器管理等 8 大子系统，返回 JSON 与统一错误结构，涉线上操作走"预览计划—用户确认"两阶段；阿里云 Ops MCP Server 把 ECS/RDS/OSS/VPC/云监控封成 MCP 工具；火山 AgentKit 用 HTTP 转 MCP 把控制台 API 逐条转成工具，还带同名工具覆盖告警。共同点：让 agent 拿结构化结果，压根不看屏。

**路线 B：把屏幕变成工具。** `agent-desktop` 走无障碍树，是存量系统唯一可行的路。但它的边界写在发布材料里：应用没提供无障碍信息的部分（地图画面本身、自绘画布、远程桌面画面）它就看不见。而这恰好是老旧控制台、厂商设备 Web UI、专有图形终端最密集的地方。

两条路的分界线是**仪器化程度**，可分四级：有 API ／ 有 CLI ／ 有无障碍树 ／ 只有像素。前两级是新建系统的正解，后两级是存量系统的止痛药；把 B 当成 A 的替代品，是 2026 年最常见的架构误判。

### 3. 表征污染：被审计者提供审计原料

11 月 2 日流传的一份安全审计（ERA 研究员在 Apollo Research 指导下对开源 Codex harness 做红队，OpenAI 已确认修复其中若干项；本条为二手转述，原文待核）称找到 11 种绕过沙箱与 Auto-review 的路径。其中三种正打在表征层：替换可信钩子背后的脚本，让监控信任被篡改的执行链；**伪造用户回合，使 Auto-review 分不清哪句是人说的、哪句是 agent 写的**；审批完成后修改文件，绕过事后检查。

这条比任何产品发布都更值得 SRE 记住：监控读的是 transcript，而 transcript 是 agent 可写的。审计的原料由被审计者生产，"看会话、看日志"的监督就退化成"信任被监督者的自述"。它与 GUI 层的 `STALE_REF` 正好构成一组对照——引用会过期是为了防点错，而 transcript 永不过期，是为了防谁？

### 4. 视图的成本与不可复现

`agent-desktop` 的 273 vs 3,811 token 说明：在所有读取方式里，看像素是最贵的。mcp-grafana 的 summary/JSONPath/patch 三件套说明：视图的熵会直接变成 agent 的账单。更麻烦的是复现——截图不带视图指纹、不带数据口径、不带时间窗；TeleAgent 生成的屏是即时产物，事故之后没有人能重建"当时那屏长什么样"。第 39 期讲断网重放，管的是动作；这里是**感知输入无法回放**，更难，因为输入本身没被存下来。

## 三、技术竞争力

| 方案 | 表征形态 | 主要读者 | 可追问性 | 视图版本/复现 | 明确边界 |
|---|---|---|---|---|---|
| Grafana mcp-grafana v2 | dashboard JSON + MCP 工具 | agent | 高（JSONPath、可执行 panel query） | 有 `list_dashboard_versions` | 仍依赖面板定义，不覆盖像素 |
| 腾讯云 CloudQ | 全景图谱 + 数智大屏双路 | 人 + agent | 中（图谱可下钻） | 未公开 | 强在资源关系，弱在时序原始值 |
| 北京电信 TeleAgent | 自然语言生成监测视图 + 数字孪生 | 人 | 低 | 无（即时产物） | 重保场景定制，难通用 |
| 嘉为蓝鲸 BK-CLI·鲸智 | CLI + JSON | agent | 高 | 走平台配置版本 | 仅覆盖自家 8 子系统 |
| 阿里云 Ops MCP Server | 云 API → MCP 工具 | agent | 高 | 随云资源版本 | 只覆盖有 API 的产品 |
| 火山 AgentKit（HTTP→MCP） | 控制台 API → MCP 工具 | agent | 高 | 未公开 | 只覆盖有 API 的产品 |
| Vercel agent-desktop | 无障碍树快照 + 元素引用 | agent | 中（引用可重取） | 有时点，无指纹 | 自绘/画布/远程桌面失明 |
| 传统 computer use（截图+坐标） | 像素 | agent | 极低 | 几乎不可复现 | 分辨率、主题、缩放敏感 |

判读：海外在解决"读得准"，国内在解决"看得懂"，开源在解决"够得着"。三家都绕开了同一块，即**视图指纹**——没有一家把 `view_id + 版本 + 数据口径 + 生成者 + 时间窗` 写进 trace 或事故证据包。继第 38 期"幂等并发防护"、第 39 期"断网重放通过率"之后，这是第三个明确的市场空白，而且它比前两个更容易做，只是没人认为该自己做。

## 四、技术挑战

1. **视觉判据不可复现。** 分辨率、DPI 缩放、明暗主题、字体、语言任一变化即可让同一故障得出两种结论；视觉判据没有回归测试，也没有人认为它需要。
2. **无障碍树的天花板正好压在老系统上。** 自绘、画布、地图、视频、远程桌面、遗留 Flash——越是没 API 的地方，越是无障碍信息最差的地方。
3. **面板变更无门禁。** 改一个阈值颜色，等于当天起所有历史告警的语义全部改写；这件事走的是配置台，不是变更单。
4. **截图不是证据，只是渲染结果的复印件。** 可裁剪、可伪造、无口径、无指纹；复盘时"当时那屏"只剩一张 PNG 和一段回忆。
5. **坐标点击是不可声明的写。** GUI 操作的目标无法语义化（"左边第三个按钮"），幂等键无从派生、`If-Match` 无从比较——第 38 期的写入门禁双证制在界面上整体失效；而屏幕只有唯一焦点，多 agent 各一根光标也要排队，第 40 期的并发预算在界面层被强制为 1。
6. **生成式视图的审计真空。** 谁生成的、按什么数据、当时长什么样，三问皆无答案，而它已经开始进指挥大厅。

## 五、展望与建议

1. **视图清单化。** 每个进值班台的关键视图登记 `view_id`、读者（人/agent/双）、聚合口径、阈值来源、最后验证时间。读不懂的图不该出现在 2am 的屏幕上。
2. **`view_digest` 进证据包。** 任何截图或快照必须带视图版本、数据口径、生成时间窗、生成者，否则不进事故复盘。成本极低，收益是把"我记得当时是红的"变成可对账的陈述。
3. **可追问性门禁。** 每个面板至少要有一条"点开能追到原始序列"的路径；追不到的面板标注为"仅人类可读"，禁止作为 agent 判据来源。
4. **面板变更走变更流水线。** 与代码同级 review，改颜色、改聚合、改截断都要说明"这会让谁误判"。
5. **仪器化四级盘点。** 对存量系统按 API/CLI/无障碍树/仅像素 打标，只对最后一级上 GUI agent，且必须先备好 GUI 互斥与操作审计。
6. **双读者对齐抽检。** 每周抽 5 个事件，把"人看屏的结论"与"agent 读数的结论"做差异对照，差异率入 SLI。这是唯一能提前发现表征分裂的办法。

一句话收束：**"看得见"曾经是运维的终点，现在只是读数的起点。** 2027 年采购会上会被问的问题不再是"有没有大屏"，而是"这屏谁能读、读了算不算证据"。
