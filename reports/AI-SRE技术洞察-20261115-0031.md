# AI-SRE 技术洞察（第 196 期）

**生成时间**：2026-11-15 00:31（北京时间）｜**窗口**：2026 年，重点最近 30 天
**本期主题**：流式面／增量面（Streaming）——Agent 边说边做；客户端断了，动作还在继续；用户看到一半，账单已经全付

---

## 题眼

91 期说「会话状态是唯一没有快照的东西」，180 期说背压，186 期说终止条件，191 期说结构化输出。四件事在**流式**场景里合成一个日常故障：**用户看着 Agent 一个字一个字回答，看到一半关掉页面/挂了电话；服务端不知道，模型继续生成、工具继续调用、副作用继续提交**。**用户以为「我取消了」，系统记录「任务完成」，账单按全量收。** 流式把「一次调用」拆成了「一串事件」——**而取消、计费、副作用提交，三个语义各说各话**。**流式不是传输方式，是状态机：开始、增量、提交、取消，四个状态要能对上。** **对不上，用户看到的和系统记的就是两件事。**

## 一、发展趋势

**趋势一：流式成为默认交互。** 首 token 延迟是体验；**但流式让「完成」的边界变模糊**。

**趋势二：取消开始端到端传播。** 客户端断开 → 服务端取消 → 工具停止；**不传播，就是白烧钱**（186 期）。

**趋势三：副作用提交与流式解耦。** 先说、后做、再提交；**不让「说了一半」变成「做了一半」**。**「说」可以流，「做」要等确认。**

## 二、技术现状：三种流，通常只流一种

**Token 流：最成熟。** 增量返回；**断连后模型可能继续生成**（143 期）。

**工具调用流：部分支持。** 工具参数流式拼接；**拼到一半断连，参数不完整**（191 期）。

**副作用提交：几乎不流式。** 边流边执行；**用户取消时已经改了三处**。

**现状：取消只取消「显示」。** 前端停了；**后端不知道，继续跑**。

**三种断连，一种比一种难处理。** 客户端主动关（最明确）、超时断（最常见）、进程崩（最难）；**三种在服务端看起来可能一样：连接没了**。

## 四、技术挑战

**一，断连不等于取消。** TCP 断了；**模型不知道，继续生成**。

**二，副作用已经发生。** 说了「正在退款」；**取消时退款已提交**（80 期）。

**三，计费按生成量。** 用户没看完；**token 已经算了**（143 期）。

**四，取消有延迟。** 取消信号到工具，中间有窗口；**窗口里又做了一步**。

**五，部分 JSON 无法解析。** 流到一半的 JSON；**解析失败，前端显示错**（191 期）。

**六，恢复语义不清。** 断线重连；**是续流、重放还是重跑**（184 期）。

**七，多端不同步。** 手机取消、桌面还在跑；**取消信号没有广播**。

## 五、需求分解、用户旅程与实现方案

### 5.1 需求（按优先级）

- **R1 `stream.*` 字段**：`stream_id`、`tokens_sent`、`cancelled_at`、`effects_committed[]`、`orphan`、`billed_tokens`。
- **R2 取消传播**：断连→取消→工具停；**全链路同一信号**。
- **R3 副作用边界**：先流后提交；**提交前可取消**。
- **R4 孤儿检测**：取消后仍提交的动作；**单独统计**。
- **R5 计费口径**：按发送/按生成分开记；**断连部分可解释**（165 期）。
- **R6 恢复语义**：续流/重放/重跑三选一；**显式声明**。

### 5.2 用户旅程

- **用户**：看到一半关页面 → 服务端收到断连 → 取消生成 → 未提交的副作用回滚 → 只计已发送。
- **SRE**：发现孤儿动作 → 查取消链路 → 修传播。
- **财务**：断连计费异常 → 查 `billed_tokens` → 确认口径。
- **审计**：抽查一次取消 → 核对副作用与计费 → 确认无孤儿。

### 5.3 实现方案（90 天）

- **0–30 天：埋点。** 流 ID、发送量、取消时刻、已提交动作。
- **30–60 天：传播。** 取消全链路；副作用提交边界。
- **60–90 天：对账。** 孤儿统计；计费口径；恢复语义；多端取消广播。

**第 137 个市场空白（五项）**：取消传播覆盖率、副作用边界覆盖率、孤儿动作可测率、断连计费可解释率、恢复语义明确率——无一内建；`stream.*`／`cancel.*` 为**第 106 次无人提字段族**。本地 173／173-kb 连续第 96 期成组启用：肖汉松 22「全局调度器：分派、等待」＝全库唯一把「等待」写成组件的实践，本期首次当主线；配 186 期终止、191 期输出。判词：**本地把等待写进调度器，联网侧 2026 年才把流式做成默认；两边都没把「取消后还有没有动作在跑」做成流字段。**
