# AI-SRE 技术洞察（第 247 期）

**生成时间**：2026-11-17 11:31（Asia/Shanghai）
**洞察窗口**：2026 年，重点为 2026-10-18 至 2026-11-17
**本期主题**：标记面／内容来源与水印（Content Provenance & Watermarking）——AI 说的话，能不能证明是它说的

## 题眼

欧盟 AI Act 第 50 条的透明度义务已于 **2026-08-02** 起可执行：生成式 AI 系统必须在合成音频、图像、视频、文本中嵌入机器可读标记，使内容可被检测为人工生成；聊天机器人须告知用户正在与 AI 交互；深度伪造须披露（Baker Botts，2026-09-09）。配套的《标记与标注行为准则》草案 2026-03-05 发布、最终版 **2026-06-09** 定稿，自愿遵守但会成为监管机构的实践参照（Licentium，2026-07-15）。技术侧同时发生两件事：C2PA 规范走到 **2.4**，新增 `c2pa.ai-disclosure` 断言与合成内容指南（2026-07）；而 2026-08-17 一个开源去水印工具在 GitHub 上拿到 11,000 星，声称能抹掉 Claude 的统计水印、SynthID-Text、OpenAI 隐形标记，并清掉 C2PA 与 EXIF（36kr，2026-08-17）。USENIX Security 2026 的 **MARKNULL**（2026-10-08）则给出了水印移除攻击的学术版本。一个荒诞细节：某 C2PA MCP 工具在 PyPI 上把截止日写成「2026-12-02」，与法定的 08-02 差四个月——供应链对期限的理解都没对齐。

## 一、发展趋势

**第一，标记从「平台自律」变成「法定义务」。** 2026 年 8 月之后，面向欧盟用户的生成式输出不带机器可读标记，是合规缺陷，不是体验问题。

**第二，两种技术路线并存且互补。** C2PA 是「签名的元数据清单」，绑在文件字节上；统计水印是「改采样骰子」，藏在 token 分布里。前者怕剥离，后者怕改写；一起用才覆盖「元数据被删」和「内容被转述」两种场景。

**第三，攻防已经产业化。** 一边是 C2PA SDK、SynthID、各家水印 API；另一边是开源 remover 与学术移除攻击。标记的强度不再是「有没有」，而是「被去掉要花多少成本、去掉后还能不能恢复」。

**第四，检测从「单点判定」走向「证据链」。** 检测器只给概率分；真正的举证要串起「生成时清单—分发时签名—转发后软绑定—争议时仲裁」。

**第五，Agent 输出成为新的标记对象。** Agent 起草的公告、工单回复、变更单，出事时要能回答「这是人写的还是 Agent 写的、哪版模型、谁授权发的」——这正好接上第 216 期三层校验与第 231 期责任链。

## 二、技术现状

**C2PA / Content Credentials 2.4**：资产字节做 SHA-256 硬绑定，清单存 JUMBF，claim 用 COSE_Sign1＋X.509 签名；任何字节改动都会让 claim 失效，除非编辑者重新签名形成新清单链。2.2 起有「软绑定」（指纹/隐形水印）与 Soft Binding Resolution API，用于元数据被剥离后从内容本身恢复。2.4 增加 `c2pa.ai-disclosure` 断言与 `crJSON`，专门表达「AI 生成」。

**统计文本水印**：SynthID-Text 一类方案在采样时用密钥与前文哈希替换随机数，使 token 选择带上可检测偏置；检测端用同一密钥算分数。优点是随文本走、不依赖元数据；缺点是改写、翻译、摘要、重排都会削弱信号，且需要持有密钥才能验证。

**Anthropic 的文本水印**：2026-08 官方博客详解基于 SynthID-Text 的追踪方案；数天后开源 remover 出现，说明「统计水印」的对抗门槛并不高。

**合规工具链**：`c2pa-watermark-mcp`（PyPI 0.1.0，2026-06-24）把官方 `c2pa-python` SDK 包成 MCP server，让 Agent 在生成时附清单、运行时验来源，并带纯标准库 HMAC 兜底；其文档把截止日写成 12-02，属于典型的供应链口径漂移。

**检测与仲裁**：平台侧检测器（SynthID detector、C2PA verifier）给「是否 AI 生成」的概率；争议场景还需要「哪个模型、哪一版、哪次生成」——这层只有生成方的日志与签名清单能提供。

现状判断：**标记的「嵌入」已经产品化，「证明」还没有。** 你能买到 SDK、水印 API、检测器；买不到「这条输出在转发三次、被摘要一次、翻译一次之后，仍然可归因到某次生成」的完整证据。

## 三、技术竞争力

| 方案 | 代表 | 绑定方式 | 抗剥离 | 可检测性 | 运维可用性 |
|---|---|---|---|---|---|
| C2PA 清单 | Content Credentials 2.4 | 字节哈希＋签名 | 中（可重签/剥离） | 高（有清单即可验） | 强（标准成熟） |
| 软绑定/指纹 | C2PA 2.2+ | 内容指纹 | 中 | 中 | 中 |
| 统计文本水印 | SynthID-Text / Anthropic | 采样偏置 | 低—中（改写即弱） | 需密钥 | 中（影响生成） |
| 可见标识 | Art 50(4) 深度伪造标签 | 人眼可见 | 高（但可裁掉） | 人可读 | 强 |
| 元数据 EXIF/XMP | 相机/编辑器 | 文件头 | 低（一键清） | 易读 | 弱 |
| 平台检测器 | 各家 detector | 模型判别 | — | 概率分 | 中（误报） |
| 自建 HMAC sidecar | 内部管道 | 旁路签名 | 高（跟内容走） | 需内部验 | 强（可控） |
| 生成日志留痕 | 自建 | 请求 ID | 高 | 需关联 | 强（但不出门） |
| 截图/录屏取证 | 人工 | 无 | 低 | 弱 | 应急 |
| 第三方取证 | 鉴定机构 | 综合 | — | 报告 | 慢/贵 |
| 不做标记 | — | 无 | 无 | 无 | 合规风险 |

**判读**：C2PA 强在「来源可验证」，弱在「元数据可被剥离」；统计水印强在「跟着内容走」，弱在「改写即失效、需密钥」。真正的分水岭是**跨形态的可归因性**：一条 Agent 生成的公告被复制进工单、被摘要进周报、被翻译成英文之后，还能不能指回原生成。

**本期反转**：过去把水印当「防伪」，现在要当**「生成侧的证据留存」**。防伪注定被攻破；但生成侧的清单、密钥、日志只要还在，事后仍可举证——水印是威慑，清单是证据。

**判词**：「C2PA SDK、水印 API、检测器、可见标签、取证服务」全部可采购，「这条输出是不是这个 Agent 在什么时候用哪版模型生成的，且经转发、摘要、翻译后仍可证明」不可采购。

## 四、技术挑战

**其一，剥离成本太低。** 开源 remover 11,000 星说明「去标记」已是大众工具；C2PA 清单被删后只能靠软绑定恢复，而软绑定本身也可被攻击。

**其二，改写削弱水印。** Agent 的输出经常被下游再加工（摘要、翻译、格式化），统计信号逐步衰减；检测阈值定高了漏报，定低了冤枉人。

**其三，密钥与验证的边界。** 统计水印验证需要密钥；把密钥给平台等于暴露检测能力，不给又无法自证。

**其四，误报的代价。** 检测器把人类作品判成 AI 生成，会引发名誉与版权争议；概率分不能当结论。

**其五，合规口径漂移。** 连工具文档都把 08-02 写成 12-02；供应链对齐本身是运维问题。

**其六，Agent 场景的授权链。** 标记只证明「机器生成」，不证明「谁授权发布」；两者必须分开记。

**其七，留存期。** 清单、密钥、生成日志要留多久？争议可能发生在数月后，留存策略要与事故取证对齐。

## 五、需求分解、用户旅程与实现方案

**需求分解（五项）**：① 对外 AI 输出可枚举；② 生成时自动附清单与披露断言；③ 转发/编辑后仍可检测；④ 检测结果可解释、可申诉；⑤ 授权链与生成链分开留证。

**用户旅程（SRE/内容平台工程师）**：盘点对外输出 → 生成管道加 C2PA 与 `ai-disclosure` → 灰度文本水印 → 建检测端点与阈值 → 做一次「转发—摘要—翻译」后的检测演练 → 争议时出证据包。

**90 天实现方案**：
- **0–30 天**：列出所有面向欧盟用户的生成式输出（聊天、公告、图片、音频）；给每条输出加请求 ID；接入 C2PA SDK，生成时写清单与 `c2pa.ai-disclosure`；聊天机器人加显式 AI 披露。
- **31–60 天**：文本水印灰度（先内部公告、后对外）；建检测端点，记录「分数＋模型版本＋密钥版本」；对摘要/翻译链路做衰减测试，定阈值；建申诉通道。
- **61–90 天**：把生成清单、密钥、日志纳入留存策略（与事故取证同周期）；做一次红队演练（用开源 remover 攻自己的输出）；出「一条公告的三次转发」证据包样例；把「标记缺失」纳入发布门禁。

**第 175 个市场空白（五项）**：跨形态归因服务、水印衰减监测、检测误报申诉台、生成授权链台账、标记留存策略引擎。
