# LoopForge 班次协议

一个值守班次就是一轮微型工厂：开班=frame、巡检=slice、处置=dispatch、班末交接=handover、复盘=review。五条契约原样带过来：零提问（未知→假设，不→问题队列）、证据或没发生、fail-closed、单事件单包单尝试、交接报告即交付。本技能给出每个环节的动作、产物与出口条件；三段式证据与门禁细则见 loopforge-evidence-gates，改进记账与保留门见 loopforge-rsi-ledger。

## 开班简报（frame 的值守翻译）

接班的第一个动作是写 `shifts/<日期>-<班次>-brief.md`，不是先刷告警。骨架五段：

- **范围**：本班看护的服务/仓库/指标逐项指名；不在清单上的一律写进 Non-goals，范围外的事不猜着接。
- **预算**：并行处置数上限、单事件尝试上限（默认 3）、升级路径（SEV1 叫谁、联系方式写死在简报里）。
- **未知→假设**：每个未知一行，`未知 -> 假设: <最小可逆默认>`；影响方案形状的未知升级为 Non-goal 划出去，细节级未知才落假设。
- **承接**：逐条读上一班交接报告的未决与风险，各标「本班接手」或「挂起+理由」。

出口条件：简报落盘，范围/预算/升级路径三行齐全，未知清单无空项，上一班未决全部有归属标注。

## 巡检切片（slice 的值守翻译）

每个检查项写成一个切片，头部字段与处置工单同构：`Status`（pending/ok/fail）、`Proof`（可执行单行命令）、`Depends on`（前置切片或数据就绪条件）。切片纪律：

- **独立可验证**：一项一命令一证据文件，多子检查拆多文件（计数取同次运行最大值，不跨文件求和）。命令目标指向切片自己的对象（单个模块、单条探针、单份日志），全库扫描证明的是仓库不是切片，证据不可归属。
- **证据归属**：命令的执行结果必须落为 check.py 可解析的三段式证据文件——首行 `$ <命令>`、次行 `# exit <码> 及耗时`、其后是原始输出；且输出须含默认正则可计数的检查项标记，无标记计数为 0，按假通过拒绝。默认正则只认四种形态：`Ran N tests`、`N passed`、`Tests: N`、`checks: N`——巡检命令末尾接一记 `echo "checks: $(grep -c ok checks.txt)"` 即可命中；逐项 ok/FAIL 行与末尾 `checked=N` **不在默认正则内**（计数 0、按假通过拒收），坚持逐项形态时给 `check.py evidence` 配 `--pattern` 覆盖计数。
- **辨析（防走样）**：三段式是证据文件的格式而非命令的格式，命令保持可执行单行。不要把切片的 Proof 字段写成「$ … / # … / 输出」三段文本——那是一份不可执行的记录，门禁直接拒绝。自检法：把 Proof 原样粘回 shell 必须能直接运行。

出口条件：每个切片头部三行齐全，Proof 单行可执行且指向切片自身对象，证据文件与切片一一对应。

## 处置派发（dispatch 的值守翻译）

### 派发前合并：去重键、语义分组、每班上限

- **去重键**：`(服务, 指标, 语义标签)` 三元组为键；同键重复告警只留时间戳最早的一条，其余标记回声、不进处置流。
- **语义分组**：疑似同一根因的多个键（同一部署引发重启+延迟）合并为一个事件，事件描述写「一组症状+疑似共同根因」，不逐条派发。
- **每班可行动事件上限**：超过上限（默认 8）只留严重度最高与影响面最大的，其余进工单队列留给白班；派不完的队列是交接材料，不是本班的失败。

### 严重度路由

| 级别 | 判定 | 路由 |
|---|---|---|
| SEV1 | 主服务不可用或资损进行中 | 立即 page 值班 IC 并指定一名处置执行体，全程陪跑 |
| SEV2 | 主功能降级、无冗余兜底 | page 备班 IC 并派发处置包，30 分钟无进展按 SEV1 路径升级 |
| SEV3 | 次要功能受损、有冗余 | 进工单队列，本班内处置 |
| SEV4 | 观测到异常、无用户影响 | 工单记录，工作时间处理 |

### 指针派发与尝试接力

- **派发三件套**：指针提示（「读 <处置包路径> 并逐条执行」，绝不内联全文——拿到全文的执行体会重写方案）；精确报告格式（`STATUS: done|blocked` / `PROOF: 跑了什么与观察结果` / `FILES` / `NOTES`）；自述不算 done——执行体自报 done 只是主张，必须由门禁重跑证据关闭（见 loopforge-evidence-gates）。
- **处置包头部两字段**：`allowed_writes`（允许写入的文件清单）+ 简报哈希（本班开班简报的指纹，对应总图 spec_sha+drift 行）。
- **验收比对改动面**：证据验收时比对实际被改的文件与 `allowed_writes`——越出清单的写或改即告警，不默认放行，书面豁免（批准人/理由/范围）记台账后才可越过；简报哈希对不上=简报已变，旧包作废重切重派。
- **单事件单包单尝试**：一个事件同一时刻只有一个处置包在跑。**attempt K+1 接力棒规则**：重试必须重开新处置包并内嵌上次门禁输出尾部，让新尝试从观察到的失败出发；原样重发同一包等于浪费预算。到达尝试上限即升级封锁，事件带着「已试什么、卡在哪、下一步假设」进交接报告，不拖垮其余事件。
- **并行上限与 runbook 互斥**：同时在跑的处置包不超过开班预算数；两个包不得写同一文件/资源，会重叠的先合并成一个包；同名 runbook 互斥——同一 runbook 同时只允许一个实例。

出口条件：在班事件每个要么有在册的处置包、要么按路由进了队列或升级，不存在「看了没动」的事件。

## 交接报告（handover 的值守翻译）

班末必写 `shifts/<日期>-<班次>-handover.md`，**安静班次也写**。三要素：

- **未决**：在途事件/工单，各带当前 attempt 数、下一动作与预计触发时间；
- **风险**：本班观察到的异常趋势、逼近的门限、临时关闭的检查项及恢复条件；
- **决策**：本班做过的假设与处置决策各一行——假设了什么、依据什么、何时被证伪。

**班末复盘四问**（各一行答案，附于交接报告末尾）：一问证据——本班已关闭事件里哪个的证据最弱，何时补强；二问假设——本班落的假设哪条最可能被证伪，验证动作是什么；三问失败——哪次返工或升级消耗最大，根因是什么；四问改进——下一班最该改的一件事是什么，走哪条改进轨（策略类过保留门/文档类人审）。

班次指标（切片通过率、事件数、尝试均值）只从值班台账读取，不凭记忆填数。安静班次强制产出：三要素各写「无」并附一条本班巡检证据指针，让下一班分得清「查过且无事」与「没查」。

出口条件：三要素段落齐全（安静班次的「无」也算齐全），班末复盘四问各有一行答案，每个指标都带台账出处。

## 班次复盘（review 的值守翻译）

三轴分评、不合并：**标准轴**（处置是否越权改了范围外文件）、**方案轴**（严重度判级与路由是否合理）、**证据轴**（每个已关闭事件的证据文件是否存在、是否真证明了处置生效）。AI 起草、人审定稿；blameless——归因机制，不归因人；每个行动项带 owner 与截止时间，无 owner 不立项。**证据轴抽查重跑**：取证据文件头部的时间戳/cwd/命令哈希为锚点，由处置执行体以外的角色在干净环境重跑同一命令，比对 exit 码与关键输出；锚点对不上或输出不一致即记为复盘发现。

改进沉淀双轨：策略/预测器/自动化率类改动→走 loopforge-rsi-ledger 的保留门（预测-行动-观测-改进，过保留门槛才入账）；runbook/切片文档类改动→就地修订，人审定稿或书面豁免后才算数。
