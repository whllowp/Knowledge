## 核心观点
- 痛点：长程 Agent 进入核心生产后，**有了日志、指标和完整 Trace，仍判断不了 Agent 是否做对了任务**。传统微服务那套可观测回答不了三件事：① Agent 是否正确完成任务？② 问题发生在哪个环节？③ 如何持续衡量和改善质量？
- 四个新挑战与解法：
  1. **异构 Agent 数据语义不统一** → 统一埋点与采集，遵循 **OTel GenAI 语义约定，L1/L2/L3 三层、9 类 Span**；
  2. **质量难度量且必须线上度量** → 以 Trace 为中心的实时评估链路，声明式表达式接入，**分钟级端到端延迟**；
  3. **规模化评估 token 成本（百万级流量）** → 多阶段混合 AI 评估，**小模型/正则全量粗筛 + 大模型按需精判**；
  4. **推理引擎盲区（token 级）** → 关联推理引擎，**Token 粒度定位、概率分布评判稳定性**。

## 关键事实/数据
- **90%+ token 成本降低**；粗筛阶段小模型 + 正则过滤 **99% 流量，仅 <1% 进入大模型**。
- 落地案例（OCR 截断参数调优）：「历史 2000 / 当前轮 4000」配置 badcase 率最低 **0.0273%**，基准版本 0.1401%。
- 新 Agent **接入周期从周级 → 天级**。

## 主要踩坑/风险
- 同一工具调用 / RAG / 记忆读写在不同 Agent 框架里数据模型完全不同（独立 Span / event 日志行 / 不上报），必须先统一语义。
- 长程任务几十步，错误可能出在任何一步，端到端 Trace 不等于可定位。

## 可引用结论
> 有了完整 Trace 仍判断不了 Agent 是否做对任务——可观测的下一站是「以 Trace 为中心的实时评估 + Token 级深度分析」。
