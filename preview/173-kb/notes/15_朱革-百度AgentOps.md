## 核心观点
- 矛盾：当 Agent 从「单点试用」走向「规模化生产」，**接入部署、版本边界、运行观测、安全管控的缺失集中爆发——企业用得起来，却管不住、不敢放大**。
- 解法：**AgentOps 五层架构（接入/网关/平台/能力/基础设施）+ 五大中心（Agent 管理·安全·变更·评估·知识）**，控制面与数据面分离，统一纳管 Agent 的「运行、安全、变更、评估、知识」，让 Agent 从「能跑」走向「敢用」。
- 五大核心能力：Runtime 全生命周期托管 / 安全管控 / 场景仿真回放 / 知识沉淀与能力闭环 / Agent 自主进化。

## 关键事实/数据
- 规模化挑战六类：接入部署、配置版本、运行观测、安全权限、能力复用、质量演进。
- **新 Agent 交付周期从「周级」降到「天级」**，稳定性有 SLA 兜底；全生命周期托管覆盖创建→配置→部署→运行→升级→监控→故障恢复→下线。
- 安全管控四类高危：用户 / 模型 / 系统 / 并发层面都可能让一次写操作失控（案例：Agent 迭代后与 DB 交互，数据字典不匹配导致 insert 持续失败）。
- 实践沉淀示例：**Case MTTR 60 → 10 分钟**（已核验）。

## 主要踩坑/风险
- Agent、Skill、Prompt、工具和知识缺少统一版本边界，调试易污染线上版本。
- 生产写操作缺少统一权限、审批、限流、审计和回滚控制，是规模化最大拦路虎。

## 可引用结论
> 当 Agent 从单点试用走向规模化生产，缺失的接入/版本/观测/安全集中爆发——企业用得起来，却管不住、不敢放大。AgentOps 让 Agent 从「能跑」走向「敢用」。
