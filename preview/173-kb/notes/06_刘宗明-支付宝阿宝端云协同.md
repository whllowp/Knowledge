# 06 · 端云协同下的 Agentic 多端互联实践（支付宝「阿宝」）

## 核心观点
- **终端 Agent 正在成为新的入口**：能力栈从 Prompt/RAG → Workflow/工具调用 → Multi-Agent/A2A 持续扩展。
- 支付宝「阿宝」生活服务助手采用端云架构：**多端入口（手机 / 车载 / App / 眼镜）表达需求与接收反馈 + 云端 Agent（任务理解、规划、工具选择）+ 端侧 Runtime（端 MCP、端 Loop，交互运行时）**。
- 标准化组件：**AHA（Agent Hub Access）**、**xUI（Agent 端云解决方案）**、**SIS（Skill Interface Standard）**；多端互联展望 Anywhere / Anytime。

## 关键事实/数据
- 能力演进时间线：2023 ChatGPT 对话问答 → 2024 GPT-4o 多模态感知 → 2025–2026 Operator 任务执行（理解目标、调用工具、执行任务）。
- 行业对照：豆包（自然对话）、千问（对话办事）、Muse（个人 Agent，委托目标持续推进）、阶跃（手机智能体 STEPX Neo/Amoo）。
- 交互原则：**用户参与选择与关键确认**；Agent 协助查找/点击/输入，需选择或确认时交回用户。
- 多端互联实例：手机助手发起需求（如「帮我点一杯蜜雪冰城柠檬水」「帮我预约明天下午 3 点去萧山机场的车」），车载助手呈现商品与门店，用户在车机继续选择确认。

## 主要踩坑/风险
- 移动应用中 Agent 需「在对话中查看商品、选择规格、确认信息」，服务界面随任务进展出现，对端侧运行时与交互闭环要求高。
- 任务执行类 Agent 必须保留「交回用户确认」的闸口，避免越权操作。

## 可引用结论
> Agent 参与应用操作，协助查找 / 点击 / 输入，需要选择或确认时交回用户——多端互联的核心是人机协同而非全自动。
