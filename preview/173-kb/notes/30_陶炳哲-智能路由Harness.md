## 核心观点
- 智能路由成立的**三个前提**：① 尺寸差（小模型快且便宜、大模型担复杂）② 同尺寸也分岔（数据配方/架构/推理引擎改变能力价格速度）③ **harness × 目标任务**（同模型同思考力度换框架，部分场景成本差 2 倍而质量不变）。
- 灵魂命题：**路由的是「执行方案」**——把适合的任务交给适合的「模型 + harness」，并满足质量、预算与供给约束；而非简单「难的给大模型」。
- **模型与 harness 必须联合评测**；选型要看**错误重叠**（互补性比单一排名更有意义），偏差度越大越适合路由。

## 关键事实/数据
- 尺寸差：稠密 27B 每 token 算力约为激活 13B、总参 284B MoE 的 **2.1 倍**；激活参数→边际成本，总参数→固定成本（MoE 稀疏主要省计算但专家权重仍需常驻）。
- 同尺寸候选：某 BMK 分数 42/52/45/57，总 token 260M/260M/130M/140M，工具调用错误率 0.39%/0.01%/2.78%/2.58%——分数之外要看效率与错误率。
- **同权重、同挂牌价，供应商吞吐差 23 倍**（OpenRouter provider P50，2026-09-06 采样）。
- 成本排序会翻转：Sonnet 5 单价便宜 1.7 倍，但每任务 $2.09 vs $1.94、完成率低 6pp；同两模型在 Hermes/Kilo/Claude Code 上贵 32%/57%/便宜 16%。

## 主要踩坑/风险
- 「难的给大模型，不难的给便宜模型」只考虑了复杂度——长上下文不一定需复杂推理，短指令也可能推进大型工程。
- 单价便宜 ≠ 任务便宜；成本弹性受框架显著影响（Pi 每轮上下文少约 3 倍）。

## 可引用结论
> 真正的命题是「匹配模型 + harness」；模型与 harness 必须联合评测，选型要看错误重叠而非单一排名。
