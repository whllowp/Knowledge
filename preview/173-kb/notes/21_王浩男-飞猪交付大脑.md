## 核心观点
- 核心判断：**个人能力的增强 ≠ 团队交付能力的增强**；生产级需求交付必须多角色协作（产品/设计/研发/测试），AI 提效卡在「协作」而非「单点」。
- 解法：串联各环节的 AI Native 小闭环，形成**端到端交付大闭环**——在 Agent 主导下，多角色协作完成需求交付。
- 三大设计支柱：**上下文共享**（打破 Agent 间信息孤岛）、**交付流程**（4 环节大闭环）、**云端执行**（可靠长程任务运行环境）。

## 关键事实/数据
- 上下文共享：同一需求共享「项目背景 / 业务知识 / 仓库代码 / 工程规范 / 可用 Skill / 本次需求 PRD·设计稿·范围·验收标准 / 过程澄清与成果」，需求分析 Agent、研发 Agent、测试 Agent 分别读取各自所需上下文，结果交回供人审阅。
- 交付流程 4 环节：① 需求澄清（PRD/设计稿→需求共识：目标/范围/业务规则/验收标准）② 交付共识（技术约定/各仓任务/测试用例）③ Coding & 部署（可测试版本/部署记录）④ 测试（测试报告/问题清单/回归）。需求变化或测试发现问题 → 回到相关环节迭代。
- 云端执行：交付平台（FaaS）+ 常驻 Node 容器的 Agent 执行服务 + 统一 Agent 运行框架；页面/BFF 负责身份、权限、上下文与产物校验。

## 主要踩坑/风险
- 需求信息及变更结论原本需「人整理后传给各自 Agent」，易形成信息孤岛；须用共享上下文消除。

## 可引用结论
> 个人能力的增强 ≠ 团队交付能力的增强；超级流程的价值是把多角色的 AI Native 小闭环，串成端到端交付大闭环。
