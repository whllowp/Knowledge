# 05 · 把大模型关进确定性笼子：蚂蚁 SRE 基于 Agent 的应急根因定位实践与踩坑

- **来源文件**：刘凯宁-蚂蚁 SRE 基于 Agent 的应急根因定位实践与踩坑.pdf
- **厂商/讲者**：刘凯宁（蚂蚁集团 技术风险 SRE 技术专家，QCon 上海 2026.10）
- **主题领域**：SRE / Agent 应急根因定位（RCA）/ 业务 Skill / 运维本体
- **页数/文本量**：33 页 / 3584 字

## 核心观点
- 通用组件定位已逐步成熟，但**业务特性问题成为准确率提升的瓶颈**；因此沿已有应急体系继续深入，把业务 SRE 经验沉淀为可复用的**诊断 Skill**。
- 「**工程的交给工程，大模型的交给大模型**」：明确规则交给代码，综合判断依靠业务知识与证据（把大模型关进确定性笼子）。
- 三大支柱：**业务定位 Skill**（SRE 把排查方法写成可维护/可验证/可复用的诊断能力）+ **DeRiskCoWork**（云端运行空间，管理 Skill 全流程）+ **AntOntology**（统一跨系统业务语义，以实体与关系组织查询，连接 API/在线库/文档）。

## 关键事实/数据
- 生产诊断链路：极光告警自动触发 → DeRiskCoWork 承接业务路由与 Skill 执行 → 匹配业务 Skill → 沿业务路径取证（数据+业务知识）→ 返回诊断报告（结论/证据/待确认项）。
- 业务 Skill 标准研发流程：① 开发调试（经验写成 Skill）② 评测回放（真实案例验证）③ 部署投产（云端运行）④ 反馈迭代（生产问题进入下一轮）。
- 已运行：极光告警自动触发、群内按需发起，DeRiskCoWork 承接诊断；同一套业务经验同时服务自动诊断与现场排查。

## 主要踩坑/风险
- **写出一个 Skill 离稳定投产还有多远**：需经真实案例与回放检验，否则只是「能跑」而非「可信」。
- 业务语义分散导致取证困难——故引入 AntOntology 以实体/关系统一接入。

## 可引用结论
> 业务定位 Skill 是 SRE 可维护、可验证、可复用的业务成果；工程交给工程，大模型交给大模型。
