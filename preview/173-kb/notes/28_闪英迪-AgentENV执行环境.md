## 核心观点
- AI Agent 除训练外，**需要自己的执行环境（沙箱）**，服务于：训练评测、在线服务（Word/PPT/图表/OpenClaw 等）。
- Agent Rollout（多轮工具调用）必须持续保留文件、进程与测试环境——现有沙箱平台「成本高昂、环境定义不灵活、镜像分发效率低下」三大痛点。
- 一个可复用的 **Workspace** 应承载题目代码与构建好的依赖环境，供后续任务复用。

## 关键事实/数据（已核验）
- **执行环境侧开销占比约 35%**，是 RL 训练中不可忽视的成本来源（GPU 128 卡 $640 + CPU/MEM 等）。
- 厂商建议「32–128 并发 Rollout 需配备 32–64 vCPU/GPU」；DeepSWE 1000 核/64 GPU ≈ 16 vCPU/GPU。
- 生产问题：**使用容器方案，每天都有约 5% 的节点因 Agent 的破坏而宕机**；OCI 镜像须全量下载解包，而**运行时只用到 4%–13%** 的数据——镜像分发效率是核心痛点。

## 主要踩坑/风险
- 训练数据（Issue/PR）易得，但**补齐运行环境（Env/Solution/Test）** 成本高，环境构建常成瓶颈。
- 镜像全量分发 + Agent 破坏性操作，导致资源浪费与稳定性风险并存。

## 可引用结论
> 执行环境侧开销占比约 35%；Agent 训练/服务的真正成本不仅在大模型，也在持续可用的沙箱与镜像分发。
