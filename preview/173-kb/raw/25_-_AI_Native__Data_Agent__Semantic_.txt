语义模型解析与校验：错误尽量在编译期暴露
主键、关系基数、表达式类型、时间粒度——每一项都是后面规划正确性的前提
semantic_model:
- name: orders
  datasets:
  - name: orders
    primary_key: [order_id]        # 粒度
  - name: customers
    primary_key: [customer_id]
  relationships:
  - from: orders   to: customers
    from_columns: [customer_id]    # N:1
  metrics:
  - name: revenue
    expression: SUM(orders.amount)
    filter: orders.status != 'cancelled'
  - name: avg_order_value
    expression: revenue / order_count   # 比率
1
主键 → 粒度
每个 dataset 的行由什么唯一标识；这是后面所有「在哪个粒度聚
合」判断的根
2
关系 → 基数
N:1 可安全展开，1:N 会复制行；基数未知时规划器宁可拒绝
3
表达式 → 类型
SUM / COUNT / AVG / COUNT DISTINCT / 比率；类型决定该指标
能否求和、上卷、归因
4
时间 → 粒度与窗口
时间维度的最小粒度、日历与窗口语义，是同环比正确性的前提
dosi validate 可运行上游 apache/ossie 参考校验器：对规范校验，而不是对某
个引擎的理解校验

聚合规划：粒度与 fan-out 的三条出路
引擎不会发出一条它无法证明安全的、对重复行敏感的聚合；三条路，只走一条
路 径  1
单粒度直接聚合
请求的维度全部位于一条无行复制的关联路径上——直接 GROUP 
BY。
路 径  2
按粒度拆分 → 合并
每个指标在自己的事实粒度聚合成 CTE；Fact 与 Fact 之间先对齐
粒度，再合并（见右）。
路 径  3
拒绝：fan_out_risk
两条都证明不了——返回结构化错误，点名出问题的关系，并给出
可改查的更细粒度。
路径 2 的产物 · 两个指标、两个粒度、一次请求
-- total_delay_minutes (Delay 粒度) + passengers (Flight 粒度)
WITH m0 AS (
  SELECT aircraft.tail_number,
         SUM(delays.delay_minutes) AS delay_min
  FROM delays LEFT JOIN flights … LEFT JOIN aircraft …
  GROUP BY aircraft.tail_number),
m1 AS (
  SELECT aircraft.tail_number,
         SUM(flights.passenger_count) AS pax
  FROM flights LEFT JOIN aircraft …
  GROUP BY aircraft.tail_number)
SELECT COALESCE(m0.tail_number, m1.tail_number),
       m0.delay_min, m1.pax
FROM m0 FULL OUTER JOIN m1
  ON m0.tail_number = m1.tail_number
-- 本例中 passengers 不会被延误行数放大
-- 粒度已一致（均为 aircraft.tail_number）：直接 FULL OUTER JOIN
-- 粒度不一致：D-conform 对齐后合并；更复杂的场景：semi join
生成的 SQL 对仓库友好：一次请求一条有界的 pushdown 查询，交给仓库优化器与物化视图；语义层无缓存、无存储

指标代数：这个指标能不能这样用？
可加 / 可上卷 / 可重构 / 不透明——从 IR 推导，作者零额外字段，Agent 聚合前先问引擎
Additive 可加
SUM · COUNT
跨分组可直接相加
Rollupable 可上卷
MIN · MAX
可上卷，但不可相加
Reconstructible 可重构
AVG
分解为 sum / count 后再合成
Opaque 不透明
COUNT(DISTINCT)
两者都不行；必须回到叶子重算
推导出的四种能力 · 每个指标
summable 跨分组可求和 → 维度拆解时可直接加总
rollup-safe 可从细粒度上卷到粗粒度，不需重算
attributable 可归因，并由类型决定归因方法
forecastable 可按时间序列外推
通过 dosi list metrics 与 Python / MCP 暴露为 attributable / 
attribution_strategy 字段

01
语义层是Data agent的共识，语义层的质量决定了Data agent的下限
