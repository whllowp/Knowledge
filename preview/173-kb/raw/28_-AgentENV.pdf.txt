面向智能体的分布式执行环境
AgentENV 总览
AENV：面向智能体的分布式执行环境
• AgentENV（简称AENV) 是面向智能体的分布式执行环境
• 已服务于Kimi K3 训练，支撑 150 万个镜像与 5000 万个执行环境
• https://github.com/kvcache-ai/AgentENV
• 运行在近千节点上，支撑数十万沙箱并发运行，每天产生快照数据1PB+
• AgentENV 的存储后端已被 Deepseek 的DSec 所使用

AENV 的总体优势
• 基于MicroVM 提供强隔离
• 降低每个执行环境的部署成本
• 提升部署密度：减少内存、存储和运行时资源消耗
• 提升资源利用率：暂停、持久化、恢复低活跃的执行环境
• 高可扩展性
• 数据存储在对象存储中，本地硬盘仅作为cache 和 buffer，可无限扩展
• 易于使用
• 兼容E2B，无需代码修改
• 支持多容器镜像的组合，支持执行环境中嵌套 Docker
• 无缝衔接对象存储，不需要设置复杂的分布式存储
AENV 的架构
• Gateway：请求转发，可无限横向扩
展
• Scheduler：无状态的调度器，从各个
节点收集CPU/内存等信息，决定调度

• Node：负责管理每个节点的执行环境
• Firecracker： 给每个执行环境独立的虚
拟机
• Ublk：给每个执行环境提供内存镜像与

• Shared FS/OSS：负责数据的可靠存

AENV 通过复用提升部署密度
• PageCache 占据了每个 VM 的绝大部分内存开销
• 将 Page Cache 放在Guset 端：多个VM 读取的Page 存在冗余，结合 
aenv 块存储，将Page Cache 从Guest OS 卸载到 Host，可显著降低内
存消耗
• 内存归还：结合 DAMON 与 virtio-balloon，把 guest 内不活跃的 file-
backed cache 或可回收页面归还宿主机
• 从同一 RootFS 启动的多个 VM的内存可复用
• 将每个镜像启动时所需的内存构建为一个 Memory Block Device，映射
到 VM 中
• 多个执行环境的内存通过OS 的mmap 机制实现自然共享
