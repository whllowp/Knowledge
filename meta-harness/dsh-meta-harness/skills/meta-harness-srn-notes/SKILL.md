# SRN 地板基线与重型管线晋级规则（ARCHITECTURE.md §2.7）

依据：arXiv:2611.13524v1。论文最重要的正面结论：**SRN（Simple Reflection with Notes）**——一个刻意简化的有界笔记基线——在全部四个评测设定中准确率追平或超过 Meta-Harness/EvoSkill/RRSI，而总 token 少 65.6%~71.0%（相对 Static 基线平均 +4.7 准确率点、仅 +3.6% token）。SRN 因此是快循环的**默认地板**，重型管线降级为**条件启用**。

## SRN 快循环规范（默认开启，几乎零税）

- **单条笔记 ≤2048 token**，全量替换式重写（不是追加）；
- **固定更新边界**：每 4 个任务更新一次（不是每任务、不是会话结束）——高频更新的边际收益递减而税线性增长；
- **有界支撑集**：仅从最近窗口的**失败任务**中提取，判定只依赖**标量验证器结果**（成功/失败/部分），不做 LLM-judge 轨迹评判；
- **一次生成调用**完成重写；**无效响应保持原笔记不变**（静默保留，不重试）；
- **零额外结构**：无候选验证、无并行 rollout、无检索搜索、无 embedding——更新调用预算 <0.4% 总 token（论文实测水位）；
- 笔记注入走简报「稳定区」（prompt-cache 友好），每次重写后视为新的缓存前缀版本。

笔记落盘形态（§2.5）：`.claude-flow/note.md`，与 `rsi-ledger.jsonl` 同目录；笔记同样携带 born_cost/used_count/last_used 计量字段。

## 重型管线晋级规则（默认关闭，逐项启用）

1. 每个重型组件（判别式路由学习器 / PageRank 巩固 / 神经轨迹 / cross-encoder 重排…）必须在与「仅 SRN」的对照实验中证明：**Δ准确率 > 该组件的边际 RSI Tax 折算成本**（按 §7.4 双轴协议评测；对照组固定三档 Static/SRN/被测配置，重型组件的晋级判决只与 SRN 比，赢过 Static 不说明值得花税）；
2. **任务内 P–P–C 改进环（在线无真值模式，§2.4）列为新的重型组件**：默认关闭，启用同样对照 SRN 判决；其递归预算 **k**（每任务候选数/组合会话数/链式步数）是**税旋钮**，**k=1 为默认地板档**（与 SRN 地板同哲学——先证明 k>1 值得付税），上调须按 §5.2 对照 k=1 判决。低档先行有据：两种递归均随 k=1→5 单调上升，且 **k=2 已超过全部基线在 k=5 的表现**（Harness² §4 图5——大部分增益集中在前两步）；
3. 晋级判决本身计入 Verify 类税收，且是**一次性成本**——同一组件不重复晋级评审，降级同样需要证据；
4. 组件可独立晋级/降级，不做全有全无——目标是「最便宜的够用配置」（论文证明这通常就是 SRN 本身）。

**架构推论（非论文原文）**：SRN 的支撑集判定依赖**标量验证器结果**（成功/失败/部分）；无 ground-truth 验证器的任务上该信号缺失，SRN 判定与 held-out 重打分两条路径都不可用（§2.4）。此时**行为对比三态（尤其「回归」检测）是该场景下可用的替代信号源**——同任务/同模型/同配置对比只判行为变化（缓解/无变化/回归）、不判对错，作证据不作验证。

**降级通道（自动）**：任一组件连续两个评测窗口未能保住晋级时的优势边际，自动降回关闭并留回执。

## 与机制论文的关系（防误读为矛盾，§2.7 末段）

Meta-Harness 论文（arXiv:2603.28052v1）的机制（轨迹反馈、难搜索集、接口验证）、AutoDesign（arXiv:2608.13560v1）的制度条件（单组件更新、合取验收门、ℒ 记录）与 **Harness²（arXiv:2610.14224v1）的行为对比与库复利**都是 RSI Tax 的**降税手段**而非对立面——Harness² 的 Probe 在单任务上付少量额外执行（候选 rollout × k）即产出对比证据，对照 held-out 全集重放的验证税（无真值任务上后者本不可用）；harness 改进库积累后免探测直接改进（探测税资产化，§2.3）。结论：**快循环仍以 SRN 为地板不动**；「代码空间搜索 + 轨迹反馈」全套与任务内 P–P–C 改进环均仅元循环/慢循环/在线模式条件启用，晋级仍按双轴协议对照 SRN 判决。
