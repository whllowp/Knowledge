# RSI Tax 分类账协议（ARCHITECTURE.md §2.6–2.6.2）

依据：arXiv:2611.13524v1《The RSI Tax: When Recursive Self-Improvement Is Not Worth the Cost》；在线无真值模式记账口径与第 5/6 条防呆另依 Harness²（arXiv:2610.14224v1，ARCHITECTURE.md 附D D1/D6/D8/D10 轮）。核心方法论：**把自我改进调用与任务调用严格分离记账**。端到端成本 = 任务执行 token + RSI Tax；论文实测不受约束的重型自进化方法税率达 100%~393%——改进的开销超过被改进的任务本身。

## 税率与三分类（§2.6）

税率 `ρ = N_RSI / N_task`（自我改进 token / 任务执行 token）。每笔进化调用必须归入其一：

| 分类 | 含义 | 典型项 |
|---|---|---|
| **Verify** | 验证在位者/候选（在已完成的支撑任务上重打分） | sandbox 回放、frontier 重打分、smoke test、held-out 评估、注入消融 |
| **Explore** | 探索（额外 rollout、提案生成、轨迹判定、embedding） | 巩固前的重算、路由学习器重训、神经轨迹训练、提案搜索轮、**在线无真值模式的 Probe 候选执行与行为对比分析**（Harness² 口径：论文明言对比只供后续组合、不验证任务正确性——**不得记 Verify**） |
| **Write** | 写入/修订持久状态 | 写 pattern/记忆条目/SKILL.md/笔记/策略参数、因果边写入、**在线无真值模式的 Compose/反思/写 harness 改进库条目** |

**在线无真值模式记账口径（§2.6，Harness² arXiv:2610.14224v1）**：**参考执行归任务调用**——任务的首次正常执行同时是交付候选（最终选择池必含项），**不计 RSI 税、不与任务 token 双记**；Probe 候选执行与行为对比分析记 **Explore**；Compose/反思/写 harness 改进库记 **Write**。

无法归类三类的进 "Other" 残差；**残差占比 >10% 视为记账缺陷**，需补分类而不是忽略。

## 记账规则（§2.6）

1. 任务调用与 RSI 调用**调用域不相交**——同一批 token 不得双记。
2. 每笔成本**归集到它关联的产物**（某条 pattern、某个技能、某次策略变异），并打「后续是否被实际使用」标记。
3. **被拒绝的更新照常计税**——候选生成+验证的成本不因最终未采纳而消失，这是「税」的定义。
4. RSI 预算挂 L5 层（税率上限 + 单轮更新 token 上限），与权限检查共用策略引擎卡点（预算即策略）。

账本落盘形态（§2.5）：`.claude-flow/rsi-ledger.jsonl`，追加写，每笔 Verify/Explore/Write 归集到产物 id。

## 后续使用追踪（§2.6.1）

论文实测 23.7%~63.6% 的税花在**从未被后续任务使用的产物**上（unretrieved artifacts 是纯浪费）。对策：

- 每个进化产物（pattern/记忆条目/技能/笔记/策略参数）携带三个计量字段：`born_cost`（诞生成本，含其 Verify+Explore+Write 分摊）、`used_count`、`last_used`；
- 「使用」的定义要严格：**注入 ≠ 使用**——只有产物被注入后确实影响了行为（被引用/被采纳/结果归因非零）才计 `used_count`；
- 巩固时计算**浪费率** = 未使用产物的累计 born_cost / 总 RSI 支出；**连续两个窗口 >25%** 时自动收紧该类产物的生成预算并归档最旧的未使用产物；
- 审计口径：后续使用是描述性证据（用了≠有用，没用≠可删），归档默认可恢复。

## 花任何 Verify/Explore 预算前的七条前置防呆（§2.6.2，编号 0–6）

0. **第 0 层接口验证**：候选进 sandbox 前先过秒级零 LLM 成本冒烟——导入模块/实例化类/极小样本调用一次；畸形候选拦截成本近零，排在第 1 条之前（轻量验证先于昂贵评测）。
1. **决策不变式检查（反 603k 案）**：验证开始前必须先断言 `∃ 决策路径: 候选胜出`——若候选被约束（预算上限/类型不匹配/单调性保证/在位者构造性占优）预先排除，跳过验证直接拒绝，只记 Explore。**执行级形态（在线无真值模式）**：Probe 三态中「行为无变化」与「回归」均使候选胜出的决策路径不存在——不进 Compose 及后续晋级验证，直接拒绝、只记 Explore，仅「缓解」继续。
2. **提案空闲轮上限（反 58M 案）**：搜索轮（Explore）必须每轮产出提案或显式的「继续搜索」理由；连续 2 个空闲轮即终止本轮搜索并回执失败——搜索不是可以无限烧预算的合法状态。
3. **支撑集预筛**：Verify 只在「结果可翻转决策」的支撑任务上跑（frontier 边界附近）；在稳赢/稳输任务上重打分是纯 Verify 浪费（验证占重型方法总税的 74.8%~93.6%，是第一削减对象）。
4. **验证成本阶梯**：确定性 blocking 规则检查（零 LLM 成本）→ 标量验证器 → 模型/VLM 评判（最贵、最后置，仅前级未通过或需主观维度时介入）。
5. **无新证据即停（Harness² 附录 G）**：在线无真值模式的 Probe 连续无新证据即停止本轮递归——论文原文 "stop when additional probes yield little new evidence"（论文列为未来方向，本架构即行制度化）；与第 2 条提案空闲轮上限**同构**——probe 与搜索一样不是可无限烧预算的合法状态；判定产自已付费 rollout 的对比记录，**零新增调用**。
6. **候选间错误前提隔离（Harness² 附录 E.6，失败模式三防之一）**：Compose 可读全部执行证据，但**候选生成阶段不得继承另一候选未经当前任务证据核实的假设**——E.6 实测错误前提跨候选传播（literal-key 要求与未核实 cache 假设）致 **2–11 分损失**。配套两防：行为对比证据不足以分辨质量时**默认保留在位者/参考交付**（选择保守化）；编辑未绑定可观察目标缺陷类别的提案**直接拒**（编辑绑定缺陷，对接 §2.4 双候选范围划分）。三防只在已付费证据上判，零新增评估调用。

第 1–3 条在策略引擎卡点内执行，检查本身零 LLM 调用（纯条件判断）；第 0 条为零 LLM 成本的秒级冒烟；第 4 条是验证环节的成本排序纪律；第 5 条是在线无真值模式的自适应停止准则；第 6 条是在线无真值模式的失败模式三防。违反即阻断并留审计记录。

## 元循环晋级的五道门（§2.4，摘要）

接口验证（第 0 层冒烟）→ 廉价静态门前置（预期效应量 × 任务流剩余长度 < 验证成本预算的候选不进 sandbox）→ 评估 rollout 上限（held-out 分割一次生成、多次复用）→ 晋级边际 > 验证噪声 → 合取式验收 `J_train(候选)>J_train(在位) ∧ J_dev(候选)≥J_dev(在位)`（dev 集轨迹与分数绝不暴露给提案生成器）。另：与在位基线「逻辑相同、仅常数不同」的参数变体不进 sandbox（反参数调参门）。**该门的执行级证据（Harness² §2.2）**：在线无真值模式下，Probe 三态中的「行为无变化」（同任务/同模型/同配置执行而行为未变 ≈ 仅常数不同）与「回归」都直接拒绝、只记 Explore；仅「缓解」进 Compose——三态判定产自 Probe 已付费 rollout，零新增成本。

**没有双轴报告的改进不算改进（§7.4）**：最终准确率 A(T)、总 token N(T)、税率 ρ、相对 SRN 的净 token 溢价四项并列呈现，任何单项美化视为报告无效；外环总成本必须披露（Verify/Explore/Write 分账），缺账不视为改进。
