# 灶台风暴 SIZZLE! — 游戏设计文档

版本：1.0 · 2026-11-02
引擎：three.js r186（浏览器）· Canvas 2D（俯视模式）· WebAudio

---

## 1. 一句话

一间会让人手忙脚乱的厨房，两种看法：**走进去亲手做**，或者**站在上面统揽全局**。切菜、煎肉、摆盘、出餐，订单不等人。

## 2. 设计支柱

1. **动作要具体，结果要立刻看见。** 拿起的食材出现在手里；切菜有刀、有碎屑、有进度；肉饼在锅里变深、冒烟、烧焦。
2. **同一个厨房，两种镜头。** 第一人称负责沉浸与身体感；俯视负责调度与本地合作。两者共享规则，不共享手感。
3. **混乱是设计出来的，不是 bug。** 单手持物、会烧焦的肉、限时订单、有限的灶台——压力来自真实的取舍。
4. **一眼能读懂。** 工位有标签、食材有颜色/图标、订单有配方、上菜窗口发光；不靠文字也能猜出七八成。
5. **短局可重开。** 3 分钟一班，结算给星，记录留在本地；失败成本低，下一把立刻开始。

## 3. 两种模式

### 模式 01 · 沉浸厨房（First-Person）

- 3D 厨房，指针锁定第一人称，眼高 1.62m。
- **核心动词**：走位 → 看准 → 抓取 → 放置 → 切/煎 → 摆盘 → 端盘 → 上菜。
- 交互是“靠近 + 朝向 + 最近工位”，不是准星射线命中；准星变琥珀色即表示可互动。
- 单手持物：手里最多一样东西（食材或盘子），迫使玩家规划路线。
- 切菜在砧板上按住左键 / `E`；刀在右下手部出现，食材弹跳、碎屑飞溅、音效随节奏触发。
- 煎炉有 2 台，肉饼 5.5s 熟、10.5s 焦；熟肉饼不拿走会继续变焦。
- 上菜窗口是唯一结算点：端着配好的盘子按 `E`，彩带、铃声、分数弹出。

### 模式 02 · 街机厨房（Arcade / Local Co-op）

- 俯视 2D，10m × 7m 厨房完整可见；相机固定，按窗口等比缩放。
- 移动速度更快（3.35 m/s），无冲刺；玩家可在柜台之间穿插。
- **本地双人**：P1 = WASD + 空格，P2 = 方向键 + Enter；单人只启用 P1。
- 两名玩家各自持有一样东西，可同时切菜、往同一张盘子上加料、抢同一个灶台。
- 提示系统：P1 走 DOM 底部提示条，P2 在头顶显示 `Enter` 上下文提示；两名玩家都有目标工位虚线框。
- 视觉：暖色瓷砖、木柜台、不锈钢岛台、霓虹招牌、墙面挂钟、上菜口、垃圾桶；食材/状态用 emoji + 颜色 + 进度环表达。

**为什么选这个第二模式**：需求只明确了模式 1。用 2D 俯视 + 本地双人作为模式 2，可以直接复用模拟内核，同时提供与第一人称相反的体验（全局视野、社交混乱、更快的节奏）。若改为经营/剧情/联机，`core/` 与 UI 壳仍可复用。

## 4. 核心循环

```text
看订单 → 规划路线 → 取料/备料 → 加工（切 / 煎）→ 摆盘 → 上菜 → 得分/连击 → 下一单
   ↑                                                                    │
   └──────────────────── 订单超时 / 烧焦 / 送错 ←────────────────────────┘
```

**每个班次的张力曲线**：开局订单少（教学/热身）→ 中段订单重叠 → 最后 45 秒订单堆积 + 倒计时变红 + 最后 15 秒提示。结算给星，鼓励重开。

## 5. 厨房与工位

```text
                        后墙（z = -3.5）
  ┌──────────────────────────────────────────────────────────────┐
  │ [面包][肉饼][芝士][生菜][番茄][洋葱]        [上菜窗口]        │
  │                                                              │
  │        [砧板][煎炉A][煎炉B][出餐台][盘子]   ← 中岛 (z=0.3)   │
  │                                                              │
  │                    (玩家活动区)                    [垃圾桶]  │
  └──────────────────────────────────────────────────────────────┘
                         前墙（z = +3.5）        P1/P2 出生在 z≈2.5
```

- 房间 10 × 7m，墙高 3m；中岛不可穿越，玩家必须绕行——这是“路线规划”的空间成本。
- 工位交互半径 1.55m（3D）/ 1.32m（2D），取工位矩形最近点距离；3D 还要求朝向点积 > 0.05。
- 工位与行为：

| 工位 | 交互 |
|---|---|
| 食材箱 ×6 | 空手拿取对应生食材；无限供应 |
| 砧板 | 放上可切食材；空手按住互动切碎；切好拿走 |
| 煎炉 ×2 | 放生肉饼；熟/焦后可拿走；不拿会继续焦 |
| 出餐台 | 放空盘；把食材一份份摆上；端起整盘 |
| 盘子台 | 拿空盘（无限） |
| 上菜窗口 | 端着有配料的盘子结算 |
| 垃圾桶 | 销毁手中物品（烧焦肉饼、错盘） |

### RSI 动态菜单与年度相册

`src/core/rsi.js` 把 Dream-RSI 的循环压到游戏尺度：

1. **在线班次**：从 3 道 RSI 推荐 + 班次底池出订单；推荐订单金色描边、出餐 +25%。
2. **发现历史**：记录推荐、实际出餐分布、分数/星级/超时/难度/重玩。
3. **回放世界**：用历史班次离线评估当前策略、标签扰动策略、经验策略的 replay score。
4. **策略选择**：只有超过当前 replay score 才升级版本；策略权重/探索率/版本存本机。
5. **年度相册**：按菜谱/月份/城市/天气汇总，生成回忆录，导出 HTML/打印 PDF。

上下文：城市（上海/成都/广州/北京/杭州）、天气（晴/雨/雪/热浪/起风）、偏好（清爽/素食/肉食/芝士/辛香/番茄/经典）。城市/天气由玩家选择，避免联网依赖；详见 `design/RSI.md`。

## 7. 订单、计分与星级

### 订单

- 同时存在的订单上限 = 班次 `slots`（2–3）。
- 每 `spawnInterval` 秒尝试补一位客人；避免连续两次同一菜谱。
- 每位客人独立倒计时；到期移除并清零连击（不扣分）。
- 上菜时匹配“最紧急的同菜谱订单”。

### 计分

```text
基础分 = 菜谱分
小费   = round(基础分 × 0.35 × 订单剩余时间比例)
倍率   = 1 + min(连击, 4) × 0.25          // 1.00 → 2.00
RSI加成 = round((基础分 + 小费) × 倍率 × 0.25)  // 仅今日推荐菜
得分   = round((基础分 + 小费) × 倍率) + RSI加成
```

- 成功出餐：连击 +1（上限 8），连击计时器重置为 30s。
- 订单超时：连击清零。
- 烧焦：连击 -1。
- 送错菜/乱配盘：0 分，不消耗订单，统计里记为浪费。

### 星级与记录

- 结算按班次三个阈值给 0–3 星。
- 最佳分数/星级按 `模式:班次` 存入 `localStorage`（键 `sizzle-rush:v1`）。
- 结算显示：完成订单、最高连击、超时订单、烧焦数量。

## 8. 班次

| # | 名称 | 时长 | 同时订单 | 订单间隔 | 时限系数 | 菜谱 | 1★/2★/3★ |
|---|---|---|---:|---:|---:|---|---|
| 1 | 早班 · 熟悉灶台 | 180s | 2 | 7.0s | 1.15 | RSI 3 道 + 基础池 | 300 / 475 / 625 |
| 2 | 午市 · 客流高峰 | 210s | 2 | 7.0s | 1.20 | RSI 3 道 + 全部 | 300 / 425 / 800 |
| 3 | 夜宵 · 极限出餐 | 180s | 2 | 6.0s | 1.10 | RSI 3 道 + 全部 | 225 / 375 / 625 |

设计意图：班次 1 教流程（订单少、时限宽）；班次 2 教并行（双灶台、更长的班次、更多菜谱）；班次 3 考极限调度（订单更密、时限更紧、必须提前备料/利用连击）。

> 阈值来源：`npm run balance` 的机器人模拟（80 局/班次/档位）+ 新手 p50 / 普通 p50 / 熟练 p50 取整。**不是真人数据**；旧阈值（650/1000/1450 等）在模拟里 2★/3★ 不可达。真人采集协议见 `PLAYTEST-PROTOCOL.md`。
>
> **RSI 推荐菜 +25% 会提高实际分数**；当前目标尚未把 RSI 加成纳入模拟，仍作为旧基线，下一轮应重跑模拟/真人后调整。
>
> 02/03 从 3 单降到 2 单、放宽订单耐心，是因为机器人模拟显示 3 单排队会让熟练玩家也出现 26–33% 超时；2 单后熟练超时降到 0–9%，更接近“高手能救场、普通人会漏单”。
>
> 数据页支持导入 CSV、按经验组计算建议，并把建议作为**本机覆盖**应用到下一班；覆盖存 `sizzle-rush:v1` 的 `meta.targets`，不改代码，可“恢复官方”。

## 9. 操作与相机

### 第一人称

- 鼠标：`movementX/Y` 直接改 yaw/pitch（不乘 dt），灵敏度 0.0021 × 设置倍率；pitch 限制 ±1.45 rad（约 ±83°）。
- 移动：WASD 相对 yaw；目标速度 3.05 m/s，冲刺 4.75 m/s；速度用 `1 - exp(-13dt)` 平滑。
- 碰撞：圆形胶囊 (r=0.31) 对 AABB，两轮推开；房间边界 clamp。
- 头部晃动：步频相位驱动 2.6cm 垂直 + 0.9° roll；冲刺时 FOV +4.5°。
- 镜头震动：trauma² 衰减模型，切菜/烧焦/上菜分别给不同 trauma；只作用于相机，不移动身体。
- 手部：右下手持物 + 前臂/手；切菜时切换为刀并做 26Hz 摆动。

### 俯视

- 相机固定，`scale = min(w / 10.9, (h - 132) / 7.55)`，房间居中；窗口 resize 重新计算。
- 移动 3.35 m/s，`1 - exp(-14dt)` 平滑；圆形碰撞 + 玩家间分离。
- 屏幕震动：canvas 整体 translate 抖动，trauma 线性衰减。

### 输入抽象

- `src/core/input.js` 把物理键映射为命名动作：FP `forward/back/left/right/sprint/interact`；Arcade `p1* / p2*`。
- 键位存 `localStorage` 的 `sizzle-rush:bindings:v1`；`Bindings` 单例被 UI 与游戏共享，改绑立即生效。
- 冲突检测：一个物理键只能绑定一个动作；`Escape` 保留给暂停；每个模式可单独恢复默认。
- 手柄：标准映射，左摇杆/十字键移动，右摇杆视角（FP），A 互动+按住切菜，X/RB 切菜，RT/L3 冲刺，Start 暂停；边沿检测 + 径向死区 0.18。
- 触屏：2D 街机专用；左下虚拟摇杆 + 右下互动键 + 暂停。摇杆向量覆盖键盘/手柄，互动键支持按住切菜；`?touch=1` 可强制开启。
- HUD/提示/手册从同一绑定表取键名；手柄/触屏时自动切换文案（A / 互动 / 摇杆）。

## 10. 反馈与音频

- **触觉层**：拿起/放下/摆盘/切/煎/上菜/烧焦/超时，每种事件都有独立的音效 + 视觉（粒子/闪/弹字/震动）。
- **镜头震动**按重要性分级：切菜 0.035、上菜 0.42、烧焦 0.24、超时 0.18。
- **蒸汽/黑烟**：GPU Points 粒子，加色混合（蒸汽）与普通混合（烟/碎屑），池化。
- **上菜**：铃声 + 彩带 + `+分数` 弹出 + 票券消失 + HUD 连击倍率变化。
- **音频总线**：Master → 压缩器 → 输出；Music / SFX 两条子总线，音量设置映射到平方增益（感知更均匀）。
- **音乐**：104 BPM，4 小节循环（Cmaj7–Am7–Fmaj7–G7），kick/snare/hat/bass/chord/lead 分层；强度随剩余时间、连击、订单压力升高，增加 hat 密度与 lead 出现频率。
- **滋滋声**：持续滤波噪声床，按灶台数量平滑增益。
- **SFX 变化**：切菜/脚步等用随机频率偏移，避免机关枪式重复。

## 11. UI / UX

- **屏幕栈**：菜单 → 模式/班次 → 游戏 → 暂停 / 结算 → 设置 / 手册。覆盖层替换而非布尔标志堆叠。
- **HUD**：左分数、中订单、右倒计时；底部上下文提示 + 手持物 + 操作提示；准星状态（可互动/危险/切菜）。
- **响应式**：flex/grid 布局，基准 1920×1080，页面在 1024×640 与 1440×900 下均验证；窄屏隐藏教学/操作长条并压缩订单卡。
- **提示分级**：主动作（标题）→ 副提示（哪个键/百分比）→ 阻塞原因（红边）；另有顶部 toast 与中央得分弹字。
- **上手清单**：拿料 / 切菜 / 煎肉 / 摆盘 / 上菜五步，事件驱动打勾；上菜后自动收起。
- **设置**：音量、音乐、音效、灵敏度、FOV、画面精细度、镜头晃动、反转 Y、教学提示；即时生效并持久化。

## 12. 美术方向

- **关键词**：深夜小馆、暖色钨丝灯、绿瓷砖、旧木头、黄铜、手写菜单、霓虹招牌。
- **形状语言**：圆角方块与低多边形食物；轮廓优先，切碎/熟/焦通过“小碎片/颜色/焦黑”区分。
- **调色板**：奶油 `#f7e8d0`、番茄 `#e8503a`、琥珀 `#f6a623`、深绿岛台 `#2d4b3f`、木棕 `#8a5a34`、夜色 `#100b09`。
- **光照**：半球光 + 带阴影的方向主光 + 3 盏暖吊灯 + 灶台橙光 + 上菜口暖光 + 霓虹补光；ACES tone mapping，曝光 0.96。
- **纹理**：地面陶砖、奶油墙砖、深绿地铁砖、木纹、不锈钢、霓虹字、菜单黑板、海报、纸票——全部 Canvas 程序化生成，`SRGBColorSpace`，无外部图片。
- **UI 风格**：奶油纸张订单、琥珀主按钮、番茄强调、粗黑标题、轻微斜切/旋转；告示贴纸质感。
- **资产出处**：无第三方美术/音频素材；食物/设备为 three.js 基础几何体组合。详见 `THIRD_PARTY_NOTICES.md`。

## 13. 技术架构

```text
main.js  App
 ├─ UI (ui/ui.js)         屏幕栈 / HUD / toast / 结算
 ├─ AudioEngine           合成 SFX + 自适应音乐
 ├─ GameSession           core：Kitchen + OrderManager + 计分 + 计时
 └─ Mode
     ├─ FirstPersonMode   three.js 场景 + FPControls + 交互 + FX
     └─ ArcadeMode        Canvas2D 绘制 + 双人输入 + 交互 + FX
```

- **数据驱动**：`core/data.js` 定义食材、菜谱、工位、班次、碰撞体；3D 与 2D 都读同一份。
- **状态所有权**：`Kitchen` 持有工位/物品；玩家只持 `hands.carry`；`GameSession` 处理订单、计分、结算；表现层只读状态并消费事件。
- **渲染同步**：每帧从 Kitchen 读取工位物品/状态，用 `uid + state + cook bucket + contents` 作为签名，只在变化时重建 3D 物品网格；标签按状态节流重绘。
- **性能**：约 450–460 draw calls / 19k tris；粒子池；纹理只生成一次；阴影仅方向主光；像素比上限 2；质量设置控制分辨率。
- **可测试性**：核心模拟无 DOM/three 依赖，Node 单元测试直接驱动；调试 API `window.__SIZZLE__` 提供传送/给菜/结算，供 Playwright 使用。
- **试玩闭环**：每班自动记录带参与者/经验标签的真人样本，含首单时间、暂停次数和结算页难度/重玩意愿；`npm run analyze -- csv` 输出分经验百分位和阈值建议；自动化样本单独标记、默认排除。
- **平衡工具**：`npm run balance` 用真实规则 + 寻路机器人做可达性下限检查；真人 CSV 到位后用分析脚本替换阈值。
