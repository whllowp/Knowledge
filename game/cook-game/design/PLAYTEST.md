

## 5. 视觉/体验主观评估

**做得好的：**

- 第一人称厨房的尺度与材质可信：站在中岛前，木板、瓷砖、不锈钢、霓虹、上菜口暖光都能读出“深夜小馆”。
- 手持汉堡/沙拉的画面很有说服力，盘子和手部出现后沉浸感明显提升。
- 3D 到 2D 的规则一致性很好：切菜、煎、摆盘的节奏一致，2D 更像“快速复盘”。
- 上菜的反馈层很足：铃声 + 彩带 + 得分 + 倍率 + 票券消失。
- 2D 双人同屏的“抢灶台”空间关系成立。

**还不够好的：**

- 3D 场景里，玩家站在中岛前时柜台占据视野下部很大比例；这是第一人称写实尺度，但会让第一次玩的人觉得“离得太近”。可考虑把交互距离放宽到 1.7m，或把相机稍微后移。
- 立体声/混音无法在当前环境试听；合成音色可能偏“电子”，需要真人试听调 EQ。
- 2D 的墙面装饰较平，房间两侧仍有留黑；可以加侧墙/挂画填充。
- 订单卡的配料文字在窄屏会截断；390px 竖屏下订单卡已经接近极限，再窄需要折叠。
- 难度/星级目标目前是模拟校准版；真人可能觉得 1 星偏难或偏易。
- 手柄右摇杆视角在无头注入下可用，但真实手感（死区、加速度、灵敏度）还需要人手确认。
- 触屏按钮在 390px 竖屏可用，但摇杆/按钮会占用不少画面；横屏可能更合适，待真人验证。

**发现：**

- 旧阈值（650/1000/1450、1200/1800/2600、1400/2100/3100）与真实节奏严重脱节：熟练机器人 3 分钟也只能出 5 道左右、拿约 650 分，2★/3★ 基本不可达。
- 旧班次 2/3 同时挂 3 单、订单间隔 4.2s/2.8s，排队订单大量超时；熟练机器人超时率也到 26–33%。改成 2 单、放宽耐心后，熟练超时率降到 0–9%，普通仍有 35–47%，符合“高手能救场、普通人会漏单”的定位。
- 当前阈值按“新手 p50 / 普通 p50 / 熟练 p50”取整：`01 [300,475,625]`、`02 [300,425,800]`、`03 [225,375,625]`。新手大多能拿 1 星，普通能拿 1–2 星，熟练在 2–3 星之间。
- 机器人的路线是“最优但保守”的下限：它不会预切多份、不会利用双灶并行、不会在等肉时切菜；真人熟练玩家应更高。反之，真人会紧张、误点、找不到台面。两边不能互相替代。

**明确限制：** 这不是真人试玩数据。模拟只能回答“目标是否可达”，不能回答“好不好玩、难不难、晕不晕”。真人数据必须按 [PLAYTEST-PROTOCOL.md](PLAYTEST-PROTOCOL.md) 采集后重拟合。

## 7. 已知问题

1. **无头环境帧率低**（SwiftShader），不能用于性能结论；真实 GPU 待测。
2. **音频未在人耳监听下评估**；只验证了上下文状态、节点创建、无异常。
3. **暂停按钮在指针锁定时不可点击**（浏览器行为）；请用 Esc；手柄 Start 可暂停。
4. **真人试玩数据仍为空**；当前星级阈值是模拟校准版，不能当成最终平衡结论。
5. **触屏只覆盖 2D 街机且只控制 P1**；第一人称仍需键鼠/手柄。
6. **键位重绑只覆盖键盘**；手柄采用标准映射，固定不可改。
7. **下一天/下一班次的渲染器重建**已验证不崩，但长时间反复重开未做压力测试。
8. `localStorage` 在 `file://` 下因浏览器而异；Chrome 通常可用；无存储时退回内存（当次有效）。
9. 试玩数据只存本机；换浏览器/清缓存会丢，需要手动导出。
10. **2P 星级目标按 1P 标定**；双人配合会明显更容易满星，这是有意的合作奖励。
11. **没有在线联机**；2P 是同屏本地。

## 8. 下一轮验证计划

1. 按 [PLAYTEST-PROTOCOL.md](PLAYTEST-PROTOCOL.md) 招募 ≥5 名新手 + ≥3 名熟练玩家，覆盖键鼠/手柄/触屏。
2. 导出 CSV（每局已带参与者/经验标签），运行 `npm run analyze -- playtest.csv --min=3`；按报告的 1★/2★/3★ 建议替换模拟值，并对照超时率警告决定是否调订单耐心。
3. 重点观察：第一次玩是否理解“先放盘再摆料”、3D 眩晕、手柄右摇杆灵敏度、触屏竖屏遮挡、重绑后提示是否清楚。
4. 若触屏样本显示 P1 操作困难，评估双摇杆/更大按钮/横屏提示，或把移动端明确做成“仅街机”。
5. 在真实 GPU（至少 GTX 1650 / Iris Xe）上跑 Chrome Performance 面板，记录帧时间与 draw calls；目标 1080p 60fps。
6. 用耳机试听并调整音乐/SFX 比例，加入侧链 ducking。
7. 长时间反复重开/切模式压力测试，确认 WebGL 资源释放。
