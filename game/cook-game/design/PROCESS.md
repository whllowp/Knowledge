# 流程记录 — 用 awesome-gamedev-agent-skills 造《灶台风暴》

这份文档记录：为什么这样选引擎、读了哪些技能、每条技能如何落到代码里，以及哪些地方是刻意偏离。

---

## 1. 起点与范围

- 需求：做一款 Cook 游戏，两个模式；模式 1 是《胡闹厨房 2》式的第一人称沉浸做菜。
- 工作区：空目录（只有技能仓库 `awesome-gamedev-agent-skills-main` 和另一个参考仓库）。
- 产品目标：一个**能直接打开就玩**的双模式做菜游戏，而不是演示文档。
- 时间盒：一个长会话内完成可玩版本 + 验证 + 文档。

## 2. 路由（Router）

按 `router/SKILL.md` 的算法：

1. **检测引擎**：工作区没有 `project.godot`、`*.uproject`、`package.json` 引擎依赖等指纹；用户也没有指定引擎。
2. **默认规则**：router 建议新项目默认 Godot（该技能库覆盖最全）。
3. **实际选择**：**three.js（浏览器）**。理由：
   - 最终交付要“打开就能玩”，并且要在当前自动化环境里做**像素级验证**（Playwright 截图 + 真实键鼠事件）；
   - 浏览器方案不需要 Godot 导出模板 / 原生窗口 / 平台构建链；
   - 3D 与 2D 模式可以共用同一套 JS 模拟内核，并在同一个页面里切换；
   - 技能库中的 `threejs-*` 技能覆盖了场景、材质光照、循环与 resize。
4. **任务分类**：
   - 引擎：`threejs-scene-setup`、`threejs-materials-lighting`
   - 类型：`fps-shooter`（第一人称控制器/相机/交互手感的结构参考；本作不是射击）
   - 学科：`camera-systems`、`input-systems`、`game-ui-ux`、`game-feel`、`level-design`、`audio-design`、`create-game-assets`、`performance-optimization`
   - 流程：`prototype-fast`
5. **组合顺序**：引擎基础 → 学科 → 类型粘合 → 流程/范围。

> 偏离说明：默认引擎是 Godot，本项目选择 Web 引擎是**交付/验证约束**驱动的有意偏差，而不是忽略路由。核心模拟层（`src/core/`）不依赖 three.js，若未来迁移到 Godot，规则层可以原样移植。

## 3. 技能 → 代码映射

### 3.1 `threejs-scene-setup`

应用：
- `WebGLRenderer` + `Scene` + `PerspectiveCamera`（fov 可调 62–92）；
- 渲染循环由 App 的 `requestAnimationFrame` 驱动，`dt` 钳制在 `[0, 0.1]`（防止切标签后的巨大跳变）；
- `resize()` 同时更新 `camera.aspect`、`updateProjectionMatrix()`、`renderer.setSize()`；
- 像素比预算：`min(devicePixelRatio, 1.5) × quality`，上限 2；设置里可调到 60%；
- 没有用 `THREE.Timer`（r186 已有），而是 `performance.now()` + clamp，行为等价且更直接。

对应文件：`src/fp/fpMode.js`、`src/main.js`、`src/ui/ui.js`。

### 3.2 `threejs-materials-lighting`

应用：
- PBR `MeshStandardMaterial`：木头、瓷砖、不锈钢（metalness 0.82）、黄铜（0.9）；
- 三灯思路：半球环境光 + 带阴影的方向主光 + 暖色点光（吊灯/灶台/上菜口/霓虹）；
- `renderer.shadowMap.enabled` + 主光 `castShadow` + 网格 `castShadow/receiveShadow` 三处开关齐全；
- `ACESFilmicToneMapping` + 曝光 0.96；
- `RoomEnvironment` + `PMREMGenerator` 提供 IBL，强度 0.16，避免过曝；
- 所有 Canvas 纹理标记 `SRGBColorSpace`；粗糙度/法线类数据贴图保持线性。

对应文件：`src/fp/kitchen3d.js`、`src/fp/textures.js`、`src/fp/fpMode.js`。

### 3.3 `fps-shooter`（结构参考）

应用：
- 第一人称移动 + 鼠标视角；**鼠标增量不乘 dt**，移动积分乘 dt；
- pitch 限制 ±1.45 rad；
- FOV / 灵敏度作为设置暴露；
- 把“射击”替换为“做菜交互”：取最近工位 + 朝向点积 + 距离，而不是 hitscan；
- 保留了 FPS 的反馈分层：准星状态、镜头抖动、音效、粒子。

没有照搬：生命值、武器、后坐力、敌人 AI（本作不需要）。

对应文件：`src/fp/player.js`、`src/fp/fpMode.js`。

### 3.4 `camera-systems`

应用：
- 第一人称 look：yaw/pitch 分离，pitch clamp；
- 相机在移动/碰撞解算之后更新（`player.update()` 内部先算位置，再写相机）；
- 震动用 **trauma² 衰减 + 正弦扰动**，作为相机的附加旋转偏移，而不是移动身体；
- FOV 随冲刺平滑变化，走位/急停不突变。

页面上 2D 模式没有跟随相机（固定全景），所以只用了第一人称部分。

### 3.5 `input-systems`

应用：
- 命名动作层：`src/core/input.js` 把物理键映射为动作，逻辑上区分“按住”（移动/切菜）与“按下瞬间”（互动）；
- 键盘用 `event.code`（物理键位），避免输入法/布局影响；键位可在设置中重绑，冲突检测、Esc 保留、恢复默认、持久化；
- 手柄用标准映射 + 径向死区 + 边沿检测；左摇杆/十字键移动，右摇杆视角，A 互动+切菜，X/RB 切菜，RT/L3 冲刺，Start 暂停；
- 2D 双人用两套动作（P1/P2）；触屏摇杆 + 互动键作为 P1 的额外输入源，和键盘/手柄合并；
- HUD/提示/手册从同一绑定表取键名，手柄/触屏时自动切换文案。

未实现：手柄自定义映射、输入缓冲/ coyote time（本作没有跳跃，不需要）。

### 3.6 `game-ui-ux`

应用：
- 屏幕栈：menu / modes / settings / help / data / pause / results，任何时刻最多一个 active；
- HUD 用 flex/grid + clamp 字号，而不是绝对像素；
- 订单卡是事件驱动重建（按 ticket id 集合），计时条每帧只更新宽度；
- 打字/焦点：按钮可 Tab，模式卡片可 Enter 选择；键位捕获用 capture 阶段监听，避免误触游戏输入；
- 结果/暂停是覆盖层，游戏世界仍在背景中渲染；
- 安全区：触屏控件使用 `env(safe-area-inset-*)`；390×844 竖屏下隐藏 HUD 键位提示、提示条上移；
- 试玩数据页：汇总 KPI + 分组表 + CSV/JSON 导出 + 清空。

缺口：手柄焦点导航（用摇杆选菜单）未做；色盲/高对比模式未做。

### 3.7 `game-feel`

应用：
- **反馈分层**：一次上菜 = 铃声 + 彩带 + 分数弹字 + 镜头 trauma + 票券 HUD 变化 + 连击提示；
- **重要性分级**：切菜 0.035 trauma / 烧焦 0.24 / 上菜 0.42 / 超时 0.18；
- **缓动**：菜单/结算/提示用 cubic-bezier，票据/星星有弹入；
- **短暂、回到静止**：所有 shake/scale 都会衰减，不改变模拟状态。

未用：hit-stop（做菜不需要冻结帧）、squash & stretch 的物体形变（3D 低模上收益低）。

### 3.8 `level-design`

应用：
- 先定玩家度量：走速 3.05/4.75 m/s、交互半径 1.55m、柜台高度 0.92m、眼高 1.62m；
- 用这些尺寸反推厨房：10×7m、两个 2.3m 宽过道、中岛 7.6m 长；从出生点到最远食材箱约 5m；
- “教 → 练 → 考”：班次 1 少单宽限，班次 2 三单双灶，班次 3 密集短时限；
- 用灯光/颜色引导：上菜口暖光、霓虹在正前方、绿色岛台与奶油后墙形成对比；菜单黑板放在中岛正面。
- 上手清单把关键路径拆成 5 步，避免玩家在 3D 里迷路。

### 3.9 `audio-design`

应用：
- 总线：Master（压缩器）← Music / SFX；设置映射到平方增益；
- 自适应音乐：104 BPM，4 小节和声循环，按 `intensity` 增加 hat/lead 密度；intensity 来自剩余时间、连击与订单压力；
- SFX 变化：切菜/脚步随机频率；上菜用三音琶音；
- 滋滋声：持续滤波噪声床，按正在煎的灶台数量平滑；
- 没有做侧链 ducking / 空间音频（单场景，优先级低）。

对应文件：`src/core/audio.js`。

### 3.10 `create-game-assets`

应用：
- 先锁技术框：3D 休闲写实、暖色小馆、低多边形食物、无外部图片、程序化纹理；
- 定义视觉系统：形状语言（圆角、厚边、低模）、调色板（奶油/番茄/琥珀/深绿/木棕）、材质（木/瓷砖/不锈钢/黄铜）、光照方向；
- 资产清单在代码层面以“工位/食材/状态”枚举：6 食材 × 3 状态 + 盘子 + 工位 + 装饰；
- 没有图像生成工具可用 → 采用 **code-native 程序化资产**（Canvas 纹理 + three.js 几何体），并在实际游戏比例与背景下检查（截图验证）；
- 记录出处：无第三方素材；全程序化。

### 3.11 `performance-optimization`

应用：
- 先测量：浏览器内 `renderer.info.render.calls / triangles`（约 450–460 / 19k，1440–1920 宽，含阴影与粒子）；
- 分辨率预算：像素比上限 + 质量设置；粒子池；纹理只生成一次；物品网格按签名重建而不是每帧重建；
- 未做真实 GPU profile（当前环境是 SwiftShader 软件渲染，帧率不代表真机）；列为下一轮工作。

### 3.12 `prototype-fast`

应用：
- 问题：**“第一人称做菜的核心动作是否能在 3D 厨房里成立，并且和 2D 街机共享同一套规则？”**
- 核心动词：抓取 → 加工 → 摆盘 → 出餐。
- 灰盒优先：先做几何厨房 + 基础交互 + 计时，再加入纹理、灯光、粒子、音频。
- 范围纪律：只做 3 菜谱、3 工位类型、3 班次；不做联机/剧情/角色动画。
- 与技能的偏离：原型技能建议“验证后重写”，本项目把它作为可交付原型继续打磨；代码结构已按“可成长”组织（共享 core + 两个表现层），不是一次性 spike。

## 4. 实现顺序（实际执行的顺序）

1. 读技能 → 写 `core/data.js`（食材/菜谱/工位/班次/碰撞体）。
2. 写 `Kitchen` + `OrderManager` + `GameSession`；先写 Node 测试，确保规则正确。
3. 写 UI 壳（菜单/模式/设置/手册/HUD/结算）。
4. 写 three.js 厨房 + 第一人称控制器 + 交互 + 粒子。
5. 写 2D 街机模式（复用 core）。
6. 写 WebAudio 合成。
7. Playwright 端到端：菜单 → 沙拉全流程 → 烹饪/烧焦/丢弃 → 双人 → 结算 → 下一班次 → 暂停/继续。
8. 按截图迭代视觉（见 PLAYTEST 的“发现并修复”）。
9. 输入抽象 + 键位重绑 + 手柄 + 2D 触屏；每项补独立 E2E。
10. 试玩遥测 + 数据面板 + CSV/JSON 导出；真人样本带参与者/经验标签。
11. CSV 分析 + 数据页导入/建议/本机阈值覆盖；下一班生效，可恢复官方。
12. RSI 动态菜单：城市/天气/偏好推荐、推荐菜加分、历史回放策略改进、年度相册/HTML 导出。
13. 机器人平衡模拟；按模拟结果下调不可达的星级阈值、调整 02/03 的订单队列。
14. 文档与最终构建。

## 5. 关键设计决策

| 决策 | 选项 | 选择与理由 |
|---|---|---|
| 盘子摆盘 | 手持盘子直接加料 / 盘子必须先放台面 | 先放台面：更有空间成本，也让“出餐台”成为明确的节奏点 |
| 切菜输入 | 单击一次切一刀 / 按住连续切 | 按住连续切：低操作负担，进度可见；3D 里同时支持左键与 E |
| 配方匹配 | 顺序敏感 / 多重集 | 多重集：单手持物下更宽容；汉堡用“面包在顶部”的视觉顺序补足 |
| 烧焦 | 自动消失 / 留在锅里 | 留在锅里：制造“必须处理”的压力，也提供垃圾桶的用途 |
| 连击 | 只加时间 / 加倍率 | 加倍率（最高 ×2）：给熟练玩家超额回报，也给“先做急单”一个理由 |
| 3D 交互 | 准星射线 / 最近工位+朝向 | 最近工位+朝向：手柄式宽容，避免远处误触；准星只做状态反馈 |
| 2D 相机 | 跟随 / 固定全景 | 固定全景：双人同屏必需，也让玩家能规划路线 |
| 第二模式 | 经营 / 剧情 / 2D 街机 | 2D 街机：复用规则、与第一人称形成对照、本地双人成本低 |

## 6. 验证门槛

- `npm test`：41/41 通过（15 个核心 + 7 个输入 + 6 个遥测 + 6 个 CSV 分析 + 2 个阈值覆盖 + 5 个 RSI）。
- `node scripts/playtest.mjs`：真实键鼠完成沙拉并上菜，推荐菜得分 150。
- `node scripts/arcade-test.mjs`：双人移动/碰撞、P1 切菜、P2 拿料、上菜 170。
- `node scripts/cook-test.mjs`：指针锁定、鼠标 yaw、音频上下文 running、煎熟、烧焦、垃圾桶。
- `node scripts/flow-test.mjs`：15 秒警告、连击、结算、下一班次重建、暂停/继续（指针锁定恢复）、重开。
- `node scripts/rebind-test.mjs`：冲突拒绝、E→R 生效、旧键失效、恢复默认、持久化。
- `node scripts/gamepad-test.mjs`：虚拟手柄拾取/移动/视角/暂停、P1/P2 分配。
- `node scripts/touch-test.mjs`：`?touch=1` 强制触屏、摇杆移动、互动键拿料、暂停/恢复。
- `node scripts/telemetry-test.mjs`：结算记录、汇总面板、CSV 下载。
- `node scripts/human-playtest-test.mjs`：覆盖 `navigator.webdriver`，验证参与者/经验标签、真人汇总、CSV 列。
- `node scripts/rebalance-test.mjs`：导入 CSV、计算建议、应用本机覆盖、下一班生效、恢复官方。
- `node scripts/rsi-test.mjs`：城市/天气/偏好改变推荐、推荐菜 +25%、RSI 历史、年度相册、HTML 下载。
- `npm run analyze -- sample.csv`：验证 CSV 解析、分组百分位与阈值建议。
- `npm run balance`：80 局/班次/档位，输出分数/出餐/超时/星级分布。
- 截图检查：1440×900、1280×900、1024×640、390×844 下的主菜单、模式/RSI、3D 厨房、手持菜、上菜、2D 双人、触屏、结算、手册、设置、绑定、数据、年度相册。

## 7. 与技能的偏差 / 缺口

| 技能建议 | 本项目 | 原因 / 后续 |
|---|---|---|
| 新项目默认 Godot | 选 three.js | 交付与自动验证约束；core 可移植 |
| 完整 InputMap + 重绑定 | 已做命名动作 + 键盘重绑；手柄固定标准映射 | 手柄自定义映射列后续 |
| 手柄/触屏 | 已做标准手柄 + 2D 触屏 | 第一人称触屏、手柄菜单导航列后续 |
| 真人试玩调参 | 自动遥测 + 经验标签 + CSV 分析 + 本机阈值覆盖；真人样本为空 | 环境无真人；协议、导出、分析、应用已就绪 |
| 真实 GPU profile | 仅 draw call / 三角面 + 软件渲染 | 下一轮在真机 Chrome 上 profile |
| 侧链 ducking | 未做 | 单场景、音乐已很低 |
| 图像生成资产 | 程序化生成 | 无 imagegen 工具；程序化更可控且零版权风险 |
| 原型“验证后重写” | 保留并产品化 | 共享 core 已按可成长结构组织 |

## 8. 如果重来

- 更早做真人试玩，而不是先堆视觉：订单时限/星级目标需要手感数据。
- 把 HUD 的订单卡做成可复用的 DOM 组件，减少每次重建 innerHTML。
- 在 3D 里加一个“最近工位名称 + 按键”的世界空间提示，减少对底部提示条的依赖。
- 尽早加一个性能面板（帧时间、draw calls），把“优化”从猜测变成数字。
