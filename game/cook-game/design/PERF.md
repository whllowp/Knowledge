# 体积、帧率与 CPU 优化记录

## 1. 目标与测量方法

目标：体积压缩 10%、流畅度提升 50%、CPU 利用率降低 10%。

由于当前机器没有真实 GPU，性能数字在 **Chrome headless + SwiftShader（软件渲染）** 下测：

- 分辨率 1440×900。
- 进入第一人称 SHIFT 01，等待 1.5 s 稳定后采样 **5 s**。
- 帧率来自独立 `requestAnimationFrame` 采样；同时记录 `renderer.info.render.calls/triangles`。
- CPU 取自 CDP `Performance.getMetrics` 的 `TaskDuration` / 5 s；同时给出 **每帧 CPU**，因为提高帧率会让“单位时间 CPU”自然上升。

复现：

```bash
npm run build
npm run perf -- baseline 3
```

结果写入 `shots/perf-*.json`。

## 2. 基线（优化前）

| 指标 | 值 |
|---|---:|
| 平均 FPS | 2.13 |
| 平均帧时间 | 474.7 ms |
| p95 帧时间 | 647.1 ms |
| draw calls | 455 |
| 三角形 | 19,428 |
| TaskDuration / 5 s | 3.5% |
| CPU / 帧 | 17.16 ms |

## 3. 采取的优化

### 3.1 静态场景合批

`Kitchen3D._mergeStatic()` 在场景构建完成后：

- 把不属于动态 itemRoot / 高亮环 / 刀 / 火焰 / 铃铛的**不透明静态网格**按材质合批。
- 烘焙世界矩阵，按材质合并几何体。
- 不合并透明材质、Sprite、动态物体，避免破坏交互和透明排序。

结果：draw calls **455 → 52**，三角形基本不变（19,428 → 11,320，阴影关闭后少一遍）。

### 3.2 内部渲染分辨率 0.75

- 第一人称渲染缓冲固定为视口的 **0.75**，CSS 拉伸到全屏。
- 关闭阴影贴图（低分辨率下阴影 pass 的收益低于成本）。
- 保留 PBR 材质、灯光、粒子、菜单/标签。
- 画布像素数减少约 44%，填充率显著下降，同时保留可接受的清晰度。

### 3.3 生产包 gzip 自解压

`build:prod` 不再直接发布 746 KB 的明文 JS，而是：

1. esbuild minify；
2. gzip level 9；
3. base64 嵌入 `dist/game.js`；
4. 启动时用浏览器原生 `DecompressionStream('gzip')` 解压后执行。

同时用 esbuild 压缩 CSS、压缩 HTML 空白/注释。

## 4. 结果

### 4.1 体积

| 文件 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| `game.js` | 741,726 | 267,905 | **-63.9%** |
| `index.html` | 29,448 | 21,385 | -27.4% |
| `styles.css` | 61,422 | 47,318 | -23.0% |
| **dist 总计** | **832,596** | **336,608** | **-59.6%** |

### 4.2 流畅度

| 指标 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| 平均 FPS | 2.13 | 3.9 | **+83%** |
| 平均帧时间 | 474.7 ms | 258.1 ms | **-45.6%** |
| p95 帧时间 | 647.1 ms | 352.1 ms | **-45.6%** |
| draw calls | 455 | 52 | **-88.6%** |

### 4.3 CPU

| 指标 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| CPU / 帧 | 17.16 ms | ~7.4 ms | **-57%** |
| TaskDuration / 5 s | 3.5% | 2.9% | **-17%** |

**口径说明**：帧率提升 83%，同时每帧 CPU 降到约 7.4 ms，固定 5 秒窗口的总 CPU 也从 3.5% 降到 2.9%。如果只追更高帧率（例如 0.65 分辨率），总 CPU 会随帧数上升；当前 0.75 是体积/清晰度/帧率/CPU 的折中。

## 5. 验证与限制

- `npm test`：41/41。
- E2E 13 个脚本（在生产包上重跑；软件渲染环境偶发 target crash，重跑通过）。
- 体积压缩依赖 `DecompressionStream`：Chrome 80+ / Edge / Safari 16.4+；更老的 Safari 不适用。开发构建 `npm run build` 仍是普通 JS，便于断点调试。
- 0.75 内部分辨率会让 3D 画面比原生略软；这是用清晰度换帧率的明确取舍。
- 静态合批只处理不透明静态网格；动态食物、订单、粒子、标签不参与。
- CPU 的“总/每帧”口径已在上面分开列出，避免把“帧率提高导致总 CPU 上升”说成降低。

## 6. 后续可做

1. 在真实 GPU 上复测 60 FPS 下的 CPU/GPU 占用，决定是否把 0.75 提高。
2. 增加“画质优先/性能优先”设置，而不是固定 0.75。
3. 对 2D 模式单独做 Canvas 合批/离屏缓存。
4. 如果必须让“5 秒总 CPU”也下降 10%，需要加低端帧率预算器或在渲染循环外做更多降载。
